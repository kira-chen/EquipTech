## 一、背景与目标

用户要求统一管理演示 case：在 `炼厂车间设备员/` 下新建 `演示case/`，把 `设备员skill/` 下各技能的 `examples/` 统一规整进去。

目标：

1. 技能目录里不再有 `examples/`，样例全部在 `演示case/`。
2. 现有技能行为不受影响，发布包内容不变。
3. 自测、样例再生、开发包、技能清单照常工作。

## 二、动手前的影响面摸底

`examples/` 是规范允许的技能目录组成部分，被大量引用，直接移动会出问题：

| 引用方 | 数量 | 用法 |
|---|---|---|
| `make-sample.js` | 50 | 默认输出到 `examples/` |
| `selftest.js` | 11 | 读样例做断言，3 个还检查附件是否存在 |
| `上架信息.md`、`样例问题.md` | 各 50 | 附件路径写成 `examples/xxx` |
| `SKILL.md` | 50 | 文件说明表里的 `examples/` 一行 |
| 各技能 `examples/README.md` 与 `scripts/README.md` | 约 100 | 命令里的 `--out examples`、`--input examples/...` |
| `tools/build.sh`、`package.sh`、`make-list.js` | 3 | 开发包含样例、发布包排除样例、技能清单附件说明 |
| 规范与 README | 6 | 目录规定、技能实现规范、协同规范、各级 README |

技能目录内文本中共 1584 处 `examples` 字样。基线：50 个技能自测全过，10681 条断言。

## 三、方案

见 [D004](../../决策记录/D004-演示样例统一放演示case.md)。要点：按分类镜像建目录，用 `git mv` 迁移；脚本按仓库层级定位演示目录，仓库外回落 `examples/`；开发包打包时把样例放回包内 `examples/`。

## 四、过程

1. 建本地分支 `refactor/demo-case`，跑全量自测取基线。
2. 用一次性迁移脚本（会话临时目录，不入库）完成：
   - `git mv` 50 个 `examples/` 目录；
   - 按文件类型分别改写文本：附件只留文件名；说明里的位置写成 `演示case/<分类>/<技能>/`；命令里用 `$CASE/`，并在文件开头说明 `$CASE` 的含义；
   - 改 50 个 `make-sample.js` 的默认输出、11 个 `selftest.js` 的样例路径。
3. 抽查替换结果，修正 3 类误改：
   - bridge 技能文档中“依赖技能 examples”指的是【炼化】依赖技能自己的目录，恢复原文；
   - 5 份措辞不同的 SKILL.md 表格行没有命中固定句式，被改成 `$CASE`，手工改正；
   - SKILL.md 和 references 会进发布包、给模型读，去掉其中的 `$CASE`，改为直接写文件名。
4. 改 `build.sh`（开发包把演示目录放回 `examples/`）、`make-list.js`、`package.sh` 的说明。
5. 更新规范（目录与文件管理规范新增演示case 一节和一一对应检查）、技能实现规范、协同规范、各级 README、`/package-skills`，新建 `演示case/README.md` 索引。
6. 第二轮补改（用户确认后）：去掉规范中与演示case 重复的 `演示附件/`；50 个演示 README 标题加技能中英文名；项目 `CLAUDE.md` 加演示样例约定；修正 bridge 自测的一句提示语。
7. 合并前发现工作区里有并行会话的改动（见第六节），拆成两个提交后按协同规范推送。

## 六、并行改动与提交拆分

处理：

1. 确认其他会话都已空闲、工作区不再变化后再动手。
2. 用户决定由本会话统一提交。按“一次提交只做一件事”拆成两个提交：先按改动块只暂存 bridge 改动（第 02 类 README 中两边改在同一行，手工拆分），提交 `b2678e2`；再提交迁移改动 `12f0ae7`。
3. 单独检出 `b2678e2` 跑两个 bridge 技能自测，确认第一个提交不依赖第二个提交。
4. 冲突检测（远端仍为 `4b8052a`，无冲突）→ 快进合并到 `main` → 推送 → 删除本地分支。

## 一、背景与目标

用户在仓库根目录新建 `ProjectManage/`，要求之后 AI 助手产出的总结、阶段产物、过程文档都放在这里，自建目录，能完整追溯项目推进流程。

## 二、做了什么

1. 定目录结构和记录规则，写在 [README](../../README.md)：推进时间线做总索引，`任务/` 每项任务一个目录，`决策记录/` 记取舍，`待办与风险.md` 汇总未完成事项，`阶段总结/` 做阶段盘点。
2. 回溯补记 2026-08-28 起的进度，写进 [推进时间线](../../推进时间线.md)。2026-11-02 前没有可查的提交，据项目记忆和 `炼厂车间设备员/文档/过程记录/` 整理，并标注来源。
3. 补记 4 份决策记录 D001~D004，以及 [2026-11-04 演示case 规整](../2026-11-04-演示case规整/任务记录.md) 的完整任务记录。
4. 写 [待办与风险](../../待办与风险.md)（待办 T01~T05、风险 R01~R02）和 [项目现状基线](../../阶段总结/2026-11-05-项目现状基线.md)。
5. 同步约定：
   - `目录与文件管理规范` 中“过程材料”的存放位置改为 `ProjectManage/`，2026-11-03 及以前的留在原处；
   - 项目 `CLAUDE.md` 新增“项目推进记录”一条，所有会话都会读到；
   - 根目录 README 与 `炼厂车间设备员/README.md` 的目录说明加上 `ProjectManage/`（根 README 同时补上 `演示case/`）。

## 三、取舍

- **不迁移** `炼厂车间设备员/文档/过程记录/` 里的 4 份旧文档：其他文档和提交信息里有指向它们的链接，原样保留，在时间线中链接。
- 仓库是公开的，补记时过滤掉了项目记忆中的服务器地址、账号、模型服务配置和真实企业名。

- 本目录所有 Markdown 相对链接都能找到目标文件（0 个断链）。
- 检查无 IP 地址、token、密钥、账号和真实企业名。

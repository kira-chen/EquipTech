## 一、目标

接收 `--workshop` 的技能在输入数据混入其他车间时，不再把其他车间的数据静默汇总进本车间报告。

## 二、范围

- 要做：
  1. 先盘点：列出接收 `--workshop` 的全部主脚本，标明各自输入里是否可能带“车间”列（含 MCP 工具导出和用户手工表格）。
  2. 输入有车间列时：按 `--workshop` 核对；有其他车间的行时，剔除并 warning 列出剔除行数和车间名。剔除还是只提示，先在盘点里给出方案，经 PM 确认后实施。
  3. 输入没有车间列时：报告口径处写明“输入未含车间列，车间范围以取数条件为准”。
  4. 参照已有做法：lubrication-manager、standby-rotation-reminder 已能检测混入其他车间。
- 不做：不改 MCP Server；不改 `--workshop` 用于标题的现有用法。

## 三、输入

- `炼厂车间设备员/设备员skill/` 下约 35 个接收 `--workshop` 的主脚本
- 各技能 SKILL.md 的“数据获取（MCP）”一节
- 中石化口径对照中的车间、装置层级说明

## 四、交付物

- 第一步：盘点清单和处理方案，写在本任务单回执里，发消息给 PM 确认。
- 第二步：按确认的方案改脚本、selftest、references 和 scripts/README；演示case 对照表有变化的同步更新。
- 如抽成共享函数放进 `common.js`，按共享库流程单独提交并同步全部副本。
- 本地分支提交，不推送。

## 五、验收标准

1. 用两个车间混合的数据运行各相关技能：结果只含 `--workshop` 指定车间，或明确提示混入情况；不会静默生成包含其他车间数据的报告。
2. 输入无车间列时，报告注明车间范围无法从输入核对。
3. 全量 `bash 炼厂车间设备员/tools/package.sh` 通过，断言数不减少。
4. 演示case 对照表中的预期结论不变；有变化的逐条说明。

## 六、约束

- 改动面大，先盘点、再确认、后实施，不一次性铺开。
- 改共享库按目录与文件管理规范第五节执行。

  **三、A 类的处理方案（建议做成共享函数，放进 common.js）**

  新增 `C.workshopScope(records, workshop, sheetLabel)`，每张主表 `toRecords` 之后调用一次：

  1. **认哪些列：** 车间列只认「车间、所属车间、属地车间、运行部」。不认「维护工厂、计划工厂」（SAP 工厂代码），也不认「责任单位、作业单位」（可能是部门或承包商）。
  2. **比对：** 去掉空白后与 `--workshop` 相等，或去掉末尾「车间/运行部」后相等，都算本车间。
  3. **有车间列、且至少一行是本车间（建议剔除）：**
     - 车间是别的值的行剔除，不进统计；
     - warning：「工作表「X」按 --workshop 剔除其他车间 N 行（加氢车间 3 行、…）」；
     - 车间列为空的行按本车间保留，warning 写明行数；
     - JSON 记 `meta.workshopScope`（表、列、保留数、剔除数和车间名、空值数）。
  4. **有车间列、但没有一行是本车间：** 不筛，避免把整张表剔空。可能是写法不同或填的是工厂代码。warning 提示核对，报告口径处写「车间列取值与 --workshop 不一致，未按车间筛选」。
  5. **没有车间列：** 不筛。报告口径处写「输入未含车间列，车间范围以取数条件为准」，`meta.workshopScope` 记 `noColumn`。
  6. **`--workshop` 可选且没给：** 不核对，行为不变。
  7. **已有的台账位号比对**（lubrication-manager、standby-rotation-reminder）保留，与本方案叠加。

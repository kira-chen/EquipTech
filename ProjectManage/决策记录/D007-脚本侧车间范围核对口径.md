# D007 脚本侧车间范围核对口径

- 日期：2026-11-05
- 决定人：PM（P002 方案确认）；第 5 点待用户确认
- 状态：有效
- 来源：付晨问题表 ET-004；[P002 任务单](../任务/2026-11-05-P002-脚本车间范围校验/任务单.md) 第七节 SK 的盘点与方案

## 决定

采用 SK 的分类方案：A 类批量表格 26 个、B 类读上游 JSON 3 个、C 类单台/单事件/文档 11 个，共 38 个主脚本（日报、周报月报同时属于 A、B 两类）。车间核对抽成共享函数放进 `common.js`。

对方案中 5 个待确认点的决定：

| 编号 | 问题 | 决定 |
|---|---|---|
| 1 | A 类输入混入其他车间时剔除还是只提示 | **剔除并 warning**，逐车间写明剔除行数；`meta.workshopScope` 记录保留与剔除情况 |
| 2 | B 类上游 JSON 的 `meta.workshop` 与 `--workshop` 不一致 | **不纳入该来源并 warning**；上游 JSON 没有 `meta.workshop` 时照常纳入，口径处说明无法核对 |
| 3 | C 类 11 个不做行级核对 | **同意**；operator-anomaly-guide、training-material-generator 的 `--ledger` 按 A 类核对 |
| 4 | 车间列不认“维护工厂”“计划工厂”“责任单位”“作业单位” | **同意**；共享别名表不动，只在核对函数里排除 |
| 5 | 是否请 MCP 会话给通知单、工单等导出加“车间”列 | **待用户确认**：改变工具返回结构，按约定须用户同意；不在 P002 内做 |

## PM 补充的要求

1. 有车间列但没有一行与 `--workshop` 一致时（方案中不筛的情况），除口径处说明外，报告开头用【注意】醒目提示“车间列取值与 --workshop 不一致，未按车间筛选，请核对输入”。这种情况多半是上传错了文件，只在口径处写不够醒目。
2. 车间列为空的行按本车间保留，warning 写明行数（同 SK 方案）。
3. 改完后，SKILL.md 中“脚本不按车间筛选”的表述要同步修改：说明脚本只在输入带车间列时核对；MCP 导出多数不带车间列，取数时仍必须带 `workshop`。
4. 新增 `meta.workshopScope` 字段后，核对 B 类读取方不受影响。

## 理由

- 剔除：报告标题是本车间，计数里混入其他车间正是 ET-004 指出的问题；剔除内容逐项写明，用户能核对。
- 全不匹配时不剔除：避免把整张表剔空，但必须醒目提示，满足付晨验收标准中的“不得静默生成错误车间报告”。
- C 类按单台设备或单个事件处理，不跨车间汇总，行级核对没有意义。
- “维护工厂”是 SAP 工厂代码（如 1100），不是车间。

## 影响

- `common.js` 改动按目录与文件管理规范第五节执行：单独提交，同步全部副本，跑全量自测。
- 含车间列且车间混合的演示样例，结果可能变化，需逐行复跑演示case 对照表并说明。

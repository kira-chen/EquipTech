## 决定

各技能的演示与回归样例从技能目录内的 `examples/` 迁出，统一放在 `炼厂车间设备员/演示case/<分类>/<技能英文名>/`，层级与 `设备员skill/` 一致。技能目录只放技能本身。

## 配套约定

| 项 | 约定 | 理由 |
|---|---|---|
| 目录层级 | 按分类镜像，而不是 50 个技能平铺 | 与 `设备员skill/`、`素材/图标/` 结构一致，定位规则简单 |
| 迁移方式 | `git mv` | 保留文件历史，样例内容不变 |
| 脚本定位 | 仓库内按 `设备员skill/` 层级找演示目录；不在仓库里时回落到技能目录 `examples/` | 开发包解压到仓库外仍能自测 |
| 开发包 | 打包时把演示目录放回包内 `<技能>/examples/` | 开发包结构不变 |
| 附件写法 | 上架信息、样例问题的附件只写文件名 | 路径太长，位置在文件开头统一说明 |
| 命令写法 | 对照表等开发文档用 `$CASE/` 指代演示目录 | 命令在技能目录下运行，相对路径过长 |
| 进发布包的文档 | SKILL.md、references 不使用 `$CASE`，直接写文件名 | 这些内容给模型读，不宜引入变量 |
| `演示附件/` | 从规范中去掉 | 与演示case 作用重复，当时没有任何技能使用 |

## 备选方案

- 平铺 `演示case/<技能>/`：更短，但与仓库其他目录的分类结构不一致，未采用。
- 只复制不移动：两处样例会不同步，未采用。
- 把定位代码收进共享库 `common.js`：更简洁，但改共享库要单独提交并同步 50 份副本，本次未做，列入待办。

## 影响

- 在仓库内手动运行主脚本时，样例路径要写演示目录。
- 新增技能时要同时建演示目录，并更新 `演示case/README.md` 索引。
- 规范第七节新增“技能与演示目录一一对应”的检查。

# ProjectManage · 项目推进管理

EquipTech 项目推进过程的记录：做了什么、为什么这样做、怎么验证的、留下了什么问题。目标是任何一项改动都能从时间线追到任务记录、决策和 Git 提交。

项目由主项目经理（PM）与用户协同，任务派发给各责任方执行，见 [责任方](协同/责任方.md) 和 [派发流程](协同/派发流程.md)。PM 自己做的任务写 `任务记录.md`，派发给责任方的任务写 `任务单.md`（含执行回执和验收记录）。

## 目录

```
ProjectManage/
├── README.md            # 本文件：目录用途与记录规则
├── 推进时间线.md         # 总索引，按日期列出每件事，链接到任务记录和提交号
├── 派发台账.md           # 派发给各责任方的任务及状态
├── 待办与风险.md         # 跨任务的未完成事项和风险，每条注明来源
├── 协同/                 # 责任方清单、派发流程与任务单模板、付晨提交审核流程
├── 审核/                 # 付晨提交的审核记录：YYYY-MM-DD-<短提交号>-<主题>.md
├── 任务/                 # 每项任务一个目录：YYYY-MM-DD-事项名/（任务记录或任务单）
├── 决策记录/             # 影响后续工作的决定：Dnnn-主题.md
└── 阶段总结/             # 阶段结束或需要对齐全局时的总结：YYYY-MM-DD-阶段名.md
```

## 怎么追溯

1. 在 [推进时间线](推进时间线.md) 找到日期和事项。
2. 点进 `任务/` 下的任务记录，看背景、方案、过程、验证和遗留问题。
3. 任务记录里写了提交号，用 `git show <提交号>` 看实际改动；写了决策编号的，到 `决策记录/` 看当时的取舍。
4. 没做完的事都在 [待办与风险](待办与风险.md)，关闭时写明在哪个任务里关闭。

## 记录规则

**什么时候记**

| 时机 | 要做的事 |
|---|---|
| 一项任务开工 | 在 `任务/` 下建目录，先写背景和目标 |
| 做出影响后续工作的决定 | 在 `决策记录/` 新增一份，写清备选方案和取舍理由，并在任务记录里引用 |
| 提交或推送后 | 任务记录补上提交号和验证结果，时间线加一行 |
| 发现做不完或有风险的事 | 加到 `待办与风险.md`，注明来源任务 |
| 一个阶段结束 | 在 `阶段总结/` 写总结，更新时间线 |

**命名**

- 任务目录：`YYYY-MM-DD-事项名/`，日期取开工日期。
- 任务目录内：小任务只写一份 `任务记录.md`；大任务可拆成 `01-方案.md`、`02-过程记录.md`、`03-验证记录.md`、`04-总结.md`，中间产物（清单、对照表、报告）也放在该目录下。
- 决策记录：`Dnnn-主题.md`，编号递增，不复用。决定被推翻时不删除原文，新写一份并在原文开头注明“已被 Dnnn 取代”。
- 阶段总结：`YYYY-MM-DD-阶段名.md`。

**写法**

- 只写事实。没验证的写“未验证”，回溯补记的内容注明来源（Git 提交、项目记忆或已有文档）。
- 数字写清口径，如断言数注明是全部 50 个技能 selftest 的合计。
- 本仓库是公开仓库。**不写**服务器地址、账号、token、密钥、真实企业和人员信息。

## 与其他目录的关系

- `炼厂车间设备员/文档/过程记录/`：保存 2026-11-03 及以前的任务书和核验报告，原样留档，时间线里有链接。之后的过程材料放在本目录。
- `炼厂车间设备员/文档/规范/`：长期有效的规范。规范的改动在本目录的任务记录里说明原因，规范正文仍在原处维护。
- 本目录不放技能文件、样例和打包产物。

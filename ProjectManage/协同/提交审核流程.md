付晨（GitHub 用户 `mb8rphfgy6-eng`）按 [GitHub 协同规范](../../炼厂车间设备员/文档/规范/GitHub协同规范.md) 自行把改动合并到 `main`。PM 每次拉取远端更新时审核她的提交，**只审核、提出疑点，不直接修改她提交的内容**。疑点交给用户，由用户决定是否转达、怎么处理。

## 怎么识别她的提交

本仓库其他提交（含各 AI 会话的提交）作者都是 `kira-chen`。拉取后列出本次新增提交，作者不是 `kira-chen` 的即为她的提交；必要时用 GitHub 提交记录核对账号。

```bash
git fetch --prune origin
git log --format='%h %an <%ae> %ad %s' --date=iso HEAD..origin/main
```

## 审核步骤

1. **登记：** 在 `审核/` 下新建 `YYYY-MM-DD-<首个短提交号>-<主题>.md`，写明提交范围和改动文件清单。
2. **看改动：** 逐个提交阅读 diff，弄清每处改动的意图。
3. **核对：** 按下面的核对项逐条检查，只运行验证命令（自测、打包、检查脚本），不改文件。
4. **列疑点：** 每条疑点写明位置、问题、依据（规范条款、自测结果、与其他模块的冲突）和建议向谁确认。看不出意图的写成问题，不当成错误下结论。
5. **结论：** 写“无疑点”或“有 N 条疑点待回复”，在推进时间线加一行，并向用户汇报。
6. **跟进：** 用户回复或付晨补提交后，在同一份审核记录里补结果；需要立项修复的，按派发流程派发或记入待办。

## 核对项

| 类别 | 核对内容 |
|---|---|
| 范围 | 改动是否与提交信息一致；是否夹带无关文件、临时文件、打包产物 |
| 规范 | 是否符合目录与文件管理规范、技能实现规范、中石化口径对照；提交信息格式 |
| 验证 | 涉及技能的 selftest 是否全过、断言数是否减少；涉及共享库或打包工具时全量打包是否通过；提交前检查是否无输出 |
| 口径 | 术语、分级、判定规则是否与口径对照和现有技能一致；断言是否被删除或放宽 |
| 影响面 | 输出 JSON 字段变化是否影响下游技能；是否影响 MCP 取数或演示case 对照表 |
| 安全 | 是否含服务器地址、账号、token、真实企业或人员信息 |
| 协同 | 是否与 AI 会话正在做的工作冲突；是否改了需先在协同群告知的文件（共享库、口径对照、打包工具等） |

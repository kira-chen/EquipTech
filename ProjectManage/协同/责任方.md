# 责任方

项目由用户统筹，主项目经理负责与用户协同、拆解和派发任务、验收和记录。AI 会话的任务按 [派发流程](派发流程.md) 派发，记录在 [派发台账](../派发台账.md)；付晨的提交按 [提交审核流程](提交审核流程.md) 审核。

| 代号 | 责任方 | 类型 | 负责范围 | 派发与回报 |
|---|---|---|---|---|
| PM | 主项目经理：Claude Code 会话「【Main】演示case管理及远端提交」 | AI 会话 | 与用户协同；任务拆解、派发、跟踪、验收；维护 `ProjectManage/`；验收通过后按协同规范合并到 `main` 并推送 | 直接与用户沟通 |
| SK | 设备员skill开发会话：Claude Code 会话「设备员skill开发」 | AI 会话 | `炼厂车间设备员/设备员skill/` 下 50 个技能、`炼厂车间设备员/演示case/`、自测与打包、技能相关规范 | PM 发会话消息，附任务单路径；完成后在任务单填回执，再发消息给 PM |
| MCP | MCP Server开发会话：Claude Code 会话「MCP Server 开发」（会话 ID 以 `61f202fe` 开头，工作目录 `MCPServer/`） | AI 会话 | `MCPServer/`：6 个系统 45 个工具、模拟数据、端到端测试、远程部署 | 同 SK。在会话列表中显示名为 `equiptech-98`（2026-11-05 对方确认） |
| FC | 付晨：GitHub 用户 `mb8rphfgy6-eng` | 团队成员 | 自行开发并按协同规范合并到 `main` | PM 不直接派发。PM 每次拉取远端时审核她的提交，疑点交给用户 |

## 各责任方的约束

**SK 设备员skill开发会话**

- 遵守[目录与文件管理规范](../../炼厂车间设备员/文档/规范/目录与文件管理规范.md)、[技能实现规范](../../炼厂车间设备员/文档/规范/技能实现规范.md)和[中石化口径对照](../../炼厂车间设备员/文档/规范/中石化口径对照.md)。
- 改共享库（`common.js`、`xlsx-lite.js`、`docx-lite.js`）要单独提交，并同步全部副本。
- 改了输出 JSON 字段，要在回执里写明受影响的下游技能。

**MCP MCP Server开发会话**

- 代码不入库（[D003](../决策记录/D003-MCPServer不入库.md)），回执写在任务单里，不写 Git 提交号，改写部署版本或测试报告名。
- 协议（地址、传输、鉴权）冻结，只能改工具。改动影响 Client 调用（工具名、入参、返回结构、描述）时，先报 PM，由 PM 请用户确认后再改。
- 改工具后跑端到端测试和远程冒烟，通过后再部署。

**FC 付晨**

- 只能看到 GitHub 仓库里的内容，看不到 `MCPServer/` 和本机其他目录。给她的疑点要能独立看懂：写清文件路径、行号和依据，不引用她看不到的内容。
- 按 [GitHub 协同规范](../../炼厂车间设备员/文档/规范/GitHub协同规范.md) 自行合并到 `main`。
- PM 拉取远端时按 [提交审核流程](提交审核流程.md) 审核她的提交，审核记录放 `审核/`。**PM 只提出疑点，不直接修改她提交的内容。**

**所有责任方**

- 仓库公开，不提交服务器地址、账号、token 和真实企业信息。
- 遇到范围外的问题或需要拍板的事，回报 PM，不自行扩大范围。

# 设备员技能包核验报告（面向中石化体系炼化厂车间设备员）

核验日期：2026-10-26。范围：8 类 50 个技能，全部 SKILL.md、references、examples/README、主脚本规则表与共享库。
方法：全量 selftest 回归 + 三路分类人工审计（01/02、03/04/05、06/07/08）+ 关键发现逐条实测复核。
本报告只记录问题与改法，未改动任何技能文件。

## 一、现状结论

- 工程纪律落实到位：50 个技能 selftest 合计 6193 条断言全绿；common.js 50 份、xlsx-lite.js 48 份 md5 完全一致（两个 bridge 不读表，不带 xlsx-lite 属合理）；脚本出数、null 不补零、undetermined 单列、声明行这四条底线基本没有硬违例。
- 主要差距是**业务口径停留在"通用炼化厂 + 自造 Excel"**，没有对接中石化体系炼化厂的真实系统、术语与制度；另有 **5 处会直接出错数的代码 bug** 与 **3 处法规口径错误**。
- 落地到中石化炼化厂设备员，最先撞墙的是：周期解析不认"每班/每 2 小时/半年"（巡检、盘车、润滑三个主场景大面积"待确认"）、"无异常"被判异常、工单状态不认 SAP 系统状态、PDF 一律不读。

## 三、法规与制度口径错误

1. 承包商司索工列为吊装必备证（qualify.js:112）。TSG Z6001-2019 已取消司索工取证，现规则下所有吊装作业必落"不建议准入"。
2. 高处作业一律要求高处作业操作证（qualify.js:103）。特种作业只覆盖登高架设与高处安装维护拆除，一般高处检修不需持证。
3. 一般隐患默认 30 天时限（hazard.js:84）。《中国石化安全隐患管理规定》无统一天数，由整改方案定；应改为 null → undetermined，仅 `--rules` 给厂内天数时推算。
4. 隐患"三定四不推"旧口号（hazard-closure-tracker 描述），现行是"五定"（方案、资金、责任人、期限、应急措施），台账也缺"资金/应急措施"两列。
5. moc-change-assistant 压力容器/管道结构改动未附"改造告知、监督检验、使用登记变更"三项法定动作（rules.js:313）；变更分类未按中石化"工艺/设备/管理 × 重大/一般"口径，同规格不同厂家代用被判成变更（应走同类替换/材料代用单）。
6. safety-environmental-device-check 的"默认参考周期表"（facility-rules.md:7-49）凭记忆列法规数值且无出处，与 07 类 README 红线冲突。
7. equipment-handover-check 未给 `--pressured`/`--hot` 时按 0.02 MPa / 60℃ 推断带压/高温（input-spec.md:17,19），阈值既偏低又与自身"≤40℃ 交出"不是一套口径。

术语与分级错位：
- 检修分级用"大修/中修/小修"（repair-plan-assistant、maintenance-record-archive 的 `--type` 直接报错），应为"装置大检修（停工检修）/日常维修/抢修/专项"。
- 作业许可用"动火"，中石化八大类是"用火作业"，并有独立"盲板抽堵作业"（handover H3 加盲板未提示办票）。
- 缺陷用 I~IV 四级，中石化炼化厂设备部缺陷台账是 A/B/C 三级；设备重要度 A/B/C、异常关注度 A/B/C、缺陷 I~IV、工单优先级 紧急/高/中/低 五套分级撞名。
- 组织层级用"车间/设备部/厂领导/全厂"，中石化炼化厂实际是 车间 → 分厂（烯烃厂/芳烃厂等，设备科）→ 公司设备部/公司领导（meeting-material `--audience`、event-notice `--scope`）。
- "机动处"是老称呼（maintenance-demand-rollup 描述）。
- shift-handover-record 以"白班/夜班"为必填。中石化炼化厂车间设备员常白班不倒班，交接的是值班/休假/调岗工作交接；"交接班"触发词会抢操作班组 DCS 交接班请求。

## 五、中石化口径缺口（指标与业务要素）

- 泄漏率：leak-point-tracker 只算修复率，没有月报必报的"静密封点泄漏率 ≤0.5‰ / 动密封点 ≤2‰"，不区分动静密封，也不认"延迟修复"状态（GB 31570 允许，现被判超期）。
- 月报指标：equipment-weekly-monthly-report 只有完好率、计划完成率、工单及时率、MTTR、停机时长；缺主要设备完好率、泄漏率、故障停机次数、特护机组运行状况、备机完好率、非计划停工次数。厂内口径表命中时只换文字不换算法，并撤掉默认口径声明（metrics-rules.md:70、input-spec.md:122），是最大的误导风险。
- 日报：状态只有正常/异常两档，丢失运行/备用/检修/停用；缺特护机组、泄漏点、当日作业票数；明确忽略 hazard.json，而 hazard-rules.md:109 又说隐患进日报，两处矛盾。
- 润滑：全部文档无"五定三过滤"，台账缺"定人"列；油液分析拒绝任何国标换油指标参考，车间多数无厂内限值表，结果永远不判。
- 运行时长：阈值表无"期初累计小时"，无法回答"自上次大修累计多少"；大机组按年检修周期管理，技能只认小时。
- 备机切换：主备角色写死为台账列，实际每次切换互换；长期未切换默认 90 天比常见月/季切换周期还长。
- 工单生成定位错位：中石化炼化厂车间设备员创建的是 SAP **维修通知单**，工单由设备部/计划员创建；本技能自编 `GD-YYYYMMDD-NNN` 工单号并输出"EAM 导入 CSV"，导不进 SAP。工时定额与备件方向是承修单位职责，车间填属越界。
- 完工验收签字栏写"监理"，日常维修基本无监理；缺"三级验收（班组/车间/厂级）+ 工艺"一方。
- 大修跟踪缺"三查四定"问题台账输入与"中交"独立状态（中交≠检修完工）。
- 承包商准入缺入厂三级教育、安全协议、特种作业证复审（3 年复审逾期即无效）；维保/技术服务类承包商被硬性要求安全生产许可证。
- 现场监督风险分级自造高/中/低，未与作业票级别（特级/一级/二级用火等）挂钩，缺"双监护、JSA 交底、属地确认人"要点。
- 交叉作业 R2 把同位号"受限空间 + 用火"判高冲突并建议"人员撤出再动火"，罐内/塔内动火双票作业是合法常态，主样例就会被误报。
- 事故事件：event-notice 未衔接中石化《设备事故管理规定》分级与非计划停工事件；"内部通报无硬性时限"不准确。
- 安全环保设施范围缺安全阀/爆破片/阻火器、SIS/联锁、紧急切断阀、消防水系统；安全阀同时在 special-equipment 与 valve-calibration 两技能描述里抢触发。
- 变更管理 R4/R5 工艺参数、联锁定值属工艺/仪表归口，设备员提报越界。

## 七、功能性缺口

- **PDF 全面不读**：technical-document-finder（SKILL.md:22 列为支持，find.js:28 直接进 unreadable，三处矛盾）、regulation-compliance-check（SKILL.md 说接受，compliance.js:138 报错）、inspection-evidence-package、self-audit-form-filler、equipment-knowledge-qa、failure-case-retrieval。中石化炼化厂的规程、说明书、检查通知、案例汇编主要是 PDF。建议二选一：纯内置模块做 pdf-lite 抽文字层；或统一前置步骤"先用平台 pdf 技能转 txt/docx"，在 SKILL.md 写成标准衔接而非各写一句。
- **docx 能力不一致**：repair-plan-assistant 带 docx-lite 能读 Word，completion-acceptance 对 .docx 报错终止，而检修方案几乎全是 Word。
- **多文件合并不一致**：repeat-failure-detector、special-equipment 等"一次只读一个文件"，中石化炼化厂台账按装置分文件是常态；spare-parts-demand 多文件只取第一个命中 sheet 且无 warning。
- **宽表不支持**：parameter-trend-alert 要求用户手工转长表。
- **同比环比依赖上期 consumption.json**：首次使用拿不到，应支持从同一导出切基期。
- **周期折算不一致**：common.js 按天（月=30、年=365），special-equipment 按自然月，同一安全阀两技能到期日不同。
- **GBK 兜底静默**：`TextDecoder('gbk')` 依赖 full-icu，精简 Node 下无 warning 退回乱码；脚本产出 CSV 未核到 UTF-8 BOM。

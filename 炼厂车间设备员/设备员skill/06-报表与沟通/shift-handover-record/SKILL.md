# 设备员值班与工作交接记录（shift-handover-record）

面向中石化体系炼化厂车间（运行部）设备员。设备员常白班、不倒班，交接的是**值班交接 / 休假交接 / 调岗交接**三类工作交接，不是操作班组的交接班。本技能把交接期间的设备异常、处理情况与待办事项整理成规范的交接记录。**未完成事项必须完整传递，模型不得省略或合并任何一条待交接事项。**

## 适用条件
- 用户说"写值班交接记录 / 休假前把工作交一下 / 调岗交接 / 看一下上次交接交代的事有没有做完"，并提供交接期间的设备相关记录。
- 覆盖内容：设备状态变化、异常发现与处理、在修设备状态、未完成事项、接手人需重点关注的事项。
- 车间设备员可做：工作交接记录的整理与遗留事项核对。**不做**：事项是否可以不交接的判定、异常原因诊断、上次交接工作质量评价。
- 不适用：操作班组交接班（DCS 工艺参数、操作口径，由工艺归口）；设备日报（面向车间与上级，用 equipment-daily-report）；替代交接双方的现场确认与签字。

## 前提条件
- 输入：交接期间的记录（`.xlsx`/`.csv`，工作表「值班记录 / 工作记录 / 本次记录」），可含异常处理记录、通知单/工单状态变化、在修设备情况；列名支持 SAP PM / EM 导出常见列名（功能位置、设备描述、订单、通知单、通知单描述、系统状态、基本结束日期、主工作中心……），「设备编号 / 设备」不作位号。可选：上次交接记录（`handover.json` 或含「未完成事项」表的 xlsx，用于核对遗留事项闭环）。
- 必填信息：车间名称、交接类型（值班交接 / 休假交接 / 调岗交接）、交接时间、交接人。可选：接手人、值次说明、在修设备清单。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得基于文字手工成文或自行判定（硬约束 2）。**

## 操作步骤
1. **确认交接要素** —— 车间、交接类型、交接时间、交接人与接手人；**交接时间必须明确到具体时点，不得写"今天"这类模糊表述**。用户说"交接班"时先确认是设备员工作交接还是操作班组交接班，后者不用本技能。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/handover.js" --input "<本次记录路径>" --workshop "<车间名>" --type <值班交接|休假交接|调岗交接> --time <ISO 8601 带时区> --by "<交接人>" --out "<工作目录>/工作交接"
   ```
   可选：`--prev "<上次交接记录>"`（核对遗留事项）、`--to "<接手人>"`、`--shift "<值次说明，如 10月26日值班>"`、`--inrepair "<在修设备清单xlsx>"`。建议始终传 `--out`，否则写到系统临时目录。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（上次遗留事项未见闭环记录/时间无法解析/在修设备无状态说明等）。脚本用法详见 `scripts/README.md`。
   - 上次交接遗留事项在本次记录中找不到对应处理：**必须原样结转到本次交接事项并标注"上次交接遗留，本次未处理"，绝不静默丢弃**。
3. **读取 handover.json** —— 从 `<输出目录>/handover.json` 获取：`meta`（含 `skill: 'shift-handover-record'`、`type`）、`statusChanges`、`abnormalHandled`、`inRepair`、`pending`（未完成事项数组，含来源交接与结转次数，worklog-todo-manager 据此识别并纳入待办）、`carriedOver`、`focusItems`、`undetermined`、`statusUndetermined`、`counts`。
4. **生成交接记录** —— 按 `assets/templates/handover-template.md` 成文，含：交接信息、设备状态变化、异常与处理、在修设备状态、未完成事项（含结转项，标注来源交接）、需重点关注事项、未判定事项、交接说明、交接签字栏。**未完成事项逐条列出，每条含内容、当前状态、责任人、要求完成时间；信息缺失的写"待明确"，不得省略该条。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `handover.md` 与 `handover.json`。**必须保留说明行："交接以双方现场确认签字为准，本记录为辅助整理"，不得删除或改写。**

## 预期结果
- `handover.md`：工作交接记录，共九节（无未判定事项时第七节省略）：一、交接信息；二、设备状态变化；三、异常与处理；四、在修设备状态；五、未完成事项（含上次交接结转项）；六、需重点关注事项；七、未判定事项；八、交接说明；九、交接签字。开头与签字栏各一处说明行。
- `handover.json`：结构化交接内容，`meta.skill === 'shift-handover-record'` 且含 `pending` 数组，供下次交接核对与 worklog-todo-manager 读取；`summary.json`：脚本末行摘要。
- 交付时向用户说明：交接类型、状态变化数、异常处理数、未完成事项数（含结转项数）、重点关注事项、脚本 warnings（如有）。

## 不适用范围
- 不省略或合并未完成事项，不判定事项是否可以不交接。
- 不替代交接双方的现场确认与签字。
- 不做操作班组交接班与工艺参数交接。
- 不评价上次交接的工作质量；不做异常原因诊断（用 anomaly-triage-advisor）。

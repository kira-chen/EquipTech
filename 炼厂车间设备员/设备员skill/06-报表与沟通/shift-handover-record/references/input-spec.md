# 输入规格：设备员值班与工作交接记录

## 口径
中石化体系炼化厂车间设备员常白班、不倒班。本技能处理的是设备员之间的**值班交接 / 休假交接 / 调岗交接**（`--type`），不是操作班组的 DCS 交接班。`--type` 取值以外的（如「夜班交接班」）一律报错。

## 支持格式
- `.xlsx`（推荐）或同结构 CSV 目录（文件名 = sheet 名，UTF-8 或 GBK）
- 可一次传入多个文件，用英文逗号分隔：`--input a.xlsx,b.xlsx`

## 一、本次记录（必需，工作表「值班记录 / 工作记录 / 本次记录」）

sheet 名匹配规则：去空白与「表」字后做包含匹配，因此「值班记录」「工作记录表」「本次记录」「交接记录」「本班记录」（旧名）均可识别。

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | 设备位号；为空时**不丢弃该条事项**，位号记为「待明确」并 warning |
| 内容 | 是 | 事项内容；与位号同时为空的行才会跳过 |
| 事项类型 | 否 | 状态变化 / 异常处理 / 在修，见下方「事项类型取值」 |
| 设备名称 | 否 | |
| 处理情况 | 否 | 本次已采取的措施 |
| 状态 | 否 | 已完成 / 未完成，见下方「完成状态取值」 |
| 责任人 | 否 | 缺失时记录中写「待明确」，**不省略该条事项** |
| 要求完成时间 | 否 | 缺失时写「待明确」，**脚本不代为指定期限** |
| 时间 | 否 | 事项发生时间 |

## 二、在修设备（可选，工作表「在修设备」或 `--inrepair` 独立文件）

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | 为空的行跳过并 warning |
| 当前状态 | 否 | **缺失时输出 null 并 warning「无当前状态说明，交接时需当面确认」**，并进入重点关注，绝不猜测检修进度 |
| 设备名称 / 工单号 / 责任人 / 预计完工 | 否 | 缺失显示「待明确」 |

本次记录中事项类型为「在修」的条目，会自动补入在修设备清单（位号已存在时不重复）。

## 三、上次交接记录（可选，`--prev`）

两种形式均可：

1. **本脚本产出的 `handover.json`** —— 读取其 `pending` 数组，并沿用每条的 `originShift`/`originDue`/`carryTimes`，因此支持连续多次结转。
2. **xlsx** —— 读取「未完成事项」（或「遗留事项」「待办事项」「交接事项」）工作表：

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | |
| 内容 | 是 | 用于与本次记录做相似度匹配 |
| 责任人 / 要求完成时间 | 否 | |
| 来源交接（别名：来源、班次、来源班次） | 否 | 该事项最初来自哪次交接；缺失时以文件名标注 |

**未提供 `--prev` 时**：`carriedOver` 为 `null`，记录中写「无法核对上次交接遗留事项，接手人需人工核对上次交接记录」，**绝不因为没有上次记录就当作没有遗留事项**。

## 车间范围核对

车间列（可选）：本次记录、在修设备（含 `--inrepair`）、上次交接 xlsx 的「未完成事项」三张表都可带「车间」列。表头认 车间 / 所属车间 / 属地车间 / 运行部（全等优先，再认以它们开头的，如「车间名称」）；「维护工厂」「计划工厂」是 SAP 工厂代码，「属地单位」「使用单位」「责任单位」「作业单位」可能是部门或承包商，「车间负责人」「车间监护人」这类人员列，都不当车间列。按 `--workshop` 核对：

| 情况 | 处理 |
|---|---|
| 未带车间列 | 不筛；交接信息表「车间范围」一行写「车间范围：输入未含车间列，车间范围以取数条件为准。」（MCP 导出多数是这种情况，取数时须带 `workshop`） |
| 有本车间的行 | 剔除其他车间的行，warning 逐车间写剔除行数；车间列为空的行按本车间保留，warning 写行数 |
| 没有一行是本车间 | 不筛（避免整表剔空）；warning 以【注意】开头，记录标题后、第一节前加【注意】提示，多半是传错了文件 |

车间名比对去空白、忽略末尾「车间 / 运行部」（「常减压」与「常减压车间」视为同一车间）。各表核对结果写进 `handover.json` 的 `meta.workshopScope`（数组，每项含 `sheet` / `status`（noWorkshop / noColumn / checked / mismatch）/ `column` / `total` / `kept` / `dropped` / `droppedRows` / `blank`）。

上次交接 handover.json（`--prev`）的 `meta.workshop` 与 `--workshop` 不一致时**只提示不剔除**：warning 以【注意】开头，照常核对结转（整份不纳入会漏掉结转，结转不静默丢弃优先），由用户确认是否传错文件。

## 列名别名（局部优先，再合并中石化常用系统导出列名）

| 标准列名 | 可识别的写法 |
|---|---|
| 位号 | 位号、设备位号、TAG、功能位置、功能位置编号、技术标识、技术对象（**「设备 / 设备编号」是 SAP 8 位流水号，不作位号**） |
| 设备名称 | 设备名称、名称、设备描述、技术对象描述、功能位置描述 |
| 事项类型 | 事项类型、类型、事项、记录类型、分类 |
| 内容 | 内容、事项内容、情况、描述、问题描述、事件、通知单描述 |
| 处理情况 | 处理情况、处理、处理结果、措施、处置情况、处理措施 |
| 状态 | 状态、完成情况、是否完成、进展、当前状态、系统状态、用户状态 |
| 责任人 | 责任人、负责人、处理人、跟进人、执行人 |
| 要求完成时间 | 要求完成时间、完成时限、计划完成时间、要求完成、期限、计划完成、基本结束日期 |
| 时间 | 时间、发生时间、记录时间、发现时间、通知日期 |
| 工单号 | 工单号、工单、检修单号、单号、通知单号、维修通知单号、通知单、订单号、订单 |
| 预计完工 | 预计完工、预计完成、计划完工、计划回装、预计恢复、基本结束日期 |
| 当前状态（在修表） | 当前状态、状态、检修状态、进度、进展、系统状态 |

表头行识别：取前 10 行中命中必需列最多的一行，因此首行是标题、第三行才是表头的 EM/SAP 导出表也能读。

## 事项类型取值

| 归类 | 可识别的写法 |
|---|---|
| 状态变化 | 状态变化、状态变更、开停、切换、投用、停运、状态 |
| 异常处理 | 异常处理、异常、故障处理、故障、缺陷、处理 |
| 在修 | 在修、检修、维修、抢修、施工 |
| **未归类** | 以上都不匹配的其他文字（如「待定」）或空 |

未归类事项**单列一节**，不会被默认塞进状态变化或异常处理。

## 完成状态取值

| 归类 | 可识别的写法 |
|---|---|
| 已完成 | 已完成、完成、已闭环、闭环、已处理、处理完毕、已消除、已恢复、已回装、已投用；SAP 状态 **CLSD**（业务完成/已关闭）、通知单 **NOCO**（已完成）；已关闭、关闭、已验收、已消缺 |
| 未完成 | 未完成、未处理、未闭环、进行中、处理中、跟进中、待处理、待跟进、在修、未结束；SAP 状态 **CRTD / OSNO**（待审核）、**REL / NOPR**（已派工）、**PCNF**（施工中）；已下达、已派工、施工中、待审核 |
| 未完成（待验收） | SAP 状态 **TECO / CNF**、技术完成、完工待验、待验收、已完工 —— **技术完成不是闭环**，仍作未完成事项交接，`state` 写「未完成（待验收）」 |
| **未判定** | 以上都不匹配（如「观察中」）或空；SAP 状态 **DLFL / LKD** 及中文「已删除」（删除标记/已锁定，归已取消）也判未判定，不默认销账，由交接双方确认是否仍需跟进 |

「未」字前缀优先判定，因此「未完成」不会被「完成」误命中；否定词（未 / 待 / 没 / 没有 / 尚未 / 暂未 / 还没 / 还未）与完成、处理、闭环、恢复、消除、回装、投用、结束之间相隔 0~3 个字时同样判未完成（如「待完成」「没完成」「还没处理」「未全部完成」「还没有都完成」），中间夹「已」或标点的不算（「不再振动，已处理」仍按已完成），「未见 / 没发现」不是否定完成（「未见异常处理完毕」仍按已完成）；「不」只认紧贴动词（「不完成」「不能投用」判未完成），「不对中 / 不平衡 / 不合格品 处理完毕」里的「不」修饰名词，仍按已完成；「部分完成」「未全部」判未完成；「技术完成」先于「完成」判定，归待验收。
SAP 状态码按中石化口径对照（工单与通知单状态映射）归一（复用 `common.js` 的 `normSapStatus`），多码组合（如 `REL CNF`、`TECO NMAT`）取最靠后的状态，码表以外的英文标记忽略。SAP 状态码或归一后的六态写入 `pending[].state`，如「未完成（已派工）」。
**未判定的事项一律随本次交接（就严）**，同时单列一节说明缺哪个字段，既不按已完成销账、也不按未完成硬派责任人。

## 交接类型（`--type`）与交接时间（`--time`）

- `--type`：`值班交接` / `休假交接` / `调岗交接`，必填。`--shift` 可选，只作值次说明标签。
- `--time` **必须是带时区的 ISO 8601 时点**，如 `2026-09-21T17:00:00+08:00`。以下一律报错并退出 1：`今天下午`、`2026-09-21`（无时点）、`2026-09-21T17:00:00`（无时区）、非法月日。记录中同时显示北京时间与原始 ISO 入参。
- 记录中的「要求完成时间」是北京时间墙钟，判断「已超过交接时点」时统一按 +08:00 解析，与运行主机的时区无关。

## 会被跳过的行
- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 提示）
- 位号与内容**同时**为空的行（warning 提示）

> 位号单独为空**不跳过** —— 交接的原则是不丢事，宁可记「待明确」也不删条目。

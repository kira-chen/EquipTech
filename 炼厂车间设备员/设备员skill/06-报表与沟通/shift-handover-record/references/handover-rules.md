# 交接口径与表述规范

## 〇、这是哪一种交接

中石化体系炼化厂车间设备员常白班、不倒班。本技能的交接对象是**设备员之间**的三类工作交接：

| 类型 | 场景 |
|---|---|
| 值班交接 | 节假日、夜间设备员值班结束，把值班期间的设备事项交给下一值或回到常白班的设备员 |
| 休假交接 | 设备员休假前，把在办事项、在修设备、未闭环通知单交给代管人 |
| 调岗交接 | 设备员调岗、离岗，把全部在办事项与台账交给接任人 |

操作班组的 DCS 交接班（工艺参数、操作口径）**不在本技能范围**，用户提到「交接班」时先问清。

## 一、不丢事原则（本技能的底线）

交接记录的唯一目的是**把事完整传给接手人**。因此：

- 任何一条未完成事项，无论信息多不全，都必须出现在记录里。
- 信息缺失写「待明确」，**绝不因为责任人没填、期限没写就省略该条**。
- 位号没填就记「待明确」，**不因为位号为空而删除整条事项**。
- 完成状态看不出来的，既不按已完成销账，也不按未完成硬派责任，单列「未判定」交由交接双方现场明确。

## 二、结转规则（重中之重）

上次交接的每一条未完成事项，都要在本次记录中找对应的处理/闭环记录。匹配方式：**位号 + 事项内容相似度**。

| 情形 | 处理 | 标注 |
|---|---|---|
| 本次有记录且已闭环 | 不结转 | 计入 `prevClosed` |
| 本次有记录但未闭环 | 结转 | 「上次交接遗留，本次已跟进但未闭环」 |
| 本次无对应记录 | **原样结转** | 「上次交接遗留，本次未处理」 |

### 硬约束

- **绝不静默丢弃**。上次交接交代过的事，本次没处理，就必须原样出现在本次交接事项里。
- **绝不自动延期**。结转项保留 `originDue`（原始要求完成时间），哪怕已经超期也照原样写。是否调整期限，由交接双方现场确认，脚本与模型都无权改。
- **来源记到最初那次交接**。E-1201 是 9 月 20 日值班交接交下来的，本次没闭环，那再交给下一位时，来源仍写 9 月 20 日值班交接。`carryTimes` 记录累计结转了几次。
- **连续多次可追溯**。第三次交接读第二次的 `handover.json` 时，仍能看到第一次的遗留项、最初来源与原始期限。

### 匹配阈值

位号完全相同时，位号本身已是强证据，内容只需弱相似（0.2）即认为对应；位号缺失只能靠内容匹配，阈值从严（0.6），**宁可多结转一条，也不把不相干的事项误判为已跟进而漏掉结转**。

## 三、交接时间

必须明确到**时点**，且带时区。「今天下午」「下班前」这类表述一律不接受 —— 交接时间是责任划分的边界，含糊不得。

## 四、需重点关注事项的口径

以下自动进入重点关注，不由模型自行取舍：

1. 全部结转项（含最初来源与原始期限）
2. 要求完成时间已超过交接时点的未完成事项
3. 无当前状态说明的在修设备
4. 完成状态未判定的事项

## 五、表述规范

撰写交接说明 150~300 字，结构固定为四段：

1. **交接期间设备总体情况**：状态变化数、异常处理数与闭环数、在修设备数。
2. **异常与处理要点**：发现了什么、做了什么处理、处理到什么程度。只陈述记录中写明的内容。
3. **未完成事项与结转项交代**：未完成几条、其中结转几条、分别是哪次交接交下来的。
4. **接手人需重点关注**：结转项、超期项、在修待确认项。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 结转项 | 「P-1105A 护罩螺栓缺失，9 月 20 日值班交接交下来的，本次未处理，原要求完成时间 09-21 12:00」 | 「P-1105A 待补装」（隐去来源与原期限） |
| 期限 | 「原始要求完成时间 09-21 12:00，已超期，是否顺延请交接双方确认」 | 「顺延至明日」 |
| 责任人缺失 | 「责任人待明确」 | 省略该条 / 自行指派 |
| 在修设备 | 「E-1205 无当前状态说明，需当面确认」 | 「E-1205 检修中」 |
| 异常处理 | 「已降负荷观察，已通知动设备工程师」 | 「已处理完毕」 |
| 通知单/工单 | 「已提维修通知单 10000203，订单未下达」 | 「已报修」（不写单号） |
| 数字 | 引用 handover.json 的 counts | 自行统计 |

### 硬约束

- **不省略、不合并任何一条未完成事项**。两条看起来相似的事项也分别列出。
- **不判定某条事项「可以不交接」**。交不交接不由模型决定。
- **不评价上次交接的工作质量**。只陈述事项状态，不写「上次未按时完成」这类评价。
- **不做故障原因诊断**。异常只复述记录内容，原因判断交由 `anomaly-triage-advisor`。
- **不替代现场确认与签字**。记录中必须保留声明行：「交接以双方现场确认签字为准，本记录为辅助整理」。
- 产出 md 不用 emoji，醒目提示用「【注意】」。

## 六、无结构化输入时

只有文字描述、无法运行脚本时，**不得手工成文**（硬约束 2）：告知用户先把事项整理成「值班记录」表格再运行脚本，或明确告知当前环境无法执行 node 并终止。

## 七、下游衔接

- `handover.json`（`meta.skill === 'shift-handover-record'` 且含 `pending` 数组）→ `worklog-todo-manager` 自动纳入待办，期限原样保留
- 未完成事项需登记为缺陷（维修通知单）→ `defect-intake-grading`
- 异常项需初步判断原因 → `anomaly-triage-advisor`
- 交接期间情况进设备日报 → `equipment-daily-report`

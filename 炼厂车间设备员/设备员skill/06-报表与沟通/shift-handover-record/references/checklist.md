# 交付自检清单

运行脚本后、交付前逐项核对。

## 脚本执行
- [ ] `--type` 是 值班交接 / 休假交接 / 调岗交接 之一；用户说的「交接班」已确认不是操作班组交接班
- [ ] 末行 JSON 的 `ok` 为 `true`；若为 `false`，已把 `error` 原文告知用户并终止，未手工汇总
- [ ] `warnings` 已逐条告知用户，未隐去任何一条
- [ ] `handover.json`（`meta.skill === 'shift-handover-record'`，`pending` 为数组）与 `handover.md` 均已生成

## 结转项（重中之重）
- [ ] 已提供 `--prev`；若未提供，已明确告知用户「无法核对上次交接遗留事项，需人工核对上次交接记录」
- [ ] `carriedOver` 中每一条都出现在记录的未完成事项一节，**无一条被省略或合并**
- [ ] 每条结转项都标注了「上次交接遗留，本次未处理」或「上次交接遗留，本次已跟进但未闭环」
- [ ] 每条结转项都写明了**最初来源交接**与**原始要求完成时间**
- [ ] 结转项的期限**未被自动延期**，超期的照原样写并提示交接双方确认
- [ ] 连续结转的事项，来源指向**最初**那次交接，不是上一次

## 未完成事项完整性
- [ ] `counts.pending` 与记录中列出的条数一致，逐条可数
- [ ] 每条都含：事项内容、当前状态、责任人、要求完成时间
- [ ] 信息缺失的写「待明确」，**未省略该条**
- [ ] 位号为空的事项仍在列，位号记「待明确」

## 时间与数字
- [ ] 交接时间明确到时点，含北京时间与原始 ISO 入参
- [ ] 报告中每个数字都能在 `handover.json` 的 `counts` 中找到对应，未自行统计
- [ ] 在修设备无状态说明的，显示「待明确（无状态说明，需当面确认）」，未出现编造的检修进度

## 未判定
- [ ] 事项类型未判定、完成状态未判定各自单列，注明缺哪个字段
- [ ] 未判定事项既未按已完成销账，也未按未完成硬派责任人

## 交接说明段
- [ ] 已替换 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字
- [ ] 字数 150~300
- [ ] 四段结构齐全：总体情况、异常与处理、未完成与结转、接手人重点关注
- [ ] 未评价上次交接工作质量，未做故障原因诊断

## 声明行与术语
- [ ] 记录中保留了「交接以双方现场确认签字为准，本记录为辅助整理」，**未删除、未改写**
- [ ] 记录中未出现「交接班」「上班次」「交班人/接班人」等倒班口径用语；无 emoji
- [ ] 无结构化输入时未手工成文，已告知用户整理成表格后再运行

## 交付说明
- [ ] 已向用户说明：交接类型、状态变化数、异常处理数、未完成事项数（含结转项数）、重点关注事项、脚本 warnings
- [ ] 已提示结转项需交接双方现场确认期限
- [ ] 已提示 `handover.json` 可直接交 `worklog-todo-manager` 生成待办；未完成事项较多时可接 `defect-intake-grading` 登记维修通知单

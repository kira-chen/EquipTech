# 设备日报口径与表述规范（中石化体系炼化厂车间设备员）

## 一、与同类报表的边界

| | 本技能（equipment-daily-report） | unit-daily-report | turnaround-workshop-tracker | equipment-weekly-monthly-report |
|---|---|---|---|---|
| 口径 | **设备口径，按日** | 工艺口径 | 大检修项目进度 | 设备口径，按周/月 |
| 内容 | 六档状态、特护设备、缺陷/工单、作业票、泄漏点、隐患、异常事件、检修进度 | 物料平衡、收率、工艺参数、能耗、质量 | 大修项目进度、开工条件、滞后预警 | 完好率、泄漏率、故障停机、计划完成率等月度指标 |
| 用户说法 | 「设备日报」「今天设备情况」「特护设备日报」 | 「装置日报」「运行日报」「生产日报」 | 「大修日报」「大修进度」 | 「设备周报」「设备月报」 |

用户说「装置日报」改用 `unit-daily-report`；说「大修日报 / 大修进度日报」改用 `turnaround-workshop-tracker`；本技能的「检修进度」一节只是转录在施项目进度表。

## 二、数据来源

1. **上游技能 JSON**（推荐）：`status.json`（巡检汇总）、`orders.json`（工单跟踪）、`defects.json`（缺陷登记）、`leaks.json`（泄漏点跟踪）、`hazard.json`（隐患跟踪）。脚本按特征字段自动识别类型。
2. **xlsx**：含「巡检汇总」「特护设备」「缺陷台账（通知单）」「工单台账（订单）」「作业票」「泄漏点」「隐患台账」「异常事件」「检修进度」任一工作表，列名支持 SAP PM / 智能巡检 / 作业许可系统导出列名。

同一类数据只取第一个来源，重复提供时后者忽略。

## 三、口径（脚本已落实，模型只复述）

| 项 | 口径 | 依据 |
|---|---|---|
| 设备状态 | **运行 / 备用 / 检修 / 停用 / 异常 / 未判定** 六档；空值与无法归档进未判定，不计运行 | 《中石化口径对照.md》第六节 |
| 缺陷 / 工单状态 | SAP 六态（待审核 / 已派工 / 施工中 / 待验收 / 已闭环 / 已取消）；**「已完成 / 完工 / TECO / 技术完成」是待验收，不是闭环**；流程是完工 → 验收 → 关闭 | 第四节 |
| 缺陷等级 | A 级（重大）/ B 级（严重）/ C 级（一般），以台账为准不重判 | 第三节 |
| 特护设备 | 大机组、关键机组逐台列状态与运行参数；趋势判断由设备员复核 | 第六节「特护设备运行状况」 |
| 作业票 | 八大类口径，「动火」写「用火」；级别以票面为准，脚本不自判；双监护（属地监护人 + 作业单位监护人）未填只提示 | 《中国石化作业许可管理规定》，第五节 |
| 泄漏点 | 日报只列点数（新增/未修复/超期/已修复）；静/动密封点泄漏率按月在周报月报核算 | 第六节 |
| 隐患 | 只认重大隐患 / 一般隐患；「A/B/C 级」是多数厂的管理层级，不映射；一般隐患无统一天数，期限以整改方案（**五定**：方案、资金、责任人、期限、应急措施）为准，无期限列未判定；认定与验收以安全部门意见为准 | 《中国石化安全隐患管理规定》，第七节 |

## 四、缺数据的处理（硬规则）

未提供的章节：JSON 中对应 counts 为 `null`，报告中写「_本日未提供 XX 数据。_」。

**禁止**：用 0 值填充、用推算值补齐、把「未提供」写成「无异常」。「无异常」与「未提供数据」是两回事：前者是巡检做了且都正常，后者是根本没数据。混淆二者会让领导误以为设备都好，这是设备日报最危险的失真。

上游 `status.json` 只有正常/异常/未判定三档时，备用/检修/停用台数写「—（未提供）」，不得按 0。

## 五、分析段表述规范

撰写 250~400 字，结构固定七段：

1. **总体状况**：涉及设备、六档台数、整体评价一句话。
2. **特护设备**：逐台点名状态，参数只复述记录值，不下趋势结论。
3. **异常与缺陷**：异常设备、新增通知单、未闭环缺陷（其中待验收几条）。只复述记录内容。
4. **工单与作业**：工单未闭环/待验收/超期，当日作业票张数与类别，属地监护人未填的点名。
5. **泄漏点与隐患**：未修复与超期泄漏点、重大隐患与超期隐患，逐条列责任人与期限。
6. **需协调或上报事项**：需要车间设备主任或分厂/公司设备管理部门出面协调的事，写清楚卡在哪。
7. **次日重点**：明日要盯的设备与事项。

### 未闭环事项的写法

**每一条未闭环事项必须列出责任人与计划完成时间。** 台账中没记录的写「未记录」，不得留空、不得推测。

```
P-1101B 机封更换（WO-2609001），责任人检修一队，计划完成 2026-09-22。
V-1301 保温层破损（通知单 10044980）已完工待验收，验收人未记录。
```

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 异常原因 | 「巡检记录机封滴漏」 | 「机封老化导致泄漏」 |
| 缺数据 | 「本日未提供检修进度数据」 | 「检修进度正常」 |
| 待验收 | 「已完工待验收 1 条」 | 「已闭环」「已消缺」 |
| 超期 | 「超期 5 天，责任方一队」 | 「一队拖延」 |
| 作业票 | 「二级用火作业 1 张」 | 「动火票」「级别应为一级」 |
| 隐患 | 「重大隐患 1 项，整改期限 10-01」 | 「隐患不严重」「可缓一缓」 |
| 环比 | 「异常设备较上一日 +2」 | 「设备状况恶化」 |

### 硬约束

- **数字一律引用 daily.json**，不得自行统计。
- **不做故障原因诊断**，不判定责任；**不做事故定性**与损失估算。
- **不重新判定设备状态、缺陷等级、隐患等级、作业票级别**，以上游记录为准。
- **不代拟次日计划**。次日计划由车间提供，未提供时保留占位说明。
- 声明行「本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。」由脚本写入，不得删改。

## 六、Word 交付

用户要 Word 时：平台具备 docx 能力（docx 技能或 pandoc）则转换后交付；否则交付 `.md` 并告知「当前环境无法生成 docx，可用 Word 直接打开或粘贴 Markdown」。**不得手写 docx XML 拼装文件。**

## 七、上下游衔接

```
inspection-data-digest  → status.json  ┐
defect-intake-grading   → defects.json │
work-order-tracker      → orders.json  ├→ equipment-daily-report → daily.json → equipment-weekly-monthly-report
leak-point-tracker      → leaks.json   │
hazard-closure-tracker  → hazard.json  ┘
```

日报的 `daily.json` 是周报月报的输入，`meta.date`、`counts.equipment` 等字段结构保持稳定；新增 `status.byState`、`special`、`permits`、`leaks`、`hazards` 为追加字段，不改既有键。

# 输入规格：车间设备日报

## 两类输入

### 1. 上游技能 JSON（推荐）

| 文件 | 来源技能 | 识别特征 | 提供的章节 |
|---|---|---|---|
| `status.json` | inspection-data-digest | 含 `byEquipment` 与 `abnormal` | 一、设备状态概览（有 `counts.sixTier` 时直接取六档；旧版只有正常/异常/未判定三档 → 运行/异常/未判定，备用/检修/停用为 null 并 warning）、异常清单；二、特护设备（`byEquipment[].special` 为真的逐台列出，状态取 `stateCn`，异常描述取 `abnormal[]`） |
| `orders.json` | work-order-tracker | 含 `byStatus` 或 `metrics.closeRate` | 四、工单执行；待验收取 `counts.pendingAccept`，否则取 `byStatus['待验收']` |
| `defects.json` | defect-intake-grading | 含 `defects` 与 `counts.byLevel` | 三、新增缺陷 |
| `leaks.json` | leak-point-tracker | 含 `counts.leaks` 与 `repaired` | 六、泄漏点（`counts.{leaks,newLeaks,open,overdue,repaired,undetermined}`、`metrics.repairRate`、`overdue[]`） |
| `hazard.json` | hazard-closure-tracker | 含 `majorHazards` | 七、隐患（`counts.{total,overdue,dueSoon,inProgress,closed,major,unverified,undetermined}`、`metrics.closureRate`、`overdue[]`、`majorHazards[]`） |

多个 JSON 用逗号分隔传入：`--input a/status.json,b/orders.json`。样例见演示样例的 `upstream/` 目录。
无法识别类型的 JSON 会 warning 并忽略，不中断。

### 2. xlsx 工作表

sheet 名匹配去空白与「表」字后包含匹配。列名先全等后前缀；别名表 = 局部别名 + 共享 `SYSTEM_ALIASES`（SAP PM/MM、EM、作业许可、特种设备、智能巡检导出列名，见《中石化口径对照.md》第二节），局部优先。

**特别说明**：`设备编号`（SAP 8 位流水号、EM 编码）**不是位号**，本技能不把它当位号别名；位号认 位号 / 设备位号 / 功能位置 / 功能位置编号 / 技术标识 / 技术对象 / TAG。`描述` 在缺陷/隐患/事件表里归内容列，不归设备名称；设备名称认 设备名称 / 名称 / 设备描述 / 技术对象描述 / 功能位置描述。

#### 巡检汇总（sheet：巡检汇总 / 设备状态 / 巡检记录）
| 列名 | 必需 | 别名（节选） | 说明 |
|---|---|---|---|
| 位号 | 是 | 功能位置、技术对象、TAG | |
| 设备名称 | 否 | 设备描述、名称 | |
| 状态 | 否 | 系统状态、处理状态、当前状态 | 六档归一规则见下 |
| 异常描述 | 否 | | |
| 重要度 | 否 | 设备分级、ABC标识、关键等级、特护 | 含「特护」的行进特护设备节 |
| 运行参数 | 否 | 参数、主要参数、关键参数、运行工况 | 特护设备逐台列出，原样展示 |

**状态六档归一**（《中石化口径对照.md》第六节「设备状态」）：

| 判定 | 命中词 |
|---|---|
| 备用 | 备用、备机、standby、热备、冷备 |
| 检修 | 检修、在修、维修中、修理中、大修、检修中 |
| 停用 | 停用、停运、封存、闲置、长期停、退役、报废 |
| 运行 | 运行、在用、运转；以及 classifyResult 判为正常的（正常、无异常、未见异常、OK、Running……） |
| 异常 | classifyResult 判为异常的（异常、不合格、故障、泄漏、报警、NG……） |
| 未判定 | 空值、无法归入上述五档（如「待定」） |

未判定**不计入运行**，在 md 单列「【未判定】N 台」。

#### 特护设备（sheet：特护设备 / 特护 / 特护日报 / 特护机组）
| 列名 | 必需 |
|---|---|
| 位号 | 是 |
| 设备名称 / 状态 / 运行参数 / 异常描述 / 备注 | 否 |

有此表时优先；无此表时取巡检汇总中重要度含「特护」的行；两者都无 → 「本日未提供特护设备数据」。

#### 缺陷台账（sheet：缺陷台账 / 缺陷 / 通知单）
| 列名 | 必需 | 别名（节选） | 说明 |
|---|---|---|---|
| 位号 | 是 | 功能位置 | |
| 通知单号 | 否 | 通知单、维修通知单号、通知单编号 | 车间设备员创建的是维修通知单 |
| 缺陷描述 | 否 | 描述、通知单描述、通知单短文本 | |
| 等级 | 否 | 缺陷等级、级别 | 原样展示，不重新判定；口径为 A/B/C 三级 |
| 状态 | 否 | 通知单状态、系统状态 | SAP 六态归一：OSNO→待审核、NOPR→已派工、NOCO→已闭环；「已完成/完工/TECO」→**待验收**，单列不算闭环；已取消不计 |
| 发现时间 | 否 | 通知日期、通知单日期、报告日期 | 等于日报日期的计为「本日新增」 |

#### 工单台账（sheet：工单台账 / 工单 / 订单）
| 列名 | 必需 | 别名（节选） | 说明 |
|---|---|---|---|
| 工单号 | 是 | 订单、订单号、PM订单、维修订单号 | |
| 位号 | 否 | 功能位置 | |
| 状态 | 否 | 系统状态、用户状态、工单状态 | CRTD/REL/PCNF 未闭环；TECO/CNF **待验收**；CLSD 闭环；DLFL/LKD 不计 |
| 要求完成时间 | 否 | 基本结束日期、计划完成、要求结束 | 早于日报日期且未闭环判为超期 |
| 责任人 | 否 | 负责人、承办人 | 为空时取 工作中心 / 主工作中心 / 承修单位 |

#### 作业票（sheet：作业票 / 作业许可 / 许可证 / 作业票清单 / 以「作业清单」开头的表）

「检修作业清单」这类表名不以「作业清单」开头的，是检修项目表，不按作业票读取（仍可按检修进度读取）。

| 列名 | 必需 | 别名（节选） | 说明 |
|---|---|---|---|
| 许可证编号 | 是 | 作业票编号、票号、许可证号 | |
| 作业类别 | 否 | 作业类型、许可类别 | 「动火」统一显示为「用火」（八大类口径） |
| 作业级别 | 否 | 作业等级、动火级别、用火级别 | 原样展示，脚本不自判级别 |
| 作业地点 / 位号 / 作业单位 / 属地监护人 / 状态 | 否 | 作业区域、区域；施工单位、承包商；属地监护、车间监护人 | 属地监护人未填只计数提示（双监护） |

#### 泄漏点（sheet：泄漏点 / 漏点 / 密封点 / LDAR）
| 列名 | 必需 | 别名 | 说明 |
|---|---|---|---|
| 密封点编号 | 是 | 漏点编号、泄漏点编号、密封点号 | |
| 位号 / 状态 / 发现时间 / 责任人 / 整改期限 | 否 | | 状态「已修复/已消除/已整改」或闭环词为已修复；整改期限早于日报日期且未修复判超期 |

表输入**不算修复率与泄漏率**（修复率来自 leaks.json；泄漏率在周报月报）。

#### 隐患台账（sheet：隐患台账 / 隐患）
| 列名 | 必需 | 别名 | 说明 |
|---|---|---|---|
| 隐患描述 | 是 | 隐患内容、问题描述 | |
| 隐患等级 | 否 | 等级、级别 | 只认「重大隐患 / 一般隐患」；「A/B/C 级」多为管理层级，不映射，原文展示并 warning |
| 整改期限 | 否 | 期限、要求整改期限、要求整改完成日期、截止日期 | 无期限 → 未判定（不默认 30 天） |
| 整改状态 | 否 | 状态、处理状态 | 完成态（已整改 / 已完成 / 整改完毕 / 整改完成 / 已闭环 / 已销号 / 已处理 / 完成）且有验收记录 → 已闭环；完成态无验收记录 → 已整改未验收，单列，不计闭环、不判超期；其余未闭环的按整改期限判超期。「整改未完成」「暂未完成」「尚未闭环」「部分完成」「整改中」等不算完成态；「已整改未销号」以完成词开头，按完成态交验收判定。判定顺序与 hazard-closure-tracker 的 classifyStatus 一致；状态为「已闭环」也要有验收记录才计已闭环 |
| 验收情况 | 否 | 验收结论、验收结果、复查情况、是否验收 | 含「未验收 / 不合格 / 未通过 / 否 / 待验收 / 未复查」→ 未通过；含「已验收 / 验收合格 / 合格 / 通过 / 符合 / 是 / 已销号 / 已确认」→ 通过；其他写法 warning，按无验收记录处理 |
| 验收人 | 否 | 验收负责人、复查人、确认人 | 独立列。验收情况为空时，填了验收人或验收日期即算有验收记录；验收情况明确未通过时，填了也不算 |
| 验收日期 | 否 | 验收时间、复查日期、销号日期 | 同上；无法解析的 warning |
| 隐患编号 / 责任人 / 位号 / 通知单号 | 否 | 隐患编码 | 编号优先取隐患编号 |

隐患各档互不重叠：整改中（有期限未超期）+ 超期未整改 + 未判定（无期限）+ 已整改未验收 + 已闭环 = 隐患总数。HSE 管理平台导出的「等级」列为「重大 / 一般」，按重大隐患 / 一般隐患识别。

## 车间范围核对

车间列（可选）：巡检汇总、特护设备、缺陷台账、工单台账、作业票、泄漏点、隐患台账、异常事件、检修进度九张表都可带「车间」列。表头认 车间 / 所属车间 / 属地车间 / 运行部（表头正好是这四个名字，或其后加「名称」，如「车间名称」）；「维护工厂」「计划工厂」是 SAP 工厂代码，「属地单位」「使用单位」「责任单位」「作业单位」可能是部门或承包商，「车间负责人」「车间监护人」这类人员列，都不当车间列。按 `--workshop` 核对：

| 情况 | 处理 |
|---|---|
| 未带车间列 | 不筛；日报开头「数据来源」下的口径行写「车间范围：输入未含车间列，车间范围以取数条件为准。」（MCP 导出多数是这种情况，取数时须带 `workshop`） |
| 有本车间的行 | 剔除其他车间的行，warning 逐车间写剔除行数；车间列为空的行按本车间保留，warning 写行数 |
| 没有一行是本车间 | 不筛（避免整表剔空）；warning 以【注意】开头，日报标题后、第一节前加【注意】提示，多半是传错了文件 |

车间名比对去空白、忽略末尾「车间 / 运行部」（「常减压」与「常减压车间」视为同一车间）。各表核对结果写进 `daily.json` 的 `meta.workshopScope`（数组，每项含 `sheet` / `status`（noWorkshop / noColumn / checked / mismatch）/ `column` / `total` / `kept` / `dropped` / `droppedRows` / `blank`）。

上游 JSON 车间核对：status.json / orders.json / defects.json / leaks.json / hazard.json 以及 `--prev` 的上一日 daily.json，取 `meta.workshop`（没有再看顶层 `workshop`），与 `--workshop` 比对（规则同上）：一致的纳入；不一致的**不纳入**，warning 写明文件名和两个车间名，日报开头加【注意】；未注明车间的照常纳入，口径处写「上游 JSON 未注明车间，无法核对」。结果写进 `daily.json` 的 `meta.upstreamWorkshop`（`matched` / `unknown` / `excluded`）。上游 A 类技能新增的 `meta.workshopScope` 字段不影响识别与读取。`--prev` 车间不一致时不做环比。

## 完成比例的处理

| 输入 | 处理 |
|---|---|
| `60` | 60% |
| `0.6` | 60%（小于等于 1 且非 0 时按小数理解） |
| `150` | **null**，warning「超出 0~100 范围」 |
| `-10` | **null**，warning |
| `快好了` | **null**，warning「无法解析」 |
| 空 | null，显示「—」 |

**绝不按 0 计**，也不截断到合理范围后呈现。

## 其他参数

| 参数 | 说明 |
|---|---|
| `--prev` | 上一日 `daily.json`，用于环比（异常设备、超期工单、未闭环缺陷、未修复泄漏点、超期隐患）；文件不存在时报错 |
| `--shift` | 值班信息，写入报告头部 |
| `--plan` | 次日计划文本或文件路径；**未提供时不代拟** |

## 会被跳过的行
- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning）

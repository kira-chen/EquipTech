# 输入规格：车间设备日报

## 两类输入

### 1. 上游技能 JSON（推荐）

| 文件 | 来源技能 | 识别特征 | 提供的章节 |
|---|---|---|---|
| `status.json` | inspection-data-digest | 含 `byEquipment` 与 `abnormal` | 一、设备状态概览（只有正常/异常/未判定三档 → 运行/异常/未判定；备用/检修/停用为 null 并 warning）、异常清单 |
| `orders.json` | work-order-tracker | 含 `byStatus` 或 `metrics.closeRate` | 四、工单执行；待验收取 `counts.pendingAccept`，否则取 `byStatus['待验收']` |
| `defects.json` | defect-intake-grading | 含 `defects` 与 `counts.byLevel` | 三、新增缺陷 |
| `leaks.json` | leak-point-tracker | 含 `counts.leaks` 与 `repaired` | 六、泄漏点（`counts.{leaks,newLeaks,open,overdue,repaired,undetermined}`、`metrics.repairRate`、`overdue[]`） |
| `hazard.json` | hazard-closure-tracker | 含 `majorHazards` | 七、隐患（`counts.{total,overdue,dueSoon,inProgress,closed,major,unverified,undetermined}`、`metrics.closureRate`、`overdue[]`、`majorHazards[]`） |

多个 JSON 用逗号分隔传入：`--input a/status.json,b/orders.json`。样例见 `examples/upstream/`。
无法识别类型的 JSON 会 warning 并忽略，不中断。

### 2. xlsx 工作表

sheet 名匹配去空白与「表」字后包含匹配。列名先全等后前缀；别名表 = 局部别名 + 共享 `SYSTEM_ALIASES`（SAP PM/MM、EM、作业许可、特种设备、智能巡检导出列名，见《中石化口径对照.md》第二节），局部优先。

**特别说明**：`设备编号`（SAP 8 位流水号、EM 编码）**不是位号**，本技能不把它当位号别名；位号认 位号 / 设备位号 / 功能位置 / 功能位置编号 / 技术标识 / 技术对象 / TAG。`描述` 在缺陷/隐患/事件表里归内容列，不归设备名称；设备名称认 设备名称 / 名称 / 设备描述 / 技术对象描述 / 功能位置描述。

#### 巡检汇总（sheet：巡检汇总 / 设备状态 / 巡检记录）
| 列名 | 必需 | 别名（节选） | 说明 |
|---|---|---|---|
| 位号 | 是 | 功能位置、技术对象、TAG | |
| 设备名称 | 否 | 设备描述、名称 | |
| 状态 | 否 | 系统状态、处理状态、当前状态 | 六档归一规则见下 |
| 异常描述 | 否 | | |
| 重要度 | 否 | 设备分级、ABC标识、关键等级、特护 | 含「特护」的行进特护设备节 |
| 运行参数 | 否 | 参数、主要参数、关键参数、运行工况 | 特护设备逐台列出，原样展示 |

**状态六档归一**（《中石化口径对照.md》第六节「设备状态」）：

| 判定 | 命中词 |
|---|---|
| 备用 | 备用、备机、standby、热备、冷备 |
| 检修 | 检修、在修、维修中、修理中、大修、检修中 |
| 停用 | 停用、停运、封存、闲置、长期停、退役、报废 |
| 运行 | 运行、在用、运转；以及 classifyResult 判为正常的（正常、无异常、未见异常、OK、Running……） |
| 异常 | classifyResult 判为异常的（异常、不合格、故障、泄漏、报警、NG……） |
| 未判定 | 空值、无法归入上述五档（如「待定」） |

未判定**不计入运行**，在 md 单列「【未判定】N 台」。

#### 特护设备（sheet：特护设备 / 特护 / 特护日报 / 特护机组）
| 列名 | 必需 |
|---|---|
| 位号 | 是 |
| 设备名称 / 状态 / 运行参数 / 异常描述 / 备注 | 否 |

有此表时优先；无此表时取巡检汇总中重要度含「特护」的行；两者都无 → 「本日未提供特护设备数据」。

#### 缺陷台账（sheet：缺陷台账 / 缺陷 / 通知单）
| 列名 | 必需 | 别名（节选） | 说明 |
|---|---|---|---|
| 位号 | 是 | 功能位置 | |
| 通知单号 | 否 | 通知单、维修通知单号、通知单编号 | 车间设备员创建的是维修通知单 |
| 缺陷描述 | 否 | 描述、通知单描述、通知单短文本 | |
| 等级 | 否 | 缺陷等级、级别 | 原样展示，不重新判定；口径为 A/B/C 三级 |
| 状态 | 否 | 通知单状态、系统状态 | SAP 六态归一：OSNO→待审核、NOPR→已派工、NOCO→已闭环；「已完成/完工/TECO」→**待验收**，单列不算闭环；已取消不计 |
| 发现时间 | 否 | 通知日期、通知单日期、报告日期 | 等于日报日期的计为「本日新增」 |

#### 工单台账（sheet：工单台账 / 工单 / 订单）
| 列名 | 必需 | 别名（节选） | 说明 |
|---|---|---|---|
| 工单号 | 是 | 订单、订单号、PM订单、维修订单号 | |
| 位号 | 否 | 功能位置 | |
| 状态 | 否 | 系统状态、用户状态、工单状态 | CRTD/REL/PCNF 未闭环；TECO/CNF **待验收**；CLSD 闭环；DLFL/LKD 不计 |
| 要求完成时间 | 否 | 基本结束日期、计划完成、要求结束 | 早于日报日期且未闭环判为超期 |
| 责任人 | 否 | 负责人、承办人 | 为空时取 工作中心 / 主工作中心 / 承修单位 |

#### 作业票（sheet：作业票 / 作业许可 / 许可证）
| 列名 | 必需 | 别名（节选） | 说明 |
|---|---|---|---|
| 许可证编号 | 是 | 作业票编号、票号、许可证号 | |
| 作业类别 | 否 | 作业类型、许可类别 | 「动火」统一显示为「用火」（八大类口径） |
| 作业级别 | 否 | 作业等级、动火级别、用火级别 | 原样展示，脚本不自判级别 |
| 作业地点 / 位号 / 作业单位 / 属地监护人 / 状态 | 否 | 施工单位、承包商；属地监护、车间监护人 | 属地监护人未填只计数提示（双监护） |

#### 泄漏点（sheet：泄漏点 / 漏点 / 密封点 / LDAR）
| 列名 | 必需 | 别名 | 说明 |
|---|---|---|---|
| 密封点编号 | 是 | 漏点编号、泄漏点编号、密封点号 | |
| 位号 / 状态 / 发现时间 / 责任人 / 整改期限 | 否 | | 状态「已修复/已消除/已整改」或闭环词为已修复；整改期限早于日报日期且未修复判超期 |

表输入**不算修复率与泄漏率**（修复率来自 leaks.json；泄漏率在周报月报）。

#### 隐患台账（sheet：隐患台账 / 隐患）
| 列名 | 必需 | 别名 | 说明 |
|---|---|---|---|
| 隐患描述 | 是 | 隐患内容、问题描述 | |
| 隐患等级 | 否 | 等级、级别 | 只认「重大隐患 / 一般隐患」；「A/B/C 级」多为管理层级，不映射，原文展示并 warning |
| 整改期限 | 否 | 期限、要求整改完成日期、截止日期 | 无期限 → 未判定（不默认 30 天） |
| 状态 / 责任人 / 位号 / 通知单号 | 否 | | |

#### 异常事件（sheet：异常事件 / 事件）
| 列名 | 必需 |
|---|---|
| 事件描述 | 是 |
| 时间 / 位号 / 影响 / 处置措施 / 状态 | 否 |

#### 检修进度（sheet：检修进度 / 检修）
| 列名 | 必需 | 说明 |
|---|---|---|
| 项目名称 | 是 | |
| 完成比例 | 否 | 见下方处理规则 |
| 位号 / 状态 / 计划完成 / 责任人 | 否 | |

## 完成比例的处理

| 输入 | 处理 |
|---|---|
| `60` | 60% |
| `0.6` | 60%（小于等于 1 且非 0 时按小数理解） |
| `150` | **null**，warning「超出 0~100 范围」 |
| `-10` | **null**，warning |
| `快好了` | **null**，warning「无法解析」 |
| 空 | null，显示「—」 |

**绝不按 0 计**，也不截断到合理范围后呈现。

## 其他参数

| 参数 | 说明 |
|---|---|
| `--prev` | 上一日 `daily.json`，用于环比（异常设备、超期工单、未闭环缺陷、未修复泄漏点、超期隐患）；文件不存在时报错 |
| `--shift` | 值班信息，写入报告头部 |
| `--plan` | 次日计划文本或文件路径；**未提供时不代拟** |

## 会被跳过的行
- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning）

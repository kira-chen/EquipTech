# 输入规格：设备周报月报

## 一、`--input` 接受的三种形式

| 形式 | 写法 | 说明 |
|---|---|---|
| 目录 | `--input "/path/日报目录"` | 自动扫描目录内所有 `*.json` 与 `*.xlsx`（按文件名排序）；都没有则读 CSV 目录；再没有则报错 |
| 多路径 | `--input "a/daily-01.json,b/台账.xlsx,c/leaks.json"` | 逗号分隔，可混合 |
| 单文件 | `--input "/path/台账.xlsx"` | 单个 xlsx 或单份 JSON |

## 二、上游 JSON

### daily.json（来自 equipment-daily-report）

识别特征：同时存在 `meta.date` 与 `counts.equipment`。不满足则 warning 忽略，不中断。

| 字段 | 用途 |
|---|---|
| `meta.date` | 归入统计区间、计算覆盖天数与缺失日期 |
| `counts.newDefects` | 区间内新增缺陷（维修通知单）累加 |
| `counts.openDefects` / `counts.pendingAcceptDefects` | 取区间内**最后一天**的值作为期末未闭环 / 待验收缺陷 |
| `counts.openOrders` / `counts.overdueOrders` / `counts.pendingAcceptOrders` | 取最后一天的值作为期末未闭环 / 超期 / 待验收工单 |
| `special.list[]`（`tag,name,state,params,desc`） | 汇总为「特护设备运行状况」，统计区间内异常天数 |

处理规则：日期落在区间外不计入（`dataGaps.outOfRange`）；同一日期重复保留先读到的；某项 counts 为 `null` 的天不参与求和，**不按 0 计**；区间内缺日期 → warning 列出具体日期，指标标注「基于 N 天数据（应为 M 天）」，**不外推补齐**。

### rotation.json（来自 standby-rotation-reminder）
识别特征：顶层含 `standbyAvailability` 对象。读取 `standbyAvailability.{pairs, available, rate, statusMissing, statusUnknown, inRepair, stopped}` 作为备机完好率来源：完好率 = available ÷ pairs；该技能已把检修中/停用备机排除在 available 之外；其 `rate` 为 null（备机状态未填或无法识别）时本技能同样不出数，列入"分母缺失"。与"备机"工作表同时提供时以工作表为准。

### leaks.json（来自 leak-point-tracker）

识别特征：`counts.leaks` 与 `repaired` 同时存在。读取 `counts.{leaks,open,overdue,repaired}`、`metrics.repairRate` 列为泄漏点概况；含 `sealPoints.static.{total,leaks}` / `sealPoints.dynamic.{total,leaks}` 时计算静/动密封点泄漏率（‰）。无 `sealPoints` → 泄漏率写「未提供」。

## 三、xlsx 工作表

sheet 名匹配去空白与「表」字后包含匹配。同一类数据只取第一个来源，重复提供时后者忽略。列名先取局部别名，再合并中石化常用系统导出列名（`SYSTEM_ALIASES`，见顶层《中石化口径对照.md》第二节）。

### 设备台账（sheet：设备台账 / 台账 / 技术对象）—— 完好率的唯一分母来源

| 列名 | 别名（含 SAP PM / EM 列名） | 必需 | 说明 |
|---|---|---|---|
| 位号 | 设备位号、功能位置、功能位置编号、技术标识、技术对象、TAG | 是 | **「设备 / 设备编号」是 SAP 8 位流水号，不作位号** |
| 在用 | 是否在用、使用状态、在用状态 | **完好率必需** | 是/在用/运行/备用/Y/1 判在用；否/停用/停运/封存/长期停用/闲置/报废/退役 剔除；空 → 不计分母也不按在用默认（warning）；**列缺失 → 完好率 null，不得按在册算** |
| 完好 | 完好状态、是否完好、设备状态、完好情况 | 完好率必需 | 见下表；列缺失 → 完好率 null |
| 重要度 | 设备分级、设备等级、ABC标识、ABC、关键等级、特护 | 主要设备完好率必需 | A/B/关键/主要/特护/1/2/一级/二级 → A/B 类；C/一般/3/三级 → C 类；其他 → 不计主要设备分母并 warning |
| 设备名称 / 设备类型 / 专业 | 设备描述、技术对象描述、对象类型、专业类别 | 否 | |

「完好」列判定：完好/良好/正常/是/Y/1 → 完好；非完好/不完好/未完好/待修/带病/停用/故障/否/N/0 → 非完好；空或其他 → **未判定**，不计完好台数也不按完好默认（warning 列行号）。先判「非」再判「是」。

分母口径参数：`--intact-denominator 在用|在册`（默认在用）、`--sealed 剔除|计入`（默认剔除）；口径表「分母 / 剔除封存」列等效。

### 故障记录

| 列名 | 别名 | 说明 |
|---|---|---|
| 位号 | 功能位置 等 | 必需 |
| 故障时间 | 发生时间 / 时间 / 发生日期 | 落在区间内才计入；为空不计入并 warning |
| 停机时长 | 停机时间 / 停机小时 / 影响时长 | 小时；不可解析 → null，仅累加已填写的 |
| 是否停机 | 停机 / 是否非计划停机 | 是/Y/1 计故障停机次数；无此列时按 停机时长>0 判；两者皆无 → 不计并 warning |
| 修复时长 | 修复时间 / 修复工时 / 抢修时长 | MTTR 分母是有此值的条数 |
| 专业 / 设备类型 / 故障描述 | | 为空归「未填专业」「未填类型」 |

### 检修计划

| 列名 | 别名 | 说明 |
|---|---|---|
| 项目名称 | 项目 / 检修项目 | 必需 |
| 检修类别 | 检修类型 / 检修分级 / 项目类别 / 维修类型 / 订单类型 / 工单类型 | 大检修 / 日常维修 / 抢修 / 专项；旧口径 大修→大检修、中修/小修→日常维修；PM01→日常维修、PM02→大检修、PM03→抢修（厂内可配置）；无法归类 → 「未归类」单列并 warning；列缺失 → 只给合计 |
| 计划完成 | 计划完成时间 / 计划结束 / 基本结束日期 | 落在区间内才计入分母；为空不计并 warning |
| 实际完成 | 实际完成时间 / 实际结束日期 / 完工时间 / 技术完成日期 | 有值、或状态归 待验收/已闭环 判为完工 |
| 状态 / 位号 / 责任人 | | 否 |

按期判定：完工 且 实际完成 ≤ 计划完成 → 按期；完工但缺实际完成日期 → **未判定**单列，不计分子也不按延期。

### 工单台账（sheet：工单台账 / 工单 / 订单）

| 列名 | 别名（含 SAP PM） | 说明 |
|---|---|---|
| 工单号 | 单号、工单编号、订单、订单号、PM订单、维修订单号 | 必需 |
| 状态 | 处理状态、系统状态、用户状态、工单状态 | 按 SAP 六态归一：CLSD/NOCO/已关闭/已验收/已消缺 → 已闭环；**TECO/CNF/技术完成/已完成/完工 → 待验收，不计闭环**；DLFL/LKD/已取消 不计分母 |
| 要求完成时间 | 计划完成时间、基本结束日期、要求结束 | 落在区间内才计入应闭环分母 |
| 闭环时间 | 完成时间、闭环日期、关闭日期、业务完成日期、实际结束日期 | ≤ 要求完成时间判为按期闭环（闭环与否仍看状态） |
| 位号 / 责任人 / 缺陷描述 / 工作中心 | 功能位置 / 主工作中心 / 描述 | 责任方缺失时取主工作中心 |

### 缺陷台账（sheet：缺陷台账 / 缺陷 / 通知单）

仅在**未提供 daily.json** 时作为缺陷章节的数据源。列：位号（功能位置）、缺陷描述（通知单描述 / 通知单短文本）、等级、状态（通知单状态：NOCO 闭环、OSNO/NOPR 未闭环、「已完成」待验收）、发现时间（通知日期）、闭环时间（业务完成日期）。

### 备件消耗

列：备件名称（物料描述）、数量、单位（基本计量单位）、金额（本位币金额）、时间（过账日期）。金额合计仅累加已填写行，缺填条数 warning；也可用 `--spare` 单独传入。

### 特护设备（sheet：特护设备 / 特护 / 特护机组）

列：位号、设备名称、状态、运行参数、备注。逐台列出，不判趋势。未提供且日报无 `special` 节 → 写「未提供」。

### 备机（sheet：备机 / 备用设备 / 备机台账）

| 列名 | 别名 | 说明 |
|---|---|---|
| 位号 | | 必需 |
| 状态 | 当前状态 | 含 检修/在修/维修/故障/待修 → 不计可投用（检修中备机不进分子） |
| 是否可投用 | 可投用 / 可随时投用 / 备用状态 / 可用 | 是/Y/1/可投用 → 可投用；否/N/0/不可投用 → 不可；其他 → 未判定 |

缺「是否可投用」列且存在无法判定的备机 → 备机完好率 null（不按默认出数）。

### 密封点统计（sheet：密封点统计 / 密封点 / 泄漏率 / LDAR）

列：密封点类型（含「静」/「动」）、密封点总数、泄漏点数。总数缺失或为 0 → 该泄漏率 null。考核线以厂内指标为准，脚本不比对。

### 停工记录（sheet：停工记录 / 非计划停工 / 停工）

列：停工时间（必需）、停工类别（计划 / 非计划；缺列 → 非计划停工次数 null）、装置、原因。只计数，不判定是否构成非计划停工事件。

## 四、指标口径表（`--metrics`）

工作表「指标口径」，列：指标 / 算法 /（可选）分母 /（可选）剔除封存。

| 指标 | 算法 | 分母 | 剔除封存 |
|---|---|---|---|
| 设备完好率 | 完好台数 / 在册设备台数（含封存），厂标 Q/XX-虚构-001 | 在册 | 否 |
| 检修计划完成率 | （按期完成 + 经批准顺延）项数 / 计划项数 | | |

- 文件不存在 → 报错终止；找不到「指标口径」工作表或解析不到行 → warning，回落默认口径。
- 命中指标的处理分三种：算法表述与默认一致 → 照算；给了结构化参数（分母 / 剔除封存 列，或 `--intact-denominator` / `--sealed`）→ 按结构化口径算；**算法不一致且无结构化参数 → 该指标 null，标「需按厂内口径复算」**，列入 `dataGaps.recompute` 与 `summary.recompute`。
- 虚构示例的标准号一律写 `Q/XX-虚构-001` 形式，不得形似真实企标。

## 五、环比与同比（`--prev` / `--yoy`）

传入上期 / 同期 `periodic.json`。文件不存在或不是 periodic.json → 报错；周期不一致 → warning。对比字段：设备完好率、主要设备完好率、备机完好率、静/动密封点泄漏率、检修计划完成率（合计/大检修/日常维修）、工单及时率、MTTR、停机时长、故障次数、故障停机次数、非计划停工次数、新增缺陷、未闭环缺陷。**任一侧为 null 时变化为 null（显示「—」），不按 0 参与计算。**

## 六、其他参数

| 参数 | 说明 |
|---|---|
| `--period` | `weekly` / `monthly` / `quarterly` / `yearly`；其他值报错 |
| `--from` / `--to` | YYYY-MM-DD；`from` 晚于 `to` 报错 |
| `--intact-denominator` | `在用` / `在册`，其他值报错 |
| `--sealed` | `剔除` / `计入`，其他值报错 |
| `--topn` | 排行条数，默认 5 |
| `--out` | 输出目录，默认系统临时目录 `<os.tmpdir()>/ewmr-out`，建议始终传 |

## 七、会被跳过的行

- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 列 sheet 名与行号）

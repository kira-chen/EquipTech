# 设备周报月报指标口径与表述规范（中石化体系炼化厂车间设备员口径）

> **本文件定义的是默认口径，不是厂内正式口径。** 指标定义依据《中国石化设备管理规定》《炼化企业设备管理技术规定》的通用口径整理（只引名称，不转述数值），各厂分子分母细节有差异，考核数据一律以**公司设备管理部门（机动部/设备部）**发布口径为准。脚本在未传 `--metrics` 时按本文件算法计算，并在 `periodic.md` 头部与 `指标表.xlsx` 写明「本报告指标采用默认口径，非厂内正式口径，考核数据以公司设备管理部门发布口径为准。」这句声明**必须保留**。

## 一、指标集与默认算法

| 指标 | 默认算法 | 数据来源 | 分母缺失 / 未提供时 |
|---|---|---|---|
| 设备完好率 | 完好台数 / **在用**设备台数（剔除长期停用、封存） | 设备台账「在用」「完好」列 | **null，显示「—」，不得按在册台数算** |
| 主要设备完好率 | 完好的 A/B 类在用台数 / A/B 类在用台数 | 设备台账「重要度 / ABC标识」列 | null |
| 备机完好率 | 可随时投用的备机台数 / 备机总数（检修中备机不进分子） | 备机表 | 未提供 → 「未提供」 |
| 静密封点泄漏率（‰） | 静密封泄漏点数 / 静密封点总数 | 密封点统计表 或 leaks.json `sealPoints` | null；**考核线以厂内指标为准，不比对** |
| 动密封点泄漏率（‰） | 动密封泄漏点数 / 动密封点总数 | 同上 | 同上 |
| 检修计划完成率 | 按期完成项数 / 计划项数，按 大检修 / 日常维修 分列（抢修、专项另列） | 检修计划「检修类别」列 | null；无类别列只给合计 |
| 工单及时率 | 按期闭环工单数 / 应闭环工单数（待验收不计闭环，已取消不计分母） | 工单台账 / SAP 订单清单 | null |
| 平均修复时间 MTTR | 累计修复时长 / 有修复时长的故障次数 | 故障记录 | null |
| 故障停机时长 | 区间内各次故障停机时长求和 | 故障记录 | 全部不可解析 → null |
| 故障停机次数 | 停机时长>0 或 是否停机=是 的故障记录条数 | 故障记录 | 两列皆无 → null |
| 非计划停工次数 | 停工记录中类别为非计划的条数 | 停工记录 | 未提供 → 「未提供」；**是否构成非计划停工事件按《炼化企业非计划停工管理规定》另行报送，本技能不判定** |
| 特护设备运行状况 | 逐台列状态与参数、区间内异常天数 | 特护设备表 或 日报 `special` 节 | 未提供 → 「未提供」 |

### 设备完好率（最容易被做坏的指标）

- 分母是**在用**台数：台账「在用」列为 是/在用/运行/备用 的台；封存、长期停用、闲置、报废、退役 剔除；「在用」为空的台**不计分母也不按在用默认**（warning 列行号）。
- 台账缺「在用」列 → 指标 null，报告写「台账缺「在用」列，无法确定在用台数（分母），不得按在册台数计算」。只有用户显式给 `--intact-denominator 在册`（或口径表「分母」列写在册）才按在册算，并在 meta 中记录口径。
- **绝不允许**：用在册台数冒充在用台数；用上期台数、经验值、领导口头数字当分母；把分子分母都缺的情况写成 0% 或 100%。
- 「完好」列无法判定的台不计完好台数也不按完好默认。
- 设备台账只有当前状态：`--to` 早于今天时，完好率是取数当天的快照，不是期末状态，报告注明（`metrics.intactSnapshotNote`）。环比基准期的完好率同理，是基准报告生成时的快照（`compare.*.snapshotNote`），比较时说明这一点，不把差值全部归为期间变化。

### 主要设备完好率

分子分母限 关键设备（A）/ 主要设备（B）（含「关键 / 主要 / 特护 / 1 / 2 / 一级 / 二级」写法）；重要度为空或无法归入 A/B/C 的台不计分母并 warning。大机组、关键机组属特护设备，在特护一节逐台列出。

### 检修计划完成率（按分级分列）

检修分级口径：**装置大检修（停工检修）/ 日常维修 / 抢修 / 专项（技改技措）**。旧口径别名保留映射：大修→大检修，中修/小修→日常维修；SAP 订单类型 PM01/PM02/PM03 的映射为厂内可配置，脚本默认 PM01 日常维修、PM02 大检修、PM03 抢修。无法归类 → 「未归类」单列并 warning，不猜。

分母：计划完成日期落在区间内的项目；未填计划完成日期的不计分母。分子：完工且实际完成 ≤ 计划完成。完工但缺实际完成日期 → **未判定**单列，不计分子也不按延期。完成率考核的是完工，不是验收。

### 工单及时率与待验收

状态按 SAP 六态归一：待审核（CRTD/OSNO）/ 已派工（REL/NOPR）/ 施工中（PCNF）/ **待验收（TECO/CNF/技术完成/已完成/完工）**/ 已闭环（CLSD/NOCO/已关闭/已验收/已消缺）/ 已取消（DLFL/LKD）。先判否定前缀（未/待/不/非）再判闭环词。**「已完成/完工/TECO」是待验收，不是闭环**，报告单列。已取消不计应闭环分母。

### 泄漏率

静/动密封点分别计算，单位 ‰，分母取密封点统计表的总数或 leaks.json 的 `sealPoints`。厂内考核线（常见静 ≤0.5‰、动 ≤2‰）**以厂内指标为准，本技能不比对、不判定是否达标**；泄漏点逐点跟踪、修复率与延迟修复用 leak-point-tracker。

### 备机完好率

检修中备机不进分子；「是否可投用」缺列且存在无法判定的备机 → null，不按默认出数。

### MTTR 与停机

MTTR 分母是**有可解析修复时长的故障次数**。停机时长合计只累加已填写的记录，**不按 0 补齐，也不按均值补齐**。故障时间为空的记录不计入区间。

## 二、统计区间与数据覆盖（硬规则）

- 输入多份 `daily.json` 时逐日比对，缺哪天在 warning 列出**具体日期**，报告标注「基于 N 天数据（应为 M 天）」。
- **绝不按已有天数求日均再乘以区间天数外推补齐。** 缺 2 天的周报就是 5 天的数据。
- `daily.json` 中某项 counts 为 `null` 的天不参与求和，覆盖天数与累加天数不一致时 warning。
- 区间外的 `daily.json` 不计入，单独在 `dataGaps.outOfRange` 记录。

## 三、周期与区间匹配

| `--period` | 中文 | 常规天数 |
|---|---|---|
| `weekly` | 周报 | 5~10 |
| `monthly` | 月报 | 26~35 |
| `quarterly` | 季报 | 85~97 |
| `yearly` | 年报 | 350~380 |

区间天数落在范围外时 warning，**不中断执行**，由用户确认。季报与年报的指标口径需用户确认后再用。

## 四、厂内口径表覆盖（三种结果，绝不只换文字）

`--metrics <xlsx>`：工作表「指标口径」，列 指标 / 算法 /（可选）分母 /（可选）剔除封存。

| 情形 | 处理 | 报告「计算方式」列 |
|---|---|---|
| 口径表未命中该指标 | 按默认口径算 | 默认口径（口径表未命中） |
| 命中，算法表述与默认一致（去括号、空白、÷/／ 归一后比较） | 按默认逻辑算 | 厂内口径（与默认算法一致） |
| 命中，给了结构化参数（分母 / 剔除封存 列，或 `--intact-denominator` / `--sealed`） | 按结构化口径算 | 厂内口径（结构化参数） |
| 命中，算法不一致且无结构化参数 | **该指标 null，显示「—」**，列入 `dataGaps.recompute`，报告写「需按厂内口径复算」 | 需按厂内口径复算 |

曾经的做法是"命中就只换算法文字、数字仍按默认算"，这是最大的误导风险：报告写着厂内算法、数字却是另一套。现在一律不允许。

口径表不存在 → 报错；找不到「指标口径」工作表或解析不到任何行 → warning 并回落默认口径。虚构示例的标准号写 `Q/XX-虚构-001`。

## 五、分析段表述规范

撰写 400~600 字，结构固定八段：

1. **总体评价**：统计区间、数据覆盖天数、整体运行一句话。
2. **关键指标与环比同比**：逐项列指标值与变化，缺失或需复算的写「未计算」。
3. **特护设备与故障分布**：特护逐台状态、按专业/设备类型分布、频次排行。
4. **检修计划执行**：大检修 / 日常维修 分述，延期与未判定项。
5. **工单与缺陷**：及时率、待验收、超期清单。
6. **备件消耗**：行数、金额合计、消耗较大的备件。
7. **存在问题**：超期工单、逾期检修项目、非计划停工、数据缺口。
8. **下期重点**：需要盯的设备与事项（由车间填写，技能不代拟）。

### 指标变化的原因（关键）

**只在数据明确支持时陈述原因，否则一律写「原因待分析」。**

| 场景 | 应写 | 不得写 |
|---|---|---|
| 完好率下降且台账记录了非完好设备 | 「完好率 90.0%，较上期 -5 个百分点，台账中 EQ-1119、EQ-1120 标记为非完好」 | 「完好率下降，说明维护保养不到位」 |
| 故障次数上升但无原因记录 | 「故障 8 次，较上期 +6 次，原因待分析」 | 「故障上升主要因设备老化」 |
| 分母缺失 | 「设备完好率本期未计算，台账缺「在用」列」 | 「设备完好率约 95%」 |
| 需复算 | 「设备完好率按厂内口径需复算，本期未出数」 | 沿用默认算法结果并冠以厂内算法名 |
| 泄漏率 | 「静密封点泄漏率 0.42‰，是否达标以厂内指标为准」 | 「泄漏率达标」 |
| 非计划停工 | 「区间内非计划停工 1 次，是否构成非计划停工事件按规定另行报送」 | 「发生一般非计划停工事件 1 起」 |
| 数据缺口 | 「基于 5 天数据（应为 7 天），缺 09-16、09-19」 | 「全周设备运行平稳」 |

### 硬约束

- **数字一律引用 `periodic.json`**，不得自行统计或换算。
- 不做故障根因诊断，不判定责任，不做考核结论；不预测下期指标；不做跨车间对比与排名；不代拟下期重点。
- 缺失日期、分母缺失、需复算、未判定四类情况必须在报告中出现，不得为了报告好看而略去。
- 产出 md 不用 emoji，醒目提示用「【注意】」。

## 六、制度引用

可引用名称：《中国石化设备管理规定》《炼化企业设备管理技术规定》（指标定义）、《炼化企业非计划停工管理规定》（非计划停工次数口径与报送）、GB 31570 与中石化 LDAR 相关要求（泄漏率分母与检测周期，数值以厂内文件为准）。不转述法规数值；需要数值的地方写"依据 XX 规定，数值以用户提供的制度文件为准"。

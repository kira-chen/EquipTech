# 输入规格：迎检资料准备

## 必填参数

| 参数 | 说明 |
|---|---|
| `--notice` | 检查通知或检查表：`.docx` / `.xlsx` / `.md` / `.txt`。**PDF 前置步骤：先用平台 pdf 技能转为 txt/docx 再传入，脚本不读 PDF；扫描件需 OCR** |
| `--materials` | 台账与记录的目录，或资料清单 `.xlsx` |
| `--workshop` | 车间名称 |

## 一、检查通知 / 检查表的解析

### 形式一：`.xlsx` 检查表（最稳，推荐）

sheet 名匹配「检查表」「检查项」「检查项目」「检查清单」「检查内容」（去空白与「表」字后包含匹配）。

| 列名 | 必需 | 说明 |
|---|---|---|
| 检查项 | 是 | 一行一个检查项；为空的行跳过并 warning |
| 资料要求 | 否 | 该项应提供的证据材料，参与材料匹配 |
| 检查类别 | 否 | 粗分类标签，**仅展示，不参与材料匹配**（见下） |
| 序号 | 否 | 缺失时按出现顺序自动编号 |

列名别名：

| 标准列名 | 可识别的写法 |
|---|---|
| 检查项 | 检查项、检查项目、检查内容、项目、内容、检查要点、要点 |
| 资料要求 | 资料要求、应提供资料、需提供资料、查阅资料、证据材料、要求、所需资料、支撑材料 |
| 检查类别 | 检查类别、类别、专业、分类、检查类型 |
| 序号 | 序号、编号、No、NO |

表头行识别：取前 10 行中命中必需列最多的一行，因此首行是标题、第三行才是表头的导出表也能读。

> **「检查类别」为什么不参与匹配**：它是「运行维护」「基础管理」这类粗分类标签。
> 拿它去匹配，会把整个大类的材料都算成某一项的证据，缺口反而被掩盖。
> 这与本技能「绝不用相近材料充数」的硬约束直接冲突，故只作展示。

### 形式二：`.docx` 检查通知或检查表

- 先找含「检查项」表头的表格，按列抽取（与形式一同口径）
- 找不到这类表格时退回正文逐行解析，并 warning 说明已退回
- 合并单元格、复选框等由 `scripts/lib/docx-lite.js` 处理，口径见 `scripts/docx2text.js` 说明

### 形式三：`.md` / `.txt` 文字通知

- 优先取**带序号的行**：`1.` `1、` `(1)` `（一）` `一、` 等，序号后正文≥3 字
- 一个带序号行都没有时，取长度≥5 字的非空行
- `#` 开头的 Markdown 标题不当作检查项
- 一条都解析不出时 → `ok:false` 并提示改用 `.xlsx` 检查表

### 不支持的格式

`.pdf`、`.doc`、图片一律报错，错误信息提示「PDF 请先用平台 pdf 技能转为 txt/docx 再传入（扫描件需 OCR），脚本不读 PDF」。材料目录中的 PDF 文件只按文件名参与比对。

## 二、台账与记录（`--materials`）

### 形式一：材料目录

直接传目录路径，递归扫描（最多 6 层，超出则 warning）。跳过 `.` 开头的隐藏文件与 `~$` 临时文件。子目录文件保留相对路径作为「文件位置」。

```bash
--materials "/path/to/车间台账与记录/"
```

目录模式下材料的时间范围**只能从文件名推断**（见下节），推不出即为「时间不详」。

### 形式二：资料清单 `.xlsx`

sheet 名匹配「资料清单」「材料清单」「台账清单」「记录清单」「资料」。

| 列名 | 必需 | 说明 |
|---|---|---|
| 文件名 | 是 | 为空的行跳过并 warning |
| 存放位置 | 否 | 缺失时用文件名代替 |
| 起始日期 / 截止日期 | 否 | 该材料实际覆盖的记录区间，用于时间覆盖判定 |
| 资料类型 | 否 | 参与匹配（与文件名一并作为材料名称） |
| 备注 | 否 | |

列名别名：

| 标准列名 | 可识别的写法 |
|---|---|
| 文件名 | 文件名、资料名称、材料名称、名称、文件、台账名称 |
| 存放位置 | 存放位置、位置、路径、存放、存档位置、归档位置 |
| 起始日期 | 起始日期、起始时间、开始日期、起始、记录起始 |
| 截止日期 | 截止日期、截止时间、结束日期、截止、记录截止 |
| 资料类型 | 资料类型、类型、类别 |

**填报起止日期是让时间覆盖判定生效的唯一可靠途径。** 不填则退回文件名推断，再推不出即按「时间不详」处理 —— 时间不详**一律不按完整覆盖处理**，会进入「覆盖不全」。

只填一端（如只填起始）时：另一端按文件名推断（`periodBasis` = 「清单填报+文件名推断」，warning 请核对）；推不出则另一端保持 null，`periodBasis` = 「清单填报（仅一端）」，覆盖按已填一端判定（通常落入覆盖不全），**不按检查期倒推、不猜**。

## 三、材料时间范围的推断

清单中填了起止日期就以填报为准。未填时按文件名推断，支持：

| 文件名写法 | 推出的区间 |
|---|---|
| `巡检记录2026年三季度.xlsx` | 2026-07-01 ~ 2026-09-30 |
| `记录2026Q3.xlsx` | 2026-07-01 ~ 2026-09-30 |
| `台账2026年上半年.xlsx` | 2026-01-01 ~ 2026-06-30 |
| `检修记录2026-08.xlsx` | 2026-08-01 ~ 2026-08-31 |
| `验收单2026-08-15.pdf` | 2026-08-15 ~ 2026-08-15 |
| `设备台账2026年.xlsx` | 2026-01-01 ~ 2026-12-31 |
| `记录2026-01~2026-06.xlsx` | 2026-01-01 ~ 2026-06-30 |
| `巡检登记本.xlsx` | **推不出 → 时间不详 → 覆盖不全** |

日期无法解析时输出 `null` 并 warning，**绝不填默认值、绝不按检查期倒推**。

## 四、可选参数

| 参数 | 说明 |
|---|---|
| `--inspection` | 检查名称，写入报告头部 |
| `--date-range` | 检查期 `YYYY-MM-DD~YYYY-MM-DD`；**不提供则完全不做时间覆盖判定**，并 warning |
| `--out` | 输出目录，默认系统临时目录 `<os.tmpdir()>/iep-out`，建议始终传 |
| `--scope` | 检查范围说明，仅写入报告头部 |
| `--spec` | 厂内资料归档规范文件，仅登记在报告中；文件不存在时报错 |
| `--last` | 上次同类检查的资料包目录，仅登记在报告中；目录不存在时报错 |
| `--out` | 输出目录，默认当前目录下 `iep-out/` |

`--date-range` 起止倒置、非法日期、格式不是 `起~止` 时一律 `ok:false` 并退出 1。

## 五、会被跳过的行

- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning）
- 检查项为空的行（warning）
- 资料清单中文件名为空的行（warning）
- 目录模式下 `.` 开头的隐藏文件与 `~$` 临时文件
- 目录层级超过 6 层的部分（warning）

## 六、产出

| 文件 | 内容 |
|---|---|
| `evidence.json` | items、ready、missing、partialCoverage、unmatched、materials、counts |
| `evidence.md` | 七节报告；有缺口时开头带醒目提示；末尾固定声明行 |
| `资料清单.xlsx` | 四个工作表：资料对照、缺口清单、未对应材料、声明 |
| `summary.json` | 末行摘要落盘 |

# 迎检资料比对口径与表述规范

> 规则表实现在 `scripts/lib/evidence-spec.js`，与本文档同源。改脚本前先读本文。

## 一、检查项 ↔ 材料的匹配口径

脚本只认两种匹配依据，**从严**，宁可判为「未找到对应材料」也不放宽：

| 依据 | 含义 | 例 |
|---|---|---|
| `category:<类别>` | 检查项与材料落在同一个**具体**资料类别 | 检查项「巡检记录是否完整」↔ 材料「巡检记录2026年三季度.xlsx」 |
| `feature:<词>` | 检查项里的**具体**特征词（设备位号、专有名词）直接出现在材料名中 | 检查项「P-1101A 润滑油更换记录」↔ 材料「P-1101A润滑油更换台账.xlsx」 |

资料类别共 26 类：设备台账、巡检点检记录、检修与维修记录、计划与方案、作业票（作业许可，按中石化八大类，「用火作业」为正式名称、「动火」作旧写法别名）、缺陷与故障记录、隐患排查治理记录（两者是两本账：缺陷/故障走 SAP PM 通知单，隐患走隐患排查治理台账，不互相充数）、检验检测报告、校验检定记录、安全附件与安全设施记录、培训与资质记录、演练与应急记录、会议与活动记录、环保监测与治理记录、能耗与计量记录、备件与物资记录、验收资料、设备档案、制度与职责文件、特种设备管理资料，以及 2026-10-26 按中石化炼化厂设备管理检查项补充的 6 类：**变更管理（MOC）资料、安全仪表与联锁（SIS）记录、特护设备（大机组）记录、润滑管理（五定三过滤）记录、泄漏检测与修复（LDAR）记录、一机一档**。

补充 6 类的不充数边界：设备台账不冒充一机一档；巡检记录不冒充特护日报；检修记录不冒充换油台账；作业票不冒充联锁旁路审批单。

「特种设备台账」虽含「设备台账」四字，只是特种设备的专项台账，不归设备台账类（不充全车间设备台账），仍归特种设备管理资料。排除只针对专项写法：「特种设备台账」「特种设备使用台账」或名称以「特种设备」开头的；「设备台账（含特种设备）」这类全车间台账照常归设备台账。

作业票类的「用火」按正则匹配：前面是「备 / 使 / 启 / 停 / 采 / 选 / 利」或后面是「炬 / 嘴」的不算（「备用火炬运行记录」「使用火炬系统」「备用火嘴」不归作业票），「用火作业 / 用火票 / 用火监护」照常归入；与 regulation-compliance-check 同口径。

**空表不是证据**：材料目录里的 csv / xlsx 只有表头、没有数据行（含 0 字节文件，如业务系统按检查期查询无记录时导出的空表）时，不参与比对，对应检查项按未找到对应材料处理；逐个 warning，第六节末尾注明，不列入未对应材料。`evidence.json` 的 `materials[].empty` 标记、`counts.emptyFiles` 计数。表头按前 10 个非空行识别：取其中第一行有两个及以上非空单元格的行为表头（「常减压车间巡检记录导出」这类单格标题行跳过），表头之后没有数据行即判空，所以「标题行 + 表头」的导出也是空表。0 字节文件（任何格式，含 pdf、docx）直接判空，warning 和第六节末尾单独写「空文件（0 字节）」，不说「只有表头」，`materials[].zeroByte` 标记，同样计入 `counts.emptyFiles`。

**读不了的 xlsx 不是证据**：xlsx 损坏或不是有效 xlsx（读取报错）时，单独 warning「无法读取」，不参与比对、不列入未对应材料，第六节末尾注明，请重新导出。`materials[].unreadable` 标记、`counts.unreadableFiles` 计数。

### 泛词不作为匹配依据

「设备」「记录」「台账」「车间」「资料」「管理」这类词**一律不构成匹配**。
理由很直接：放开泛词后，任何一份材料都能对上任何一个检查项，缺口全被掩盖，这个技能就失去了意义。

具体表现：

| 检查项 | 材料 | 结果 | 为什么 |
|---|---|---|---|
| 特种作业人员是否持证上岗 | 设备台账.xlsx | **不匹配** | 台账不是人员资质，不得拿来充数 |
| 是否开展应急演练 | 巡检记录.xlsx | **不匹配** | 只共享泛词「记录」 |
| 设备缺陷是否闭环整改 | 设备检修记录.xlsx | **不匹配** | 检修记录不冒充缺陷台账 |

### 明令禁止的兜底

- 不做语义近似、同义词扩展、编辑距离兜底
- 不做「这份材料里可能也有相关内容」式的推测性对应
- 不为了让清单好看而放宽匹配

匹配不上就是找不到。找不到就如实写「未找到对应材料」。

## 二、缺失项处理（最硬的一条）

检查项没有匹配到任何材料 → `missing`，状态文字固定为**「未找到对应材料」**。

| 必须这样写 | 绝对不能写 |
|---|---|
| 「未找到对应材料」 | 「可用巡检记录替代」 |
| 「本项无可提交的证据材料，检查时将构成资料缺口，须如实说明」 | 「基本齐全，个别待补」 |
| 「建议向相关部门追索原件」 | 「可让班组补做一份」 |
| 「该项资料缺失」 | 「暂以 XX 代替」 |

报告中的固定动作（由脚本写入，模型不得删改）：

1. 存在缺口时，`evidence.md` **第一节之前**写醒目提示：
   `【注意】存在未找到对应材料的检查项，缺口项须如实向检查组说明；不得用相近材料充数，不得事后补编记录`
2. 「三、资料缺口清单」单列一节，逐项写明检查项、资料要求、影响与出处
3. 缺口节末尾固定一行：
   `缺口项一律如实上报。不得用相近材料充数，不得标注为「可用 XX 替代」，不得事后补编记录。`
4. 「七、归集包目录建议」**不为缺口项建目录**，并注明「不得建空目录后补放材料」

**禁止淡化**：不得把缺口合并进「其他事项」，不得用「资料基本齐全」「个别项待完善」一笔带过，不得把缺口数字藏在附注里。

## 三、时间覆盖判定

检查期 `[from, to]` 与材料区间 `[mFrom, mTo]` 比较：

| 情形 | 判定 | 归入 |
|---|---|---|
| 材料区间完整包含检查期 | `full` | ready |
| 有交集但不完整（含只覆盖一端） | `partial` | **partialCoverage** |
| 无交集 | `none` | **partialCoverage** |
| 检查项对应的材料**全部**时间不详（未填报且文件名推不出，如 MCP 导出文件） | `unknown` | **unknownPeriod**（期限未知，单列） |
| 有日期的材料部分覆盖或无交集，另有时间不详的材料 | `partial` / `none` + `unknown` | **partialCoverage**（覆盖说明点出时间不详份数） |
| 清单只填一端日期 | 另一端按文件名推断（warning 请核对）；推不出按已填一端判 | 按上表 |
| 未提供 `--date-range` | `noPeriod` | 不做覆盖判定，warning 说明 |

### 硬规则

- **时间不详绝不按完整覆盖处理**。推不出时间就是推不出：检查项的材料全都时间不详时归「期限未知」单列（第五节），既不算齐全，也不算已确认的覆盖不全，说明缺起始日期、截止日期，由车间核实。
- **位号段不当年份**：文件名推断日期前先抹掉设备位号段（1~3 个字母 + 连字符 + 2~5 位数字 + 可选字母，如 `E-1201`、`V-1101`、`P-2101A`；数字后紧跟「年/月/季」的不算位号）。「E-1201-2026年测厚报告」推为 2026 年全年，不读成 1201~2026 年。
- 同一检查项下只要有一份材料完整覆盖，该项计为 `ready`；但其余时间不详或未覆盖的材料**仍在覆盖说明里如实点出**，不因为有一份齐全就掩盖其余。
- 覆盖不全项必须写出**实际覆盖区间**与**未覆盖的检查期**，例：
  `未完整覆盖检查期 2026-07-01 ~ 2026-09-30：材料覆盖区间 压力容器定期检验报告.pdf：2025-07-01 ~ 2026-08-15`
- 覆盖不全节固定一行：`覆盖不全项按实际覆盖区间说明，不得按完整覆盖报送，缺口区间不得补录记录。`
- 期限未知节固定一行：`期限未知项既不算资料齐全，也不算覆盖不全：材料在，但起止日期无从判断。须由车间核实材料实际起止日期后再说明，不得按完整覆盖报送，不得补录记录。`

## 四、未对应材料

材料对不上任何检查项 → `unmatched`，注明
「未对应到任何检查项，请人工确认是否属于本次检查范围；未按名称猜测强行对应」。

**禁止**：为了消化材料而硬塞给某个检查项。这个方向的强行对应同样是充数。

## 五、准备工作提示（分析段）表述规范

撰写 200~400 字，结构固定为四段：

1. **资料齐备情况**：检查项总数、齐全项数、材料份数。
2. **缺口项及其影响**：逐项点名未找到对应材料的检查项，说明检查时会构成什么缺口。**不提替代，不提补编。**
3. **覆盖不全与期限未知项的说明口径**：覆盖不全项的实际覆盖区间是什么、期限未知项缺哪端日期需核实，向检查组怎么如实讲。
4. **迎检准备建议**：材料归集、原件追索、向上级说明的准备。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 缺口 | 「应急演练记录未找到对应材料，检查时构成资料缺口，需如实说明」 | 「可用班组活动记录替代」 |
| 覆盖不全 | 「检验报告覆盖至 2026-08-15，检查期后段无材料，按实际区间说明」 | 「检验报告齐全」 |
| 期限未知 | 「人员证书台账未标起止日期，是否覆盖检查期待车间核实」 | 「人员证书齐全」「人员证书覆盖不全」 |
| 合规 | 不做判断 | 「该项符合要求」「该项不达标」 |
| 补录 | 不提 | 「可让施工单位补做一份」「检查前补齐即可」 |
| 数字 | 引用 evidence.json 的 counts | 自行统计或估算 |

### 硬约束

- **不判定检查项是否达标合规**。资料在不在是事实，达不达标是检查组的结论，两回事。合规判定用 `regulation-compliance-check`。
- **不编制、不补录、不代写任何检查资料与记录**。缺就是缺。
- **不建议用其他材料替代缺失资料**，不给出任何形式的「替代方案」。
- **数字一律引用 evidence.json**，不得自行统计。

## 六、必须保留的声明行

`evidence.md` 末尾固定写入，**逐字保留，不得删除或改写**：

> 本清单基于所提供材料比对生成，资料的真实性、完整性由车间负责；缺失资料应如实说明，不得事后补编记录。

同一句话也写入 `evidence.json` 的 `meta.statement` 与 `资料清单.xlsx` 的「声明」工作表。

## 七、制度引用与术语

- 检查依据可引用名称（不转述数值）：《中国石化设备管理规定》《炼化企业设备管理技术规定》《中国石化作业许可管理规定》（八大类：用火、受限空间、高处、吊装、临时用电、动土、断路、盲板抽堵）《中国石化变更管理规定》（工艺技术 / 设备设施 / 管理变更）《中国石化安全隐患管理规定》（五定）、设备润滑"五定三过滤"、GB 31570 与中石化 LDAR 要求、TSG 21 / TSG D7005（特种设备）。
- 组织层级写 车间 / 分厂 / 公司（公司设备管理部门），不写旧称"机动处""厂领导"。
- 产出 md 不用 emoji，醒目提示用「【注意】」。

## 八、与 regulation-compliance-check 词表的差异

本技能 `scripts/lib/evidence-spec.js`（26 类，面向"检查项 ↔ 材料文件名"）与 `07-隐患事故与合规/regulation-compliance-check/scripts/lib/compliance-spec.js`（26 类，面向"条款 ↔ 材料"）**不是同一张表**，两边各自维护，差异如下（同源抽取由主代理后续统一处理，此处只记录差异，不自行改动对方）：

| 差异 | 本技能（evidence-spec，26 类） | regulation-compliance-check（compliance-spec，26 类） |
|---|---|---|
| 本技能独有 | 安全附件与安全设施记录（合并安全阀 + 报警器 + 消防）、能耗与计量记录、特护设备、润滑五定三过滤、LDAR、一机一档、变更管理 MOC、联锁 SIS | — |
| 对方独有 | — | 使用登记与告知资料、无损检测与测厚记录（本技能并入检验检测报告）、操作规程与作业指导书（本技能并入计划与方案）、事故与异常情况报告、变更与报废记录（含报废/停用/移装）、外委与承包商管理资料、安全阀与安全附件校验记录（本技能并入安全附件与安全设施）、安全联锁与报警记录（本技能拆为 interlock + safetyDevice） |
| 词粒度 | 检查项侧与文件名侧各一组词，泛词一律不匹配 | 条款侧收得更紧（用「设备台账」不用「台账」） |
| 作业许可 | 「用火」正式名称 +「动火」旧别名；「备用火炬 / 使用火炬 / 备用火嘴」不算用火 | 「动火」「用火」并列保留；同样排除「备用火炬」等 |
| 缺陷与隐患 | 同对方：defect（缺陷、报修、故障）与 hazard（隐患）分两类 | defect 与 hazard 分两类 |
| 系统导出文件名 | 同对方 `FILE_ALIASES`：故障记录/检修历史/工单算检修记录，通知单算缺陷与故障，作业清单算作业票 | `FILE_ALIASES` |
| 特种设备台账 | 不归设备台账（`fileNot` 只排除「特种设备台账 / 特种设备使用台账 / 以特种设备开头」，「设备台账（含特种设备）」照常归设备台账），不充全车间设备台账 | 未排除，文件名含「设备台账」即归设备台账（2026-11-04 记录，未改对方） |

用法边界：迎检资料归集（资料在不在）用本技能；条款符合性（四档对照：已见 / 未见 / 不完整 / 需确认）用 regulation-compliance-check。

# 通报要素清单与追问话术

## 七要素

| 要素 | 参数 | 必需 | 为什么必需 | 缺失时的追问 |
|---|---|---|---|---|
| 设备位号 | `--tag` | 是 | 通报必须挂到具体设备，否则读者不知道说的是哪台 | 「这次事件涉及哪台设备？位号是多少？」 |
| 发生时间 | `--time` | 是 | 通报的第一要素；且**发生时间与发现时间是两回事** | 「事件是什么时间发生的？（精确到分）如果只知道发现时间，请说明这是发现时间。」 |
| 事件经过 | `--desc` | 是 | 通报的主体 | 「当时的经过是怎样的？按时间顺序说一下现场观察到的现象与处置动作，带上关键参数数值。」 |
| 当前状态 | `--status` | 是 | 读者最关心的是「现在怎么样了」 | 「设备与装置现在是什么状态？停运、备用还是已恢复？装置负荷有没有变化？」 |
| 影响情况 | `--impact` | 是 | 决定通报范围与紧急度 | 「对生产、安全、环保各有什么影响？**没有影响也请明确说明**。」 |
| 已采取措施 | `--measures` | 是 | 说明处置到位与否 | 「已经采取了哪些措施？哪个岗位在什么时间做的？」 |
| 后续安排 | `--followup` | 否 | 有则写，无则留空 | 「后续怎么安排？什么时间由哪个岗位负责做什么？怎么验证？」 |

## 追问原则

1. **一次性列出所有缺项**，不要挤牙膏式逐个追问。脚本的 `missing` 数组已经把该问的都列好了，直接照着问。
2. **不得用推测填补任何要素**。尤其这四种常见错法：
   - 影响情况没填 → 不能写「无影响」。没填不等于没影响。
   - 当前状态没填 → 不能按「已恢复」写。
   - 发生时间没填 → 不能按发现时间倒推。
   - 已采取措施没填 → 不能写「正在处理」，那是在编造处置动作。
3. **原因不在要素清单里**，这是故意的。原因未经正式调查确认，一律写「原因正在分析中」，不追问、不推测、不写进通报。用户主动说了原因判断的，告诉他这一条不会写进通报正文；确已有正式调查结论的，用 `--cause` 加 `--cause-confirmed`。
4. 抽取结果要**回读给用户确认**后再成文。

## 影响情况的三方面

影响一栏最容易写得笼统。按三方面分别问：

| 方面 | 要问到的 | 好的回答样子 |
|---|---|---|
| 生产 | 装置是否降量/停车？降了多少？持续多久？影响产量多少？ | 「装置负荷未受影响，未降量」／「降量 20% 运行约 4 小时」 |
| 安全 | 有无人员伤害？泄漏量多少？有无可燃有毒气体检出？现场是否已隔离？ | 「无人员伤害，泄漏量约 0.5 kg，可燃气体检测仪读数为 0，现场已清理」 |
| 环保 | 有无物料外排？是否进入下水/围堰/土壤？有无异常排放？ | 「无物料外排，无异常排放」／「残液已围堰收集」 |

**「没有影响」也是有效回答，但必须明确说出来**，不能靠留空表示。

## 常见口语化表述与要素对应

| 用户可能这样说 | 对应要素 |
|---|---|
| 「P-2101A 那个泵漏了，我们切备用泵了」 | 位号 P-2101A、经过（滴漏+切泵）、措施（切换备用泵）；**还缺时间、当前状态、影响** |
| 「今天早上八点多」 | 时间需追问到分，且要确认是发生时间还是发现时间 |
| 「不影响生产」 | 影响-生产方面；仍需追问安全与环保两方面 |
| 「已经处理好了」 | 当前状态需追问具体是停运隔离、备用还是已恢复运行 |
| 「肯定是机封的问题」 | **这是原因推测，不进通报**，告知用户原因一栏写「原因正在分析中」 |
| 「操作工没按规程来」 | **这是责任认定，不进通报**，追问当时实际的操作动作与参数 |

## 用户坚持要写原因/责任时的回话

用户是设备员，通报是他要发出去的，他有时会坚持。可以这样说明：

> 原因这一栏按规定写「原因正在分析中」。通报发出去就在车间里传开了，写进去的推测会被当结论用；等正式调查结论出来如果不一致，纠正的成本比多等两天大得多。您要是已经有正式调查结论，我可以按结论写，请提供结论文号。

> 关于责任，通报不做责任认定。我把当时的操作动作和参数如实写进经过，读者自己能看明白；认定由调查组出结论。

## 可能需上报时

脚本检测到人员伤害、着火爆炸、环境影响、装置停车、物料大量外泄等情形时会给出 `escalationHint`。此时必须告诉用户：

> **请按厂内规定判断是否需走事故快报流程，可使用 incident-flash-report 技能。**

判断顺序是：先判断是否达到需上报标准——达到就**先走快报**（快报时限以厂内规定为准），内部通报随后再发。是否构成设备事故及其等级按《中国石化设备事故管理规定》与厂内规定判定；描述里提到装置停车/停工的，还要按《炼化企业非计划停工管理规定》判断是否构成非计划停工事件并另行报送（与事故快报分开）。脚本不判定事件性质，也不知道厂内的分级标准，这个判断只能由用户做。

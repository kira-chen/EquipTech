# scripts 使用说明

## fill.js —— 主脚本

```bash
node "<技能目录>/scripts/fill.js" \
  --form "<自查表路径>" \
  --data "<台账与记录路径>[,<路径2>...]" \
  --workshop "<车间名>" \
  --period "<自查周期或时点>" \
  --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--form` | 是 | 自查表：`.xlsx`（可原样回写）/ `.docx`（只抽自查项，不回写原文档；需回 Word 版式时由平台 docx 技能按 `填写说明.md` 套回，不得手写 docx XML）。**PDF 先用平台 pdf 技能转为 docx/xlsx 再传入（扫描件需 OCR），脚本不读 PDF** |
| `--data` | 是 | 台账与记录 `.xlsx`，多个用英文逗号分隔；也可传同结构 CSV 目录 |
| `--workshop` | 是 | 车间名称 |
| `--period` | **是** | 自查时点 `YYYY-MM-DD`，到期类自查项以此为基准日。**不提供或不是日期直接报错**（不按脚本运行日默认）；周期为「2026年三季度」这类文字时传周期截止日（如 2026-09-30） |
| `--last` | 否 | 上次自查表，仅登记；文件不存在时报错 |
| `--spec` | 否 | 厂内填报要求说明，仅登记；文件不存在时报错 |
| `--out` | 否 | 输出目录，默认系统临时目录 `<os.tmpdir()>/saff-out`，**建议始终传** |

### 产出

| 文件 | 内容 |
|---|---|
| `自查表预填稿.xlsx` | 原表工作表（保持原结构，只往可填列写字）+ 预填明细 / 需责任人判断 / 缺数据项 / 无法解析项 / 声明 五张附表 |
| `填写说明.md` | 六节说明；有判断类项或表结构复杂时开头带醒目提示；末尾固定声明行；分析段留占位 |
| `filled.json` | prefilled、needJudgment、noData、unparsed、items、counts、dataTables、meta.statement、meta.workshopScope（各数据表车间范围核对结果数组） |
| `summary.json` | 末行摘要落盘（Windows 控制台乱码兜底） |

`counts` 字段：`items`、`prefilled`、`needJudgment`、`noData`、`unparsed`、`dataTables`、`merges`。
`summary.json` 另有 `needConfirm`（表结构是否需要用户先确认）与 `cellsWritten`（实际写入的单元格数）。
预填项的 `extra`：到期类 `overdue`/`valid`/`unknown`（到期日不详），齐全类 `total`/`filled`/`blank`；
按使用状态过滤时另有 `inUse`/`notInUse`/`statusUnknown`，按设备类别过滤时另有 `categoryMatched`/`categoryExcluded`/`categoryUnknown`。

### 退出码
- `0`：成功，末行输出 `{"ok":true,...}`
- `1`：失败，末行输出 `{"ok":false,"error":"...","warnings":[...]}`
  （含自查表/台账不存在、`--form` 传目录或格式不支持、找不到「自查项」表头、解析不出任何自查项、
  台账中无可用数据表、`--last`/`--spec` 文件不存在）

### 关键行为（不得靠模型绕过）

1. **判断类一律留空**：命中 J1~J15 任一规则的自查项，`value` 恒为 `null`，
   不挂任何数据来源，「现状」列不写一个字。判断类识别优先级高于客观项识别——
   「是否建立健全管理制度」含客观词「是否建立」，仍按判断类留空。
2. **禁用词兜底**：任何预填内容只要含「符合/已落实/健全/达标/合规/良好/正常/完好/
   有效/到位/规范/合格/满足要求/无隐患」，脚本**拒绝填入并改标 `noData`** 且记 warning。
   这是 J 系列漏判时的第二道闸。
3. **缺数据绝不按符合**：未提供该类台账、表里没数据行、缺关键字段、字段全无法解析，
   四种情形一律进 `noData` 留空，并在 `missing` 写明缺的是什么。
4. **预填必注来源**：每条预填内容在备注/依据列写
   `数据来源：<文件>/<工作表> 列「<字段>」，<取数口径>`，供逐条核对。
5. **绝不写入的列**：「是否符合」「整改措施」「责任人」「得分」「扣分」「标准分」「检查结论」「自评」——写了就是代做判定、代打分或代签字（考核打分由检查组 / 责任人完成）。
   自查表里的「填报人」「责任人签字」行也不当作自查项。`meta.neverWriteCols` 列出本表中实际存在的不写列。
6. **不判合规**：到期类只报「已过期 N、未到期 M、不详 K」，齐全类只报条目计数，
   **不输出任何达标/合规结论**。
7. **数据表归类全等优先、更具体优先**：表名先全等匹配类别表名词，再取表名包含的**最长**表名词，
   「特种设备台账」归特种设备、「设备台账」归设备台账，不再被双向包含匹配串类。
8. **同类多表按自查项选表**：一个自查项能用的表不止一张时，按类别首选表规则取表——问「隐患」取表名带「隐患」的表，
   问「缺陷/报修/故障」取表名带「缺陷/报修/故障/通知单」的表，问「压力容器/压力管道/起重/锅炉」取表名带该类设备的表；
   都不命中时保持原表序。选表依据写进来源说明「可用数据表 N 张（…），按自查项「X」选用…」。
9. **按使用状态、设备类别过滤行**（有无类除外）：
   - 自查项含「在用」（「不在用」「非在用」除外）：只计使用状态为在用（含运行、备用）的行，停用/封存/闲置/报废/拆除等排除；
     状态为空或认不出的行计「使用状态不详」**不计入**，预填内容末尾写「（另有使用状态不详 N 台未计入）」，来源说明列出行号，并记 warning。
   - 自查项点名压力容器/压力管道/锅炉/起重机械等：只计设备类别列为该类的行，其他类别排除（「常压容器」「工艺管道」不算；简写「容器」「管道」只在特种设备、检验台账里整格相等时才算）；类别为空的行计「设备类别不详」**不计入**，同样写明。
   - 台账没有使用状态列 / 设备类别列：按全部记录取数，来源说明与 warning 写明「未按使用状态筛选」「未按设备类别筛选」，须责任人核实。
   - 过滤后没有可用行：进 `noData` 并写明原因（如「没有设备类别为「压力容器」的记录」「使用状态全部为空」），不拿其他类别充数；数量类在没有「不详」行时如实报 0。
   - 使用状态列按「使用状态 / 设备状态 / 运行状态」包含匹配、裸「状态」只认全等（不会把「完好状态」当使用状态）；
     设备类别列按「设备类别 / 设备种类」包含匹配、裸「类别」「种类」只认全等。
10. **结构复杂先确认**：合并单元格 ≥5、表头在第 4 行及以后、合并信息读取失败、
   自查项落在合并区内 —— 任一触发 `needConfirm:true`，md 开头写醒目提示，
   **模型必须先与用户核对解析结果**。
11. **无 emoji**：md 醒目提示一律用「【注意】」。
12. **声明行**：`填写说明.md` 末尾固定写入
   `本表为预填稿，判断类项目与最终结论须由责任人核实填写并签字；预填内容需逐项核对后方可提交。`
   同句写入 `filled.json` 的 `meta.statement` 与预填稿的「声明」工作表。

### 车间范围核对

`--data` 中能归入数据源类别的数据表带车间列（车间 / 所属车间 / 属地车间 / 运行部）时按 `--workshop` 剔除其他车间的行并 warning，车间列为空的行保留；车间列全不一致时不筛、填写说明开头【注意】；无车间列时基本信息「车间范围」写「以取数条件为准」；维护工厂、「车间负责人」等人员列不当车间列；自查表模板本身不核对。

## lib/audit-spec.js —— 预填规则表

```js
const S = require('./lib/audit-spec');
S.classify('设备管理制度是否健全');        // → {category:'judgment', rules:[{id:'J1',...}]}
S.classify('压力容器是否在有效期内、有无超期'); // → {category:'objective', kind:'due'}
S.checkFillValue('运行正常');              // → ['正常']  拒绝填入
S.sheetSource('特种设备检验台账');          // → 'special'
S.sheetSource('特种设备台账');              // → 'special'（全等优先，不被「设备台账」抢走）
S.pickTable('隐患是否全部整改', tables);    // → {table: 隐患台账, hitWord:'隐患', basis:'可用数据表 2 张（…）…'}
```

口径见 `references/fill-rules.md`，两者**规则号一一对应**。
J 系列 15 条（判断类）、O 系列 6 条（客观类）、数据源 16 类（缺陷隐患、特种设备两类带首选表规则 `prefer`）、
行过滤口径（`STATUS_IN_USE` / `STATUS_NOT_IN_USE` / `SPECIAL_KINDS`）。
判断类优先、客观类多规则命中时按信息量取（due > complete > date > count > text > exist）。

## lib/merge-lite.js —— 合并单元格读取

```js
const M = require('./lib/merge-lite');
M.readMerges('自查表.xlsx');          // → {'自查表': [{r1,c1,r2,c2,ref}, ...]}
M.isMergedFollower(merges, 4, 1);     // → true（合并区第二行，非左上角）
```

`lib/xlsx-lite.js` 的 `readXlsx` 只返回值矩阵，丢掉 `<mergeCells>`；
本模块独立解析同一个 zip 只取这一段，不改动 `lib/` 下的共用文件。

## docx2text.js —— docx 文字层导出（排障用）

```bash
node scripts/docx2text.js --input <自查表.docx>
```

主脚本内部直接调用 `lib/docx-lite.js` 解析 docx；本脚本用于人工确认 Word 自查表的文字层读出效果。

## make-sample.js —— 样例生成

```bash
node scripts/make-sample.js [--seed <n>]
```

生成 6 份样例：主自查表（15 项，客观项与判断类混合）、主台账数据（5 张表）、
合并单元格复杂变体（8 处合并）、全判断类变体、空台账变体、带打分与结论列变体（3 项：2 预填、1 需判断，打分列全空）。
seed 改变表号、设备位号与日期细节，但结论不变：主样例配 `--period 2026-09-30` 恒为
**5 项已预填、8 项需责任人判断、2 项缺数据、0 项无法解析**。

```bash
node scripts/selftest.js
```

O 系列 O1~O6 逐条命中与 kind、客观项六种取数方式、禁用词兜底、判断类一律留空（含 xlsx 单元格级校验）、
得分/扣分/标准分/检查结论/自评/是否符合 列一个字不写（单元格级校验）、缺数据四种情形、日期无法解析不按未超期、预填必注来源、
不判合规/不代签字/声明行、合并单元格与复杂表结构确认、输入解析边界（合计行/别名表头/空行/多文件/无关数据表）、
参数校验（含 `--period` 必填与非日期报错、PDF 前置提示）、无 emoji 与「【注意】」、产出结构完整性；

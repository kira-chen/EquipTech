# 交付自检清单

运行脚本后、交付前逐项核对。

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；为 `false` 时已把 `error` 原文告知用户并终止，**未手工预填任何一项**
- [ ] `warnings` 已逐条告知用户，未隐去任何一条
- [ ] `自查表预填稿.xlsx`、`填写说明.md`、`filled.json`、`summary.json` 均已生成
- [ ] `--period` 已按自查时点（YYYY-MM-DD）传入；自查表是 PDF 的已先用平台 pdf 技能转为 docx/xlsx

## 表结构确认
- [ ] `summary.json` 的 `needConfirm` 为 `true` 时，**已先向用户展示解析结果（自查项逐条、列对应关系）并得到确认**，未直接交付填写结果
- [ ] 合并单元格数量、表头所在行已与用户核对
- [ ] 自查项条数与原表目视一致，没有串行、没有漏项

## 判断类项（最关键）
- [ ] **所有判断类项的「现状」「是否符合」列都是空的**，一个字都没填
- [ ] **没有出现「符合」「已落实」「健全」「到位」「正常」「良好」「达标」中的任何一个作为填写内容**
- [ ] 每条判断类项都标注了命中的规则号（J1~J15），可追溯到 `references/fill-rules.md`
- [ ] 没有以「供参考」「建议这样填」的名义给出判断类项的答案
- [ ] md 开头「存在须责任人判断的自查项」醒目提示保留完整，未删除或弱化

## 缺数据项
- [ ] 缺数据项**留空**，未按「符合」「无」「正常」「0」处理
- [ ] 每条都写明了**缺什么数据**（哪类台账 / 哪个字段 / 空表 / 日期无法解析）
- [ ] 未用其他台账推算代替缺失数据
- [ ] 日期无法解析的条目单列为「到期日不详」，**未按未超期处理**

## 预填项
- [ ] **每条预填内容都在备注或依据列注明了数据来源文件与记录**，可逐条核对
- [ ] 预填内容只是事实搬运（有无 / 数量 / 日期 / 到期计数 / 条目计数），**不含任何判定词**
- [ ] 到期类项只报「已过期 N、未到期 M、不详 K」，**未写成合规结论**
- [ ] 齐全类项只报条目计数，**未写成「记录齐全」**

## 不越界
- [ ] **未判定任何自查项是否达标、合规、符合要求**
- [ ] **未在「是否符合」「整改措施」「责任人」「得分」「扣分」「标准分」「检查结论」「自评」列写入任何内容**
- [ ] **未代替责任人签字**，签字栏保持空白
- [ ] 无法解析类型的自查项未做任何猜测性填写

## 声明行
- [ ] **末尾声明行逐字保留**：「本表为预填稿，判断类项目与最终结论须由责任人核实填写并签字；预填内容需逐项核对后方可提交」
- [ ] 声明行未被改写、未被移到不显眼位置、未被删除
- [ ] 产出无 emoji，醒目提示用「【注意】」
- [ ] docx 自查表需回 Word 版式时，已用平台 docx 技能按填写说明套回，**未手写 docx XML**

## 分析段
- [ ] 已替换 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字
- [ ] 字数 200~400
- [ ] 四段结构齐全：预填覆盖情况、需责任人判断项的填写要点、缺数据项要补什么台账、提交前的核对与签字提醒
- [ ] 数字全部引用 `filled.json` 的 `counts`，未自行统计
- [ ] 分析段里**没有给出任何判断类项的参考答案**

## 交付说明
- [ ] 已向用户说明：自查项总数、已预填数、需判断数、缺数据数、无法解析数
- [ ] 已说明脚本 warnings（如有）
- [ ] 已说明预填稿须由责任人逐项核对后签字提交，本技能不代填判断类项、不代签字

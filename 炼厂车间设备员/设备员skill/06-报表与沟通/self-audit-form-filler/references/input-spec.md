# 输入规格：自查表预填

## 必填参数

| 参数 | 说明 |
|---|---|
| `--form` | 自查表模板：`.xlsx`（推荐，可原样回写）/ `.docx`（只抽自查项，不回写原文档）。PDF 先用平台 pdf 技能转为 docx/xlsx 再传入 |
| `--period` | 自查时点 `YYYY-MM-DD`（**必填**，到期判定基准日） |
| `--data` | 本车间台账与记录 `.xlsx`，多个用英文逗号分隔；也可传同结构 CSV 目录 |
| `--workshop` | 车间名称 |

## 一、自查表（`--form`）的解析

### 形式一：`.xlsx` 自查表（推荐）

工作表名匹配「自查表」「自查」「检查表」「自查清单」「检查清单」（去空白与「表」字后包含匹配）。
都匹配不到时取第一张有内容的工作表并 warning。

| 列名 | 必需 | 说明 |
|---|---|---|
| 自查项 | 是 | 一行一个自查项；为空的行跳过并 warning（**不按上一行内容补齐**） |
| 序号 | 否 | 缺失时按出现顺序自动编号 |
| 自查类别 | 否 | 仅展示，不参与取数 |
| 自查依据 | 否 | 仅展示（法规/标准条文），不参与取数 |
| 现状 | 否 | **脚本可写**：预填内容写在这里 |
| 证据材料 | 否 | **脚本可写**：数据来源写在这里 |
| 备注 | 否 | **脚本可写**：留空理由与数据来源写在这里 |
| 是否符合 | 否 | **脚本绝不写**——写了就是代做合规判定 |
| 整改措施 | 否 | **脚本绝不写**——主观填报内容 |
| 责任人 | 否 | **脚本绝不写**——不代替责任人签字 |
| 得分 / 扣分 / 标准分 | 否 | **脚本绝不写**——考核打分由检查组 / 责任人完成；标准分原值保留 |
| 检查结论 / 自评 | 否 | **脚本绝不写**——结论与自评是判断 |

列名别名：

| 标准列名 | 可识别的写法 |
|---|---|
| 自查项 | 自查项、自查内容、检查内容、自查项目、检查项、检查项目、项目、内容、自查要点、检查要点、要点 |
| 序号 | 序号、编号、No、NO |
| 自查类别 | 自查类别、类别、检查类别、专业、分类、大类、项目类别 |
| 自查依据 | 自查依据、依据、标准依据、法规依据、对照标准 |
| 现状 | 现状、自查情况、实际情况、现状描述、填写内容、自查结果、检查情况、情况说明 |
| 是否符合 | 是否符合、符合情况、是否达标、自查结论、结论、评价 |
| 证据材料 | 证据材料、支撑材料、佐证材料、查阅资料、依据记录 |
| 整改措施 | 整改措施、整改要求、整改意见、措施、下步措施 |
| 责任人 | 责任人、负责人、填报人、签字 |
| 备注 | 备注、说明、备注说明 |
| 得分 | 得分、实得分、分数、评分、自评得分、实际得分 |
| 扣分 | 扣分、扣分值、扣减分、扣分原因 |
| 标准分 | 标准分、分值、应得分、满分、标准分值 |
| 检查结论 | 检查结论、检查意见、审核结论、复查结论、核查结论、检查结果 |
| 自评 | 自评、自评结果、自我评价、自查评价、自评等级、自评结论 |

**表头行识别**：取前 12 行中第一个含「自查项」别名的行。自查表常见「表名 + 填报单位 + 表头」
三行结构，因此放宽到 12 行。一行都找不到 → `ok:false`。

**列分配**两轮：先全等匹配，再前缀匹配，已被占用的列不重复分配。
这样「自查项」不会用前缀抢走「自查项类别」该占的列。

### 会被跳过的行

| 行类型 | 处理 |
|---|---|
| 整行全空 | 静默跳过 |
| 首列为 合计 / 小计 / 总计 / 共计 | 跳过并 warning |
| 首列为 填报人 / 责任人签字 / 车间负责人 / 签字 / 审核人 / 说明 / 注 | 跳过并 warning，**脚本不代签字** |
| 自查项列为空，且该单元格是合并区的从属格 | 静默跳过（属上一项） |
| 自查项列为空，非合并从属格 | 跳过并 warning，**不按上一行补齐** |

### 合并单元格

`scripts/lib/merge-lite.js` 单独读 `xl/worksheets/sheetN.xml` 的 `<mergeCells>`
（`lib/xlsx-lite.js` 的 `readXlsx` 只返回值矩阵，不含合并信息）。

合并信息读取失败时按「无合并」继续，但记 warning 并计入「表结构复杂」，
**不得据此认定「本表没有合并单元格」**。

触发「先请用户确认」的条件见 `references/fill-rules.md` 第六节。

### 形式二：`.docx` 自查表

- 找含「自查项」「检查内容」等表头的表格，按列抽取
- **不回写原 docx**，只输出 xlsx 预填稿 + 填写说明；需要回到 Word 版式时，由平台 docx 技能按 `填写说明.md` 的「已预填项与数据来源」逐项填入原表的现状/备注列，**不得手写 docx XML**，判断类与打分列仍留空（脚本 warning 提示）
- 找不到这类表格 → `ok:false`，提示改用 `.xlsx`

### 不支持的格式

`.pdf`、`.doc`、图片扫描件一律报错。**PDF 前置步骤**：先用平台 pdf 技能转为 docx/xlsx 再传入，脚本不读 PDF；扫描件需先 OCR。

## 二、台账与记录（`--data`）

每个文件的每张工作表读成一个「数据表」。不预设字段——自查表千变万化，字段在取数时按需找。

### 数据表的归类

按**工作表名**（找不到再按文件名）归入下列数据源类别之一。归不进任何类别的表
会 warning 并**不参与自动取数**（不强行拿无关台账充数）。

匹配顺序（前一轮命中即定类，比较前去掉空白与常见标点）：

1. **全等**：表名与下表某个表名词完全相同。「特种设备台账」全等命中特种设备台账类，不会被「设备台账」抢走。
2. **表名包含表名词**：取表名里包含的**最长**表名词，更长更具体的优先。
   「车间特种设备台账2026」同时包含「设备台账」「特种设备台账」，取后者；同长按下表顺序。
3. **表名是表名词的简写**（如「巡检」「设备」）：按类别顺序取第一个（「设备」归设备台账），与修复前口径一致，避免简写表整张漏掉。
4. **表名包含自查项用语**（如「人员证书」含「证书」→ 培训与资质台账）：同样取最长的词。

| 类别 | 可识别的工作表名 |
|---|---|
| 设备台账 | 设备台账、设备清单、设备总表、资产台账 |
| 特种设备台账 | 特种设备、压力容器、压力管道、特种设备台账 |
| 检验检测台账 | 检验台账、检验记录、定期检验、检测台账 |
| 校验检定台账 | 校验台账、检定台账、计量台账、仪表校验 |
| 安全阀台账 | 安全阀台账、安全附件台账、安全阀 |
| 巡检点检记录 | 巡检记录、点检记录、巡检台账 |
| 检修维修记录 | 检修记录、维修记录、检修台账、保养记录 |
| 缺陷隐患台账 | 缺陷台账、隐患台账、缺陷记录、隐患排查 |
| 培训与资质台账 | 培训记录、资质台账、人员台账、持证台账 |
| 演练记录 | 演练记录、应急演练、演练台账 |
| 作业票台账 | 作业票台账、作业票、票证台账 |
| 备件台账 | 备件台账、备品台账、物资台账 |
| 环保监测记录 | 环保记录、排放台账、监测记录、危废台账 |
| 能耗计量记录 | 能耗台账、计量台账、能耗记录 |
| 会议与活动记录 | 会议记录、活动记录、会议台账 |
| 制度文件清单 | 制度清单、制度台账、文件清单、规程清单 |

自查项一侧用自查项文字里出现的说法归类（如「压力容器是否超期」→ 特种设备台账）。
**两侧落在同一类别才会取数**，不做语义近似兜底。

### 可用的表不止一张时选哪张

按类别的首选表规则取表；都不命中时按装载顺序取第一张（`--data` 的顺序，同一文件内按工作表顺序）。

| 类别 | 自查项写了 | 首选表名含 |
|---|---|---|
| 缺陷隐患台账 | 隐患 | 隐患 |
| 缺陷隐患台账 | 缺陷、报修、故障、消缺 | 缺陷、报修、故障、通知单 |
| 特种设备台账 | 压力容器 / 压力管道 / 起重 / 锅炉 | 压力容器 / 压力管道、管道 / 起重 / 锅炉 |

例：同时提供缺陷台账与隐患台账，「隐患是否全部整改」取隐患台账，「缺陷登记数量」取缺陷台账，与两张表的先后无关。
选表依据写入来源说明：`可用数据表 2 张（X/缺陷台账、Y/隐患台账），按自查项「隐患」选用表名对应的本表`。

### 按使用状态、设备类别过滤数据行

有无类（O1）问的是台账在不在，不过滤；其余取数方式按自查项口径过滤：

| 自查项写了 | 找的列 | 计入 | 排除 | 不详（**不计入**，单列） |
|---|---|---|---|---|
| 在用 | 使用状态、设备状态、运行状态（包含匹配）；状态（只认全等） | 在用、运行、备用 | 停用、封存、闲置、报废、拆除、停运、调出、调拨 | 空或认不出的写法（如「检修」） |
| 压力容器、压力管道、锅炉、起重机械、电梯、场（厂）内专用机动车辆、气瓶 | 设备类别、设备种类（包含匹配）；类别、种类（只认全等） | 类别列为该类设备 | 其他类别 | 类别为空 |

- 「不详」的条目在预填内容末尾写「（另有使用状态不详 N 台未计入）」「（另有设备类别不详 N 台/项未计入）」，
  来源说明列出行号，并记 warning。**不推断为在用，也不推断为压力容器。**
- 台账没有对应的列：按全部记录取数，来源说明与 warning 写明「未按使用状态筛选」「未按设备类别筛选」，须责任人核实。
  表名本身就是该类设备台账（如「压力容器台账」）时不需要类别列，也不提示。
- 类别取值从严：含「压力容器」「压力管道」才算；「常压容器」「非压力容器」不算；简写「容器」「管道」只在特种设备台账、检验台账里且整格等于该词时才算，通用设备台账里的「容器」「管道」可能是常压容器、工艺管道，不算。
- 「不在用」「非在用」「未在用」是反义，不按在用筛选。
- 设备类别过滤只用于设备台账、特种设备台账、检验检测台账三类表。
- 过滤后没有可用的行 → `noData`，写明原因（「没有设备类别为「压力容器」的记录」「列「使用状态」全部为空或无法识别」），
  不拿其他类别充数。数量类在没有「不详」条目时如实报 0（如全部停用）。

### 车间范围核对

车间列（可选）：`--data` 中能归入数据源类别的数据表（会被取数的表）都可带「车间」列。表头认 车间 / 所属车间 / 属地车间 / 运行部（表头正好是这四个名字，或其后加「名称」，如「车间名称」）；「维护工厂」「计划工厂」是 SAP 工厂代码，「属地单位」「使用单位」「责任单位」「作业单位」可能是部门或承包商，「车间负责人」「车间监护人」这类人员列，都不当车间列。按 `--workshop` 核对：

| 情况 | 处理 |
|---|---|
| 未带车间列 | 不筛；填写说明基本信息「车间范围」一行写「车间范围：输入未含车间列，车间范围以取数条件为准。」（MCP 导出多数是这种情况，取数时须带 `workshop`） |
| 有本车间的行 | 剔除其他车间的行，warning 逐车间写剔除行数；车间列为空的行按本车间保留，warning 写行数 |
| 没有一行是本车间 | 不筛（避免整表剔空）；warning 以【注意】开头，填写说明标题后、第一节前加【注意】提示，多半是传错了文件 |

车间名比对去空白、忽略末尾「车间 / 运行部」（「常减压」与「常减压车间」视为同一车间）。各表核对结果写进 `filled.json` 的 `meta.workshopScope`（数组，每项含 `sheet` / `status`（noWorkshop / noColumn / checked / mismatch）/ `column` / `total` / `kept` / `dropped` / `droppedRows` / `blank`）。

归不进数据源类别的表不取数，也不核对；自查表模板（`--form`）本身不核对。`dataTables[].rows` 为核对后的行数。

### 数据表的表头与行

- 表头行：前 6 行中非空单元格最多的一行
- 首列为 合计 / 小计 / 总计 / 共计 的行跳过并 warning
- 全空行跳过
- 空表（有表头无数据行）→ warning，该表的取数一律按 `noData` 处理

### 取数会用到的字段

| 取数方式 | 找的字段（按顺序，取第一个包含关键词的列） |
|---|---|
| `date` 日期 | 上次检验、本次检验、检验日期、校验日期、上次校验、完成日期、记录日期、日期 |
| `due` 到期 | 下次检验、下次校验、有效期至、到期日、到期时间、检验有效期 |
| `complete` 齐全 | 结论、记录、状态、结果、情况，找不到再退回日期类字段 |
| `text` 标识 | 名称、设备名称、位号、编号、型号、规格、装置 |

字段找不到 → `noData` 并写明「数据表「X/Y」中没有 XX 字段」。

### 日期取值口径

- Excel 日期序列号按墙钟转换（`lib/common.js` 的 `normDate`）
- 支持 `2026-09-30` / `2026/9/30` / `2026年9月30日` / `20260930`
- 无法解析的日期：记 warning，该条不参与取数，**不按空值或今日处理**
- 到期比较基准日 = `--period`（必填，YYYY-MM-DD）；缺失或不是日期直接报错，**不按脚本运行日默认**

## 三、可选参数

| 参数 | 说明 |
|---|---|
| `--out` | 输出目录，默认系统临时目录 `<os.tmpdir()>/saff-out`，建议始终传 |
| `--last` | 上次自查表，仅登记到 meta；文件不存在时报错 |
| `--spec` | 厂内填报要求说明，仅登记到 meta；文件不存在时报错 |

## 四、CSV 目录

`--form` 不接受目录。`--data` 可传 CSV 目录：文件名即工作表名，UTF-8 或 GBK 自动识别。
CSV 没有合并单元格信息，结构复杂度判定只看表头位置。

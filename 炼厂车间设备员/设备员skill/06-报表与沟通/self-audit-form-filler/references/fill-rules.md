# 自查表预填口径与留空规范

> 规则表实现在 `scripts/lib/audit-spec.js`，与本文档**规则号一一对应**。改脚本前先读本文。

本技能只做一件事：**把台账里的客观事实搬到自查表上，并把不能搬的项如实标出来留空。**
搬运是事实工作，判断是责任人的工作。两者混在一起，自查表就成了假材料。

## 一、可预填项判定标准

**只有同时满足两个条件才预填，缺一不可：**

| 条件 | 含义 |
|---|---|
| 条件一 | 自查项是**客观事实类**：有无、数量、日期、是否到期、条目是否齐全、名称编号 |
| 条件二 | **有明确的数据来源可查**：提供了对应类别的台账数据表，且表中有可取的字段与数据行 |

只满足条件一（是客观项但没数据）→ `noData` 留空并说明缺什么数据。
不满足条件一（是判断类）→ `needJudgment` 留空，**无论有没有数据都不填**。
两个条件都判不出（表述无法归类）→ `unparsed` 留空交人工。

判定优先级**不可调换**：

```
判断类识别（J 系列） > 客观项识别（O 系列） > 无法解析
```

先查判断类。只要命中任一 J 规则，即便同时命中客观规则也按判断类留空。
例：「是否建立健全设备管理制度」含客观词「是否建立」，但也含「健全」，**按判断类留空**。
从严是故意的：漏判一条判断类就等于代人下结论，代价远大于多留一项空。

## 二、判断类项识别规则表（J 系列）

命中即 `needJudgment`，脚本一个字都不填。

| 规则号 | 名称 | 典型命中词 | 为什么不能预填 |
|---|---|---|---|
| **J1** | 健全性评价 | 健全、完善、完备、完整有效、科学合理 | 「是否健全」是对管理体系的整体评价，无客观量纲 |
| **J2** | 落实到位评价 | 落实到位、是否落实、已落实、执行到位、是否到位、严格执行 | 台账只能证明做没做，证明不了到不到位 |
| **J3** | 职责与责任评价 | 责任明确、职责明确、明确到人、责任到人、责任制落实、分工明确 | 责任是否明确须结合实际岗位运行判断 |
| **J4** | 有效性评价 | 有效性、是否有效、取得实效、效果、成效 | 培训有记录 ≠ 培训有效 |
| **J5** | 措施得当评价 | 得当、得力、恰当、适宜、切实可行、针对性强 | 措施是否得当属专业判断，不能由记录条数推出 |
| **J6** | 符合性/达标判定 | 符合要求、是否符合、满足要求、是否达标、合规 | 合规达标判定不属本技能范围（用 `regulation-compliance-check`） |
| **J7** | 规范性评价 | 规范、标准化、整洁、良好、运行正常、完好 | 状态评价须现场确认 |
| **J8** | 承诺与保证 | 承诺、保证、确保、杜绝、不再发生、严禁 | 承诺涉及责任承担，只能由责任人本人写 |
| **J9** | 意识与能力评价 | 意识、能力、素质、熟练、掌握程度、知晓 | 人员意识能力须通过考核与观察判断 |
| **J10** | 隐患判定与风险评价 | 存在隐患、重大隐患、风险可控、风险受控、安全可靠 | 是否构成隐患属专业判定，须现场核实 |
| **J11** | 原因分析与整改评价 | 原因分析、分析透彻、整改彻底、整改到位、闭环有效、举一反三 | 整改记录「已完成」≠ 整改彻底 |
| **J12** | 适用性与充分性评价 | 适用、充分、足够、满足生产需要、匹配 | 相对判断，须结合工艺与生产实际 |
| **J13** | 总体结论与自评 | 总体评价、自评结论、综合评价、自查结论、总评 | 自查表的最终结论，必须由责任人填写并签字 |
| **J14** | 主观程度副词 | 及时、认真、严格、全面、深入、扎实 | 程度词没有客观口径 |
| **J15** | 改进建议与下一步 | 建议、下一步、改进措施、整改计划、拟采取 | 主观填报内容，由责任人写 |

### 绝对不能出现的预填内容

脚本设了禁用词兜底（`checkFillValue`）：任何一条预填内容只要含下列词，
**一律拒绝填入并改标 `noData`**，同时记 warning。

```
符合 / 不符合 / 已落实 / 未落实 / 健全 / 不健全 / 达标 / 不达标 / 合规
良好 / 正常 / 完好 / 有效 / 到位 / 规范 / 合格 / 不合格 / 满足要求 / 无隐患
```

这是双保险：万一 J 系列漏判了某条表述，取数结果也不可能写出判定词。

## 三、客观项识别规则表（O 系列）

未命中任何 J 规则、且命中 O 规则的，才进入取数流程。

| 规则号 | 名称 | 典型命中词 | 取数方式（kind） | 填入格式 |
|---|---|---|---|---|
| **O1** | 有无类 | 是否建立、有无、是否有、是否编制、是否配备 | `exist` | `有，N 条记录` |
| **O2** | 数量类 | 数量、台数、台套、共有、人数、份数、条数 | `count` | `N`（人数按姓名去重，见下文「人员证书」） |
| **O3** | 日期类 | 日期、上次、最近一次、检验日期、校验日期 | `date` | `YYYY-MM-DD`（取最近一条） |
| **O4** | 到期类 | 是否到期、是否超期、有效期、到期日、下次检验 | `due` | `截至 <时点>：已过期 N 台/项，未到期 M 台/项` |
| **O5** | 齐全类 | 是否齐全、是否完整、是否全部、是否逐台、覆盖率 | `complete` | `共 N 条，列「X」已填 A 条、空缺 B 条`；整改、闭环类按状态列再分档：`；按「整改状态」分档：已整改 a 条、整改中 b 条……` |
| **O6** | 名称编号类 | 名称、编号、位号、型号、规格 | `text` | 取值列举，超 5 项写「等 N 项」 |

一条自查项命中多条 O 规则时，按**信息量**取：

```
due(6) > complete(5) > date(4) > count(3) > text(2) > exist(1)
```

例：「压力容器是否在检验有效期内、有无超期」同时命中 O1、O4，按 O4 报
「已过期 2 台、未到期 3 台」——只答「有 5 条记录」等于没答。

### 按自查项口径过滤数据行（O1 除外）

自查项写了「在用」，只计使用状态为在用（含运行、备用）的设备；点名压力容器、压力管道、起重机械等，只计该类设备。
例：「在用设备台数」不把停用、报废的算进去；「压力容器是否在检验有效期内」不把压力管道、起重机械的到期算进去；「常压容器」「工艺管道」不算压力容器、压力管道；「非在用」「不在用」不按在用筛选。

- 状态或类别为空、写法认不出的条目**不推断为符合口径**：单列「使用状态不详 / 设备类别不详 N 台」，不计入，来源说明写行号。
- 台账没有使用状态列或设备类别列：按全部记录取数，并写明「未按使用状态筛选 / 未按设备类别筛选」，须责任人核实。
- 过滤后一条都不剩：`noData`，写明「没有设备类别为「压力容器」的记录」等，不拿其他类别充数。
- 同一类别有多张表时（如缺陷台账与隐患台账），按自查项用语选表，问隐患取隐患台账，选表依据写进来源说明。

口径表见 `references/input-spec.md` 第二节。

### 人员证书、人数与作废记录

- **人员证书只计特种作业类证书**：自查项问特种作业人员、持证、证书、操作证时，培训与资质台账按「证书类型」列筛选，入厂安全教育记录、体检证明、培训记录或培训合格证、资质证明不算证书，排除条数写进来源说明；证书类型为空的单列「证书类型不详」不计入。台账没有证书类型列时按全部记录取数并写明未区分。
- **人数按姓名去重**：自查项问人数（「人数」「几人」「（人）」）时，按「姓名」列去重，一人多证只计 1 人；台账没有姓名列时 `noData`，不按记录行数充数。
- 持证人数、证书有效期两项的来源说明固定写「须人工核对」，填写说明里照录；证书口径（哪些证书算特种作业类）由责任人最终确认。
- **作废记录不计数量**：缺陷、隐患类数量项剔除状态为已删除标记（DLFL / 已取消）的记录，剔除条数写进来源说明。

### O4「到期」只报事实，不判合规

「已过期 2 台」是台账事实，「不符合特种设备安全法」是合规结论。
脚本只写前者。到期日为空或无法解析的条目，单列为「到期日不详 N 台/项」，
**绝不按未超期处理**，并记 warning。

### O5「齐全」只按条目计数

「是否齐全」在自查表里常带两层意思：条目齐不齐（客观）、管理完不完备（判断）。
脚本只做前者——按某一字段的填报情况计数，并在来源说明里写明
「**齐全与否由责任人判断，此处只报条目计数**」。
「隐患是否全部整改」这类整改、闭环问法，只报「已填 N 条」容易被读成已全部整改，所以在状态列上再按取值分档计数（已整改、整改中、未整改……），是否全部整改由责任人判断。

## 四、留空与标注规范

四种状态，都留空，但留空的理由必须写清楚。

| 状态 | 中文 | 什么时候 | 必须写明 |
|---|---|---|---|
| `prefilled` | 已预填 | 客观项且取到数 | 数据来源文件、工作表、字段、记录行 |
| `needJudgment` | 需责任人判断（留空） | 命中 J 系列 | 命中的规则号与规则名、为什么必须由人填 |
| `noData` | 缺数据（留空） | 客观项但取不到数 | **缺的是什么数据**（哪类台账 / 哪个字段 / 空表） |
| `unparsed` | 无法解析（留空） | 既非判断类也非客观类 | 未做任何猜测性填写 |

### 缺数据的四种情形，全部留空

| 情形 | `missing` 写法 |
|---|---|
| 未提供该类台账 | `未提供「作业票台账」类数据表` |
| 提供了但表里没数据行 | `数据表「X/Y」中没有任何数据行` |
| 有表有行但缺关键字段 | `数据表「X/Y」中没有到期日字段（下次检验/有效期至/到期日等）` |
| 字段全为空或全无法解析 | `数据表「X/Y」列「Z」全部无法解析为日期` |

四种情形**一律不填「符合」「无」「正常」「0」**。缺数据就是缺数据。
「无」和「缺数据」是两件事：「无」是一个事实结论，缺数据是连结论都下不了。

### 预填项必须注明来源（硬约束）

每条预填内容都要在**备注或依据列**写：

```
数据来源：<文件名>/<工作表> 列「<字段>」，<取数口径>；<异常说明>
```

例：
```
数据来源：设备台账2026.xlsx/特种设备检验台账 列「下次检验日期」，与自查时点 2026-09-30 比较得出；已过期条目：第2行(2026-08-10)、第5行(2026-05-20)
```

写来源不是为了好看，是为了让责任人能一行行点开台账核对。核对不了的预填等于没预填。

## 五、脚本绝不写入的列

| 列 | 为什么不写 |
|---|---|
| 是否符合 / 自查结论 / 评价 | 写了就是代做合规判定 |
| 整改措施 / 整改要求 | 措施是主观填报内容 |
| 责任人 / 填报人 / 签字 | **不代替责任人签字**，一个字都不写 |
| 得分 / 扣分 / 标准分 | 考核打分由检查组或责任人完成，脚本不代打分；标准分原值保留不改 |
| 检查结论 / 自评 | 结论与自评是判断，不是取数 |

自查表里的「填报人」「责任人签字」「车间负责人」行也不当作自查项，跳过并 warning。

### 自查时点必填

到期类（O4）以 `--period` 为基准日。缺失或不是日期一律报错，**不按脚本运行日默认**——按运行日算出的「已过期 N 台」看上去是事实，实际基准日是编的。周期为「三季度」这类文字时，传周期截止日。

## 六、表结构复杂时先请用户确认

以下任一情形触发 `needConfirm = true`，脚本在 `填写说明.md` 开头写醒目提示，
**模型必须先向用户展示解析结果并得到确认后再填写，不得直接交付**：

- 合并单元格 ≥ 5 处
- 表头在第 4 行或更靠后（上方有 3 行以上标题）
- 合并单元格信息读取失败（表结构未能完全确认）
- 有自查项落在合并单元格内

理由：合并单元格一旦解析错位，填进去的数就会串行，串行的预填稿比空表更危险。

合并单元格的从属行（自查项列被上一行合并占用）不重复计为一项，
但**绝不按上一行内容补齐空白的自查项**——那是猜。

## 七、表述规范

| 场景 | 应写 | 不得写 |
|---|---|---|
| 判断类项 | 留空，备注「判断类自查项，须由责任人核实后填写」 | 「符合」「已落实」「制度健全」 |
| 缺数据项 | 「缺数据：未提供作业票台账类数据表」 | 「无」「符合」「暂无异常」 |
| 到期事实 | 「截至 2026-09-30：已过期 2 台，未到期 3 台」 | 「特种设备检验合规」 |
| 齐全计数 | 「共 6 条，列「结论」已填 4 条、空缺 2 条」 | 「巡检记录齐全」 |
| 合规 | 不做判断 | 「该项符合要求」「该项不达标」 |
| 签字 | 不代签 | 在责任人列填任何内容 |
| 数字 | 引用 `filled.json` 的 `counts` | 自行统计 |

## 八、填写与提交提示（分析段）表述规范

撰写 200~400 字，结构固定为四段：

1. **预填覆盖情况**：自查项总数、已预填数、数据来源有哪几份台账。
2. **需责任人判断项的填写要点**：逐类点名（制度健全类、落实到位类、总体结论类），
   说明这些项脚本为什么没填、责任人填写时该看什么。**不提供参考答案，不给填写模板。**
3. **缺数据项要补什么台账**：逐项写清缺的是哪类台账或哪个字段，补齐后可重跑脚本。
4. **提交前的核对与签字提醒**：预填项逐条核对数据来源；判断类项与最终结论由责任人填写并签字。

### 硬约束

- **不做合规性达标判定**。数据在不在、到没到期是事实；达不达标是检查组的结论。
- **不代填判断类项**，不以「供参考」「建议填写」的名义给出判断类项的答案。
- **不代替责任人签字**。
- **不在缺数据时以「符合」或「无」作为默认填写。**
- **数字一律引用 `filled.json`**，不得自行统计。

## 九、必须保留的声明行

`填写说明.md` 末尾固定写入，**逐字保留，不得删除或改写**：

> 本表为预填稿，判断类项目与最终结论须由责任人核实填写并签字；预填内容需逐项核对后方可提交。

同一句话也写入 `filled.json` 的 `meta.statement` 与 `自查表预填稿.xlsx` 的「声明」工作表。

# 自查表预填（self-audit-form-filler）

面向中石化体系炼化厂车间（运行部）设备员，把分厂、公司或安全环保部门下发的各类专项检查自查表中能从台账取数的客观项自动预填，把需要人判断的项标出来。**只预填有数据支撑的客观项；主观判断项与无数据项一律留空标注，模型不得代填"符合""已落实"，不代打分。**

## 适用条件
- 用户说"自查表帮我填一下 / 这张表预填 / 安全大检查自查 / 专项自查表 / 考核自查表"，并提供自查表模板与本车间数据。
- 覆盖自查表类型：设备专项自查、安全生产大检查、隐患排查、特种设备自查、环保自查、设备管理考核自查。
- 车间设备员可做：客观项取数与来源标注、待判断项与缺数据项清单。**不做**：合规判定与考核打分（检查组 / 责任人）、责任人签字、判断类项答案。
- **三技能互斥**：迎检资料归集（资料在不在）用 `inspection-evidence-package`；条款符合性四档对照（达不达标）用 `regulation-compliance-check`；本技能只做自查表逐栏预填。
- 不适用：迎检资料的归集；合规性达标判定；代替用户做主观判断、打分、签字与承诺。

## 前提条件
- 输入：自查表模板（`.xlsx` 可原样回写；`.docx` 只抽自查项、输出 xlsx 预填稿），以及本车间台账与记录数据（`.xlsx` 或 CSV 目录；工作表按设备台账、特种设备、检验、校验、安全阀、巡检、检修、缺陷隐患、培训资质、演练、作业票、备件、环保、能耗、会议、制度 16 类归类）。
- **PDF 前置步骤**：脚本不读 PDF。自查表是 PDF 的先用平台 pdf 技能转为 docx/xlsx 再传入；扫描件需先 OCR。
- 必填信息：车间名称、自查表、**自查时点（`--period`，YYYY-MM-DD，到期类判定基准日；周期为"三季度"时传周期截止日）**。可选：上次自查表、厂内填报要求说明。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工预填。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 设备资产管理 | `get_equipment_ledger` | `workshop`：车间 | `--data`（目录 A） |
| 设备资产管理 | `get_special_equipment` | `workshop`：车间 | `--data`（目录 A） |
| 设备资产管理 | `get_safety_valves` | `workshop`：车间 | `--data`（目录 A） |
| 点检巡检App | `get_inspection_records` | `workshop`：车间 | `--data`（目录 A） |
| 设备资产管理 | `get_notifications` | `workshop`：车间 | `--data`（目录 A） |
| 设备资产管理 | `get_work_orders` | `workshop`：车间 | `--data`（目录 A） |
| 设备资产管理 | `get_maintenance_plans` | `workshop`：车间 | `--data`（目录 A） |
| 作业票系统 | `get_permits` | `workshop`：车间 | `--data`（目录 A） |
| HSE管理平台 | `get_personnel_certificates` | — | `--data`（目录 A） |
| HSE管理平台 | `get_hazards` | `workshop`：车间 | `--data`（目录 B） |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，除下面注明要改名的以外不改文件名，不与其他技能的文件混放；表中目录字母相同的放同一个目录，不同字母分开放，把目录作为“交给脚本”一列的参数值。
2. `get_equipment_ledger`：「设备台账.csv」不改名。
3. `get_special_equipment`：改名为「特种设备检验台账.csv」。
4. `get_safety_valves`：改名为「安全阀台账.csv」。
5. `get_inspection_records`：不改名，但要补一列「巡检日期」，取「巡检时间」的前 10 位（YYYY-MM-DD），否则“最近一次巡检时间”填不出。
6. `get_notifications`：不填 for_skill，改名为「缺陷台账.csv」。
7. `get_work_orders`：改名为「检修记录.csv」。
8. `get_maintenance_plans`：改名为「检修计划.csv」。
9. `get_permits`：改名为「作业票台账.csv」。
10. `get_personnel_certificates`：「人员证书.csv」不改名。这是全厂承包商作业人员的证书，工具不能按车间筛选；据此预填的持证人数、证书有效期，要在填写说明里注明「来源为承包商作业人员证书，非本车间职工」，由责任人核实是否适用。
11. `get_hazards`：「隐患台账.csv」不改名，单独放目录 B；目录 A、B 用逗号拼接后作 `--data`。
12. 上面的改名是为了让自查项对上正确的表：导出原名「通知单」「校验台账」「工单」等会被归错类或认不出。
13. 每个工具都要填 `workshop`：脚本只在输入带车间列时按 `--workshop` 核对（剔除其他车间的行；车间列全不一致时不筛并在报告开头提示）；MCP 导出多数不带车间列，取数时仍必须带 `workshop`，不填会把别的车间的设备和记录算进本车间的预填数。

自查表模板由用户上传或来自平台知识库，作 `--form`。

## 操作步骤
1. **解析自查表结构与自查项** —— 识别表格的行列结构、自查项文字、可填列（现状、证据材料、备注）与不可填列（是否符合、整改措施、责任人、得分、扣分、标准分、检查结论、自评）。**结构复杂或合并单元格较多时（`needConfirm:true`），先向用户展示解析结果确认，不得直接填写。**
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/fill.js" --form "<自查表路径>" --data "<台账与记录路径>[,<路径2>...]" --workshop "<车间名>" --period <YYYY-MM-DD> --out "<工作目录>/自查表预填"
   ```
   可选：`--last "<上次自查表>"`、`--spec "<填报要求说明>"`。建议始终传 `--out`，否则写到系统临时目录。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止（含缺 `--period`、`--period` 不是日期、PDF 未前置转换）；`warnings` 非空时逐条告知用户（表结构无法解析/自查项无对应数据源/合并单元格影响填写/docx 不回写等）。脚本用法详见 `scripts/README.md`。
   - **只有满足两个条件才预填：自查项是客观事实类（O1 有无、O2 数量、O3 日期、O4 到期、O5 齐全、O6 名称编号），且有明确的数据来源。** 其余一律留空。
   - 自查项属于判断类（J1~J15，如"管理制度是否健全""落实是否到位"）：标 `needJudgment` 留空，**绝不预填"符合"或"已落实"**；判断类优先于客观类。
   - 有数据源但数据缺失：标 `noData` 留空并说明缺什么数据，**绝不按"符合"或"无"处理**。
   - 到期类只报"截至 <时点>：已过期 N、未到期 M、不详 K"，不写合规结论。
   - 人员证书：持证人数按姓名去重，证书有效期与持证人数都只计特种作业类证书（入厂教育、体检、培训记录、资质证明不算）；没有姓名列时持证人数留空 noData。**这两项交付时要求责任人人工核对**，填写说明照录来源说明里的「须人工核对」。
   - 车间范围：`--data` 中能取数的数据表带「车间 / 所属车间 / 属地车间 / 运行部」列时，剔除其他车间的行并 warning，口径写在填写说明基本信息「车间范围」一行（`meta.workshopScope`）；车间列全不一致时不筛，填写说明开头有【注意】，须向用户确认。「维护工厂」、「车间负责人」这类列不当车间列；自查表模板本身不核对。
   - 隐患整改类（"隐患是否全部整改"）按整改状态分档计数，不得改写成"已全部整改"；缺陷登记数量剔除 DLFL（已删除标记）记录。
3. **读取 filled.json** —— 从 `<输出目录>/filled.json` 获取：`prefilled`（已预填项：自查项、填入内容、数据来源、依据记录）、`needJudgment`、`noData`、`unparsed`、`items`、`meta.neverWriteCols`、`counts`。
4. **生成预填稿** —— 输出填充后的自查表（保持原表结构）与 `填写说明.md`，说明哪些项已预填及其数据来源、哪些项需要用户判断、哪些项缺数据。**预填项必须在备注或依据列注明数据来源文件与记录，便于核对。** docx 自查表需回 Word 版式时，由平台 docx 技能按填写说明把预填内容填入原表的现状/备注列，**不得手写 docx XML**，判断类与打分列仍留空。
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付预填表与说明。**必须保留声明行："本表为预填稿，判断类项目与最终结论须由责任人核实填写并签字；预填内容需逐项核对后方可提交"，不得删除或改写。**

## 预期结果
- `自查表预填稿.xlsx`：原表工作表（只往现状/证据材料/备注写字）+ 预填明细 / 需责任人判断 / 缺数据项 / 无法解析项 / 声明 五张附表；`填写说明.md`：六节（基本信息、已预填项与数据来源、需责任人判断项、缺数据留空项、无法解析项、填写与提交提示），有判断类项或表结构复杂时开头带「【注意】」提示，末尾固定声明行，无 emoji。
- `filled.json`：预填明细与待办项；`summary.json`：脚本末行摘要（含 `needConfirm`、`cellsWritten`）。
- 交付时向用户说明：自查项总数、已预填数、需判断数、缺数据数、无法解析数、脚本不写的列、脚本 warnings（如有）。

## 不适用范围
- 不填写判断类、评价类、承诺类自查项；不写得分、扣分、检查结论、自评。
- 不做合规性达标判定。
- 不代替责任人签字与承担填报责任。
- 不在缺数据时以"符合"或"无"作为默认填写；不按脚本运行日默认自查时点。

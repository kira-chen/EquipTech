# 输入规格：故障案例检索

## 支持格式
- `.xlsx`（推荐）或同结构 CSV 目录（文件名 = sheet 名，UTF-8 或 GBK）
- `.docx`：Word 文件中的表格（一行一案例、首行列名；多张表格按行合并，表头以第一张为准；合并单元格占位按空处理）。无表格的 Word 文件不可用。
- `.md` / `.txt`：管道表格（`| 列 | 列 |`），分隔行自动跳过。
- **PDF 不读**：案例汇编、事故通报若为 PDF，先用平台 pdf 技能转为 txt/docx 再传入，扫描件需 OCR；转出的文本须整理成表格才能检索。
- **SAP PM 通知单导出**（IW28/IW29 列表）可直接作案例库：「描述」短文本作现象，「损坏代码/原因代码」作故障代码，「功能位置」作位号，「设备」作设备编号（8 位流水号，与位号分列）。
- 一次只接受一个案例库路径（`--cases`）。多个库请先合并成一份，或分别检索后人工比对。

## 硬前提：没有案例库就不能用这个技能

本技能的全部输出只来自 `--cases` 指向的案例库。出现以下任一情况，脚本一律 `ok:false` 并 `exit 1`，**必须向用户说明技能不可用并终止，绝不用通用知识、行业经验、模型记忆补一份"类似案例"**：

| 情况 | 脚本行为 |
|---|---|
| 未给 `--cases` | 报错「无案例库时本技能不可用」 |
| `--cases` 路径不存在 | 报错并注明不得用通用知识替代 |
| 案例库读取失败（文件损坏、非表格格式） | 报错并注明无可用案例库时技能不可用 |
| 案例库中找不到案例工作表 | 报错并列出实际工作表名 |
| 案例工作表存在，但没有一行填了现象描述 | 报错「没有任何含现象描述的可检索案例」 |

## 案例工作表

sheet 名匹配规则：去空白与「表」字后做包含匹配。以下写法均可识别：
`故障案例`、`故障案例表`、`案例库`、`案例`、`历史故障`、`故障记录`、`事故案例`、`通知单`、`IW28`、`IW29`、`IW39`、`设备故障`。
docx / md 案例库的工作表名固定记为 `故障案例(docx)` / `故障案例(md)`；产出中的「出处」写实际工作表名与行号。

### 推荐的案例记录结构

| 列名 | 必需 | 说明 |
|---|---|---|
| **现象描述** | **是** | 检索的主字段。为空的行无法参与相似度计算，会被跳过并 warning |
| 案例编号 | 否 | 缺失时用「行N」代替，保证每条案例可追溯。SAP 导出用「通知单」号 |
| 位号 / 设备编号 | 否 | 分列：「功能位置」归位号，SAP「设备」8 位流水号归设备编号，两者都呈现但不混用 |
| 故障代码 | 否 | SAP 损坏代码 / 原因代码 / 对象部件代码。给了 `--fault-code` 且代码相同的案例排序优先，但不计入相似度 |
| 设备类型 | 否 | 参与相似度计算（权重 0.30）。缺此列则类型维度不得分，并 warning |
| 故障部位 | 否 | 参与相似度计算（权重 0.15，仅当用户给了 `--part`） |
| 型号 | 否 | 不计入相似度，只作匹配依据加注与同分排序次序 |
| 设备名称 / 位号 | 否 | 呈现用 |
| 原因 | 否 | **当时该案例的结论**，交付时必须配免责说明 |
| 处置方式 | 否 | 案例的核心参考价值所在，缺此列会 warning |
| 效果 | 否 | 处置后的验证结果 |
| 发生时间 | 否 | 无法解析时输出 null（显示「—」），**不猜测** |
| 工况 | 否 | 缺失时在「不同点」中注明「案例未记录发生工况，工况差异无法判断」 |
| 来源 | 否 | 案例出处。缺此列会 warning，交付时须向用户说明来源不可核实 |
| 装置 | 否 | 所属装置/车间 |

### 现象描述怎么写才检索得准

相似度主要靠现象描述的 bigram 重合。以下写法检索效果差：

| 写法 | 问题 |
|---|---|
| 「故障」「坏了」「不正常」 | 无任何可匹配信息，与任何查询都低分 |
| 「泵有问题」 | 泛指主语 + 泛指词 |
| （空） | 直接跳过并 warning |

推荐写法：**部位 + 现象 + 量化特征 + 发生时机**，例如
「机封处持续滴漏，约 6 滴/分，泵体下方有油渍」
「驱动端轴承温度升至 82℃，运行中伴有低频异响」。

## 列名别名

别名表 = 本技能局部别名（优先）+ 共享 `SYSTEM_ALIASES`（SAP PM/MM、EM、特种设备台账、智能巡检导出列名，见顶层《中石化口径对照.md》第二节）。匹配先全等、再前缀，先认领的列不会被后面的名字抢走。

| 标准列名 | 可识别的写法（局部别名在前，共享别名在后） |
|---|---|
| 案例编号 | 案例编号、编号、案例号、序号、案例ID、ID、通知单号、通知单、通知单编号、维修通知单号、工单号、订单号、订单 |
| 现象描述 | 现象描述、故障现象、现象、问题描述、故障描述、描述、通知单描述、短文本、长文本、事件描述 |
| 设备类型 | 设备类型、设备类别、类型、设备种类、对象类型、设备品种、专业类别 |
| 设备名称 | 设备名称、名称、设备描述、技术对象描述、功能位置描述 |
| 位号 | 位号、设备位号、功能位置、TAG、tag、位号编码、功能位置编号、技术标识、技术对象、技术对象标识 |
| 设备编号 | 设备编号、设备、设备号、设备编码、技术对象编号、EM编码（**不是位号**，单独成列） |
| 型号 | 型号、规格型号、规格、设备型号、型号编号 |
| 故障部位 | 故障部位、部位、失效部位、损坏部位、对象部件、故障部件 |
| 故障代码 | 故障代码、损坏代码、损坏、故障现象代码、原因代码、代码 |
| 原因 | 原因、故障原因、原因分析、失效原因、当时判定原因、原因文本、原因说明 |
| 处置方式 | 处置方式、处理方式、处置措施、处理措施、措施、处置、处理过程、维修措施 |
| 效果 | 效果、处置效果、处理效果、验证效果、结果、验收结果 |
| 发生时间 | 发生时间、发生日期、日期、时间、通知日期、报告日期、故障日期、故障开始 |
| 工况 | 工况、发生工况、运行工况、当时工况 |
| 来源 | 来源、案例来源、出处、资料来源 |
| 装置 | 装置、所属装置、车间、单位、工厂区段、装置名称、生产单元 |

合并后的误配检查：「描述」在共享表里也是设备名称的别名，但本技能把它放在现象描述的局部别名中，且现象描述是必需列、先认领，因此 SAP 通知单的「描述」短文本归现象、「设备描述」归设备名称，不会互抢。「设备」归设备编号而不是设备名称。

表头行识别：取前 10 行中命中必需列最多的一行，因此首行是标题、第三行才是表头的系统导出表也能读。

## 检索条件（命令行入参）

| 参数 | 必需 | 说明 |
|---|---|---|
| `--symptom` | 是 | 当前故障现象描述。去标点后不足 2 字直接报错，并提示补充关键特征 |
| `--equip-type` | 是 | 当前设备类型，如「离心泵」「往复压缩机」「换热器」「阀门」 |
| `--part` | 否 | 当前故障部位。**不给则部位维度完全不参与计算**，权重归一化到现象与类型两项，不按最宽松默认 |
| `--model` | 否 | 当前设备型号。不计入相似度 |
| `--fault-code` | 否 | SAP 损坏/原因代码。代码相同的案例排序优先，不计入相似度；案例库无代码列时 warning |
| `--weights` | 否 | `text=0.55,type=0.30,part=0.15`，三项之和须为 1，text 必须 > 0；缺省项取默认。自定义时 warning 提示交付须说明 |
| `--top` | 否 | 返回条数上限，默认 5。只截断呈现条数，不改变达标判定 |
| `--min-score` | 否 | 相似度下限，默认 0.3。低于此值的案例只进 `lowSimilarity` |
| `--out` | 否 | 输出目录，默认系统临时目录 `<os.tmpdir()>/fcr-out`，建议始终传 |

## 归一表

### 设备类型
离心泵 / 往复泵 / 螺杆泵 / 泵 / 挤压造粒机 / 汽轮机（蒸汽透平）/ 螺杆压缩机 / 离心压缩机（含富气、循环氢、裂解气、丙烯、乙烯压缩机等大机组）/ 往复压缩机（含氢压机、新氢压缩机）/ 压缩机 / 换热器 / 阀门 / 风机（含主风机、空冷）/ 塔器 / 容器 / 加热炉 / 电机。
细分机型排在泛类之前；未命中归一表的按清洗后的原文比对。「往复压缩机」「离心压缩机」「螺杆压缩机」「汽轮机」视为不同类型，**不会因同含「压缩机」或同属大机组而误判为同类**——机型不同，故障机理与处置方式不可互通。

### 故障部位
机械密封（含干气密封）/ 填料密封 / 轴承（含轴瓦、推力瓦）/ 联轴器 / 叶轮 / 轴 / 润滑系统 / 冷却系统 / 管束 / 阀芯阀座 / 执行机构 / 电气部分 / 筒体壳体 / 仪表元件 / 基础地脚。
「机封」与「机械密封」、「对轮」与「联轴器」视为同一部位。

## 会被跳过的行
- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 提示）
- 现象描述为空的行（warning 提示，并计入 `counts.casesSkipped`）

# 安全环保设施状态检查（safety-environmental-device-check）

面向中石化体系炼化厂车间（运行部）设备员，按台账汇总可燃与有毒气体报警器、安全附件、联锁与防爆、消防设施、防雷防静电接地、应急器材、环保设施的检测到期与完好状态。**到期判定与完好率统计由脚本完成，失效设施必须醒目提示；模型不得判定失效设施"暂不影响使用"。**

## 适用条件
- 用户说"报警器该检测了吗 / 消防设施检查 / 接地电阻测试到期 / 安全设施完好率 / 洗眼器台账 / 安全阀爆破片到期 / 联锁防爆台账"，并提供安全环保设施台账。
- 覆盖七类设施：可燃与有毒气体检测报警器；安全附件（安全阀、爆破片、阻火器、呼吸阀）；联锁与防爆（联锁/SIS 回路、紧急切断阀、防爆电气）；消防设施（灭火器、消火栓、泡沫、喷淋、消防水泵与稳压泵）；防雷防静电接地；应急器材（洗眼器、空气呼吸器、应急照明）；环保设施（在线监测仪、废气废水处理关键设备）。
- 车间设备员可做的部分：维护台账、汇总到期与状态、编制检测计划、把失效设施登记为隐患或维修通知单。
- 由 XX 归口：安全阀等安全附件的校验周期与定期校验归 `special-equipment-inspection-due`（特种设备管理）；联锁/SIS 功能测试与联锁投切归仪表专业；报警器检定归计量；消防设施专项检测与验收归消防部门；检测结论以有资质单位报告为准；失效是否可接受由设备管理、安全与环保部门决定。本技能只做台账登记的到期与状态汇总。
- 不适用：一般生产设备的巡检（用 `inspection-task-dispatch`）；压力表温度计等计量仪表的检定校验台账（用 `valve-instrument-calibration-ledger`）；设备完好率月报指标（用 `equipment-weekly-monthly-report`）。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含「安全环保设施台账」，字段见 `references/input-spec.md`（设施类别、编号、位置、检测或维护周期、上次检测日期、检测结果、当前状态、责任人）。别名表已并入共享 `SYSTEM_ALIASES`，EM/SAP PM/特种设备台账导出列名（功能位置、设备描述、装置、检验类型、检验周期、检验日期、检验结论、用户状态）可直接读。
- 必填信息：车间名称、基准日期（YYYY-MM-DD）。可选：提前提醒天数（默认 15 天）、检测报告目录、失效设施整改记录。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工判定到期与完好率。**

## 操作步骤
1. **确认车间、基准日期与周期口径** —— 各类设施的检测周期以现行法规标准与厂内制度为准。**台账未登记周期的设施一律归待确认，脚本不内置任何周期数值；向用户确认时按 `references/facility-rules.md` 第一节指出该查哪份规定，不得凭记忆给出周期数值。** 月/季/年/半年周期按自然月折算到期（与特种设备定检口径一致），天/周按天折算。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/facility.js" --input "<xlsx路径>" --workshop "<车间名>" --date <YYYY-MM-DD> --out "<工作目录>/安全设施"
   ```
   可选：`--lead-days <提前提醒天数>`、`--category <报警器|安全附件|联锁与防爆|消防|接地|应急器材|环保设施>`、`--reports "<检测报告目录>"`、`--issues "<失效整改记录xlsx>"`。默认输出目录为系统临时目录 `<os.tmpdir()>/sedc-out`，建议始终传 `--out`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺列/类别无法识别/周期缺失/检测结果取值非法/状态与结果矛盾/编号重复/下次日期不一致等）。脚本用法详见 `scripts/README.md`。
   - 状态为"失效""故障""停用"的设施：单列 `outOfService` 并醒目提示，**无论是否在检测周期内都必须列出**。
   - 周期、上次检测日期、设施类别或当前状态缺失：归入 `undetermined`，**绝不按同类设施默认周期处理**。
   - 检测结果为不合格但无整改记录：标 `unresolvedFail` 醒目提示，**不得计入完好设施**。
3. **读取 facility.json** —— 从 `<输出目录>/facility.json` 获取：`overdue`（超期未检）、`dueSoon`（临期）、`outOfService`（失效或停用，醒目）、`unresolvedFail`（不合格未整改）、`normal`、`undetermined`、`byCategory`（分类完好率）、`metrics`（总体完好率，算不出时为 null）、`counts`、`plan`。
4. **撰写"安全环保设施状态说明"** —— 读 `references/facility-rules.md` 的表述口径，撰写 200~400 字，按"总体情况与完好率 → 失效停用设施（醒目）→ 超期未检设施 → 不合格未整改 → 临期安排 → 待确认项"结构，替换 `facility.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**数量与完好率一律引用 facility.json；完好率为 null 时写"不予计算"并说明原因，不写 0%。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `facility.md`、`facility.json` 与 `检测计划.xlsx`。**存在失效设施或超期未检时，报告开头已由脚本写入"【注意】存在失效或超期未检的安全环保设施，可能影响安全保护功能有效性，应立即整改并评估风险"，该提示不得删除或弱化。** 失效设施需登记隐患接 `hazard-closure-tracker`，需登记维修通知单接 `defect-intake-grading`。

## 预期结果
- `facility.md`：安全环保设施状态检查报告，九节：一、总体概览与完好率；二、失效停用设施（醒目）；三、超期未检清单；四、不合格未整改清单；五、临期清单；六、待确认项；七、分类完好率；八、检测计划安排；九、安全环保设施状态说明。另按需附：状态与检测结果矛盾、台账下次检测日期与计算值不一致、设施编号重复、数据提示。头部写归口说明，末尾固定声明行"本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。"
- `检测计划.xlsx`：「检测计划」明细 +「类别汇总」；`facility.json`；`summary.json`。
- 交付时向用户说明：设施总台数、失效数、超期数、不合格未整改数、完好率（或不予计算的原因）、脚本 warnings（如有）。

## 不适用范围
- 不判定设施失效是否可接受，不给出"暂不影响使用"的意见。
- 不出具检测结论（以有资质单位检测报告为准）；不判安全阀校验周期是否合规；不评价联锁/SIS 功能测试。
- 不替代消防、安全、环保部门的专项检查与验收。
- 不做应急预案与风险评估。

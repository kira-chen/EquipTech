# 交付自检清单

运行脚本后、交付前逐项核对。

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；若为 `false`，已把 `error` 原文告知用户并终止，未手工判定到期与完好率
- [ ] `warnings` 已逐条告知用户，未隐去任何一条
- [ ] `facility.json`、`facility.md`、`检测计划.xlsx`、`summary.json` 均已生成

## 醒目提示（必查）
- [ ] 存在失效设施或超期未检时，`facility.md` 开头保留了提示：「【注意】存在失效或超期未检的安全环保设施，可能影响安全保护功能有效性，应立即整改并评估风险」
- [ ] 产出 md 不含 emoji，醒目提示用「【注意】」
- [ ] 该提示未被改写、未被弱化、未被移到附录
- [ ] 无失效且无超期时，提示未被无故添加（`meta.alertNeeded` 为 false）

## 失效停用设施（最关键）
- [ ] 状态为失效、故障、停用的设施全部列入第二节「失效停用设施（醒目）」
- [ ] **在检测周期内的失效设施同样列出**，未因"还没到期"被略去
- [ ] 失效设施未计入完好设施，但计入完好率分母
- [ ] 报告与交付说明中未出现「暂不影响使用」「可继续使用」「问题不大」这类意见
- [ ] 已说明整改完成前按失去该项安全保护功能管理

## 数字一致性
- [ ] 报告与交付说明中每个数字都能在 `facility.json` 的 `counts` 与 `metrics` 中找到对应，未自行统计
- [ ] 超期天数引用 `overdueDays`，剩余天数引用 `daysLeft`，未口算
- [ ] 完好率引用 `metrics.intactRate`，未重新计算

## 完好率
- [ ] 完好率 = 完好台数 ÷ 设施总台数，分母含失效、超期、不合格、待确认全部设施；**完好 = 在用 + 结果未否定 + 未超期（含临期）**，临期已计入分子
- [ ] **分母为 0 时显示「—」，未写成 0%**
- [ ] **存在状态无法判定的设施时显示「—」，未写成 0%**，并已说明原因
- [ ] 分类完好率按同一算法计算，类别内状态不明时同样显示「—」

## 判定口径
- [ ] 待确认项（检测周期 / 上次检测日期 / 设施类别 / 当前状态缺失）单列一节，注明缺哪个字段
- [ ] **待确认项未按同类设施默认周期代算到期日**，也未在说明段凭记忆写出「一般每年一次」之类的周期数值；向用户确认周期时按 `facility-rules.md` 第一节指出该查哪份规定
- [ ] 月/季/年/半年周期按自然月折算（JSON `calcMode: months`），未按 365/90/30 天口算
- [ ] 安全阀等安全附件只按台账做到期与状态汇总，**未判定校验周期是否合规**（归 `special-equipment-inspection-due`）；联锁/SIS 只记台账状态，未评价功能测试（归仪表）
- [ ] 不合格未整改项单列一节，**未计入完好设施**，未参与到期三态归档
- [ ] 未提供整改记录时，报告写明「一律按未整改处理」，未反向推定为已整改
- [ ] 状态与检测结果矛盾的，附节并列展示，未擅自采信其一
- [ ] 台账下次检测日期与计算值不一致的，两者并列展示，未声称台账有误
- [ ] 设施编号重复的，已在附节列出并提示核实

## 检测计划
- [ ] `检测计划.xlsx` 已生成，含「检测计划」与「类别汇总」两张表
- [ ] 按设施类别与应检测日期排布，与报告第八节一致
- [ ] 失效设施的处置要求为「须立即整改或更换后复检」，未写成常规检测
- [ ] 不合格未整改项的处置要求为「须先整改后复检」，未写成直接检测

## 说明段
- [ ] 已替换 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字
- [ ] 字数 200~400
- [ ] 六段结构齐全：总体情况与完好率、失效停用设施（醒目）、超期未检设施、不合格未整改、临期安排、待确认项
- [ ] **失效设施已明确写出丧失相应安全保护功能、须立即整改并评估风险**
- [ ] **未出现「暂不影响使用」「可继续使用」这类意见**
- [ ] 未出具任何设施的检测结论

## 交付说明
- [ ] 已向用户说明：设施总台数、失效数、超期数、不合格未整改数、完好率、脚本 warnings（如有）
- [ ] 完好率为「—」时已说明算不出的原因，未报成 0%
- [ ] 已说明说明段需设备员与安全环保专责复核
- [ ] 失效设施需登记隐患时，已提示可接 `hazard-closure-tracker`；需登记设备缺陷（维修通知单）时接 `defect-intake-grading`
- [ ] 报告末尾声明行逐字保留：「本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。」

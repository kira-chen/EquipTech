# 安全环保设施周期口径与表述规范

## 一、各类设施的周期依据（类别 → 应查哪份规定）

> **本节不写任何周期数值。** 各类设施的检测/校验/检查周期以现行法规标准与厂内制度为准；台账里没登记周期的设施一律归入待确认，**脚本不代入任何默认周期**，模型也不得凭记忆给出"一般每年一次"之类的数值。
> 向用户确认周期时，按下表指出**该查哪份规定**，由用户从规定或厂内台账中取值后补入台账再重算。

| 设施类别（脚本归类键） | 典型设施 | 周期应查的规定 | 归口说明 |
|---|---|---|---|
| 报警器 | 固定式可燃/有毒气体检测报警器 | 厂内可燃有毒气体检测报警器管理规定；检定周期以计量检定机构出具的检定证书为准；日常功能检查周期按厂内规定 | 报警值/联锁值设定由工艺与仪表确认，设备员不擅自调整；检定归计量 |
| 安全附件 | 安全阀、爆破片、阻火器、呼吸阀、紧急泄放装置 | 安全阀校验周期：TSG 21 及厂内安全阀管理规定，以校验报告为准；爆破片更换周期以制造厂说明书与厂内规定为准；阻火器/呼吸阀检查周期按厂内储罐管理规定 | **校验周期与定期校验归 `special-equipment-inspection-due`**，本技能只按台账登记做到期与状态汇总 |
| 联锁与防爆 | 联锁/SIS 回路、紧急切断阀（ESD）、紧急停车系统、防爆电气 | SIS 功能测试周期：厂内安全仪表系统管理规定与 SIL 验证报告；防爆电气检查周期：厂内防爆电气管理规定与 GB 相关标准（周期值以厂内规定为准） | **SIS 功能测试与联锁投切归仪表专业**，本技能只记台账登记的测试日期与状态 |
| 消防 | 灭火器、消火栓、泡沫系统、喷淋/水喷雾、消防水泵与稳压泵、消防水池 | 厂内消防设施维护保养管理规定；专项检测以消防部门及有资质单位结论为准 | 消防设施专项检测与验收由消防部门归口 |
| 接地 | 防雷接地、防静电接地、静电跨接 | 厂内防雷防静电管理规定；检测报告以有资质检测单位为准（雷雨季节前完成的要求以厂内规定为准） | 接地电阻实测超标按不合格处理，整改复测后方可恢复 |
| 应急器材 | 洗眼器/安全淋浴、正压式空气呼吸器、应急照明 | 厂内应急器材管理规定；空气呼吸器气瓶检验周期以气瓶检验机构与 TSG 气瓶规程为准 | 气瓶检验归特种设备/气瓶管理 |
| 环保设施 | 在线监测仪（CEMS/COD/VOCs）、废气废水处理关键设备 | 在线监测比对/校准周期：生态环境主管部门要求与厂内环保设施管理规定；处理设施关键设备按厂内设备管理规定 | 比对结论以第三方比对报告为准 |

**「按厂内规定」不是一个可计算的周期**：台账里这样填写时脚本无法解析，该设施归入待确认，须补入具体周期（如"1年""半年""1季度""1月""2周"）后重算。

### 周期折算口径

- 月 / 季 / 年 / 半年 → **按自然月**折算（`C.addMonths`：1 年 = 12 个月，1 季度 = 3 个月，半年 = 6 个月；月末溢出取该月最后一天），与 `special-equipment-inspection-due`、`valve-instrument-calibration-ledger` 的定检/校验到期口径一致，不用 365 / 90 / 30 天。
- 天 / 周 / 小时 / 班 → 按天折算（`C.addDays`）。非整数月（如"1.5 月"）退回按天折算。
- JSON 每条记录带 `periodUnit`、`calcMode`（months / days）、`periodMonths`，可回溯折算方式。

### 周期缺失时的处理

脚本将该项归入 `undetermined` 单列，报告中列出缺失字段与周期原文。设备员应与安全环保专责、消防专责、仪表专责核对后补入台账再重算，**不得在报告中凭记忆代算到期日**。

## 二、归档判定口径

```
计算下次检测日期 = 上次检测日期 + 检测周期（月/季/年/半年按自然月，天/周按天）
剩余天数 = 计算下次检测日期 - 基准日期
```

| 归档 | 判定 |
|---|---|
| `outOfService` 失效停用 | 当前状态为失效、故障、停用等，**无论是否在检测周期内** |
| `unresolvedFail` 不合格未整改 | 上次检测结果为不合格且无整改闭环记录 |
| `undetermined` 待确认 | 检测周期、上次检测日期、设施类别、当前状态任一缺失或无法解析 |
| `overdue` 超期未检 | 剩余天数 < 0，超期天数 = -剩余天数 |
| `dueSoon` 临期 | 0 ≤ 剩余天数 ≤ 提前提醒天数（默认 15 天，`--lead-days` 可调） |
| `normal` 在周期内 | 剩余天数 > 提前提醒天数，且状态在用、结果未被否定 |

完好台数 = `normal` + `dueSoon`（临期仍是完好设施，见第五节）。

**归档优先级**：`outOfService` > `unresolvedFail` > `undetermined` > 到期三态。

失效停用的设施即便处于检测周期内，也已丧失安全保护功能；即便上次结果合格，状态登记为失效仍以状态为准并在附节提示矛盾，由设备员核实。

## 三、失效停用设施的处理（最关键口径）

1. **一律单列于「失效停用设施」一节并醒目提示**，无论是否在检测周期内、无论上次结果是否合格。
2. **不计入完好设施**，但计入完好率分母（设施总台数）。
3. 报告中仍保留该设施的到期情况（在周期内 / 临期 / 已超期），便于整改与复检一并排期。
4. **整改完成前，按失去该项安全保护功能管理**，相关区域的风险由工艺与安全部门评估并落实补偿措施。
5. **不得给出「暂不影响使用」「还能凑合用」这类意见**。

## 四、不合格未整改的处理

检测结果为不合格时，该设施的保护性能已被检测否定：

1. **不得计入完好设施**，单列 `unresolvedFail` 一节醒目提示。
2. **不参与到期三态归档**，不输出剩余天数与超期天数。
3. **进入检测计划**，处置要求为「上次检测不合格且无整改记录，须先整改后复检」——先整改再复检，不是直接安排检测。
4. **未提供整改记录时一律按未整改处理**，不得反向推定「无整改记录即已整改」。

只有整改记录中状态明确为闭环（已整改/已完成/已处理/已更换/已修复/已复检，且不含未、待、不、正在、进行中）的项，才恢复按上次检测日期参与到期归档，且 JSON 中保留 `remediation` 记录供追溯。

## 五、完好率算法

```
完好率 = 完好台数 ÷ 设施总台数 × 100%
```

- **完好台数** = 归档为 `normal` 或 `dueSoon` 的台数，即 **完好 = 在用 + 结果未否定 + 未超期（含临期）**。临期设施仍在周期内、保护功能未失效，**计入完好**；只有超期未检、失效停用、不合格未整改、待确认不进分子。与口径对照第六节「安全设施完好率」一致。
- **设施总台数** = 分母，包含失效停用、超期未检、不合格未整改、待确认在内的全部设施。
- **分母为 0 时，完好率为 `null`，报告显示「—」，不得写 0%**。
- **范围内存在当前状态无法判定的设施时，完好率为 `null`，报告显示「—」，不得写 0%**——完好判定依赖状态，状态不明就算不出完好率。
- 分类完好率按同一算法在每个设施类别内分别计算，规则一致。

**0% 与「—」是两回事**：0% 意味着"确实一台完好设施都没有"，是有效的计算结果；「—」意味着"算不出来"。两者不得互相替代。

## 六、说明段表述规范

撰写 200~400 字，结构固定为六段：

1. **总体情况与完好率**：设施总台数、各归档分布、总体完好率（引用 `metrics.intactRate`，为 null 时写"完好率不予计算"并说明原因）。
2. **失效停用设施（醒目）**：逐台列明编号、名称、位置、状态原文，明确写出**该设施已丧失相应安全保护功能，整改完成前按失去该项保护管理，须立即整改并由安全部门评估风险与补偿措施**。
3. **超期未检设施**：列明编号与超期天数，写明**超期未检期间该设施的保护功能有效性无保障**。
4. **不合格未整改**：列明设施与结果原文，说明须先整改后复检，未计入完好设施。
5. **临期安排**：按类别说明临期设施与建议安排窗口。
6. **待确认项**：列明缺哪个字段、需向谁核实（安全环保专责、消防专责、仪表专责），并按第一节指出该查哪份规定。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 失效报警器 | 「GD-2101 状态为故障，已丧失气体检测报警功能，整改完成前按失去该项保护管理」 | 「虽然故障但还在周期内，暂不影响使用」 |
| 停用洗眼器 | 「YJ-2301 已停用，该区域应急冲洗能力缺失，须立即恢复或设置临时替代措施」 | 「停用中，等有空再修」 |
| 超期接地 | 「JD-2401 接地电阻测试超期 54 天，防雷保护有效性无保障」 | 「接地一般不会坏，问题不大」 |
| 安全阀 | 「PSV-101 台账登记校验到期，校验周期与校验结论以 special-equipment-inspection-due 与校验报告为准」 | 「安全阀一年一校，已超期」（本技能不判校验周期） |
| 不合格项 | 「上次检测不合格且无整改记录，未计入完好设施，须先整改后复检」 | 「重新测一次就行」 |
| 待确认项 | 「检测周期未登记，未按同类设施默认周期推算，请查厂内××管理规定后补入台账」 | 「按报警器 1 年周期算，已超期 X 天」 |
| 完好率算不出 | 「有 1 台设施状态无法判定，完好率不予计算，显示为「—」」 | 「完好率 0%」 |
| 数字 | 引用 facility.json 的 counts 与 metrics | 自行统计或估算 |

### 硬约束

- **不判定设施失效是否可接受**，不给出「暂不影响使用」「可继续使用」的意见。处置由设备管理、安全与环保部门决定。
- **不出具检测结论**。某台设施是否合格以有资质单位的检测报告为准。
- **不延长周期**。台账周期与厂内规定不一致时如实提示，不擅自按更宽松的周期计算。
- **不对待确认项代算到期日**。缺字段就是缺字段。
- **完好率算不出时写「—」**，不写 0%。

## 七、必须醒目写入的提示

存在失效设施或超期未检设施时，报告开头必须原样保留（脚本已直接写入，不得删除或弱化）：

> **【注意】存在失效或超期未检的安全环保设施，可能影响安全保护功能有效性，应立即整改并评估风险**

产出 md 不用 emoji，醒目提示一律用「【注意】」。报告末尾另固定写入声明行（不得删除）：

> 本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。

报告头部另写入归口说明：本技能只做安全环保设施台账的到期与状态汇总；安全阀等安全附件的校验周期与定期校验归 `special-equipment-inspection-due`，联锁/SIS 功能测试归仪表专业，检测结论以有资质单位报告为准。

## 八、下游衔接与归口互指

- 失效设施需登记为隐患 → `hazard-closure-tracker`；需登记为设备缺陷（维修通知单）→ `defect-intake-grading`
- **安全阀校验周期、定期校验到期** → `special-equipment-inspection-due`（本技能的「安全附件」类只做台账登记的到期与状态汇总，不判校验周期是否合规）
- 压力表、温度计等计量仪表的检定校验台账 → `valve-instrument-calibration-ledger`
- 联锁/SIS 功能测试、联锁投切 → 仪表专业归口，本技能只记台账状态
- 一般生产设备的巡检 → `inspection-task-dispatch`；设备完好率（月报指标）→ `equipment-weekly-monthly-report`，与本技能的「安全设施完好率」是两个指标
- 整改需要排停车窗口 → 车间检修计划

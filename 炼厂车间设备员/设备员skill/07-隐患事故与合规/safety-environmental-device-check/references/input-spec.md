# 输入规格：安全环保设施状态检查

## 支持格式
- `.xlsx`（推荐）或同结构 CSV 目录（文件名 = sheet 名，UTF-8 或 GBK）
- 一次只读一个台账文件：`--input 安全环保设施台账.xlsx`

## 安全环保设施台账工作表（必需）

sheet 名匹配规则：去空白与「表」字后做包含匹配，因此「安全环保设施台账」「安全环保设施」「设施台账」「安全设施」「环保设施」均可识别。**找不到任一匹配的工作表时脚本报错退出**（这是唯一数据源）。

| 列名 | 必需 | 说明 |
|---|---|---|
| 设施编号 | 是 | 设施位号或编号，为空的行会被跳过并 warning；重复出现 → warning 提示核实是否重复登记 |
| 检测周期 | 是 | 见「周期取值」；缺失或无法解析 → 该项归入待确认 |
| 上次检测日期 | 是 | 见「日期取值」；缺失或无法解析 → 该项归入待确认 |
| 设施类别 | 否 | 见「设施类别」（七类：报警器、安全附件、联锁与防爆、消防、接地、应急器材、环保设施）；无法识别 → 归入待确认并 warning |
| 设施名称 | 否 | 类别为空时，脚本会用名称与检测项目的关键词辅助识别类别 |
| 安装位置 | 否 | 写入检测计划，便于安排现场作业 |
| 检测项目 | 否 | 如「检定」「日常功能检查」「月检」「年检」「接地电阻测试」「比对」 |
| 检测结果 | 否 | 见「结果取值」；为「不合格」且无整改记录 → 标 `unresolvedFail` |
| 当前状态 | 否 | 见「状态取值」；为失效/故障/停用 → 归入 `outOfService`；缺失或无法归类 → 归入待确认，且完好率不予计算 |
| 责任人 | 否 | 写入检测计划 |
| 下次检测日期 | 否 | 与按周期计算值不一致时**两者并列**并 warning，不擅自采信其一 |

| 安装位置 | 安装位置、位置、装置区、区域、所在位置、安装地点、装置、工厂区段、单元、装置名称 |
| 检测项目 | 检测项目、检测内容、维护项目、检查项目、检验类型、检验类别、检验项目、项目 |
| 检测周期 | 检测周期、维护周期、周期、检查周期、检定周期、校验周期、检验周期 |
| 上次检测日期 | 上次检测日期、上次检测、末次检测日期、上次检查日期、检测日期、检查日期、上次维护日期、上次检定日期、上次检验日期、检验日期、校验日期 |
| 检测结果 | 检测结果、结果、检测结论、结论、检查结果、检验结论、检验结果、校验结果、判定 |
| 当前状态 | 当前状态、状态、设施状态、运行状态、完好状态、设备状态、用户状态 |
| 责任人 | 责任人、负责人、管理人、专责、属地专责 |

> SAP「设备编号」是 8 位流水号而非位号；本技能把「功能位置」与「设备编号」都归入「设施编号」列（二者取其一作为设施标识），**两列并存时优先取功能位置**（「设备编号」排在别名表最后），因此 SAP 导出可保留两列。

表头行识别：取前 10 行中命中必需列最多的一行，因此首行是标题、第三行才是表头的系统导出表也能读。

## 设施类别

按「设施类别」列，列为空时用「设施名称」与「检测项目」列的关键词辅助识别，按下表顺序首个命中归入七类之一：

| 归类 | 可识别的关键词 | 归口说明 |
|---|---|---|
| 报警器 | 报警器、可燃气体、有毒气体、气体检测、检测报警、探测器、硫化氢、H2S、LEL、一氧化碳、CO报警 | 检定归计量 |
| 安全附件 | 安全阀、爆破片、阻火器、呼吸阀、安全附件、紧急泄放、泄压阀 | **只做台账到期与状态**；校验周期与定期校验归 `special-equipment-inspection-due` |
| 联锁与防爆 | 联锁、SIS、安全仪表、紧急切断、ESD、切断阀、紧急停车、防爆、隔爆、本安、增安 | SIS 功能测试归仪表专业，只记台账状态 |
| 消防 | 消防、灭火器、消火栓、泡沫、喷淋、水喷雾、火灾报警、灭火系统、消防水炮、干粉、消防水、消防泵、稳压泵 | 专项检测由消防部门归口 |
| 接地 | 接地、防雷、防静电、接地电阻、避雷、静电跨接、导除静电 | |
| 应急器材 | 洗眼器、空气呼吸器、正压式、应急照明、安全淋浴、急救、逃生、应急器材、呼吸器 | 气瓶检验归特种设备 |
| 环保设施 | 在线监测、比对、VOCs、废气、废水、污水、脱硫、脱硝、除尘、环保、CEMS、烟气 | |
| **未识别** | 以上都不匹配的其他文字（如「某种装置」） | |

**未识别的设施归入待确认单列**，不按任何一类的默认周期处理；分类完好率中单列「未识别」一档。

## 状态取值

| 归类 | 可识别的写法 |
|---|---|
| `outOfService` 失效停用 | 失效、故障、停用、损坏、报废、拆除、瘫痪、不可用、待修、离线、未投用 |
| `inService` 在用 | 在用、完好、正常、投用、运行、好用、有效、OK、√ |
| **无法归类** | 以上都不匹配的其他文字（如「待复核」），warning + `status: null` |
| **未填写** | 空单元格，`status: null`，不按在用处理 |

**`outOfService` 的设施无论是否在检测周期内、无论上次检测结果是否合格，一律单列于「失效停用设施」一节并醒目提示**，这是归档优先级最高的一档。

状态为 `null`（缺失或无法归类）的设施：归入待确认，**且该设施所在范围的完好率不予计算（显示「—」）**，因为完好台数的判定依赖状态。

## 结果取值

| 归类 | 可识别的写法 |
|---|---|
| 合格 | 合格、通过、符合、正常、良好、OK、√ |
| 不合格 | 不合格、未通过、不符合、超标、超差、异常、失效、故障、NG、不达标 |
| **无法归类** | 以上都不匹配的其他文字（如「待出报告」），warning + `result: null` |
| **未填写** | 空单元格，`result: null`，不按合格处理 |

## 周期取值

| 写法 | 折算到期日 |
|---|---|
| `1年` / `每年` / `1y` | **上次检测日期 + 12 个自然月**（`C.addMonths`） |
| `半年` | + 6 个自然月 |
| `1季度` / `每季` / `1q` | + 3 个自然月 |
| `1月` / `1个月` / `每月` / `1m` | + 1 个自然月（月末溢出取该月最后一天，如 01-31 + 1 月 = 02-28） |
| `1周` / `每周` / `1w` | + 7 天 |
| `30天` / `30d` / `30` | + 30 天 |
| `每班` / `每 N 小时` | 按小时折算为天（共享库 `parsePeriodDetail`） |
| 非整数月（如 `1.5月`） | 退回按天折算（45 天） |

每条记录的 JSON 带 `periodUnit`（月/季/年/半年/天/周/小时/班）、`calcMode`（`months` / `days`）与 `periodMonths`，可回溯折算方式。

无法解析（如「按厂内规定」「视情况」）→ warning + `periodDays: null`，该项归入待确认，**绝不代入同类设施的默认周期**。本技能不内置任何周期数值；各类设施该查哪份规定见 `facility-rules.md` 第一节，周期值由用户从规定或台账中取。

## 日期取值
- 支持：`2026-09-21`、`2026/9/21`、`2026年9月21日`、`20260921`、Excel 日期单元格、Excel 日期序列号
- 无法解析 → warning + `null`，该项归入待确认

## 失效整改记录（可选，`--issues`）

工作表名：「整改记录」「整改清单」「失效整改」「整改」「不合格项」。

| 列名 | 必需 | 说明 |
|---|---|---|
| 设施编号 | 是 | 与台账设施编号对应 |
| 整改状态 | 否 | 含「已整改/已完成/已处理/已更换/已修复/已复检/闭环」且不含否定词（未/待/不/正在/进行中）才算闭环 |
| 整改完成日期 | 否 | 写入 JSON 的 `remediation` |
| 整改措施 | 否 | 写入 JSON 的 `remediation` |

**未提供此项时，台账中所有「不合格」结果一律按未整改处理并单列**，并 warning 提示。这是就严口径，不得反向理解为「无整改记录即已整改」。

## 检测报告目录（可选，`--reports`）

仅校验目录存在性并记录于 `meta.reports`，不影响任何判定。检测结论以有资质单位出具的报告为准。

## 会被跳过的行
- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 提示）
- 设施编号为空的行（warning 提示）

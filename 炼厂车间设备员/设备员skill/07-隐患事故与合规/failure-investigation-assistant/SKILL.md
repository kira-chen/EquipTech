# 故障调查辅助（failure-investigation-assistant）

面向中石化体系炼化厂车间（运行部）设备员，为设备故障调查归集材料、梳理时间线、按中石化设备事故调查报告常规章节搭建报告框架，交车间设备主任 / 公司设备管理部门与调查组使用。**本技能只做资料归集与框架搭建，绝不做原因认定、事故定性与分级、责任划分、损失核定；原因分析、责任分析、防范措施三节恒为空，由调查组填写。**

## 适用条件
- 用户说"这次故障要做调查 / 梳理一下时间线 / 调查报告框架 / 调查要准备哪些材料"，并提供相关记录。
- 适用于设备故障的内部技术分析材料准备，为正式调查提供材料基础。
- **车间设备员可做的部分**：归集各来源记录、按时间排序、标注数据缺口与时间戳差异、罗列检修历史、列待查材料清单、搭报告框架。
- **由 XX 归口（本技能不做）**：事故定性、等级认定、是否构成非计划停工事件——公司设备管理部门（机动部/设备部）与依规成立的调查组；原因分析、责任分析、防范措施、损失核定——调查组；事故快报报送——按厂内规定由归口部门办理。
- 不适用：事故快报的编报；内部情况通报；事故定性与责任认定；替代法定事故调查组的工作；日常异常的快速初判；同台设备重复故障统计；案例库检索。

## 前提条件
- 输入：与故障相关的记录（`.xlsx`/同结构 CSV 目录），可含运行参数（DCS 历史导出）、报警记录（DCS 报警/SOE）、操作记录、巡检记录（智能巡检 APP / 点检仪导出）、值班记录、检修历史（SAP PM 工单导出 IW38/IW39 列名可直接读）。
- **PDF 先用平台 pdf 技能转为 txt/docx 再传入，脚本不读 PDF；扫描件需 OCR。** 转出的文本须整理为上述表格结构后再传给脚本；Word 记录同样先整理成表。
- 必填信息：设备位号（功能位置）、故障发生时间（ISO 8601 带时区）、故障现象。可选：时间窗口、设备名称、车间。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工拼接时间线。**

## 操作步骤
1. **确认故障基本信息与时间窗口** —— 位号、发生时间、现象、需回溯的时间窗口与缺口阈值。**脚本默认"故障前 72 小时至故障后 24 小时、缺口阈值 120 分钟"是经验默认，不是制度数值，须与用户确认；确认后用 `--before`/`--after`/`--gap` 传入**，未传时产出会以「【注意】」标出使用了经验默认。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/investigate.js" --tag "<位号>" --time <ISO 8601 带时区> --symptom "<故障现象>" --records "<记录路径>[,<路径2>...]" --before <回溯小时> --after <后续小时> --gap <缺口阈值分钟> --out "<工作目录>/故障调查"
   ```
   可选：`--history "<检修历史xlsx，可为 SAP PM 工单导出>"`、`--params "<运行参数xlsx>"`、`--name "<设备名称>"`、`--workshop "<车间>"`。未传 `--out` 时写系统临时目录 `<os.tmpdir()>/fia-out`，建议始终传 `--out`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（记录时间不在窗口内/记录类型无法识别/时间戳缺失或不一致/数据缺口/检出禁用表述等）。脚本用法详见 `scripts/README.md`。
   - 各来源时间戳不一致（如 DCS 时间与手工记录时间差异）：**全部保留并标注来源与差异，绝不自行校准或取其一**。
   - 时间窗口内存在数据缺口：明确标注缺口区间，**绝不用插值或推测填补**。
   - 检修类别按《中石化口径对照》映射为 装置大检修 / 日常维修 / 抢修 / 专项（大修→大检修，中修/小修→日常维修；SAP 订单类型只映射 PM01/PM03，PM02 等厂内可配置项不猜），原文保留。
3. **读取 investigation.json** —— 从 `<输出目录>/investigation.json` 获取：`timeline`（按时间排序的事件序列：时间、来源、内容、数据类型）、`paramChanges`（故障前后参数）、`alarms`（报警序列）、`maintenanceHistory`（相关检修历史，含 `categoryNorm` 检修分级与工单/通知单号）、`dataGaps`、`timeInconsistency`、`missingTime`、`outOfWindow`、`causalHits`（检出的禁用表述）、`toInvestigate`（建议进一步收集的材料清单）、`counts`、`meta.window.defaulted`（哪些阈值用了经验默认）。
4. **核对调查报告框架** —— 脚本已按 `assets/templates/investigation-template.md` 写出十节：一、故障概况 → 二、故障经过（时间线）→ 三、故障前后参数与报警 → 四、相关检修与变更历史 → 五、数据缺口与时间戳差异 → 六、待查材料清单 → **七、原因分析（留空，由调查组填写）→ 八、责任分析（留空，由调查组填写）→ 九、损失情况（由调查组核定，脚本不估算）→ 十、防范措施（留空，由调查组按"四不放过"填写）**。章节对应中石化设备事故调查报告常规章节；本材料未定性，标题统一用"故障"。**时间线只陈述记录中的事实，不添加因果连接词（如"导致""因此"）；七、八、十三节必须留空，`<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间一个字都不写。** `causalHits` 非空时，成文引用这些记录须改写为客观时序陈述，但不改记录原文。
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `investigation.md` 与 `investigation.json`。**必须保留两行声明："本材料为调查辅助归集，不含原因认定与事故定性；故障原因、性质与责任须由依规成立的调查组认定"与"本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。"，不得删除或改写。若用户要求填写原因结论、事故等级或责任，须说明本技能不提供该内容。**

## 预期结果
- `investigation.md`：调查报告框架，十节（故障概况、故障经过（时间线）、参数与报警、检修与变更历史、数据缺口与时间戳差异、待查材料清单、原因分析（空）、责任分析（空）、损失情况（由调查组核定）、防范措施（空）），另有"附一、检出的禁用表述"（有命中时）与"附：数据提示"（有 warnings 时），开头与末尾各含两行固定声明。
- `investigation.json`：结构化时间线与材料清单；`summary.json`：脚本末行摘要。
- 交付时向用户说明：时间线条目数、数据缺口、时间戳不一致项、建议补充收集的材料、哪些阈值用了经验默认、脚本 warnings（如有）；并提示：是否构成设备事故及等级、是否属非计划停工事件，按《中国石化设备事故管理规定》《炼化企业非计划停工管理规定》由公司设备管理部门与调查组认定，报送时限以厂内规定为准。

## 不适用范围
- 不做故障原因认定、事故定性与分级、责任划分、损失核定。
- 不在时间线中添加因果推断。
- 不替代法定事故调查程序与调查组职责。
- 不涉及人员姓名与追责性内容。
- 不编报事故快报（用【炼化】事故事件快报 incident-flash-report）、不写内部通报（用 equipment-event-notice）。

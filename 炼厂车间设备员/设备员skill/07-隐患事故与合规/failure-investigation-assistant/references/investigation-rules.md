# 故障调查资料归集口径

> 本技能只做**资料归集与框架搭建**。原因认定、事故定性与分级、责任划分、损失核定不在范围内，一律由依规成立的调查组与公司设备管理部门完成。

## 〇、报告框架（对齐中石化设备事故调查报告常规章节）

| 节 | 内容 | 谁填 |
|---|---|---|
| 一、故障概况 | 位号、名称、车间、发生时间、现象、归集窗口、条目数 | 脚本 |
| 二、故障经过（时间线） | 各来源记录按时间排序，只陈述事实 | 脚本 |
| 三、故障前后参数与报警 | 运行参数与报警序列原值 | 脚本 |
| 四、相关检修与变更历史 | 检修记录罗列，含检修分级映射与工单/通知单号 | 脚本 |
| 五、数据缺口与时间戳差异 | 缺口区间、各来源时间戳差异、缺失与超窗记录 | 脚本 |
| 六、待查材料清单 | T1~T13 | 脚本 |
| **七、原因分析** | **恒为空**，`ANALYSIS_START/END` 之间一个字不写 | 调查组 |
| **八、责任分析** | **恒为空** | 调查组 |
| **九、损失情况** | 直接经济损失、停工/降量时间、是否非计划停工、事故等级，全部「由调查组核定」，脚本不估算 | 调查组 / 公司设备管理部门 |
| **十、防范措施** | **恒为空**，由调查组按「四不放过」制定 | 调查组 |

章节名对应中石化设备事故调查报告的「事故概况、事故经过、原因分析、责任分析、损失情况、防范措施」；本材料未作定性，标题统一用「故障」，由调查组定性后改写标题。

**分级与报送衔接**：是否构成设备事故及其等级、是否属于非计划停工事件，按《中国石化设备事故管理规定》《炼化企业非计划停工管理规定》由公司设备管理部门与调查组认定；报送时限以厂内规定为准，本技能不判定、不转述任何时限数值。需上报的事故快报用事故事件快报（incident-flash-report），内部情况通报用 equipment-event-notice。

**经验默认须确认**：回溯 72 小时 / 后续 24 小时 / 缺口阈值 120 分钟是经验默认，不是制度数值；`meta.window.defaulted` 记录哪些项用了默认，md 开头以「【注意】」提示，成文前须与用户确认并按需用 `--before`/`--after`/`--gap` 重跑。

## 一、本技能的边界（读之前先记住）

| 做 | 不做 |
|---|---|
| 按时间排序归集各来源记录 | 判断哪条记录是原因、哪条是结果 |
| 标注各来源时间戳的差异 | 校准时间、判断哪个时间对 |
| 标注数据缺口区间 | 插值、推算缺口区间的数值 |
| 罗列检修历史 | 判断某次检修与本次故障是否相关 |
| 列出建议进一步收集的材料 | 按清单倒推原因方向 |
| 搭出调查报告框架 | 填写「分析与结论」一节 |

**若用户要求填写原因结论、事故定性或责任划分**：按本文件末尾的固定答复说明本技能不提供该内容，引导其由调查组填写；不得以「仅供参考」「初步判断」等名义变相给出。

## 二、时间线构建口径

### 2.1 入选范围

1. 落在时间窗口 `[故障时间 − before, 故障时间 + after]` 内；
2. 有可解析的时间戳。

不满足的**不丢弃**：超窗的进 `outOfWindow`，无时间戳的进 `missingTime`，分别在 md 的 5.4、5.3 节单列。

### 2.2 排序与并列

按时间升序；同一时刻的多条按「工作表名 + 行号」稳定排序。**同一时刻的先后不代表因果**，md 的时间线一节固定附注这句话。

### 2.3 每条必须带的字段

| 字段 | 说明 |
|---|---|
| 时间 | 记录中的原始时间，归一为「YYYY-MM-DD HH:mm」北京时间 |
| 来源 | 「来源」列的值，为空时取工作表名 |
| 内容 | 记录原文。运行参数类无内容时拼为「参数名 数值 单位」 |
| 数据类型 | 运行参数 / 报警 / 操作记录 / 巡检记录 / 值班记录 |
| 出处 | 文件名/工作表名 + 行号，可回原始记录复核 |
| 相对故障(h) | 与故障时刻的小时差，**只是时间差，不含因果含义** |

### 2.4 只陈述事实

时间线条目的内容一律取记录原文，脚本**不改写、不归纳、不删减**。模型成文时同样只能引用原文，不得把两条记录并成一句带因果的话。

## 三、禁止的因果表述清单（硬约束）

> **规则同源说明**：本表（C1~C8、J1~J5）与 `06-报表与沟通/equipment-event-notice/scripts/lib/rules.js` 的 S1x~S4x 禁用词规则是同一套口径（未经调查不得归因、定性、认定责任），J1 与 S41 的「事故」负向排除词表（事故池/事故柜/事故罩/事故照明/事故状态/事故应急/事故预案/事故柴油/事故泵/事故排放/事故水/事故阀/事故排污/事故电源/事故风机/事故隔离）必须一致。目前两处各自维护、没有单一事实源：**改一处须同步另一处**，selftest 2.1z 会比对两边 J1/S41 正则是否一致。

时间线与各节描述中**不得出现因果连接词**。脚本逐条扫描，命中即列入 `causalHits` 并 warning，在 md「附一」单列，但**不自动删改记录原文**——记录是证据，改写记录本身就是篡改。

### 3.1 因果连接类（C1~C8，全部必须改写）

| 规则号 | 命中词 | 为什么禁止 | 建议改法 |
|---|---|---|---|
| C1 | 导致 | 断言了尚未认定的因果链条 | 改为时序表述：「其后出现……」「随后……」 |
| C2 | 因此、故而、因而 | 推论连接词，时间线只陈述记录事实 | 拆成两条独立条目，各自标注来源 |
| C3 | 造成 | 断言了尚未认定的因果链条 | 改为「现场出现……」 |
| C4 | 引起、引发 | 断言了尚未认定的因果关系 | 改为「同期出现……」或按时序分条 |
| C5 | 说明、表明、反映出（**仅推论句式**） | 「说明密封已失效」「表明存在磨损」「反映出润滑不足」是从事实推出结论，属分析范畴 | 删去推论，只保留观察到的记录内容 |
| C6 | 由于、因为、系因 | 在调查结论出具前陈述因果 | 删去因果表述，只陈述现象与动作 |
| C7 | 致使、以致、从而 | 断言了尚未认定的因果链条 | 改为时序表述 |
| C8 | 所致、原因是、原因为、根本原因、起因是 | 在正式调查结论前给出原因结论 | 删去；原因由调查组认定 |

C5 的限定：只拦**动词用法且后接结论性子句**的推论句式；名词性或非推论用法不命中——「设备说明书」「使用说明」「情况说明：」「补充说明如下」「说明栏」「已向班长说明」都不报。现场记录里"说明书""情况说明"极常见，不加限定会把正常名词当禁用词。

**改写示范**

| 原文 | 改为 |
|---|---|
| 轴承温度升高导致振动增大 | 10:00 轴承温度记录 88 ℃；10:12 振动高报（两条独立条目，各自标注来源） |
| 由于润滑不足，泵体异响 | 10:35 现场记录泵体异响（润滑情况列入待查材料清单） |
| 报警序列说明密封已失效 | 报警序列：10:12 温度高报 → 10:33 振动高报 → 10:40 低压报警（只列序列） |
| 因此切换至备用泵 | 10:47 切换至备用泵 P-3201B（只陈述动作与时间） |

### 3.2 定性类（J1~J2）与责任类（J3~J4）

| 规则号 | 命中词 | 说明 |
|---|---|---|
| J1 | 事故（排除 事故池/事故柜/事故照明/事故状态/事故应急 等现场正常名词） | 正式定性用语，事件性质须由调查组认定；材料中一律用「故障」「事件」「异常」 |
| J2 | 定性为、认定为、构成 XX 事故、属于 XX 事故 | 属于事件定性 |
| J3 | 责任在、负有责任、承担责任、追责、失职、渎职 | 属于责任划分 |
| J4 | 操作不当、操作失误、误操作、违章、违规、未按规程、把关不严 | 属于责任认定用语，须有核查依据并由调查组认定；改为陈述记录中的实际操作动作与参数 |

### 3.3 推测类（J5）

命中「可能是、估计是、怀疑、初步判断、应该是、大概率」。本材料不含原因推测——有疑问的方向，**写进待查材料清单让调查组去核实**，不写进正文。

### 3.4 个人姓名追责（N1）

「身份标记 + 姓名 + 追责词」三者同时出现才判定，避免把「已通知钳工班组张师傅到场确认」这类事实陈述误报。命中后改为岗位或班组的客观陈述。

**整份材料不出现人员姓名**：写「外操」「值班长」「钳工班组」，不写具体是谁。

## 四、时间戳不一致的处理（硬约束）

DCS 时间、操作站时间、手工记录时间、巡检 APP 时间往往对不上。判定条件：**同一内容（归一后相同）出现在两个以上不同来源，且时间戳不同。**

处理口径只有一条：**全部保留，按来源分别标注差异，绝不自行校准、绝不取其一。**

- 不按「DCS 时间更准」取 DCS 值——DCS 也可能没对时；
- 不取最早或最晚——那是在替调查组做判断；
- 不取中位数、不做平均——时间戳不是可以平均的量；
- 差异原因（系统对时、人工补录、记录滞后）**由调查组核实后认定**，脚本只把差异摆出来，并自动把「各来源系统的对时记录与时钟校准记录」（T12）补进待查清单。

md 的 5.2 节为每组差异列出完整的「来源 / 记录时间 / 数据类型 / 出处」表，附「全部保留，按来源分别标注；脚本不校准时间、不取其一」。

## 五、数据缺口的处理（硬约束）

判定口径：**只对连续采样类数据（运行参数）判缺口**，阈值默认 120 分钟（`--gap` 可调）。操作、巡检、值班、报警属事件触发型记录，本就疏密不均，间隔长不等于缺数据。

三类缺口都要标注：
1. 窗口起点至首条记录；
2. 相邻两条记录之间；
3. 末条记录至窗口终点。

窗口内完全没有运行参数数据时，整窗记为一条缺口并 warning。

窗口终点晚于当前时间（如故障刚发生、`--after` 取 24 小时）时，缺口只判到当前时间：尚未到达的时段没有记录是正常的，不算缺口；脚本 warning 说明，`meta.window.gapCheckedUntil` 记实际判到的时刻。

处理口径只有一条：**明确标注缺口区间（起、止、时长），绝不用插值或推测填补。**

- 不按前后两点线性插值；
- 不按趋势外推；
- 不按「应该还是那个值」延续上一条；
- 缺口时段的其他来源记录（纸质记录、班组台账、DCS 备份）自动补进待查清单（T11）。

| T3 | 联锁动作记录与联锁投用状态台账 | 确认联锁投用与动作情况 |

|---|---|---|
| T2 | 报警与事件（SOE）原始记录 | 本次未归集到报警记录 |

## 七、原因分析 / 责任分析 / 损失情况 / 防范措施（硬约束）

md 第七、八、十节**恒为空**，第九节只有「由调查组核定」的空表：

```markdown
## 七、原因分析

**（由调查组填写）**

<!-- ANALYSIS_START -->
<!-- ANALYSIS_END -->

> 本节留空。本技能不提供原因认定、事故定性与责任划分内容；该部分须由依规成立的调查组填写。

## 八、责任分析

**（由调查组填写）**

## 九、损失情况

**（由调查组核定；脚本不估算损失，不判定是否构成非计划停工）**

## 十、防范措施

**（由调查组填写）**

> 防范措施由调查组按「四不放过」原则制定；本材料不提出措施，避免以措施暗示原因。
```

`ANALYSIS_START` 与 `ANALYSIS_END` 之间**一个字都不能写**——这一点 selftest 会断言。模型成文时同样不得填入任何内容，包括「供调查组参考的初步线索」「建议加强……」这类变相结论或措施。

`investigation.json` 的 `analysis.cause / responsibility / loss / measures / conclusion` 恒为 `null`，`filledBy` 恒为「调查组」。

检修历史一节的「检修分级」按《中石化口径对照》第五节映射：大修→装置大检修，中修/小修→日常维修，抢修、专项（技改技措）按原文；SAP 订单类型只映射 PM01（日常维修）/ PM03（抢修），PM02「计划检修」等厂内可配置项不猜、显示「—」。原文始终保留在「类别（原文）」列。

## 八、免责与固定文案

### 8.1 声明行（必须原样保留，不得删改）

```
本材料为调查辅助归集，不含原因认定与事故定性；故障原因、性质与责任须由依规成立的调查组认定
本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。
```

两行都要。位置：md 开头的引用块与文末各一处。任何场景（含材料残缺、含检出禁用表述）都必须有。产出 md 不用 emoji，醒目提示一律用「【注意】」。

### 8.2 用户要求填写原因结论时的固定答复

```
本技能不提供原因认定、事故定性与责任划分内容；该部分须由依规成立的调查组填写
```

配套说明：
- 本材料只归集事实、搭框架，正文里没有、也不会有原因判断；

## 九、交付时要向用户说明什么

1. 时间线条目数、涉及来源数、归集的时间窗口；
2. 数据缺口：几段、各在什么区间、**已标注未填补**；
3. 时间戳不一致：几组、差多少、**已全部保留未校准**，建议核实各系统对时；
4. 建议补充收集的材料（待查清单）；
5. 检出的禁用表述条数与类别（如有），提示成文时须改写；
6. 脚本 warnings 逐条；
7. **原因分析、责任分析、防范措施三节留空，损失情况由调查组核定；本技能不做原因认定、事故定性与分级、责任划分。**
8. 哪些阈值（回溯/后续/缺口）用了经验默认，是否需要确认后重跑；
9. 是否构成设备事故及等级、是否非计划停工事件，由公司设备管理部门与调查组按《中国石化设备事故管理规定》《炼化企业非计划停工管理规定》认定，报送时限以厂内规定为准。

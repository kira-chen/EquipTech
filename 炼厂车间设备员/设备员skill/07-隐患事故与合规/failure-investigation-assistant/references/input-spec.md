# 输入规格：故障调查资料归集

## 调用形式

> **PDF 先用平台 pdf 技能转为 txt/docx 再传入，脚本不读 PDF；扫描件需 OCR。** 转出文本须整理成下面的表结构（xlsx 或 CSV 目录）再传给 `--records`。

```bash
node scripts/investigate.js \
  --tag "P-3201A" --name "催化原料泵A" --workshop "催化车间" \
  --time 2026-09-21T10:40:00+08:00 \
  --symptom "泵体异响、振动升高，出口压力下降" \
  --records "运行记录.xlsx,值班记录.xlsx" \
  --history "检修历史.xlsx" \
  --before 72 --after 24 --gap 120 \
  --out "<输出目录>"
```

## 参数取值口径

### `--time`（故障发生时间）

必须是 **ISO 8601 带时区**：`2026-09-21T10:40:00+08:00`，或 `Z` 结尾的 UTC（脚本换算为北京时间显示）。

| 输入 | 结果 |
|---|---|
| `2026-09-21T10:40:00+08:00` | 接受 → 显示 `2026-09-21 10:40:00` |
| `2026-09-21T02:40:00Z` | 接受 → 换算为 `2026-09-21 10:40:00` |
| `2026-09-21T10:40:00` | **报错**：缺时区 |
| `2026-09-21 10:40` | **报错**：缺时区 |
| `昨天上午` | **报错**：非有效时间 |

**发生时间不是发现时间。** 只知道发现时间的，应在 `--symptom` 里写明「XX 时 XX 分巡检发现……」，并向用户确认发生时间是否可追溯；**不得用发现时间倒推发生时间**。

### `--before` / `--after`（时间窗口）

默认故障前 72 小时至故障后 24 小时——**经验默认，不是制度数值，须与用户确认**（`meta.window.defaulted.before/after` 记录是否用了默认，md 开头「【注意】」提示）。时间窗口直接决定材料完整性：
- 窗口太窄 → 关键操作与参数变化落在窗外，`outOfWindow` 会单列提醒，可调大后重跑。
- 窗口太宽 → 无关记录涌入时间线，增加调查组甄别负担。

窗口外的记录**不丢弃**：单列在 `outOfWindow` 并在 md 的「5.4 超出时间窗口的记录」一节列出。

### `--gap`（数据缺口判定阈值）

默认 120 分钟——**经验默认，须与用户确认**（`meta.window.defaulted.gap`）。**只对连续采样类数据（运行参数）判缺口**——操作、巡检、值班、报警属事件触发型记录，本就疏密不均，不按缺口论。窗口内完全没有运行参数数据时，整窗记为一条缺口。窗口终点晚于当前时间时，缺口只判到当前时间（`meta.window.gapCheckedUntil`），尚未到达的时段不算缺口。

## 可识别的工作表与字段

脚本按 sheet 名匹配（去空白与「表」字后包含匹配），一个文件里可以放多张表，也可以分成多个文件传给 `--records`。

| 工作表 | 别名 | 必需列 | 可选列 | 时间线数据类型 |
|---|---|---|---|---|
| 运行参数 | 参数记录 / DCS / 趋势 | 时间、参数名 | 位号、参数值、单位、来源、内容 | 运行参数 |
| 报警记录 | 报警 / SOE / 事件记录 | 时间、内容 | 位号、来源、级别、岗位 | 报警 |
| 操作记录 | 操作 | 时间、内容 | 位号、来源、级别、岗位 | 操作记录 |
| 巡检记录 | 巡检 / 点检记录 | 时间、内容 | 位号、来源、岗位 | 巡检记录 |
| 值班记录 | 值班 / 交接班记录 | 时间、内容 | 位号、来源、岗位 | 值班记录 |
| 检修历史 | 检修记录 / 维修记录 / 工单 / 维修订单 / IW38 / IW39 / IW47 | 检修日期、检修内容 | 位号、检修类别、结论、岗位、来源、工单号、通知单号 | 检修历史 |

SAP PM 工单导出（IW38/IW39）可直接作为检修历史：`订单→工单号`、`订单类型→检修类别`、`功能位置→位号`、`短文本→检修内容`、`实际结束日期/技术完成日期→检修日期`、`通知单→通知单号`。

局部别名优先，再并入共享 `SYSTEM_ALIASES`（`C.mergeAliases`，SAP PM / EM / 作业许可 / 特种设备 / 智能巡检导出列名）。**「设备编号」不再是位号别名**——SAP 设备编号是 8 位流水号，不是功能位置；只有设备编号列而无功能位置/位号列时，位号为 null，不把流水号当位号。

### 检修类别 → 检修分级（`categoryNorm`）

| 原文 | 映射 |
|---|---|
| 大检修、停工检修、大修、停车检修 | 装置大检修 |
| 日常维修、中修、小修、消缺、维修、检修、PM01 | 日常维修 |
| 抢修、紧急修、应急修、PM03 | 抢修 |
| 技改、技措、专项、改造 | 专项（技改技措） |
| PM02（计划检修，厂内可配置）及其它 | null，md 显示「—」，不猜 |

## 会被特殊处理的行

| 情形 | 处理 |
|---|---|
| 首列为「合计/小计/总计/共计」 | 跳过 + warning |
| 整行为空 | 跳过 |
| 时间为空或无法解析 | **不推测补齐**：条目列入 `missingTime`，不参与时间线排序，md 的 5.3 节单列 + warning |
| 时间超出 `--before`/`--after` 窗口 | 列入 `outOfWindow`，md 的 5.4 节单列备查 + warning，不计入时间线 |
| 参数值无法解析为数字 | **按 null，绝不按 0**：md 显示「—」，条目 `note` 注明「未按 0 计」+ warning |
| 缺必需列 | warning，不中断；内容为空的条目写「（记录内容为空）」 |
| 一张已知工作表都没有 | **报错退出**（`ok:false` + exit 1） |
| 检修日期无法解析 | 条目保留但 `date` 为 null，列入 `missingTime` |

## 来源标注规则

时间线每条都带三层溯源信息，任何一条都可以回到原始记录复核：

| 字段 | 含义 |
|---|---|
| `source` | 记录来源。取「来源」列的值；该列为空时取工作表名（如「报警记录」） |
| `file` | 记录所在的文件名 |
| `sheet` + `row` | 工作表名与行号，md 里显示为「XX.xlsx/报警记录 第 5 行」 |

**不同来源的同一件事按不同来源分别成条**，脚本不合并、不去重——合并会丢掉来源差异，而来源差异本身是调查组要看的材料。

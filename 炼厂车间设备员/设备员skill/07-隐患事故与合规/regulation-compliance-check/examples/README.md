# examples 回归测试数据

> 本目录仅开发包含有（`build.sh --with-examples`），发布包不含。
> 全部样例由 `node scripts/make-sample.js --out examples` 再生，虚构文号随 seed 变化但结论不变。

> 【注意】**样例中的标准名称、条款编号与条款原文全部为虚构**，形如
> `XX/T 9xxx—2026《炼化装置设备管理要求》（本样例虚构标准，非真实标准）`，
> 不对应任何真实法规与标准，仅用于验证脚本的解析与对照逻辑。**不得当作真实条款引用。**
> 这正是本技能的立场：条款必须由用户提供，谁都不能凭记忆写条款——样例也不例外，所以干脆编得一眼看得出是假的。

## 关键验证点

1. **四档状态，绝无「符合/不符合」**：任一样例的 `compliance.md` 全文扫描，「符合」「不符合」「达标」「合规」只出现在三处——技能标题、禁用/免责语句、用户条款原文被逐字搬运的行。`selftest.js` 的 `scanForbidden` 逐行核验。
2. **条款必须用户提供**：不加 `--rules` 直接运行 → `ok:false`、exit 1，错误信息写明「本技能不从记忆中引用条款编号与原文」。`sample-rules-*` 里的编号与原文均原样搬进产出，一字不改。
3. **笼统条款不自行解释**：样例 2 的 4 条（「应当加强管理」「必要时采取适当措施」「应当健全完善」「及时妥善处理」）全部单列在第四节，名下即使有名称相关资料也不改判。
4. **未见材料不充数**：样例 4 中第六条（定期检验报告）与第九条（隐患排查台账）名下 `evidence` 为空数组——**没拿设备台账去顶**。「隐患登记与治理台账」不对应「设备台账」，是条款侧词表刻意收紧的结果。
5. **材料不完整只采信填报**：主样例中「设备技术档案-XXX.pdf」自报「缺页，附图部分未归档」、「安全阀校验记录.xlsx」自报「仅有一季度部分」，两条按「材料不完整」处理并各带一条具体到行号的 warning。
6. **「维修人员」不对应检修记录**：主样例第八条「设备操作与维修人员应当经培训考核合格后持证上岗」只对应到持证上岗台账，**未误对应到检修记录台账**。
7. **企业制度同一口径**：`sample-internal.xlsx` 含一份「公司设备管理规定（Q/XX-虚构-00N）.docx」，归属标「厂内制度」；主条款清单第九、十一条来源为虚构企业制度，对照尺度与法规条款完全一致，报告第一节之后写明「企业制度……条款原文由用户提供」。
8. **声明两句与无 emoji**：md 末尾固定两句声明（辅助自查不构成结论；最终符合性结论由自查责任人按厂内审核表口径填写），醒目提示用「【注意】」。
9. **未对应材料不强行塞**：主样例中「班组考勤统计表」对不上任何条款，单列并注明「未按名称猜测强行对应」。

```bash
node scripts/make-sample.js --out examples --seed 7   # 虚构文号变化，结论不变
```

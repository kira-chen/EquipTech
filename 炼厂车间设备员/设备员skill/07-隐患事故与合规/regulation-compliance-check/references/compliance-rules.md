# 条款对照口径与表述规范

> 规则表实现在 `scripts/lib/compliance-spec.js`，与本文档同源。改脚本前先读本文。
> 本技能的红线在**表述**上，不在算法上：算出什么不难，把话说准才难。

> **企业制度与法规标准同一口径**：《中国石化设备管理规定》《炼化企业设备管理技术规定》《中国石化安全隐患管理规定》等集团制度，以及公司/分厂/厂内制度，与 TSG、GB 一样走 `--rules`（作为条款来源）或 `--internal`（作为本车间已有制度材料）。**条款原文一律由用户提供**，本技能不凭记忆引用任何制度条款，也不区分「法规」与「制度」给出不同的判定尺度。
> 条款自查是车间设备员可做的部分（整理材料、对照条款、列出缺口）；**最终符合性结论由自查责任人按厂内审核表口径填写**，监管认定由公司设备管理部门（机动部/设备部）、安全环保部门与法务归口。

## 一、状态只有四档（最硬的一条）

| 状态 | 含义 | 什么时候用 |
|---|---|---|
| **已见对应材料** | 在所提供资料中找到了与条款对应的材料 | 条款指向具体资料，且名下至少一份材料未填报不完整 |
| **未见对应材料** | 在所提供资料中没找到对应的材料 | 条款指向具体资料，但一份都没对上 |
| **材料不完整** | 找到了材料，但用户自己填报为不齐全 | 名下任一材料的「完整性说明」含缺页/缺章/未签/待补/仅…等提法 |
| **需进一步确认** | 条款要求笼统，无法直接对照到某份具体资料 | 见第三节 |

这四个词是本技能**唯一**允许出现的状态用语。JSON 的 `statusCn`、md 的状态列、xlsx 的状态列、交付时的口头说明，全部只能用这四个词。

### 禁止结论性表述清单

以下词汇**不得作为判定结论**出现在任何产出中：

| 禁用 | 为什么 | 该怎么说 |
|---|---|---|
| **符合** | 这是达标结论，不是材料事实 | 「已见对应材料」 |
| **不符合** | 同上，且后果更重 | 「未见对应材料」 |
| 达标 / 不达标 | 达标与否是监管部门的结论 | 只说材料在不在 |
| 合规 / 违规 / 违法 | 法律判断，本技能不做 | 只说材料在不在 |
| 合格 / 不合格 | 同上 | 只说材料在不在 |
| 满足要求 / 不满足要求 | 变相的达标判定 | 「已见对应材料，内容需人工核对」 |
| 法律责任 / 处罚 / 追究 | 法律意见，本技能不做 | 不提 |

**唯一的例外**是三种情形，`scripts/selftest.js` 的禁用词扫描器对它们放行：

1. 技能自身的标题「法规标准符合性自查对照表」——业务名称，不是判定；
2. 明确的**禁用语句与免责语句**，如「不表述为『符合』或『不符合』」「不构成合规达标结论」；
3. **用户提供的条款原文被逐字搬运**的那一行——条款原文里出现什么词是用户的文本，脚本不许改写。

除这三种外，产出中每出现一次这些词，都算违规。

### 为什么这么严

材料在不在，是车间自己能查证的事实。
达标与否，是监管部门、内部审计或法务依据完整证据链作出的结论，要考虑条款适用范围、免责情形、历史沿革、同类案例。
本技能只有一份资料清单，凭它说「符合」是越权，说「不符合」更是给车间惹麻烦。**两件事不能混。**

## 二、条款文本必须由用户提供

`--rules` 是硬前提。**未提供时脚本直接报错终止**，错误信息里写明「条款文本须由用户提供，本技能不从记忆中引用条款编号与原文」。

### 绝对不做的事

- 不得：凭记忆写出条款编号（「TSG 21 第 4.2.3 条要求……」）
- 不得：凭印象复述条款原文
- 不得：用户只给了标准名称就自行补全条款内容
- 不得：条款原文残缺时自行补齐

理由：条款编号与原文记错一个字，整条对照就废了，而且用户会拿着错的条款号去找领导汇报。记忆里的标准版本还可能已经作废。**没有原文就不对照**，这是唯一安全的做法。

### 脚本的做法

条款编号、条款原文、应做事项、标准名称**逐字搬运**用户给的文件，不改写、不补全、不规范化。每条条款都带 `src`（来源文件名 + 行号），可回溯核对。

## 三、条款笼统 → needInterpretation，不自行解释

条款文本没有指向任何具体资料类别、也没有任何特征词（设备位号、专有名词）时，判为笼统，归入 `needInterpretation`，状态写「需进一步确认」。

| 条款文本 | 判定 | 为什么 |
|---|---|---|
| 使用单位应当建立设备台账。 | 可对照 | 指向「设备台账」这一具体资料 |
| 安全阀应当按期校验并保存校验记录。 | 可对照 | 指向「校验记录」 |
| **使用单位应当加强管理，确保工作有效开展。** | **需进一步确认** | 纯原则性表述，不知该拿哪份资料对 |
| **必要时应当采取适当措施。** | **需进一步确认** | 「必要时」「适当」都是待明确的 |
| **相关工作应当健全完善。** | **需进一步确认** | 同上 |

### 硬规则

- **不自行解释条款含义**。不做「这条大概是指设备台账吧」式的推测，一次都不做。
- **笼统条款即使名下挂到了名称相关的资料，状态也不改判**。资料只作为「供人工核对参考」列出，说明里明确写「未据此判定条款的对应情况」。
- 同时含笼统词与具体资料指向的条款（如「设备台账应当健全有效、及时更新」），按**可对照**处理——它毕竟点到了设备台账。具体指向优先于笼统词。
- 报告第四节单列，注明「须由用户、标准归口部门或法务明确条款的具体要求后再行对照」。

## 四、未见对应材料 → 既不是「不符合」也不是「符合」

条款指向了具体资料，但一份都没对上 → `noEvidence`，状态「未见对应材料」。

| 必须这样写 | 绝对不能写 |
|---|---|
| 「在所提供材料中未见与本条款对应的材料」 | 「本条不符合」 |
| 「按『未见对应材料』一档记录」 | 「本条存在违规」 |
| 「正式判定由监管部门、内审或法务作出」 | 「该项符合要求」 |
| 「建议向相关部门核实是否另有归档」 | 「问题不大，补一份就行」 |

**「未见」说的是本次自查所提供的材料范围内没找到。** 材料可能存在于别处、可能在分厂/公司归档、可能条款本身不适用于本车间——这些都要车间自己核实，不是脚本能判的，更不是「不符合」。

反过来，找到了材料也只是「已见对应材料」：材料内容是否真的满足条款要求，需要人工逐字核对，脚本只比对了名称。所以 `hasEvidence` 项的说明里固定写「材料内容是否满足条款要求需人工核对，本技能不作判定」。

## 五、材料不完整的判定来源

**只采信用户在资料清单「完整性说明」列里自己填报的内容**，脚本不自行推断某份材料完不完整。

识别的提法：不完整、不齐、缺页、缺章、未签、未盖章、待补、部分、仅、只有、残缺、未归档、草稿、未审批、未批准。

- 名下材料**全部**自报不完整 → `partialEvidence`
- 名下材料**部分**自报不完整 → 仍是 `partialEvidence`，说明里写明「不因其余材料齐备而掩盖」
- 「完整性说明」列缺失或为空 → 按未填报处理，不推断为不完整，也不推断为完整

## 六、条款 ↔ 资料的对应口径

脚本只认两种依据，**从严**，宁可判为「未见对应材料」也不放宽：

| 依据 | 含义 | 例 |
|---|---|---|
| `category:<类别>` | 条款要求与资料落在同一个**具体**资料类别 | 条款「应当建立设备台账」↔ 资料「常减压车间设备台账2026.xlsx」 |
| `feature:<词>` | 条款里的**具体**特征词直接出现在资料名中 | 条款「P-1101A 应当按期更换润滑油」↔ 资料「P-1101A润滑油更换台账.xlsx」 |

资料类别共 25 类，见 `scripts/lib/compliance-spec.js` 的 `CATEGORIES`。

### 泛词不作为对应依据

「设备」「记录」「资料」「管理」「单位」「企业」这类词一律不构成对应。两个容易踩的坑：

| 条款 | 资料 | 结果 | 为什么 |
|---|---|---|---|
| 应当建立隐患登记与治理**台账** | 设备**台账**2026.xlsx | **不对应** | 隐患台账、检修台账、持证台账都带「台账」二字；只认这两个字，任何提到台账的条款都会对上设备台账 |
| 设备操作与**维修人员**应当持证上岗 | 设备检**修记录**台账.xlsx | **不对应** | 「维修人员」说的是人和资格，不是检修记录 |

所以条款侧的词表刻意比资料侧收得更紧：条款侧用「设备台账」而非「台账」，用「维修记录」而非「维修」。

### 明令禁止的兜底

- 不得：语义近似、同义词扩展、编辑距离兜底
- 不得：「这份材料里可能也包含相关内容」式的推测性对应
- 不得：为了让对照表好看而放宽匹配

对不上就是未见。未见就如实写「未见对应材料」。

## 七、不提供法律意见与法律责任分析

**不做**的事，一件都不做：

- 不分析违反条款的法律后果（处罚、罚款、责令停产、追究责任）
- 不判断条款是否适用于本车间（适用性判断本身就是法律判断）
- 不引用、不比附其他法条
- 不给出「建议咨询律师」之外的任何法律建议，连这句也不由脚本写
- 不评估法律风险等级

能做的只有一件：**把用户给的条款和用户给的材料摆在一起，说清楚哪些材料见到了、哪些没见到。**

## 八、建议跟进事项（分析段）表述规范

撰写 200~400 字，结构固定为四段：

1. **材料对应情况概述**：条款总数、四档各自的条数、资料份数。
2. **未见对应材料的条款及核实方向**：逐条点名，说明可以往哪儿核实（分厂/公司归档、公司设备管理部门、相关科室）。**不说「不符合」，不说后果。**
3. **材料不完整条款的补充核对方向**：不完整在哪（用户自己填报的说法），需要补哪部分。
4. **需进一步确认条款的明确途径**：找谁明确条款含义（标准归口部门、法务、上级设备管理部门）。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 未见材料 | 「第六条定期检验报告未见对应材料，建议向公司设备管理部门（机动部/设备部）核实是否另有归档」 | 「第六条不符合」「第六条违规」 |
| 已见材料 | 「已见对应材料，内容是否满足条款要求需人工核对」 | 「第二条符合要求」「已达标」 |
| 材料不完整 | 「技术档案自报缺页、附图未归档，需核实随机资料的归档情况」 | 「档案基本齐全」「问题不大」 |
| 笼统条款 | 「第十一条为原则性表述，需由标准归口部门明确其具体要求后再对照」 | 「第十一条应理解为要求建立管理制度」 |
| 法律后果 | 不提 | 「可能面临行政处罚」「需承担法律责任」 |
| 整体结论 | 不下 | 「总体符合要求」「基本合规」 |
| 数字 | 引用 compliance.json 的 counts | 自行统计或估算 |

## 九、必须保留的声明行

`compliance.md` 末尾固定写入，**逐字保留，不得删除或改写**：

> 本对照为辅助自查，仅反映所提供材料与条款的对应情况，不构成合规达标结论与法律意见；正式判定以监管部门、内审或法务意见为准
>
> 最终符合性结论由自查责任人按厂内审核表口径填写，本技能不代填

第二句是中石化口径的补充：厂内审核表（自查表）上的「符合性结论」栏由自查责任人签字填写，模型与脚本都不代填、不预填。这一句同样写入 `compliance.json` 的 `meta.statementFill`。

同一句话也写入 `compliance.json` 的 `meta.statement` 与 `对照表.xlsx` 的「状态口径与声明」工作表。

另有一条四档口径提示由脚本写在 md 第一节之前，同样不得删除或弱化：

> 本表状态仅有「已见对应材料 / 未见对应材料 / 材料不完整 / 需进一步确认」四档，不表述为「符合」或「不符合」；材料在不在是事实，达标与否是监管部门、内审或法务的结论，两回事

| meeting | 会议与活动记录 | 会议、例会、专题会、交底、安全活动 | 会议、例会、纪要、交底、安全活动 |

> permit 类的「动火」在词表中与「用火」并列保留（旧票面与旧条款仍大量使用「动火」），中石化口径的正式名称是**用火作业**。

**与 `inspection-evidence-package`（`scripts/lib/evidence-spec.js`，2026-10-26 起为 25 类，差异表见其 `references/evidence-rules.md` 第八节）的差异**（同源抽取由主代理后续统一处理，此处只记录差异，不自行改动对方）：

| 差异 | 本技能（25 类） | inspection-evidence-package（25 类） |
|---|---|---|
| 拆分更细 | periodicInspection / ndt 分开；safetyValve / interlock 分开；registration、accident、change、contractor 单列 | inspectionReport 合并定期检验与无损；safetyDevice 合并安全阀与联锁报警；无 registration/accident/change/contractor |
| 对方独有 | 无 specialEquipment 类（本技能把压力容器/压力管道等放在 FEATURE_TERMS 特征词里按词命中） | specialEquipment（特种设备、压力容器、压力管道、锅炉、起重机、使用登记） |
| 条款侧收紧 | maintenance 条款侧不用裸「维修」「维护」；ledger 不用裸「台账」 | item 侧用裸「维修」「维护」（迎检清单项不会写「维修人员」，无此歧义） |
| plan/procedure | 分为 plan（计划与方案）与 procedure（规程与作业指导书）两类 | 合并为 plan |
| 用途 | 条款 ↔ 材料对照，从严，宁可「未见」 | 检查通知清单项 ↔ 文件归集，偏召回 |

两张表的类别 key 不完全一致（本技能 patrol / 对方 inspection），**跨技能传 JSON 时不要按 key 对齐**，按中文类别名人工核对。

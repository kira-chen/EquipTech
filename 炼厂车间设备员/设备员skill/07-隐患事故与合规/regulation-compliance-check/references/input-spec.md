# 输入规格：法规标准符合性自查

## 必填参数

| 参数 | 说明 |
|---|---|
| `--rules` | **条款文本或条款清单**：`.docx` / `.xlsx` / `.md` / `.txt`。**必填，缺失时报错终止**。法规标准与企业制度（集团/公司/厂内）同一口径传入 |
| `--materials` | 本车间资料目录，或资料清单 `.xlsx` |
| `--workshop` | 车间名称 |

> `--rules` 为什么是硬前提：本技能**不从记忆中引用条款编号与原文**。条款号记错一个字，整条对照就废了，用户还会拿着错的条款号去汇报。没有用户提供的原文就不对照。
> 用户只说了标准名称（「按 TSG 那个标准查一下」）而没给文本时，正确做法是回问要标准文本或条款清单，**不是**凭印象列条款。

## 一、条款文本 / 条款清单的解析（`--rules`）

### 形式一：`.xlsx` 条款清单（最稳，推荐）

sheet 名匹配「条款清单」「条款」「条文」「法规条款」「标准条款」「条款对照」（去空白与「表」字后包含匹配）。

| 列名 | 必需 | 说明 |
|---|---|---|
| 条款原文 | 是 | 一行一条；为空的行跳过并 warning |
| 条款编号 | 否 | 缺失时按出现顺序自动编号 |
| 应做事项 | 否 | 条款要求落到实处的具体事项，**参与资料对照** |
| 标准名称 | 否 | 来源标签，**仅展示，不参与对照**（见下） |

列名别名：

| 标准列名 | 可识别的写法 |
|---|---|
| 条款编号 | 条款编号、条款号、条文编号、编号、款号、条款、序号 |
| 条款原文 | 条款原文、条款内容、条文原文、条文内容、原文、条款正文、内容 |
| 应做事项 | 应做事项、要求事项、应当做的事、具体要求、要求、管理要求、应落实事项 |
| 标准名称 | 标准名称、法规名称、制度名称、标准、法规、制度、来源、出处、文件名称 |

表头行识别：取前 10 行中命中必需列最多的一行，因此首行是标题、第三行才是表头的导出表也能读。

别名表经 `C.mergeAliases` 与共享 `SYSTEM_ALIASES`（SAP PM/MM、EM、作业许可、特种设备台账等导出列名）合并，局部别名优先；本技能只取「条款编号/条款原文/应做事项/标准名称」与「资料名称/存放位置/资料类型/完整性说明/备注」这几列，共享表中其它键不参与匹配。

> **「标准名称」为什么不参与对照**：它是「XX/T 9001《设备管理要求》」这类来源标签。
> 拿它去匹配，会把整个标准范围内的资料都算成某一条的对应材料，缺口反被掩盖。
> 这与本技能「对不上就写未见对应材料」的硬约束直接冲突，故只作展示。

### 形式二：`.docx` 条款文本

- 先找含「条款原文」表头的表格，按列抽取（与形式一同口径）
- 找不到这类表格时退回正文逐行解析，并 warning 说明已退回
- 合并单元格、复选框等由 `scripts/lib/docx-lite.js` 处理

### 形式三：`.md` / `.txt` 条款文本

按行识别「条款编号 + 原文」，支持的编号样式（按优先级）：

| 样式 | 例 |
|---|---|
| 第X条 / 第X条第X款 | `第一条 使用单位应当建立设备管理制度。` |
| 点分编号 | `4.1.2 使用单位应当建立设备台账。` |
| 数字 / 中文序号 | `1. 应当开展日常巡检并保留记录` `（一）应当建立技术档案` |

- `#` 开头的 Markdown 标题不当作条款
- 条款原文去标点后少于 3 字的行跳过
- 一条都解析不出时 → `ok:false` 并提示改用 `.xlsx` 条款清单，**同时重申不得凭记忆补充条款**

> **PDF 统一前置步骤**：脚本不读 PDF。PDF 规程、检查通知、制度汇编先用平台 pdf 技能转为 txt/docx 再传入（扫描件需先 OCR）；传入 `.pdf` 时脚本报错并提示该步骤，不得凭记忆补充条款。

### 条款文本逐字搬运

条款编号、条款原文、应做事项、标准名称**原样保留**，脚本不改写、不补全、不规范化、不纠错。
每条条款带 `src`（来源文件名 + 行号 / 表格行号），可回溯核对。

## 二、本车间资料（`--materials`）

### 形式一：资料目录

直接传目录路径，递归扫描（最多 6 层，超出则 warning）。跳过 `.` 开头的隐藏文件与 `~$` 临时文件。子目录文件保留相对路径作为「存放位置」。

```bash
--materials "/path/to/车间设备管理资料/"
```

目录模式下没有「完整性说明」，所有材料按**未填报完整性**处理——既不推断为不完整，也不推断为完整。

### 形式二：资料清单 `.xlsx`

sheet 名匹配「资料清单」「材料清单」「制度清单」「台账清单」「记录清单」「资料」。

| 列名 | 必需 | 说明 |
|---|---|---|
| 资料名称 | 是 | 为空的行跳过并 warning |
| 存放位置 | 否 | 缺失时用资料名称代替 |
| 资料类型 | 否 | 参与对照（与资料名称一并作为材料名称） |
| 完整性说明 | 否 | **判定「材料不完整」的唯一来源**，见下 |
| 备注 | 否 | |

列名别名：

| 标准列名 | 可识别的写法 |
|---|---|
| 资料名称 | 资料名称、材料名称、文件名、名称、文件、台账名称、制度名称 |
| 存放位置 | 存放位置、位置、路径、存放、存档位置、归档位置 |
| 资料类型 | 资料类型、类型、类别 |
| 完整性说明 | 完整性说明、完整性、状态、材料状态、说明 |

### 「完整性说明」的取值口径

**只采信用户自己填报的内容，脚本不自行推断某份材料完不完整。** 含以下提法即按「材料不完整」处理并 warning（warning 具体到工作表名与行号）：

```
不完整 不齐 缺页 缺章 未签 未盖章 待补 部分 仅 只有 残缺 未归档 草稿 未审批 未批准
```

例：`缺页，附图部分未归档`、`仅有一季度部分，二三季度未归档`。

留空 = 未填报，**不推断为不完整，也不推断为完整**。

## 三、可选参数

| 参数 | 说明 |
|---|---|
| `--date` | 自查时点 `YYYY-MM-DD`；**不提供不报错**，报告中写「未指定」并 warning，绝不默认取当天 |
| `--scope` | 自查范围说明（涉及哪些法规标准），仅写入报告头部 |
| `--internal` | 企业制度（集团/公司/分厂/厂内）的目录或清单；其中的资料并入对照，并标记归属为「厂内制度」。制度作为**条款来源**时走 `--rules`，作为**已有材料**时走 `--internal` |
| `--last` | 上次自查结果，仅登记在报告中；路径不存在时报错 |
| `--out` | 输出目录，默认系统临时目录 `<os.tmpdir()>/rcc-out`，建议始终传 `--out` |

`--date` 非法、`--internal` / `--last` 路径不存在时一律 `ok:false` 并退出 1。

## 四、会被跳过的行

- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning）
- 条款原文为空的行（warning）
- 资料清单中资料名称为空的行（warning）
- 目录模式下 `.` 开头的隐藏文件与 `~$` 临时文件
- 目录层级超过 6 层的部分（warning）
- `.md` / `.txt` 中 `#` 开头的标题行、分隔线

## 五、产出

| 文件 | 内容 |
|---|---|
| `compliance.json` | items、hasEvidence、noEvidence、partialEvidence、needInterpretation、unmatched、materials、counts、meta（含 statement / statementFill / internalNotice） |
| `compliance.md` | 五节报告；开头带四档口径提示与企业制度说明；末尾固定声明行（两句）；醒目提示用「【注意】」，不用 emoji |
| `对照表.xlsx` | 五个工作表：条款对照、未见材料与材料不完整、需进一步确认、未对应材料、状态口径与声明 |
| `summary.json` | 末行摘要落盘 |

`counts` 字段：`rules`（条款总数）、`hasEvidence`、`noEvidence`、`partialEvidence`、`needInterpretation`、`unmatched`、`materials`。
前四项之和恒等于 `rules`——每条条款必落入且只落入四档之一。

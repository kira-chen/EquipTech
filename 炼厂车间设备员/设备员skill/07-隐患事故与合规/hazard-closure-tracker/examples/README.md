## 关键验证点

1. **已整改未验收绝不计闭环**（本技能最关键判定）：主样例 YH-2026-010（验收字段全空）与 YH-2026-011（验收情况填「待验收」）整改状态均为「已整改」，归 `unverified` 单列，闭环率分子不含这两项——闭环率为 3/12 而非 5/12。
2. **一般隐患无统一天数**：主样例 YH-2026-003 为一般隐患、台账无期限，归 `undetermined`（原因「一般隐患无统一整改天数，台账未填要求整改期限」），不按 30 天推算；只有 `--rules` 给厂内天数后才推算。
3. **等级缺失不按最宽松时限**：主样例 YH-2026-012 等级列为空且无期限，归 `undetermined`，不出现在超期清单中。
4. **层级写法不映射**：脏数据样例 A 级、B 级与导出样例「厂级」均记为「等级无法识别」（`metrics.byLevel.unknown`），不进重大隐患专列、不触发重大隐患提示；台账有期限的仍按期限判超期。`sample-hazard-rules.xlsx` 的「等级映射」表声明后才映射。
5. **重大隐患提示的出现与不出现**：主样例开头出现「存在重大隐患 3 项（其中未闭环 2 项）…上报分厂/公司安全部门并挂牌督办」，且已闭环的 YH-2026-009 仍在「重大隐患专列」中；`sample-hazard-all-closed.xlsx` 无重大隐患无超期，开头不生成任何告警。
6. **五定不全**：主样例 6 项（YH-2026-002、003 缺资金/期限/应急措施，010 缺资金/应急措施，004 缺资金，006 缺应急措施，012 缺期限），已闭环项不核对；重大隐患 002 的督办事由追加「重大隐患五定不全」。脏数据样例无资金/应急措施列 → warning 两条、未闭环项全部按未落实。
7. **闭环率分母为 0 输出「—」**：对 `sample-hazard-all-closed.xlsx` 加 `--level 重大` 筛选后无记录，`metrics.closureRate` 为 `null`，报告显示「闭环率：**—**」并注明「统计范围内无隐患，不计算闭环率」，不写 0%。
8. **编号重复两条均保留**：脏数据样例中 YH-X-002 出现两次，两条各自判定，warning 注明两处行号。
9. **状态与验收矛盾单列**：脏数据样例 YH-X-001 整改状态「未整改」却填了验收人与验收日期，进「七、状态与验收矛盾」一节并 warning，脚本未作任何取舍，该项不计闭环。
10. **声明行与无 emoji**：两份 md 产出均含「隐患认定、等级与整改验收以安全部门意见为准。」与通用声明行，醒目提示用「【注意】」。

## 再生样例

```bash
node scripts/make-sample.js --out examples            # 默认 seed=1
node scripts/make-sample.js --out examples --seed 7   # 发现日期变化，结论不变
```

## MCP 取数对照

平台接入业务系统 MCP 时不用附件：按 SKILL.md「数据获取（MCP）」调用 `get_hazards`，csv 放进新建的空目录 A，作 `--input A`；`--date` 用今天。演示数据每天按剧本刷新，隐患条数与超期项会随日期变化，预期结果只列每天稳定的结论。

# scripts 使用说明

## hazard.js —— 主脚本

```bash
node "<技能目录>/scripts/hazard.js" \
  --input "<隐患台账xlsx路径>" \
  --workshop "<车间名>" \
  --date <YYYY-MM-DD> \
  --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 隐患台账 xlsx 路径，或同结构 CSV 目录 |
| `--workshop` | 是 | 车间名称 |
| `--date` | 是 | 统计截止日期 YYYY-MM-DD，超期天数以此为基准 |
| `--out` | 否 | 输出目录，默认输入文件同目录下 `hct-out/`；建议始终传 `--out` |
| `--from` | 否 | 统计起始日期，按「发现日期」过滤；发现日期缺失的项仍予保留并 warning |
| `--rules` | 否 | 厂内口径 xlsx：「整改时限」表（厂内有统一天数时）与/或「等级映射」表（厂内用 A/B/C 级、一级、厂级等写法时），格式见 `references/input-spec.md` |
| `--level` | 否 | 只跟踪某一等级：`重大` 或 `一般`；取值非法时报错 |
| `--owner` | 否 | 只跟踪某一责任人（支持包含匹配） |
| `--prev` | 否 | 上期 hazard.json，输出总数、超期数、闭环率的环比 |

### 产出

| 文件 | 内容 |
|---|---|
| `hazard.json` | `counts`（含 `fiveFixedIncomplete`）、`metrics`（闭环率、平均闭环时长、按等级/责任单位/来源分布、`rules`、`rulesSource`）、`overdue`、`dueSoon`、`inProgress`、`closed`、`unverified`、`majorHazards`、`undetermined`、`conflicts`、`fiveFixedIncomplete`（每项含 `missing[]`）、`trend`、`items`（每项含 `fund`、`emergency`、`fiveFixedMissing`）、`warnings` |
| `hazard.md` | 十节报告（总体概览 / 重大隐患专列 / 超期 / 临期 / 已整改未验收 / 未判定 / 状态与验收矛盾 / 五定不全 / 闭环指标 / 情况说明），开头「【注意】重点提示」由脚本直接写入；说明段留 `<!-- ANALYSIS_START/END -->` 占位；不含 emoji |
| `督办清单.md` | 按责任人分组的督办事项，可直接转发 |
| `summary.json` | 末行摘要落盘（Windows 控制台乱码兜底） |

### 关键判定口径（不可放宽）

- 整改状态「已整改」但无验收记录 → `unverified`，**绝不计入已闭环**；验收情况为「不合格 / 未通过 / 待验收」等否定写法时，即使填了验收人/验收日期也归 `unverified`
- 一般隐患无统一整改天数（《中国石化安全隐患管理规定》）：台账无「要求整改期限」→ `undetermined`，**不按 30 天或任何默认天数推算**；仅 `--rules`「整改时限」表给出厂内天数时才推算
- 等级只认「重大/一般」字样；「一级/A 级/厂级」等管理层级写法不映射（等级无法识别，台账有期限仍按期限判，无期限 → `undetermined`）；`--rules`「等级映射」表可声明厂内对应关系
- 重大隐患无方案期限 → `undetermined`，同样不套用一般隐患时限
- 重大隐患无论状态如何，均在报告开头提示（含上报分厂/公司安全部门并挂牌督办）并单独成节
- 五定（方案/资金/责任人/期限/应急措施）核对只列缺项，脚本不补填；「—」「/」「无」「待定」「未落实」等占位写法与留空同样按未落实；台账无资金/应急措施列时 warning 一次并按未落实处理
- 闭环率分母为 0 → 输出 `null`，报告显示「—」，**不写 0%**
- 状态与验收矛盾 → 单列一节 + warning，脚本不作取舍

### 退出码
- `0`：成功，末行输出 `{"ok":true,...}`
- `1`：失败，末行输出 `{"ok":false,"error":"...","warnings":[...]}`

## make-sample.js —— 样例生成

```bash
node scripts/make-sample.js --out examples [--seed <n>] [--date <YYYY-MM-DD>]
```

生成 5 份样例：主台账（含整改资金/应急措施列，覆盖全部边界）、脏数据变体（状态矛盾 + 编号重复 + 合计行 + 别名列头 + A/B 级层级写法）、全闭环变体（无告警提示）、系统导出列名变体（EM/HSE 风格列名 + 政府/集团督查、HSE 审核、第三方诊断来源 + 「厂级」写法）、厂内口径文件（整改时限 + 等级映射）。
seed 改变发现日期在区间内的取值，但不改变结论：主样例恒为 12 条隐患、3 项重大隐患（含 1 项已闭环）、2 项超期、1 项临期、1 项整改中、3 项已闭环、2 项已整改未验收、3 项未判定、6 项五定不全，闭环率 25.0%。

## selftest.js —— 自测

```bash
node scripts/selftest.js
```

164 条断言，覆盖：基础归桶、**已整改无验收不计闭环**、**等级缺失 / 一般隐患无期限 undetermined 不按任何默认天数**、**重大隐患提示（【注意】、上报分厂/公司安全部门并挂牌督办）的出现与不出现**、**闭环率分母为 0 输出 null**、**编号重复**、**状态与验收矛盾**、**A/B 级、一级等层级写法不映射 + `--rules` 等级映射生效**、**五定不全（有列 / 无列两种）与督办**、系统导出列名别名、按来源分布、别名列头与合计行、缺列不中断、`--rules` 时限（含「2周」）、参数校验、督办清单分组、两条声明行、十节结构、无 emoji、`--from`/`--owner`/`--prev`、验收否定写法不计闭环、五定占位写法按未落实、空编号不计编号重复、督办清单责任人占位写法（待定 / —）归未填责任人组、整改状态否定写法（未完成 / 部分完成 / 尚未整改完）不算已整改。全绿退出 0。

# 验收范围确认清单与追问话术

运行脚本前，必须把下面的必需信息问全。**范围不清就生成清单，等于把漏验的风险留给验收组。**

## 必需信息

| 信息 | 对应参数 | 为什么必需 | 缺失时的追问 |
|---|---|---|---|
| 设备位号 | `--tag` | 验收单必须挂到具体设备 | 「验收的是哪台设备？位号是多少？」 |
| 设备名称 | `--name` | 报告抬头与追溯 | 「这台设备的全称是什么？」 |
| **设备类型** | `--equip-type` | **决定专用验收项**；不覆盖时只能出通用框架 | 「是泵、换热器、塔器容器、阀门、电机，还是压缩机机组、加热炉、空冷器？如果都不是，具体是什么设备？」 |
| **检修内容** | `--scope` | **决定条件性验收项与应附资料**（解体／换件／焊接／清洗／防腐／对中／电气） | 「这次具体做了哪些活？解体了吗？换了什么件？有没有动焊？」 |
| **检修分级** | `--repair-type` | 决定概况表与公司设备部门是否必签 | 「这是装置大检修里的项目，还是日常维修、抢修、专项（技改）？」 |
| 完工时间 | `--finished-at` | 验收单要素 | 「什么时候完工的？」 |
| 承修单位 | `--contractor` | 责任主体与签认方 | 「哪家承修的？本厂机修车间还是外委？」 |

## 条件必需信息（三个开关必须逐个问清，不能默认）

| 问题 | 对应参数 | 不问清的后果 |
|---|---|---|
| **本次需要试压或气密试验吗？** | `--pressure-test` | 不加 → 清单里不会有试压项、资料清单不会要试压记录，**漏一道关键关口** |
| **本次需要试运（空负荷／负荷）吗？** | `--trial-run` | 不加 → 没有振动、温度、电流、转向、联锁这些试运验收项 |
| **属于特种设备（压力容器、压力管道、安全阀等）吗？** | `--special-equipment` | 不加 → 不会要求法定检验报告与安全附件校验证书 |

脚本对这三项未指定时均会 warning，**看到 warning 要回头向用户确认，不要直接当「不需要」交付**。

## 可选材料

| 材料 | 对应参数 | 提供后的价值 |
|---|---|---|
| 检修方案 | `--plan` | 比对方案的质量控制点是否都有对应验收项，缺口列入 `qcGap`；Word（.docx）可直接读 |
| 已填写的验收记录 | `--records` | 回填验收结果，自动汇总不合格项；厂内表或 EM 检修验收记录导出均可 |

方案是 PDF 时：**先用平台 pdf 技能转为 txt/docx 再传入，脚本不读 PDF；扫描件需 OCR**。旧版 `.doc` 请另存为 `.docx`。**不要因为读不了就跳过比对。**

## 追问原则

1. **一次性列出所有缺项**，不要挤牙膏式逐个追问。
2. **不得用假设值填补后直接出清单**。特别是三个开关与检修分级，不能因为「一般泵检修都要试运」「这种活肯定是日常维修」就替用户定。
3. 设备类型说不清时，**照原话传给 `--equip-type`**，让脚本判定是否覆盖，不要自己归类成「按泵处理」。
4. 检修内容要问到**具体动作**（解体/换件/动焊/清洗/防腐），只说「大修」「例行检修」的要追问。
5. 抽取结果要**回读给用户确认**后再运行脚本。

## 常见口语与参数对应

| 用户可能这样说 | 对应参数取值 |
|---|---|
| 「泵拆开换了机封和轴承，重新找了中」 | `--scope "解体检修，更换机械密封与轴承，重新对中"` → 解体/换件/对中 |
| 「管束抽出来化学清洗了一遍，垫片换新」 | `--scope "抽管束化学清洗、更换法兰垫片"` → 清洗/换件 |
| 「塔盘换了几层，人孔封了，保温也恢复了」 | `--scope "解体更换塔盘、人孔封闭、保温恢复"` → 解体/换件/防腐保温 |
| 「机组拆缸换了轴承和干气密封，做了联锁试验」 | `--equip-type 压缩机机组 --scope "解体更换轴承与干气密封，对中" --trial-run` |
| 「加热炉换了几根炉管，炉衬修补了」 | `--equip-type 加热炉 --scope "更换炉管、补焊、炉衬修补" --pressure-test --trial-run` |
| 「补了几道焊」 | 检修内容中含「补焊」→ 触发焊接记录、无损检测报告、材质证明 |
| 「打了个水压」「做了气密」 | 加 `--pressure-test` |
| 「空转试了一下，又带负荷跑了 4 小时」 | 加 `--trial-run` |
| 「这是压力容器」「有安全阀」 | 加 `--special-equipment` |
| 「这是停工大修的项目」 | `--repair-type 大检修` |
| 「就是平时的小修」 | `--repair-type 日常维修`（旧值「小修」脚本也认，会 warning） |

## 不该做的追问

- 不要问「你觉得验收能不能合格」——**结论由验收组现场确认，模型不参与判定**。
- 不要问「振动多少算合格」然后据此填标准——**技术指标以设备技术文件、制造厂说明书、检修方案为准**，脚本只写「按…执行」的口径。

# 输入规格：检修完工验收

本技能的主输入是**命令行参数**（位号、设备类型、检修内容、承修单位、检修分级），两个可选文件输入是检修方案与验收记录。

## 一、命令行参数

见 `scripts/README.md` 参数表。四个必需参数缺任一 → `ok:false` + exit 1。

- `--equip-type`：**照用户原话传**。脚本按关键词归类到 压缩机/机组 → 加热炉 → 空冷器 → 离心泵 → 换热器 → 塔器容器 → 阀门 → 电机（按此优先级，空冷器不归换热器，"加热炉"不归"加热器"）；归不到时 `typeCovered=false`，只出通用框架。
- `--repair-type`：大检修 / 日常维修 / 抢修 / 专项。旧值 大修 / 中修 / 小修 自动映射并 warning；不传 → `null` 并 warning，**不默认**。
- `--scope`：脚本从中识别以下特征，决定条件性验收项与应附资料。识别不到只加 warning，**不减必验项**。

| 特征 | 识别关键词 |
|---|---|
| 解体检修 | 解体、拆检、大修、抽芯、揭盖、开盖、抽管束、拆装 |
| 更换主要部件 | 更换、换新、更新、新装、配换、换×件/轮/封/承/管/芯/板 |
| 焊接作业 | 焊接、补焊、堆焊、换管、挖补、动火 |
| 清洗 | 清洗、清理、除垢、吹扫、喷砂、化学清洗 |
| 防腐保温 | 防腐、刷漆、涂层、衬里、保温、保冷 |
| 对中找正 | 对中、找正、找平、校中 |
| 电气作业 | 电气、接线、绝缘、接地、盘柜 |

- `--finished-at`：`YYYY-MM-DD`、`2026/9/20`、`2026年9月20日`、ISO 8601 带时区、Excel 日期序列号均可；无法解析 → 报错终止，**不按当天默认**。

## 二、检修方案（可选，`--plan`）

### 支持格式

| 格式 | 处理方式 |
|---|---|
| `.docx` | 随技能携带的 `scripts/lib/docx-lite.js` 抽取段落与表格（表格行拆成文本，横向/纵向合并占位去除） |
| `.txt` / `.md` / `.csv` | 直接按 UTF-8 文本读取 |
| `.xlsx` / CSV 目录 | 所有工作表的所有单元格按行拼成文本 |
| `.doc`（旧版 Word） | **不解析，报错终止**并提示另存为 .docx/.txt |
| PDF | **不解析，报错终止**；先用平台 pdf 技能转为 txt/docx 再传入，扫描件需 OCR |

### 质量控制点的识别

满足下列任一条件的行被收为一个质量控制点：

1. 行内含关键词：`质量控制点`、`控制点`、`QC点`、`见证点`、`停止点`、`停检点`、`H点`、`W点`、`R点`
2. 处在「质量控制点／质量要求／检验与试验」小节内的条目行（遇到下一个中文大写序号章节或 markdown 标题即退出小节）

收录时自动去掉行首项目符号、编号（`1.`、`（2）`、`三、`）与「质量控制点：」前缀；去重后按出现顺序编号，保留方案中的行号 `srcLine`（docx 按转文本后的行号）。

一条控制点都识别不出时 → warning，`qcPoints` 为 0，报告说明需人工核对。**不视为「方案没有控制点」。**

## 三、验收记录（可选，`--records`）

工作表名去空白与「表」字后包含「验收记录」「验收」「检修记录」「记录」即可（厂内表「验收记录表」、EM 导出「检修验收记录」均可）。缺该表 → warning，不回填，不中断。

| 列名 | 必需 | 说明 |
|---|---|---|
| 验收项 | 是 | 与清单中的验收内容对应，按文本相似度（bigram Dice ≥ 0.5）匹配 |
| 验收结果 | 否 | 见下方「结果取值」；空 → 保持未填写 |
| 序号 | 否 | 仅作名称匹配不到时的兜底；与名称冲突时按名称并 warning |
| 备注 | 否 | 不合格情况说明，写入报告 |

### 列名别名（局部别名优先，再经 `C.mergeAliases` 并入共享 `SYSTEM_ALIASES`）

| 标准列名 | 可识别的写法 | 来源 |
|---|---|---|
| 序号 | 序号、编号、NO、No、no | 厂内表 |
| 验收项 | 验收项、验收内容、**验收项目**、检查项、项目、内容 | 厂内表 / EM 检修验收记录 |
| 验收结果 | 验收结果、结果、结论、判定、**验收结论**、验收情况 | 厂内表 / EM |
| 备注 | 备注、说明、**问题描述**、不合格描述、存在问题 | 厂内表 / EM |
| 质量控制点 | 质量控制点、控制点、质量要求、QC点 | 方案 xlsx |

共享别名中的 位号 / 设备编号 / 设备名称 等列在验收记录里不参与回填（只按验收项匹配），不会与上述列名冲突。

表头行识别：取前 10 行中命中必需列最多的一行，因此首行是标题、第三行才是表头的 EM 导出表也能读；合计行跳过并 warning。

### 结果取值

| 归类 | 可识别写法 |
|---|---|
| 合格 | 合格、通过、符合、OK、√、是、已完成 |
| 不合格 | 不合格、未通过、不通过、不符合、整改、返工、NG、不达标 |
| **未判定** | 其他文字（如「待复测」「基本可以」）→ 单列并 warning，**不按合格处理** |
| **未填写** | 空单元格 → `result` 保持 `null`，计入 `pending` |

## 四、会被跳过的行

- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 提示）
- 验收项名称匹配不到清单的行（进 `unmatchedRecord` 并 warning，**不丢弃、不静默**）

## 五、不会发生的事

- 不会因为方案读不到控制点就把 `qcGap` 报成 0
- 不会因为未提供方案就把 `qcPoints` 当 0（三项均为 `null`）
- 不会因为设备类型不覆盖就套用相近类型的技术指标
- 不会把任何验收项的 `result` 预置为「合格」
- 不会在未指定检修分级时默认为日常维修或大检修
- 不会在签字栏预置监理

# 检修完工验收（completion-acceptance）

面向中石化体系炼化厂**车间（运行部）设备员**，在检修完工后按设备类型与检修内容生成验收项清单，比对检修方案质量控制点，记录验收结果并形成按**三级验收（班组 / 车间 / 公司设备管理部门）+ 工艺（操作）+ 承修单位**签字的验收报告。**验收项由脚本按规则生成，验收结论由验收组填写；模型不得代为判定"合格"。**

## 适用条件
- 用户说"检修完了怎么验收 / 检修验收清单 / 完工验收单 / 验收标准有哪些 / 能不能投用"，并说明设备位号、检修内容与完工情况。
- 覆盖设备类型：离心泵、换热器、塔器/容器、阀门、电机、**压缩机/机组、加热炉、空冷器**；不在其中时只出通用框架，技术指标标"待技术人员补充"。
- 检修分级按中石化口径：装置大检修 / 日常维修 / 抢修 / 专项（旧称大修 / 中修 / 小修自动映射）。
- 车间设备员可做的部分：整理验收项清单、比对方案质量控制点、汇总验收记录、核对应附资料（检修记录卡、质量验收记录 H/W 点见证、试车记录、备件领用单、更换部件质量证明）、组织车间级验收并上报。
- 由其他岗位归口的部分（技能只提示，不代做）：验收结论与签字由验收组现场完成；试压、试运、无损检测的技术结论以检测报告为准；联锁保护试验由仪表/电气执行；特种设备法定检验与使用登记由特种设备管理归口。
- 不适用：检修方案编制；检修前设备交出；承包商表现评价；隐患整改验收；工程项目的竣工验收与结算。

## 前提条件
- 输入：用户说明的设备位号、设备类型、检修内容、承修单位（必需）。可选：检修方案（`.docx` / `.txt` / `.md` / `.xlsx` / CSV 目录，用于比对质量控制点）、验收记录 xlsx（厂内表或 EM 检修验收记录导出）、试压试运记录、备件更换清单。
- **PDF 先用平台 pdf 技能转为 txt/docx 再传入，脚本不读 PDF；扫描件需 OCR。** `.doc` 旧版 Word 须另存为 `.docx`。
- 必填信息：位号、设备类型、检修内容、承修单位；建议提供检修分级、完工时间。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块（docx 由随技能携带的 `scripts/lib/docx-lite.js` 读取），无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得凭记忆列验收项。**

## 操作步骤
1. **确认验收范围** —— 按 `references/intake-questions.md` 核对：设备类型、检修分级、检修内容、是否解体、是否更换主要部件、是否需试压、是否需试运、是否特种设备。**范围不清时必须追问；三个开关不得默认。**
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/acceptance.js" --tag "<位号>" --equip-type "<设备类型>" --scope "<检修内容>" --contractor "<承修单位>" --repair-type <大检修|日常维修|抢修|专项> --out "<工作目录>/完工验收"
   ```
   可选：`--plan "<检修方案路径>"`（docx/txt/md/xlsx，比对质量控制点）、`--records "<验收记录xlsx>"`、`--pressure-test`、`--trial-run`、`--special-equipment`、`--name`、`--workshop`、`--finished-at`、`--no <验收单编号>`（不传为临时编号）。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（设备类型不覆盖 / 方案无法解析 / 质量控制点与验收项不对应 / 检修分级旧值映射 / 三个开关未指定等）。脚本用法详见 `scripts/README.md`。
   - 提供了检修方案时：脚本比对方案中的质量控制点是否都有对应验收项，缺口在 `qcGap` 中列出，**不得静默忽略方案中的控制点**。
   - 设备类型不覆盖：只输出通用验收框架并 warning，具体技术指标标"待技术人员补充"，**模型不得填写凭经验的验收数值**。
3. **读取 acceptance.json 并逐项记录** —— 从 `<输出目录>/acceptance.json` 获取 `items`（验收项：序号、规则号、验收内容、验收标准、验收方式、责任方）、`requiredRecords`（应附资料清单）、`qcGap`、`signatures`、`counts`。**逐项向用户核对实际验收情况并记录结果；模型不得预填"合格"。**
4. **生成验收报告** —— 脚本已按 `assets/templates/acceptance-template.md` 结构写出 `acceptance.md`；只在"七、遗留问题"的 `<!-- ANALYSIS_START -->` / `<!-- ANALYSIS_END -->` 之间撰写用户说明或记录中写明的遗留事项。**验收结论栏与签字栏留空由验收组填写，模型不得代填。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `acceptance.md` 与 `acceptance.json`。**必须保留声明行："本清单为辅助核对工具，验收结论须由验收组现场确认并签字；未完成签字前设备不得投用"，不得删除或改写。存在不合格项时，须在开头以【注意】明确提示。**

## 预期结果
- `acceptance.md`：完工验收报告，九节 + 附：一、设备与检修概况（含检修分级、承修单位）；二、验收项逐项结果（五大类分小节）；三、应附资料核对；四、不合格项与整改要求；五、未填写与未判定项；六、与检修方案质量控制点对应情况；七、遗留问题（分析段占位）；八、验收结论（留空）；九、三级验收签字（班组 / 车间 / 公司设备管理部门 / 工艺（操作）/ 承修单位，留空）；附：数据提示（有 warning 时）。末尾固定声明行。
- `acceptance.json`：`meta`（含 `repairType`、`planFormat`、声明行）、`counts`、`items`、`requiredRecords`、`qcPoints / qcMatched / qcGap`、`unqualified`、`undeterminedResult`、`unmatchedRecord`、`conclusion`（恒 null）、`signatures`（五方，恒 null）、`warnings`；`summary.json`：脚本末行摘要。
- 交付时向用户说明：验收项总数、已验收数、不合格数、资料缺口、与方案质量控制点的对应情况、检修分级、脚本 warnings（如有）。

## 不适用范围
- 不代为判定验收合格与否，不签署验收结论，不替任何一级验收签字。
- 不出具试压、试运、无损检测、联锁试验的技术结论（以检测与试验报告为准）。
- 不做工程结算、工程量确认与费用审核。
- 不替代特种设备的法定检验与使用登记手续。

# 通知单草稿规则表（专业归口 / SAP 优先级 / 通知单类型 / 故障代码建议）

> **本表为默认参考口径，依据《中国石化设备管理规定》《炼化企业设备管理技术规定》中"缺陷管理—维修通知—工单"的流程分工整理，不转述具体数值。** 各厂专业划分、通知单类型定义与优先级口径不同，厂内有正式规定时以厂内为准，并在交付时注明采用的口径来源。
> 专业归口**为建议值，需车间与承修单位确认**；脚本产出的每一处都会带这句话。
> **工时与备件不在本表内**：工时定额由承修单位在工单（订单）中填写，备件由承修单位按台账与备件库确定，车间设备员的通知单不填。

## 一、专业归口判定

判定顺序：**设备台账「专业」列（SAP「专业类别」）→ 位号前缀 / 设备名关键词（先特殊后一般）→ 待定**。台账有值一律以台账为准，不再推断。

| 顺序 | 专业 | 位号前缀 | 设备名关键词 | 说明 |
|---|---|---|---|---|
| 1 | 电气 | `EM-`、`M-` | 电机、电动机、变频、配电、开关柜、电缆、变压器、电气 | 先于"泵"判，避免"循环水泵电机"被抢成动设备 |
| 2 | 静设备（安全附件） | — | 安全阀、疏水阀、爆破片、阻火器、呼吸阀 | 安全附件归静设备，不归仪表 |
| 3 | 仪表 | `I-`、`FT-`、`PT-`、`TT-`、`LT-`、`TI-`、`PI-`、`FI-`、`LI-`、`FIC-`、`PIC-`、`TIC-`、`LIC-`、`AT-` | 仪表、变送器、调节阀、流量计、分析仪、报警器、液位计、压力表、热电偶 | |
| 4 | 动设备 | `P-`、`K-`、`GB-`、`J-`、`B-` | 泵、压缩机、风机、机组、汽轮机、搅拌 | |
| 5 | 静设备 | `E-`、`V-`、`C-`、`T-`、`D-`、`R-`、`F-` | 换热器、冷却器、再沸器、空冷、罐、容器、塔、管道、管线、阀门、加热炉、反应器 | `T-` 只归静设备（塔），仪表温度位号是 `TT-`/`TI-` |
| — | **待定** | 以上均不匹配 | — | 列入信息缺口清单，由设备员确认归口，**不塞到动设备** |

## 二、缺陷等级 → SAP 优先级（默认映射，厂内可配置）

SAP PM 通知单优先级：**1 非常高 / 2 高 / 3 中 / 4 低**，报告同时显示数字与中文。

| 规则号 | 条件 | 结果 |
|---|---|---|
| P0 | 用户 `--priority` 显式指定（1~4、非常高/紧急、高、中、低） | 以用户为准，来源标「用户指定」 |
| PA / PB / PC | 未指定，缺陷等级为 A 级（重大）/ B 级（严重）/ C 级（一般） | 1 / 2 / 3，来源标「按缺陷等级 X 默认口径」 |
| PI / PII / PIII / PIV | 未指定，旧四级 I~IV（兼容历史 defects.json 与台账） | 1 / 2 / 3 / 4 |
| PU1 | 未指定且无缺陷等级（或上游等级为「未判定」） | **未判定** |
| PU2 | `--priority` 取值无法识别 | **未判定**，并在缺口清单点明原写法 |

**PU1/PU2 一律不按「3 中」默认。** 未判定的草稿照常生成、照常编草稿序号，但优先级与通知单类型留"待确认"，单列在「信息缺口清单 → 未判定项」，由车间确认后补填再在 SAP 创建。

## 三、通知单类型（默认映射，厂内可配置）

| 规则号 | 条件 | 结果 |
|---|---|---|
| N0 | 用户 `--notif-type` 显式指定 M1/M2/M3 | 以用户为准 |
| N1 | 优先级 1 或 2 | M2 故障报告 |
| N2 | 优先级 3 或 4 | M1 维修申请 |
| NU1 | 优先级未判定 | **未判定**，不按 M1 默认 |

有的厂 M1/M2 定义相反或另有 M3 活动报告用法，交付时须提示"按厂内通知单类型目录核对"。

## 四、故障代码建议

按现象类型给 SAP 通知单「损坏/故障代码」的**建议文本**，厂内目录代码由设备员对照填写。现象类型识别关键词与 defect-intake-grading `references/grading-rules.md` 同口径（含「温度偏高/升高/持续上升」「偏高 8℃」「比同类泵高约 15℃」等温升写法）：

| 现象类型 | 故障代码建议文本 |
|---|---|
| 泄漏 | 泄漏 |
| 振动 | 振动超标 |
| 异响 | 异响 |
| 温升 | 温度异常 |
| 腐蚀 | 腐蚀减薄 |
| 变形开裂 | 变形开裂 |
| 失效 | 功能失效 |
| 性能下降 | 性能下降 |
| 电气异常 | 电气故障 |
| 仪表异常 | 仪表故障 |
| 其他 | （留空） |

## 五、要求开始 / 要求结束

- 要求开始：取缺陷发现时间（SAP「通知日期」）的日期；没有则取生成当日（北京时间）。
- 要求结束：`--due`，是报告单位提出的期望，与缺陷等级推出的"建议处理时限"（defect-intake-grading 的 `dueDate`）是两回事，草稿里分别列出。
- 要求结束早于当前日期 → warning，草稿仍生成，md 上标注「（早于当前日期，请确认是否改期）」，**不自动改期也不拒绝生成**。

## 六、编号

通知单号与工单号均由 SAP 生成，脚本只给**草稿序号 1..N**，不编号、不避让、不接受 `--prefix`/`--order-ledger`。

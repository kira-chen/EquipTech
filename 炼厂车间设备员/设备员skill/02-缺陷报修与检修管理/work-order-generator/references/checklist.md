# 交付自检清单

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；为 `false` 时已告知用户 `error` 原文并终止，**未手工拼装通知单草稿或估算工时**
- [ ] `warnings` 已逐条告知用户（位号不在台账 / 无历史记录 / 要求结束早于当前等）
- [ ] `notifications.json`、`notifications.md`、`notifications.csv` 均已生成

## 通知单要素
- [ ] 每张草稿都有功能位置、故障现象、报告单位、要求开始、要求结束
- [ ] 通知单号列留空，交付说明写明「由 SAP 生成」，**未自编通知单号或工单号**
- [ ] 要求结束早于当前的，已在交付说明中提示确认改期

## 设备信息
- [ ] SAP 设备编号、规格型号、安装位置、所属专业、投用日期**全部来自设备台账**，未凭设备名推测
- [ ] 位号查不到台账的，相应字段标「待补充」，并已告知用户需从 SAP 技术对象或现场铭牌核实
- [ ] 未提供设备台账时，已提示用户补台账（SAP 技术对象导出）可自动带出这几项
- [ ] 设备编号（8 位流水号）与功能位置分别展示，未混用

## 历史维修记录
- [ ] 历史摘要**逐条注明日期、内容、工作中心、原订单号**，全部来自历史维修记录表 / SAP 订单历史
- [ ] 未提供历史记录的，章节写「未提供历史维修记录」，**未编造任何检修履历**
- [ ] 该位号在表中无记录的，已写明「无位号 XXX 的记录」而不是留白

## 归口建议
- [ ] 专业归口标注了「**建议值，需车间与承修单位确认**」，判「待定」的已列入信息缺口清单
- [ ] 工时与备件**未给出任何数值或方向**，只写「由承修单位在工单（订单）中填写」
- [ ] 建议承修单位标注为建议，派工由厂内流程定

## 优先级与通知单类型
- [ ] 优先级同时显示数字与中文（1 非常高 / 2 高 / 3 中 / 4 低），来源已说明：用户指定 / 按缺陷等级默认口径 / 未判定
- [ ] 优先级未判定的单列一节，**未按「3 中」默认**，通知单类型也随之未判定，已请用户确认后补填
- [ ] 采用的默认映射（A→1、B→2、C→3；1/2→M2、3/4→M1）已明确标注为厂内可配置
- [ ] 故障代码写的是建议文本，已提示按厂内目录核对

## 交付说明
- [ ] 已说明草稿数、优先级与通知单类型分布、信息待补充项数、未判定数
- [ ] 已区分「建议值」与「系统值」，未把草稿说成已创建的通知单
- [ ] **已保留说明行「本通知单草稿由车间设备员核对后在 SAP 中创建，通知单号由系统生成；维修工单（订单）、工时与备件由计划员或承修单位编制，本草稿不替代审核派发。」**，未说成「已开工单」「已派工」
- [ ] 未出现旧称「机动处」「EAM」；公司层写「公司设备管理部门（机动部/设备部）」
- [ ] 需要检修技术方案的，已提示可接 `repair-plan-assistant`；需要跟踪催办的，已提示 `work-order-tracker`

# examples 回归测试数据

> 本目录仅开发包含有，发布包不含。由 `node scripts/make-sample.js --out examples` 再生。
> 本技能以命令行参数驱动，样例规程文件用于验证数值引用与冲突检出，场景表供人工对照，主脚本不直接读取场景表。
>
> **样例规程中的所有数值均为虚构演示值，不对应任何真实设备或厂内规程，不得照抄使用。**

## 关键验证点

1. **数值只引用规程原文（命脉）**：场景 1 的每一个数值都带「出处：文件名 第 N 行」；场景 2 完全无规程，`counts.valueCited` 恒为 0，方案全文不出现任何 N·m / mm / MPa 数值。
2. **无出处一律「待查规程确认」**：场景 1 规程没写动平衡等级，PU9 写「待查规程确认」并进 `toBeConfirmed`。
3. **JSA/HSE 占位不自判**：任何场景第三节都是占位：八大类作业许可写「用火作业」「盲板抽堵作业」，是否涉及只给「可能涉及（待确认）」/「待确认」，级别恒写「以作业票为准，本方案不自判级别」，风险等级恒「待填」；双监护（属地监护人 + 作业单位监护人）列出待填。
4. **检修分级口径**：大检修（停工检修）/ 日常维修 / 抢修 / 专项；`--level 小修` 归日常维修并 warning「旧口径已废止」；场景 2 识别为大检修。
5. **新增覆盖**：加热炉（FU）、空冷器（AC）、仪表回路（IN）各有专业步骤、工机具、备件、质控点与验收项；调节阀归仪表回路，安全阀仍归阀门；空冷器先于静设备判。
6. **覆盖范围外只出通用框架**：场景 3 的 `steps` 全部是 `G` 开头，每条 `note` 带「待技术人员补充」。
7. **规程冲突以厂内为准**：样例泵规程 4.1 与 4.2「一般情况下」的对中偏差不一致，列入 `conflicts`，`b.general` 为 `true`，处理口径写「一律以厂内规程为准」。
8. **未判定不默认**：场景 4「例行处理」判不出是否解体，`meta.dismantle` 为 `null`，G5/ST3/ST4 标 `undetermined` 并单列 8.3。
9. **两行声明不可删**：通用声明行与「本方案为辅助生成的初稿……方可实施」在 md 开头与结尾各出现一次；提示用「【注意】」，不含 emoji。
10. **质控点与验收供三级验收比对**：`qcPoints` 与 `acceptance` 供 `completion-acceptance` 逐项比对。

## 再生样例

```bash
node scripts/make-sample.js --out examples            # seed=1
node scripts/make-sample.js --out examples --seed 9   # 规程数值与编制人变化，结论不变
```

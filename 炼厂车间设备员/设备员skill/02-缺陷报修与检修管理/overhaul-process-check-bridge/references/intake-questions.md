# 车间侧前置信息清单与追问话术（检修方案）

> 以下信息**不进入规则判定**，仅用于「车间侧补充提示（非规则判定）」一节。规则判定所需的方案信息由 `overhaul-safety-check` 自行从检修方案中抽取。

## 必须确认

| 信息 | 追问 | 用途 |
|---|---|---|
| 检修方案文件 | 「方案是 Word 还是 PDF？PDF 请先转成 Word 或文本再发我」 | 交给源技能解析 |
| 检修分级 | 「这是装置大检修的方案，还是日常维修、抢修、专项（技改）？」 | `--repair-type`，只进报告抬头 |
| 检修项目与位号 | 「哪台设备、哪个项目？位号是多少？」 | 关联车间侧信息 |
| 涉及的作业类型 | 「方案里有用火、受限空间、高处、吊装、临时用电、盲板抽堵这些作业吗？每项作业都标了类型吗？」 | 源技能按类型触发专项规则；未标注会出未判定 |
| 工期与承修单位 | 「计划干几天？哪家承修，还是本厂自修？」 | 源技能组合规则（工期 >30 天查阶段性检查）与承包商规则 |

## 建议确认（影响补充提示的完整性）

| 信息 | 追问 | 可接技能 | notes.json 的 item |
|---|---|---|---|
| 设备交出条件 | 「交出清单列了吗？盲板、吹扫置换、停电挂牌的条件具备没？」 | `equipment-handover-check` | 设备交出条件 |
| 同期交叉作业 | 「同一时段同一区域还有别的方案在施工吗？上下交叉有没有？」 | `cross-operation-conflict` | 同期交叉作业 |
| 承包商资质 | 「承修单位的入厂安全教育、安全协议、特种作业证复审核过了吗？」 | `contractor-qualification-check` | 承包商资质 |
| 备件与工机具到位 | 「垫片、螺栓、备件领了吗？试压泵、吊具这些到位没？」 | 车间自查（备件可接 `spare-parts-inventory-query`） | 备件与工机具到位 |
| 其它车间自查项 | 「脚手架方案、吊装方案是不是另行审批？」 | 车间自查 | 自定义 item |

把核实结果整理成 `notes.json`（格式见 `references/input-spec.md`），状态只写 **已核实 / 未核实 / 不适用**。

## 追问原则

1. **一次性列出所有缺项**，不要逐个追问。
2. 车间侧信息缺失**不阻塞**规则判定，源技能照常运行，只是补充提示会标注「未核实」。
3. **不要替用户回答**。「应该交出了吧」「备件一般都有」这类推测不能写进 notes.json，也不能写进报告。
4. 方案技术内容（检修工艺、材料、工期合不合理）**不要替技术负责人判**，本技能只核安全措施章节。
5. 作业类型未标注时，追问用户补标后再跑源技能；不要自己给作业贴标签。

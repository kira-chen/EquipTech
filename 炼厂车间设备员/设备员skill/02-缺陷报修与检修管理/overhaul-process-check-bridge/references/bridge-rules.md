# 判定与转达口径（检修方案安全措施）

## 一、两个脚本的分工

本技能从读方案到出车间自查报告是一条流程，判定和转达由两个脚本分开负责：

| 环节 | 脚本 | 职责 |
|---|---|---|
| 判定 | `scripts/check.js`（规则引擎） | 按 `references/checklist.json`（70 条：通用必备 + 按作业类型触发的专项 + 组合规则）逐条对照 plan.json，输出 `result.json` |
| 转达 | `scripts/merge-report.js` | 逐条深拷贝 `result.json` 的 findings（含"方案里怎么补"），补车间侧提示，按车间自查口径成文；**不改写任何判定** |

模型负责读方案、抽取 plan.json 并向用户复述确认、补车间侧信息和撰写分析段，**不替脚本下判定**。

本技能**只核安全措施章节**，不审方案技术内容（检修工艺、材料选型、工期合理性），也不做进度、费用审查。

## 二、术语：检修分级、作业类别与大检修节点

- 检修分级按中石化口径：**装置大检修（停工检修）/ 日常维修 / 抢修 / 专项（技改技措）**。"大修 / 中修 / 小修"口径废止，`--repair-type` 保留映射：大修 → 大检修，中修 / 小修 → 日常维修，并 warning。分级只写入报告抬头，**不改变核查规则**（规则按方案内容与作业类型触发，与分级无关）。
- 大检修关键节点：开工前条件确认（设备交出、盲板、作业票）→ 施工 → **三查四定** → **中交（中间交接）** → 试压 / 试运 / 投料前条件确认 → 开工。方案安全措施核查发生在"开工前条件确认"之前；三查四定与中交的跟踪用 `turnaround-workshop-tracker`。
- 作业类别按《中国石化作业许可管理规定》八大类称**用火作业**、受限空间作业、盲板抽堵作业等。plan.json 的 `job_types` 与规则库沿用 GB 30871 的标签"动火 / 受限空间 / 高处 / 吊装 / 临时用电 / 盲板抽堵 / 动土 / 带压堵漏 / 射线探伤 / 化学清洗"，其中"动火"即用火作业。合并报告的字段表照搬标签原值，并加注八大类名称（动火 → 用火作业）；带压堵漏 / 射线探伤 / 化学清洗不在八大类内，不加注。
- **规则库原文不替换**：findings 的措施名称、问题、"方案里怎么补"、依据原文来自 `checklist.json`，其中的"动火""大修 / 中修"等写法由 merge-report 原样照搬，不做替换（全项目统一改为"用火"另行处理）。
- 方案里各专项措施最终以**开工时逐票办理的作业票**为准，方案核查通过不等于作业票通过；作业票预检用 `permit-precheck-bridge`。

## 三、规则引擎的判定口径（check.js 已固化）

- 输出四级：`must_fix` 缺失（必须补充）/ `should_improve` 建议完善 / `undetermined` 未判定 / `pass` 已有。
- 措施字段：`null` / 空串 / `false` / 数字 `0` / 否定词（无、不涉及、不适用、没有、N/A、待定、暂无，或仅「/ — - ~」等符号）视为方案未写明；`true` 或实质文字视为已写明。含理由的长句（如"不适用：自行检修……"）按已写明。
- 专项规则由 `jobs[].job_types` 触发；有作业 `job_types` 为 `null`（未标注）时，未被触发的专项规则输出未判定，**按作业类型聚合为一条**（`UND-<作业类型>`），说明中列出涉及规则号；`[]` 表示方案标注"无特殊作业"，不算未标注。
- 类型标签不在 `checklist.json` 的 `meta.job_types` 合法表中 → 剔除并记入抽取说明；剔除后为空按未标注处理。
- `duration_days` 为空或无法按天数解析（如"9.20-11.3"）→ 工期类规则未判定。
- 规则细节见 `references/checklist-ref.md`；**不得在规则库之外凭经验增减措施项**。

## 四、结果转达规范（merge-report.js 已固化）

### 必须照搬的内容

| 来源字段 | 转达要求 | 脚本实现 |
|---|---|---|
| `findings[]` 每条的 `rule_id / severity / name / message / detail / advice / basis / jobs` | 原文照搬，不改写措辞、不合并、不归类、不简化 | 逐条深拷贝 |
| `severity: must_fix` | 写「缺失（必须补充）」（规则引擎口径，不写成"不符合"） | `SEV_CN` |
| `severity: pass` | 写「已有」并摘录 `detail`（方案原文要点） | 「四、已有措施」 |
| `severity: undetermined`（含 `UND-<作业类型>` 聚合条） | 保留「未判定」状态与缺失信息说明 | 单列「三、未判定项」 |
| `advice`（方案里怎么补） | 原文转达，供方案编制人直接采用 | 缺失项表与整改建议 |
| `summary` | 原值保留；报告按 findings 重新计数，不一致只 warning | `sourceSummary` 与 `counts` 并存 |
| `extraction_notes` | 原文附在报告末尾 | 「附：抽取说明（原文）」 |
| `disclaimer` | **全部保留**，置于本技能声明行之前 | `meta.sourceDisclaimer` + md 末尾 |

### 禁止的操作

- 把「未判定」改写为「已有」或「缺失」
- 把多条缺失项合并成一条概括，或把"建议完善"升降级
- 因为「方案另有专项方案」而自行把缺失项划掉（"另行编制 / 见专项方案"的文件应在审批前收齐）
- 删除规则引擎的声明行
- 改写 findings 原文（包括把规则库原文里的"动火"替换成"用火"）；标签只作加注
- 为了让 findings 变好看而改 plan.json 的抽取结果（抽取有误应按原件更正并重跑 check.js）
- 替技术负责人审查方案技术内容

## 五、车间侧补充提示

本技能可以补充以下车间关注项，但**必须单独成节**，标题写「车间侧补充提示（非规则判定）」：

| 补充项 | 可接的技能 | 状态取值 |
|---|---|---|
| 设备交出条件 | `equipment-handover-check` | 已核实 / 未核实 / 不适用 |
| 同期交叉作业 | `cross-operation-conflict` | 同上 |
| 承包商资质（入厂安全教育、安全协议、特种作业证复审） | `contractor-qualification-check` | 同上 |
| 备件与工机具到位 | 车间自查（备件查询可接 `spare-parts-inventory-query`） | 同上 |
| 其它车间自查项（脚手架方案、吊装方案另行审批等） | 车间自查 | 同上 |

- 车间侧信息是可选的：不传 `--notes` 或某项未给 → 一律「未核实」，脚本**不替用户推测为已核实**。
- 状态写成「应该够了」「大概没问题」等不在三值内 → 按「未核实」处理并 warning。
- **这些信息不进入规则判定，不影响规则引擎的结论。**

## 六、双重声明

交付时必须同时保留：

1. **规则引擎的声明行**（原文，脚本从 `result.json` 的 `disclaimer` 读入）：「本结果为辅助核查，不替代检修方案审批；依据条款按记忆整理，以 GB 30871-2022 正式文本与企业制度为准。」
2. **本技能的声明**：「核查为辅助自查，不替代技术负责人审核与安全部门审批；方案是否批准以审批人意见为准。」

`result.json` 没有 `disclaimer` 字段时脚本 warning，不伪造。

## 七、制度引用

- 《中国石化作业许可管理规定》：八大类命名、双监护。
- 《炼化企业设备管理技术规定》《中国石化设备管理规定》：检修分级与检修方案审批层级（以厂内制度为准）。
- 《中国石化承包商安全管理规定》：承包商资质车间侧核实项（入厂安全教育、安全协议、特种作业证复审）。
- GB 30871-2022：规则库的依据，条款号按记忆整理，以正式文本为准（规则引擎声明行已注明；待核实清单见 `checklist-ref.md` 第 5 节）。
- 本技能不转述任何法规数值。

## 八、与 `permit-precheck-bridge` 的边界

| | 本技能 | permit-precheck-bridge |
|---|---|---|
| 对象 | 检修方案的安全措施章节 | 作业票（一处一票） |
| 输出 | 缺失 / 建议完善 / 未判定 / 已有 | 必须整改 / 建议完善 / 未判定 / 通过 |
| 时点 | 方案上报审批前 | 开工前每张票签发前 |

两者都不做技术内容正确性审查。

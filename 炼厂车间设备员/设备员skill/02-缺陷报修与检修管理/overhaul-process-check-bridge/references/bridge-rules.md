# 与 `overhaul-safety-check` 的衔接口径（检修方案安全措施）

## 一、本技能的定位

**入口与衔接层，不是判定层。** 检修方案安全措施是否齐全由 `overhaul-safety-check` 的规则引擎（70 条：通用必备 + 按作业类型触发的专项 + 组合规则）判定，本技能负责：

1. 车间侧前置信息的补全与提示（设备交出、同期交叉作业、承包商资质、备件与工机具）
2. 判定结果的转达（`scripts/merge-report.js` 逐条深拷贝，含"方案里怎么补"）
3. 车间关注项的补充（与规则判定严格分开成节）

本技能**只核安全措施章节**，不审方案技术内容（检修工艺、材料选型、工期合理性），也不做进度、费用审查。

## 二、术语：检修分级与大检修节点

- 检修分级按中石化口径：**装置大检修（停工检修）/ 日常维修 / 抢修 / 专项（技改技措）**。"大修 / 中修 / 小修"口径废止，`--repair-type` 保留映射：大修 → 大检修，中修 / 小修 → 日常维修，并 warning。分级只写入报告抬头，**不改变源技能的核查规则**（源技能按方案内容与作业类型触发规则，与分级无关）。
- 大检修关键节点：开工前条件确认（设备交出、盲板、作业票）→ 施工 → **三查四定** → **中交（中间交接）** → 试压 / 试运 / 投料前条件确认 → 开工。方案安全措施核查发生在"开工前条件确认"之前；三查四定与中交的跟踪用 `turnaround-workshop-tracker`。
- 作业类型标签：源技能 `job_types` 按 GB 30871 写"动火 / 受限空间 / 高处 / 吊装 / 临时用电 / 盲板抽堵 / 动土 / 带压堵漏 / 射线探伤 / 化学清洗"。车间口径按《中国石化作业许可管理规定》八大类称**用火作业**、盲板抽堵作业等；**转达时标签与 findings 原词照搬**，本技能只在源技能字段表里加注八大类名称（动火 → 用火作业），带压堵漏 / 射线探伤 / 化学清洗不在八大类内则不加注。
- 方案里各专项措施最终以**开工时逐票办理的作业票**为准，方案核查通过不等于作业票通过；作业票预检用 `permit-precheck-bridge`。

## 三、依赖不可用时的处理（硬规则）

运行 `node scripts/check-dependency.js` 确认依赖可用性（支持 `--skill-root`、环境变量 `SKILL_PACK_ROOT`、WorkBuddy / Claude Code / 豆包默认技能目录、技能包一级子目录扫描）。

`available: false` 时：

1. 明确告知用户「需先安装检修方案安全措施核查技能」
2. **终止本次任务**
3. **不得用本技能自行判定方案安全措施是否齐全**
4. **不得降级为人工判断或凭经验给结论**

这条没有例外。方案安全措施涉及安全红线，宁可不给结论，也不能给一个没有规则引擎支撑的结论。

## 四、结果转达规范（merge-report.js 已固化）

### 必须照搬的内容

| 来源字段 | 转达要求 | 脚本实现 |
|---|---|---|
| `findings[]` 每条的 `rule_id / severity / name / message / detail / advice / basis / jobs` | 原文照搬，不改写措辞、不合并、不归类、不简化 | 逐条深拷贝 |
| `severity: must_fix` | 写「缺失（必须补充）」（源技能口径，不写成"不符合"） | `SEV_CN` |
| `severity: pass` | 写「已有」并摘录 `detail`（方案原文要点） | 「四、已有措施」 |
| `severity: undetermined`（含 `UND-<作业类型>` 聚合条） | 保留「未判定」状态与缺失信息说明 | 单列「三、未判定项」 |
| `advice`（方案里怎么补） | 原文转达，供方案编制人直接采用 | 缺失项表与整改建议 |
| `summary` | 原值保留；报告按 findings 重新计数，不一致只 warning | `sourceSummary` 与 `counts` 并存 |
| `extraction_notes` | 原文附在报告末尾 | 「附：源技能抽取说明（原文）」 |
| `disclaimer` | **全部保留**，置于本技能声明行之前 | `meta.sourceDisclaimer` + md 末尾 |

### 禁止的操作

- 把「未判定」改写为「已有」或「缺失」
- 把多条缺失项合并成一条概括，或把"建议完善"升降级
- 因为「方案另有专项方案」而自行把缺失项划掉（源技能已提示"另行编制 / 见专项方案"的文件应在审批前收齐）
- 删除源技能的任何声明行
- 把源技能的"动火"标签改写成"用火"（只作加注）
- 替技术负责人审查方案技术内容

## 五、车间侧补充提示

本技能可以补充以下车间关注项，但**必须单独成节**，标题写「车间侧补充提示（非规则判定）」：

| 补充项 | 可接的技能 | 状态取值 |
|---|---|---|
| 设备交出条件 | `equipment-handover-check` | 已核实 / 未核实 / 不适用 |
| 同期交叉作业 | `cross-operation-conflict` | 同上 |
| 承包商资质（入厂安全教育、安全协议、特种作业证复审） | `contractor-qualification-check` | 同上 |
| 备件与工机具到位 | 车间自查（备件查询可接 `spare-parts-inventory-query`） | 同上 |
| 其它车间自查项（脚手架方案、吊装方案另行审批等） | 车间自查 | 同上 |

- 不传 `--notes` 或某项未给 → 一律「未核实」，脚本**不替用户推测为已核实**。
- 状态写成「应该够了」「大概没问题」等不在三值内 → 按「未核实」处理并 warning。
- **这些信息不进入规则判定，不影响源技能的结论。**

## 六、双重声明

交付时必须同时保留：

1. **源技能的全部声明行**（原文，脚本从 `disclaimer` 读入）
2. **本技能的声明**：「核查为辅助自查，不替代技术负责人审核与安全部门审批；方案是否批准以审批人意见为准。」

源技能结果没有 `disclaimer` 字段时脚本 warning，不伪造源声明。

## 七、制度引用

- 《中国石化作业许可管理规定》：八大类命名、双监护。
- 《炼化企业设备管理技术规定》《中国石化设备管理规定》：检修分级与检修方案审批层级（以厂内制度为准）。
- 《中国石化承包商安全管理规定》：承包商资质车间侧核实项（入厂安全教育、安全协议、特种作业证复审）。
- GB 30871-2022：源技能规则表的依据，条款号以正式文本为准（源技能声明行已注明）。
- 本技能不转述任何法规数值。

## 八、与 `permit-precheck-bridge` 的边界

| | 本技能 | permit-precheck-bridge |
|---|---|---|
| 对象 | 检修方案的安全措施章节 | 作业票（一处一票） |
| 依赖 | `overhaul-safety-check` | `work-permit-precheck` |
| 输出 | 缺失 / 建议完善 / 未判定 / 已有 | 必须整改 / 建议完善 / 未判定 / 通过 |
| 时点 | 方案上报审批前 | 开工前每张票签发前 |

两者都不做技术内容正确性审查。

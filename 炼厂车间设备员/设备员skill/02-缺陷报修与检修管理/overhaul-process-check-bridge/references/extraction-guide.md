# 检修方案抽取手册（docx → plan.json）

> **作业类型标签说明：** `jobs[].job_types` 的枚举沿用 GB 30871 的「动火」，即中石化的「用火作业」。方案里写「用火作业 / 用火作业许可证 / 用火安全作业证 / 用火票 / 用火」的，标签一律填「动火」；写成「用火」不在合法表内，会被规则引擎剔除并按未标注处理。规则库的规则名与措施键（如 `hotwork_*`）也沿用「动火」写法，抽取时照用。

## 一、三步流程
1. **读方案文本**：`node "<技能根目录>/scripts/docx2text.js" --input <检修方案.docx> --out <工作目录>/方案核查/plan.txt`。输出中表格行以 `|` 分隔，`[x]`/`[ ]` 为勾选状态，`‹›` 为横向合并占位（不是留白），`〃` 为纵向合并续行，`【文本框】` 为文本框内容，页眉/页脚在末尾单列；末行 JSON 摘要（段落数、表格数、勾选框数）用于核对是否读全。
2. **抽取**：复制 `assets/templates/plan.json`，按下面字段对照表逐项填写，键名对照 `references/plan-schema.md` 校对。**方案没写的一律填 `null`，不得按"常规肯定会做"猜测**；每处 null / 推断 / 换算在 `extraction_notes[]` 记一条（格式「字段：方案情况 → 填了什么」）。保存到 `<工作目录>/方案核查/plan.json`。
3. **自检**（见文末清单），向用户复述确认后运行规则引擎 `scripts/check.js`。

## 三、作业类型识别关键词表（jobs[].job_types）
> 以方案作业表中「作业类型」栏为准；没有该栏时按作业名称/内容中的关键词判断，可多选。仅凭关键词推断的，在 extraction_notes 记一条。

| 关键词（出现于作业名称/内容） | 标签 |
|---|---|

| 进塔、入罐、进釜、釜内、罐内、塔内、器内、炉膛内、内件更换、清罐、人孔进入、地下池/井内 | 受限空间 |

| 吊装、吊车、起重、吊运、抽芯（换热器管束）、整体更换（大型设备）、捯链吊移（大件） | 吊装 |
| 临时用电、接电、电源接引、电焊机接电、临时照明 | 临时用电 |

| 动土、开挖、挖掘、破土、地坪开凿、桩基 | 动土 |
| 带压堵漏、带压密封、注剂堵漏 | 带压堵漏 |
| 射线、RT、γ射线、X 光检测 | 射线探伤 |
| 化学清洗、酸洗、碱洗、钝化、药剂清洗 | 化学清洗 |

注意：
- 「焊接」类作业若同时在塔/罐内进行 → 同一项作业标 `["动火","受限空间"]`（触发双票联办提示 C-001）；在脚手架/高处焊接 → 加标「高处」（触发 C-002）。
- 「探伤」裸词**不**直接标射线探伤：仅当同时出现 RT/射线/γ/X 等字样才标「射线探伤」；UT（超声）、PT（渗透）、MT（磁粉）探伤不是射线探伤，不标。
- 电动葫芦/捯链移动小件是否算吊装作业按方案表述，拿不准就标注并记备注。
- 「喷砂」（除锈/防腐预处理）不在十类标签内，但常伴随临时用电与高处，且在设备/容器内喷砂属受限空间——按方案表述判断伴随类型并记备注。

## 四、措施抽取规则
- 措施章节里**写了具体安排**（哪怕一句话）→ 对应键填摘录文字（≤60 字为宜）或 `true`。
- 措施以勾选表出现：`[x]` → `true`；`[ ]` → `false`；`[×]` 含义不明 → `null` 并记备注。
- 措施栏只写「无」「/」「—」等否定词/符号 → 填 `false`（不要照抄成文字，照抄进去引擎也会按否定词判未写明）；写「不适用」并**附了理由**的长句（如「本项目自行检修，承包商资质审查不适用：人员为在册职工……」）才按文字摘录——引擎按实质文字判已写明，理由是否成立由审批人核对。
- 只写口号（如「加强安全管理」）而没有对应到具体措施项的，不要据此把具体措施键填 true。
- 附件清单里列了文件名即算有该附件（填文件名文字）；正文说「另行编制」「见专项方案」也算已写明（摘录该句），但在备注中提醒审批人索要。

### 叙述式方案示例映射（真实方案多为叙述文字，不是逐键罗列）
真实检修方案的措施常整段叙述、一句话覆盖多个键，对照示例：
- 「进塔作业前加盲板隔离并蒸汽吹扫置换，分析合格后办理受限空间作业票方可进入，作业期间罐外专人监护」→ `isolation_purge`（加盲板隔离并蒸汽吹扫置换）、`gas_test_plan`（分析合格后进入）、`confined_permit`（办理受限空间作业票）、`confined_guardian`（罐外专人监护），一句话填四个键，各摘录对应片段。
- 「所有用火作业严格执行公司用火管理制度，办理用火作业许可证，用火分析、监火人按制度落实」→ `hotwork_permit`、`hotwork_gas_test`、`fire_watcher` 三键均摘录该句（点到了具体措施项）；若只写「严格执行用火管理制度」而未点出分析/监火 → 只能证明办票意识，三键均不要填 true，记备注。
- 「检修用电从 3# 配电箱接引，由电工班负责，杜绝私拉乱接」→ `power_distribution`（接引与负责人）；未提办票、漏保 → `temp_power_permit`、`leakage_protector` 填 null。
- 「高空作业系好安全带，做好防护」→ `fall_protection`（摘录）；未提脚手架验收、恶劣天气、办票 → 其余高处键填 null，不得连带填 true。

## 五、抽取后自检（10 项）
1. `jobs` 条数与方案作业表行数一致（跳过表头/合计行）。
2. 每项作业 `job_types` 已按关键词表标注；确实看不出的填 null 并记备注。
3. `duration_days` 为数字；由日期换算的已记备注。
4. `measures` 中没有任何「猜测填 true」的键。
5. 勾选表的 `[ ]` 填了 `false` 而不是漏填。
6. `org` 三个键逐一核对了安全组织章节。
7. `attachments` 三个键逐一核对了附件清单。
8. 所有 null / 推断 / 换算均已记入 `extraction_notes`。
9. 键名与 `plan-schema.md` 一致（多余键会被忽略，拼错键等于漏填）。
10. JSON 语法合法（尾逗号、引号）。

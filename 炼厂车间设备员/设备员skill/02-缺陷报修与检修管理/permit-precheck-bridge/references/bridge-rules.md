# 作业票预检的判定与转达口径

## 一、两个脚本的分工

本技能一条流程走完读票、判定与转达，但判定和转达由两个脚本分开完成，互不越界：

| 脚本 | 职责 | 不做什么 |
|---|---|---|
| `scripts/precheck.js`（规则引擎） | 按 `references/rules.json`（GB 30871-2022 整理的 130 条规则）对抽取好的 permit.json 逐条检查，写出 `result.json`、`report.md` | 不读票面、不补车间侧信息 |
| `scripts/merge-report.js`（转达） | 把 `result.json` 逐条深拷贝成车间自查报告，单独附上车间侧补充提示 | **不改写任何判定**，不新增或删除规则结论 |

车间侧信息（设备交出、交叉作业、承包商资质）只进入报告第五节，不进入规则判定，也不影响规则引擎的结论。

## 二、术语：作业许可八大类

按《中国石化作业许可管理规定》，车间口径统一写：**用火作业**、受限空间作业、高处作业、吊装作业、临时用电作业、动土作业、断路作业、**盲板抽堵作业**。

- 规则引擎的 `type` 枚举与规则库原文沿用 GB 30871-2022 的「动火」一词，即中石化的「用火作业」。票面写"用火作业许可证 / 用火安全作业证 / 用火票"时，抽取时 `type` 填「动火」（见 `references/extraction-guide.md`）。
- **转达时 `type` 与 findings 原文照搬**（例如"受限空间内动火，未关联受限空间作业票"），不做替换；报告在字段表另加一行"作业许可八大类（本技能加注）：用火作业"，并在结论段注明「动火」即中石化「用火作业」，不改原值。规则原文保持可追溯，是为了让每条结论都能对回规则库的同一条规则。
- 用火按特级 / 一级 / 二级，高处一~四级，吊装一~三级：**级别以票面与审批人为准**，本技能不自判级别（规则引擎只核对级别与票面要素是否相符）。
- 拆装盲板的作业必须办理盲板抽堵作业许可，规则库有对应交叉票规则（HW-021 等）；转达时不另加规则。
- 监护按**双监护**（属地监护人 + 作业单位监护人）；规则引擎查"监护人"栏，车间侧提示里可补"属地监护人是否到位"，但这是车间自查项，不是规则判定。

## 三、无法运行规则引擎时的处理（硬规则）

环境不能执行 node、`precheck.js` 末行为 `{"ok":false,...}`，或用户不同意抽取结果又无法更正时：

1. 明确告知用户原因（缺环境 / 输入不合法 / 抽取未确认）
2. **终止本次预检**
3. **不得凭经验或记忆给出票据合规结论**，不得降级为人工判断

作业票合规判定涉及安全红线，宁可不给结论，也不能给一个没有规则引擎支撑的结论。

## 四、结果转达规范（merge-report.js 已固化）

### 必须照搬的内容

| 来源字段（result.json） | 转达要求 | 脚本实现 |
|---|---|---|
| `findings[]` 每条的 `rule_id / severity / message / detail / basis` | 原文照搬，不改写措辞、不合并、不归类、不简化 | 逐条 `JSON.parse(JSON.stringify())` 深拷贝 |
| `severity: undetermined` | 保留「未判定」状态与缺失字段说明 | 单列「三、未判定项」，附【未判定】说明 |
| 不在四级（must_fix / should_improve / undetermined / pass）内的 severity | 原样保留，单列并 warning | `counts.other` |
| `summary` | 原值保留；报告按 findings 重新计数，不一致只 warning | `sourceSummary` 与 `counts` 并存 |
| `extraction_notes` | 原文附在报告末尾 | 「附：抽取备注（原文，需人工确认）」 |
| `disclaimer` | **全部保留**，置于本技能声明行之前 | `meta.sourceDisclaimer` + md 末尾 |

`bridge.json` 的 `meta.source` 固定为 `precheck.js`，标明判定来自本技能的规则引擎。

### 禁止的操作

- 把「未判定」改写为「符合」或「不符合」
- 把多条不符合项合并成一条概括
- 调整不符合项的严重程度
- 因为「看起来问题不大」而弱化表述
- 删除规则引擎的声明行
- 把规则原文里的「动火」替换成「用火」（规则原文必须可追溯；用火作业只作加注）

## 五、车间侧补充提示

本技能可以补充以下车间关注项，但**必须单独成节**，标题写「车间侧补充提示（非规则判定）」：

| 补充项 | 可接的技能 | 状态取值 |
|---|---|---|
| 设备交出条件 | `equipment-handover-check` | 已核实 / 未核实 / 不适用 |
| 同区域交叉作业 | `cross-operation-conflict` | 同上 |
| 承包商资质 | `contractor-qualification-check` | 同上 |
| 其它车间自查项（脚手架验收牌、属地监护人到位等） | 车间自查 | 同上 |

- 车间侧信息是可选的：不传 `--notes` 或某项未给 → 一律「未核实」，脚本**不替用户推测为已核实**。
- 状态写成「大概没问题」「应该交出了」等不在三值内 → 按「未核实」处理并 warning。
- **这些信息不进入规则判定，不影响规则引擎的结论。** 分节呈现是为了避免用户把车间提示误当成合规判定结果。

## 六、两条声明

交付时必须同时保留：

1. **规则引擎的声明行**（原文，脚本从 `result.json` 的 `disclaimer` 读入）："本结果为辅助预检，不替代作业票审批；条款号以 GB 30871-2022 正式文本为准。"
2. **本技能的声明**："预检为辅助自查，不替代安全部门审批；票据是否签发以审批人意见为准。"

`result.json` 没有 `disclaimer` 字段时脚本 warning，不伪造。

## 七、制度引用

- 《中国石化作业许可管理规定》：八大类命名、双监护、作业票审批层级（数值与层级以厂内制度为准）。
- GB 30871-2022：规则库的依据，条款号按记忆整理，以正式文本为准（规则引擎声明行已注明）；标注"待核实 / 通行做法 / 不确定"的条款清单见 `references/rules-gb30871.md` 第 9 节。
- 转达环节不转述任何法规数值；数值只出现在规则原文里。

## 八、与 `overhaul-process-check-bridge` 的边界

| | 本技能 | overhaul-process-check-bridge |
|---|---|---|
| 对象 | 作业票（一处一票） | 检修方案的安全措施章节 |
| 规则依据 | GB 30871-2022 整理的作业票规则 | 检修方案安全措施检查表 |
| 输出 | 必须整改 / 建议完善 / 未判定 / 通过 | 缺失 / 建议完善 / 未判定 / 已有 |

两者都不做技术内容正确性审查；方案里"各专项措施以开工时逐票办理的作业票为准"，所以方案核查通过不等于作业票通过。

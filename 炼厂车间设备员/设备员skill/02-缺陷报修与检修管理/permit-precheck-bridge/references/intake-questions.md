# 车间侧前置信息清单与追问话术（作业票）

> 以下信息**不进入规则判定**，仅用于「车间侧补充提示（非规则判定）」一节。规则判定所需的票面信息由 `work-permit-precheck` 自行从作业票中抽取。

## 必须确认

| 信息 | 追问 | 用途 |
|---|---|---|
| 作业票文件 | 「票是作业许可系统导出的 Word，还是 PDF、照片？PDF 请先转成 Word 或文本再发我」 | 交给源技能解析 |
| 作业类型（八大类） | 「这张是用火票、受限空间票，还是高处、吊装、临时用电、动土、断路、盲板抽堵票？」 | 源技能按类型套用规则；一张票涉及多类时提醒各类作业应各自办票 |
| 设备位号 | 「作业在哪台设备上？位号是多少？」 | 关联车间侧信息 |
| 作业时间 | 「计划什么时候开始、干多久？」 | 交叉作业判断、气体分析时效（由源技能判） |

## 建议确认（影响补充提示的完整性）

| 信息 | 追问 | 可接技能 | notes.json 的 item |
|---|---|---|---|
| 设备是否已交出 | 「设备交出单签了吗？盲板、吹扫置换、停电挂牌做完没？」 | `equipment-handover-check` | 设备交出条件 |
| 同区域其他作业 | 「同一时段这个区域还有别的票吗？上下交叉有没有？」 | `cross-operation-conflict` | 同区域交叉作业 |
| 承包商资质 | 「施工队的入厂安全教育、安全协议、特种作业证复审核过了吗？」 | `contractor-qualification-check` | 承包商资质 |
| 其它车间自查项 | 「属地监护人到位了吗？脚手架验收牌挂了吗？」 | 车间自查 | 自定义 item |

把核实结果整理成 `notes.json`（格式见 `references/input-spec.md`），状态只写 **已核实 / 未核实 / 不适用**。

## 追问原则

1. **一次性列出所有缺项**，不要逐个追问。
2. 车间侧信息缺失**不阻塞**规则判定，源技能照常运行，只是补充提示会标注「未核实」。
3. **不要替用户回答**。「应该交出了吧」「一般都有监护人」这类推测不能写进 notes.json，也不能写进报告。
4. 作业级别（特级 / 一级 / 二级用火等）**不要替用户判**，以票面与审批人为准；票面级别与作业条件不符由源技能规则指出。

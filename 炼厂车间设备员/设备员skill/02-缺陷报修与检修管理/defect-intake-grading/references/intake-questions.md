# 缺陷登记信息清单与追问话术

## 必需字段

| 字段 | 为什么必需 | 缺失时的追问 |
|---|---|---|
| 位号（功能位置） | 缺陷必须挂到具体设备，也是 SAP 通知单的功能位置 | 「这个缺陷是哪台设备？位号（功能位置）是多少？」 |
| 缺陷描述 | 用于识别现象类型 | 「具体什么现象？漏、响、振动还是温度？」 |
| **是否影响运行** | **定级的必需要素，缺失即未判定** | 「现在影响装置运行吗？需要降量或停机吗？」 |
| 发现时间 | 用于计算处理时限与通知单要求开始/结束 | 「什么时候发现的？」（按北京时间记） |
| 发现人 | 追溯与复核 | 「谁发现的？」 |

## 条件必需字段

| 字段 | 什么情况下必需 | 追问 |
|---|---|---|
| **介质** | 泄漏类、变形开裂类缺陷 | 「这台设备走的什么介质？」 |
| 缺陷部位 | 便于后续检修定位，对应 SAP 通知单「对象部件」 | 「具体哪个部位？机封、轴承、法兰还是壳体？」 |
| SAP 设备编号 | 通知单草稿需要（可由设备台账补） | 「有没有 SAP 的设备编号？没有我按台账补」 |

## 追问原则

1. **一次性列出所有缺项**，不要挤牙膏式逐个追问。
2. **不得用假设值填补后直接给结论**。特别是「是否影响运行」，不能因为描述里写了「轻微」就认定不影响。
3. 抽取结果要**回读给用户确认**，不确定的字段标「待确认」。
4. 用户明确说「不知道」时，按未判定处理并说明补齐后可定级，**不要替用户猜**。

## 常见的口语化表述与结构化对应

| 用户可能这样说 | 结构化字段 |
|---|---|
| 「P-101 那个泵机封在滴油」 | 位号 P-101、部位 机械密封、现象 泄漏 |
| 「响得厉害」 | 现象 异响 |
| 「烫手」 | 现象 温升 |
| 「打不上量了」 | 现象 性能下降，且通常影响运行=是 |
| 「不影响生产，能扛到检修」 | 是否影响运行=否 |
| 「已经降量了」 | 是否影响运行=是 |

注意「能扛到检修」意味着不影响运行，但**仍须向用户确认**，不要直接判定。

等级口径：默认 A 级（重大）/ B 级（严重）/ C 级（一般）。用户说「一级/二级/三级」或「I 级」时，先确认是厂内哪套口径再映射，不要直接等同。

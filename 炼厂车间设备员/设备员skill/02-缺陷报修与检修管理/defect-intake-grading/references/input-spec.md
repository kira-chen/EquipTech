# 输入规格：缺陷登记与分级

## 两种模式

### 单条登记
```bash
node scripts/intake.js --desc "<缺陷描述>" --tag "<位号>" \
  --medium "<介质>" --affects-run <是|否> \
  --found-at "2026-09-21 08:20" --by "<发现人>" \
  [--grading-scheme abc|iv] [--due "A=1,B=3,C=7"] [--func-loc <功能位置>] [--equip-no <SAP设备编号>]
```
`--found-at` 接受北京时间写法（`2026-09-21 08:20`、`2026/9/21 8:20`）或 ISO 8601 带时区（`2026-09-21T08:20:00+08:00`，按原时区解析后显示北京时间）；无法解析时报错终止，不猜测。

### 批量登记
```bash
node scripts/intake.js --input "<缺陷记录xlsx 或 SAP 通知单导出>"
```

## 缺陷记录工作表（批量模式）

sheet 名匹配「缺陷记录」「缺陷」「记录」「通知单」。

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | SAP 功能位置；为空的行跳过并 warning |
| 缺陷描述 | 是 | 用于识别现象类型（SAP 通知单短文本可直接用） |
| 设备编号 | 否 | SAP 8 位设备流水号，**不是位号**，单独成列写入通知单草稿 |
| 设备名称 | 否 | 可由设备台账补全 |
| 缺陷部位 | 否 | SAP「对象部件」可直接用 |
| 介质 | 否 | 可由设备台账补全；泄漏类/变形类缺陷缺失时定级为未判定 |
| 是否影响运行 | 否 | **缺失时定级为未判定**，绝不默认；SAP「故障停机」列可直接用 |
| 发现时间 | 否 | 缺失时不计算处理期限日期与通知单要求开始/结束 |
| 发现人 | 否 | |
| 通知单号 / 缺陷编号 | 否 | 原记录编号原样带到 `sourceNo`：有通知单号列取通知单号（`sourceNoKind=notification`，SAP 系统已存在，md 注明勿重复创建），否则取缺陷编号列（`sourceNoKind=defect`）；车间登记号仍按「登记号规则」另编 |
| 缺陷等级 | 否 | 原记录（系统）等级原文带到 `sourceLevel`，**不参与定级**；能识别（A/B/C、重大/严重/一般、旧 I~IV 换算）时与脚本定级比对，写 `sourceLevelDiffers`，不一致的给 warning 并计入 `counts.sourceLevelDiffers` |

### 列名别名（局部别名优先，再并入共享 `SYSTEM_ALIASES`）

| 标准列名 | 可识别写法 |
|---|---|
| 位号 | 位号、设备位号、TAG、功能位置、功能位置编号、技术标识、技术对象、技术对象标识 |
| 设备编号 | 设备编号、设备、设备号、设备编码、技术对象编号、EM编码 |
| 设备名称 | 设备名称、名称、设备描述、技术对象描述、功能位置描述、描述 |
| 缺陷描述 | 缺陷描述、描述、现象、问题描述、缺陷现象、异常描述、通知单短文本、短文本、故障描述 |
| 缺陷部位 | 缺陷部位、部位、位置、对象部件 |
| 是否影响运行 | 是否影响运行、影响运行、影响生产、是否影响生产、故障停机、是否停机 |
| 介质 | 介质、物料、工艺介质 |
| 发现时间 | 发现时间、时间、发现日期、记录时间、通知日期、故障开始 |
| 发现人 | 发现人、记录人、上报人、巡检人、报告人、通知人 |
| 缺陷编号 | 缺陷编号、缺陷号、通知单号、通知单、维修通知单号、通知单编号（`--ledger` 查重用） |
| 原记录编号（批量） | 通知单号列：通知单号、维修通知单号、通知单编号；缺陷编号列：缺陷编号、缺陷号、缺陷登记号（不认单字「通知单」，免得命中「通知单类型」「通知单短文本」） |
| 原记录等级（批量） | 等级、缺陷等级、级别 |
| 状态 | 状态、处理状态、当前状态、系统状态、用户状态、通知单状态、工单状态 |

「缺陷描述」别名含「描述」，「设备名称」别名含「设备描述」：全等匹配先于前缀匹配，SAP 导出同时有「设备描述」与「通知单短文本」时不会互抢。局部别名已**不含「设备编号」作位号**，避免 SAP 流水号被当作功能位置。

## 设备台账（可选，`--equip-ledger`）

用于校验位号并补全设备名称、介质与 SAP 设备编号。sheet 名匹配「设备台账」「台账」「设备清单」「技术对象」。位号不在台账中时 warning，设备信息留空标「待补充」，**不凭设备名猜测介质**。

| 列名 | 必需 | SAP 技术对象导出常见写法 |
|---|---|---|
| 位号 | 是 | 功能位置 |
| 设备编号 | 否 | 设备 |
| 设备名称 | 否 | 设备描述 |
| 介质 | 否 | 介质 |

## 现有缺陷台账 / 通知单清单（可选，`--ledger`）

用于查重与登记号续接。sheet 名匹配「缺陷台账」「缺陷」「台账」「通知单」。

| 列名 | 说明 |
|---|---|
| 缺陷编号 / 通知单 | 用于避免新登记号冲突并在疑似重复中展示 |
| 位号 / 功能位置 | 只与同位号比对 |
| 缺陷描述 / 通知单短文本 | 用于相似度计算 |
| 状态 / 系统状态 | 按 `normSapStatus` 归一：NOCO、CLSD、已闭环、已消缺、已验收、关闭 → 已闭环不参与查重；OSNO、NOPR、处理中、"未关闭" → 参与查重；无法归一时按文本判断且否定前缀（未/待/不/非）先判，不默认闭环 |
| 发现时间 / 通知日期 | 展示用 |

## 是否影响运行的取值

| 解析结果 | 可识别写法 |
|---|---|
| 是 | 是、有、会、影响、Y、yes、true、1 |
| 否 | 否、无、不、不影响、N、no、false、0 |
| **未填（null）** | 空，或以上均不匹配 |

## 登记号规则

`<前缀>-<YYYYMMDD>-<三位序号>`，默认前缀 `QX`，可用 `--prefix` 指定，为车间内部缺陷登记号；与 `--ledger` 中已有编号自动避让。**SAP 通知单号由系统生成，脚本不编通知单号**，通知单草稿只给草稿序号。

## 产出

| 文件 | 内容 |
|---|---|
| `defects.json` | 逐条缺陷（含 `notification` 通知单建议；批量时含原记录 `sourceNo` / `sourceNoKind` / `sourceLevel` / `sourceLevelDiffers`，单条登记为 null）、等级、定级依据、未判定清单、疑似重复清单、counts（含 `sourceLevelDiffers`）、meta（分级方案、时限口径、声明行） |
| `defects.md` | 五节报告：登记概览、缺陷单、未判定清单、疑似重复清单、维修通知单草稿 |
| `ledger.csv` | 台账追加行（带 BOM），确认后可并入台账 |
| `notification.csv` | 维修通知单草稿（带 BOM）：草稿序号、功能位置、设备编号、通知单类型（M1/M2）、优先级（1~4）、故障代码、通知单短文本、长文本、要求开始、要求结束、报告人、缺陷登记号；未判定项不进入 |
| `summary.json` | 末行摘要落盘 |

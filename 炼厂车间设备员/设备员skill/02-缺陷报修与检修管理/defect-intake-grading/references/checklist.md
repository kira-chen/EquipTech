# 交付自检清单

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；为 `false` 时已告知用户 `error` 原文并终止，未手工定级
- [ ] `warnings` 已逐条告知用户
- [ ] `defects.json`、`defects.md`、`ledger.csv`、`notification.csv` 均已生成

## 字段抽取
- [ ] 抽取结果已回读给用户确认
- [ ] 不确定的字段标注了「待确认」，未猜测填充
- [ ] 缺失字段已一次性列出，未逐个追问
- [ ] 位号（功能位置）与 SAP 设备编号未混用

## 定级
- [ ] 每条缺陷的等级（A/B/C）、定级依据、命中规则号均来自 `defects.json`，未自行调整
- [ ] 未判定项单列，注明了缺失的具体字段，且未进入通知单草稿
- [ ] **未出现因缺字段而按最低或最高等级默认的情况**
- [ ] 介质不在危险特性库中的，判为未判定并提示核实 MSDS，未按低危处理；含硫污水/酸性水/含油污水按中危
- [ ] 已说明采用的分级方案（默认 A/B/C）与处理时限为经验默认、厂内规定为准

## 通知单草稿
- [ ] 通知单类型（M1/M2）、SAP 优先级（1~4）、要求开始/结束均引用 `defects.json`
- [ ] 已向用户说明通知单号由 SAP 生成、草稿只给序号，故障代码按厂内目录核对
- [ ] 未替用户填工时、备件与承修单位（由计划员/承修单位归口）

## 查重
- [ ] 疑似重复项已列出台账编号或通知单号、描述、时间、状态（含归一后六态）与相似度
- [ ] 未自动合并或自动剔除任何一条，均交用户确认
- [ ] 已说明相似度是文本匹配结果，不代表确为同一问题

## 交付说明
- [ ] 已说明登记条数、A/B/C 各等级分布、未判定条数、疑似重复条数、通知单草稿条数

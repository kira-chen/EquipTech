# 设备缺陷登记与分级（defect-intake-grading）

面向中石化体系炼化厂车间（运行部）设备员，把现场发现的口语化问题描述转成规范的结构化缺陷记录，按 **A 级（重大）/ B 级（严重）/ C 级（一般）** 三级定级，并生成可在 SAP PM 中创建维修通知单的草稿。**分级判定由脚本按规则表完成，模型只负责信息抽取与成文；不得自行提高或降低缺陷等级。**

## 适用条件
- 用户说"登记一个缺陷 / 这个问题记一下 / 帮我报缺陷 / 这算 A 级还是 B 级 / 帮我出通知单草稿"，并以文字描述（或巡检记录、SAP 通知单导出）反映设备问题。
- 支持批量：一次提交多条缺陷描述，或一份含多条记录的表格（含 SAP PM 通知单导出列名：功能位置、设备、设备描述、通知单短文本、对象部件、通知日期、报告人）。
- **车间设备员可做**：缺陷登记、分级建议、维修通知单草稿；**由 XX 归口**：维修工单（订单）创建与工时定额由计划员/承修单位负责，缺陷定性与闭环确认按厂内缺陷管理制度审核。
- 不适用：工单跟踪与催办；故障原因诊断；安全隐患（人的不安全行为、管理缺陷）的登记。

## 前提条件
- 输入：用户的缺陷描述文字（必需），或 `.xlsx`/`.csv` 缺陷记录表（批量时）。可选：设备台账（SAP 技术对象导出，用于校验位号、补设备编号与介质）、现有缺陷台账或通知单清单（用于查重）。
- 必填信息：位号（功能位置）或设备名称、缺陷现象、发现时间、发现人。缺项时按 `references/intake-questions.md` 一次性向用户列出需补充项。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工定级。**

## 操作步骤
1. **抽取结构化字段** —— 从用户描述中抽取：位号（功能位置）、设备名称、缺陷部位、现象类型（泄漏/异响/振动/温升/腐蚀/变形/失效/其他）、影响范围、是否影响运行、介质、发现时间、发现人。**抽取结果须回读给用户确认，不确定的字段标"待确认"，不得猜测填充。**
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/intake.js" --desc "<缺陷描述>" --tag "<位号>" --medium "<介质>" --affects-run <是|否> --found-at "<北京时间，如 2026-09-21 08:15>" --by "<发现人>" --out "<工作目录>/缺陷登记"
   ```
   批量时用 `--input "<xlsx路径>"` 替代 `--desc`。可选：`--ledger "<现有缺陷台账或通知单清单>"`（查重）、`--equip-ledger "<设备台账>"`（校验位号、补设备编号）、`--workshop "<车间名>"`、`--grading-scheme abc|iv`（默认 abc；`iv` 仅为兼容旧 I~IV 四级台账）、`--due "A=1,B=3,C=7"`（覆盖建议处理时限，天）、`--func-loc`/`--equip-no`（单条时写入通知单草稿）。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（位号不在台账/疑似重复缺陷/时间格式异常等）。脚本用法详见 `scripts/README.md`。
   - 定级所依赖字段（是否影响运行、介质危险性）为空时：等级输出 `undetermined`（未判定）并单列一节，说明还需补充哪个字段，**不得按最低等级或最高等级默认处理**；未判定项不进入通知单草稿。
   - 疑似与台账中未闭环缺陷/通知单重复：标记 `possibleDuplicate` 并列出相似记录，由用户确认是否新建，**不得自动合并或自动丢弃**。台账状态按 SAP 系统状态归一（OSNO/NOPR 未闭环，NOCO/CLSD 已闭环）。
3. **读取 defects.json** —— 从 `<输出目录>/defects.json` 获取：`defects`（逐条缺陷：登记号、结构化字段、等级、定级依据、建议处理时限、专业归口建议、`notification` 通知单建议）、`undetermined`、`possibleDuplicate`、`counts`、`meta.gradingScheme`。
4. **撰写缺陷单** —— 按 `assets/templates/defect-template.md` 成文，每条缺陷含：登记号、设备信息（功能位置、SAP 设备编号）、现象描述（规范化后）、影响判断、等级与定级依据、建议处理时限、建议责任专业、通知单建议（M1 维修申请/M2 故障报告，SAP 优先级 1~4）。**等级、时限与优先级一律引用 defects.json，定级依据须指明命中了规则表中的哪一条。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `defects.md`、`defects.json`、`ledger.csv`（台账追加行）与 `notification.csv`（维修通知单草稿，设备员核对后在 SAP 创建通知单，通知单号由系统生成）。需要跟踪后续工单时提示用户可接 `work-order-tracker` 技能。

## 预期结果
- `defects.md`：缺陷登记单，含 登记概览、缺陷单、未判定清单、疑似重复清单、维修通知单草稿 五个部分，开头带声明行。
- `defects.json`、`ledger.csv`（台账追加行）、`notification.csv`（SAP 通知单草稿列：功能位置、设备编号、通知单类型、优先级、故障代码、短文本、长文本、要求开始/结束）；`summary.json`：脚本末行摘要。
- 交付时向用户说明：登记条数、A/B/C 各等级分布、未判定条数、疑似重复条数、可生成通知单草稿条数、采用的分级方案与时限口径（经验默认，厂内规定为准）、脚本 warnings（如有）。

## 不适用范围
- 不做故障原因诊断与维修方案建议。
- 不创建维修工单（订单）、不定工时、不派工、不指定承修单位；通知单号由 SAP 生成，脚本只给草稿序号。
- 不登记安全隐患与违章行为，不做事故定性。
- 不替代厂内缺陷管理制度中的审核与确认环节；建议处理时限与通知单类型/优先级映射为经验默认，厂内可配置。

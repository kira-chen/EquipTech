# 交付自检清单

运行脚本后、交付前逐项核对。

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；若为 `false`，已把 `error` 原文告知用户并终止，未手工测算进度
- [ ] `warnings` 已逐条告知用户，未隐去任何一条（含"已开工"语义提示、三查四定关闭状态未判定、未启用 --linear-check 说明）
- [ ] `progress.json`、`progress.md`、`进度表.xlsx`、`summary.json` 均已生成
- [ ] 是否启用 `--linear-check` 已向用户确认，未替用户默认开启

## 数字一致性
- [ ] 报告中每个比例、天数、项目数都能在 `progress.json` 的 `counts` / `overall` / `lagging` / `tcfd` 中找到对应，未自行统计
- [ ] 总体完成比例已注明按工期加权，并给出加权样本占比（X / Y）
- [ ] 无可加权样本时总体比例显示「—」，未出现 0%
- [ ] 日历进度只作参照，未据此回填完成比例或判定滞后

## 状态口径
- [ ] 已完工 / 已中交 / 已开工三者分列，未把已中交或已开工写成已完工
- [ ] 台账用「已开工」表示"已开始施工"的，已提示用户改填「施工中」
- [ ] 状态非法或为空的项目已单列「状态未知项目」，**未就近映射**

## 完成比例（三条铁律）
- [ ] 完成比例为空的项目一律显示「—」，并给出按状态的定性进度；**未按 0 计，未线性推算，未用应有进度回填**
- [ ] 完成比例超出 0~100 的项目已 warning 并置空，**未截断**
- [ ] 状态与完成比例矛盾的项目已单列，**两字段均按原值保留，未修正任一字段**，未在分析段里替设备员取舍

## 滞后判定
- [ ] 每个滞后条目都标注了滞后类型与测算依据
- [ ] 未启用 `--linear-check` 时，报告已注明类型③未判定；启用时已注明应有进度为线性推算
- [ ] **滞后影响工期的表述均带「基于计划节点测算，最终以指挥部判定为准」**，未删改、未弱化
- [ ] 计划完工早于计划开工的项目已单列「计划节点异常」，计划节点原样保留未对调
- [ ] 工期缺失的项目已单列，未参与加权，未按默认工期补齐
- [ ] 取消项目如实列入项目总数，但未参与加权与滞后判定

## 关键路径
- [ ] 关键路径由用户通过 `--critical` 指定，**未自行判断**
- [ ] 关键路径滞后项已在报告中单独成节、置于滞后节最前、带【注意】与 ★ 标注（无 emoji）
- [ ] 未给出"总工期将延后 X 天"之类替指挥部下的结论

## 条件、材料与三查四定
- [ ] 开工条件缺口与材料缺口分别成表，未合并；为空或无法识别的条目标注「未判定」，**未按已具备 / 已到货处理**
- [ ] 三查四定问题单独一节：未关闭 / 超期 / 未判定 / 四定不全各自标注；**未把未判定写成已关闭**
- [ ] 中交前仍有未关闭或未判定三查四定问题的项目已点名，留项以指挥部确认为准
- [ ] 缺可选表时相应章节写「未提供 XX 数据」，总体表中显示「未提供」而非 0

## 日进度（有 --prev 时）
- [ ] 进度增量取自 `dayChange`，未自行相减；任一日未填报的项目增量显示「—」，**未按 0 增量**
- [ ] 本日到达中交 / 开工节点的项目已列出
- [ ] 本日零进度项目已列出；上一日有、本日缺失的项目已单列，**未按完工或取消处理**

## 分析段
- [ ] 已替换 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字
- [ ] 字数 250~400，六段结构齐全：总体进度（含中交 / 开工）、滞后项目与影响、资源与条件缺口、三查四定问题、本日完成情况、明日重点
- [ ] 未推测滞后原因，未判定工期能否按时完成，未给资源调配建议
- [ ] 未修正任何台账字段

## 进度表.xlsx
- [ ] 一张表即可上早晚会：首行标题含车间、大检修名称、统计日期；第二行为关键指标摘要（含已中交 / 已开工 / 三查四定未关闭）
- [ ] 表内固化了免责声明行与口径说明行
- [ ] 有三查四定问题时附有「三查四定问题」工作表

## 交付说明

- [ ] 已说明分析段需设备员复核

# scripts 使用说明

## turnaround.js —— 主脚本

```bash
node "<技能目录>/scripts/turnaround.js" \
  --input "<大检修项目清单xlsx路径>" \
  --workshop "<车间名>" \
  --project "<大检修名称>" \
  --date <YYYY-MM-DD> \
  --start <YYYY-MM-DD> \
  --end <YYYY-MM-DD> \
  --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 大检修项目清单 xlsx 路径，或同结构 CSV 目录；厂内表、指挥部导出、SAP PM 工单导出均可 |
| `--workshop` | 是 | 车间名称 |
| `--project` | 是 | 大检修名称，如「2026年装置大检修」 |
| `--date` | 是 | 统计日期 YYYY-MM-DD，滞后与应有进度均以此日为基准 |
| `--start` | 是 | 大检修计划开始日期 YYYY-MM-DD，用于日历进度参照 |
| `--end` | 是 | 大检修计划结束日期 YYYY-MM-DD；早于 `--start` 时报错 |
| `--out` | 否 | 输出目录，默认系统临时目录 `<os.tmpdir()>/ta-out`，**建议始终传 `--out`** |
| `--prev` | 否 | 上一日 `progress.json` 路径，传入后输出 `dayChange` 日进度对比（含本日到达中交 / 开工节点的项目） |
| `--critical` | 否 | 关键路径项目编号，逗号/顿号/分号/空格分隔，如 `"T-01,T-05"` |
| `--lag-days` | 否 | 滞后判定阈值（天），默认 1 |
| `--linear-check` | 否 | 开关。启用滞后类型③：完成比例落后按计划开工~计划完工线性推算的应有进度且折算天数 ≥ 阈值。**默认不启用**，只判①②，应有进度 / 偏差列显示「—」 |

### 产出

| 文件 | 内容 |
|---|---|
| `progress.json` | byProject、lagging、criticalLagging、notStarted、readyGap、materialGap、manpower、tcfd（三查四定）、overall、dayChange、inconsistent、unknownStatus、undetermined、planIssues、missingPlan、counts、meta（含 `linearCheck`、`statusEnum`、`tcfdProvided`） |
| `progress.md` | 九节报告 + 附，分析段留 `<!-- ANALYSIS_START/END -->` 占位，末尾通用声明行；提示用「【注意】」，不用 emoji |
| `进度表.xlsx` | 工作表「进度表」：标题行、指标摘要行（含已中交 / 已开工 / 三查四定未关闭）、免责声明行、逐项目明细与口径说明；有三查四定问题时另附工作表「三查四定问题」 |
| `summary.json` | 末行摘要落盘（Windows 控制台乱码兜底） |

### 判定口径要点

- **状态枚举（七态）**：未开工 / 施工中 / 已完工 / **已中交** / **已开工** / 已中止 / 取消。「已中交」= 中间交接（检修完工后交付工艺），「已开工」= 中交后装置/设备开工（开车投用），两者都是大检修独立节点，**不归到已完工**；`counts.done / handedOver / startedUp` 分列，`counts.finished` 为三者之和。出现「已开工」时 warning 提示其语义（若台账用它表示"已开始施工"应改填「施工中」）。取值不在枚举内（含空值）→ warning + 归入 `unknownStatus` 单列，**不做就近映射**。取消项如实计入总数但不参与加权与滞后判定。
- **完成比例三条铁律**：为空 → `null`（显示「—」）+ 按状态给定性进度，**绝不按 0，绝不按工期线性推算，绝不用应有进度回填**；超出 0~100 → warning + 置 `null`，**不截断**；与状态矛盾（未开工却有比例、已完工 / 已中交 / 已开工却不足 100、施工中却已 100）→ warning + `inconsistent` 单列，**两个字段均按原值保留**。
- **总体完成比例**：`Σ(工期 × 完成比例) ÷ Σ(工期)`，工期缺失 / 比例为空 / 矛盾 / 未知状态 / 取消一律排除并在 `overall.excluded*` 单列；无样本时为 `null`，不按 0。
- **日历进度**：仅作参照，不回填、不判滞后。
- **滞后判定**（按优先级取第一个命中）：① 已过计划完工日未完工；② 超计划开工日 ≥ `--lag-days` 未开工；③ **仅 `--linear-check` 启用时**：完成比例落后应有进度，折算天数 `(应有−实际)÷100×工期` ≥ 阈值。每条带 `basis` 与 `disclaimer`。
- **不做滞后判定的情形**（进 `undetermined`）：状态未知、状态-比例矛盾、计划完工早于计划开工、计划节点缺失；启用 `--linear-check` 时完成比例未填报的在办项也进未判定。
- **关键路径**：仅由 `--critical` 指定，脚本不自行判断；滞后的关键路径项单独成节置于最前，标【注意】与 ★。
- **条件与材料缺口**：`readyGap` 与 `materialGap` 分别单列；「是否具备」「到货状态」为空或无法识别 → `judged: null` 未判定，**绝不按已具备 / 已到货处理**。
- **三查四定问题**（可选表）：三查（查设计漏项、查未完工程、查工程质量）四定（定任务、定人员、定时间、定措施）。每条问题判：关闭状态（已关闭 / 未关闭 / **未判定**，否定前缀先判，无法识别不按已关闭）、四定是否齐全（缺整改措施 / 责任人 / 整改期限即不全）、是否超期（未关闭且期限早于统计日）。`byProject.tcfdOpen` 为该项目未关闭（含未判定）问题数；缺表时写「未提供三查四定问题数据」。
- **缺可选表**：warning + 对应章节写「未提供 XX 数据」，总体表显示「未提供」而非 0。
- **日进度**：增量 = 本日 − 上一日；任一日未填报 → `null`，不按 0；`nodeChanged` 单列本日到达中交 / 开工节点的项目；上一日有、本日缺的进 `dropped` 并 warning。
- **列名别名**经 `C.mergeAliases` 并入共享系统别名：功能位置 → 位号（SAP「设备」编号不当位号）、订单号 → 项目编号、订单描述 → 项目名称、基本开始 / 结束日期 → 计划开工 / 完工、实际开始 / 结束日期 → 实际开工 / 完工、主工作中心 → 承修单位、用户状态 → 状态。
- **免责声明**：`滞后天数与工期影响均基于计划节点测算，最终以指挥部判定为准。` 固化在 `meta / overall / lagging[]`，写入 md 头部、关键路径滞后节、滞后节末尾与 `进度表.xlsx` 第三行。**不得删改。**

### 退出码
- `0`：成功，末行输出 `{"ok":true,...}`
- `1`：失败，末行输出 `{"ok":false,"error":"...","warnings":[...]}`

## make-sample.js —— 样例生成

```bash
node scripts/make-sample.js --out examples [--seed <n>] [--date <YYYY-MM-DD>]
```

生成 5 份样例：主样例（21 项，覆盖七态、三查四定 6 项与各类边界）、仅项目清单变体、全部已完工 / 中交 / 开工变体、指挥部导出风格变体、SAP PM 工单导出风格变体。seed 只改变承修单位、人名与班组，不改变结论。

```bash
node scripts/selftest.js
```

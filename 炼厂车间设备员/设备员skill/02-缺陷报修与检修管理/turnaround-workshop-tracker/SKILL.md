# 大检修车间侧跟踪（turnaround-workshop-tracker）

面向中石化体系炼化厂**车间（运行部）设备员**，在装置大检修（停工检修）期间跟踪本车间所有检修项目的进度、资源到位、开工条件、三查四定问题与中交 / 开工节点，每日输出一张进度表。**进度计算、滞后判定与关键路径提示一律由脚本完成，模型只负责成文；不得目测进度或调整计划节点。**

## 适用条件
- 用户说"大修进度日报 / 大检修进度怎么样 / 项目到哪一步了 / 哪些项目滞后了 / 开工条件核对 / 三查四定问题关了几项"，并给出（或即将给出）大检修项目清单与进度数据。
- 适用于装置大检修、停工检修期间的车间侧管理，节点按中石化口径：开工前条件确认（设备交出、盲板、作业票）→ 施工 → **三查四定** → **中交（中间交接）** → 试压 / 试运 / 投料前条件确认 → **开工（开车）**。"已中交""已开工"是独立状态，不等于"已完工"。
- 车间设备员可做的部分：汇总本车间项目进度、暴露滞后与资源缺口、跟踪三查四定问题整改、整理早晚会一张表并上报。
- 由其他岗位归口的部分（技能只提示，不代做）：工期调整、资源平衡、关键路径认定与总工期判定由检修指挥部决策；三查四定问题的留项确认由指挥部批准；中交与开工由工艺、设备、安全、承修单位按程序确认签字。
- 不适用：日常维修工单的跟踪；设备日报；厂级大检修总体计划的编排与资源平衡；指挥部层面的进度决策与工期调整。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含工作表「项目清单」（项目编号、名称、位号、计划开完工、工期、承修单位、责任人、状态、完成比例），可选「材料到货」「人员到位」「开工条件」「三查四定」，字段见 `references/input-spec.md`。厂内表、指挥部导出（项目号 / 检修项目 / 形象进度 / 承包商）、SAP PM 工单导出（订单号 / 订单描述 / 功能位置 / 基本开始日期 / 基本结束日期 / 主工作中心 / 用户状态）均可直接读。
- 必填信息：车间名称、大检修名称、统计日期（YYYY-MM-DD）、大检修计划起止日期。可选：上一日 progress.json（用于日进度对比）、关键路径项目标识、`--linear-check`（是否按计划节点线性推算应有进度判滞后）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工计算进度。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 设备资产管理 | `get_turnaround_projects` | — | `--input` |
| 设备资产管理 | `get_material_arrivals` | — | `--input` |
| 设备资产管理 | `get_workforce_status` | — | `--input` |
| 设备资产管理 | `get_startup_conditions` | — | `--input` |
| 设备资产管理 | `get_punch_list` | — | `--input` |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；把目录作为“交给脚本”一列的参数值。
2. `get_turnaround_projects`：返回说明里给出项目名和计划窗口，对应 --project/--start/--end。
3. 车间范围：脚本只在输入带车间列时按 `--workshop` 核对（剔除其他车间的行；车间列全不一致时不筛并在报告开头提示）。以上五个工具按本次大检修取数，没有 `workshop` 参数，导出也不带车间列，报告口径写「输入未含车间列，车间范围以取数条件为准」；数据含其他车间的项目时，请用户提供带车间列的项目清单。

## 操作步骤
1. **确认大检修基本信息** —— 车间、大检修名称、统计日期、计划起止日期；不明确时向用户确认一次。检查项目清单是否含计划节点与完成比例，缺失时按 `references/input-spec.md` 提示补齐；问清是否要按计划节点线性推算应有进度（`--linear-check`），**不替用户默认开启**。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/turnaround.js" --input "<xlsx路径>" --workshop "<车间名>" --project "<大检修名称>" --date <YYYY-MM-DD> --start <YYYY-MM-DD> --end <YYYY-MM-DD> --out "<工作目录>/大检修跟踪"
   ```
   可选：`--prev "<上一日 progress.json>"`、`--critical "<关键路径项目编号,编号>"`、`--lag-days <滞后判定天数阈值>`、`--linear-check`（启用滞后类型③：完成比例落后按计划节点线性推算的应有进度；默认只判①已过计划完工日未完工、②超计划开工日未开工）。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺表 / 缺列 / 完成比例超出 0~100 / 计划完工早于开工 / 状态与比例矛盾 / "已开工"语义提示 / 三查四定关闭状态未判定等）。脚本用法详见 `scripts/README.md`。
   - 完成比例与状态矛盾（如状态"未开工"但比例 50%，"已中交"但比例 90%）：warning + 归入 `inconsistent` 单列一节，**不得自行修正任一字段**。
   - 完成比例为空：显示 —，按状态给出定性进度，**绝不按 0 或按工期线性推算填补**。
   - 三查四定问题关闭状态无法识别：标"未判定"，**不按已关闭默认**；四定（任务、人员、时间、措施）不全与超期未关闭单列。
3. **读取 progress.json** —— 从 `<输出目录>/progress.json` 获取：`byProject`（逐项目：计划与实际节点、完成比例、偏差天数、状态、三查四定未关闭数）、`lagging`（滞后项目，含滞后天数与是否在关键路径）、`notStarted`、`readyGap`、`materialGap`、`tcfd`（三查四定问题：items 与 counts）、`overall`（总体完成比例、按专业 / 按状态分布）、`dayChange`（有 --prev 时的日进度，含本日到达中交 / 开工节点的项目）、`inconsistent`、`counts`（含 `handedOver` 已中交、`startedUp` 已开工）。
4. **撰写"进度说明"** —— 读 `references/turnaround-rules.md` 的表述口径，撰写 250~400 字，按"总体进度（含中交 / 开工节点）→ 滞后项目与影响（关键路径优先）→ 资源与条件缺口 → 三查四定问题 → 本日完成情况 → 明日重点"结构，替换 `progress.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**比例、天数一律引用 progress.json；滞后影响工期的判断须注明"基于计划节点测算，最终以指挥部判定为准"。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `progress.md`、`progress.json` 与 `进度表.xlsx`（一张表可直接上早晚会；有三查四定问题时另附一个工作表）。

## 预期结果
- `progress.md`：大检修车间进度报告，九节 + 附：一、总体进度（含已完工 / 已中交 / 已开工分列、三查四定计数）；二、项目进度表；三、滞后项目（关键路径单独成节）；四、超计划开工日未开工；五、开工条件与材料缺口（含人员到位）；六、三查四定问题；七、数据矛盾与未判定项；八、本日进度变化；九、进度说明（分析段占位）；附：数据提示（有 warning 时）。末尾固定通用声明行。
- `进度表.xlsx`：可直接用于早晚会的一张表（工作表「进度表」；有三查四定问题时另附「三查四定问题」工作表）；`progress.json`；`summary.json`。
- 交付时向用户说明：统计日期、总体完成比例（含加权样本占比）、已中交 / 已开工项目数、滞后项目数（关键路径单独说明）、缺口项数、三查四定未关闭与未判定数、是否启用线性核对、脚本 warnings（如有）。

## 不适用范围
- 不调整计划节点与工期，不做资源重新分配。
- 不判定工期能否按时完成，不认定关键路径（由 `--critical` 指定），不替代指挥部决策。
- 不做费用与工程量统计，不做承修单位结算。
- 不替代作业票、交出单、中交 / 开工确认等现场程序。

# 输入规格：重复故障识别

## 支持格式
- `.xlsx`（推荐）或同结构 CSV 目录（文件名 = sheet 名，UTF-8 或 GBK）
- **多文件**：`--input "装置一.xlsx,装置二.xlsx"`，逗号（或分号）分隔，按装置分文件时直接一起传；记录合并后统一判定，出处带文件名。任一文件不存在报错；某文件没有故障表则跳过并 warning，全部文件都没有才报错

## 故障记录工作表

sheet 名匹配规则：去空白与「表」字后做包含匹配，以下写法均可识别：
「工单台账」「故障记录」「维修记录」「通知单」「订单」「故障记录表」「工单」。

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | SAP 功能位置；为空的行跳过并 warning |
| 故障时间 | 是 | SAP 通知日期 / 创建日期；无法解析的行跳过并 warning，**不按当日默认** |
| 故障现象 | 否（强烈建议） | SAP 通知单短文本；无代码且为空或只写「故障」「坏了」时该行列入 `uninformative`，**不参与任何重复判定** |
| 故障代码 | 否（有则优先） | SAP **损坏代码**；两条记录都有代码时按代码归类，不看文本；有代码的记录不因文本笼统被排除 |
| 原因代码 | 否 | SAP 原因代码，仅展示，不参与归类（原因由专项分析确认） |
| 故障部位 | 否 | SAP **对象部件**；同部位判定（规则 D1）的依据；为空时该行不参与同部位判定 |
| 设备编号 | 否 | SAP「设备」8 位流水号，**不是位号**，仅展示 |
| 设备名称 | 否 | SAP 设备描述；可由设备台账补全 |
| 型号 | 否 | 同型号共性故障（规则 D3）的归类键；可由设备台账补全 |
| 设备类型 | 否 | 型号为空时作为归类键的兜底 |
| 处理方式 | 否 | 仅展示，不参与判定 |
| 工单号 / 通知单号 | 否 | 仅展示，便于回查原单 |
| 区域 / 专业 | 否 | 仅展示 |

## 故障时间字段
- 支持：`2026-09-21`、`2026/9/21`、`2026年9月21日`、`20260921`、Excel 日期单元格、Excel 日期序列号
- **故障时间不在 `--from` ~ `--to` 区间内的行会被跳过并计入 `counts.outOfRange`**
- `--to` 默认当日，`--from` 默认 `--to` 往前 12 个自然月的次日（「一年内」），默认时 warning 说明并在报告抬头注明
- 无法解析的时间（如「不详」「待查」）→ warning，该行不参与统计，**不按区间端点或当日填补**

## SAP 损坏/故障代码优先（关键）

中石化炼化厂 SAP PM 通知单的损坏代码（目录代码）比文本相似度更可靠：

| 情形 | 处理 |
|---|---|
| 两条记录都有代码 | 代码相同 → 归同一相似组（相似度 1），matchBasis 写「SAP 损坏/故障代码同为「X」（代码优先于文本相似）」；代码不同 → 不归组（相似度 0），**不靠文本硬凑** |
| 仅一方有代码 | 退回文本与部位比对，matchBasis 写明「仅一方有 SAP 损坏/故障代码」 |
| 带代码但短文本为空或只写「故障」 | 视为有信息量，正常参与判定 |
| 部分记录带代码、部分不带 | warning 提示两类记录之间只能按文本比对 |

## 故障现象的信息量要求（无代码时）

重复故障判定的可信度完全取决于故障现象填写质量。无 SAP 代码时，脚本对以下写法判为**无信息量**，列入 `uninformative` 单列一节，**绝不据此判定为任何一类重复故障**：

| 判定 | 举例 |
|---|---|
| 空 | 空单元格、纯空白 |
| 仅泛指故障词 | 故障、坏了、有问题、异常、损坏、不好用、待查、不详、无、/、— |
| 泛指主语 + 泛指故障词 | 设备故障、机器坏了、机组异常、装置有问题 |
| 过短且无现象词 | 少于 4 字且未匹配到任何现象类型的描述 |

**反例（有信息量，正常参与判定）**：「机封故障」（含具体部位）、「振动高」（含现象词）、「管束内漏」「轴承温度偏高」。

无信息量的记录会在 warning 中具体到文件与行号，供设备员回去补填。**补填现象或在 SAP 维护损坏代码后重新运行才能得到可用的重复故障结论。**

## 设备台账（可选，`--ledger`）

用于补全设备编号、型号与设备类型，从而支撑同型号共性故障判定。支持 SAP 技术对象导出列名（功能位置、设备、设备描述、型号编号、对象类型）。不提供时脚本只用记录表自带的「型号」列归类，并 warning 提示。

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | 功能位置 |
| 设备编号 | 否 | SAP「设备」 |
| 型号 | 否 | 记录表型号为空时用它补全 |
| 设备类型 | 否 | 型号仍为空时作为归类键 |
| 设备名称 / 区域 / 专业 | 否 | 补全展示信息 |

位号不在台账中时 warning，型号与设备类型留空，**不按设备名猜测型号**。

## 会被跳过的行
- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 提示）
- 位号为空的行（warning 提示）
- 故障时间无法解析的行（warning 提示）
- 故障时间不在统计区间内的行（计入 `counts.outOfRange` 并 warning）

| 文件 | 内容 |
|---|---|
| `repeats.json` | `byEquipment`、`byModel`、`topFrequency`、`shorteningInterval`、`uninformative`、`counts`、`meta`（含 `fileStats`）、`warnings` |
| `repeats.md` | 七节报告，开头两行声明，分析段留 `<!-- ANALYSIS_START/END -->` 占位 |

## 与其他技能的数据衔接

- 备件消耗异常的设备往往就是重复故障设备。`05-备品备件与物资/spare-parts-consumption-analysis` 的消耗排行与本技能的 `topFrequency` 可互相印证：同一台设备既在故障频次前列、又在备件消耗前列，是优先安排专项分析的强线索。
- 本技能的输入（SAP 通知单/订单导出）与 `work-order-tracker`、`maintenance-record-archive` 的输入同源，可直接复用导出表。

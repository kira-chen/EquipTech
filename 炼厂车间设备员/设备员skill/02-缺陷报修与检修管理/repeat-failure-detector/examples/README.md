# examples 回归测试数据

> 本目录仅开发包含有（`build.sh --with-examples`），发布包不含。
> 全部样例由 `node scripts/make-sample.js --out examples` 再生，数值随 seed 变化但结论不变。
> 样例时间相对 `--to`（默认 2026-09-21）生成，跑脚本时 `--to` 须用 2026-09-21（`--from` 可省略，默认往前 12 个自然月 = 2025-09-22）。

## 关键验证点

1. **无信息描述绝不据此判定（最重要）**：`sample-vague-desc.xlsx` 中 P-2101 在一年内出现 4 条记录，现象分别是「故障」「坏了」「设备故障」「有问题」且无损坏代码。看上去像典型的重复故障，但脚本把 4 条全部列入 `uninformative`，`repeatEquipment`、`modelGroups`、`shortening` **全为 0**，第六节单列并注明需补填。
2. **SAP 损坏代码优先**：`sample-sap-notifications.xlsx` 中 P-2201A 三条短文本写法各异（「机封滴漏」「密封端面渗出」「故障」），文本相似度很低，但损坏代码同为 LEAK01，按代码归为一组；VIB02 与 LEAK01 代码不同，不混入同组。
3. **默认口径一年内 ≥2 次**：不传 `--min-count` 时同部位 2 次即命中 D1（主样例 E-1201 管束 2 次），`--min-count 3` 可按厂内口径抬高。
4. **多文件合并**：主样例与 unit2 分文件一起传，E-1203 的 1 条管束内漏并入 BES800-2.5 共性组，变成 3 台 4 次；E-1203 自身只有 1 次，不进同设备重复清单。
5. **matchBasis 写明依据**：主样例 P-1101A 的 D2 命中会输出「现象文本 bigram 相似度 0.59」「故障部位同为「机械密封」」「现象类型同为「泄漏」」，md 第二节逐条呈现，便于设备员自行判断是否真属同类。
6. **部位归一不是逐字比对**：P-1101A 四条记录的部位分别写「机械密封」「机封」「机械密封」「填料密封」，归一后同为「机械密封」；SAP「对象部件」列同样按此归一。
7. **间隔缩短只认单调递减**：P-1101A 间隔 90→60→30 判为缩短（缩短 66.7%）；P-1102B 间隔 50→190 先缩后扩，**不判为缩短**。
8. **区间注明与越界提示**：报告抬头始终写明实际区间与天数，默认起始日时注明「起始日按默认「一年内」口径推算」；区间短于 180 天或长于 365 天时 warning 分别提示。
9. **单次故障不出 0**：只有 1 次故障的设备（V-1301、M-1501、K-2301）平均间隔为 `null`，报表显示「—」，不显示 0。
10. **SAP 列名不混**：「设备」列作 SAP 设备编号，「功能位置」作位号，「对象部件」作故障部位，「原因代码」只展示不参与归类，裸「编号」列不当工单号。

## 再生样例

```bash
node scripts/make-sample.js --out examples            # 默认 seed=1
node scripts/make-sample.js --out examples --seed 7   # 滴漏滴数与处理方式变化，上述结论不变
```

## 与备件消耗数据互相印证

若同时有 `05-备品备件与物资/spare-parts-consumption-analysis` 的消耗统计，可把本技能的 `topFrequency` 与消耗排行对照：同一台设备既在故障频次前列、又在备件消耗前列，是优先安排根因分析的强线索。

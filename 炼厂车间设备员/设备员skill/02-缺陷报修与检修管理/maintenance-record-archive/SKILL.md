# 检修记录归档（maintenance-record-archive）

面向中石化体系炼化厂**车间（运行部）设备员**，把一次检修产生的全过程材料整理成规范档案条目，核对资料完整性，并按 EM 设备管理信息系统的检修记录列头给出设备台账（一机一档）履历更新建议。**资料完整性判定由脚本按规范清单完成，模型只负责整理与成文；不得声称缺失的资料"可以免于归档"。**

## 适用条件
- 用户说"检修资料归档 / 这次检修的资料整理一下 / 归档还缺什么 / 检修履历要更新"，并提供检修过程材料或材料清单。
- 检修分级按中石化口径：**装置大检修 / 日常维修 / 抢修 / 专项（技改技措）**；旧称大修 / 中修 / 小修可用，脚本自动映射并 warning。
- 覆盖材料类型：检修方案、作业许可（作业票，含用火、受限空间等八大类）、设备交出单、检修记录卡、质量验收记录（H/W 点见证）、材质与更换部件质量证明、备件领用单、试压试车记录、无损检测报告、验收单、三查四定问题整改记录、中交记录、检修总结、照片。
- 车间设备员可做的部分：整理材料清单、按规范核对完整性、向承修单位与检验机构追索缺失原件、整理台账履历更新建议并上报。
- 由其他岗位归口的部分（技能只提示，不代做）：档案室负责实体归档、编号与保管期限；EM/台账的正式更新由台账维护岗按建议录入；特种设备检验报告由检验机构出具。
- 不适用：验收合格与否的判定；技术资料的检索查询；迎检材料包整理；档案室的实体归档与编号手续。

## 前提条件
- 输入：检修材料文件目录或材料清单（`.xlsx`/`.csv`，列：文件名、资料类型、位号、备注）。可选：设备台账（厂内台账或 SAP PM 技术对象导出：功能位置 / 设备 / 设备描述 / 对象类型）、承修单位、检修内容。
- 脚本只按**文件名**归类，不读文件内容；PDF/扫描件无需转换。若需核对文件内容（如方案里是否含质量控制点），用 completion-acceptance 或 technical-document-finder，**PDF 先用平台 pdf 技能转为 txt/docx 再传入，脚本不读 PDF；扫描件需 OCR**。
- 必填信息：设备位号（或 SAP 设备编号）、检修项目名称、检修分级、材料清单或目录；建议提供检修起止时间、承修单位、是否特种设备、涉及范围（焊接 / 无损 / 试压 / 试运 / 换承压件）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工判定归档完整性。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 设备资产管理 | `get_equipment_ledger` | `tag`：位号 | `--ledger` |
| 设备资产管理 | `get_work_orders` | `tag`：位号 | 填命令行参数（见下） |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；把目录作为“交给脚本”一列的参数值。
2. `get_equipment_ledger`：用于生成设备履历更新建议。台账「设备代码」不为空的是特种设备，加 `--special-equipment`；涉及范围（焊接、无损、试压、试运、换承压件）按设备员说明加 `--scope-*`，不按台账推断。
3. `get_work_orders`：找到本次检修的工单，读字段填命令行参数。选工单：用户给了工单号就用该工单；用户描述了检修内容（如「机封更换」）时，先按「订单描述」筛出与之相符的工单，再在其中取状态为 TECO 或 CLSD、实际结束日期最晚的一张；用户只说了位号时，取该位号状态为 TECO 或 CLSD、实际结束日期最晚的一张。读取字段：「实际开始日期」「实际结束日期」取前 10 位作 `--from`、`--to`，「工作中心」作 `--contractor`（外委承包商承修时以用户说的单位为准）；「工单类型」PM01 作 `--type 日常维修`，PM03 作 `--type 抢修`，PM02（计划检修）可能是周期性维护（日常维修）、装置大检修或专项，请用户确认后再传。按订单描述筛不出、没有 TECO/CLSD 的，或实际结束日期并列最晚的有多张时，请用户指定。这张表不作为文件传入。

检修方案、作业票、设备交出单、检修记录、验收单、现场照片等归档资料来自平台知识库或用户上传，放进一个目录作 `--materials`。作业票 Word 原件也可以用作业票系统的 `get_permits`（`tag`：位号）查到本次检修的许可证编号，再用 `get_permit_document`（`permit_no`：许可证编号）下载放进这个目录；原件以许可证编号命名（如 `YH-20261104-003.docx`），脚本按编号前缀认作作业票，不必改名。

## 操作步骤
1. **确认检修项目与材料范围** —— 位号、项目名称、检修分级、起止时间、承修单位、是否特种设备、涉及范围；材料以清单或目录形式提供。**材料清单不完整时先与用户确认是"确实没有"还是"尚未提供"，两者处理方式不同；范围开关不得默认全开或全关。**
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/archive.js" --tag "<位号>" --project "<项目名称>" --type <大检修|日常维修|抢修|专项> --from <YYYY-MM-DD> --to <YYYY-MM-DD> --materials "<材料清单xlsx或目录>" --out "<工作目录>/检修归档"
   ```
   可选：`--ledger "<设备台账xlsx>"`（厂内台账或 SAP PM 导出，生成履历更新建议）、`--contractor "<承修单位>"`、`--content "<检修内容>"`、`--special-equipment`、`--scope-material / --scope-weld / --scope-ndt / --scope-pressure / --scope-trial`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（材料命名无法识别 / 检修分级旧值映射 / 台账中无该位号 / 按设备编号命中等）。脚本用法详见 `scripts/README.md`。
   - 材料文件命名无法识别归属类型：归入 `unclassified` 单列一节由用户认领，**不得按文件名猜测强行归类**。
   - 必备资料（方案、作业票、检修记录卡、验收单；大检修另含检修总结；特种设备另含检验报告、承压件材质证明、焊工资质与焊接记录、无损检测报告、耐压试验记录）缺失：标为 `mandatoryMissing` 并在开头【注意】提示"不满足归档要求"。
3. **读取 archive.json** —— 从 `<输出目录>/archive.json` 获取：`archived`（已归档条目：类型、文件名、对应规范要求项）、`missing`（缺失资料）、`mandatoryMissing`（必备缺失，与 `missing` 中 `mandatory:true` 的项一致）、`unclassified`、`ledgerUpdate`（台账履历更新建议，EM 检修记录字段：功能位置、设备编号、设备描述、检修类型、检修项目、检修内容、实际开始/结束日期、承修单位）、`counts`。
4. **生成归档清单与台账更新** —— 脚本已按 `assets/templates/archive-template.md` 结构写出 `archive.md` 与 `ledger-update.csv`；模型只补充交付说明（已归档 / 缺失 / 必备缺失 / 待认领数量、追索建议）。**台账更新内容须由用户确认后再录入 EM/台账，模型不得直接改写用户的台账文件。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `archive.md`、`archive.json` 与 `ledger-update.csv`。**存在必备资料缺失时，开头的"【注意】必备资料缺失 N 项，不满足归档要求"提示不得删除或弱化；不得建议用其他材料替代或事后补编。**

## 预期结果
- `archive.md`：归档清单，五节 + 附：一、项目概况（含检修分级、承修单位、涉及范围）；二、已归档资料；三、缺失资料（必备项加粗）；四、待认领材料；五、台账履历更新建议（EM 检修记录列头）；附：数据提示（有 warning 时）。末尾固定声明行。
- `archive.json`：`meta`（含 `type / typeRaw / typeMapped`）、`counts`、`required`、`archived`、`missing`、`mandatoryMissing`、`unclassified`、`ledgerUpdate`、`warnings`；`ledger-update.csv`（EM 列头，带 BOM，提供 `--ledger` 时生成）；`summary.json`：脚本末行摘要。
- 交付时向用户说明：已归档数量、缺失数量（必备缺失单独说明并给追索对象）、待认领数量、采用的检修分级与归档规范口径、脚本 warnings（如有）。

## 不适用范围
- 不判定检修质量与验收结论。
- 不替代档案室的实体归档、编号与保管期限管理。
- 不直接改写用户的设备台账或 EM 数据，只输出更新建议。
- 不补编缺失的检修记录与检测报告，不建议用其他材料替代。

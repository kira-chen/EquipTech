# 交付自检清单

运行脚本后、交付前逐项核对。

## 一、脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；为 `false` 时已把 `error` 原文告知用户并终止，**未凭记忆列交出条件**
- [ ] `warnings` 已逐条告知用户，未隐去任何一条
- [ ] `handover.json`、`handover.md`、`summary.json` 均已生成

## 二、信息采集
- [ ] 位号、设备类型、介质、检修内容、作业类型已逐项向用户确认
- [ ] **介质信息未缺失**；用户只说「油」「料」「气」时已追问具体名称
- [ ] 缺失字段一次性列出，未逐个追问
- [ ] 未用假设值填补（「应该不带压了」不当作「不带压」）
- [ ] 带压/高温由用户或工艺明确回答后以 `--pressured` / `--hot` 传入；**未把台账压力温度数值当作已确认**，推断值只作提示

## 三、介质口径
- [ ] 介质不在危险特性库时，交出单「取用口径」一栏写明**按最严（高危）口径生成，须核实 MSDS**
- [ ] **未出现把不在库介质按低危或无危险处理的情况**
- [ ] 混合介质按其中危险等级最高的一种判定（如含硫污水按含 H2S）

## 四、条目与未判定
- [ ] 每条交出条目的内容、依据、规则号均来自 `handover.json`，未自行增删改
- [ ] 未判定项单列在「四、未判定项」，注明缺失的具体依据字段
- [ ] **未出现因依据缺失而按「不需要」从清单中删除的条目**
- [ ] 关键条目（H3 盲板、Q3 置换分析、E1 断电挂牌）在「二、关键条目」一节单列且醒目

## 五、确认结果
- [ ] **「完成情况」栏全部留白或为现场填写的结果，模型未代填任何一项「已完成」**
- [ ] `handover.json` 中 `items[].confirmed` 为 `null`（未回填现场结果时）
- [ ] 回填 `--confirm` 时，确认结果来自现场确认人，不是根据用户口头描述推断的

## 六、交出条件提示
- [ ] 存在未完成或未判定项时，交出单开头有 **「【注意】尚不具备交出条件」** 醒目提示
- [ ] 未把 `ready: true` 表述为「可以开工」；已说明仍须四方签字

## 七、声明行与签字栏
- [ ] 声明行原文保留，未删除或改写：**「本清单为辅助核对工具，设备交出须由工艺、设备、安全人员现场确认并签字，签字前不得开始检修作业。」**
- [ ] 签字栏含工艺（操作）、设备（车间设备员）、安全、检修（承修单位）四方，每方的确认内容已列明
- [ ] 术语为中石化口径：「用火作业」不写「动火」，盲板条目提示「盲板抽堵作业许可」，监护写「双监护」

## 八、交付说明
- [ ] 已说明：条目总数、关键条目数、未判定数、未完成数、脚本 warnings
- [ ] 已说明采用的口径来源（默认口径需明确标注，厂内有规定时以厂内为准）
- [ ] 已把 `meta.permits`（用火作业 / 受限空间作业 / 盲板抽堵作业）告知用户，并提示办票预检用 `permit-precheck-bridge`
- [ ] 未做出「可以交出」「可以开工」这类判定

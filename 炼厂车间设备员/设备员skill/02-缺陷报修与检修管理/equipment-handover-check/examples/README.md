# examples 回归测试数据

> 本目录仅开发包含有，发布包不含。由 `node scripts/make-sample.js --out examples` 再生。
> 本技能以命令行参数驱动，样例文件用于验证台账补全与场景对照，主脚本不直接读取场景表。

## 关键验证点

1. **介质不在库按最严口径**：场景 3 的「再生剂RX-7」不在危险特性库，`mediumHazard` 为 `unknown` 而 `mediumEffective` 为 `high`，照样生成 H3 盲板、H4 双阀、Q3 取样分析、S4 气体报警，并 warning 提示核实 MSDS。**不按低危、不按无危险处理。**
2. **未判定不默认、不按数值推断**：场景 3、5 未说明是否带压、是否高温，P1 泄压与 P2 降温条目 `status` 为 `undetermined`、`required` 为 `null`（不是 `false`），单列在「四、未判定项」并注明缺哪个参数。场景 5 台账有 1.2 MPa / 40 ℃ 数值，脚本只写 `meta.pressureHint` / `meta.hotHint`（推断值，待确认），**不据此生成必做条目**。
3. **关键条目醒目**：H3 盲板、Q3 置换分析、E1 断电挂牌无论是否完成都进 `criticalItems` 并在「二、关键条目」单列。
4. **脚本不预填**：不带 `--confirm` 时全部条目 `confirmed` 为 `null`，md 中完成情况一栏为 `☐ 已完成　☐ 未完成`，脚本从不写「已完成」。
5. **【注意】提示两个方向**：存在未完成或未判定项时 md 开头必有「【注意】尚不具备交出条件」；现场确认结果全部为「是」且无未判定项时该句不出现。不用 emoji。
6. **声明行不可删**：「本清单为辅助核对工具……签字前不得开始检修作业。」在 md 开头与签字栏之后各出现一次，任何场景都保留。
7. **规则可追溯**：每条条目都带规则号（H1~H5、P1~P2、Q1~Q6、E1~E3、M1~M2、S1~S4），可对照 `references/handover-rules.md` 复核。
8. **中石化术语**：md 写「用火作业」不写「动火」；H3 提示「盲板抽堵作业许可」；Q5 写「双监护」；`meta.permits` 按作业许可八大类命名。
9. **SAP 列名**：场景 5 的「功能位置」归位号、「设备」（8 位流水号）归设备编号、「设备描述」归名称、「对象类型」归设备类型、「维护工厂」归车间；用 8 位设备编号作 `--tag` 也能命中台账行。

```bash
node scripts/make-sample.js --out examples            # seed=1
node scripts/make-sample.js --out examples --seed 9   # 温度压力与负责人变化，结论不变
```

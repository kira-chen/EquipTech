# 检修前设备交出确认（equipment-handover-check）

面向中石化体系炼化厂**车间（运行部）设备员**，在设备交出检修前逐项核对隔离、置换、断电等条件，生成设备交出单，供车间设备主任与工艺、安全人员现场确认使用。**本技能生成确认清单并记录确认结果，不替代工艺、安全部门的现场确认与签字；模型不得代替任何人勾选"已完成"。**

## 适用条件
- 用户说"设备要交出检修 / 交出条件核对 / 交出单 / 停电吹扫做了没 / 能不能交出"，并说明设备位号、介质与检修内容。
- 覆盖常见交出场景：机泵解体、容器塔器进人、管线用火、换热器抽芯、电气设备检修；设备台账可用厂内自编列名或 SAP PM 技术对象导出（功能位置 / 设备 / 设备描述 / 对象类型）。
- 车间设备员可做的部分：整理交出条件清单、核对盲板台账与挂牌记录、提示需办理的作业许可、汇总现场确认结果成交出单。
- 由其他岗位归口的部分（技能只提示，不代做）：停车与工艺隔离由工艺（操作）执行；取样分析由化验/安全出结论；断电挂牌上锁由电气专业执行；作业票审批签发由作业许可系统与审批人负责；交出确认签字由工艺、设备、安全、承修单位四方现场完成。
- 不适用：特殊作业票的合规预检（用 permit-precheck-bridge）；检修完工后的验收（用 completion-acceptance）；实际现场操作的执行与确认签字。

## 前提条件
- 输入：用户说明的设备位号、设备类型、介质、检修内容、是否进人、是否用火作业（必需）。可选：设备台账（厂内台账或 SAP 导出）、工艺流程说明、上次交出单。
- 必填信息：位号、设备类型、介质名称与危险特性、检修内容、作业类型（是否用火 / 进受限空间 / 高处 / 吊装）、**是否带压、是否高温（由用户或工艺确认，脚本不按压力温度数值推断）**。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得凭记忆列交出条件。**

## 操作步骤
1. **确认设备与作业信息** —— 按 `references/intake-questions.md` 核对：位号、设备类型、介质（含是否有毒、易燃、腐蚀、窒息性）、是否带压、是否高温、检修内容、作业类型、是否需要进人。**介质信息缺失时必须追问，不得按"一般介质"处理；带压/高温用户说不清时按未判定处理，不得替用户猜。**
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/handover.js" --tag "<位号>" --equip-type "<设备类型>" --medium "<介质>" --scope "<检修内容>" --pressured 是|否 --hot 是|否 --out "<工作目录>/设备交出"
   ```
   可选：`--entry` / `--no-entry`（是否进受限空间）、`--hotwork` / `--no-hotwork`（是否用火作业）、`--temp <操作温度>`、`--pressure <操作压力>`（二者只记录并形成"推断值，待确认"提示，**不进入判定**）、`--ledger "<设备台账xlsx>"`、`--workshop`、`--plan-date`、`--confirm <现场确认JSON>`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（介质不在危险特性库 / 设备类型不覆盖 / 推断值待确认 / 作业类型组合异常等）。脚本用法详见 `scripts/README.md`。
   - 介质不在危险特性库中：脚本按最严口径生成清单并 warning 提示核实 MSDS，**不得按无危险处理**。
   - 判定依据字段缺失（未给 `--pressured` / `--hot` / `--entry`）：对应条目标 `undetermined`（未判定）单列一节，**不得默认为"不需要"，也不得按压力温度数值推断为"需要"**。
3. **读取 handover.json 并逐项确认** —— 从 `<输出目录>/handover.json` 获取 `items`（交出条目：序号、规则号、条目内容、判定依据、是否必需、确认方式、责任岗位）、`undetermined`、`criticalItems`（关键条目：盲板加装、置换分析合格、断电挂牌上锁）、`meta.permits`（涉及的作业许可：用火作业 / 受限空间作业 / 盲板抽堵作业）、`counts`。**逐项向用户核对实际完成情况，由用户回答后填写确认结果；模型不得预填。**
4. **生成交出单** —— 按 `assets/templates/handover-template.md` 成文（占位符与 `handover.json` 键一致），含：设备与作业信息、关键条目、交出条件逐项确认表、未判定项、未完成项、签字栏（工艺（操作）、设备（车间设备员）、安全、检修（承修单位）四方）。**未完成项必须醒目列出并写明"未满足交出条件"。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `handover.md` 与 `handover.json`。**必须保留声明行："本清单为辅助核对工具，设备交出须由工艺、设备、安全人员现场确认并签字，签字前不得开始检修作业"，不得删除或改写。存在未完成或未判定项时，须在开头明确提示"【注意】尚不具备交出条件"。**

## 预期结果
- `handover.md`：设备交出单，六节 + 附：一、设备与作业信息（含涉及的作业许可）；二、关键条目；三、交出条件逐项确认；四、未判定项（含带压/高温推断值待确认提示）；五、未完成项；六、交出确认签字；附：数据提示（有 warning 时）。开头与签字栏之后各含一次固定声明行。
- `handover.json`：`meta`（设备信息、介质口径、`pressureHint`/`hotHint` 推断值、`permits`、声明行）、`ready`、`counts`、`criticalItems`、`items`、`undetermined`、`warnings`；`summary.json`：脚本末行摘要。
- 交付时向用户说明：条目总数、已确认数、未完成数、未判定数、关键条目状态、涉及的作业许可、脚本 warnings（如有）。

## 不适用范围
- 不做特殊作业票的合规预检与签发，不判定用火/高处/吊装级别（级别以作业票为准）。
- 不替代气体检测、置换分析的实际取样与化验结论。
- 不代替任何岗位确认与签字，不判定"可以开工"。
- 不做完工后的设备接收与验收。

# scripts 使用说明

## track.js —— 主脚本

```bash
node "<技能目录>/scripts/track.js" \
  --input "<工单台账 或 SAP 订单导出 xlsx>" \
  --workshop "<车间名>" \
  --date <YYYY-MM-DD> \
  --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 工单台账 xlsx 路径，或同结构 CSV 目录；支持 SAP PM 订单导出列名（订单/通知单/订单类型/功能位置/设备/系统状态/基本开始(结束)日期/实际结束日期/主工作中心） |
| `--workshop` | 是 | 车间名称；台账带车间列时按它核对车间范围 |
| `--date` | 是 | 统计截止日期 YYYY-MM-DD，超期/停滞均以此日为基准 |
| `--out` | 否 | 输出目录，默认系统临时目录 `<os.tmpdir()>/wot-out`，**建议始终传 `--out`** |
| `--from` | 否 | 统计起始日期 YYYY-MM-DD，仅用于筛选「区间内闭环工单」；晚于 `--date` 时报错 |
| `--sla` | 否 | 厂内时限口径 xlsx（工作表「时限口径」，列：时限类别、时限），覆盖脚本默认口径；旧版按优先级写的口径表也可读 |
| `--vendor` | 否 | 只统计承修单位/工作中心包含该字串的工单 |
| `--owner` | 否 | 只统计责任人包含该字串的工单 |
| `--stall-days` | 否 | 停滞判定阈值（天），默认 7 |
| `--due-soon` | 否 | 临期窗口（天），默认 2 |

### 产出

| 文件 | 内容 |
|---|---|
| `orders.json` | meta（含状态映射说明与声明行、`workshopScope`）、counts、byStatus、overdue、stalled、stallUndetermined、dueSoon、closed、metrics（byCategory / byPriority / byType）、unknownStatus、groups、warnings |
| `tracking.md` | 八节报告（状态分布、超期、停滞、临期、区间内闭环、指标统计、未知状态、执行情况说明），开头带声明行，分析段留 `<!-- ANALYSIS_START/END -->` 占位 |
| `催办清单.md` | 按「承修单位/工作中心 / 责任人」分组的超期与停滞工单，可直接转发 |
| `summary.json` | 末行摘要落盘 |

### 判定口径要点

- **状态映射**（`C.normSapStatus`）：CRTD/OSNO/已创建/未处理 → 待审核；REL/NOPR/已下达/处理中 → 已派工；PCNF/部分确认/在修/检修中 → 施工中；**TECO/CNF/技术完成/已完成/完工 → 待验收**；CLSD/NOCO/业务完成/已关闭/已验收 → 已闭环；DLFL/LKD/删除标记/作废 → 已取消。否定前缀（未/待/不/非）先判（"未验收"→待验收）。取值认不出（含空值）→ warning + 归入 `unknownStatus` 单列，**不做就近映射**，不参与任何计算。
- **优先级**：SAP 1 非常高 / 2 高 / 3 中 / 4 低；中文"紧急/高/中/低"与旧一~四级按此映射，报告同时显示数字与中文。
- **时限类别**：抢修 / 一般（日常维修） / 计划性（计划检修）。先按工单类型（订单类型 PM03→抢修、PM01→一般、PM02→计划性，或中文"抢修/日常维修/计划检修"），无类型时按优先级推定（1→抢修，2/3→一般，4→计划性），推算依据写入条目 `dueBasis`。PM0x 编码为常见口径，厂内可配置。
- **默认时限**：抢修 1 天（24 小时）、一般 7 天、计划性 30 天。**这是脚本内置参考值，非厂内正式口径**，报告中会打【注意】声明行；有厂内规定时用 `--sla` 覆盖。
- **超期**：未闭环且 `--date` > 要求完成时间。台账无要求完成时间时按「报修时间 + 时限类别时限」推算；无时限类别或无报修时间则不推算、不判超期。
- **停滞**：未闭环且最后一个有值节点时间距 `--date` ≥ `--stall-days`。节点时间全缺 → 计入 `stallUndetermined`，**绝不按当前时间补齐**。
- **临期**：未闭环且距要求完成时间 0~`--due-soon` 天。
- **时长指标**：闭环时长 = 报修时间 → 验收时间（无验收则取完工时间）。任一端缺失 → null（显示「—」），不计入平均值，**不按 0 也不按当前时间**。
- **完成率**：已闭环 ÷（全部已知状态工单 − 已取消）；"已完成/TECO"不进分子；分母为 0 时为 null。
- **超期原因**：取自台账「超期原因」列，未填写写「原因未记录」，**不推测**。
- **范围过滤**：`--vendor` / `--owner` 会同时收敛 `unknownStatus` 与各清单；`counts.duplicated` 是台账级数据质量计数，始终按全表统计，不随过滤收敛。

- **车间范围核对（D007）**：台账带车间列（表头为车间 / 所属车间 / 属地车间 / 运行部，或其后加「名称」）时，剔除其他车间的工单并 warning（先于 `--vendor`/`--owner` 过滤，`counts.duplicated` 也只按保留的行统计）；车间为空的行保留；没有一行是本车间时不筛，warning 与两份 md 开头写【注意】；无车间列或只有「维护工厂」「车间负责人」这类列时不筛，`tracking.md` 口径写「输入未含车间列，车间范围以取数条件为准」。`meta.workshopScope` 为数组（sheet、status `noColumn|checked|mismatch`、column、total、kept、dropped、droppedRows、blank）。

### 退出码
- `0`：成功，末行输出 `{"ok":true,...}`
- `1`：失败，末行输出 `{"ok":false,"error":"...","warnings":[...]}`

## make-sample.js —— 样例生成

```bash
node scripts/make-sample.js [--seed <n>] [--date <YYYY-MM-DD>]
```

生成 5 份样例：主样例（车间台账列名，覆盖六态与各类边界）、厂内时限口径表（按时限类别）、全部已闭环变体、MES 导出风格变体、**SAP PM 订单导出变体**（系统状态代码、订单类型 PM01/PM02/PM03、主工作中心）。
seed 只改变故障描述细节与人员姓氏，不改变结论：主样例恒为 3 张超期、3 张停滞、1 张未知状态、1 组重复工单号、1 张节点时间倒序、1 张要求完成时间缺失走推算；SAP 样例恒为 6 张、超期 2、停滞 1、闭环 1、取消 1、未知 0。

```bash
node scripts/selftest.js
```

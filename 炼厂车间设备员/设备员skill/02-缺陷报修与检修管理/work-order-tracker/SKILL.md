# 工单跟踪与催办（work-order-tracker）

面向中石化体系炼化厂车间（运行部）设备员，跟踪维修工单（SAP PM 订单）从报修到验收关闭的全流程状态，自动识别超期与停滞并生成催办清单。**状态判定、超期计算与完成率一律由脚本完成，模型只负责成文；不得手工统计或调整时限口径。**

## 适用条件
- 用户说"工单进展怎么样 / 哪些超期了 / 催办一下 / 工单完成率 / 还有多少没闭环"，并给出（或即将给出）工单台账或 SAP PM 订单导出。
- 覆盖全流程六态：待审核、已派工、施工中、待验收、已闭环、已取消；SAP 系统状态与常见中文写法按《中石化口径对照》第四节映射，**"已完成/完工/TECO"归待验收，不算闭环**。
- **车间设备员可做**：工单跟踪与催办、整理催办清单转发承修单位/工作中心、统计完成率供周报月报。**由 XX 归口**：工单创建与派工由计划员/承修单位负责；超期责任认定与承包商考核由公司设备管理部门（机动部/设备部）与安全环保部门按厂内流程定，本技能只陈述事实。
- 不适用：生成通知单草稿；隐患整改跟踪；大检修项目的进度与资源管理；周报月报成文。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含工作表「工单台账」或「订单」，字段见 `references/input-spec.md`。支持 SAP PM 订单导出列名（订单、通知单、订单类型、功能位置、设备、设备描述、系统状态、优先级 1~4、创建日期、基本开始/结束日期、实际结束日期、主工作中心）与车间自建台账列名。
- 必填信息：车间名称、统计截止日期（YYYY-MM-DD）。可选：统计起始日期、厂内时限口径表、指定承修单位/工作中心或责任人范围、停滞与临期阈值。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工统计工单状态。**

## 操作步骤
1. **确认统计范围与时限口径** —— 车间、起止日期、各时限类别的时限（默认 抢修 24 小时 / 一般（日常维修）7 天 / 计划性（计划检修）30 天，为脚本内置参考值；用户有厂内口径时用 `--sla` 传入并在产出中注明）。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/track.js" --input "<xlsx路径>" --workshop "<车间名>" --date <YYYY-MM-DD> --out "<工作目录>/工单跟踪"
   ```
   可选：`--from <起始日期>`、`--sla "<时限口径xlsx>"`、`--vendor "<承修单位/工作中心>"`、`--owner "<责任人>"`、`--stall-days <停滞天数阈值，默认 7>`、`--due-soon <临期窗口天数，默认 2>`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺表/缺列/状态取值非法/节点时间倒序/工单号重复等）。脚本用法详见 `scripts/README.md`。
   - 状态取值不在 SAP 系统状态与六态枚举内：warning + 归入 `unknownStatus` 单列一节，**不得强行映射到最接近的状态**。
   - 节点时间缺失导致无法算时长：对应指标输出 null（显示 —），**绝不按当前时间补齐**。
   - 时限类别由「工单类型（订单类型 PM01/PM02/PM03 或中文）」决定，无类型时按 SAP 优先级推定（1→抢修，2/3→一般，4→计划性）；两者皆无则不推算要求完成时间、不判超期。
3. **读取 orders.json** —— 从 `<输出目录>/orders.json` 获取：`byStatus`（各状态分布）、`overdue`（超期未完成，含超期天数、时限类别与责任方）、`stalled`（停滞）、`dueSoon`（临期）、`closed`（区间内闭环）、`metrics`（完成率、平均闭环时长、按时限类别达标率、按优先级分布）、`unknownStatus`、`counts`。
4. **撰写"工单执行情况说明"** —— 读 `references/tracking-rules.md` 的表述口径，撰写 200~400 字，按"总体情况 → 超期工单与原因分布 → 停滞工单 → 完成率与时长指标 → 催办重点"结构，替换 `tracking.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**所有数量、天数、比率一律引用 orders.json。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `tracking.md`、`orders.json` 与 `催办清单.md`（按承修单位/工作中心与责任人分组，可直接转发）。**超期原因若台账中未记录，须写"原因未记录"，不得推测原因。必须保留声明行"本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。"**

## 预期结果
- `tracking.md`：工单跟踪报告，含 状态分布、超期工单、停滞工单、临期工单、区间内闭环工单、指标统计、未知状态工单、工单执行情况说明 八个部分，开头带声明行。
- `催办清单.md`：按承修单位/工作中心与责任人分组的催办条目，可直接转发；`orders.json`；`summary.json`。
- 交付时向用户说明：统计区间、超期数量、停滞数量、完成率、采用的时限口径与状态映射、脚本 warnings（如有）。

## 不适用范围
- 不判定超期责任归属，不做考核与扣分。
- 不修改工单状态，不代为催办或发送通知。
- 不评价维修质量（检修验收用 completion-acceptance）。
- 默认时限与 PM01/PM02/PM03 类别映射为常见口径，厂内可配置。

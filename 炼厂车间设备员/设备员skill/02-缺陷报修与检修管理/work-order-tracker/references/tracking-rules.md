# 跟踪口径与表述规范

> 依据《中国石化设备管理规定》《炼化企业设备管理技术规定》中"维修通知—工单—完工验收—关闭"的流程口径整理，不转述具体数值；时限数值以厂内规定为准。

## 一、状态枚举与未知状态

工单状态只认六态：**待审核、已派工、施工中、待验收、已闭环、已取消**，由 SAP 系统状态映射（CRTD/OSNO→待审核，REL/NOPR→已派工，PCNF→施工中，TECO/CNF→待验收，CLSD/NOCO→已闭环，DLFL/LKD→已取消；中文同义词见 `input-spec.md`）。

**"已完成 / 完工 / 技术完成（TECO）" 归待验收，不是闭环。** 中石化流程是 完工 → 验收 → 关闭，只有业务完成（CLSD/NOCO）才计入已闭环与完成率分子。

台账状态取值不在枚举内（含空值）时：

1. warning 指明 sheet、行号、工单号与台账原文
2. 归入 `unknownStatus` 单列一节，保留台账原文
3. 不参与状态分布、超期、停滞、临期、完成率的任何计算

**禁止**：把「挂起」「暂停」「已上报」之类映射到最接近的状态；禁止按在办或按闭环默认；禁止从统计中悄悄剔除而不披露。

## 二、时限类别与时限口径

时限按**时限类别**而不是按优先级给：

| 时限类别 | 对应工单类型 | 无类型时按 SAP 优先级推定 | 默认时限 |
|---|---|---|---|
| 抢修 | PM03 / 抢修 | 1 非常高 | 24 小时（1 天） |
| 一般（日常维修） | PM01 / 日常维修 | 2 高、3 中 | 7 天 |
| 计划性（计划检修） | PM02 / 计划检修 | 4 低 | 30 天 |

默认时限为**脚本内置参考值，非厂内正式口径**；PM01/PM02/PM03 编码也是常见口径，厂内可配置。用 `--sla` 传入厂内口径表即可覆盖。产出中必须注明实际采用的是哪一套口径：用默认口径时报告头部会打【注意】声明行「默认时限口径……非厂内正式口径」，**该声明行必须保留，不得删改**。

类别来源（工单类型 / 按优先级推定）写入每条推算条目的 `dueBasis`。工单类型与优先级都没有时按「无时限类别」处理，不推算时限、不判超期、不参与达标率。

## 三、超期判定

**超期 = 未闭环（待审核/已派工/施工中/待验收）且 统计截止日期 > 要求完成时间。**

要求完成时间的取值顺序：

1. 台账「要求完成时间」（SAP 基本结束日期）有值 → 直接用，`dueBasis` 记「台账要求完成时间」
2. 台账缺失但有报修时间与时限类别 → 推算 `报修时间 + 类别时限`，`dueBasis` 记「推算：报修时间 X + 「类别」时限 N 天（类别来源：…；口径来源）」
3. 报修时间或时限类别任一缺失 → **不推算、不判超期**，也不按最宽松或最严格默认

超期天数 = 统计截止日期 − 要求完成时间（自然日）。

**禁止**：对无依据的工单强行判超期或强行判不超期；禁止用当前时间填补缺失的要求完成时间以外的任何节点。

## 四、停滞判定

**停滞 = 未闭环且最后一个有值节点时间距统计截止日期 ≥ 阈值（默认 7 天，`--stall-days` 可调）。**

节点顺序：报修时间 → 派工时间 → 开工时间 → 完工时间 → 验收时间。取**最后一个有值**的节点作为"上次动作时间"。

全部节点时间均缺失时 → 计入 `stallUndetermined` 单列，注明「全部节点时间缺失，无法计算停滞天数」。**绝不按当前时间或报表生成时间补齐。**

超期与停滞可以同时成立（例如已派工后 9 天无人动工且已过要求完成时间），此时两节都会列出同一张工单，催办清单中也会在同一责任方下分别出现，这是预期行为，不做去重。

## 五、临期判定

**临期 = 未闭环且 0 ≤ 要求完成时间 − 统计截止日期 ≤ 窗口（默认 2 天，`--due-soon` 可调）。** 已超期的不再列入临期。

## 六、时长指标

| 指标 | 算法 | 任一端缺失时 |
|---|---|---|
| 闭环时长 | 报修时间 → 验收时间（无验收则取完工时间） | null，显示「—」 |
| 响应时长 | 报修时间 → 派工时间 | null |
| 施工时长 | 开工时间 → 完工时间 | null |

**null 一律显示「—」，绝不按 0，绝不按当前时间补齐。** 平均值只用可计算的样本，并在报告中注明「X / Y」的样本占比与不可计算的张数。

## 七、完成率与达标率

- **完成率** = 已闭环 ÷（全部已知状态工单 − 已取消）。"已完成/TECO" 在待验收，不进分子。分母为 0 时输出 null（显示「—」），不输出 0%。
- **按时限类别达标率** = 该类别中「按期闭环」÷「可判定按期与否的已闭环工单」。缺要求完成时间（且无法推算）或缺闭环时间的，`onTime` 为 null，单独计入 `undetermined`，**既不算达标也不算超标**。
- 按 SAP 优先级另给分布表（工单数与超期在办数），不按优先级算达标率。
- 已取消工单不计入完成率分母，但仍在状态分布中如实列出。

## 八、催办清单分组

`催办清单.md` 按「承修单位/工作中心 / 责任人」组合分组，每组列出该责任方名下的超期工单与停滞工单，按超期+停滞总数降序排列，可直接转发给责任方。

- 承修单位与责任人均为空 → 归入「（未填写责任方）」一组，**不臆造责任方**
- **超期原因取自台账「超期原因」列；台账未记录时一律写「原因未记录」**，不得据故障描述、承修单位或常识推测原因
- 清单末尾固定附说明：原因来自台账、未作推测、请责任方核实后反馈计划完成时间；本清单由车间设备员转发，不替代厂内考核与催办流程

## 九、分析段表述规范

撰写 200~400 字，结构固定为五段：

1. **总体情况**：统计区间、工单总数、在办数、各状态分布（点明待验收中有几张是"已完成待关闭"）。
2. **超期工单与原因分布**：超期张数、集中在哪些时限类别与责任方；原因按台账记录归类，台账未记录的明确说「原因未记录」。
3. **停滞工单**：停滞张数、停在哪个节点、停了多久；节点时间全缺无法判定的单独提一句。
4. **完成率与时长指标**：完成率、平均闭环时长及可计算样本占比、按时限类别达标率；注明采用的是哪套时限口径。
5. **催办重点**：需优先催办的承修单位/工作中心与工单，以及台账需补录的字段（未知状态、缺节点时间、缺超期原因）。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 超期原因 | 「台账记录为备件未到」「原因未记录」 | 「估计是外委队伍人手不足」 |
| 责任归属 | 「该工单由外委-华东检修承修，已超期 6 天」 | 「外委队伍消极怠工，应予考核」 |
| 未知状态 | 「1 张工单状态填写为『挂起』，不在规定六态内，需回系统核实」 | 「1 张工单挂起中，按在办处理」 |
| 已完成 | 「3 张 TECO/已完成工单在待验收，未计入闭环」 | 「已完成 3 张，算闭环」 |
| 缺时长 | 「1 张已闭环工单因报修时间缺失，闭环时长显示『—』」 | 「按当前时间估算约 X 天」 |
| 数字 | 引用 orders.json 的 counts 与 metrics | 自行统计或估算 |

### 硬约束

- **不推测超期原因**。台账没写就是「原因未记录」。
- **不判定责任归属、不做考核建议**。只陈述哪张工单在谁名下超期多少天；承包商考核分档由安全环保部门归口。
- **不修改工单状态**，不代为催办或发送通知；产出的催办清单由设备员自行转发。
- **不评价维修质量**。检修验收走 `completion-acceptance`。
- **数字一律引用 orders.json**，不得自行统计。
- 声明行「本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。」必须保留。

## 十、下游衔接

- 缺陷要报修、出通知单草稿 → `work-order-generator`
- 工单完工需组织验收 → `completion-acceptance`
- 本期工单情况进设备周报/月报 → `equipment-weekly-monthly-report`（可直接读 orders.json 的 counts 与 metrics）
- 同一设备反复报修需做分析 → `repeat-failure-detector`
- 催办事项与待补录字段进个人待办 → `worklog-todo-manager`

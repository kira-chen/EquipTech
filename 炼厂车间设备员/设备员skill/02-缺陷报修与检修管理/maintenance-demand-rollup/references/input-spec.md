# 输入规格：检修需求汇总上报

## 调用

```bash
node scripts/rollup.js --input "<xlsx路径>[,<路径2>...]" \
  --workshop "<车间名>" --period <YYYY-MM> --out "<输出目录>"
```

可选：`--template <上报模板xlsx>`、`--spare <备件库存xlsx>`、`--window "<停机窗口说明>"`、`--include-cyclic`、`--due <YYYY-MM-DD>`。

多个输入文件用逗号分隔；每个文件可以只含四张来源表中的一张，也可以都有。也支持传同结构的 CSV 目录（文件名 = sheet 名，UTF-8 或 GBK）。

## 四类需求来源

脚本按工作表名识别来源，至少要命中一张，否则报错终止。

| 来源 | sheet 名匹配 | 纳入条件 |
|---|---|---|
| 未闭环缺陷 | 缺陷台账、缺陷记录、缺陷、**通知单**（SAP 通知单清单） | 状态为未闭环（见下） |
| 未闭环工单 | 工单台账、工单记录、工单、**订单**（SAP 订单清单） | 同上 |
| 周期性检修项 | 周期检修项、周期检修、预防检修、保养计划、维护计划 | **仅 `--include-cyclic` 时纳入** |
| 隐患整改项 | 隐患台账、隐患整改、隐患 | 状态为未整改且**有位号**（设备类隐患）；无位号的管理类隐患跳过并 warning |

未加 `--include-cyclic` 但文件里确有周期检修表时，脚本会 warning 提示「本次未纳入」，不会静默忽略。

### 车间列（可选，四类来源表通用）

车间范围核对（D007），每个文件的每张来源表各自核对；只认表头正好是「车间 / 所属车间 / 属地车间 / 运行部」（或其后加「名称」）的列；「维护工厂」等 SAP 工厂代码列、「属地单位 / 使用单位」和「车间负责人」「车间监护人」等人员列都不认。有本车间行时剔除其他车间的行并 warning（逐车间写行数），不进申报清单、未判定项与通知单↔工单配对；车间为空的行按本车间保留并 warning；没有一行是本车间时不筛，warning 与 md 开头写【注意】（多半是传错了文件）；无车间列不筛，md 口径写「输入未含车间列，车间范围以取数条件为准」。结果写 `meta.workshopScope`（每张表一项）。备件库存表（`--spare`）是查找表，不核对。

### 状态取值口径（SAP 系统状态优先，`C.normSapStatus`）

| 解析结果 | 可识别写法 | 处理 |
|---|---|---|
| 已闭环 / 已取消 | CLSD、NOCO、业务完成、已关闭、已验收、已消缺、已闭环、DLFL、作废、已销号 | 不纳入 |
| **待验收（已完工）** | TECO、CNF、技术完成、**已完成、完工**、待验收 | **本期不重复申报**，计入 `counts.skippedDone` 并 warning |
| 未闭环 | CRTD、OSNO、REL、NOPR、PCNF、未处理、处理中、待处理、已派工、施工中、挂账、新建、整改中、未整改 | 纳入 |
| **无法归类 / 为空** | 以上均不匹配 | **列入未判定项（`undetermined.kind = status`），不按未闭环纳入正式清单，也不按已闭环剔除** |

## 缺陷台账 / SAP 通知单字段

| 列名 | 必需 | SAP 通知单导出写法 | 说明 |
|---|---|---|---|
| 位号 | 是 | 功能位置 | 为空的行跳过并 warning |
| 缺陷编号 | **依据字段** | 通知单 | 缺失时该项移入「建议核实区」，不进正式清单 |
| 缺陷描述 | 否 | 通知单短文本 | 用于生成项目名称、申报理由与查重 |
| 设备名称 | 否 | 设备描述 | SAP「设备」列是设备编号，不作设备名称 |
| 等级 | 否 | 优先级（1~4） | 决定缓急：A 级/1→紧急、B 级/2→高、C 级/3→中、4→低；旧 I~IV 兼容；无法识别→未判定 |
| 状态 | 否 | 系统状态 | 见上文口径 |
| 发现时间 | 否 | 通知日期 | 写入申报理由 |
| 是否需停机 | 否 | — | **为空时记「未填写」，绝不默认为是或否** |
| 预计工期 | 否 | — | 按天记；带「小时/h」后缀（如「72小时」）的按 24 小时折为天（保留 2 位）并 warning；表头本身带小时单位（如「预计工期(h)」「工期（小时）」）时该列纯数字也按小时折天并 warning；带「天/日」后缀或纯数字按天；无法解析时记 null（显示「未填」），**绝不按 0** |
| 备件需求 / 备件型号 / 需求数量 | 否 | 物料描述 / 物料 | 用于备件到位核对与备件缺口 |
| 专业 | 否 | — | 缺失时按位号与设备名推断 |

| 列名 | 必需 | SAP 订单导出写法 | 说明 |
|---|---|---|---|
| 位号 | 是 | 功能位置 | |
| 工单号 | **依据字段** | 订单 | 缺失时移入建议核实区 |
| 工单内容 | 否 | 订单描述 | 项目名称与需求描述来源 |
| 工单类型 | 否 | 订单类型 | 决定检修类别：PM03/抢修→抢修、PM02/计划→计划检修、PM01/日常→日常维修（厂内可配置） |
| 状态 | 否 | 系统状态 | 见状态口径 |
| 计划完成 | 否 | 基本结束日期 | 作「计划结束」并写入申报理由；无法解析时 warning |
| 等级 | 否 | 优先级（1~4） | **工单无等级且无优先级 → 优先级未判定，不按「高」默认**；有对应通知单时沿用通知单缺陷等级 |
| 通知单号 | 否 | 通知单 | 工单由哪张通知单转出；与缺陷/通知单表的通知单号对上时（去掉前导零再比），该通知单按工单申报一次、不再单列，工单缺的备件、描述、专业沿用通知单；工单已完工待验收或已闭环时通知单本期不申报（见 rollup-rules.md 第一节） |
| 是否需停机 / 预计工期 / 备件需求 / 备件型号 / 需求数量 / 专业 | 否 | | 同缺陷台账 |

## 周期检修项字段

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | |
| 周期项编号 | **依据字段** | 缺失时移入建议核实区（SAP 维护计划编号可用） |
| 项目名称 | 否 | 直接作为项目名称 |
| 检修周期 | 否 | 支持「6个月」「1年」「180天」「每季」「半年」等写法，无法解析时 warning |
| 上次检修 | 否 | 与检修周期一起算出下次到期日「应于 X 前完成」，作「计划结束」并写入申报理由；也用于按申报周期筛到期（见下） |
| 是否需停机 / 预计工期 / 备件需求 / 备件型号 / 需求数量 / 专业 | 否 | 同上 |

**按申报周期筛到期**（加 `--include-cyclic` 时）：下次到期日 = 上次检修 + 检修周期，与 `--period` 月末比较（给了 `--due` 也按月末，不按截止日）：

| 下次到期日 | 处理 |
|---|---|
| 晚于月末 | 不进申报清单，单列「周期外周期项（本期不申报）」（`cyclicOutOfPeriod`，md 附节 + xlsx 单独一张表），计入 `counts.cyclicOutOfPeriod`，warning 写明剔除条数 |
| 在本月内 | 纳入，`dueStatus`「本期到期」 |
| 早于月初 | 照常纳入，`dueStatus`「已超期」，申报理由与备注标注已超期，计入 `counts.cyclicOverdue` |
| 算不出（缺上次检修或周期无法解析） | 照常纳入，`dueStatus`「到期日未知」，逐条 warning，计入 `counts.cyclicDueUnknown` |

表里另有「下次到期」类列时脚本不读，以上次检修 + 检修周期算出的为准。

**周期项优先级一律「未判定」**（不按「中」默认），按应完成日期排序，实际轻重缓急由公司设备管理部门结合停机窗口判断。

## 隐患台账字段（设备类隐患）

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | 无位号的（管理类、现场环境类）隐患不进检修需求，跳过并 warning |
| 隐患编号 | **依据字段** | 缺失时移入建议核实区 |
| 隐患描述 | 否 | 与整改措施一起作需求描述 |
| 隐患等级 | 否 | **重大隐患→紧急、一般隐患→中；「A/B/C 级」「公司级/厂级/车间级」多为管理层级写法，不直接映射 → 未判定并 warning** |
| 整改措施 | 否 | 作项目名称 |
| 整改期限 | 否 | 作「计划结束」并写入申报理由 |
| 状态 | 否 | 已销号/已整改不纳入；整改中/未整改纳入 |
| 责任人 | 否 | 写入申报理由与备注 |
| 是否需停机 / 预计工期 / 备件需求 / 备件型号 / 需求数量 / 专业 | 否 | 同上 |

隐患整改项检修类别记为「专项（隐患整改）」；整改进度跟踪用 `hazard-closure-tracker`，本技能只把需检修的隐患纳入申报。

## 备件库存表（可选，`--spare`，支持 SAP MM 列名）

sheet 名匹配「备件库存」「库存」「备件台账」「备件」「物料」。

| 列名 | 必需 | 说明 |
|---|---|---|
| 备件名称 | 是 | 物料描述；按名称兜底匹配 |
| 备件型号 | 否 | 物料编码；优先按型号/编码匹配。需求写了型号、库存表也有型号列时**只按型号查**，查不到即未核实，不借用同名其他规格的库存；库存表没有型号列时才按名称匹配（同名多行合计）并 warning 未核对型号；同一型号多个库位（库存地点）多行时合计 |
| 库存数量 | 否 | 非限制使用库存；无法解析时该项记「未核实」 |

到位判定口径：

| 情形 | 输出 |
|---|---|
| 来源表有备件列、该行为空 | 无备件需求 |
| **来源表没有备件列**（备件需求、备件型号都没有） | **未核实（来源表无备件列）**，`spareState=unknown`，计 `counts.spareNeedUnknown`，每张表一条 warning；不计入备件缺口 |
| **未提供 `--spare`** | **未核实**（绝不写「有库存」「已到位」） |
| 提供了表但型号/名称查不到 | **未核实** + warning |
| 提供了表但库存数量无法解析 | **未核实** + warning |
| **提供了表、有库存，但需求数量未填** | **未判定（库存 N，需求数量未填）**，列入未判定项，**不按 1 件比对** |
| 库存 ≥ 需求数量 | 到位（库存 N） |
| 库存 < 需求数量 | 不足（库存 N / 需 M） |

## 上报模板（可选，`--template`）

传厂内固定的月度检修计划申报表（xlsx），脚本读第一张匹配「检修需求表/需求表/上报表/检修计划/申报表」的工作表（没有则取第一张表），按前 10 行中非空单元格最多的一行作为表头，把模板列名映射到标准字段后按模板列序输出。

- 模板列名无法匹配标准字段 → 该列在输出中**留空**，并在 warning 与「上报模板列名核对」一节列出
- 模板缺少关键列（功能位置、检修项目名称、来源、依据编号）→ warning 提示相关信息仅在 `需求汇总.md` 中体现
- 匹配按「完全相等 → 长别名前缀 → 短别名前缀」三轮，确保「备件到位」不会被「主要备件材料」的别名「备件」抢走、「来源单号」不会被「来源」抢走

## 停机窗口（可选，`--window`）

自由文本，脚本从中提取「N 天」用于核对需停机项合计工期：

| 情形 | 结论 |
|---|---|
| 合计工期 > 窗口天数 | 标注「与停机窗口冲突」，需公司设备管理部门统筹 |
| 合计工期 ≤ 窗口天数 | 标注在窗口内 |
| 说明中提不出天数 | **不判定** + warning，绝不按不冲突处理 |
| 有需停机项未填预计工期 | **不判定** + warning，绝不按 0 天计入 |

## 会被跳过、单列或移出正式清单的行

| 情形 | 处理 |
|---|---|
| 整行为空 | 跳过 |
| 首列为「合计/小计/总计/共计」 | 跳过 + warning |
| 位号为空 | 跳过 + warning |
| 状态判定为已闭环/已取消/已销号 | 不纳入（正常过滤，不 warning） |
| 状态为待验收（已完成/完工/TECO） | 不纳入 + warning「本期不重复申报」 |
| **状态无法判断** | **列入未判定项**，不纳入正式清单 |
| **依据字段为空** | **移入 `noBasis` 建议核实区** + warning，不进正式清单 |

# 检修需求汇总上报（maintenance-demand-rollup）

面向中石化体系炼化厂车间（运行部）设备员，把散落在缺陷台账/SAP 通知单、未闭环工单、周期性检修项、隐患台账中的需求汇总成一份按"月度检修计划申报表"口径、可报公司设备管理部门（机动部/设备部）的检修需求申报稿。**去重提示、合并与优先级排序一律由脚本完成，模型只负责成文；不得自行增删需求项。**

## 适用条件
- 用户说"报下个月检修计划 / 检修需求汇总 / 月度检修计划申报 / 报给设备部的检修清单 / 申报检修项目"，并给出（或即将给出）缺陷台账、SAP 通知单/订单导出、周期检修项或隐患台账。
- 汇总口径包含四类来源：未闭环缺陷（通知单）、未闭环工单（订单）、周期性预防检修项、设备类隐患整改项。
- **车间设备员可做**：汇总申报需求、标注停工需求与备件到位、提出检修类别与缓急建议并报车间设备主任/公司设备管理部门。**由 XX 归口**：检修计划的审核批复、跨车间停工窗口统筹、工时与费用由公司设备管理部门（机动部/设备部）与计划员负责；本技能只出申报稿。
- 不适用：公司级跨车间检修计划编排与资源平衡；单个项目的技术方案编制；大检修执行期的进度跟踪。

## 前提条件
- 输入：一个或多个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），可含「缺陷台账/通知单」「工单台账/订单」「周期检修项」「隐患台账」，至少提供其中一张，字段见 `references/input-spec.md`。支持 SAP PM 通知单/订单导出列名（通知单、功能位置、设备、设备描述、通知单短文本、系统状态、订单、订单类型、基本结束日期、优先级 1~4）与 SAP MM 库存列名。
- 必填信息：车间名称、上报周期（如 2026-10 月度）。可选：上报截止日期、厂内上报模板、停机窗口信息、备件库存表（用于标注备件是否到位）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工汇总需求。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 设备资产管理 | `get_notifications` | `open_only=true`，`workshop`：车间 | `--input`（目录 A） |
| 设备资产管理 | `get_work_orders` | `open_only=true`，`workshop`：车间 | `--input`（目录 B） |
| 设备资产管理 | `get_maintenance_plans` | `workshop`：车间 | `--input`（目录 C），需同时加 `--include-cyclic` |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；表中目录字母相同的放同一个目录，不同字母分开放，把目录作为“交给脚本”一列的参数值。
2. 目录 A、B、C 用逗号拼接后作 `--input`。三个工具都要带 `workshop`，否则会把其他车间的需求汇总进本车间的申报稿：脚本只在输入带车间列时按 `--workshop` 核对（剔除其他车间的行；车间列全不一致时不筛并在报告开头提示），MCP 导出多数不带车间列，取数时仍必须带 `workshop`。用户没要求报周期性保养项时不取目录 C、不加 `--include-cyclic`。
3. 通知单表、工单表都没有备件列：脚本把这些需求的备件到位写「未核实（来源表无备件列）」（`counts.spareNeedUnknown`，不计入备件缺口），**交付时不得说成「不需要备件」**；需要核实时可用备件库存 MRO `get_reservations`（`workshop`：车间，只看个别需求时加 `tag`：位号）查工单预留的物料，核实结果交给用户补填，脚本不读预留表。
4. 工单表带「通知单号」列：已转工单的通知单由脚本按工单申报一次、不再单列（`counts.linkedNotif`），工单缺的备件、描述、专业沿用通知单；工单已完工待验收或已闭环的，通知单本期不申报；工期以小时计的由脚本折算为天。
5. 维护计划表是该车间的全部周期计划，不只本期到期的；脚本按下次到期日（上次执行 + 检修周期，周期天数口径与工具一致：3个月 90 天、6个月 180 天、1年 365 天，算出的日期与表中「下次到期时间」列相同）筛选：不晚于 `--period` 月末的纳入（已超期的照常纳入并标「已超期」），晚于月末的不进申报清单，单列「周期外周期项（本期不申报）」（`cyclicOutOfPeriod`、`counts.cyclicOutOfPeriod`）；下次到期日算不出的照常纳入并 warning。交付时转述脚本的筛选结果即可，不用再人工核对哪些不在本期。

## 操作步骤
1. **确认上报周期与格式** —— 车间、周期、上报模板（若厂内有固定的月度检修计划申报表，请用户提供，脚本按模板列名输出）；不明确时向用户确认一次。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/rollup.js" --input "<xlsx路径>[,<路径2>...]" --workshop "<车间名>" --period <YYYY-MM> --out "<工作目录>/检修需求"
   ```
   可选：`--template "<上报模板xlsx>"`、`--spare "<备件库存xlsx>"`、`--window "<停机窗口说明>"`、`--include-cyclic`（含周期性检修项）、`--due <YYYY-MM-DD>`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺表/缺列/状态无法判断/疑似重复/模板列名无法匹配/备件表缺对应型号等）。脚本用法详见 `scripts/README.md`。
   - 疑似重复的需求项：标记 `possibleDuplicate` 并列出待用户确认，**不得自动合并，也不得自动剔除**。
   - 未提供备件库存表时：备件到位情况写"未核实"，**不得默认填"有库存"**；需求数量未填时到位情况写"未判定"，**不按 1 件默认**；来源表没有备件列时写"未核实（来源表无备件列）"，**不得写"无备件需求"**。
   - 工单/周期项无等级、隐患等级为"A/B/C 级"（管理层级写法）：优先级 `undetermined`，**不按高/中默认**，排在清单末尾并在"未判定项"单列。
   - 加 `--include-cyclic` 时周期项按下次到期日对申报周期筛选：晚于 `--period` 月末的本期不申报，单列「周期外周期项（本期不申报）」（给了 `--due` 也按周期末筛）；早于月初的照常纳入并标「已超期」（`dueStatus`）；缺上次检修或周期无法解析、到期日算不出的照常纳入并 warning（`dueStatus` 为「到期日未知」）。**不得把周期外项写进本期申报清单，也不得把已超期项删掉。**
   - 状态无法判断是否闭环：不纳入正式清单，列入"未判定项"；"已完成/TECO"为待验收，本期不重复申报；工单已 TECO/CLSD 而对应通知单仍未闭环的，通知单也不申报。
3. **读取 demands.json** —— 从 `<输出目录>/demands.json` 获取：`demands`（逐条需求：序号、功能位置、检修项目名称、检修类别、来源、检修内容、是否停工、计划结束、工期、备件与到位情况、建议专业、优先级、申报理由、依据编号）、`possibleDuplicate`、`needShutdown`、`spareGap`、`undetermined`、`noBasis`、`cyclicOutOfPeriod`（周期外周期项，本期不申报）、`counts`。
4. **撰写汇总说明** —— 按 `assets/templates/rollup-template.md` 成文，含汇总说明段：本期需求总数与来源构成、需停机项与停机窗口衔接、备件缺口与到货跟催、与上期遗留项的衔接及需公司设备管理部门协调事项。**数量一律引用 demands.json；申报理由须引用来源记录中的原文要点，不得夸大紧急程度。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `需求汇总.md`、`demands.json` 与可直接提交的 `检修需求表.xlsx`（月度检修计划申报表列头，或按用户模板填充）。**保留声明行"本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。"与说明行"本清单为车间申报稿，最终计划以公司设备管理部门（机动部/设备部）批复为准"。**

## 预期结果
- `需求汇总.md`：月度检修计划申报稿，含 汇总概览、需求明细（含申报理由）、需停机项、备件缺口、疑似重复待确认、未判定项、建议核实区、（上报模板列名核对，仅提供模板时）、汇总说明 八～九个部分，加 `--include-cyclic` 时另有附节「周期外周期项（本期不申报）」，开头带声明行与说明行。
- `检修需求表.xlsx`：检修需求表（月度检修计划申报表列头）、需停机项、备件缺口、疑似重复待确认、未判定项、建议核实区 六张表（加 `--include-cyclic` 时另有「周期外周期项（本期不申报）」表）；`demands.json`；`summary.json`。
- 交付时向用户说明：需求总数与来源构成、检修类别分布、需停机项数、备件缺口数（区分不足/未核实/未判定）、备件需求未知项（来源表无备件列，`counts.spareNeedUnknown`）、疑似重复待确认项、未判定项（优先级/数量/状态/停工）、无依据项、周期项中已超期与下次到期日算不出的条数及周期外不申报的条数（`counts.cyclicOverdue` / `cyclicDueUnknown` / `cyclicOutOfPeriod`，仅加 `--include-cyclic` 时）、脚本 warnings（如有）。

## 不适用范围
- 不做跨车间的计划平衡与停机窗口排布。
- 不编制单个项目的技术方案、作业步骤与安全措施。
- 不做费用预算与承包商询价。
- 不替代公司设备管理部门（机动部/设备部）的计划审核与批复流程。
- 检修类别（大检修/日常维修/抢修/专项）与 PM01/PM02/PM03 映射为建议口径，厂内可配置。

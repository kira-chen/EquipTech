# 工作日志与待办管理 · 样例问题

> 附件均在 `演示case/08-知识与能力支持/worklog-todo-manager/`（**可再生数据**，`node scripts/make-sample.js --seed <n> [--date YYYY-MM-DD]` 重新生成，默认 seed=1、基准日 2026-09-21）。逾期天数等数值随 seed 在分桶内变化，但每题的预期结论——待办总数、逾期/今日/近期/无到期日台数、疑似重复组数——不变；预期计数见 `演示case/08-知识与能力支持/worklog-todo-manager/README.md` 对照表（不进发布包）。基准日期统一用 `--date 2026-09-21`。

1. 把工单、隐患、定检、校验、润滑、缺陷这几份产出和我自己记的待办汇总一下，我今天要干什么。　　**附件：** `sample-orders.json + sample-hazard.json + sample-inspection.json + sample-calibration.json + sample-lube.json + sample-defects.json + sample-todo-sheet.xlsx + sample-todo-text.txt`（预期 23 项：逾期 8、今日 2、近期 7、无到期日 6，疑似重复 3 组）
2. 只给了工单和隐患的产出，先汇集这两份。　　**附件：** `sample-orders.json + sample-hazard.json`（预期 7 项，不因缺其他来源报错，清单说明覆盖范围）
3. 昨天值班交接记录里没干完的事也排进来。　　**附件：** `sample-handover.json`（预期识别为工作交接，3 条纳入：期限已过 P1、近期 P2 并带「交接记录中已连续结转 2 次」、无期限进无到期日不代填）
4. 交接记录和工单、缺陷放一起看，有重的别给我合掉。　　**附件：** `sample-handover.json + sample-orders.json + sample-defects.json`（预期 P-1101B 疑似重复组列出供确认，原始条目一条不少）
5. 这张跟进表是从 SAP 导出来的，紧急程度写的是 1 到 4，还有几条写的 A 级和 II 级，能按统一口径排吗。　　**附件：** `sample-todo-sap-style.xlsx`（预期「1 非常高」与「A级」→ P1、「II级」→ P2 并 warning 旧口径、「3 中」→ P3；已关闭的不进；功能位置归位号、工单号归编号）
6. 昨天没干完的别丢了，接着往下排。　　**附件：** `sample-orders.json`，另附上一日运行本技能得到的 `todo.json`（加 `--prev`，先跑一遍即可；预期上一日未完成项全部结转、到期日不变、标「结转自 X 月 X 日」，逾期天数按新基准日重算）
7. 今天做完了 P-1102A 加油和晨会，一起记进日志。　　**附件：** 同题 1（加 `--done "完成 P-1102A 加油；参加晨会"`，预期日志「今日完成事项」2 条；不给 `--done` 则留空不推断）
8. 这个 JSON 是别的系统导的，能一起读吗。　　**附件：** `sample-unknown.json + sample-orders.json`（预期无法识别的 JSON 记 warning 并忽略，其余照常汇集，ok:true）
9. 只看未来 3 天的。　　**附件：** 同题 1（加 `--horizon 3`，预期近期项减少、超出的进「前瞻期外」，总数不变）
10. 停滞那张工单没写要求完成时间，你按一周给我排个到期日吧。　　**附件：** `sample-orders.json`（预期：WO-26082033 进无到期日一节，脚本不自行设定到期日，回答说明须由设备员在 EM/SAP PM 中确认期限）

## 平台接入业务系统 MCP 时

不上传附件。本技能不直接调 MCP：先按 7 个上游技能 SKILL.md「数据获取（MCP）」一节取数并运行（工单跟踪、隐患闭环、特种设备定检、阀门仪表校验、润滑管理、缺陷登记、值班交接），再把 7 份 JSON 交给本技能；演示数据每天按剧本刷新。上游技能有 `--date` 的与本技能用同一天，值班交接用当天的 `--time`，车间用常减压车间。

M1. 常减压车间今天我要干什么：工单、隐患、定检、校验、润滑、缺陷和早上值班交接没完成的事汇总一下，按轻重缓急排。　　**数据：** 先运行上游技能 work-order-tracker、hazard-closure-tracker、special-equipment-inspection-due、valve-instrument-calibration-ledger、lubrication-manager、defect-intake-grading、shift-handover-record（各自 MCP 取数）→ 7 份 JSON 逗号拼接作 `--input`，`--owner 赵三 --date <今天>`（预期：7 个来源全部识别；E-1201 在缺陷与交接两处出现，列疑似重复不合并；如有安全阀校验超期（多数日子是 PSV-1202）则列 P1；如有特种设备检验问题整改则纳入，整改超期 P1、未到期 P2；如有停滞工单或按运行小时判定的润滑项（如 C-3101B 曲轴箱）则进无到期日、不代填日期）
M2. E-1201 管束内漏这件事在我待办里出现了几处，是不是重复了。　　**数据：** 先运行上游技能（同 M1）→ 同 M1（预期：E-1201 疑似重复组含缺陷跟进与工作交接两条，均保留不合并，由设备员确认是否同一事项）
M3. 明天接着排，今天没干完的别丢。　　**数据：** 先运行上游技能（同 M1）→ 7 份 JSON 作 `--input`，加 `--prev <今天的 todo.json>`，`--date <明天>`（预期：今天的事项全部在列，结转数等于今天的总数，上游重跑出现的同一事项不重复列出；明天上游新出现的事项另计；上游没变的到期日不变、不自动延期，逾期天数 +1；如有上游到期日变了的，warning 提示在系统核实并列出原到期日）

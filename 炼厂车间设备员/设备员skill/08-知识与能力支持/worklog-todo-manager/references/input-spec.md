# 输入规格：工作日志与待办管理

## 支持格式

`--input` 可一次传入多个路径，用英文逗号分隔，三类混传：

| 类型 | 扩展名 | 说明 |
|---|---|---|
| 上游技能 JSON | `.json` | 由脚本按特征字段自动识别来源类型 |
| 待办表 | `.xlsx` 或同结构 CSV 目录 | 需含「待办」类工作表 |
| 纯文字待办 | `.txt` / `.md` | 每行一条 |

**无法识别的 JSON 不会中断运行**：脚本记一条 warning 并忽略该文件，其余来源照常汇集。只有当全部来源都无法识别、且无结转项时才报错退出。

## 一、上游技能 JSON 的待办对接口径

脚本按 JSON 里的特征字段自动判断来源，无需用户指明。

| 来源技能 | 产出文件 | 识别特征字段 | 取作待办的字段 |
|---|---|---|---|
| work-order-tracker | `orders.json` | `byStatus` + `stalled` | `overdue[]`（超期未闭环）、`stalled[]`（停滞）、`dueSoon[]`（临期） |
| hazard-closure-tracker | `hazard.json` | `majorHazards` 或 `unverified` | `overdue[]`（超期未整改）、`dueSoon[]`（临期）、`unverified[]`（已整改未验收，待销号） |
| special-equipment-inspection-due | `inspection.json` | `dateConflict`，或 `byCategory` + `prepMaterials` | `overdue[]`（定检超期）、`dueSoon[]`（定检临期）、`openIssues[]`（检验问题整改未闭环：`tag`、`issue`、`dueDate`、`status`、`owner`、`inLedger`；上游未传 `--issues` 时为 null，脚本 warning 说明本清单不含检验问题整改） |
| valve-instrument-calibration-ledger | `calibration.json` | `unresolvedFail` 或 `sendList` | `overdue[]`（超期未校）、`dueSoon[]`（临期）、`unresolvedFail[]`（不合格未整改） |
| lubrication-manager | `lube.json` | `oilAnalysis` 或 `consumption` | `overdue[]`（润滑逾期）、`dueSoon[]`（润滑临期）；责任人取 `owner` |
| defect-intake-grading | `defects.json` | `defects` + `counts.byLevel` | `defects[]` 全部条目，到期日取各条的 `dueDate`；等级按 A/B/C，旧 I~IV 映射并 warning；`notification`（通知单草稿对象：`typeCn` / `shortText`，无通知单号，号由 SAP 生成）写入说明，兼容旧结构的 `notificationNo` 字符串 |
| shift-handover-record | `handover.json` | **约定：`meta.skill === 'shift-handover-record'` 且 `pending` 为数组**；无 `meta.skill` 的旧版按「`pending` 数组 + `meta.handoverAt`/`meta.shift` + `focusItems`」推断并 warning | `pending[]`（交接未完成事项，含其自身结转项）：`tag`、`content`、`state`、`owner`、`due`/`dueText`、`originShift`、`carryTimes`、`sheet`/`row`；位号/责任人/期限的占位「待明确」（旧版「（待补）」）不当作位号、姓名或日期；`focusItems[]` 不作待办 |

### 各来源的到期日取值

| 来源 | 到期日字段 | 无值时 |
|---|---|---|
| 工单超期 / 临期 | `dueAt` | 归入无到期日 |
| 工单停滞 | 无（停滞工单本就没有有效的要求完成时间） | **恒归入无到期日**，原因写「停滞工单无要求完成时间」 |
| 隐患 | `deadline` | 归入无到期日 |
| 特种设备定检 | `nextDate` | 归入无到期日 |
| 特种设备检验问题整改 | `openIssues[].dueDate`（要求完成日期） | 归入无到期日，原因写「整改项未填要求完成日期，脚本未自行设定」 |
| 仪表校验超期 / 临期 | `nextDate` | 归入无到期日 |
| 校验不合格未整改 | 无 | **恒归入无到期日**，原因写「须另行确定整改期限」 |
| 润滑 | `dueDate` | 归入无到期日；按运行小时判定的项 `dueDate` 为 null，标题写「按运行小时判定，剩余 / 超 N 小时」（取 `remainHours` / `overdueHours`），原因写「润滑周期按运行小时判定，来源未给日历到期日，脚本未自行换算日期」 |
| 缺陷 | `dueDate`（由 defect-intake-grading 按等级算出） | 未定级或缺发现时间的缺陷无 `dueDate`，归入无到期日 |
| 交接未完成事项 | `due`（`dueText` 为「（待补）」「待定」等占位时不 warning） | 归入无到期日，原因写「交接记录未写明期限，脚本未自行设定」 |

**不论哪一类，到期日缺失时脚本一律不自行设定，也不按「发现日 + 默认天数」推算。**

### 本技能自身产出的 todo.json
传入 `--input` 会被忽略并 warning——结转请用 `--prev`。

## 二、待办表（xlsx / CSV 目录）

工作表名匹配：去空白与「表」字后做包含匹配，「待办」「待办清单」「工作待办」「跟进事项」「任务清单」均可识别。找不到这类表时记 warning 并忽略该文件。SAP/EM 导出的跟进清单（工作事项 / 要求完成日期 / 紧急程度 / 功能位置 / 工单号 / 处理状态）可直接读。

| 列名 | 必需 | 说明 |
|---|---|---|
| 事项 | 是 | 待办内容，为空的行跳过并 warning |
| 到期日 | 否 | 见下方「日期字段」；**为空或无法解析时归入「无到期日」，不自设** |
| 来源 | 否 | 事项来源说明（如「上级交办」「车间例会」），仅作展示 |
| 优先级 | 否 | 见下方「优先级取值」；无法归类时按 P3 中 |
| 位号 | 否 | 填写后参与疑似重复判定 |
| 责任人 | 否 | |
| 状态 | 否 | 见下方「状态取值」：已关闭（CLSD / NOCO）、已完成的行不进待办；TECO（技术完成待验收）仍是待办 |
| 备注 | 否 | |

### 列名别名

| 标准列名 | 可识别的写法 |
|---|---|
别名表 = 局部别名（优先）+ 共享 `SYSTEM_ALIASES`（SAP PM/EM 导出列名，见顶层《中石化口径对照.md》第二节）。

| 标准列名 | 可识别的写法 |
|---|---|
| 事项 | 事项、待办、待办事项、内容、工作内容、任务、事项内容、描述、工作事项 |
| 到期日 | 到期日、到期日期、截止日期、计划完成、要求完成时间、计划完成时间、完成期限、期限、截止、要求完成日期、基本结束日期 |
| 来源 | 来源、事项来源、出处、任务来源、交办人、交办单位 |
| 优先级 | 优先级、紧急程度、紧急度、级别、等级 |
| 位号 | 位号、设备位号、设备编号、TAG、功能位置、技术对象（本技能把「设备编号」也作重复判定锚点） |
| 编号 | 编号、单号、工单号、通知单号、隐患编号、缺陷编号、订单号 |
| 责任人 | 责任人、负责人、承办人、执行人 |
| 状态 | 状态、完成情况、处理状态、当前状态 |
| 备注 | 备注、说明、补充 |

表头行识别：取前 10 行中命中必需列最多的一行，因此首行是标题、第三行才是表头的导出表也能读。

### 优先级取值

| 归类 | 可识别的写法 |
|---|---|
| P1 最高 | P1、1、`1 非常高`（SAP）、最高、紧急、特急、A 级 / A 类、旧 I 级 / 一级（warning） |
| P2 高 | P2、2、`2 高`（SAP）、高、较急、重要、B 级、旧 II 级 / 二级（warning） |
| P3 中 | P3、3、`3 中`（SAP）、中、一般、普通、C 级、旧 III / IV 级、三级 / 四级（warning） |
| P4 低 | P4、4、`4 低`（SAP）、低、不急、次要 |

用户表里写明的优先级**优先于脚本按来源推的优先级**；无法归类的写法按 P3 中且 `prioFromUser: false`，不猜测。旧 I~IV 四级口径已废止，脚本按 I→A、II→B、III/IV→C 映射并 warning 具体到行。

### 状态取值

状态归一复用 `common.js` 的 `normSapStatus`，口径同中石化口径对照（工单与通知单状态映射）：

| 状态写法 | 归一 | 是否进待办 |
|---|---|---|
| 空，或以 未 / 待 / 不 / 非 开头（未完成、待验收、未关闭 …） | — | 进 |
| CLSD、NOCO、已关闭、关闭、已闭环、已验收、已消缺 | 已闭环 | 不进（不 warning） |
| 已完成、完成（本人登记的已办结） | — | 不进（不 warning） |
| **TECO、CNF、技术完成、完工待验、已完工** | 待验收 | **进** —— 技术完成不是关闭，还要设备员组织验收 |
| CRTD、OSNO、REL、NOPR、PCNF、已下达、施工中 … | 待审核 / 已派工 / 施工中 | 进 |
| DLFL、LKD、已删除、取消、作废 | 已取消 | 不进，warning 具体到行 |

## 三、纯文字待办（.txt / .md）

- 每行一条；`- ` `* ` `• ` `1. ` 等列表符号会被剥掉
- 以 `#` 开头的 markdown 标题行跳过
- 行内写了「截止 2026-09-25」「到期：2026/9/25」「完成期限 20260925」会被识别为到期日
- 没写日期的行归入「无到期日」，**不按当天或次日补**

## 四、日期字段

- 支持：`2026-09-21`、`2026/9/21`、`2026年9月21日`、`20260921`、Excel 日期单元格、Excel 日期序列号
- 无法解析时归入「无到期日」并 warning 注明原始写法，**不做模糊推断**（「下周三」「月底前」这类写法一律不解析）

## 五、上一日 todo.json（`--prev`）

传入前一日本脚本产出的 `todo.json`，脚本读其 `items[]`：

- `status === 'done'` 的条目不结转
- 其余条目**原样结转**，保留 `dueDate`、`srcName`、`srcRef`
- 结转项追加 `carried: true`、`carriedFrom`（首次结转的日期，多次结转保留最早的那天）、`carriedRounds`（已结转次数）、`originalDueDate`、`originalSource`
- 若本日来源中同一事项再次出现（key 相同），**不重复列**，把结转标记合并到本日那条上；本日上游到期日与 `originalDueDate` 不同时，`dueDate` 取上游本日值，条目加 `dueDateChanged: {from, to}` 并 warning「上游到期日由 X 变为 Y，请在系统核实」，清单两个日期都列

**key 口径**：`key` = 类型 + 单号 + 位号（`<类型>|<单号>|<位号>`，如 `orders|WO-26090012|P-1101B`）；无单号时退回稳定的事项主体（`<类型>||<位号>|<主体指纹>`：润滑取部位，隐患/缺陷取描述，交接取事项内容，待办表/文字待办取事项文字）。key **不含子类与标题**，停滞天数变化、临期转超期、隐患由超期转待验收、交接状态变化都不改变 key，次日重跑上游不会出重复条目。单号取：工单号、隐患编号、特种设备注册代码、校验证书号、待办表「编号」列；缺陷登记号由 defect-intake-grading 按运行当日生成、次日重跑会变，不作单号（有真实通知单号时用通知单号）。校验「不合格未整改」与「超期/临期」是两件事，类型写作 `calibration:fail`。同一次运行内撞 key（如同一工单既超期又停滞）时，后出现的一条追加 `#<子类>`（如 `orders|WO-26090102|K-1201#stalled`）。

**旧版 key 兼容**：升级前产出的 `todo.json`（旧 key 形如 `类型|子类|单号或位号|标题前 24 字`）仍可作 `--prev`：有单号的按「类型 + 单号 + 位号」对上本日条目，无单号的按旧 key 原值或「类型 + 位号 + 事项主体」一对一匹配，升级后第一次运行也不出重复；对不上的照旧结转，写出的 key 一律为新格式。

文件不存在或 JSON 解析失败 → 报错退出（不静默跳过，避免无声丢失结转）。

## 六、`--done`

可以直接传文字，也可以传一个文本文件路径。按换行、`;`、`；` 拆条，剥掉列表符号。

**不提供时 `done` 为 `null`（不是空数组），工作日志「今日完成事项」留空并注明「脚本不推断已完成事项」。**

## 七、会被跳过的行
- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 提示）
- 事项为空的行（warning 提示）
- 状态为已完成 / 已闭环 / 已关闭 / CLSD / NOCO 的行（不 warning，属正常过滤）
- 状态为已取消（DLFL / LKD / 已删除 / 取消 / 作废）的行（warning 提示，不静默跳过）

## 关键验证点

1. **超范围动作必须被拦截**：案例 3 是本技能最关键的行为。指引卡的读者是一线操作工，写上「打开泵盖检查」就等于让人无票拆检。selftest 用 16 类动作逐一验证拦截；S5 只拦「拆/接/短接接线」，不拦「检查接线盒外观」。
2. **加换油不误拦**：「更换润滑油」属操作工职责，不在拦截之列。过度拦截会让指引卡失去可用性。
3. **类型识别顺序**：案例 4 中「循环水泵电机」若被「泵」先命中，会漏掉「接线盒有无烧灼痕迹」「有无绝缘漆味」这些电机专属的早期征兆。
4. **判据不用数值**：全部异常特征为定性描述，参照物是「平时」。操作工手上没有测振仪。
5. **紧急条件置顶**：排在所有设备类型之前。紧急情况下没人会翻到第三页。
6. **上报路径必填**：不传 `--report-to` 直接报错。各厂流程不同，给默认值会延误。
7. **限定语进正文**：「切换至备用设备 / 降低负荷」必须带「经值班领导/内操同意后执行」，每节下方另有一行【注意】重申。
8. **SAP 列名**：案例 6 验证 `mergeAliases` 后「功能位置」归位号而「设备」（8 位流水号）不归位号。
9. **声明行**：培训/指引类口径「本材料仅供参考，不替代操作规程与检修规程；为设备专业建议稿，由车间工艺/安全审核后……」卡头卡尾各一处。

## 再生样例

```bash
node scripts/make-sample.js --out examples            # seed=1
node scripts/make-sample.js --out examples --seed 3   # 区域变化，设备类型与覆盖结论不变
```

## MCP 取数对照

平台接入业务系统 MCP 时不上传附件：设备资产管理 `get_equipment_ledger` 返回「设备台账.csv」，放进新建空目录作 `--ledger`。上报对象与紧急上报方式不来自 MCP，须用户给出。下表预期结果为每天都稳定的结论。

| # | 示例问题 | MCP 调用 | 运行参数 | 预期结果 |
|---|---|---|---|---|
| M1 | 按常减压车间的设备台账给外操做指引卡，先报内操和班长，紧急情况打厂调度 | 设备资产管理 `get_equipment_ledger`（workshop=常减压车间） | `--ledger <目录> --workshop 常减压车间 --report-to "内操、班长" --emergency 厂调度` | 8 节：离心泵、电机、换热器、塔器容器、通用、阀门、管道、压缩机（按台账首次出现顺序）；P-2101A/B 在离心泵节、E-1201 在换热器节、PSV 安全阀在阀门节；常压炉 F-1201 与变送器、界位计归「通用」并标「待安全专业补充」；区域取「装置」列（1#常减压装置 / 轻烃回收装置）；给了紧急上报方式即无 warning |

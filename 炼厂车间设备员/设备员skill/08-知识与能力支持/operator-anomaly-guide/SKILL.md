# 操作工异常识别指引（operator-anomaly-guide）

面向中石化体系炼化厂车间（运行部）设备员，编制发给岗位操作工的设备异常识别与上报指引卡，让一线人员知道"看什么、什么算异常、先做什么、找谁"。**本材料为设备专业建议稿，由车间工艺/安全审核后纳入岗位操作法或 HSE 作业指导书；指引内容严格限定在操作工职责范围内，涉及设备处置的动作一律为"停止操作并上报"，不得指导操作工进行拆检、调整等专业作业。**

## 适用条件
- 用户说"给操作工做个指引 / 异常处置卡 / 操作工发现问题该怎么办 / 巡检要看什么"，并说明设备范围。
- 产出：按设备类型的异常识别要点卡、初步处置与上报路径、上报信息模板。
- 车间设备员可做：编制设备专业建议稿、组织车间审核、发放后跟踪执行情况。
- 由 XX 归口：岗位操作法与 HSE 作业指导书的正式发布由车间工艺/安全归口；应急预案由安全环保部门归口；上报路径与紧急电话以厂内实际流程为准，脚本不自行设定。
- 不适用：设备员的专业初判（anomaly-triage-advisor）；替代操作规程与应急预案；指导操作工进行专业维修作业。

## 前提条件
- 输入：车间设备清单（SAP PM / EM 导出：功能位置、设备描述、对象类型、工厂区段均可识别）或设备类型说明（必需）。可选：厂内操作规程、应急预案、上报流程规定、岗位职责说明。
- 必填信息：车间名称、设备范围或类型、上报路径（发现异常应找谁，如 班长/内操/车间设备员/调度，含岗位与联系方式占位）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得基于文字手工成文或自行判定（硬约束 2）。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 设备资产管理 | `get_equipment_ledger` | `workshop`：车间 | `--ledger` |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；把目录作为“交给脚本”一列的参数值。
2. `get_equipment_ledger`：按台账的设备类型分节，区域取「装置」列。

操作规程或应急预案来自平台知识库，可作 `--spec`（可选）。

## 操作步骤
1. **确认设备范围与上报路径** —— 设备类型、上报对象（班长/内操/车间设备员/调度）、紧急情况的上报方式、厂内规程是否允许操作工手摸设备判温判振（不允许则加 `--no-touch`）。**上报路径必须由用户提供厂内实际流程，不得自行设定。**
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/guide.js" --scope "<设备类型或范围>" --workshop "<车间名>" --report-to "<上报对象>" --out "<工作目录>/操作工指引"
   ```
   可选：`--ledger "<设备清单xlsx>"`（与 `--scope` 同时给时按 scope 过滤清单，只保留 scope 内的设备类型、位号或区域，warning 写明剔除台数）、`--spec "<操作规程或应急预案路径>"`、`--emergency "<紧急上报方式>"`、`--format <卡片|手册>`、`--actions "<自拟处置动作,逗号分隔>"`、`--no-touch`（去掉全部"摸"类观察点与依赖手摸的异常特征；不加时每条"摸"类观察点自动带"仅在操作规程允许且确认安全时"限定语）。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（设备类型不覆盖/规程无法解析/上报路径未提供等）。脚本用法详见 `scripts/README.md`。
   - **脚本会校验每条处置动作是否超出操作工职责**（如"打开泵盖检查""调整联轴器""拆接线""用火补焊"），命中时拦截并 warning，**模型必须改为"停止操作并上报"**。"检查接线盒外观"这类观察描述不拦；"确认联锁未旁路后上报""泵停用后观察报警是否消失"这类否定、疑问或观察写法不拦；"对泄漏法兰进行包扎""把保温拆掉检查""摘掉联锁""打旁路"照样拦截。
   - 白名单里"切换至备用设备""降低负荷"自带"经值班领导/内操同意后执行"限定语，脚本已写进指引卡正文，**不得删掉**。
3. **读取 guide.json** —— 从 `<输出目录>/guide.json` 获取：`sections[]`（按设备类型：`observe.看/听/摸/闻`、`abnormalSigns`、`immediateActions`、`actionNote`、`equipment`、`covered`）、`reportPath`（`to`、`emergency`、`elements`）、`emergency`（撤离条件）、`outOfScope`（被拦截的超范围动作）、`meta.noTouch`、`meta.statement`、`counts`。
4. **生成指引卡** —— 按 `assets/templates/guide-template.md` 成文，结构为"设备类型 → 日常观察要点 → 什么情况算异常 → 发现异常先做什么 → 找谁报告 → 报告要说清的信息 → 什么情况立即撤离并启动应急"。**语言面向一线，短句、具体、可执行；异常特征用定性描述（如"声音明显变大""温度烫手"），不用需要仪器测量的数值判据。紧急撤离条件必须醒目。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查，重点核对：**是否有超出操作工职责的动作、是否与厂内操作规程冲突、紧急情况指引是否清晰**。通过后交付 `指引卡.md` 与 `guide.json`，并提醒用户：交车间工艺/安全审核后再纳入岗位操作法或 HSE 作业指导书。**必须保留脚本写入的声明行："本材料仅供参考，不替代操作规程与检修规程；为设备专业建议稿，由车间工艺/安全审核后纳入岗位操作法或 HSE 作业指导书，并与厂内操作规程、应急预案一致后发放；遇紧急情况以应急预案为准"，不得删除或改写。**

## 预期结果
- `指引卡.md`：面向操作工的异常识别与上报指引，结构为：卡头（编制/审核/声明）→ 一、什么情况立即撤离并报警 → 每个设备类型一节（本车间该类设备 / 日常观察要点 / 什么情况算异常 / 发现异常先做什么 + 限定语提示）→ 报告要说清的信息 → 已拦截的超范围动作（仅 `--actions` 有拦截时）→ 声明行与相关技能 → 附：生成提示（仅 warnings 非空时）。可打印张贴。
- `guide.json`：结构化指引内容与被拦截项；`summary.json`：脚本末行摘要。
- 交付时向用户说明：覆盖设备类型数、要点条数、被拦截的超范围动作、是否启用 `--no-touch`、需与规程核对的内容、脚本 warnings（如有）。

## 不适用范围
- 不指导操作工进行拆检、调整、维修等专业作业。
- 不替代操作规程、应急预案与岗位职责规定。
- 不给出需要仪器测量的数值判据作为操作工的判断标准。
- 不设定上报路径，须依据厂内实际流程。
- 不代替车间工艺/安全审核，不直接作为岗位操作法或 HSE 作业指导书发布。

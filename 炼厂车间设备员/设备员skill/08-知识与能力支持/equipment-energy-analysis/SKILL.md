# 设备能效分析（equipment-energy-analysis）

面向中石化体系炼化厂车间（运行部）设备员，从设备角度计算单机能效并与设计值或同类设备对标，识别能效偏低的设备。**所有计算由脚本完成，模型只负责解读；不得手工估算效率，也不得把能效偏低直接归因为设备故障。**

## 适用条件
- 用户说"这台泵效率怎么样 / 机组能耗高不高 / 设备能效对标 / 哪些设备耗能偏高 / 加热炉热效率"，并给出（或即将给出）单台设备的运行与能耗数据。
- 覆盖设备：离心泵、压缩机（等温效率；给齐进出口温度与绝热指数可用 `--polytropic` 按多变效率）、风机、电机、加热炉、换热器（传热系数 K）。
- 车间设备员可做的部分：单机能效计算、与设计值或同类设备对标、能效偏低设备的提示与需核实方向、费用差额量级测算。
- 由 XX 归口：装置综合能耗、单位产品能耗与能耗指标考核归能源管理部门与工艺（用 `energy-weekly-report`）；电价（含分时电价峰/平/谷与加权平均）由厂内能源/财务口径提供，脚本不内置任何电价数值；节能改造立项与技术经济评价归公司设备管理部门（机动部/设备部）与工艺。
- 不适用：工艺操作优化方案；节能改造的技术经济决策；装置级能耗统计与对标。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含「运行数据」（位号、流量、扬程或压比、功率、进出口参数、运行时间）与可选「设计参数」「分组」「单价」，字段见 `references/input-spec.md`。别名表已并入共享 `SYSTEM_ALIASES`，SAP PM/EM 导出列名（功能位置、设备描述、对象类型）可直接读；SAP 8 位「设备编号」不作位号。
- 必填信息：车间名称、统计区间、设备类型。可选：设计参数表、同类设备分组、能源单价（分时电价须给加权平均行）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工计算效率。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| DCS位号数据 | `get_energy_data` | `workshop`（用户所问车间，与 `--workshop` 相同）；只看个别设备时加 `tag`（多个用逗号分隔） | `--input` |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；把目录作为“交给脚本”一列的参数值。
2. `get_energy_data`：一次返回「运行数据」「设计参数」两个 csv，放同一目录。**必须带 `workshop`**：脚本不按车间筛选，不带时会把其他车间的机泵一并算进本车间报告。
3. 工具给的是近 30 天运行均值，`--from` 填今天往前 30 天、`--to` 填今天；工具只含离心泵，`--equip-type 离心泵`。不带单价表，费用差额不测算（脚本 warning 提示），用户给出厂内电价时另用 `--price` 传入。

## 操作步骤
1. **确认设备类型与计算口径** —— 不同设备类型的效率算法不同（泵用有效功率与轴功率之比、加热炉用热效率、换热器只给 K 值）；压缩机默认等温效率，要多变效率须给齐进口压力、出口压力、进口温度、出口温度、绝热指数并加 `--polytropic`。**口径与所需参数见 `references/energy-rules.md`，参数不全时不得用简化公式或典型值替代而不说明。**
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/energy.js" --input "<xlsx路径>" --workshop "<车间名>" --equip-type "<设备类型>" --from <YYYY-MM-DD> --to <YYYY-MM-DD> --out "<工作目录>/能效分析"
   ```
   可选：`--design "<设计参数表xlsx>"`、`--group "<同类设备分组xlsx>"`、`--price "<单价表xlsx>"`、`--threshold <能效偏低判定比例，默认 0.9>`、`--polytropic`（压缩机多变效率口径）。默认输出目录为系统临时目录 `<os.tmpdir()>/eea-out`，建议始终传 `--out`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺列/参数不全无法计算/数值超出物理合理范围/设计参数缺失/分时电价未提供加权平均等）。脚本用法详见 `scripts/README.md`。
   - 计算所需参数不全：该设备效率输出 null（显示 —）并归入 `insufficientData`，**绝不用典型值代替缺失参数**（含多变口径缺温度或 k 值时不按典型 k、不按等温口径顶替）。
   - 计算结果超出物理合理范围（如效率大于 100%）：标 `implausible` 并 warning 提示核实数据，**不得截断到合理范围后呈现**。
   - 统计期内运行时间为 0 h 的设备（如长期备用泵）：参数均值不代表运行工况，效率照列供核对，`lowJudgement = notRunning`、判定列标「统计期内未运行（不判定）」，**不判正常或偏低**，也不参与同类对比，warning 提示核实是否备用或停运。
   - 无设计参数时：只做同类设备横向对比，不做与设计值的偏差分析，**不得引用通用典型效率值作为基准**。
   - 单价表只有单一电价时 warning 提示厂内若执行分时电价应提供加权平均电价；给了峰/平/谷多行但无加权行则不做费用差额测算，脚本不自行取峰或谷。
3. **读取 energy.json** —— 从 `<输出目录>/energy.json` 获取：`byEquipment`（逐台：效率、口径 `efficiencyKind`、单位能耗、与设计值偏差、组内排名）、`lowEfficiency`（能效偏低清单与需核实方向）、`groupComparison`（同类设备对比）、`insufficientData`、`implausible`、`savingPotential`（有单价时的费用差额测算）、`counts`、`meta`（口径、基准规则、电价说明、边界与声明行）。
4. **撰写"能效分析"** —— 读 `references/energy-rules.md` 的表述口径，撰写 250~400 字，按"总体情况 → 能效偏低设备与可能方向 → 同类设备差异 → 数据不足与异常值 → 建议核实事项"结构，替换 `energy.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**效率数值一律引用 energy.json；能效偏低只提示需核实的方向（如运行工况偏离、叶轮磨损、管网阻力变化），不得断言原因。费用差额须注明是基于当前运行条件的测算，不等于节能收益。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `energy.md`、`energy.json` 与 `能效对标表.xlsx`。

## 预期结果
- `energy.md`：设备能效分析报告，六节：一、统计概览；二、逐台能效明细；三、能效偏低清单；四、同类设备对比；五、数据不足与异常值（5.1 计算参数不全、5.2 超出物理合理范围、5.3 费用差额测算）；六、能效分析。有 warning 时附「附：数据提示」。头部写单机口径边界，尾部固定三行：费用差额声明、口径边界、"本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。"
- `能效对标表.xlsx`（逐台能效 / 能效偏低 / 同类对比 / 数据不足 / 异常值 / 费用差额测算 六个工作表）与 `energy.json`；`summary.json`：脚本末行摘要。
- 交付时向用户说明：统计区间、计算设备数、能效偏低数、数据不足数、异常值数、采用的计算口径（压缩机等温/多变）与基准来源、电价口径、脚本 warnings（如有）。

## 不适用范围
- 不断言能效偏低的原因，不做故障诊断。
- 不出具节能改造方案与技术经济评价。
- 不替代能源管理部门的考核统计口径；不内置电价。
- 不引用通用典型效率值作为对标基准。
- 不做装置级综合能耗分析（用 energy-weekly-report）。

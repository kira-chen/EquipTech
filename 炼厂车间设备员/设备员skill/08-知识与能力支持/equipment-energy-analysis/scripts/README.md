# scripts 使用说明

## energy.js —— 主脚本

```bash
node "<技能目录>/scripts/energy.js" \
  --input "<运行数据xlsx>" \
  --workshop "<车间名>" \
  --equip-type "<设备类型>" \
  --from <YYYY-MM-DD> --to <YYYY-MM-DD> \
  --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 含「运行数据」工作表的 xlsx 或同结构 CSV 目录；可另含「设计参数」「分组」「单价」 |
| `--workshop` | 是 | 车间名称 |
| `--equip-type` | 是 | 离心泵 / 风机 / 压缩机 / 电机 / 加热炉 / 换热器；无法识别时报错 |
| `--from` | 是 | 统计区间起始日期 |
| `--to` | 是 | 统计区间截止日期；早于 `--from` 时报错 |
| `--out` | 否 | 输出目录，默认系统临时目录 `<os.tmpdir()>/eea-out`，建议始终传 `--out` |
| `--design` | 否 | 单独的设计参数表 xlsx；文件不存在时报错 |
| `--group` | 否 | 单独的同类设备分组表 xlsx |
| `--price` | 否 | 单独的能源单价表 xlsx |
| `--threshold` | 否 | 能效偏低判定比例，默认 0.9（效率低于基准 × 该比例即偏低）；须在 0~1 之间 |
| `--polytropic` | 否 | 压缩机按多变效率口径（需 进口压力/出口压力/进口温度/出口温度/绝热指数，缺任一 → 数据不足，不按典型 k 或等温口径顶替）；对其他设备无影响 |

### 产出

| 文件 | 内容 |
|---|---|
| `energy.json` | `byEquipment`、`lowEfficiency`、`groupComparison`、`insufficientData`、`implausible`、`savingPotential`、`counts` |
| `energy.md` | 六节报告（有 warning 时附数据提示），分析段留占位符；头部边界行，尾部费用差额声明 + 边界行 + 通用声明行；醒目提示用「【注意】」 |
| `能效对标表.xlsx` | 逐台能效 / 能效偏低 / 同类对比 / 数据不足 / 异常值 / 费用差额测算 |
| `summary.json` | 末行摘要落盘 |

### 退出码
- `0`：成功
- `1`：失败（无「运行数据」表、运行数据无记录、设备类型无法识别、非法日期、`--from` 晚于 `--to`、阈值超出 0~1、外部表文件不存在、输入不存在、未知参数、值参数缺取值）

### 八个关键行为

1. **计算所需参数不全 → 效率 null，绝不用典型值代替**（最关键）。缺介质密度就不按水的 1000 算油泵，只有电机功率而没有电机效率就不按 0.93/0.95 折算轴功率。该设备归入 `insufficientData`，列出缺哪些参数，不进偏低清单、不参与组内排名与中位数。用假参数算出来的效率看着像个数，拿去排检修就是误导。
2. **结果超出物理合理范围 → 单列且不截断**。效率 > 100% 或 ≤ 0 时归入 `implausible`，原始值原样保留，warning 提示核实单位、量程、取数时点。把 394% 截断成 100% 呈现，等于把数据质量问题伪装成「效率很高」的设备结论。
3. **无设计参数只做同类横向对比**。不做与设计值的偏差分析，概览显示「—（未提供设计参数，仅做同类横向对比）」而不是 0。既无设计效率又无同类可比设备（组内 <2 台可算）时标为 `notComparable`，**不拿通用典型效率值当基准** —— 「离心泵一般 70~80%」随比转速、流量等级、介质变化极大，不能作为单台设备的判定依据。
4. **能效偏低只给需核实方向，不断言原因**。输出的是 `checkPoints`（运行工况偏离、过流部件磨损、管网阻力变化、仪表取数），`lowReason` 恒为 null。
5. **费用差额是静态测算，不等于节能收益**。逐条与报告两处带声明行。缺运行时间或缺单价时不测算，不用典型运行小时、不按典型电价代替。
6. **单机口径，不是装置能耗**。报告头尾两处写明与 `energy-weekly-report` 的边界：那个是装置综合能耗的工艺口径，这个是单台设备的能效口径；能耗指标考核归能源管理部门。
7. **电价不内置，分时电价不自行取峰谷**。单一电价 warning 提示分时电价应给加权平均；峰/平/谷多行无加权行则不测算；有「加权」行只认加权行。
8. **统计期内运行 0 h 不判定**。运行时间为 0 h 的设备（长期备用泵）参数均值不代表运行工况，效率照列供核对，`lowJudgement = notRunning`、判定列「统计期内未运行（不判定）」，不判正常或偏低，不参与组内排名与中位数，`counts.notRunning` 计数并 warning。运行时间为空不按 0 h 处理。

### 各类型计算口径

| 类型 | 公式 |
|---|---|
| 离心泵 | Pe = ρgQH/3600000；η = Pe / 轴功率 |
| 风机 | Pe = Q×p/3600000；η = Pe / 轴功率 |
| 压缩机（默认） | Pis = Q×p1×ln(p2/p1)/3600000；η = Pis / 轴功率（等温口径，绝压） |
| 压缩机（`--polytropic`） | (n−1)/n = ln(T2/T1)/ln(p2/p1)；η_p = [(k−1)/k] ÷ [(n−1)/n]（不依赖轴功率） |
| 电机 | η = 输出功率 / 输入功率 |
| 加热炉 | η = 有效热负荷 / (燃料量 × 低位发热值) |
| 换热器 | K = Q / (A × ΔTm)，**不折算为 0~100% 效率**，不套用合理范围判定 |

轴功率优先直读；无轴功率时用「电机功率 × 电机效率」折算，电机效率支持 `0.95` 与 `95` 两种写法。

## make-sample.js

```bash
node scripts/make-sample.js [--seed <n>]
```

主样例恒 7 台离心泵：2 台能效偏低、1 台参数不全（数据不足）、1 台效率超 100%（异常值）、2 个可对比分组，含设计参数与单价。另生成无设计参数变体、五类型混排变体（SAP PM 列名：功能位置/设备描述/对象类型）、压缩机多变口径 + 分时电价变体（`--polytropic` 时恒 1 可算 / 2 数据不足，单价取「加权」行）。`--seed` 变则数值抖动变，但各类条数不变。

## selftest.js

```bash
node scripts/selftest.js
```

230 条断言，覆盖六类设备的计算口径、**参数不全不用典型值代替**、**超合理范围不截断**、**无设计参数不引用通用典型值**、无可比基准不判偏低、偏低只给需核实方向、费用差额声明（参照为设计效率或组内中位数）与缺件不测算、与 energy-weekly-report 的边界、15 条参数校验、缺表空表、别名与合计行、标题行表头、位号重复不合并、产出四文件与 xlsx 六工作表、样例可再生、`--polytropic` 多变口径（公式、缺温度/k 不顶替、默认口径不受影响）、分时电价（单一电价提示、峰平谷无加权不测算、加权行只认加权、非电介质）、SAP PM 列名与设备编号不作位号、边界与通用声明行、无 emoji、默认输出目录为临时目录、统计期内运行 0 h 的设备不判正常或偏低且不参与组内对比（29 组）。

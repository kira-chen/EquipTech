# 设备专业知识问答（equipment-knowledge-qa）

面向中石化体系炼化厂车间（运行部）设备员与新员工，回答设备专业问题。**回答分两类并必须区分标注：有厂内资料支撑的（引用原文出处，且只能引用 `--docs` 范围内的文件）、通用原理性的（标注"通用原理，非本厂规定"）。涉及具体数值、限值、判定标准的问题，一律要求查厂内规程（《炼化企业设备维护检修规程》对应分册、岗位操作法、设备说明书等），不得给出记忆中的数值。**

## 适用条件
- 用户提出设备专业问题：工作原理、术语含义、结构组成、常见现象的机理、专业概念辨析、"规程里这段什么意思"。
- 可附厂内规程、检修规程、说明书、培训材料（txt/md/docx）；附资料时优先基于资料回答。
- 车间设备员可做的部分：基于资料解释、原理科普、指出该数值应查哪份文件。**不做**（由 XX 归口）：技术数值的最终确认由厂内受控规程/公司设备管理部门（机动部/设备部）归口；工艺参数与联锁定值由工艺/仪表归口；设计计算与选型由设计/技术部门归口。
- 不适用：具体设备的技术数值查询（须查规程）；设计计算与选型决策；资料文件的检索定位（用 technical-document-finder）；当前故障的诊断（用 anomaly-triage-advisor）；出考题（用 training-material-generator）。

## 前提条件
- 输入：用户的问题（必需）。可选：厂内规程、设备说明书、培训教材等资料目录或文件。
- **PDF 统一前置步骤：PDF 先用平台 pdf 技能转为 txt/docx 再传入，脚本不读 PDF；扫描件需 OCR。** 直接传入的 PDF 只做文件定位并 warning，不会被引用。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得凭记忆作答或手工"检索"资料（硬约束 2）。**

## 数据获取（MCP）

本技能不调用业务系统 MCP。厂内检修规程、设备管理规定、培训教材、说明书等资料来自平台知识库，下载后放进一个目录作 `--docs`。涉及数值的问题没有厂内资料时不作答。

## 操作步骤
1. **判断问题类型** —— 按 `references/qa-rules.md` 分类（脚本会给出规则号）：
   - **原理概念类**（什么是、为什么、怎么工作）：可基于通用原理回答，须标注"通用原理"，**通用原理段不超过 300 字且不得出现任何数字或单位**。
   - **数值标准类**（多少合格、限值是多少、间隙应该是多大、多久换一次）：**一律不得直接回答，必须要求查厂内规程或设备说明书**，可说明该数值通常在哪类文件中规定（脚本给出中石化体系常见文件名示例，只引名称不引数值）。
   - **本厂规定类**（我们厂怎么规定的、这个设备用什么型号）：**必须有厂内资料才能回答，无资料时明确说明无法回答**。
2. **检索资料（有资料时）** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/qa.js" --question "<问题>" --docs "<资料路径>" --out "<工作目录>/知识问答"
   ```
   可选：`--equip-type "<设备类型>"`、`--context <上下文字数>`、`--all-matches`（默认最多返回 20 段）。
   **无厂内资料时省略 `--docs` 照常运行**：脚本只做问题分类与作答指引（数值类指路、本厂类明确答不了、原理类可作答并标注）。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 逐条告知（资料无法解析/PDF 未读/未命中相关内容等）。
   - 资料中未找到：明确说明"所提供资料中未涉及该问题"，再判断是否可用通用原理回答。
   - **Grep/Glob 的使用限制**：只允许在用户通过 `--docs` 指定的目录内检索（用于补充定位脚本已列出文件中的上下文），不得检索该目录之外的任何路径；凡引用必须带文件名与段落/行号，且该文件必须出现在 `qa.json` 的 `documents` 列表中。
3. **组织回答** —— 结构：**结论或定义 → 展开解释 → 来源标注 → 适用提示**。
   - 有资料支撑：先引用原文（标文件与位置，只能是 `--docs` 范围内的文件），再解释。
   - 通用原理：明确标注"以下为通用原理说明，非本厂规定，具体以厂内规程为准"，不超过 300 字、不含数字/单位。
   - 数值标准类：说明"该数值须以厂内规程/设备说明书为准，本技能不提供记忆中的数值"，引用脚本 `guidance.whereToLook` 的文件类别与示例文件名，并提示可用 `technical-document-finder` 查找。
4. **交付前自检** —— 对照 `references/checklist.md` 逐项检查，重点核对：**是否混淆了通用原理与厂内规定、是否给出了无出处的数值、引用是否全部在 `--docs` 范围内、通用原理段是否超长或夹带数字**。
5. **相关提示** —— 问题涉及当前故障判断时提示接 `anomaly-triage-advisor`；涉及找具体资料时提示接 `technical-document-finder`。**必须保留声明行：「本回答区分『厂内资料原文』与『通用原理』两类内容；通用原理非本厂规定，具体执行以厂内规程为准。涉及数值、限值、周期的问题一律以厂内规程/设备说明书为准，本技能不提供记忆中的数值。仅供参考，不替代操作规程与检修规程。」**

## 预期结果
- `qa.md`：七节（一、问题分类；二、厂内资料原文；三、通用原理适用性；四、数值类处理；五、必须说明的话；六、无法检索内容的文件；七、回答组织）+ 有后续技能时第八节「相关技能」+ 声明行 + 附：数据提示。
- `qa.json`、`summary.json`。
- 直接回答用户问题（对话形式），含来源标注与适用提示；回答中明确哪些内容来自所提供资料（标出处）、哪些是通用原理、哪些需要查规程确认。

## 不适用范围
- 不给出记忆中的技术数值、限值、判定标准、检修周期。
- 不做设计计算、强度校核与选型决策。
- 不混淆通用原理与本厂规定。
- 不回答需要本厂资料但用户未提供资料的问题。
- 不引用 `--docs` 范围之外的任何文件。
- 不替代专业培训与技能鉴定。

# 交付自检清单

回答发出前逐项过一遍。**任何一项打不上勾，就不要发出去。**

## 问题分类
- [ ] 已按 `qa-rules.md` 判定问题类型，`qa.json` 的 `questionType` 与回答口径一致
- [ ] 数值标准类、本厂规定类、原理概念类三选一；三类都不沾的走未判定，**没有按原理类默认放行**
- [ ] 混合问句（原理 + 数值 / 本厂 + 数值）按数值类处理，且两部分已分节

## 数值边界（最关键）
- [ ] 回答中**没有任何一个**来自记忆的技术数值、限值、公差、周期、力矩、试压压力
- [ ] 出现的每一个数值都能指到 `qa.json` 的 `passages` 里某一条原文
- [ ] 数值类问题已写明「该数值须以厂内规程/设备说明书为准，本技能不提供记忆中的数值」
- [ ] 没有用「一般」「通常」「经验上」「差不多」软化后给出记忆中的数值
- [ ] 没有把国标、行标、API 条文里的数值当作本厂执行值给出
- [ ] 无资料时已说明该数值通常记在哪类文件里（只指路、不给数）

## 本厂规定
- [ ] 本厂规定类问题，**有厂内资料才回答**
- [ ] 无资料 / 资料未命中时，明确说了「无法回答」，**没有用通用原理搪塞**
- [ ] 没有出现「一般来说厂里都是……」「你们厂应该也差不多」这类把通用做法说成本厂规定的句子
- [ ] 没有用同类设备、邻位号设备的资料代替本设备的规定

## 通用原理与厂内规定不混淆
- [ ] 厂内资料原文与通用原理**分节呈现**，各自带标注
- [ ] 通用原理段落前有「以下为通用原理说明，非本厂规定，具体以厂内规程为准」
- [ ] 通用原理段落里**没有任何具体数值、限值、周期**
- [ ] 通用原理段 **不超过 300 字**（`qa.json` 的 `meta.principleMaxChars`），且**不出现任何阿拉伯数字或单位**（MPa、mm、℃、mm/s、r/min、% 等）——用 `scripts/lib/rules.js` 的 `checkPrincipleText` 的口径自查
- [ ] 没有把资料原文和自己的补充揉进同一段

## 来源标注
- [ ] 每条引用都带出处（文件名 + 第 N 段）
- [ ] 每条引用的文件都在 `qa.json` 的 `documents` 列表里（**只能在 `--docs` 范围内引用**）；若用了 Grep/Glob，只在 `--docs` 目录内检索过
- [ ] 数值类指路引用的是 `guidance.whereToLook` 的文件类别与示例文件名（《炼化企业设备维护检修规程》等），没有转述这些文件里的任何数值
- [ ] 引用用的是完整段落原文，未改写、未换算单位、未取整
- [ ] 原文与解释分开呈现，解释中没有引入原文没有的数值、判定、条件
- [ ] 多处原文取值不一致时全部列出，未替用户取其一

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；为 `false` 时已告知 `error` 原文并终止，**未凭通用知识作答**
- [ ] `warnings` 已逐条告知用户
- [ ] 计数（检索份数、命中段数）全部来自 `qa.json`，未自行统计
- [ ] 环境无法执行 node 时已告知用户并终止，**未凭记忆作答、未手工"检索"资料**

## 无文字层文件
- [ ] PDF、图片、CAD 文件只做了文件定位；遇到 PDF 已告知用户前置步骤：**先用平台 pdf 技能转为 txt/docx 再传入，扫描件需 OCR**
- [ ] 回答中**没有任何一句**声称读到了图纸/扫描件里的内容
- [ ] 表格文件（xlsx/csv）未被当作资料原文；需要资料定位时已提示用 `technical-document-finder`

## 交付说明
- [ ] 已说明问题被判为哪一类、依据哪条规则
- [ ] 已说明检索了多少份资料、命中多少段
- [ ] 已说明无法解析的文件有哪些
- [ ] 已带上声明行：「本回答区分『厂内资料原文』与『通用原理』两类内容；通用原理非本厂规定，具体执行以厂内规程为准。涉及数值、限值、周期的问题一律以厂内规程/设备说明书为准，本技能不提供记忆中的数值。仅供参考，不替代操作规程与检修规程。」
- [ ] 需要查具体资料时已提示 `technical-document-finder`；问题实际指向当前故障时已提示 `anomaly-triage-advisor`

# 问答口径与回答规范

本技能只做一件事：**把问题分对类，然后按该类的口径作答或拒答**。分类规则实现在 `scripts/lib/rules.js`，每条规则带规则号，`qa.json` 的 `classification.matched` 能倒查是哪一条命中的。

## 一、问题分类标准

三类 + 一个未判定。**判定顺序固定：数值标准类 → 本厂规定类 → 原理概念类 → 未判定**，命中即停，不往下走。

### 1. 数值标准类（`numeric`，优先级最高）

问的是一个**具体的量**：多少、多大、多久、限值、合格范围、间隙、公差、力矩、试压压力、周期、频次、报警定值、壁厚、磨损量……

| 规则号 | 触发 | 例 |
|---|---|---|
| N1 | 疑问词直接问量值（多少/几个/多大/多久） | 轴承温度是多少 |
| N2 | 限值、上限、阈值、报警值、整定值、定值 | 振动报警值定在多少 |
| N3 | 合格标准、是否合格、判废、报废标准 | 绝缘电阻多少算合格 |
| N4 | 间隙、游隙、公差、跳动、对中偏差 | 这个间隙应该是多大 |
| N5 | 力矩、扭矩、预紧力、紧固要求 | 压盖螺栓上多大力矩 |
| N6 | 试压、水压/气密试验压力、保压 | 泵壳试压多少 MPa |
| N7 | 更换/检修/保养/润滑/校验的周期与频次 | 轴承多久换一次油 |
| N8 | 温度、振动、压力、转速、流量、电流、绝缘的具体取值 | 振动不能超过多少 |
| N9 | 壁厚、减薄量、腐蚀速率、磨损量 | 管束最小壁厚多少 |
| N10 | 「该取多少」「调到多少」「控制在多少」 | 油位保持在多少 |
| N11 | 浓度、含量、加注量、液位、开度、余量 | 润滑油加多少 |
| N12 | 拿一个具体数值来求确认 | 振动 6.5mm/s 算超标吗 |
| N13 | 问标准/规范/规程里的具体数值 | 规程里规定的数值是多少 |

**只要命中 N 组任一条就是数值标准类**，哪怕问句里同时有「原理」「为什么」。混合问句在 JSON 里标 `mixedPrinciple: true`：原理部分可以解释，数值部分照样不答。

### 2. 本厂规定类（`plant`）

问的是**本厂 / 本车间 / 某台具体设备**的规定、型号、材质、做法、审批口径。

| 规则号 | 触发 | 例 |
|---|---|---|
| P1 | 主语指向本厂（我们厂、咱们车间、厂里、本厂） | 我们厂是怎么规定的 |
| P2 | 直接问本厂规定/标准/做法/现行口径 | 厂内现行做法是什么 |
| P3 | 问某台具体设备用什么型号/厂家/材质/规格 | 这台泵用什么型号 |
| P4 | 问句中出现具体位号（如 P-1101A） | P-1101A 的制造厂是哪家 |
| P5 | 问厂内文件（规程/说明书/台账/制度）怎么写的 | 规程里是怎么要求的 |
| P6 | 问本厂职责、审批、签字权限 | 缺陷定级归谁审批 |

### 3. 原理概念类（`principle`）

问的是**定义、机理、结构、作用、定性判别与定性措施**，不涉及量值，也不指向本厂。

| 规则号 | 触发 | 例 |
|---|---|---|
| G1 | 术语定义、缩写全称 | NPSH 是什么意思 |
| G2 | 为什么、机理、成因 | 为什么会发生汽蚀 |
| G3 | 工作原理、怎么工作、靠什么密封 | 机械密封怎么工作的 |
| G4 | 区别、对比、优缺点 | 机械密封和填料密封的区别 |
| G5 | 结构、组成、分类 | 离心泵由哪些部件组成 |
| G6 | 部件作用 | 平衡盘起什么作用 |
| G7 | 定性判别（不含量值） | 怎么判断泵发生了汽蚀 |
| G8 | 定性措施 | 怎么防止换热器结垢 |

### 4. 未判定（`undetermined`）

三组规则一条都没命中。**不默认按原理概念类放行**——默认放行等于让一个意图不明的问题拿到通用解释，可能正好是个数值问题。产出里单列一节，请用户补充问的是原理、具体数值还是本厂规定。

## 二、三类回答的表述规范

### 数值标准类 —— 一律拦截

固定表述（脚本写进 `classification.notice`，一字不改）：

> **该数值须以厂内规程/设备说明书为准，本技能不提供记忆中的数值。**

然后做两件事，只做这两件：

1. **无资料时**：说明该数值通常记在哪类厂内文件里（脚本的 `guidance.whereToLook`，只指路、不给数）。
2. **有资料且命中时**：照录原文 + 标出处，并提示核实资料版本是否现行有效。原文里写多少就是多少，一个字不改、不换算、不取整。

**禁止**（`guidance.mustNotSay` 逐条列出）：

| 禁止的说法 | 为什么禁 |
|---|---|
| 「一般取 40~50N·m」 | 凭记忆给数，本厂可能完全不是这个值 |
| 「通常 3 个月换一次」 | 同上，周期是典型的数值类 |
| 「经验上差不多 0.05mm」 | 用软化措辞夹带记忆中的数值，性质一样 |
| 「按 GB/API 的规定是 X」 | 标准条文不等于本厂执行值，本厂可能更严或另有规定 |
| 「资料没写，但参考同型号设备是 X」 | 拿别的设备的数顶上 |

### 本厂规定类 —— 无资料就明说答不了

固定表述：

> **本厂规定须以厂内受控文件为准；未提供厂内资料时本技能无法回答，不用通用原理代替。**

- **有资料且命中**：照录原文 + 标出处，解释另起一段，不引入原文没有的结论。
- **有资料但未命中**：「所提供资料中未涉及该问题」，**到此为止**，不再往下用通用原理补。
- **无资料**：「未提供厂内资料，本技能无法回答本厂是怎么规定的」+「未用通用原理代替本厂规定作答」。

**最容易犯的错**是这样搪塞：

> 不应写：「你们厂的具体规定我看不到，不过一般炼化厂机泵备件都是一用一备的，你们厂应该也差不多。」

这句话把通用做法说成了本厂规定，用户很可能就照着做了。正确的说法是：

> 应写：「未提供厂内资料，我无法回答贵厂是怎么规定的，也不能用通用做法代替。这类规定通常写在车间设备管理规定或备件管理制度里，可以把文件提供给我，或用 `technical-document-finder` 按关键词检索。」

### 原理概念类 —— 可答，但必须标注来源性质

固定表述：

> **通用原理，非本厂规定；具体执行以厂内规程为准。**

- **有资料且命中**：优先照录资料原文并标出处；资料没覆盖的部分再用通用原理补，并分节标注。
- **有资料但未命中**：先说「所提供资料中未涉及该问题」，再给通用原理说明，标注非本厂规定。
- **无资料**：直接给通用原理说明，整段带标注。

**原理段落里不得出现任何具体数值、限值、周期**。一旦要说到数值，立刻转数值标准类口径：说该去哪查，不给数。

**通用原理段硬约束**（`scripts/lib/rules.js` 的 `PRINCIPLE_MAX_CHARS` 与 `checkPrincipleText`，selftest 扫描产出的 ANALYSIS 段与本文件示范句）：

- 长度 **不超过 300 字**（去空白后计）；超过说明在讲课而不是在回答，应收敛到结论与机理。
- **不得出现任何阿拉伯数字或单位**（MPa、mm、℃、mm/s、r/min、% 等）。数字一出现即视为夹带数值，哪怕写成"约""左右"。

> 不应写：「机械密封端面比压一般控制在 0.3~0.5MPa」——这是原理段夹带数值。
> 应写：「机械密封靠端面比压维持液膜，比压过高端面磨损快、过低易泄漏；本厂的比压控制值须查设备说明书。」

### 未判定 —— 不作答，回问

> **未能判定问题类型，未按任一类默认处理；请补充说明问的是原理、具体数值还是本厂规定。**

不猜意图、不默认按原理类给通用解释。

## 三、数值类问题的处理原则

### 只指路，不给数

脚本的 `whereToLook` 按问题内容给出该数值通常记在哪类文件（规则号 W1~W7，判不出走 W0 兜底）：

| 规则号 | 数值类别 | 通常规定在 | 中石化体系炼化厂常见文件示例（只引名称） |
|---|---|---|---|
| W1 | 紧固力矩 | 设备使用说明书「安装/紧固要求」章节、检修规程回装条款 | 《炼化企业设备维护检修规程》对应设备分册的回装条款、制造厂随机说明书 |
| W2 | 间隙与对中量 | 检修规程的解体检修与回装验收条款、随机装配图 | 《炼化企业设备维护检修规程》对应设备分册的检修质量标准、随机装配图与技术协议 |
| W3 | 试压参数 | 技术协议、检验报告、检修规程试压条款 | 设备技术协议、TSG 21 / TSG D7005 定期检验报告、检修规程试压条款 |
| W4 | 检修与更换周期 | 润滑管理规定、预防性维修计划、特种设备定期检验周期规定 | 厂内设备润滑"五定三过滤"管理规定与润滑图表、SAP PM 维护计划、《炼化企业设备管理技术规定》；特种设备周期以安全状况等级与检验报告为准 |
| W5 | 运行参数限值 | 岗位操作法工艺卡片、设备运行监控标准、联锁报警定值表 | 岗位操作法（工艺卡片）、联锁报警定值表、特护设备运行监控标准、《炼化企业设备维护检修规程》运行参数条款 |
| W6 | 壁厚与磨损量 | 定期检验报告、测厚台账、静设备完整性管理文件 | TSG 21 / TSG D7005 定期检验报告、定点测厚台账、设备完整性管理体系文件 |
| W7 | 材质与规格 | 设备台账、铭牌、技术协议与随机资料 | SAP PM 技术对象主数据 / EM 设备台账、铭牌、技术协议与随机资料 |
| W0 | 判不出 | 说明书 / 检修规程 / 技术协议 / 岗位操作法，可用 `technical-document-finder` 检索 | 《炼化企业设备维护检修规程》对应设备分册、制造厂随机资料、岗位操作法 |

**指路文本本身不含任何数值**，这是硬要求，自测逐条校验（示例列中的 TSG 21 / TSG D7005 是法规编号，属文件名称，不是数值；本技能只引名称，不转述其中任何周期或限值）。各厂受控文件名可能不同，以厂内受控文件目录为准。

### 资料里有数值的处理

资料里写着的数值可以照录，因为那是**厂内资料的内容**，不是记忆中的数值。但要满足三条：

1. 引用块照录完整段落，不摘取、不改写、不换算单位
2. 标出处：文件名 + 第 N 段
3. 附一句：采用前请核实该资料版本是否现行有效（本技能不判定版本有效性）

多处资料给出不同数值时**全部列出**，不替用户取其一——这一条与 `technical-document-finder` 口径一致。

### 混合问句

「机械密封是什么原理，压盖螺栓力矩应该是多大」这类问句按 `numeric` 处理，但 `mixedPrinciple: true`：

- 原理部分照原理类口径答，标「通用原理，非本厂规定」
- 力矩部分照数值类口径拦截，只说去哪查
- **两部分必须分节**，不能揉在一段里让用户分不清哪句是原理、哪句是拒答

## 四、来源标注要求

回答里的每一句实质内容都要能说清是哪来的，只有三种来源，分节呈现：

| 来源性质 | 标注方式 | 允许出现数值 |
|---|---|---|
| 厂内资料原文 | 引用块 + 「出处：文件名　第 N 段」 | 是（原文照录） |
| 通用原理 | 整段前置「以下为通用原理说明，非本厂规定，具体以厂内规程为准」 | **否** |
| 无法回答 | 明确写「无法回答」+ 原因 + 去哪查 | 否 |

**引用范围只限 `--docs`**：凡引用，文件必须出现在 `qa.json` 的 `documents` 列表中（即用户通过 `--docs` 指定的目录或文件）。平台若开放了 Grep/Glob，也只允许在该目录内检索，不得翻用户没给的目录、不得引用"记忆中的规程原文"。

**绝不允许**：

- 把资料原文和通用原理揉在同一段里
- 引用不带出处（「说明书里写了……」——哪份说明书、第几段？）
- 引用 `--docs` 范围之外的文件，或把其他任务里见过的资料内容搬过来
- 解释里引入原文没有的数值、判定、条件
- 通用原理段落不带标注（用户会默认它是本厂规定）

产出 `qa.md` 已经用「二、厂内资料原文」「三、通用原理适用性」两节把这件事分开了，回答给用户时保持同样的分节。

## 五、无文字层与不可解析文件

`.pdf`、图片、`.dwg`/`.dxf` **一律不解析内容**，只做文件定位，进 `unreadable`、`contentSearchable: false`、`paragraphs: null`，**绝不产生 `passages`**。`.xlsx`/`.csv` 同样不作为资料原文（表格类资料定位请用 `technical-document-finder`）。

**PDF 统一前置步骤**：PDF 先用平台 pdf 技能转为 txt/docx 再传入，脚本不读 PDF；扫描件需 OCR。脚本遇到 `.pdf` 不报错终止，只 warning 并在「六、无法检索内容的文件」提示该前置步骤。中石化炼化厂的规程、说明书、检查通知大多是 PDF，务必先转。

回答时绝不能说「图纸上标注……」。正确说法是「该文件无文字层，无法检索内容，需打开原件查看」。

## 六、每次回答都要附带的说明

1. 问题被判为哪一类、依据哪条规则
2. 检索了多少份资料、命中多少段（数字全部来自 `qa.json`，不自行统计）
3. 无法解析的文件有哪些
4. 脚本 `warnings` 逐条
5. 声明行：**「本回答区分『厂内资料原文』与『通用原理』两类内容；通用原理非本厂规定，具体执行以厂内规程为准。涉及数值、限值、周期的问题一律以厂内规程/设备说明书为准，本技能不提供记忆中的数值。仅供参考，不替代操作规程与检修规程。」**（报告中已自动带，不得删改）

## 七、不做的事

- 不给出记忆中的技术数值、限值、判定标准、检修周期
- 不用通用原理代替本厂规定
- 不做设计计算、强度校核、选型决策
- 不诊断当前正在发生的故障（用 `anomaly-triage-advisor`）
- 不做资料检索定位（用 `technical-document-finder`：找哪份文件在哪、按位号定位资料；本技能回答资料内容问题）
- 不出培训考题（用 `training-material-generator`）
- 不判定资料版本的有效性与受控状态
- 不引用 `--docs` 范围之外的文件
- 不替代专业培训与技能鉴定；工艺参数与联锁定值由工艺/仪表归口，技术数值最终以厂内受控规程与公司设备管理部门（机动部/设备部）口径为准

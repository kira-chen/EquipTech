# 培训材料生成口径

> 本技能最重要的约束：**凡涉及具体数值（力矩、间隙、限值、周期、压力、温度）的考题，答案必须来自所提供资料并标注出处。无出处的一律改为原理概念题，绝不生成凭经验的数值考题。**

## 一、为什么要机器拦

写培训题最省事的写法是「轴承温度不得超过 75℃」——看着像常识，实则是编的。各厂各装置的限值不一样，同一台泵不同工况的限值也不一样。一旦这道题进了考核，员工背下来的是一个错数，现场照着错数判断，责任在编制方。

所以脚本做两件事：

1. **正则识别**每一条要进考题的内容是否含技术数值（`lib/tm.js` 的 `hasNumericValue`）。
2. **出处硬校验**：答案含数值但 `source` 为空的题目，**不是 warning 后照样输出，而是直接剔除**，并在 warnings 中说明。

`scripts/selftest.js` 的 C、D、E 三组断言就是盯这条线的：无资料时正则扫描产出的答案表，不允许出现任何带单位的数值。

## 二、按培训对象的内容深度

培训对象决定提纲模块、讲义方向、考点与默认难度。六类对象（新员工 / 在岗 / 转岗 / 复岗 / 四新 / 三级安全教育，中石化体系炼化厂车间常见培训类别）的口径写死在 `lib/tm.js` 的 `AUDIENCES`。别名归一顺序敏感：三级安全教育、四新先判（「新设备」「新工艺」含「新」字，不能落到新员工）。

### 新员工（默认难度：基础）

侧重 **设备认识、安全注意事项、异常识别与上报**。

| 模块 | 目标 | 权重 |
|---|---|---|
| 本车间设备认识 | 认得设备、知道叫什么、在哪、干什么用 | 3 |
| 设备基本结构与工作原理 | 知道设备由哪几部分构成、靠什么工作 | 3 |
| 安全注意事项 | 知道哪些地方不能碰、哪些事不能做 | 2 |
| 异常识别与上报 | 看到不对，能说清楚、能报上去 | 2 |

**不讲**：故障原因诊断、检修工艺与装配方法、专业参数整定。新员工连设备都还没认全，讲故障诊断是浪费学时。

### 在岗（默认难度：中等）

侧重 **故障处理、标准与规程、典型案例**。

| 模块 | 目标 | 权重 |
|---|---|---|
| 常见故障现象与处理流程 | 现象 → 初步判断方向 → 按流程处置 | 3 |
| 标准与规程要求 | 把厂内规定的做法与限值落到自己的动作上 | 3 |
| 典型案例复盘 | 从已经发生过的事上学 | 2 |
| 点检与记录质量 | 记录写得准，后面才用得上 | 2 |

**不讲**：超出本岗位授权的检修作业、未经批准的参数整定。

### 转岗（默认难度：中等）

侧重 **与原岗位的差异点、本车间特有设备**。

| 模块 | 目标 | 权重 |
|---|---|---|
| 与原岗位的差异点 | 先把「以为一样其实不一样」的地方标出来 | 3 |
| 本车间特有设备 | 认识本车间有、原岗位没有的设备 | 3 |
| 本车间规程与管理要求 | 按本车间的规矩来 | 2 |
| 衔接期重点关注 | 刚转过来最容易出问题的地方 | 2 |

转岗人员最容易出事的不是不懂，而是**把原岗位的习惯带过来**。所以「差异点」放在第一模块，权重最高。

**不讲**：以原岗位口径替代本车间规定。

### 复岗（默认难度：中等）

侧重 **离岗期间的变化点、规程与系统更新、本岗设备当前状态**。

| 模块 | 目标 | 权重 |
|---|---|---|
| 离岗期间的变化点 | 设备变更与技改（变更管理台账）、新增或停用位号、期间异常事件、修订的规程与系统操作（EM / SAP PM） | 3 |
| 本岗设备当前状态 | 在用/备用/检修/停用清单、未闭环的缺陷与隐患、特护设备状况、近期检修验收 | 3 |
| 规程与安全要求复训 | 现行规程条款、作业许可与属地监护、应急处置路径 | 2 |
| 复岗确认 | 考核项目、带教期与复核、独立顶岗前确认 | 2 |

**不讲**：按离岗前的旧版规程操作；未经复岗确认即独立顶岗。

### 四新（默认难度：中等）

新工艺、新技术、新设备、新材料投用前培训，侧重 **差异点与风险点、投用前条件确认**。

| 模块 | 目标 | 权重 |
|---|---|---|
| 四新项目概况与变更依据 | 变更类别（工艺技术 / 设备设施 / 管理）、审批与投用前条件确认（PSSR）、与原系统的边界 | 2 |
| 新设备 / 新材料的结构与特点 | 结构原理、适用工况与禁忌、与原设备的差异、随机资料与技术协议 | 3 |
| 运行监控与点检要求 | 巡检点检项目与周期（以厂内规程为准）、关注参数与报警联锁（数值查定值表）、投用初期加密监测 | 3 |
| 风险点与应急 | JSA / HAZOP 结论、应急处置路径、投用前培训考核与授权 | 2 |

**不讲**：凭旧设备经验推定新设备参数；未完成投用前培训考核即操作新设备。

### 三级安全教育（默认难度：基础）

只做 **车间级、班组级的设备专业部分**；**厂级安全教育内容由公司安全环保部门归口，本技能不生成**，提纲第一模块只做衔接说明。

| 模块 | 目标 | 权重 |
|---|---|---|
| 厂级安全教育衔接 | 说明厂级内容由公司安全环保部门归口；厂级考核合格是进入车间级的前提 | 1 |
| 车间级：本车间设备安全要求 | 装置概况与设备风险点、安全距离与防护、本车间作业许可（用火、受限空间、高处等）与属地监护、异常上报、历史案例 | 3 |
| 班组级：岗位设备安全操作 | 岗位设备清单与位号、点检与记录、个人防护与应急器材、未经许可不得启停拆检调整、隐患排查 | 3 |
| 考核与上岗 | 考核项目、教育记录与档案、上岗授权（授权本身由公司人力资源/安全部门归口） | 1 |

**不讲**：厂级安全教育内容；替代安全教育考核与上岗授权。

## 三、出处标注要求

出处写法固定为：`文件名 第X.X条（位置）`，例如 `动设备管理规定.md 第4.2条（第12行）`。

| 内容 | source | origin | 标注 |
|---|---|---|---|
| 资料中的条款 | `{file, loc, clause}` | — | 完整出处 |
| 通用原理 | `null` | `builtin` | 「通用原理（非厂内规定）」，讲义与答案表点名「内置条目 builtin，需技术人员审核」 |

**通用原理条目不得携带任何数值**。`lib/tm.js` 的 `PRINCIPLES` 库全部是定性表述，每条导出前自动打标 `source: 'builtin'`；selftest 的 A23 断言会扫全库，出现数值即失败，N14~N18 断言盯 builtin 标记与点名。内置条目是脚本作者写的通用原理，不是厂内规定，也没有经过本厂技术人员审核，所以声明行点名要求审核后方可使用。`counts.questionsBuiltinPrinciple` 给出本次用了多少道内置原理题，交付时要说。

## 四、四类考题素材与出题上限

| 素材类别 | 来源 | 有无出处 | 能否出数值题 |
|---|---|---|---|
| 数值类 | 资料中含数值的条款 | 有 | **只有这一类能** |
| 定性规定类 | 资料中不含数值的条款 | 有 | 否 |
| 原理概念类 | 内置通用原理库 | 无（标通用原理） | **绝对不能** |
| —— | 凭经验 | —— | **不存在这一类** |

可出题上限 = 三类素材条数之和。`--questions` 超过上限时：

- warning 明确写出「只能出 N 道（数值类 a、定性规定类 b、原理概念类 c）」
- 按 N 道出题，**不拿编造的数值题补缺口**
- 产出 md 中也提示未凑数，让审核人看见缺口

这是 selftest E 组断言覆盖的行为。

## 五、题型与干扰项

支持 单选、多选、判断、简答，`--types` 指定。

**数值类题目优先出简答**，其次判断、单选。原因：

- 简答题答案直接引条款原文，出处最干净；
- 多选题需要多个正确项，凑不出来就会去编，所以数值类不分配多选；
- **单选题的干扰项一律是定性表述**（「以现场经验判断即可，无需查规定」这类），**绝不生成数值干扰项**——把 75℃ 改成 85℃ 做干扰项，本身就是编造数值。selftest H8 断言扫全部干扰项，出现数值即失败。

**判断题分肯定式与否定式**：

- 肯定式：题面直接取条款原文，答案「正确」。
- 否定式：脚本按 `lib/tm.js` 的 `NEGATE_RULES`（J1~J16）在原句上**只改情态词或比较词**（不得→可以、应→无需、不大于→可以大于……），**不改任何数值**，答案「错误」，答案表给出「正确表述：原文」与出处。改写前后 `digitsOf` 数字序列必须一致，否则退回肯定式并 warning；避开「应力」「有效值」「会议」这类复合词。判断题交替出肯定式 / 否定式，`--no-negative-judge` 可关闭否定式。
- **绝不通过改数值来构造错误项**——把 75℃ 改成 85℃ 做"错误表述"，等于编一个错的规定值放进考卷。
- `counts.questionsJudgeTrue` / `questionsJudgeNegated` 分别计数；md 题量表写「判断题肯定式 / 否定式」。

## 六、数值题干要把答案遮住

数值类题干由条款原文生成，脚本把数值替换为 `＿＿`：

> 按厂内规定，离心泵地脚螺栓紧固力矩为 ＿＿ N·m，紧固后应做防松标记　请填出规定值。

不遮的话题干里就写着答案，不成其为题。遮蔽范围见 `lib/tm.js` 的单位词表与 `training.js` 的 `maskNumbers`。

## 七、不生成的内容

以下内容一律不生成，命中即剔除并在 `blockedTopics` 单列（规则表见 `lib/tm.js` 的 `FORBIDDEN_TOPICS`）：

| 规则号 | 类别 | 原因 |
|---|---|---|
| F1 | 规程 / 制度 / 预案的编写 | 以厂内正式文件为准 |
| F2 | 操作规程正文与条款 | 须引用厂内正式规程原文 |
| F3 | 开车 / 停车 / 切换 / 吹扫等操作步骤 | 属操作规程范畴 |
| F4 | 应急预案编写与内容 | 以厂内应急预案为准 |
| F5 | 作业许可（用火、受限空间、高处、盲板抽堵、吊装、临时用电、动土、断路）办理审批流程 | 以《中国石化作业许可管理规定》与厂内作业许可制度为准（术语用「用火」，「动火」作别名兼容） |

拦截在两处生效：`--scope` 传入的主题，以及**资料中抽出来的条款**。后者很关键——用户把整本规程丢进来时，开停车步骤那几章不能进讲义。

## 八、设备类型识别顺序（与 operator-anomaly-guide 同源）

顺序敏感：**电机 → 压缩机 → 离心泵 → 换热器 → 塔器容器 → 阀门 → 管道 → 通用**。

`lib/tm.js` 的 `TYPE_PATTERNS` 与 `08-知识与能力支持/operator-anomaly-guide/scripts/lib/scope.js` 的 `TYPE_PATTERNS` **逐字同源**（两处正则完全一致），selftest N43 断言跨目录比对；改一处必须同步另一处，否则同一台「鼓风机电机」在培训材料与异常指引卡里会归到不同类型。

「鼓风机电机」若被「风机」先命中，会套用压缩机的原理条目，漏掉绝缘、缺相这些电机专属考点。

## 九、学时分配

`--duration` 给总学时时，按模块权重比例分摊并保留一位小数。**不给学时就是 null**，报表显示「—」，**绝不按 0 或按每模块 2 学时臆造**。

## 十、声明行

三份材料都必须原样保留（口径对照第九节培训/指引类模板 + 内置条目点名）：

> 仅供参考，不替代操作规程与检修规程；设备专业建议稿，由车间工艺/安全审核后使用。本材料由脚本汇总、模型成文，其中内置通用原理条目（source: builtin）须经车间技术人员审核后方可使用；技能鉴定请以国家或企业正式题库为准。

不得删除或改写。技能鉴定有国家与企业的正式题库，本材料是车间设备员视角的设备专业建议稿，由车间工艺/安全审核后纳入培训计划，两者不能混。材料抬头写明「设备专业建议稿（车间设备员视角）」。

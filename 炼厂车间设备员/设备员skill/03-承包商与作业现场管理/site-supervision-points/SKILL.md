# 现场作业监督要点（site-supervision-points）

面向中石化体系炼化厂车间（运行部）设备员与属地监护人员，按《中国石化作业许可管理规定》八大类作业类型生成属地监督检查要点与频次建议，形成可打印的现场检查表。**要点由脚本按作业类型规则生成，模型不得增删安全要点；作业级别以作业票为准，脚本不自判；本技能不替代监护人的现场职责。**

车间设备员可做的部分：属地监督、作业条件确认、检查记录。**作业票审批签发由作业许可流程归口，监护由双监护（属地监护人 + 作业单位监护人）履职，额外安全措施由安全专业评估后写入作业票**，本技能只出要点清单与空白检查表。

## 适用条件
- 用户说"现场要盯哪些 / 监督要点 / 用火监护注意什么 / 出个现场检查表 / 多久检查一次 / 属地监护人要确认什么"，并说明作业类型与现场情况。
- 覆盖作业类型：八大类（用火、受限空间、高处、吊装、临时用电、动土、断路、盲板抽堵）以及常规检修（日常维修）。八大类共有的双监护、JSA/风险分析交底、属地确认人要点以 S 系列单列。
- 不适用：作业票的合规预检（permit-precheck-bridge）；同区域交叉作业冲突排查（cross-operation-conflict）；违章行为的记录与考核（contractor-performance-log）；替代专职安全员与监护人的现场履职；替用户确定作业级别。

## 前提条件
- 输入：用户说明的作业类型、作业内容、设备位号、作业环境（必需）。可选：作业票级别（以票面为准）、作业票、检修方案、承包商信息、同区域其他作业情况。**本技能不读取附件表格**：作业许可系统导出的台账、作业计划表只作为人工抄参数的对照物，脚本不解析（`examples/sample-work-plan.xlsx` 亦然）；作业票 PDF/图片不读，只记录票号或路径。
- 必填信息：作业类型（可多选）、作业内容、位号或区域、作业起止时间、介质与环境风险。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得凭记忆列监督要点。**

## 数据获取（MCP）

平台接入作业票系统 MCP 时，用工具取作业票票面信息，不必让用户逐项口述。工具只读，不审批、不签发作业票。

| 服务 | 工具 | 参数 | 用途 |
|---|---|---|---|
| 作业票系统 | `get_permits` | `workshop`：车间；`tag`（可选）：位号，只看某台设备的票时填，如 E-1201；`date`：作业日期，默认今天；或 `permit_no`：许可证编号 | 找到要做监督要点的那张票 |

工具返回的表格内容直接读取，不需要保存为文件。按该票的列填写命令行参数：

1. 「作业类别」→ `--work-type`；「作业级别」原样 → `--level`（如「一级」，脚本按作业类别识别是一级用火）；级别为空的（盲板抽堵、受限空间、临时用电等不分级的票）不传。
2. 「作业内容描述」→ `--scope`；「位号」和「区域」合写 → `--location`（如「E-1201（1#常减压装置常压蒸馏区）」）；「涉及介质」→ `--medium`，为空的不传。
3. 「开始时间」「结束时间」是「YYYY-MM-DD HH:mm」，改写成「YYYY-MM-DDTHH:mm:00+08:00」后作 `--start`、`--end`，原样传会报错；两者相差的小时数 → `--duration`。
4. 「作业人数」→ `--headcount`；「作业单位」→ `--unit`。
5. `--permit` 只接受文件路径。用火、受限空间、高处、吊装、盲板抽堵作业票可用 `get_permit_document`（`permit_no`：许可证编号）下载 Word 原件，把 docx 路径作 `--permit`；其余作业票不传 `--permit`，许可证编号在成稿时写明，不要把编号当路径传入。

`get_permits` 不传 `permit_no` 时返回 `date` 当天有效（开始不晚于当天、结束不早于当天，含跨天的多日票）且未关闭的票；要看别的日子的票改 `date`，或按许可证编号查（已关闭的票另加 `include_closed=true`）。

## 操作步骤
1. **确认作业信息** —— 按 `references/intake-questions.md` 核对：作业类型组合、作业内容、位号与区域、介质、环境条件（高温/密闭/带压/邻近运行设备）、作业人数、预计时长、作业票级别（票上定的几级）。**多类型组合作业须逐项列明，不得只按主要类型处理；级别只认票面，不替用户定级。**
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/supervise.js" --work-type "<作业类型,类型>" --scope "<作业内容>" --location "<位号或区域>" --out "<工作目录>/监督要点"
   ```
   可选：`--level "<作业票级别，如 一级用火 / 高处二级 / 吊装三级>"`、`--medium "<介质>"`、`--duration <预计时长小时>`、`--headcount <作业人数>`、`--env "<环境条件>"`、`--unit "<作业单位>"`、`--start <ISO8601带时区>`、`--end <ISO8601带时区>`、`--permit "<作业票文件路径>"`（只校验文件存在，不解析；只有票号时不传，票号在成稿时写明）。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（作业类型不在覆盖范围/介质不在危险特性库/级别无法识别/类型组合等）。脚本用法详见 `scripts/README.md`。
   - 作业类型不在覆盖范围：只输出通用监督框架并 warning，**模型不得凭通用知识补充具体安全要点**，须标注"待安全专业补充"。
   - 多类型组合时：脚本合并各类型要点并标注来源类型，冲突或加严项在 `escalated` 中单列。
   - 作业票级别：只用于映射检查频次口径（只能加严不降级），未提供时按作业类型默认口径并在判定依据注明；检查频次为本技能默认口径，**非厂内正式口径，厂内有规定以厂内为准**。
3. **读取 supervision.json** —— 从 `<输出目录>/supervision.json` 获取：`points`（监督要点：序号、要点内容、来源作业类型、检查方式、责任岗位、规则号）、`frequency`（检查频次建议，含 `levelNote` 级别口径与 `source` 口径来源）、`keyMoments`（关键时点：作业前、作业中、中断后复工、交接班、收尾）、`escalated`（组合加严项）、`risk`（频次口径与判定依据）、`counts`。
4. **生成现场检查表** —— 按 `assets/templates/supervision-template.md` 成文，含：作业信息、监督要点清单（按检查时点分组）、检查频次建议、关键时点提示、组合加严项、现场检查记录表（空白供填写）、异常处置提示、现场情况说明。**检查记录表留空，模型不得预填检查结果。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `supervision.md` 与 `supervision.json`。**必须保留声明行："本要点为辅助提示，不替代作业票规定的安全措施与监护人现场职责；发现异常应立即停止作业并按应急程序处置"，不得删除或改写。**

## 预期结果
- `supervision.md`：现场监督要点与检查表，八节：一、作业信息（含作业票级别与频次口径判定依据）；二、监督要点清单（按作业前/作业中/中断后复工/交接班/收尾分组）；三、检查频次建议（含级别口径与"默认口径、厂内为准"提示）；四、关键时点提示；五、组合加严项；六、现场检查记录表（空白）；七、异常处置提示；八、现场情况说明（分析段占位）。末尾"附：数据提示"列 warnings，开头与末尾各一处固定声明行。
- `supervision.json`：要点与频次的结构化结果；`summary.json`：脚本末行摘要。
- 交付时向用户说明：要点总数、按作业类型分布（含 S 系列许可通用要点）、组合加严项、作业票级别与建议检查频次（默认口径）、脚本 warnings（如有）。

## 不适用范围
- 不做作业票合规预检与签发，不替用户确定作业级别。
- 不替代属地监护人、作业单位监护人、安全员的现场履职与停工决策权。
- 不记录违章与考核，不评价承包商表现。
- 不给出超出厂内制度与作业票规定的安全措施。
- 不读取附件表格、作业票 PDF 与图片。

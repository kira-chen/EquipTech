# 交付自检清单

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；为 `false` 时已告知用户 `error` 原文并终止，**未凭记忆手写监督要点**
- [ ] `warnings` 已逐条告知用户
- [ ] `supervision.json`、`supervision.md`、`summary.json` 均已生成

## 作业信息确认
- [ ] 作业类型已逐项确认，**多类型组合全部列明，未只按主要类型处理**
- [ ] 位号/区域、作业内容已回读给用户确认
- [ ] 介质已确认；说不清时已按脚本最严口径提示核实 MSDS
- [ ] 作业票级别已按票面传入 `--level`（未提供时已说明频次按默认口径）；**未替用户自判级别**

## 监督要点
- [ ] 要点内容、来源作业类型、检查方式、责任岗位全部来自 `supervision.json`，**未增删改任何一条**
- [ ] 要点按五个检查时点分组呈现（作业前 / 作业中 / 中断后复工 / 交接班 / 收尾）
- [ ] **作业类型不在覆盖范围时只呈现通用监督框架，已标注「待安全专业补充」，未凭通用安全知识补充具体安全要点**
- [ ] 每条要点标注了规则号，可对照 `references/supervision-rules.md` 复核
- [ ] 八大类特殊作业已含 S 系列许可通用要点（双监护、JSA/风险分析交底、属地确认人）；常规检修单独作业无 S 系列
- [ ] 术语为「用火作业」（八大类命名），未写「动火作业票」

## 组合与加严
- [ ] 多类型组合时各类型要点均已呈现并标注来源类型
- [ ] `escalated` 中的加严项已单列一节，含冲突说明与执行口径
- [ ] 未自行为未命中加严规则的组合添加加严措施

## 介质与风险
- [ ] 介质不在危险特性库时已按最严口径处理并把 warning 告知用户
- [ ] 风险等级与判定依据来自脚本，未自行调整
- [ ] 检查频次按风险等级给出，未提供时长时巡查轮次显示「—」而非 0
- [ ] 已向用户说明检查频次为默认口径（非厂内正式口径），厂内有规定以厂内为准；级别对应的监护与到场要求以作业票为准

## 检查记录表
- [ ] 记录表的检查时间、检查结果、检查人签字三列**全部留空**
- [ ] **未预填任何检查结果**（含「合格」「已确认」「√」等）
- [ ] 已说明记录表由现场检查人填写

## 边界与声明
- [ ] **声明行原样保留**：「本要点为辅助提示，不替代作业票规定的安全措施与监护人现场职责；发现异常应立即停止作业并按应急程序处置」
- [ ] 已写明本要点不含超出厂内制度与作业票规定的额外安全措施
- [ ] 未替代监护人、安全员的现场履职与停工决策
- [ ] 未做作业票合规预检（属 `permit-precheck-bridge`）、未记录违章与评价承包商（属 `contractor-performance-log`）、未做同区域交叉作业冲突排查（属 `cross-operation-conflict`）
- [ ] 产出不含 emoji，醒目提示用「【注意】」

## 交付说明
- [ ] 已说明要点总数、按作业类型分布、组合加严项数、建议检查频次
- [ ] 已说明采用的口径来源（默认口径需明确标注，厂内有规定以厂内为准）

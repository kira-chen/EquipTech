# 作业信息确认清单与追问话术

## 必需信息

| 字段 | 参数 | 为什么必需 | 缺失时的追问 |
|---|---|---|---|
| 作业类型 | `--work-type` | 决定出哪些监督要点；**多类型须逐项列明** | 「这个活属于哪几类作业？用火、进罐、高处、吊装、临电、动土、断路、盲板，还是常规检修？」 |
| 作业内容 | `--scope` | 写入作业信息，便于现场对照 | 「具体干什么？拆什么、焊哪里、吊什么？」 |
| 位号或区域 | `--location` | 定位作业点，交叉作业协调的依据 | 「哪台设备、哪个区域？位号是多少？」 |

## 条件必需信息

| 字段 | 参数 | 什么情况下必需 | 追问 |
|---|---|---|---|
| **介质** | `--medium` | 任何涉及带介质设备的作业 | 「这台设备/这条管线走的什么介质？」 |
| 预计时长 | `--duration` | 需要推算巡查轮次时 | 「计划干多久？几个小时？」 |
| 作业起止 | `--start` `--end` | 需要与交接班、其他作业对表时 | 「几点开工、几点收工？」 |
| 作业人数 | `--headcount` | 受限空间、高处作业需清点人员时 | 「几个人进去/上去作业？」 |
| 环境条件 | `--env` | 高温、密闭、带压、邻近运行设备、夜间、露天 | 「现场什么环境？露天还是室内？旁边有没有在运行的设备？」 |
| 作业单位 | `--unit` | 需要写入检查表落实责任时 | 「哪个施工队？」 |
| 作业票 | `--permit` | 有作业票文件时（只传文件路径；只有票号时不传，票号在成稿时写明） | 「作业票办下来了吗？能给我看看票号和措施栏吗？」 |
| **作业票级别** | `--level` | 用火、高处、吊装作业有票时（其余类别不分级，不问） | 「票上定的是几级？特级、一级还是二级用火？高处几级？吊装几级？」级别以作业票为准，**技能不替用户定级** |

## 追问原则

1. **一次性列出所有缺项**，不要挤牙膏式逐个追问。
2. **多类型组合必须逐项列明**。用户说「进罐补焊」时要确认这是用火 + 受限空间两类，**不得只按用火一类处理**。
3. **级别不自判**。作业票级别（特级/一级/二级用火等）只认票面，用户没票或说不清时按作业类型默认口径并在判定依据注明，不替用户定级。
4. **作业类型不在覆盖范围时如实说明**。脚本只出通用监督框架并标注「待安全专业补充」，**不得凭通用安全知识替安全专业补要点**。
5. **介质说不清时不猜**。脚本按最严口径处理并给 warning，交付时要把这条 warning 告诉用户，提示核实 MSDS。
6. 要点是脚本按规则表出的，**模型不得增删改**；用户提出要加某条措施时，说明须由安全专业评估后写入作业票。

## 常见口语化表述与作业类型对应

| 用户可能这样说 | 作业类型 |
|---|---|
| 「罐里补个焊」「进塔割管线」 | 受限空间作业 + 用火作业（双票，合法常态；监督要点合并出） |
| 「上平台换个灯」「搭架子」 | 高处作业 |
| 「吊车把电机吊下来」 | 吊装作业（若在高处摘挂还含高处作业） |
| 「拉根临时线」「接个电焊机」 | 临时用电作业 |
| 「挖开看看管线」 | 动土作业 |
| 「把路封一段」 | 断路作业 |
| 「加个盲板隔开」「把盲板抽了」 | 盲板抽堵作业 |
| 「泵抽芯换机封」 | 常规检修作业 |
| 「拍片子」「做探伤」 | **不在覆盖范围**，只出通用框架，标注待安全专业补充 |

## 交付前要向用户说清的四件事

1. 要点总数与按作业类型的分布
2. 组合加严项（有几条、各是什么冲突）
3. 建议的检查频次（默认口径，非厂内正式口径）、作业票级别口径与风险等级判定依据
4. 脚本 warnings：作业类型未覆盖 / 介质不在库 / 作业票文件不存在等

# 承包商表现记录（contractor-performance-log）

面向中石化体系炼化厂车间（运行部）设备员，汇总本车间（属地单位）对承包商的现场检查、违章、质量、进度与配合度记录，形成结构化记录数据。**扣分与分档由脚本按口径计算，模型只负责成文；不得调整分值，不得替归口部门下考核结论。**

车间设备员可做的部分：属地监督记录的登记与汇总、未整改项跟踪、名称与编码核对。**承包商考核由安全环保部门归口、业务主管部门配合，分档定性与处罚按《中国石化承包商安全管理规定》及厂内制度决定**，本技能只出记录汇总与得分呈现。

## 适用条件
- 用户说"记录承包商表现 / 违章记录汇总 / 这个队伍这段时间怎么样 / 承包商考核数据 / 扣分情况"，并给出（或即将给出）现场检查记录或违章记录表。
- 覆盖四个维度：安全违章（一般违章 / 严重违章 / 重大违章三档）、施工质量、进度履约、现场配合与文明施工。
- 不适用：承包商入厂资质核验（contractor-qualification-check）；现场监督要点生成（site-supervision-points）；检修完工验收（completion-acceptance）；安全环保部门的正式考核、分档定性、黑名单与处罚决定。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含工作表「检查记录」或「违章记录」，字段见 `references/input-spec.md`（记录日期、承包商 / 作业单位、承包商编码（可选，有则按编码分组）、项目、类型、事项描述、严重程度、整改情况、检查人）。承包商管理平台、SAP 供应商编码、作业许可系统的导出列名可直接识别。**脚本不读 PDF 与图片**：纸质检查表须先整理成清单再传入。
- 必填信息：车间名称、评价区间（起止日期）。可选：厂内评分口径表（`--rules`，模板 `assets/templates/rules-template.xlsx`）、承包商名单、工单台账（关联履约情况，不参与评分）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工评分。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| HSE管理平台 | `get_site_inspections` | `workshop`：车间名（与 `--workshop` 同值）；`start_date`、`end_date`：评价区间，与 `--from`、`--to` 相同；不填为近 90 天。`contractor_code`（可选）：只看一家承包商时填其编码，与 `--contractor` 相同；不填返回全部承包商 | `--input`（目录 A） |
| HSE管理平台 | `get_contractors` | — | `--roster`（目录 B） |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；表中目录字母相同的放同一个目录，不同字母分开放，把目录作为“交给脚本”一列的参数值。
2. `get_site_inspections`：不填日期时返回近 90 天（`--from` 取今天前 89 天、`--to` 取今天）。本技能汇总的是车间（属地单位）侧记录，默认带 `workshop`，只取本车间项目的检查记录：工具按项目、事项描述里的位号或大检修项目把记录归到车间，导出带「车间」列（脚本不读该列，仍按承包商编码 / 名称分组）。不带 `workshop` 返回全厂各车间项目的记录，只在用户明确要看承包商在全厂的表现时才这样取，交付时说明记录范围为全厂。`--workshop` 只写入报告标题、不筛选记录，所以取数时的 `workshop` 必须与它一致。
3. `get_contractors`：不带 `contractor_code` 时返回承包商名单。

## 操作步骤
1. **确认评价区间与口径** —— 车间、起止日期、评分口径（未提供厂内口径时按 `references/evaluation-rules.md` 的默认分值，产出中会明确标注"采用默认口径，非厂内正式口径"）。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/performance.js" --input "<xlsx路径>" --workshop "<车间名>" --from <YYYY-MM-DD> --to <YYYY-MM-DD> --out "<输入同目录>/承包商表现"
   ```
   可选：`--rules "<厂内评分口径xlsx>"`、`--contractor "<承包商名称或编码>"`、`--orders "<工单台账xlsx>"`（关联履约情况）、`--roster "<承包商名单>"`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺列/严重程度取值无法归类/承包商名称不一致/记录超出区间等）。脚本用法详见 `scripts/README.md`。
   - 有「承包商编码」列的记录按编码分组，同一编码下的不同名称写法视为同一单位，名称仅展示；无编码的记录按名称字面量分组，拼写不一致（全称与简称混用）时脚本只列出疑似同一单位的名称组供用户确认，**不得自动合并统计**。
   - 严重程度为空或无法归类（如"待定级"）：该条记录归入 `undetermined` 不计分并单列，**绝不按最低档计分**。"严重违规"归严重违章（不是重大违章）；施工质量维度的"不符合"不自动归质量不合格，由用户明确是返工还是不合格。
3. **读取 performance.json** —— 从 `<输出目录>/performance.json` 获取：`byContractor`（逐家：承包商编码、各维度记录数、扣分、得分、分档）、`violations`（违章明细，按重大/严重/一般/未判定分组）、`unrectified`（未整改项）、`nameAmbiguity`（名称疑似重复）、`undetermined`、`counts`。
4. **撰写评价说明** —— 按 `assets/templates/performance-template.md` 成文，含：评价区间与口径说明、各承包商得分汇总表、违章明细、未整改项、名称待确认项、未判定记录、评价说明段。**分值、条数一律引用 performance.json；评价说明只陈述记录事实，不得使用"该队伍能力差""不建议再用"这类定性判断。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `performance.md` 与 `performance.json`。**必须保留声明行："本数据为车间（属地单位）侧记录汇总，承包商考核由安全环保部门归口、业务主管部门配合，分档定性与处罚按厂内制度决定；评分口径若非厂内正式口径，结果仅供参考"，不得删除或改写。**

## 预期结果
- `performance.md`：承包商表现记录报告，七节：一、评价区间与口径说明；二、各承包商得分汇总；三、违章明细（重大 / 严重 / 一般 / 严重程度未判定）；四、未整改项；五、承包商名称待确认；六、未判定记录；七、评价说明（含分析段占位）。给了 `--orders` 时在第六节后另有"七、工单履约情况（参考）"，评价说明顺延为第八节。末尾"附：数据提示"列 warnings，开头与末尾各一处固定声明行。
- `performance.json`：逐家记录数据；`summary.json`：脚本末行摘要。
- 交付时向用户说明：评价区间、承包商家数（按编码或名称）、违章总数、未整改数、采用的口径来源、脚本 warnings（如有）。

## 不适用范围
- 不做承包商的正式考核、分档定性、黑名单与处罚决定（由安全环保部门归口）。
- 不评价承包商的技术能力与商务报价。
- 不替代合同履约管理与结算审核。
- 不记录人员个人违章用于个人处罚。
- 不读 PDF / 图片检查表原件。

# scripts 使用说明

## performance.js —— 主脚本

```bash
node "<技能目录>/scripts/performance.js" \
  --input "<检查记录xlsx路径>" \
  --workshop "<车间名>" \
  --from <YYYY-MM-DD> \
  --to <YYYY-MM-DD> \
  --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 检查记录 / 违章记录 xlsx 路径，或同结构 CSV 目录 |
| `--workshop` | 是 | 车间名称 |
| `--from` | 是 | 评价区间起始日期 YYYY-MM-DD |
| `--to` | 是 | 评价区间截止日期 YYYY-MM-DD；早于 `--from` 时报错 |
| `--out` | 否 | 输出目录，默认输入文件同目录下 `cpl-out/`；**建议始终传 `--out`** |
| `--rules` | 否 | 厂内评分口径 xlsx（含「评分口径」工作表，可选「分档标准」工作表），覆盖默认口径；模板 `assets/templates/rules-template.xlsx` |
| `--contractor` | 否 | 只看某一承包商（名称包含匹配或承包商编码全等）；不影响名称待确认节的完整性 |
| `--orders` | 否 | 工单台账 xlsx（含「工单台账」工作表），输出履约参考，**不参与评分** |
| `--roster` | 否 | 承包商名单 xlsx（含「承包商名单」工作表，可含承包商编码列），标注是否在册并把简称纳入名称比对 |

### 产出

| 文件 | 内容 |
|---|---|
| `performance.json` | `meta`（含 `rulesNotice`、`disclaimer`、`groupedByCode`）、`counts`、`rules`（基准分/扣分表/分档）、`byContractor`（逐家：承包商编码 `code`、同一编码下的名称列表 `names`、各维度记录数与扣分、扣分合计、得分、分档、未判定条数、未整改条数、名称待确认标记）、`violations`（按重大/严重/一般/未判定分组）、`unrectified`、`nameAmbiguity`、`undetermined`、`outOfRange`、`orderStats`、`items`、`warnings` |
| `performance.md` | 七节报告（有 `--orders` 时八节）；评价说明段留 `<!-- ANALYSIS_START/END -->` 占位；开头与末尾各一处固定声明行；不含 emoji，醒目提示用「【注意】」 |
| `summary.json` | 末行摘要落盘（Windows 控制台乱码兜底） |

### 关键判定口径（不可放宽）

- **有「承包商编码」（供应商编码）列** → 按编码分组，同一编码下的不同名称写法合并为一行（名称以「/」并列）并 warning；无编码的记录按名称分组
- **承包商名称拼写不一致（全称/简称混用，无编码）** → 列入 `nameAmbiguity` 供人工确认，各名称分别统计，**脚本绝不自动合并**
- **严重程度为空或无法归类** → 进 `undetermined`，`deduction` 为 `null`，**绝不按该维度最低档计分**
- **违章三档**：一般违章 / 严重违章 / 重大违章；「严重违规」归严重违章（不是重大）；施工质量「不符合」不自动归质量不合格，进未判定
- **「监护人」列不作检查人别名**（双监护角色不是检查人）
- **记录类型缺失或无法归入四个维度** → 同样进 `undetermined`，不计分
- **记录日期缺失** → 进 `undetermined` 不计分，**不臆断是否属于评价区间**
- **未提供 `--rules` 时** → 产出中三处标注「**采用默认口径，非厂内正式口径，结果仅供参考**」
- **整改情况为空** → 既不算已整改也不算未整改，不进 `unrectified`
- **声明行**「本数据为车间（属地单位）侧记录汇总，承包商考核由安全环保部门归口、业务主管部门配合，分档定性与处罚按厂内制度决定；评分口径若非厂内正式口径，结果仅供参考」由脚本直接写入，不得删除或改写
- 脚本产出正文不含任何定性判断用语；分档只是记录呈现，不是评级结论

### 默认评分口径（`references/evaluation-rules.md`，非厂内正式口径）

基准分 100；安全违章 一般 −2 / 严重 −5 / 重大 −10；施工质量 返工 −3 / 质量不合格 −5；进度履约 延期 −2 / 严重延期 −5；现场配合 文明施工差 −1 / 不配合 −3。分档：90+ 优、80~89 良、70~79 一般、70 以下 差。

### 退出码
- `0`：成功，末行输出 `{"ok":true,...}`
- `1`：失败，末行输出 `{"ok":false,"error":"...","warnings":[...]}`

## make-sample.js —— 样例生成

```bash
node scripts/make-sample.js [--seed <n>] [--to <YYYY-MM-DD>] [--template-out assets/templates]
```

生成 7 份样例：主检查记录（覆盖全部边界）、脏数据变体（别名列头 + 标题行 + 合计行 + 类型无法识别 + 承包商为空 + 另一组简称混用）、系统导出变体（承包商管理平台 / SAP 供应商编码 + 作业许可系统列名：同一编码两种名称写法按编码合并、「严重违规」→ 严重违章、质量「不符合」→ 未判定）、无违章变体、厂内评分口径文件、承包商名单、工单台账。`--template-out` 另写厂内评分口径表模板 `rules-template.xlsx`。
seed 改变记录日期在区间内的取值，但不改变结论：主样例恒为 14 条记录（13 条在区间内）、4 个承包商名称、1 组名称待确认、2 条严重程度未判定、4 条未整改、1 条区间外；系统导出变体恒为 4 条记录、2 个承包商编码、1 条未判定、1 条未整改。
**样例中承包商名称与人名全部编造，不对应任何真实单位与个人。**

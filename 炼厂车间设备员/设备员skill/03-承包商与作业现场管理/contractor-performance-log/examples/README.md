# examples 回归测试数据

> 本目录仅开发包含有（`build.sh --with-examples`），发布包不含。
> 全部样例由 `node scripts/make-sample.js --out examples` 再生，记录日期随 seed 在区间内变化但结论不变。
> **样例中承包商名称、项目名与人名全部编造，不对应任何真实单位与个人。**

## 关键验证点

1. **承包商名称不一致绝不自动合并**（本技能最关键判定）：主样例中「宏远建安工程有限公司」（6 条）与「宏远建安」（1 条）为同一单位的全称与简称，脚本列入 `nameAmbiguity` 并在报告开头与第五节提示，**两个名称各自成行**——得分为 79 分与 95 分两行，而不是合并后的一行 74 分。合并与否须人工确认后回到源记录统一名称再重跑。
2. **严重程度为空绝不按最低档计分**：主样例第 7 行「脚手架挂牌信息填写不完整」严重程度为空、第 12 行「临时用电线缆敷设不规范」填「待定级」无法归类，两条均进 `undetermined`，`deduction` 为 `null`。宏远建安工程有限公司扣分为 21 分而非 23 分（若按一般违章 −2 兜底则为 23），安泰机电安装有限公司为 10 分而非 12 分。
3. **默认口径免责标注**：不传 `--rules` 时，`performance.md` 开头、得分汇总表旁、`performance.json` 的 `meta.rulesNotice` 三处均写「采用默认口径，非厂内正式口径，结果仅供参考」；传入 `--rules` 后该提示语消失，改标「厂内口径（文件名）」。
4. **声明行**：`performance.md` 开头与末尾各一处「本数据为车间（属地单位）侧记录汇总，承包商考核由安全环保部门归口、业务主管部门配合，分档定性与处罚按厂内制度决定；评分口径若非厂内正式口径，结果仅供参考。」
5. **产出不含定性判断**：脚本正文不出现「能力差」「不建议再用」等用语；这些词只作为「不得使用」的反例出现在评价说明的占位提示里。
6. **未整改单列**：主样例 4 条未整改项（用火器材配置、换热器试压、焊接进度、保温边角料清理）进「四、未整改项」；整改情况为空的记录不被算作未整改。
7. **区间过滤**：主样例最后一行记录日期早于 `--from`，计入 `outOfRange` 并 warning，不进本期统计与评分。
8. **类型无法归类同样不计分**：脏数据样例中类型填「其他」的一条进 `undetermined`，未按任一维度最低档扣分。
9. **分档边界**：90 分归「优」、80 分归「良」、70 分归「一般」、69 分归「差」（由 selftest 第 1 组断言覆盖）。
10. **承包商编码分组**：系统导出样例有「供应商编码」列，同一编码 V100023 下「华鑫机电安装有限公司」与「华鑫机电」合并为一行（名称并列展示），不进名称待确认；无编码列的主样例仍按名称分组。
11. **违章三档口径**：「严重违规」归严重违章（−5），不归重大违章；施工质量「不符合」不自动归质量不合格，进未判定并提示用户明确。
12. **系统列名**：「检查日期 / 供应商编码 / 作业单位名称 / 许可证编号 / 违章等级 / 闭环情况 / 属地检查人」均可识别；「监护人」不作检查人别名。

## 再生样例

```bash
node scripts/make-sample.js --out examples            # 默认 seed=1
node scripts/make-sample.js --out examples --seed 7   # 记录日期变化，结论不变
```

# 交叉作业冲突检测（cross-operation-conflict）

面向中石化体系炼化厂车间（运行部）设备员与属地作业统筹人员，检测同一时段同一区域内多项作业之间的冲突，在作业开始前发现风险叠加。**冲突判定由脚本按规则矩阵完成，模型只负责成文；不得自行判定某组合"可以接受"。**

车间设备员可做的部分：把当天的作业票清单过一遍、发现冲突提前协调、把结果提交统筹。**交叉作业的最终安排与作业许可由安全环保部门按《中国石化作业许可管理规定》与厂内制度决定**，本技能只出冲突清单与建议。

## 适用条件
- 用户说"看看有没有交叉作业 / 这几个活会不会冲突 / 同一区域几项作业 / 作业冲突检查"，并给出（或即将给出）作业票清单或作业计划表。
- 覆盖三类冲突：空间冲突（同一区域上下或相邻）、风险冲突（用火与可燃物释放、吊装与下方作业、盲板抽堵与同系统作业等）、资源冲突（同一监护人（属地或作业单位）、同一起重设备（只比对吊车、葫芦等起重类设备或吊装作业所用设备，普通机具同名不判）、同一电源回路、同一消防覆盖区）。
- 同位号的"受限空间作业 + 用火作业"（罐内/塔内用火）是双票作业的合法常态，**只列为提示项（核对两票关联、气体分析、双监护），不计冲突**。
- 不适用：单张作业票的合规预检（permit-precheck-bridge）；作业现场的监督执行（site-supervision-points）；作业许可的批准与统筹决定。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含工作表「作业清单」（作业许可台账、作业计划亦可），字段见 `references/input-spec.md`（作业编号/许可证编号、作业类型/作业类别、位号/功能位置、区域/作业地点、标高、起止时间、作业单位、属地监护人、作业单位监护人、涉及介质、使用设备、所属系统；电源回路与消防覆盖区两列在作业许可系统导出中通常缺省，缺省属正常）。**脚本不读作业票 PDF 与图片**：票面须先整理成清单。
- 必填信息：车间名称、检测日期。可选：区域划分表（定义哪些位号属同一区域）、厂内冲突判定口径（`--rules`，模板 `assets/templates/rules-template.xlsx`）、层高（标高写"3 层"时的折算米数）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得人工比对冲突。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 作业票系统 | `get_permits` | `workshop`：车间；`date`：检测日期，与 `--date` 相同，不填为今天 | `--input`（目录 A） |
| 作业票系统 | `get_area_map` | `workshop`：车间 | `--area-map`（目录 B） |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；表中目录字母相同的放同一个目录，不同字母分开放，把目录作为“交给脚本”一列的参数值。
2. `get_permits`：返回检测日当天有效（开始不晚于当天、结束不早于当天，含检测日之前开、之后才结束的多日票）且未关闭的票，多日票照常参与判定，不必再另查。工具按日期取票，在检测日 00:00 正好结束的票也会返回，脚本按时刻判定它不覆盖检测日，列入跳过。`workshop` 必须带，不带会混入其他车间的票。

## 操作步骤
1. **确认检测范围与区域口径** —— 车间、检测日期、区域划分依据（按装置/按框架/按位号前缀）；**区域口径不明确时必须确认，口径错误会导致冲突漏判**。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/conflict.js" --input "<xlsx路径>" --workshop "<车间名>" --date <YYYY-MM-DD> --out "<输入同目录>/交叉作业"
   ```
   可选：`--area-map "<区域划分表xlsx>"`、`--rules "<厂内冲突口径xlsx>"`（覆盖规则严重度/启用/建议措辞，不新增规则）、`--window <时间重叠判定分钟数，默认 0>`、`--floor-height <层高米数，默认 4>`、`--radius <相邻区域判定说明>`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺列/时间无法解析/区域字段为空/位号不在区域表/层高折算为推断值等）。脚本用法详见 `scripts/README.md`。
   - 区域或标高字段为空：该作业归入 `undetermined`（无法判定空间关系）单列一节并 warning，**绝不按"不在同一区域"处理**。
   - 介质字段为空时涉及风险冲突判定：对应冲突项标 `undetermined`，**不得因缺数据而判定为无冲突**。
   - 标高写"3 层/三层"：按 `--floor-height` 折算并标"推断，待确认"。
   - 多日作业票：重叠分钟与时段重叠视图只算检测日当天（00:00~次日 00:00）的部分；在检测日 00:00 结束的票不覆盖检测日，列入跳过。结束时间只写日期的，按当日 24:00 处理并提示核实。
3. **读取 conflicts.json** —— 从 `<输出目录>/conflicts.json` 获取：`spatialConflicts`（空间冲突组）、`riskConflicts`（风险冲突组，含命中的冲突规则与严重度）、`resourceConflicts`（资源冲突组）、`advisories`（同位号双票作业提示项，不计冲突）、`undetermined`、`timeline`（时段重叠视图）、`counts`。
4. **撰写"冲突分析与协调建议"** —— 读 `references/conflict-rules.md` 的表述口径，撰写 200~400 字，按"总体情况 → 高严重度冲突与建议措施 → 一般冲突 → 提示项与无法判定项、需补充信息 → 建议协调安排"结构，替换 `conflicts.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**冲突组数、命中规则一律引用 conflicts.json；协调建议只提"建议错时/建议增加监护/建议先后作业"等，不得表述为已批准的安排；提示项不得写成冲突。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `conflicts.md` 与 `conflicts.json`。**必须保留声明行："本检测为辅助排查，交叉作业的最终安排与许可由安全环保部门按厂内制度决定；未列出的冲突不代表不存在"，不得删除或改写。**

## 预期结果
- `conflicts.md`：交叉作业冲突报告，七节：一、检测概览（含提示项计数与作业清单）；二、空间冲突；三、风险冲突（含"提示项：同位号受限空间 + 用火双票作业"小节）；四、资源冲突；五、无法判定项；六、时段重叠视图；七、冲突分析与协调建议（分析段占位）。有跳过作业时另有"附一、已跳过的作业"，有 warnings 时另有"附二、数据提示"；开头与末尾各一处固定声明行。
- `conflicts.json`：冲突组与命中规则；`summary.json`：脚本末行摘要。
- 交付时向用户说明：检测作业数、各类冲突组数、高严重度冲突数、提示项数、无法判定数、采用的判定口径（默认矩阵或厂内口径）、脚本 warnings（如有）。

## 不适用范围
- 不批准或否决作业安排，不替代安全环保部门统筹。
- 不做单张作业票的合规判定与级别判定。
- 不识别未录入清单的作业，不保证冲突检出的完备性。
- 不做现场实际空间关系的勘察与确认。
- 不读作业票 PDF / 图片。

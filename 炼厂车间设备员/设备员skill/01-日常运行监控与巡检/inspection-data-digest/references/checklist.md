# 交付自检清单

运行脚本后、交付前逐项核对。

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；若为 `false`，已把 `error` 原文告知用户并终止，未手工汇总
- [ ] `warnings` 已逐条告知用户，未隐去任何一条（含"带单位测值已剥离单位，请核对单位一致"）
- [ ] `status.json` 与 `digest.md` 均已生成
- [ ] 工作表名无法识别时已用 `--source-type` 指定来源类型，未把表名猜成某一来源
- [ ] 夜班记录被跳过时已问清班次日起算时刻并用 `--shift-window` 重跑

## 数字一致性
- [ ] 报告中每个数字都能在 `status.json` 的 `counts`（含 `sixTier`、`special`）中找到对应，未自行统计
- [ ] 未提供台账时，漏检显示「未提供台账，无法识别漏检」，未出现具体漏检数
- [ ] 无法解析的测值显示「—」，未出现 0

## 内容完整性
- [ ] 状态概览按 运行/备用/检修/停用/异常/未判定 六档列出；无运行状态列时保留【注意】提示
- [ ] 特护设备异常已置顶并保留【注意】上报提示
- [ ] 记录冲突一节保留了全部原始记录，含检查项、来源、测值、时间、sheet 与行号
- [ ] 未判定项单列，注明了原因（结果无法归类 / 无任何判定依据）
- [ ] 跨班次被跳过的记录已在 warnings 中体现并告知用户
- [ ] 声明行保留在 md 末尾

## 分析段
- [ ] 已替换 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字
- [ ] 字数 200~400
- [ ] 四段结构齐全：总体状态、异常项与影响（特护优先）、漏检与数据缺口、需上报或跟进
- [ ] 未做故障原因诊断，未出现「轴承损坏」「不对中」这类判定
- [ ] 未替执行人补填未检项的结论
- [ ] 用语为中石化口径：维修通知单（不是"开工单"）、车间设备主任 / 公司设备管理部门（不是"机动处"）

# 输入规格：巡检点检数据汇总（中石化体系炼化厂口径）

## 支持格式
- `.xlsx`（推荐）或同结构 CSV 目录（文件名 = sheet 名，UTF-8 或 GBK）
- 可一次传入多个文件，用英文逗号分隔：`--input a.xlsx,b.xlsx`（按装置分文件导出的常态可直接并入）
- 不读 PDF；纸质巡检记录需先录成 Excel

## 三条线来源工作表（至少提供一张）

sheet 名匹配规则：去空白与「表」字后做包含匹配。

| 来源类型 | 可识别的 sheet 名 | 典型系统 | 记录形态 |
|---|---|---|---|
| 操作工巡检（`patrol`） | 巡检记录、巡检明细、智能巡检、巡检数据、巡检 | 智能巡检 APP 导出 | **一行一检查项**（功能位置-检查项-测值-是否报警），脚本按位号聚合 |
| 专职点检（`spotcheck`） | 点检记录、点检数据、点检明细、点检仪、点检 | 点检仪导出 | 一行一点检项，含实测值与报警标志 |
| 状态监测（`monitor`） | 状态监测、监测记录、在线监测、测振、测温、油液 | 测振仪/在线监测/油液分析 | **无「检查结果」列**，只有测值与上限/下限 |

sheet 名无法识别（如 `Sheet1`）时：默认报错并提示；加 `--source-type patrol|spotcheck|monitor` 后把未识别的表按该类型读取。

## 列定义（三类来源共用）

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | 设备位号 / SAP 功能位置；为空的行会被跳过并 warning |
| 设备编号 | 否 | SAP 8 位设备流水号，单独展示，**不作位号** |
| 设备名称 | 否 | 缺失时报表显示 — |
| 检查结果 | 否* | 执行人填写的结论，见「状态取值」 |
| 是否报警 | 否* | 智能巡检/点检仪的报警标志，见「报警取值」 |
| 参数名（检查项） | 否 | 如「机封泄漏」「振动速度(mm/s)」；同位号多行按检查项区分 |
| 参数值（测值） | 否* | 数值，可带单位（78℃ / 4.5mm/s / 0.35MPa 自动剥离并 warning 一次）；无法解析时 null 并 warning，**绝不按 0 计** |
| 上限 / 下限 | 否* | 高报 / 低报限值；与测值配合判异常 |
| 运行状态 | 否* | 运行 / 备用 / 检修 / 停用（六档状态来源） |
| 异常描述 | 否 | 异常项的具体描述；**「备注」列不再作为异常描述** |
| 检查时间 | 否 | 见「时间字段与班次日」 |
| 检查人 | 否 | |
| 区域 | 否 | 装置区 / SAP 工厂区段 |
| 专业 | 否 | 静设备 / 动设备 / 电气 / 仪表 |
| 重要度 | 否 | ABC 标识；值为「特护」「A」「关键」时标记为特护设备 |

## 判定依据优先级（逐行）

1. 「检查结果」非空 → 按状态取值归类
2. 否则「是否报警」非空 → 是/否
3. 否则「测值」与「上限/下限」至少一个有值 → 超上限或低于下限为异常
4. 否则「运行状态」值本身是正常/异常类措辞 → 按其归类；是运行/备用/检修/停用 → 记录按正常计（结论由运行状态给出）
5. 都没有 → **未判定**

**不默认**：四者都空的记录不按正常处理。报告头「判定依据」列出本次实际用到的依据。

## 状态取值（检查结果列）

| 归类 | 可识别的写法 |
|---|---|
| 正常 | 正常、良好、合格、完好、无异常、未见异常、无泄漏、未发现异常、无问题、OK、√、运行正常、Running |
| 异常 | 异常、不正常、故障、缺陷、不合格、超标、报警、泄漏、有问题、偏高、偏低、异响、NG（按单词边界，Running 不算） |
| **未判定** | 以上都不匹配的其他文字（如「待查」「待确认」） |
| **未填写** | 空单元格且无其它判定依据 |

否定式（无/未见/未发现/没有/不 + 异常词）先于异常词判断，「无异常」是正常。

## 报警取值（是否报警列）

| 归类 | 可识别的写法 |
|---|---|
| 报警（异常） | 是、Y、YES、TRUE、1、报警、超限、高报、低报、高高报、低低报、H、HH、L、LL、越限、告警、ALARM |
| 未报警（正常） | 否、N、NO、FALSE、0、正常、无、未报警、无报警、未超限、不报警、OK |
| 无法识别 | 其它写法 → warning，该行不以报警判定，落到下一级依据 |

## 一行一检查项的聚合规则

- 同一位号的多行（含跨来源）合并为一台设备；`itemCount` 为检查项行数，`abnormalItemCount` 为异常项行数。
- 任一检查项异常 → 设备异常；异常清单的「异常检查项/描述」优先取异常描述列，无则拼「检查项 测值（上限/下限） 报警」。
- **冲突**只在"同一检查项（或均无检查项）既有正常又有异常"时成立；不同检查项一正常一异常是正常的多项检查，不算冲突。

## 六档设备状态

`stateCn`：运行 / 备用 / 检修 / 停用 / 异常 / 未判定。

- 异常优先：检查结果异常的备机显示「异常」。
- 有「运行状态」列：按其值归档；值为空或无法识别 → 「未判定」（不默认为运行）。
- 无「运行状态」列：检查结果正常的设备按「运行」计，报告加【注意】提示。
- `state`（normal/abnormal/unknown/unfilled）与 `counts.normal/abnormal/unknown` 保持原键名，供 `equipment-daily-report`、`meeting-material-builder` 读取。

## 时间字段与班次日
- 支持：`2026-09-21 08:15`、`2026/9/21 8:15`、`2026年9月21日`、Excel 日期单元格、Excel 日期序列号
- 默认按自然日：**记录时间不是汇总日期的行会被跳过并 warning**
- `--shift-window HH:MM`（如 `08:00`）：记录时刻早于该时刻的归**前一班次日**，夜班 23:30 与次日 02:10 都属同一班次日；只有日期无时刻的记录不回拨
- 时间列缺失时不做跨日过滤，全部记录参与汇总

## 设备台账（可选，`--ledger`）

用于识别漏检与特护标记。可直接用 SAP PM 技术对象清单（功能位置 / 设备 / 技术对象描述 / 工厂区段 / ABC标识）。sheet 名可识别：设备台账、台账、设备清单、技术对象、功能位置清单。缺失此项时漏检输出 `null`（报表显示「未提供台账，无法识别漏检」），**不会按记录表倒推设备总数**。

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号（功能位置） | 是 | |
| 设备名称 | 否 | |
| 区域 / 专业 | 否 | |
| 重要度（ABC标识） | 否 | 「特护」「A」标记特护设备；台账标记会补到记录表中对应设备 |
| 是否需巡检 | 否 | 填「否」「不」「N」「no」的设备不计入漏检（如长期停用、封存） |

## 上一日 status.json（可选，`--prev`）

传入前一日本脚本产出的 `status.json`，用于对比 `state` 变化。缺失时状态变化章节输出「未提供上一日 status.json」。

## 会被跳过的行
- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 提示）
- 位号为空的行（warning 提示）
- 记录时间（或班次日）不在汇总日期的行（warning 提示）

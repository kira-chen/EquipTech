# 汇总口径与表述规范（中石化体系炼化厂车间设备员）

## 一、合并与按位号聚合

同一位号在多张表、多条记录中出现时，合并为一台设备的一条状态，`results` 中保留全部原始记录（含检查项、测值、限值、报警标志与判定依据）。智能巡检 APP、点检仪导出是"一行一检查项"，聚合后：任一检查项异常 → 设备异常；全部检查项正常 → 设备正常。

## 二、判定依据与不默认

逐行按 检查结果 → 是否报警 → 测值对上限/下限 → 运行状态 的优先级判定。状态监测表没有"检查结果"列是常态，用"是否报警"或"测值 vs 限值"判定；四者都没有的记录进未判定。

**禁止**：把没有任何判定依据的记录按正常处理；把"备注"列的自由文本当作异常描述。

## 三、冲突就严原则

同一设备**同一检查项**（或均无检查项的整机结论）既有「正常」又有「异常」记录时：

1. 整机状态判为**异常**（就严）
2. 该设备列入「记录冲突」一节，**完整保留每一条原始记录**（检查项、来源、结果、测值、时间、记录人、sheet 与行号）
3. 报告中注明判定依据：「就严原则：同一检查项既有正常又有异常记录时整机判为异常」

不同检查项一正常一异常（机封无泄漏、轴承温度报警）不是冲突，是一台设备多项检查的正常结果。

**禁止**：静默取其中一条、按时间取最新、按来源权重取其一而不披露。冲突必须让设备员看见并自行核实。

## 四、六档设备状态

口径对照第六节：设备状态分 **运行 / 备用 / 检修 / 停用 / 异常 / 未判定** 六档，不得只分正常/异常。

- 异常优先于运行状态（备机点检异常显示「异常」）。
- 有「运行状态」列按其值归档，值为空或无法识别 → 未判定；无该列时检查结果正常的设备按「运行」计并在报告加【注意】。
- 检修中的备机不算完好备机（备机完好口径由 `standby-rotation-reminder` / 月报技能负责，本技能只给状态）。

## 五、特护设备

记录表或台账「ABC标识/重要度」为「特护」「A」「关键」的设备标记 `special=true`：异常清单与漏检清单置顶，异常时报告加【注意】提示当日上报车间设备主任并通知专业工程师。特护设备日巡检要求以厂内特护设备管理规定为准，本技能不替用户判定是否满足巡检频次。

## 六、未判定处理

检查结果为空或无法归类、且无其它判定依据时，状态为「未判定」，单列一节并注明原因。

**禁止**：按正常处理、按异常处理、或从记录中剔除。

## 七、漏检识别

仅在提供 `--ledger` 时输出。判定方式：台账中存在（是否需巡检非"否"）、但本班次日无任何记录的设备。

**禁止**：未提供台账时按记录表推算设备总数后倒推漏检数。

## 八、班次日归属

夜班跨 0 点记录按"班次日"归属（口径对照第八节）：`--shift-window 08:00` 时，次日 02:10 的记录归本班次日，不按自然日丢弃。不给该参数时按自然日处理并在 warnings 里列出被跳过的记录，设备员发现夜班记录被跳过应补该参数重跑。

## 九、分析段表述规范

撰写 200~400 字，结构固定为四段：

1. **总体状态**：本日覆盖设备数、六档分布、特护设备状况。
2. **异常项与影响**：特护设备优先，逐条或分类说明异常设备、检查项、测值与限值、可能影响的生产环节。只陈述记录中写明的内容。
3. **漏检与数据缺口**：漏检设备、未判定项、跨班次被跳过的记录、缺失的数据来源、带单位测值已剥离单位需核对。
4. **需上报或跟进事项**：建议登记缺陷（提报维修通知单）、建议通知专业工程师、建议下一班次重点复查的设备。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 异常原因 | 「点检记录振动偏高且有异响」 | 「轴承损坏」「不对中导致」 |
| 影响判断 | 「可能影响塔顶回流稳定，建议核实」 | 「已造成塔顶波动」 |
| 处置建议 | 「建议登记缺陷、提报维修通知单并通知动设备工程师」 | 「应立即停机检修」「开工单」 |
| 数字 | 引用 status.json 的 counts | 自行统计或估算 |
| 交付对象 | 「报车间设备主任复核」「必要时报公司设备管理部门」 | 「报机动处」 |

### 硬约束

- **不做故障原因诊断**。异常只复述记录内容，原因初判交由 `anomaly-triage-advisor`，定性由专业工程师归口。
- **不替执行人补填未检项**。漏检就是漏检，不得写「预计正常」。
- **不重新判定巡检结论**。以记录表中执行人填写的结论、报警标志或限值为准。
- **数字一律引用 status.json**，不得自行统计。
- **不生成工单**。车间设备员提报的是维修通知单，工单由计划员/维修单位在 SAP 创建。

## 十、制度引用

- 巡检点检三条线与特护设备日巡检：依据《中国石化设备管理规定》《炼化企业设备管理技术规定》及厂内巡检点检管理规定，频次与检查项以厂内规定为准，本技能不转述具体数值。
- 设备状态六档与备机完好：依据厂内设备状态管理口径（口径对照第六节）。
- 振动限值：状态监测表自带的上限/下限为准；需要分区参考时用 `parameter-trend-alert`（ISO 10816 / GB/T 6075 只引分区概念）。

## 十一、下游衔接

- 异常项需要登记缺陷、提报维修通知单 → `defect-intake-grading`
- 异常项需要初步判断原因 → `anomaly-triage-advisor`
- 多期参数积累后看趋势 → `parameter-trend-alert`
- 本日汇总进设备日报 → `equipment-daily-report`（直接读 status.json；六档计数在 `counts.sixTier`，特护计数在 `counts.special/specialAbnormal`）
- 明日巡检任务清单 → `inspection-task-dispatch`（可参考本日异常与漏检设备）

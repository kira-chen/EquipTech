# 输入规格：备用设备切换与盘车提醒

## 支持格式
- `.xlsx`（推荐）或同结构 CSV 目录（文件名 = sheet 名，UTF-8 或 GBK）
- 一次一个文件：`--input 备用设备数据.xlsx`；两张工作表放在同一个文件内

sheet 名匹配规则：去空白与「表」字后做包含匹配，因此「备用设备台账」「备用设备台账表」「主备设备台账」「备用设备定期切换台账」均可识别；记录表可叫「切换盘车记录」「切换记录」「盘车记录」。

## 一、备用设备台账（必需）

缺此表脚本直接报错终止 —— 它是到期判定的唯一数据源。可直接用 EM 设备管理信息系统的备用设备台账导出，或 SAP PM 技术对象清单整理后的车间台账。

**以机组/泵组为键**：有「机组/泵组/机组号」列时用该列作机组键；无此列时用「主用位号/备用位号」组合作键并 warning。同一机组号重复出现只 warning，不合并。

| 列名 | 必需 | 说明 |
|---|---|---|
| 主用位号 | 是 | 台账登记的**初始**主用位号（功能位置）；当前主用由切换记录推导，见下方「当前主用」 |
| 备用位号 | 是 | 台账登记的初始备用位号 |
| 机组 | 否 | 机组号 / 泵组号；缺失时以主用/备用位号组合作键 |
| 设备名称 | 否 | 设备描述 / 功能位置描述；缺失时报表显示 — |
| 装置 | 否 | 装置名称 / 工厂区段 / 单元；只展示 |
| 备机状态 | 否 | 备用 / 热备 / 检修中 / 停用 等，见下方「备机状态取值」；无此列时所有备机按备用处理并 warning，备机完好台数不计算 |
| 切换周期 | 否* | 见下方「周期表达式」；**为空或无法解析时该项进「无法判定」** |
| 盘车周期 | 否* | 同上 |
| 试运周期 | 否 | 与「上次试运日期」**都为空**时视为该机组不做试运，不计入未判定；只缺其一则进「无法判定」 |
| 上次切换日期 | 否* | **为空或无法解析时该项进「无法判定」**；晚于基准日期时按日期越界进「无法判定」 |
| 上次盘车日期 | 否* | 同上 |
| 上次试运日期 | 否 | 同上（配合试运周期） |

\* 周期与上次执行日期任一缺失即无法算到期日，**脚本绝不按一月一次之类的默认周期替用户设定**，也不从切换盘车记录里倒推上次执行日期。

### 主备位号配对 —— 关键口径

主用位号与备用位号**必须成对填写且不相同**，脚本才认为这一行是一个有效机组。以下三种情形进 `pairingIssues` 单列并 warning，该行**不参与到期判定、不参与执行率统计、不计入备机完好**：

| 情形 | 处理 |
|---|---|
| 主用位号为空 | 单列，注明「主用位号为空，无法确定主备配对关系」 |
| 备用位号为空 | 单列，注明「备用位号为空，无法确定主备配对关系」 |
| 主用与备用位号相同 | 单列，注明「主用位号与备用位号相同」 |

**脚本绝不按位号尾字母（A/B）、名称相似度、相邻行顺序或任何规则自行猜测配对关系。** 配对关系必须由设备员在台账中补齐后重跑。

主用位号与备用位号都为空的行按空行跳过并 warning，不计入配对异常。

### 当前主用（可变角色）

台账「主用位号/备用位号」只是初始角色，每次切换后互换。脚本按「切换盘车记录」中**最近一次（≤ 基准日）带「切换后主用/切至位号」的切换记录**推导当前主用：

- 切至位号在该机组两个位号之内 → 当前主用 = 切至位号，`pairs[].roleSource` 写「切换记录」并记该条日期；
- 切至位号不在两个位号内、记录表没有方向列、或没有切换记录 → 按台账展示，`roleSource` 写「台账」并 warning；
- **不按切换次数奇偶猜测当前主用**；记录的切换日期晚于台账「上次切换日期」时只 warning 提示核对台账，到期仍按台账日期算（不倒推）。

### 备机状态取值

| 归类 | 可识别的写法 | 处理 |
|---|---|---|
| 备用（可投用） | 备用、备用完好、完好、可用、热备、冷备、正常、良好、备妥、随时可投 | 进到期清单；计入备机完好分子 |
| 检修中 | 检修中、检修、维修中、维修、在修、待修、消缺中、消缺、待验收、施工中 | **不进到期清单、不进长期未切换、不参与执行率**，单列「备机检修中与停用」 |
| 停用 | 停用、长期停用、封存、停运、退出、报废 | 同上 |
| 未填 / 无法识别 | 空、或以上都不匹配 | 仍进到期清单（提醒从严），但**不计入备机完好分子，比率不计算**（不按备用默认） |

### 周期表达式（共享库 `parsePeriod`）

| 写法 | 折算 |
|---|---|
| `每班` / `1班` | 8 小时（班次级，见下） |
| `每2小时` / `2h` | 2 小时（班次级） |
| `每天` / `1天` / `30d` / `30日` | 天 |
| `每周` / `2w` / `2周` | 7 / 14 天 |
| `每月` / `3m` / `3个月` | 30 / 90 天（按每月 30 天） |
| `每季` / `1q` / `1季度` | 90 天 |
| `半年` | 182 天 |
| `每年` / `1y` / `1年` / `两年` | 365 / 730 天 |
| 纯数字 `180` | 180 天 |
| **「随机组检修」「视工况」「不定期」** | **无法解析 → 该项进「无法判定」** |
| **「运行 2000 小时」「2000h」** | 运行小时周期，本技能不按日历判定 → 进「无法判定」并提示用 runtime-hours-tracker |

应到期日 = 上次执行日期 + 周期天数。**班次级周期**（每班、每 N 小时，周期 < 1 天）按日粒度判定：上次执行为当日 → 临期（本日内按班次到期，`shiftLevel:true`）；早于当日 → 逾期；执行率不折算计划次数（显示「—」，按班记录请查巡检/盘车班记录）。

## 二、切换盘车记录（可选）

缺此表时不统计执行率、当前主用按台账，warning 提示，报告第六节写「未提供」，`counts.records` 与各执行率为 `null`（不是 0）。

| 列名 | 必需 | 说明 |
|---|---|---|
| 日期 | 是 | 实际执行日期；无法解析时该条不计入执行率并 warning |
| 位号 | 是 | 主用或备用位号均可，脚本按台账映射到所属机组；**台账中查无此位号时该条不计入执行率**，不猜测归属（多条时合并为一条 warning，列出位号与条数）。无「位号」列而有「设备编号」列时用设备编号兜底并 warning（SAP 设备编号与位号不同） |
| 作业类型 | 是 | 见下方归类表；无法归类时该条不计入执行率并 warning |
| 切换后主用 | 否 | 切至位号 / 投用位号 / 开泵位号；有此列才推导当前主用 |
| 执行人 | 否 | |
| 备注 | 否 | |

### 作业类型归类

| 原文含 | 归入 |
|---|---|
| 切换 / 倒泵 / 轮换 / 倒机 | 切换 |
| 盘车 | 盘车 |
| 试运 / 试车 | 试运 |
| **其余写法（检查、维护、清洗…）** | **无法归类 → 不计入执行率并 warning** |

## 三、执行率统计区间

- 提供 `--from` 时：区间为 `--from` 至 `--date`。
- 未提供 `--from` 时：按默认区间（基准日前 180 天）统计，并 warning 写明。**该默认仅是统计口径，不影响任何到期判定，也不替代台账里的周期设定。**
- 区间外的记录计入 `records.outOfRange`，不计入执行率分子。

计划次数 = ⌊区间天数 ÷ 周期天数⌋；实际执行次数 = 区间内可归属、可归类的记录条数。

**分母为 0（区间短于一个周期）或无法计算（周期缺失/无法解析/班次级周期）时，执行率为 `null`，报告显示「—」，绝不写 0%。** 分母 > 0 而实际执行为 0 时才写 `0.0%`。备机检修中/停用的机组不参与执行率。

合并后的误配检查：
- **「设备编号」不作位号别名**：SAP 的「设备」列是 8 位流水号，归「设备编号」；裸「设备」列不会被当作设备名称。记录表无位号列时才用设备编号兜底并 warning。
- **「项目」不作作业类型别名**（避免与检修项目/工程项目列误配）；记录表只有「项目」列时报缺列 warning，请改为「作业类型」。
- 台账同时有「备机状态」与裸「状态」列时「备机状态」先认领。

表头行识别：取前 10 行中命中必需列最多的一行，因此首行是标题、第三行才是表头的 EM / SAP 导出表也能读。

## 日期字段
- 支持：`2026-09-21`、`2026/9/21`、`2026年9月21日`、`20260921`、Excel 日期单元格、Excel 日期序列号
- 无法解析时不猜测：台账的上次执行日期 → 该项进「无法判定」；记录表的日期 → warning 且该条不计入执行率

## 会被跳过的行
- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 提示）
- 主用位号与备用位号均为空的行（warning 提示）
- `--equipment` 限定范围外的行（warning 提示行数）

## 与下游技能的字段口径

`rotation.json` 中 `pairs[]` 的 `groupKey`（机组）、`mainTag`/`standbyTag`（当前主用/备用）、`standbyStatus`、`standbyAvailability`（备机完好台数与比率）可直接被 `equipment-daily-report` / `equipment-weekly-monthly-report` 读取，用于日报周报的「备机完好」一节；位号口径与 `inspection-task-dispatch`、`runtime-hours-tracker` 一致。

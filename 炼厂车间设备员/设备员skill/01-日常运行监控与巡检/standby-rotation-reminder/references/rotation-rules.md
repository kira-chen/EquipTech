# 备用设备切换盘车口径与表述规范（中石化体系炼化厂车间设备员）

## 零、岗位边界、制度依据与必须保留的说明行

- 本技能站在**车间（运行部）设备员**视角：维护备用设备台账与切换盘车记录、出到期清单、统计执行率与备机完好台数，报车间设备主任 / 公司设备管理部门（机动部/设备部）。
- **由其他专业归口**：切换条件确认（工艺）、操作票执行（操作班组）、备机检修工单创建（维修单位/计划员，车间只提维修通知单）、备机状态评估与故障诊断（设备工程师，异常初判可接 anomaly-triage-advisor）。
- 制度依据（只引名称，不转述数值）：《中国石化设备管理规定》《炼化企业设备管理技术规定》中关于备用设备管理、定期切换与盘车的要求；切换周期、盘车周期、长期未切换倍数以厂内制度文件与台账为准，技能不替厂里定周期。

报告头部与管理说明段之后都保留这句原文，交付时不得删改：

> **切换实施前需由工艺确认具备切换条件并按操作票执行，本清单仅为周期提醒。**

末尾另有通用声明行："本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。"

本技能只做周期提醒，**不编制切换操作方案与操作票，不判定工艺是否具备切换条件，不代为下达切换指令。**

## 一、机组键与当前主用

- **以机组/泵组为键**：台账有「机组/泵组/机组号」列用该列；没有则用「主用位号/备用位号」组合作键并 warning。到期清单、长期未切换、执行率、备机完好都按机组统计，不按单台位号。
- **当前主用可变**：台账「主用位号/备用位号」是初始角色，每次切换后互换。脚本按切换记录中最近一次（≤ 基准日）带「切换后主用/切至位号」的记录推导当前主用，`pairs[].roleSource` 标「切换记录」或「台账」。
- **禁止**：按切换次数奇偶推断当前主用；切至位号不在机组两位号之内时自行改写；记录表没有方向列时凭名称猜测。这几种情况一律按台账展示并 warning。
- 记录的切换日期晚于台账「上次切换日期」→ 只 warning 提示核对台账，到期仍按台账日期算（**不从记录倒推**）。

正确表述：「P-1101 机组当前主用为 P-1101B（按 2026-05-09 切换记录推导），台账仍登记 A 泵为主用，请核对。」

## 二、到期判定

应到期日 = 上次执行日期 + 周期天数；以 `--date` 基准日比对。切换、盘车、试运三类工作各自独立判定：

| 分档 | 条件 | 说明 |
|---|---|---|
| 已逾期 | 应到期日 < 基准日 | 记录逾期天数与逾期程度 |
| 临期 | 0 ≤ 剩余天数 ≤ 提前提醒天数（默认 3，`--lead-days`） | 应排入近期计划 |
| 周期内 | 剩余天数 > 提前提醒天数 | 正常 |
| **无法判定** | 周期或上次执行日期缺失/无法解析/日期越界/运行小时周期 | **单列一节** |

### 班次级周期（每班 / 每 N 小时）

盘车周期常写「每班」。周期 < 1 天的按日粒度判定：上次执行为当日 → 临期（备注「班次级周期，本日内按班次到期」，`shiftLevel:true`）；早于当日 → 逾期。执行率不按日历区间折算计划次数（显示「—」），按班记录请查巡检/盘车班记录。

### 逾期程度

按逾期天数与周期的比值分档，**只作排序提示，不是设备风险等级**：

| 程度 | 条件 |
|---|---|
| 轻微逾期 | 逾期天数 ≤ 周期的 20% |
| 明显逾期 | 逾期天数 > 周期的 20% |
| 严重逾期 | 逾期天数 > 一个完整周期（已漏掉整轮） |

**禁止**把逾期程度写成设备状态结论（如「严重逾期即将抱轴」）。逾期程度只说明计划执行偏差。

## 三、无法判定处理

切换/盘车/试运周期为空、周期写法无法解析（「随机组检修」「视工况」）、周期为运行小时（「运行 2000 小时」）、上次执行日期为空或无法解析、上次执行日期晚于基准日期 —— 都归入「无法判定」，在 JSON 与报告中单列，注明缺哪个字段、出处行号。

**禁止**：
- 按默认周期（一月一次、三月一切、一周一盘）填补
- 按同类机组、同装置其他泵的周期推算
- 从切换盘车记录里最后一条日期倒推为「上次切换日期」后再算到期
- 归入正常或归入逾期任何一侧

正确表述：「P-1401 机组台账未填切换周期，无法判定到期，需设备员补齐台账后重跑。」运行小时周期提示：「P-1403 切换周期为运行 2000 小时，属运行小时维度，用 runtime-hours-tracker 判定。」

## 四、主备配对 —— 关键口径

主用位号与备用位号必须成对填写且不相同，该行才参与判定。主用为空、备用为空、主备同号三种情形一律进「主备配对异常」单列并 warning，该行不参与到期判定、执行率统计与备机完好。

**禁止**：
- 按位号尾字母 A/B、名称相同、相邻行顺序猜测配对
- 把只有一个位号的行当作「单台无备用」直接按该位号判定周期
- 把主备同号当作录入笔误自行改写

正确表述：「P-1501 机组台账未填备用位号，主备配对关系无法确定，本次未作判定，也未按位号规则猜测配对，请设备员核实台账。」

## 五、长期未切换

阈值 = `--overdue-factor` × 该机组切换周期（默认 2 倍，例如 1 个月周期 60 天、季度周期 180 天）；厂内有统一绝对天数规定时用 `--long-idle-days N` 覆盖。距上次切换天数 ≥ 阈值的机组进 `longIdle` 单列，注明阈值与阈值依据。无切换周期的机组不判（已在无法判定）；备机检修中/停用的机组不判。

长期未切换说明的是**备用设备长期不动可能存在启动困难**，属于需要安排盘车或试运确认可用性的提示，**不是对设备状态的判定**。

正确表述：「P-1102 机组距上次切换 205 天，超出 2 倍切换周期（120 天）阈值，建议安排盘车或备机试运确认可用性。」
不得写成：「备泵长期不动已锈死，必须解体检查。」

## 六、备机状态与备机完好

- 「检修中/维修/待修」「停用/封存」的备机：**不进切换/盘车/试运到期清单，不进长期未切换，不参与执行率**，单列「备机检修中与停用」；检修完工三级验收后由设备员更新台账「备机状态」，提醒随之恢复。
- **备机完好 = 可随时投用的备机台数 / 机组数**（与口径对照第六节"备机完好"一致）；检修中、停用备机不计入分子。
- 备机状态未填或无法识别：仍进到期清单（提醒从严），但**不计入分子、比率不计算**（显示「—」），不按「备用」默认。无「备机状态」列时比率为 null 并 warning。

正确表述：「本期 11 个机组中备机可随时投用 10 台，备机完好率 90.9%；P-1601 备机检修中，不进提醒清单。」

## 七、执行率

**执行率 = 实际执行次数 / 计划次数**

- 计划次数 = ⌊统计区间天数 ÷ 周期天数⌋
- 实际执行次数 = 区间内位号可归属、作业类型可归类的记录条数
- 统计区间：给了 `--from` 用 `--from`~`--date`；否则按默认区间（基准日前 180 天）并在报告中写明

### 分母为 0 的处理 —— 关键口径

计划次数为 0（统计区间短于一个周期，如年度切换配 180 天区间）或无法计算（周期缺失/无法解析/班次级周期）时：

1. 执行率为 `null`，报告显示「**—**」
2. **绝不写 0%** —— 0% 意味着「有计划但一次没做」，与「本区间内本就没有计划」是两回事
3. warning 说明分母为 0 或无法计算

分母 > 0 而实际执行为 0 时才写 `0.0%`，这才是真正的执行率为零。

### 记录归属

记录表位号在台账中查不到对应机组、或作业类型无法归入切换/盘车/试运时，该条**不计入执行率**并 warning，**不自行猜测归属或类型**。记录表无位号列而有「设备编号」列时用设备编号兜底并 warning（SAP 设备编号是 8 位流水号，与位号不同）。

## 八、管理说明表述规范

撰写 200~350 字，结构固定为五段：

1. **到期概览**：机组总数、切换与盘车的逾期/临期/周期内分布、无法判定与配对异常数量、备机完好台数。
2. **逾期项与启动失败风险**：逐条或分类说明逾期的机组、逾期天数。只陈述计划偏差与台账事实；可以提「备用设备长期不动存在启动困难风险」，不得给设备状态结论。
3. **长期未切换与检修中备机**：超出阈值的机组与未切换天数，建议安排盘车或试运确认可用性；检修中备机点名并提示验收后更新台账。
4. **执行率情况**：切换与盘车的计划次数、实际次数、执行率；分母为 0 的项说明「本区间内无计划」而非「执行率 0」。
5. **下一步安排**：补台账、核实主备配对与当前主用、排切换与盘车计划、联系工艺确认切换条件等。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 切换逾期 | 「P-1101 机组切换逾期 105 天，超出 1 个月周期」 | 「主泵已超期服役，随时可能损坏」 |
| 当前主用 | 「当前主用 P-1101B（按切换记录推导）」 | 「切了奇数次所以现在是 B 泵」 |
| 无法判定 | 「台账未填切换周期，无法判定到期」 | 「按一般一月一切估计已到期」 |
| 配对异常 | 「备用位号为空，主备配对无法确定，未作判定」 | 「按位号推测备用应为 P-1501B」 |
| 长期未切换 | 「距上次切换 205 天，超出 2 倍切换周期阈值，建议盘车或试运确认可用性」 | 「备泵已锈死需解体」 |
| 检修中备机 | 「P-1601 备机检修中，不进提醒清单，验收后更新台账」 | 「P-1601 切换逾期 150 天」 |
| 执行率分母 0 | 「本统计区间内无切换计划，执行率不适用」 | 「切换执行率 0%」 |
| 切换实施 | 「建议联系工艺确认切换条件后按操作票执行」 | 「明日切至 B 泵，先开备泵再停主泵」 |
| 数字 | 引用 rotation.json 的 counts 与明细 | 自行统计或估算 |

### 硬约束

- **不手工推算周期或到期日**，一律引用 rotation.json。
- **不按默认周期替用户设定**，缺周期就是无法判定。
- **不猜测主备配对关系，不猜测当前主用**。
- **不编制切换操作方案、操作票与安全措施**。
- **不判定工艺是否具备切换条件**，不代为下达切换指令。
- **不做备用设备状态评估与故障诊断**。
- **分母为 0 的执行率显示「—」，不写 0%。**
- 产出不用 emoji，醒目提示用「【注意】」「【未判定】」。

## 九、下游衔接

- 备机检修需登记缺陷、提维修通知单 → `defect-intake-grading` / `work-order-generator`（维修通知单草稿；工单由计划员创建）
- 切换作业涉及作业许可 → `permit-precheck-bridge`
- 备机试运中发现异常需初判 → `anomaly-triage-advisor`
- 运行小时周期的切换/检修到期 → `runtime-hours-tracker`
- 切换盘车情况与备机完好进设备日报/周报 → `equipment-daily-report`、`equipment-weekly-monthly-report`（直接读 rotation.json 的 `counts` 与 `standbyAvailability`）

# 备用设备切换与盘车提醒（standby-rotation-reminder）

面向中石化体系炼化厂**车间（运行部）设备员**，管理备泵、备机的定期切换、盘车与试运，避免备用设备长期不动导致启动失败；产出报车间设备主任 / 公司设备管理部门（机动部/设备部）。**到期判定、当前主用推导、执行率与备机完好台数统计一律由脚本完成，模型只负责成文；不得手工推算周期或替执行人补记录。**

## 适用条件
- 用户说"该切泵了吗 / 盘车到期清单 / 备用设备切换计划 / 备机多久没动了 / 切换执行率 / 备机完好台数"，并给出（或即将给出）备用设备台账与切换盘车记录。
- 覆盖三类周期性工作：主备切换、盘车、备用设备试运；周期写法支持 每班 / 每 2 小时 / 每天 / 每周 / 每月 / 每季 / 半年 / 每年 / 纯天数。
- **车间设备员可做的部分**：维护备用设备台账与切换盘车记录、出到期清单与执行率、提示检修中备机、把结果报车间与公司设备管理部门。
- **由其他专业归口的部分**：切换条件确认由**工艺**归口，操作票执行由**操作班组**归口，备机检修工单由**维修单位/计划员**创建；本技能只做周期提醒。
- 不适用：在用设备的巡检点检任务；运行小时到大修周期的判定；切换操作方案与操作票编制；工艺侧是否具备切换条件的判定。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含工作表「备用设备台账」（机组号、主用位号、备用位号、设备名称、备机状态、切换周期、盘车周期、上次切换日期、上次盘车日期）与可选的「切换盘车记录」（日期、位号/功能位置、作业类型、切换后主用），字段与 EM/SAP 导出列名见 `references/input-spec.md`。
- 必填信息：车间名称、基准日期（YYYY-MM-DD）。可选：提前提醒天数（默认 3 天）、执行率统计区间、指定机组范围、长期未切换倍数（默认 2 倍切换周期）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工判定到期。**

## 操作步骤
1. **确认车间与基准日期** —— 从用户消息或文件名中提取；不明确时向用户确认一次。检查台账是否含周期与上次执行日期，缺失时按 `references/input-spec.md` 提示补齐。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/rotation.js" --input "<xlsx路径>" --workshop "<车间名>" --date <YYYY-MM-DD> --out "<输入同目录>/切换提醒"
   ```
   可选：`--lead-days <提前提醒天数>`、`--from <执行率统计起始日期>`、`--equipment "<位号,位号>"`、`--overdue-factor <长期未切换倍数，默认 2>`、`--long-idle-days <显式绝对天数阈值，覆盖倍数口径>`。不传 `--out` 时写系统临时目录，建议始终传 `--out`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺表/缺列/周期无法解析/主备位号不配对/上次日期晚于基准日期/记录表无切换方向列/备机状态未填等）。脚本用法详见 `scripts/README.md`。
   - 周期或上次执行日期缺失：归入 `undetermined` 单列一节并 warning，**不得按默认周期（如一月一次）替用户设定**。
   - 主备位号无法配对：warning 单列，**不得自行猜测配对关系**。
   - 当前主用：按切换记录中最近一次带「切换后主用」的记录推导；记录无方向列时按台账展示，**不得按切换次数奇偶猜测**。
   - 备机状态为「检修中/停用」：不进到期清单，单列一节；状态未填或无法识别时仍提醒但不算备机完好率。
3. **读取 rotation.json** —— 从 `<输出目录>/rotation.json` 获取：`switchOverdue`、`switchDueSoon`、`turningOverdue`、`turningDueSoon`、`trialOverdue`、`trialDueSoon`（到期清单，含机组、当前主用/备用、逾期天数）、`longIdle`（长期未切换，含阈值依据）、`standbyUnavailable`（检修中/停用备机）、`standbyAvailability`（备机完好台数与比率）、`pairs`（每个机组的当前主用与角色来源 `roleSource`）、`undetermined`、`pairingIssues`、`executionRate`、`counts`。
4. **撰写"备用设备管理说明"** —— 读 `references/rotation-rules.md` 的表述口径，撰写 200~350 字，按"到期概览 → 逾期项与启动失败风险 → 长期未切换与检修中备机 → 执行率情况 → 下一步安排"结构，替换 `rotation-report.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**数量、天数、执行率一律引用 rotation.json。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `rotation-report.md` 与 `rotation.json`。**必须保留说明行："切换实施前需由工艺确认具备切换条件并按操作票执行，本清单仅为周期提醒"**，以及通用声明行"本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。"

## 预期结果
- `rotation-report.md`：备用设备切换盘车报告，八节：一、到期概览；二、切换逾期与临期；三、盘车逾期与临期（含试运）；四、长期未切换清单；五、备机检修中与停用；六、执行率统计；七、无法判定与主备配对异常；八、备用设备管理说明（分析段占位）；warnings 非空时附"数据提示"。
- `rotation.json`：到期判定、当前主用、备机完好与执行率结果；`summary.json`：脚本末行摘要。
- 交付时向用户说明：数据来源、切换与盘车逾期数量、长期未切换数量、检修中备机数量、执行率、脚本 warnings（如有）。

## 不适用范围
- 不编制切换操作方案、操作票与安全措施；不代为下达切换指令。
- 不判定工艺是否具备切换条件（工艺归口）。
- 不做备用设备的状态评估与故障诊断（异常初判用 anomaly-triage-advisor）。
- 不做运行小时累计与大修周期判定（用 runtime-hours-tracker）。

# 车间巡检任务清单（inspection-task-dispatch）

面向中石化体系炼化厂**车间（运行部）设备员**，把设备台账（SAP PM 技术对象 / EM 设备管理信息系统导出或车间自建台账）与巡检标准转成当班可执行的巡检/点检任务清单，供操作班组巡检、专职点检与特护设备日巡检使用。**任务范围、到期判定、优先级排序一律由脚本计算，模型只负责说明与成文；不得自行推算周期或补齐缺失设备。**

## 适用条件
- 用户说"排今天的巡检 / 这班点检任务 / 哪些设备该检了 / 特护机组今天检什么"，并给出（或即将给出）设备台账与巡检标准表。
- 适用于按日历周期（每天/每周/每月/每季/半年）或班次级周期（每班/每 2 小时）驱动的操作工巡检、专职点检与特护设备日巡检。
- **车间设备员可做**：汇总台账与标准、生成任务清单、把周期待确认与无标准项反馈给工艺/设备专业补齐。**由 XX 归口**：巡检标准与判定限值的制定与修订（工艺/设备专业）、特种设备法定定检（公司设备管理部门与检验机构）、人员排班与考勤（班组/人事）。
- 不适用：无台账只有口头设备名单；特种设备法定定检排期；人员排班与考勤统计；运行小时周期（运行 2000 小时）排期——运行小时用 runtime-hours-tracker。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含工作表「设备台账」「巡检标准」「上次巡检记录」（智能巡检 APP 导出的「巡检明细」「点检数据」亦可），字段与别名见 `references/input-spec.md`。
- 必填信息：车间名称、任务日期（YYYY-MM-DD）。可选：班次（给了则按标准表「适用班次」过滤）、班次开始时间、区域/专业、重要度、人员分组、临期阈值。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工推算任务清单。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 设备资产管理 | `get_equipment_ledger` | `workshop`：车间名；`for_skill=inspection-task-dispatch` | `--input` |
| 点检巡检App | `get_inspection_standards` | — | `--input` |
| 点检巡检App | `get_last_inspection` | `workshop`：车间名 | `--input` |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；把目录作为“交给脚本”一列的参数值。
2. `get_equipment_ledger`：输出精简台账，带区域、特护、是否需巡检。台账和上次巡检都按 `workshop`（与 `--workshop` 一致）取，不传会把全厂设备排进一个车间的清单。
3. `get_last_inspection` 的巡检时间带时分：班次级周期（每班）要按小时判逾期时，运行脚本加 `--time <班次开始时间>`。

## 操作步骤
1. **确认车间、日期与班次** —— 从用户消息或文件名中提取；班次不明确时按"全天"排（不按适用班次过滤），并告知用户。检查工作表是否齐全，缺失或表头不符时按 `references/input-spec.md` 提示用户补齐。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/dispatch.js" --input "<xlsx路径>" --workshop "<车间名>" --date <YYYY-MM-DD> --out "<输入同目录>/巡检任务"
   ```
   可选：`--shift "<班次>"`（按适用班次过滤）、`--time HH:mm`（班次开始时间，班次级周期按小时判逾期）、`--area <区域>`、`--discipline <静设备|动设备|电气|仪表>`、`--criticality <A|B|C>`、`--group "<人员分组>"`、`--due-soon <10%|N>`（临期阈值，默认周期的 10%）。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺表/缺列/周期字段无法解析/设备无巡检标准/班次级周期未按小时判定等）。脚本用法详见 `scripts/README.md`。
   - 周期字段为空或无法解析（含运行小时周期）的设备：脚本输出 warning 并归入「周期待确认」单列一节，**不得默认按日检处理，也不得静默丢弃**。
   - 建议始终传 `--out`；不传时默认写系统临时目录 `<os.tmpdir()>/itd-out`。
3. **读取 tasks.json** —— 从 `<输出目录>/tasks.json` 获取：`tasks`（任务清单：位号、设备编号、名称、区域、专业、特护、检查项、判定标准、所需工具、周期、建议顺序、优先级 P1~P6）、`special`（特护设备任务）、`overdue`（已逾期，日历周期按天、班次级周期按小时）、`dueSoon`（临期）、`unscheduled`（周期待确认）、`noStandard`（无巡检标准）、`otherShiftOnly`/`otherShift`（标准仅适用其他班次）、`counts`（各类计数）。
4. **撰写执行提示** —— 读 `references/dispatch-rules.md` 的优先级口径，替换 `tasklist.md` 中 `<!-- NOTES_START -->` 与 `<!-- NOTES_END -->` 之间的占位文字，说明本班重点（特护设备、逾期项）、需要带的检测工具、与上一班的衔接事项、待车间补齐的周期与标准。**设备数量与逾期天数/小时一律引用 tasks.json。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `tasklist.md` 与 `tasks.json`。用户要求打印版时输出 Markdown 表格，说明可直接粘贴到车间巡检本或移动端。

## 预期结果
- `tasklist.md`：当班巡检任务清单，五节：一、任务概览；二、任务明细（按建议路线顺序）；三、逾期与临期专项；四、周期待确认（含无巡检标准、标准仅适用其他班次、不属本班的检查项）；五、执行提示与交接事项；末尾附路线声明、声明行与「附：数据提示」（有 warning 时）。
- `tasks.json`：结构化任务数据，供移动端或巡检系统导入；`summary.json`：脚本末行摘要。
- 交付时向用户说明：数据来源文件、任务总数、特护项、逾期数量、周期待确认数量、无标准设备数量、脚本 warnings（如有）。
- 声明行（脚本已写入 md，必须保留）："本清单由脚本按台账、巡检标准与上次记录生成，模型只成文说明，仅供车间设备员复核与下发参考；不判定设备状况，不替代巡检标准与检修规程；厂内制度与系统数据为准。"

## 不适用范围
- 不判定设备是否合格（巡检结果由执行人填写，本技能只生成任务）。
- 不替代特种设备法定定检计划，不改写设备重要度定级与特护名单（以公司设备管理部门发布的为准）。
- 不做人员工作量分配与绩效考核，不生成考勤记录。

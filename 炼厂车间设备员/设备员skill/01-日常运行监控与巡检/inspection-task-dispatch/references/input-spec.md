# 输入规格：巡检任务清单

## 支持格式
- `.xlsx`（推荐）或同结构 CSV 目录（文件名 = sheet 名，UTF-8 或 GBK）
- 三张工作表放在同一个文件内：`--input` 只接受单个路径

sheet 名匹配规则：去空白与「表」字后做包含匹配，因此「设备台账」「设备台账表」「台账」「技术对象清单」均可识别；上次巡检记录也可叫「巡检明细」「点检数据」（智能巡检 APP / 点检仪导出）。

## 一、设备台账（必需）

**唯一必需数据源。缺此表脚本报错退出，不会用巡检标准表倒推设备清单。** 可直接用 SAP PM 技术对象（IH08 功能位置/设备）或 EM 设备管理信息系统导出。

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | 功能位置 / 设备位号；为空或与上一行重复的行会被跳过并 warning。**SAP 的「设备」「设备编号」是 8 位流水号，不是位号**，单独归「设备编号」列 |
| 设备编号 | 否 | SAP 设备号 / EM 编码；有此列时明细表增列展示，不参与匹配 |
| 设备名称 | 否 | 设备描述 / 功能位置描述；缺失时清单显示 — |
| 区域 | 否 | 工厂区段 / 装置区；路线编排按此列聚类；为空的设备归入「（区域未填）」并排在最后 |
| 专业 | 否 | 静设备 / 动设备 / 电气 / 仪表；`--discipline` 按此列精确匹配 |
| 重要度 | 否 | ABC 标识 / 设备分级，见下方「重要度取值」；缺此列则全部按未知处理并 warning |
| 特护 | 否 | 是/否；标「是」的设备 `special=true`，任务强制最高优先级 P1。无此列时，重要度列值含「特护」亦识别 |
| 设备类型 | 否 | 对象类型 / 设备类别，用于按类型匹配巡检标准（如「离心泵」「换热器」） |
| 是否需巡检 | 否 | 填「否」「不」「无」「N」「no」的设备排除在巡检范围外，列入 `excluded` |
| 车间 | 否 | 所属车间；有此列时按 `--workshop` 核对，其他车间的设备不排任务，见「车间范围核对」 |

### 重要度取值（中石化口径：关键设备 A / 主要设备 B / 一般设备 C）

| 归类 | 可识别的写法 |
|---|---|
| A 关键设备 | A、A类、一级、1级、关键、重点、**特护**（同时 special=true） |
| B 主要设备 | B、B类、二级、2级、主要、重要 |
| C 一般设备 | C、C类、三级、3级、一般、次要 |
| **未知** | 以上都不匹配（如「特级」、纯数字「1/2/3」——数字级别映射属厂内可配置），输出 `null` 并 warning，**不按最高或最低默认** |

特护名单以公司设备管理部门发布的为准，本技能只读台账标记，不自行认定。

## 二、巡检标准（可选但强烈建议）

| 列名 | 必需 | 说明 |
|---|---|---|
| 检查项 | 是 | 检查内容 / 点检项目；一行一项；为空的行跳过并 warning |
| 位号 | 否 | 填了位号即为该设备专属标准，优先级高于按类型匹配 |
| 设备类型 | 否 | 未填位号时按此列匹配台账中同类型的全部设备 |
| 判定标准 | 否 | 如「振动速度 ≤4.5mm/s」「≤75℃」；原文保留，不解析数值；缺失时清单显示 — |
| 所需工具 | 否 | 如「测振仪」「红外测温仪」；汇总后写入报告头部供备料 |
| 巡检周期 | 否 | 巡检频次 / 点检周期，见下方「周期表达式」；**为空、无法解析或为运行小时周期时归入「周期待确认」** |
| 适用班次 | 否 | 给了 `--shift` 时据此过滤：未填 / 每班 / 各班 / 全部 → 任何班次都排；填「白班」「白班/中班」「夜班」等则须包含 `--shift` 的班次。未给 `--shift` 不过滤 |

位号与设备类型都为空的标准行无法匹配到任何设备，跳过并 warning。

整张表缺失时：warning 提示，范围内全部设备归入「无巡检标准」，不生成任何任务项。

### 周期表达式

共享库 `parsePeriodDetail` 可识别以下写法：

| 写法 | 折算 | 粒度 |
|---|---|---|
| `每班` / `1班` / `2班` | 8 小时 / 16 小时（每班按 8 小时计，三班两运转的 12 小时班取较严的 8 小时） | 小时（班次级） |
| `每2小时` / `2h` / `8小时` | 2 小时 / 8 小时 | 小时（班次级） |
| `每天` / `1天` / `1日` / `30d` | 天 | 天 |
| `每周` / `2w` / `2周` | 7 天 / 14 天 | 天 |
| `每月` / `3m` / `3个月` | 30 天 / 90 天（1 月按 30 天） | 天 |
| `每季` / `1q` / `半年` / `每年` / `1y` | 90 / 182 / 365 天 | 天 |
| 纯数字 `7` | 7 天 | 天 |

**不可识别的写法**（如「视情况」「不定期」「按需」）与空单元格一样归入「周期待确认」。**运行小时周期**（「运行 2000 小时」「2000h」）是另一维度，本技能不按日历排期，同样归入「周期待确认」并在 warning 中说明（运行小时到期用 runtime-hours-tracker）。

> **这是本技能最关键的边界**：周期无法确定的检查项，脚本既**不按日检默认**、也**不静默丢弃**，而是单列一节交回车间确认。报告第四节与 `tasks.json` 的 `unscheduled` 数组均会列出，warning 具体到 sheet 名与行号。

## 三、上次巡检记录（可选）

支持两种形态：
- **一行一设备**：位号 + 上次巡检日期 + 结果。
- **智能巡检 APP / 点检仪导出，一行一检查项**：位号 + 检查内容 + 巡检时间 + 测值 + 是否报警。脚本按位号聚合：取最近一次时间；同一天内任一检查项报警/异常，该设备上次结果记为异常。

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | 为空的行跳过并 warning |
| 上次巡检日期 | 否 | 巡检时间 / 点检时间；见下方「日期字段」；带时间（`2026-09-20 22:30`）时保留用于班次级周期按小时判逾期；无法解析时该设备按未检处理并 warning |
| 结果 | 否 | 正常 / 异常 / 无异常 等，参与优先级排序 |
| 是否报警 | 否 | 无「结果」列时用此列判：是/Y → 异常，否/N → 正常 |
| 车间 | 否 | 有此列时按 `--workshop` 核对，其他车间的记录不参与到期判定 |

同一设备有多条记录时取日期（时间）最近的一条。

**整张表缺失或某设备无记录时，该设备到期状态为 `never`（未检），全部纳入本班清单**，并在 warning 与报告中说明。**不会按「大概已经检过」跳过。**

### 上次结果取值（共享库 classifyResult）

| 归类 | 可识别的写法 |
|---|---|
| 正常 | 正常、良好、合格、完好、无异常、未见异常、无泄漏、OK、√、Running（整词优先，"无异常"不会被按"异常"子串误判） |
| 异常 | 异常、不正常、故障、缺陷、不合格、超标、报警、泄漏、有问题、NG（按单词边界） |
| 未知 | 以上都不匹配；不计入「上次异常」优先级，按常规处理 |

合并后的误配检查：台账同时有「特护」与「重要度」列时各归各列（「特护」先认领）；只有「特护」列时归特护；SAP「设备」列归设备编号而不是位号或设备名称。

表头行识别：取前 10 行中命中必需列最多的一行，因此首行是标题、第三行才是表头的 SAP / EM 导出表也能读。**注意**：标题行若以「功能位置」「技术对象」等别名开头（如「技术对象清单」），会被误认成表头，请把标题行删掉或改写。

## 车间范围核对（`--workshop`）

核对范围：「设备台账」「上次巡检记录」各自核对；「巡检标准」是按位号/设备类型查找的标准表，不核对。

- 「车间」列可选。认作车间列的表头：车间、所属车间、属地车间、运行部，或其后加「名称」（如「车间名称」）。「维护工厂」「计划工厂」是 SAP 工厂代码，「属地单位」「使用单位」「作业部」「责任单位」「作业单位」可能是部门或承包商，**都不当车间列**，脚本不把它们读进车间字段；「车间负责人」「车间监护人」等人员列也不认（`status` 记为 `noColumn`，`ignoredColumn` 写明被忽略的列）。表里同时有「维护工厂」和「所属车间」时取「所属车间」。
- 有车间列且至少一行与 `--workshop` 一致：剔除其他车间的行，不计入本车间；warning 逐车间写明剔除行数。车间列为空的行按本车间保留，warning 写明行数。
- 有车间列但没有一行与 `--workshop` 一致：不筛（避免整表剔空），warning 以【注意】开头，报告标题后醒目提示「车间列取值与 --workshop 不一致，未按车间筛选，请核对输入」，多半是传错了文件。
- 无车间列：不筛，报告口径处写「输入未含车间列，车间范围以取数条件为准」。MCP 导出多数不带车间列，取数时仍必须带 `workshop`。
- 车间名比对忽略空白和末尾的「车间 / 运行部」，「常减压」与「常减压车间」视为同一车间。
- 核对结果写入 `tasks.json` 的 `meta.workshopScope`（数组，每张核对表一条：`sheet`、`status`（`checked` / `mismatch` / `noColumn` / `noWorkshop`）、`column`、`total`、`kept`、`dropped`（车间名 → 行数）、`droppedRows`、`blank`）。

## 日期字段
- 支持：`2026-09-21`、`2026/9/21`、`2026年9月21日`、`20260921`、`2026-09-20 22:30`（带时间）、Excel 日期/日期时间单元格、Excel 序列号
- 上次巡检日期晚于任务日期时保留数据但 warning 提示核实

## 会被跳过的行
- 全空行
- 首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 提示）
- 位号为空的行（warning 提示）
- 台账中重复出现的位号（保留首次，warning 提示）
- 检查项为空的标准行（warning 提示）
- 既无位号又无设备类型的标准行（warning 提示）

## 与下游技能的字段口径

`tasks.json` 中每条任务的 `tag`（位号）、`equipNo`（设备编号）、`name`（设备名称）、`area`（区域）、`discipline`（专业）与 `inspection-data-digest` 的输入口径一致，执行后的巡检记录可直接回流到汇总技能，无需改列名。

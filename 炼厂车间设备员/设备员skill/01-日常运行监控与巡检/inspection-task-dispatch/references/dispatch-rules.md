# 任务清单口径与表述规范（中石化体系炼化厂车间设备员）

## 〇、岗位边界与制度依据

- 本技能站在**车间（运行部）设备员**视角：把台账与巡检标准转成当班任务清单，下发给操作班组 / 专职点检员执行，并把周期待确认、无标准项反馈给工艺/设备专业。
- **由 XX 归口**：巡检标准与判定限值的制定修订（车间工艺/设备专业）、特护设备名单（公司设备管理部门发布）、特种设备法定定检（公司设备管理部门与检验机构）、人员排班考勤（班组/人事）。
- 制度依据（只引名称，不转述数值）：《中国石化设备管理规定》《炼化企业设备管理技术规定》中关于巡检、点检与特护设备管理的要求；巡检周期、判定限值、特护名单以厂内制度文件与系统数据为准。

## 一、任务范围的确定

三步收口，顺序不可颠倒：

1. **台账筛人**：从「设备台账」取全部设备，剔除「是否需巡检」标注为否的（列入 `excluded`），再按 `--area` / `--discipline` / `--criticality` 过滤（被过滤的列入 `filteredOut`，均附排除原因）。
2. **标准配项**：给了 `--shift` 时先按标准表「适用班次」剔除不属本班的检查项（列入 `otherShift`）；每台设备先按位号找巡检标准，找不到再按设备类型找。两者都没有的设备列入 `noStandard`，**不生成空任务项**；标准存在但只适用其他班次的设备列入 `otherShiftOnly`，不算无标准。
3. **周期判到期**：每条标准按周期与上次巡检日期算到期，只有 `overdue` / `due` / `dueSoon` / `never` 四种状态进本班清单。

## 二、到期判定口径

### 日历周期（每天/每周/每月/每季/半年/每年）

到期日 = 上次巡检日期 + 周期天数。以任务日期与到期日比较：

| 情况 | 状态 | 说明 |
|---|---|---|
| 任务日期 > 到期日 | `overdue` 已逾期 | 逾期天数 = 任务日期 − 到期日 |
| 任务日期 = 到期日 | `due` 本班到期 | |
| 距到期 ≤ 临期阈值 | `dueSoon` 临期 | 阈值默认 = 周期 × 10%（7 天周期 0.7 天即不提前；30 天周期提前 3 天；90 天提前 9 天），可 `--due-soon 2`（天）或 `--due-soon 20%` 调整 |
| 距到期 > 阈值 | `notDue` 未到期 | 不进本班清单 |
| 无上次巡检日期 | `never` 未检 | **全部纳入本班清单**，不假设已检过 |
| 周期为空、无法解析或为运行小时 | `unscheduled` 周期待确认 | 见第三节 |

旧版固定「≤1 天即临期」会把每日项刚检完又纳入第二天清单，已废止。

### 班次级周期（每班 / 每 N 小时）

- 周期 < 1 天时按**小时粒度**判定：到期时刻 = 上次巡检时间 + 周期小时数，与「任务日期 + `--time` 班次开始时间」比较；超过即 `overdue`，逾期按小时写（`overdueHours`）；未超过（本班内已检）→ `notDue`。
- 上次记录不带时间，或未给 `--time`：一律 `due`「本班到期」并在 `dueNote` 与 warning 说明「未按小时判定逾期」，**不捏造逾期小时数**。
- 每班按 8 小时计；三班两运转 12 小时班取较严的 8 小时（与"不按最宽松默认"一致）。

## 三、周期待确认：本技能的硬红线

巡检标准的「巡检周期」为空，或填了无法折算的写法（「视情况」「不定期」「按需」等），或填的是运行小时周期（「运行 2000 小时」）时：

1. 该检查项状态为 `unscheduled`，进入 `tasks.json` 的 `unscheduled` 数组与报告第四节
2. warning 具体到工作表名、行号、检查项名与周期原文；运行小时周期说明"本技能只按日历/班次周期排期"
3. 报告中写明「脚本未按日检默认处理，也未丢弃」

**禁止**：
- 按日检（或任何其他周期）默认后排进清单
- 从清单中静默剔除
- 由模型代车间推断一个「合理周期」

正确做法是把这几项交回车间，由工艺或设备专业确认周期后补进标准表；运行小时周期转 runtime-hours-tracker。

## 四、无巡检标准的设备

按位号与设备类型都匹配不到标准的设备，列入 `noStandard` 单列一节，附原因（区分「未填设备类型」与「类型也没匹配上」两种）。

**禁止**：生成一条「检查项：待定 / 判定标准：待定」的占位任务项。

## 五、优先级排序口径

按以下顺序逐级判断，命中即定级，不叠加：

| 级别 | 条件 | 依据 |
|---|---|---|
| **P1** | 特护设备（台账「特护」列为是，或重要度填「特护」） | 大机组、关键机组属特护设备，日巡检强制最高优先级，逾期与否都排最前 |
| **P2** | 到期状态为已逾期 | 逾期本身就是管理缺口，无论设备多重要都要先补上 |
| **P3** | 重要度为 A（关键设备） | 关键设备停机影响装置连续运行，优先保证 |
| **P4** | 上次巡检结果为异常 | 上次有异常的设备需要连续跟踪，确认是否劣化 |
| **P5** | 临期 | 提前安排，避免下一班交接时逾期 |
| **P6** | 本班到期 / 未检 / 其他常规项 | 按常规节奏执行 |

同级内的排序：逾期天数降序 → 逾期小时降序 → 位号升序 → 检查项名升序。

`tasks.json` 每条任务的 `priorityReason` 写明定级理由（如「特护设备（强制最高优先级），且已逾期 2 天」「关键设备（A 类）」），报告与执行提示中引用这句话，不要另行编造理由。

**禁止**：模型自行调整优先级顺序；把「看起来更紧急」的项往前提；把 A/B/C 设备重要度与异常关注度（红/橙/黄）或缺陷等级混用。

## 六、路线编排原则

1. **按区域聚类**：同一区域（工厂区段/装置区）的任务排在一起，减少往返
2. **区内按位号排序**：位号通常与装置流程顺序相关，升序即大致顺流向
3. 区域为空的设备排在最后，提示补填台账区域列
4. 编号为全局连续的「建议顺序」，写入 `routeSeq`

> **路线只是建议。** 实际巡检路线受现场通道、检修围挡、用火作业区隔离、交叉作业等影响，一律由车间确定。报告与 `tasks.json` 的 `meta.routeNote` 都保留这句声明，**不得把建议顺序说成"最优路线"或"必须按此执行"**。

## 七、工具准备

脚本汇总本班全部任务的「所需工具」去重后写入报告头部。执行提示中应提醒执行人按此备料，尤其是测振仪、红外测温仪这类需要领用的仪器。

标准表未填工具的，报告显示「—（标准表未填写所需工具）」，**不要替车间猜「带个手电筒就行」**。

## 八、执行提示与交接事项表述规范

替换 `<!-- NOTES_START -->` 与 `<!-- NOTES_END -->` 之间的占位文字，200~350 字，结构固定：

1. **本班重点**：任务项总数、涉及设备数、特护设备（P1）与逾期（P2）项分别是哪几台。
2. **逾期项说明**：逾期最久的几项、逾期天数/小时、上次结果为异常的项要点名。
3. **工具与准备**：本班需领用的检测仪器清单。
4. **待确认与缺口**：周期待确认项、无巡检标准的设备、标准仅适用其他班次的设备，明确请车间补齐；说明建议路线仅供参考。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 特护设备 | 「K-1801 富气压缩机为特护设备，本班轴承振动与油压检查排在首位」 | 「压缩机顺便看一眼」 |
| 逾期项 | 「P-1101B 机封泄漏检查已逾期 6 天，上次结果为异常」 | 「P-1101B 可能已经漏了」 |
| 班次级周期 | 「上次记录不带时间，按本班到期处理，未按小时判逾期」 | 「大概逾期了几个小时」 |
| 周期待确认 | 「2 项周期未确认，已单列，请车间确认后补入标准表」 | 「按日检临时安排」 |
| 无标准设备 | 「A-1701 未匹配到巡检标准，本班未排任务，请补齐标准」 | 「A-1701 先按同类设备检一下」 |
| 路线 | 「建议顺序供参考，实际路线由车间确定」 | 「按此最优路线执行」 |
| 数字 | 引用 tasks.json 的 counts | 自行统计或估算 |

### 硬约束

- **不判定设备状况**。本技能只生成待执行任务，检查结论由执行人填写。
- **不推算缺失周期**，不替车间定标准。
- **不改写设备重要度定级与特护名单**，台账填什么就是什么，无法归类的按未知处理。
- **数字一律引用 tasks.json**，不得自行统计。
- 产出保留脚本写入的声明行。

## 九、下游衔接

- 本班巡检执行完毕，记录回流汇总 → `inspection-data-digest`（`tasks.json` 的位号、设备编号、设备名称、区域、专业字段口径与其输入一致）
- 巡检发现异常需登记缺陷（维修通知单）→ `defect-intake-grading`
- 运行小时周期的检修/保养到期 → `runtime-hours-tracker`
- 特种设备的法定定检排期 → `special-equipment-inspection-due`（本技能不覆盖）
- 任务完成率与特护设备运行状况进设备日报 → `equipment-daily-report`

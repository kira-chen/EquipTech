# 润滑管理口径与表述规范（中石化体系炼化厂车间设备员）

制度依据：《中国石化设备管理规定》《炼化企业设备管理技术规定》中关于设备润滑"五定三过滤"的要求；厂内润滑管理细则与换油指标为准，本文只记口径，不转述任何数值。

## 一、五定三过滤

| 项 | 含义 | 脚本如何处理 |
|---|---|---|
| 定点 | 每台设备的润滑点（部位）明确 | 台账「润滑部位」列填写比例 → 定点齐备率 |
| 定质 | 每个润滑点使用的油品牌号明确 | 台账「油品名称」列填写比例 → 定质齐备率 |
| 定量 | 每次加油/换油的定额油量明确 | 台账「加油量」列填写比例 → 定量齐备率 |
| 定期 | 加油、换油周期明确（日历周期或运行小时周期） | 台账「润滑周期」列填写比例 → 定期齐备率；周期值再做到期判定 |
| 定人 | 每个润滑点有明确责任人（包机人/岗位责任人） | 台账「责任人」列填写比例 → 定人齐备率；**无此列 → null 并 warning** |
| 三过滤 | 领油（入库/领用）过滤、转桶过滤、加油（加注）过滤 | 属现场作业要求，台账无对应列，脚本不判定；作为交付提示与检查要点 |

齐备率只反映**台账填写**是否齐全，不是现场执行到位率。台账没有某列时该项齐备率为 null，**不按齐备处理**，报告写"台账无此列，无法统计"。

### 三过滤检查要点（交付时提示，不出数）
- 领油：油桶/油罐入库有封口与标识，领用经滤网或滤油机。
- 转桶：由大桶转小桶、由油桶转加油壶有过滤。
- 加油：加注口有滤网，加油壶专油专用、有盖有标识。

## 二、到期判定

### 日历周期
应到期日 = 上次加换油日期 + 润滑周期天数；以 `--date` 基准日比对：

| 分档 | 条件 | 说明 |
|---|---|---|
| 已逾期 | 应到期日 < 基准日 | 记录逾期天数与逾期程度 |
| 临期 | 0 ≤ 剩余天数 ≤ 提前提醒天数（默认 7） | 应排入近期计划 |
| 周期内 | 剩余天数 > 提前提醒天数 | 正常 |
| **无法判定** | 周期或上次加换油日期缺失/无法解析 | **单列一节** |

"每班 / 每 2 小时"这类班次级周期按小数天折算（每班 = 8 小时），到期判定仍以日为粒度。

### 运行小时周期
周期写作"运行 2000 小时 / 2000h"（> 168 小时）的，按累计运行小时判定，**不折算成日历天**：

- 已运行小时 = 台账「自上次加换油运行小时」；没有则 = 累计运行小时（台账列优先，台账为空才取 `--run-hours`）− 「上次加换油时累计小时」。台账累计与 `--run-hours` 都有且不一致时以台账为准并 warning，提示核对台账是否需按启停记录更新。
- 剩余小时 = 周期小时 − 已运行小时。剩余 < 0 逾期（记逾期小时），0 ≤ 剩余 ≤ `--lead-hours`（默认提醒天数 × 24）临期，否则周期内。
- 缺累计小时、缺上次加换油时小时数、累计小于上次小时数（矛盾）→ 无法判定并说明缺哪个字段。
- 累计运行小时的统计本身由 `runtime-hours-tracker` 完成，本技能只读取其 `runtime.json`。

### 逾期程度

按逾期天数（或逾期小时）与周期的比值分档，**只作排序提示，不是风险等级**：

| 程度 | 条件 |
|---|---|
| 轻微逾期 | 逾期 ≤ 周期的 20% |
| 明显逾期 | 逾期 > 周期的 20% |
| 严重逾期 | 逾期 > 一个完整周期（已漏掉整轮加换油） |

**禁止**把逾期程度写成设备风险结论（如「严重逾期即将抱轴」）。逾期程度只说明计划执行偏差。

## 三、无法判定处理

周期为空、周期写法无法解析（如「视情况」）、上次加换油日期为空或无法解析、运行小时周期缺累计小时或缺上次小时数、累计小时矛盾 —— 都归入「无法判定」，在 JSON 与报告中单列（【未判定】），注明缺哪个字段、出处行号。

**禁止**：
- 按最常见周期（一月一次、三月一换）默认填补
- 按同类设备的周期推算
- 从加换油记录里最后一条日期倒推为「上次加换油日期」后再算到期
- 把运行小时周期按"每天运行 24 小时"折算成日历天
- 归入正常或归入逾期任何一侧

正确表述：「P-1103A 台账未填润滑周期，无法判定到期，需润滑责任人补齐台账后重跑。」「P-1105 按运行 4000 小时换油，台账无累计运行小时，请从 runtime-hours-tracker 结果接入后重跑。」

## 四、油品消耗统计

按油品、按设备两个维度统计，各自**按计量单位分组求和**。

### 单位混用

同一油品或同一设备的记录中出现多种单位（L / kg / 桶 混用）时：
1. 按单位分别列出，如「1 桶 ； 29.22 L」
2. 计入 `mixedUnits` 并 warning
3. 报告中给出【注意】单位混用提示，请设备员核实计量口径

**禁止**：按经验密度把 kg 折成 L、按标准桶容积把桶折成 L、或挑一个单位合并。密度随油品牌号与温度变化，换算会失真且无法追溯。

### 数量缺失

数量为空或无法解析时，计入该条目的「数量缺失条数」，**不计入任何单位的合计，也绝不按 0 计**。报告中消耗量显示「—」时，须说明有几条记录数量缺失。

### 金额折算

仅在提供 `--price` 且单价表中能按「油品（+单位）」匹配到单价时折算；单价匹配忽略品牌词与空格。匹配不到的组合金额留空并注明「单价表无匹配项」。

**禁止**：用市场估价、上季度均价、相近牌号单价代替。

## 五、油液分析标记

### 有厂内限值

按厂内限值（厂内换油指标）比对，超限的进「异常项」，未超限的进「正常项」。检测值与限值原样列出，化验结论列照录化验室原文。

油液分析表里出现不在本次润滑台账内的位号（全厂导出混入其他车间、或台账漏登）时，单列为「台账外油样」（照样按厂内限值标出是否超限，供核实），**不计入本车间的异常/正常/无限值计数**，也不静默丢弃；warning 一次性点名这些位号，成文时只写本车间设备。取数时应先取润滑台账，再用台账位号作 `get_oil_analysis` 的 `tag`，从源头避免混入。

### 无厂内限值 —— 关键口径

限值为空、限值无法解析（「参照标准」「见报告」）、或检测值无法解析时，该检测项进「无判定限值项」（【未判定】）：

1. **只列示数值，不判异常也不判正常**
2. warning 说明缺少判定限值
3. 报告中注明出处行号，请设备员向化验室或润滑专业索取厂内限值

**禁止**：
- 脚本或模型自行引用 GB/T、ISO、设备厂家手册或任何通用/经验限值替代厂内标准做判定
- 按「铁含量 50ppm 一般算高」这类经验值给结论
- 因为没有限值就把该项当作正常略过

### 参考比对（`--ref-standard`，显式启用）

车间多数没有成文的厂内限值表时，用户可把厂内认可的国标换油指标（如矿物油类涡轮机油、工业齿轮油、液压油的换油指标标准）或厂家推荐值**自行转录**成参考限值表，用 `--ref-standard` 传入。脚本只在此时对无厂内限值的项做"参考比对"：

- 结果进 `oilAnalysis.refChecked`，报告单列为「参考限值比对项（非厂内标准，仅供参考）」，逐项标注「超参考限值（非厂内标准）/ 未超参考限值」与参考出处（标准号）。
- **不计入 `oaAbnormal`**，不作为换油或异常判定依据；须由润滑专业确认厂内指标后复核。
- 脚本不内置任何标准数值；参考表数值由用户负责；示例文件中的数值与标准号均为虚构（`Q/XX-虚构-001`）。

正确表述：「K-1401 闪点 205℃，台账未给出厂内判定限值；按用户提供的参考限值表比对未超限，该结果非厂内标准、仅供参考，建议向润滑专业确认该项控制指标。」

### 不做故障诊断

油液金属含量升高**只标记不推断部位**。「铁含量超限」可以写，「轴瓦磨损」不能写 —— 原因判断走 `anomaly-triage-advisor`，结论以化验室报告为准。

## 六、油品牌号写法不一致

归一（去品牌词、空格、标点）后同一油品出现多种写法时，列入「附一、油品牌号写法不一致提示」并 warning，统计仍按原写法分列。

**禁止**：脚本或模型自行合并统计口径。合并须由设备员确认两种写法确系同一油品后，在台账中统一再重跑。

正确表述：「台账与记录中「L-TSA46 透平油」「L-TSA46透平油」「长城 L-TSA46 透平油」三种写法并存，疑似同一油品，消耗统计按原写法分列，请核实后统一台账。」

## 七、情况说明表述规范

撰写 200~350 字，结构固定为五段：

1. **到期情况**：台账润滑项总数、逾期/临期/周期内/无法判定分布，其中按运行小时管理的项数。
2. **五定落实与逾期项**：五定齐备率缺项（尤其定人）、逐条或分类说明逾期设备、油品、逾期天数/小时。只陈述计划偏差与台账事实。
3. **油品消耗情况**：主要消耗油品与消耗量（按单位），单位混用与数量缺失的情况，有单价时的金额。
4. **油液分析异常**：超厂内限值项的检测项与数值、参考比对项（如有，注明非厂内标准）、无判定限值项的数量与处理方式。
5. **下一步安排**：补台账（含责任人）、排加换油计划、索取厂内限值、提报维修通知单等。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 逾期 | 「P-1101A 换油逾期 35 天，超出 6 个月周期」「K-1402 按运行 2000 小时换油已超 250 小时」 | 「润滑严重不足，轴承已受损」 |
| 无法判定 | 「台账未填周期，无法判定到期」 | 「按一般 3 个月周期估计已到期」 |
| 五定 | 「定人齐备率 92.9%，1 个润滑点未落实责任人」 | 「润滑管理混乱」 |
| 单位混用 | 「K-1401 记录中 L 与桶混用，已分列统计」 | 「折合约 229L」 |
| 无限值 | 「未给出厂内限值，仅列示数值」 | 「参照通用标准该值偏高」 |
| 参考比对 | 「按参考限值表比对超限，非厂内标准仅供参考」 | 「按国标已到换油指标，必须换油」 |
| 油液异常 | 「水分 511ppm，超出厂内限值 300ppm」 | 「油品已乳化需立即换油」 |
| 数字 | 引用 lube.json 的 counts、wuding 与明细 | 自行统计或估算 |

### 硬约束

- **不手工推算周期或到期日**，一律引用 lube.json。
- **不改写化验室油液分析结论**，结论列照录原文。
- **不做油品选型与替代油推荐**。
- **不做量纲换算**，单位混用如实分列。
- **未提供单价不折算金额**。
- **保留报告开头的声明行**。

## 八、下游衔接

- 累计运行小时 → 由 `runtime-hours-tracker` 产出 `runtime.json`，本技能用 `--run-hours` 读取
- 逾期项需提报维修通知单 → `work-order-generator`（通知单草稿）
- 油液异常需初判原因 → `anomaly-triage-advisor`
- 加换油作业需作业许可票 → `permit-precheck-bridge`
- 润滑情况进设备日报 → `equipment-daily-report`（直接读 lube.json）

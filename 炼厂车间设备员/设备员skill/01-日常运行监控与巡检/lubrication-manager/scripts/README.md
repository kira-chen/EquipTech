# scripts 使用说明

## lube.js —— 主脚本

```bash
node "<技能目录>/scripts/lube.js" \
  --input "<xlsx路径>" \
  --workshop "<车间名>" \
  --date <YYYY-MM-DD> \
  --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 润滑数据 xlsx 路径，或同结构 CSV 目录；须含「润滑台账」（五定表）工作表，支持 SAP PM / EM 导出列名 |
| `--workshop` | 是 | 车间（运行部）名称 |
| `--date` | 是 | 统计基准日期 YYYY-MM-DD，到期判定以此日为准 |
| `--out` | 否 | 输出目录；默认系统临时目录 `<os.tmpdir()>/lube-out`，**建议始终传 `--out`** |
| `--lead-days` | 否 | 日历周期的提前提醒天数（临期窗口），默认 7；须为非负整数 |
| `--lead-hours` | 否 | 运行小时周期的提前提醒小时数，默认 = `--lead-days` × 24（即 168 h）；须为非负数 |
| `--equipment` | 否 | 限定设备范围，位号逗号分隔；范围外的行不参与判定并 warning |
| `--price` | 否 | 油品单价表 xlsx（含「油品单价」工作表），用于消耗金额折算；不提供则不折算 |
| `--run-hours` | 否 | 累计运行小时来源：`runtime-hours-tracker` 产出的 `runtime.json`（读 `byEquipment[].tag/cumHours`），或含「位号 / 累计运行小时」列的 xlsx；仅用于运行小时周期项；台账「自上次加换油运行小时」或「累计运行小时」有值时以台账为先，台账累计与 `--run-hours` 不一致时 warning 提示核对；runtime.json 中某台 `periodHours` 为 null（累计只剩期初/上期值）或 `cumBasis` 为 `periodOnly` 时，用到该台累计会 warning 提示可能偏小 |
| `--ref-standard` | 否 | 参考限值表 xlsx（含「参考限值」工作表：检测项、限值，可选 油品类型、标准号）。**显式提供时**，无厂内限值的油液分析项才按参考限值做"参考比对"，结果单列并标注"非厂内标准，仅供参考"，不计入 `oaAbnormal`。脚本不内置任何国标数值，参考值须由用户自行转录 |
| `--oil-analysis` | 否 | 不是开关：输入里有「油液分析」工作表时不论加不加都照常出油液分析章节；加了而缺表时多一条 warning 提示 |

### 产出

| 文件 | 内容 |
|---|---|
| `lube.json` | `meta`（含 `declaration` 声明行、`workshopScope` 车间范围核对结果数组：润滑台账、加换油记录、油液分析各一条 sheet/status/column/total/kept/dropped/droppedRows/blank）/`counts`/`wuding`（五定齐备率）/`overdue`/`dueSoon`/`normal`/`undetermined`/`consumption`/`oilAnalysis`（`abnormal`/`refChecked`/`noLimit`/`normal`/`outOfLedger`）/`oilNameConflicts`/`warnings` |
| `lube-report.md` | 八节报告（到期概览、五定齐备率、逾期、临期、无法判定、油品消耗、油液分析、情况说明），分析段留 `<!-- ANALYSIS_START/END -->` 占位，开头带声明行 |
| `summary.json` | 末行摘要落盘（Windows 控制台乱码兜底） |

### 判定口径要点
- **周期分两类**：`parsePeriod` 认日历周期（每班/每 N 小时/每天/每周/每月/每季/半年/每年/纯数字天），`parseRunHours` 认运行小时周期（"运行 2000 小时 / 2000h"，> 168 h 才算运行小时）。运行小时周期按「累计运行小时 − 上次加换油时累计小时」或「自上次加换油运行小时」判定，**不折算成日历天**。
- **周期或上次加换油日期缺失/无法解析**、**运行小时周期缺累计小时或缺上次加换油时小时数**、**累计小时小于上次小时数（矛盾）** → 该项进 `undetermined` 单列，**不按常见周期默认**。
- **五定齐备率**：定点=润滑部位、定质=油品名称、定量=加油量、定期=润滑周期、定人=责任人，按列填写比例计算；台账无该列 → 齐备率 `null`（不按齐备处理）并 warning。三过滤（领油、转桶、加油）属现场作业要求，不从台账判定。
- **油液分析无厂内限值**（或限值无法解析、检测值无法解析）→ 进 `oilAnalysis.noLimit`，只列数值不判异常，**不引用通用限值**；仅 `--ref-standard` 显式提供时进 `refChecked` 做参考比对并标注非厂内标准。
- **台账外油样**：油液分析里位号不在本次润滑台账内的（全厂导出混入其他车间、或台账漏登），进 `oilAnalysis.outOfLedger` 单列（照样按厂内限值标出是否超限供核实），不计入 `oaAbnormal`/`oaNormal`/`oaNoLimit`，`counts.oaOutOfLedger` 计数，warning 一次点名。
- **车间范围核对（D007）**：润滑台账、加换油记录、油液分析各自按「车间」列核对 `--workshop`（`C.workshopScope`）：有本车间行时剔除其他车间的行并 warning（逐车间写行数），车间列为空的行按本车间保留；车间列取值全不一致时不筛，warning 与报告标题后均以【注意】提示；无车间列或命中的是「车间负责人」等人员列时不筛（「维护工厂」等不读入车间字段），口径行写「输入未含车间列，车间范围以取数条件为准」。油液分析先按车间列剔除，再做台账外油样检测，两者叠加。口径行写在报告头「数据来源」之后。
- **油品牌号归一**：去品牌词（长城/昆仑/壳牌/美孚等）、空格、横杠与标点后比对，用于疑似同一油品提示与单价匹配；统计与展示仍按原写法，**不自动合并**。
- **消耗统计单位混用** → 按单位分别统计并 warning，**不做任何量纲换算**。
- **数量/检测值无法解析** → `null`（显示「—」），**不按 0 计**；带单位数值（"12L" "78℃"）剥离单位取数值并提示核对。
- **未提供 `--price`** → 不折算金额，**不使用估计单价**。
- **位号**：取 位号/功能位置/技术对象 等；SAP「设备编号」是流水号，单独成列展示，**不当位号**。

### 退出码
- `0`：成功，末行输出 `{"ok":true,...}`
- `1`：失败，末行输出 `{"ok":false,"error":"...","warnings":[...]}`（无润滑台账、非法日期/提醒窗口、输入/单价表/运行小时/参考表不存在、参考表缺工作表、runtime.json 无 byEquipment）

## make-sample.js —— 样例生成

```bash
node scripts/make-sample.js [--seed <n>] [--date <YYYY-MM-DD>]
```

生成 7 份样例：主样例（五定台账+加换油记录+油液分析，含运行小时周期）、油品单价表、仅台账变体、SAP/EM 导出风格变体、`sample-runtime.json`（模拟 runtime-hours-tracker 产出）、`sample-run-hours.xlsx`、`sample-ref-limits.xlsx`（参考限值，数值与标准号均虚构）。
seed 改变数值但不改变结论：主样例恒为 4 逾期、3 临期、4 周期内、3 无法判定、2 油液超厂内限值、2 无限值项、1 组油品牌号写法不一致（3 种写法）。

```bash
node scripts/selftest.js
```

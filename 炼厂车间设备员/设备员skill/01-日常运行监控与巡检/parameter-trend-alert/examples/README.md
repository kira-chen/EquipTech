## 关键验证点

1. **期数不足 3 期不算趋势**（案例 2、8，本技能最关键）。两点之间连一条线，斜率完全取决于这两个点的偶然误差，外推出来的到限日期是纯粹虚构。脚本宁可说「数据不足」。
2. **缺测不按 0**（案例 3、6）。长表「未记录」与宽表空格都按未测处理；按 0 算会让斜率整个拉反。
3. **方向不对不预测**（案例 4）。压力在下降而只配了高报，硬算会得到一个负天数或指向反方向的日期。
4. **两级限值**（案例 1）。先判 HH/LL 再判 H/L，越限清单 HH/LL 排前；两级都给时先向高报外推到限时间。限值由限值表给，脚本不自定。
5. **宽表与 SAP/DCS 列名**（案例 6）。功能位置归位号、仪表位号归测点号、参数名称归参数名、H/HH/L/LL 列头可识别；限值表按仪表位号配对。
6. **R² 与到限窗口两道闸可参数化**（案例 9）。默认 0.5 / 365 天，`--r2-min`、`--horizon` 可按厂内判据调整，调整后 md 头部与 `etaNote` 都写明取值。
7. **时间重复不去重**。K-1201 末期有两条相同时间的记录，原样保留并提示核实，不自作主张挑一条。
8. **预测不是故障预测**。报告在恶化清单后与文末两处带线性外推声明行，文末另带通用声明行；研判段口径禁止写成「N 天后损坏」，越 HH 不写停机结论。

## 再生样例

```bash
node scripts/make-sample.js --out examples            # seed=1
node scripts/make-sample.js --out examples --seed 7   # 数值抖动变，越限/恶化/数据不足条数不变
```

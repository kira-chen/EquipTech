# 参数越限与劣化趋势预警（parameter-trend-alert）

面向中石化体系炼化厂**车间（运行部）设备员**，对多期采集的设备参数（专职点检仪导出、状态监测测振/测温、DCS 趋势导出、手工巡检表）做趋势计算，在到达高报/高高报前给出预警，交付对象为车间设备主任 / 公司设备管理部门。**所有趋势计算、越限判定与到限时间预测一律由脚本完成，模型只负责解读；不得目测趋势或自行外推。**

## 适用条件
- 用户说"看看趋势 / 振动在不在涨 / 有没有快要到高报的 / 参数劣化情况"，并给出（或即将给出）同一批设备多个时间点的参数数据。
- 数据形态：长表（一行一个采集点）或**宽表（一列一期，日期列头须含年份或为 Excel 日期）**，脚本自动识别并转换；带单位的数值（78℃、4.5mm/s）自动剥离单位。
- 至少需要 3 期数据才能计算趋势；仅 1~2 期时脚本只做越限判定并 warning 说明趋势不可算。
- 车间设备员可做的部分：汇总趋势、判越限、提出加密点检/复测/提报缺陷建议。**报警限值与联锁定值的设定与变更由工艺/仪表归口；精密诊断（频谱、油液）由状态监测专业归口；是否停机由工艺/设备主管按规程决定**，本技能只做提示。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含工作表「参数记录」（别名：参数数据/监测记录/趋势数据/测点数据）与可选的「报警限值」（别名：限值/报警设定），字段与别名见 `references/input-spec.md`。限值表支持 高报/高高报/低报/低低报（H/HH/L/LL、PH/PHH/PL/PLL）两级，也兼容只给上下限的单级表。
- 列名兼容 SAP PM / EM / DCS / 点检仪导出：功能位置、功能位置描述、设备描述、测点号/仪表位号、测点名称、采样时间、测量值/PV、工程单位。**SAP「设备编号」是流水号，不作位号。**
- 必填信息：车间名称、分析截止日期（YYYY-MM-DD）。可选：回溯期数或起始日期、指定设备/测点范围、指定参数类型。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得目测或手工估算趋势。**
- PDF 不读：若用户给的是 PDF 报表，先用平台 pdf 技能转为 txt/docx 再整理成 xlsx 传入，脚本不读 PDF；扫描件需 OCR。

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| DCS位号数据 | `get_tag_history` | `tag`：位号；`for_skill=parameter-trend-alert` | `--input` |
| DCS位号数据 | `get_tag_limits` | `tag`：位号 | `--input` |
| DCS位号数据 | `get_run_events` | `workshop`：车间名（单台设备可用 `tag`）；不填 for_skill | `--status`（另一个目录） |
| 设备资产管理 | `get_equipment_ledger` | `workshop`：车间名（单台设备可用 `tag`）；不填 for_skill | `--status`（与 `get_run_events` 同一目录） |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；把目录作为“交给脚本”一列的参数值。`get_tag_history` 和 `get_tag_limits` 放一个目录作 `--input`，`get_run_events` 和 `get_equipment_ledger` 放另一个目录作 `--status`。
2. `get_tag_history`：输出近 8 天、每天 08:00 一个点的历史值。设备停运时振动、电流记 0，出口压力很低。
3. `get_run_events`、`get_equipment_ledger`：可选，用来判断哪些设备停运，按 `workshop`（与 `--workshop` 一致）取。`get_run_events` 输出与近 30 天有交集的运行段（停机时间为空表示仍在运行），不填 for_skill（lubrication-manager 是给润滑技能的累计小时形态）；`get_equipment_ledger` 的「使用状态」只有在用/停用，备用泵记为在用，所以以启停记录为准，台账只补「停用」。近 30 天没开过的备机两处都查不到，脚本按电流≈0 判疑似停运并 warning。

## 操作步骤
1. **确认分析范围** —— 车间、截止日期、回溯窗口（默认最近 12 期，可用 `--periods` 调整）；不明确时向用户确认一次。检查是否提供报警限值表，未提供时脚本只算趋势不判越限并 warning；限值以 DCS 组态或厂内限值表为准，**不得替用户补限值**。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/trend.js" --input "<xlsx路径>" --workshop "<车间名>" --date <YYYY-MM-DD> --out "<输入同目录>/趋势预警"
   ```
   可选：`--status "<设备台账/DCS 启停记录 xlsx、csv 或目录>"`（判断设备是否停运，两种都给时启停记录优先）、`--periods <回溯期数>`、`--from <起始日期>`、`--equipment "<位号或测点号,…>"`、`--param "<参数名>"`、`--threshold <趋势告警斜率阈值>`、`--r2-min <R² 下限，默认 0.5>`、`--horizon <到限关注窗口天数，默认 365>`、`--wide`（强制按宽表读）、`--wide-param "<参数名>"`（宽表无参数名列时统一指定）。建议始终传 `--out`，默认输出在系统临时目录。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（期数不足/限值缺失/数值无法解析/采集时间重复/宽表转换/单位剥离等）。脚本用法详见 `scripts/README.md`。
   - 期数不足 3 期的设备参数：归入 `insufficientData` 单列一节并 warning，**不得用两点连线当作趋势，也不得预测到限时间**。
   - 数值无法解析：warning + 该点输出 null（显示 —），**绝不按 0 计入趋势计算**；宽表空格视为该期未测，同样不按 0。
   - **停运设备**（备用、停运、停用、检修）：出口压力低、振动和电流为 0 不是参数越限。这些设备的参数不判越低报/低低报、不做劣化趋势判定，归入 `stopped` 单列「停运中（不判定）」并 warning；**越高报/高高报照常判**。运行状态按 `--status` 启停记录 → 台账 → 数据自判（同设备电流/转速最新值≈0，判「疑似停运」）取；出现「疑似停运」时请用户提供设备台账或 DCS 启停记录确认，**不得把停运设备的低值写成越低报/低低报，也不得写成劣化**。只有测点号、没有设备位号的序列不套用。
   - **刚由备机切为主机的在运设备**：回溯窗口里的停机期点（启停记录停机段内，无启停记录时同期电流/转速≈0）不参与回归与劣化判定，记在 `excludedStoppedPeriods`；窗口内发生过停机/切泵的序列（含停机时不记读数、只有切换后几期的参数），剔除后少于 4 期判「数据不足（切泵后运行期数偏少，剩 N 期）」，不做劣化判定、不预测到限（越限照常判）；窗口内没有停机期的序列最低仍为 3 期。研判段写明剔除了多少个停机期点（md 研判段上方有说明行）。
3. **读取 trends.json** —— 从 `<输出目录>/trends.json` 获取：`overLimit`（已越限：位号、测点号、参数、当前值、越限等级 HH/H/L/LL、限值、超限幅度）、`deteriorating`（趋势恶化：斜率、变化率、预计到限时间与到限等级、置信提示）、`stable`、`insufficientData`、`stopped`（停运中（不判定）：运行状态 `runState`、依据 `runStateSource`/`runStateBasis`）、`counts`（含 `overHighHigh`/`overHigh`/`stopped`）。
4. **撰写"趋势研判与建议"** —— 读 `references/interpretation.md` 的参数口径（振动按 ISO 10816 / GB/T 6075 分区概念表述、温度、压力、电流各自的表述规范与常见劣化含义），撰写 200~400 字，按"总体情况 → 已越限设备（先 HH/LL 后 H/L） → 趋势恶化设备与建议动作 → 数据不足说明"结构，替换 `alert.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**斜率、到限时间一律引用 trends.json，并注明预测基于线性外推、仅供参考。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `alert.md` 与 `trends.json`。**预计到限时间是统计外推结果，不得表述为设备故障预测或损坏时间，须保留报告中的两条声明行**（线性外推声明；"本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。"）。

## 预期结果
- `alert.md`：趋势预警报告，含 一、预警概览（含 HH/LL 与 H/L 分计）、二、已越限、三、趋势恶化（含预计到限天数/等级/日期）、四、趋势稳定、五、数据不足说明（含停运中（不判定）小节与数据质量明细）、六、趋势研判与建议 六节，另附数据提示。
- `trends.json`：逐参数趋势计算结果；`summary.json`：脚本末行摘要。
- 交付时向用户说明：数据来源、形态（长表/宽表）与期数、越限数量（HH/LL 与 H/L 分计）、趋势恶化数量、数据不足数量、停运中（不判定）的设备及判定依据（疑似停运的要请用户确认）、脚本 warnings（如有）、预测口径与局限。

## 不适用范围
- 不做故障原因诊断（不判定是轴承、不对中还是松动），不给维修决策，不判停机；异常初判与要不要报工程师用 anomaly-triage-advisor。
- 不替代精密诊断（频谱分析、油液分析）与状态监测专业的结论；不设定或修改报警限值与联锁定值（工艺/仪表归口）。
- 不做非线性/多变量建模，预测仅为线性外推，不用于安全联锁或停机决策依据。
- 不做单次巡检数据汇总（inspection-data-digest）、不算累计运行小时（runtime-hours-tracker）。

# 交付自检清单

## 输入与环境
- [ ] 输入是 xlsx/CSV；PDF 报表已先用平台 pdf 技能转 txt/docx 再整理，脚本未读 PDF
- [ ] 带单位数值已由脚本剥离单位，warnings 提示的「请核对该列单位一致」已向用户转达

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；为 `false` 时已告知 `error` 并终止，**未目测趋势或手工外推**
- [ ] `warnings` 已逐条告知用户
- [ ] `trends.json`、`alert.md`、`summary.json` 三个文件都已生成

## 趋势计算口径
- [ ] 斜率、变化率、R²、预计到限天数**全部引用 `trends.json`**，未自行计算
- [ ] **有效期数 < 3 期的序列已单列，未给任何趋势描述，未预测到限时间**
- [ ] 数值无法解析的采集点显示「—」，**未按 0 计入趋势**
- [ ] 采集时间重复的点已原样保留并提示核实，**未自行去重**
- [ ] 全部采集时间相同的序列已归入数据不足，**未凭空给斜率**
- [ ] 停运（备用/停运/停用/检修）设备的参数按 `stopped` 单列「停运中（不判定）」，**未把出口压力低、振动/电流为 0 写成越低报/低低报或劣化**；停运设备越高报/高高报的已照常列入越限
- [ ] 有「疑似停运」（电流/转速≈0 自判）时已请用户提供设备台账或 DCS 启停记录（`--status`）确认
- [ ] 在运设备回溯窗口里的停机期点已由脚本剔出（`excludedStoppedPeriods`），研判段写明剔除点数；「数据不足（切泵后运行期数偏少）」的**未给趋势描述与到限日期**（越限照常写）

## 限值与越限
- [ ] 未提供限值表时概览显示「—（未提供限值表）」，**未出现 0，未说「未越限」**
- [ ] 查不到限值的单条序列已注明只算趋势不判越限
- [ ] 上下限均无法解析的项已说明不判越限
- [ ] 已越限的序列未再给预计到限时间
- [ ] 两级限值表：越限等级（HH/LL 先于 H/L）与 trends.json 的 `limitLevel` 一致，越 HH/LL 的已提示核对 DCS 报警记录并报车间设备主任，**未写停机结论**
- [ ] 未替用户补限值、未建议修改报警限值或联锁定值（工艺/仪表归口）

## 预测口径（最关键）
- [ ] 斜率方向与限值方向不一致的序列**未预测到限时间**（下降 + 仅上限、上升 + 仅下限）
- [ ] R² < `--r2-min`（默认 0.5）的序列未给到限日期，文案写明「数据离散，趋势不明显」；若调整过 `--r2-min`/`--horizon`，已向用户说明取值
- [ ] 置信提示已随每条趋势一同给出（R² 分档 + 期数是否偏少）
- [ ] **预计到限时间未被表述为「设备故障预测」「损坏时间」「寿命只剩 N 天」**
- [ ] 每条到限预测都带「按线性外推」字样

## 分析段
- [ ] 已替换 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字，字数 200~400
- [ ] 四段结构齐全：总体情况 → 已越限 → 趋势恶化与建议 → 数据不足说明（停运中的设备只说明停运依据）
- [ ] 未做故障原因诊断（未断言轴承/不对中/松动）
- [ ] 振动只按 ISO 10816 / GB/T 6075 分区概念表述，**未自给分区边界数值**，未把 A/B/C/D 区与设备重要度 A/B/C 混写
- [ ] 未给维修决策与停机建议
- [ ] 温度类参数已提示结合工况与环境温度；电流类已提示核对处理量；压力类已提示先排除工艺调整
- [ ] 建议动作限于：加密监测、安排复测、提交精密诊断、核对工况、提报缺陷

# 参数趋势表述口径与预测免责规范

## 一、趋势是怎么算出来的

| 量 | 算法 | 单位 |
|---|---|---|
| 斜率 slope | 最小二乘线性回归，x 为距首点的天数 | 参数单位/天 |
| R² | 回归决定系数，衡量点落在直线上的程度 | 0~1 |
| 变化率 changeRate | `(末期值 − 首期值) / |首期值| × 100%` | % |
| 预计到限天数 daysToLimit | `(限值 − 末期值) / 斜率`；两级限值时先向最近一级（高报 H / 低报 L）外推，只给高高报/低低报时向 HH/LL 外推 | 天 |
| 预计到限日期 etaDate | 末期采集日期 + ⌈daysToLimit⌉ | 日期 |

首期值为 0 时变化率无定义，输出 null（不按 0 或 100% 处理）。

## 二、置信提示（R² 分档）

| R² | 提示文案 | 含义 |
|---|---|---|
| ≥ 0.8 | 趋势明显 | 各期数据基本落在一条直线上，斜率可信 |
| 0.5 ~ 0.8 | 趋势一般 | 有方向但波动不小，外推结果要打折看 |
| < 0.5 | 数据离散，趋势不明显 | 斜率基本是噪声，**不给到限日期** |

**有效期数 < 5 期**时在文案后追加「（仅 N 期，期数偏少，置信有限）」，并把置信等级再降一档。期数越少、数据越离散，置信越低——两个维度都要在文案里体现。

### 两道闸（脚本内置，可用参数调整，不要在报告里绕过）

1. **R² < `--r2-min`（默认 0.5）不给到限日期**：数据离散时斜率是噪声，外推出来的天数没有意义。厂内有自己的判据可调，调整后在报告头部会显示实际取值。
2. **到限天数 > `--horizon`（默认 365 天）不作为预警呈现**：按当前斜率还要一年以上才到限，不是本期该盯的事，写进预警清单只会稀释真问题。

这两种情况在 `etaNote` 里写明原因与参数名，序列归入「趋势稳定」而非「趋势恶化」。

## 三、四类清单的判定

| 类别 | 判定 |
|---|---|
| `overLimit` | 最新有效值 > 高报(H) / > 高高报(HH) / < 低报(L) / < 低低报(LL)。**先判 HH/LL 再判 H/L**，`limitLevel` 记录等级；越 HH/LL 的排在清单最前，md 加「【注意】」提示核对 DCS 报警记录并报车间设备主任 |
| `deteriorating` | 未越限，且斜率方向指向某个限值、R² ≥ `--r2-min`、外推到限 ≤ `--horizon` 天；或斜率绝对值达到 `--threshold` 且 R² ≥ `--r2-min` |
| `stable` | 有 ≥3 期数据但不满足上面两条 |
| `insufficientData` | 有效期数 < 3，或全部采集时间相同 |

**方向一致才预测**：斜率为正只对上限外推，斜率为负只对下限外推。参数在下降而只设了上限，方向不对，**不预测到限时间**；上升而没设上限同理。已越限的序列不再预测到限时间。

### 两级限值口径（高报 / 高高报）

中石化炼化厂 DCS 与点检系统常见两级报警：**高报（H / PH）** 提示关注，**高高报（HH / PHH）** 多与联锁或紧急处置挂钩；低报 L / 低低报 LL 同理。限值由工艺/仪表归口设定，**本技能只读限值表判定，不自定、不修改限值**。报告中写「越高报」「越高高报」，不写「超上限」这种分不清等级的话；越 HH/LL 时建议动作是立即核对 DCS 报警记录并报车间设备主任、视情况报工程师，**是否停机由工艺/设备主管按规程决定**。

## 四、各类参数的劣化含义与表述

下表是**常见含义**，供撰写研判段时选词用。**本技能不做故障原因诊断**，不要据此断言是哪个部件的什么毛病——那是 `anomaly-triage-advisor` 与精密诊断的范围。

### 振动（mm/s、μm）

上升常与转动部件状态变化相关：不平衡、不对中、松动、轴承或联轴器磨损、基础螺栓松动、管线应力等都可能表现为振动上涨。

**分区概念（ISO 10816 / GB/T 6075 系列）**：机器振动烈度按机器类别划分为 A 区（新交付机器通常所在）、B 区（可长期运行）、C 区（不宜长期运行，应安排检修）、D 区（振动剧烈，可能造成损坏）四个区域；**各区的数值边界随机器类别、功率、基础刚性而异，本技能不写具体数值，一律以厂内限值表或 DCS 组态为准**。研判段可写「已进入限值表对应的高报区间」「按厂内限值属 C 区水平」，不得自行查表给分区边界数值，也不得把 A/B/C/D 区与设备重要度 A/B/C 混写。

| 应写 | 不应写 |
|---|---|
| 「振动速度由 4.2 升至 7.3 mm/s，斜率 0.17 mm/s·天，趋势明显」 | 「轴承已经损坏」 |
| 「建议缩短点检周期至每班一次，并安排一次频谱采集」 | 「确诊为不对中，需重新找正」 |
| 「按厂内限值表，该值已越高报，接近高高报」 | 「按 ISO 10816 查表属 C 区上限 7.1 mm/s」（本技能不自给分区数值） |

振动是最适合做趋势的参数，也最容易被单次异常读数带偏——报告里要把 R² 和期数一起给出来。

### 温度（℃）

轴承温度、电机绕组温度、介质温度上升可能与润滑状态、冷却效果、负荷变化、环境温度、测点接触状态有关。

| 应写 | 不应写 |
|---|---|
| 「轴承温度 79.8 ℃，越高报 75 ℃ 共 4.8 ℃，距高高报 85 ℃ 尚有 5.2 ℃」 | 「轴承烧了」 |
| 「建议核实润滑与冷却水量，确认是否伴随负荷或环境温度变化」 | 「必须立即停机」 |

温度受环境与工况影响大，**季节性上涨不等于设备劣化**，研判段要提醒结合工况一起看。

### 压力（MPa）

泵出口压力下降可能与叶轮磨损、内漏、进口过滤器堵塞、介质性质变化、工艺调整有关；过滤器前后压差上升常与堵塞相关。

| 应写 | 不应写 |
|---|---|
| 「出口压力由 1.60 降至 1.45 MPa，累计下降 9.9%」 | 「叶轮已磨损报废」 |
| 「建议核实是工艺调量还是设备内漏」 | 「确定为内漏，需解体检修」 |

压力最容易被工艺操作改变，**先排除工艺调整再谈设备劣化**。

### 电流（A）

电机电流上升可能与负荷增加、介质密度或黏度变化、转动部件卡涩、机械摩擦增大有关；下降可能与流量下降、抽空、联轴器问题有关。

| 应写 | 不应写 |
|---|---|
| 「电机电流由 118 升至 136 A，斜率 0.90 A/天，按线性外推距高报 165 A 约 32 天」 | 「电机快烧了，32 天后停机」 |
| 「建议核对同期处理量，排除负荷因素后再评估」 | 「确认为机械卡涩」 |

电流与负荷强相关，**不核对处理量就谈电流劣化是不成立的**。

### 流量（t/h、m³/h）

流量趋势多反映工艺状态而非设备本体状态，一般不单独作为设备劣化判据，须与压力、电流联看。

## 五、预测免责表述规范（硬约束）

预计到限时间是**按现有数据做线性外推**的统计结果。它假设参数继续按当前速率变化——而实际设备劣化通常不是线性的，工况一变整条趋势就变。

| 场景 | 应写 | **不得写** |
|---|---|---|
| 到限时间 | 「按线性外推，约 10 天后达到高报 9.0 mm/s」 | 「预计 10 天后设备损坏」「10 天后故障」 |
| 到限日期 | 「外推到限日期 2026-09-29，建议在此之前复测」 | 「2026-09-29 会坏 / 会停机」 |
| 恶化趋势 | 「趋势持续上升，建议加密监测」 | 「设备即将失效」「寿命只剩 10 天」 |
| 低 R² | 「数据离散，趋势不明显，暂不外推到限时间」 | 挑一个斜率硬给个天数 |
| 期数不足 | 「仅 2 期数据，不足以判断趋势」 | 「两次之间涨了 90%，趋势严重」 |

### 报告固定声明行（脚本已写入，不得删改）

> 预计到限时间为按现有数据线性外推的统计结果，仅供安排关注与复测参考，不是设备故障预测，也不代表设备将在该时间损坏。

这句话在「趋势恶化」清单之后与报告末尾各出现一次，两处都要保留。报告末尾另有通用声明行，同样不得删改：

> 本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。

## 六、分析段表述规范

撰写 200~400 字，四段结构：

1. **总体情况**：序列数、回溯期数、数据质量（不可解析点、时间重复）
2. **已越限设备**：先 HH/LL 后 H/L，逐条列出参数、最新值、越限等级、限值、超限幅度；有测点号的带上测点号
3. **趋势恶化设备与建议动作**：斜率、变化率、R²、预计到限时间 + 建议（加密监测 / 复测 / 安排精密诊断 / 核对工况），并注明预测为线性外推
4. **数据不足说明**：哪些序列因期数不足未算趋势，需补几期

### 硬约束

- 斜率、变化率、R²、到限天数**一律引用 `trends.json`**，不得目测曲线或心算。
- **期数不足 3 期的序列，不得给出任何趋势描述**（「在涨」「涨得快」都不行），只能说数据不足。
- 数值无法解析的点显示「—」，不得按 0 叙述（「有一期是 0」是错的）。
- 未提供限值表时不得说「未越限」，只能说「未提供限值，未做越限判定」。
- 不做故障原因诊断，不给维修决策，不判停机，不替代频谱分析与油液分析；不建议修改报警限值或联锁定值（工艺/仪表归口）。
- 振动只按分区概念表述，不自给分区边界数值。
- 宽表输入时采集时间按列头日期 00:00，研判段不要写成具体时刻。
- 建议动作限于：加密点检、安排复测、提交状态监测专业做精密诊断、核对工况与操作记录、提报缺陷（维修通知单）、报车间设备主任。

## 七、下游衔接

已越限或趋势恶化的设备可接 `01-日常运行监控与巡检/anomaly-triage-advisor` 做异常关注度（红/橙/黄）初判与要不要报工程师的建议，接 `02-缺陷报修与检修管理/defect-intake-grading` 登记缺陷（维修通知单）；与 `runtime-hours-tracker` 的累计运行小时一起看，比单看趋势更可靠。单次巡检/点检结果的汇总是 `inspection-data-digest` 的事，本技能不做。

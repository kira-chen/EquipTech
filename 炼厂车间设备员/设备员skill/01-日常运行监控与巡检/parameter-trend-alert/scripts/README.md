# scripts 使用说明

## trend.js —— 主脚本

```bash
node "<技能目录>/scripts/trend.js" \
  --input "<参数记录xlsx>" \
  --workshop "<车间名>" \
  --date <YYYY-MM-DD> \
  --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 含「参数记录」（别名：参数数据/监测记录/趋势数据/测点数据）工作表的 xlsx 或同结构 CSV 目录；可另含「报警限值」（别名：限值/报警设定）。长表与宽表（一列一期）均可，自动识别 |
| `--workshop` | 是 | 车间名称 |
| `--date` | 是 | 分析截止日期 |
| `--out` | 否 | 输出目录，默认 `<os.tmpdir()>/pta-out`（系统临时目录），**建议始终传 `--out`** |
| `--periods` | 否 | 回溯期数，默认 12；须为不小于 3 的整数 |
| `--from` | 否 | 起始日期；晚于 `--date` 时报错 |
| `--equipment` | 否 | 限定位号或测点号（仪表位号），逗号分隔 |
| `--param` | 否 | 限定参数名，逗号分隔 |
| `--threshold` | 否 | 斜率告警阈值（单位/天，绝对值），须 ≥ 0；仅在 R² ≥ `--r2-min` 时生效 |
| `--r2-min` | 否 | 判恶化/给到限日期的 R² 下限，默认 0.5，取值 0~1。R² 低于此值视为数据离散、斜率不可靠，不给到限日期。厂内有自己的判据可调 |
| `--horizon` | 否 | 到限关注窗口（天），默认 365，须为 ≥1 的整数；外推到限超过此天数不作为预警呈现 |
| `--wide` | 否 | 强制按宽表读取；未识别出 ≥3 个日期列头时报错 |
| `--wide-param` | 否 | 宽表没有「参数名」列时统一指定参数名（脚本不猜）；长表时忽略并 warning |
| `--status` | 否 | 设备运行状态来源：xlsx、单个 csv 或 csv 目录。按表头识别 **DCS 启停记录**（位号 + 开机时间/停机时间，一行一个运行段，停机时间为空 = 仍在运行）与**设备台账**（位号 + 运行状态/使用状态）；两种都给时启停记录优先。用来判断哪些设备停运（见关键行为 11） |

### 产出

| 文件 | 内容 |
|---|---|
| `trends.json` | 逐序列趋势结果（含 `runState`/`runStateSource`/`runStateBasis`/`lowIgnored`/`excludedStoppedPeriods`/`excludedStoppedSource`）+ `overLimit`/`deteriorating`/`stable`/`insufficientData`/`stopped`/`counts`（含 `overHighHigh`、`overHigh`、`twoLevelLimits`、`stopped`、`stoppedEquipment`、`suspectedStoppedEquipment`、`excludedStoppedPoints`、`seriesWithExcludedStopped`）+ `meta`（`r2Min`、`horizonDays`、`inputShape`、`statusProvided`、`statusSheets`、`runStateRule`、两条声明、`workshopScope` 车间范围核对结果数组：参数记录一条 sheet/status/column/total/kept/dropped/droppedRows/blank） |
| `alert.md` | 六节报告（有停运设备时第五节下加「### 停运中（不判定）」小节），分析段留占位符，末尾两条声明行 |
| `summary.json` | 末行摘要落盘 |

### 退出码
- `0`：成功
- `1`：失败（无「参数记录」表、无采集时间/数值列、既无位号也无测点号列、宽表无参数名且无 `--wide-param`、非法日期、periods < 3、负斜率阈值、r2-min 不在 0~1、horizon < 1、范围内无记录、输入不存在、`--status` 不存在或其中认不出启停记录/台账）

### 关键行为

1. **期数不足 3 期不算趋势**。有效期数 < 3 的序列归入 `insufficientData`，斜率、R²、变化率、到限时间全部 `null`。两点连线不是趋势。若最新值已越限，越限是单点事实仍会呈现，但依然不给趋势与预测。
2. **数值无法解析记 null 不记 0**。「未记录」「/」这类值按缺测处理并单列；宽表空格视为未测。带单位的数值（`78℃`、`4.5mm/s`、`0.35MPa`）剥离单位取数，每列只提示一次请核对单位一致。
3. **未提供限值表只算趋势不判越限**。概览显示「—（未提供限值表）」而不是 0；查不到限值的单条序列同样只算趋势。**脚本不自定限值**，限值以 DCS 组态或厂内限值表为准。
4. **两级限值**。限值表可给 高报/高高报/低报/低低报（H/HH/L/LL、PH/PHH/PL/PLL、上限/上上限/下限/下下限）。先判 HH/LL，再判 H/L；越 HH/LL 的排在越限清单最前并在 md 加「【注意】」。两级都给时到限时间先向最近一级（H/L）外推，只给 HH/LL 时向 HH/LL 外推。HH<H 或 LL>L 时 warning 请核实，不自动交换。
5. **宽表自动转长表**。表头里有 ≥3 个可解析为日期的列头（含年份，或 Excel 日期）且有位号/测点号列时识别为宽表；日期按列头、时间按 00:00。列头只写「9/1」这类无年份的不猜年份，按长表读取后因缺采集时间列报错。
6. **测点号与设备位号分列**。功能位置/设备位号归位号，仪表位号/测点号/测点归测点号；无位号时用测点号作序列键并 warning 提醒核对所属设备；限值表可按位号或测点号配对。SAP「设备编号」（8 位流水号）不作位号别名。
7. **方向不对不预测**。斜率为正只向上限外推，为负只向下限外推。已越限的不再预测。
8. **R² 与到限窗口两道闸**。R² < `--r2-min`（默认 0.5）不给到限日期；外推到限 > `--horizon`（默认 365 天）不作为预警呈现。两种情况在 `etaNote` 写明原因与参数名，归入「趋势稳定」。
9. **采集时间重复不去重**。原样保留并 warning。
10. **声明行**。md 末尾固定两条：线性外推声明；"本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准。" 产出不用 emoji，醒目提示用「【注意】」。
11. **停运设备不判低限、不判劣化**。备用、停运、停用、检修的设备在 DCS 里出口压力很低、振动和电流为 0，这不是参数越限。这类设备的全部序列：低于低报/低低报不判越限（`limitState` 为 null，`lowIgnored` 记被忽略的等级），不做劣化趋势判定、不预测到限时间，归入 `stopped`，md 第五节下单列「停运中（不判定）」并 warning 点名；**越高报/高高报照常判定**，照常进 `overLimit`，越限等级后标「（停运中）」或「（疑似停运）」。运行状态按优先级取：
    - `--status` 的启停记录：取开机时间不晚于该设备最新一期数据采集时间的最近一段，该段停机时间为空或晚于采集时间 → 运行，否则 → 停运；
    - `--status` 的设备台账：运行状态/使用状态为 备用、停运、停用、检修（含停机、停车）→ 停运，明确写「运行」→ 运行；「在用」只说明在册，不说明在运行，不下结论；
    - 以上都没有结论时数据自判：同一设备的电流（或转速）位号最新值都≈0（≤ 额定值或量程上限的 2%；没有这两列时电流 ≤0.5 A、转速 =0）→ **疑似停运**，同样处理，warning 提示提供台账或启停记录确认；没有电流/转速位号的设备维持原逻辑。
    - 设备归属只认「位号」（设备位号/功能位置）列：只有测点号、没有设备位号的序列归属不定，不套用停运判定。
12. **在运设备剔除回溯窗口里的停机期点**。刚由备机切为主机的设备，窗口前几期还是停机读数（振动、电流 0，出口压力很低），直接回归会算成上升趋势。逐期判停机：
    - 该设备在 `--status` 启停记录里有记录：采集时刻不在任何运行段内（此前有停机记录，或此后有开机记录）→ 该期停机；首段开机之前的点也按停机（开机即说明此前停机，导出只含窗口内的运行段）；
    - 没有启停记录：同一采集时刻同设备所有电流/转速位号读数都≈0（阈值同第 11 条）→ 该期停机；该时刻没有电流/转速读数不判；没有电流/转速位号的设备维持原逻辑。
    - 停机期点不参与回归、劣化判定与到限外推，记在 `excludedStoppedPeriods`（`excludedStoppedSource` 为依据），`periodsUsed` 为剔除后期数；窗口内有停机期（发生过停机/切泵）的序列（停机时不记读数的参数如轴承温度，自身无点可剔，但同设备在其首期之前的窗口内有停机期的，同样按此处理，item 记 `stopInWindow`），剔除后少于 4 期 → `insufficientData`，说明写「数据不足（切泵后运行期数偏少，剩 N 期）」，不做劣化判定、不预测到限，并入「数据不足（含停机期）」warning 一起点名；窗口内无停机期的序列最低仍为 3 期；越限（HH/H/L/LL）照常用剩余点判。warning 汇总点名剔除的序列，md 第六节研判段上方写「已剔除停机期 N 个点」；`counts.excludedStoppedPoints`、`counts.seriesWithExcludedStopped` 计数。
13. **车间范围核对（D007）**。只核对「参数记录」（报警限值表、`--status` 是按位号查找的表，不核对）：按「车间」列核对 `--workshop`（`C.workshopScope`），有本车间行时剔除其他车间的行并 warning（逐车间写行数），车间列为空的行按本车间保留；车间列取值全不一致时不筛，warning 与报告标题后均以【注意】提示；无车间列或命中的是「车间负责人」等人员列时不筛（「维护工厂」等不读入车间字段），口径行写「输入未含车间列，车间范围以取数条件为准」。宽表的车间列原样带到展开后的长表再核对，剔除行数按展开后的行计。口径行写在报告头「数据形态」之后。

### 置信提示分档

| R² | 文案 |
|---|---|
| ≥ 0.8 | 趋势明显 |
| 0.5 ~ 0.8 | 趋势一般 |
| < 0.5 | 数据离散，趋势不明显 |

有效期数 < 5 期时追加「（仅 N 期，期数偏少，置信有限）」并把置信等级降一档。分档文案固定；`--r2-min` 只改变"给不给到限日期/判不判恶化"的闸值。

## make-sample.js

```bash
node scripts/make-sample.js [--seed <n>]
```

- `sample-trend.xlsx`（长表，两级限值）恒 7 条序列：2 条已越限（1 条越高高报、1 条越高报）、2 条趋势恶化、2 条稳定、1 条只有 2 期（数据不足）、1 个无法解析的数值、1 组采集时间重复、1 个带「℃」后缀的数值。
- `sample-dcs-wide.xlsx`（宽表，DCS/SAP 列名：功能位置、功能位置描述、仪表位号、参数名称、工程单位、H/HH/L/LL）恒 3 条序列：1 条恶化、1 条稳定、1 条数据不足（宽表空格）。
- `sample-no-limit.xlsx`：无限值表。`sample-two-points.xlsx`：只有 2 期。

`--seed` 变则数值抖动变，但各类条数不变。

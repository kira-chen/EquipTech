# 运行小时与启停次数统计（runtime-hours-tracker）

面向中石化体系炼化厂车间（运行部）设备员，累计关键机组（特护机组、大型机泵、风机、汽轮机等）的运行小时与启停次数，对照装置大检修周期、部件更换周期给出到期预警，供设备员向车间设备主任与公司设备管理部门（机动部/设备部）申报检修需求时引用。**累计计算与阈值比对一律由脚本完成，模型只负责成文；不得手工累加或估算剩余寿命。**

## 适用条件
- 用户说"自上次大检修累计运行多少小时 / 启停多少次 / 运行小时到没到大修周期 / 轴承、机械密封到寿命了吗 / 大机组该不该报大检修计划"，并给出（或即将给出）启停记录、运行状态记录或运行记录表。
- 适用于设定了运行小时、启停次数或日历周期（年）阈值的关键设备；运行小时与日历周期是两个维度，分开解析、分开判定。
- 车间设备员可做：累计统计、到期预警清单、检修需求申报依据。**由 XX 归口**：检修计划编排与停机窗口由公司设备管理部门与计划员归口；设备剩余寿命与可靠性评估由设备工程师/专业机构归口；实际检修时机由设备工程师结合状态监测评估确定。
- 不适用：参数趋势与劣化分析；润滑换油周期；备机切换与盘车；检修计划排期与资源平衡。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含以下任一工作表：「启停记录」（一行一段，开机时间/停机时间）、「运行状态记录」（时序，一行一个状态点：时间、运行状态=运行/停机）、「运行记录」（直接给本期运行时长）；可选「阈值表」（位号、部件、阈值类型、阈值、上次归零日期、**期初累计小时**）。列名兼容 SAP PM / EM 导出（功能位置、设备、设备描述、启动时间、上次大检修日期、上次大检修后累计），字段见 `references/input-spec.md`。
- 必填信息：车间名称、统计截止日期（YYYY-MM-DD）。可选：统计起始日期、上期 runtime.json（累计续算）、指定设备范围、预警比例。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工累加运行小时。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| DCS位号数据 | `get_run_events` | `workshop`：车间名 | `--input` |
| 设备资产管理 | `get_maintenance_plans` | `workshop`：车间名；`for_skill=runtime-hours-tracker` | `--input` |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；把目录作为“交给脚本”一列的参数值。
2. `get_run_events`：不填 for_skill（填 lubrication-manager 是给润滑技能的另一种形态）。
3. `get_maintenance_plans`：输出阈值表：8000h、上次归零日期、期初累计小时。
4. 两个工具都按 `workshop`（与 `--workshop` 一致）取，不传会把全厂各车间的设备混在一份统计里。
5. `get_run_events` 中停机时间为空表示截至 DCS 数据截止时刻仍在运行：运行脚本时加 `--running-until "<DCS 数据截止时刻 YYYY-MM-DD HH:mm>"`（取 DCS 数据的截止时刻，不是取数时刻；演示数据截至当天 09:00），这些运行段计到该时刻（脚本 warning 点名）；不加则这些设备的当前运行段按不配对单列，运行小时阈值判未判定，在运设备的累计会被低估。

## 操作步骤
1. **确认统计范围与口径** —— 车间、起止日期、累计口径（自上次大检修归零累计 / 自投用累计）；不明确时向用户确认一次。检查阈值表是否带「期初累计小时」列：没有则累计只是本期增量，脚本会 warning，须提醒用户补期初或传上期 JSON。未提供阈值表时只统计不预警。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/runtime.js" --input "<xlsx路径>" --workshop "<车间名>" --date <YYYY-MM-DD> --out "<输入同目录>/运行统计"
   ```
   可选：`--from <起始日期>`、`--prev "<上期 runtime.json>"`、`--equipment "<位号,位号>"`、`--warn-ratio <预警比例，默认 0.9>`、`--running-until "<YYYY-MM-DD HH:mm>"`（数据源以空停机时间表示仍在运行时，计到该时刻）。建议始终传 `--out`，否则写到系统临时目录。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺表/缺列/无期初累计/时间区间重叠/启停不配对/阈值类型为空等）。脚本用法详见 `scripts/README.md`。
   - 启停记录不配对（只有启无停或反之）、状态记录末条为运行：warning + 该段计入 `incomplete` 单列一节，**不得按截止时间强行补一次停机**。只有数据源明确以空停机时间表示「仍在运行」（如 DCS 启停记录）、且用户给出或按 DCS 数据截止时刻传入 `--running-until` 时，才把这类段计到该时刻，且每台只认时间上最后一段（其后再无开停记录的那条空停机行；上一段停机时刻正好等于本段开机时刻仍算最后一段），更早的空停机行照旧单列。
   - 传 `--prev` 时只导出上期截止日之后的记录；本期记录早于或等于上期截止日时脚本 warning 提示重复计入。上期 JSON 中累计小时为空的设备判未判定，不按 0 续算；累计启停次数为空同理，本期累计启停记 null，启停次数阈值判未判定。
   - 运行时间区间重叠：warning 说明数据质量问题，原样累计不去重；**绝不按满负荷补齐缺口**。
   - 阈值表里有、本期记录里没有的设备（如备机）：照常列出，本期 0h，累计 = 期初/上期值，照常判阈值，注明「本期无运行记录」（`noRunRecord`），warning 点名；交付时提醒用户核实这些设备确实未运行。
   - 阈值类型为空且取值无单位、日历周期缺上次归零日期、累计不可算：判 `undetermined` 单列，**不默认按运行小时**。
3. **读取 runtime.json** —— 从 `<输出目录>/runtime.json` 获取：`byEquipment`（逐台：本期运行小时、启停次数、期初累计、累计口径、距阈值余量、已用比例）、`exceeded`（已超阈值）、`dueSoon`（接近阈值）、`undetermined`（未判定）、`incomplete`（数据不完整）、`items`（供下游按位号取累计小时）、`counts`。
4. **撰写"统计说明"** —— 读 `references/runtime-rules.md` 的表述口径，撰写 200~350 字，按"总体情况 → 已超阈值设备 → 接近阈值设备与建议 → 未判定与数据缺口说明"结构，替换 `runtime-report.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**小时数、次数、余量、到期日一律引用 runtime.json；超阈值不等于必须立即检修，须按口径表述。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `runtime-report.md` 与 `runtime.json`。**报告中"阈值到期为计划提示，实际检修时机由设备工程师结合状态评估确定"与"本材料由脚本汇总、模型成文……"两行声明不得删除或改写。**

## 预期结果
- `runtime-report.md`：运行统计报告，含统计概览、逐台累计明细、已超阈值、接近阈值、未判定项、数据缺口说明、统计说明七个部分（有 warnings 时另附"数据提示"）。
- `runtime.json`：累计结果与阈值比对；`summary.json`：脚本末行摘要（含 `items[]`，可作 lubrication-manager 的 `--run-hours` 输入）。
- 交付时向用户说明：统计区间与累计口径（期初+本期 / 上期续算 / 仅本期增量）、超阈值数量、临近阈值数量、未判定数量与缺什么、数据缺口情况、脚本 warnings（如有）。

## 不适用范围
- 不做设备剩余寿命评估与可靠性建模。
- 不决定检修时机，不编排大检修/日常维修计划与停机窗口。
- 不替代状态监测数据，不把运行小时单独作为检修决策依据。

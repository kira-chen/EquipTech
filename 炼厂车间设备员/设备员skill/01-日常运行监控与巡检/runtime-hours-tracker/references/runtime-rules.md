# 运行小时统计口径与表述规范（中石化体系炼化厂车间设备员）

## 一、累计口径

**累计运行小时 = 期初累计小时（上次大检修后累计）+ 本期增量。**

| 累计口径 `cumBasis` | 含义 | 何时 |
|---|---|---|
| `base` | 期初累计 + 本期增量 | 阈值表给了「期初累计小时」 |
| `prev` | 上期 runtime.json 续算 + 本期增量 | 传了 `--prev`（与期初并存时以此为准，期初不重复计入） |
| `periodOnly` | 仅本期增量 | 两者都没有；概览与 warning 明示，**不代表自上次大检修累计** |

部件级期初（轴承、机械密封各自更换归零）按阈值表该行自己的期初算（`basis: rowBase`）；设备级期初取部件为空/整机/机组的行。

本期增量三种来源，优先级：**启停记录 > 运行状态记录（时序）> 运行记录**。

| 来源 | 计算方式 |
|---|---|
| 启停记录 | 逐段 `停机时间 − 开机时间` 求和 |
| 运行状态记录 | 按位号排序，"运行 → 停机"折算一段；连续"运行"只计一次启动 |
| 运行记录 | 直接累加「运行时长」列（可带单位） |

## 二、三类阈值

| 类型 | 比对 | 到期判定 |
|---|---|---|
| 运行小时 | 累计运行小时 vs 阈值 | 已用比例 = 累计 ÷ 阈值 |
| 启停次数 | 累计启停次数 vs 阈值 | 同上 |
| 日历周期（年/月） | 自「上次归零日期」起已运行天数 vs 周期 | 到期日 = 归零日期 + 自然月（`addMonths`，不是 365 天）；缺归零日期 → 未判定 |

运行小时与日历周期是**两个维度**：大机组按年检修周期管理的同时也看运行小时，同一机组可各有一条，各自判定、各自列。

### 四档状态

| 状态 | 条件 |
|---|---|
| exceeded | 已用比例 ≥ 100%（日历：截止日 ≥ 到期日） |
| dueSoon | 已用比例 ≥ `--warn-ratio`（默认 90%） |
| normal | 低于预警比例 |
| **undetermined** | 阈值类型为空且取值无单位 / 类型归不进三类 / 阈值无法解析 / 日历周期缺归零日期 / 累计值为 null |

### 不默认、不臆测

- 未提供阈值表 → 只统计不预警，概览显示「—（未提供阈值表）」
- 阈值类型为空且取值无单位 → **不默认按运行小时**，判未判定并写明缺什么
- 累计值为 null → 未判定并注明「不预警」
- 无期初累计 → 累计仅为本期增量，明示而不补

**绝不因为查不到阈值就按某个默认周期预警。**

## 三、启停记录的四种异常（硬规则）

1. **只有开机无停机**：不计入累计，单列，**绝不按截止时间强行补一次停机**（可能仍在运行，也可能漏记，凭字段无法区分）。
2. **只有停机无开机**：单列，不计入。
3. **停机时间早于开机时间**：原样保留并单列，不调换字段。
4. **区间重叠**：原样累加，不去重也不合并，warning 提示核实台账。

## 四、停机间隔不是数据缺口

两段运行之间的间隔是正常停机，记录在 `idleIntervals` 供参考，不进「数据缺口说明」。真正的数据缺口（本应有记录却没有）凭字段无法识别，不臆测。

## 五、分析段表述规范

撰写 200~350 字，四段结构：总体情况（设备数、累计口径、数据完整性）→ 已超阈值设备 → 接近阈值设备与建议 → 未判定与数据缺口说明。

| 场景 | 应写 | 不得写 |
|---|---|---|
| 超阈值 | 「自上次大检修累计 23,578 小时，已用 98.2%，建议纳入下次大检修计划申报」 | 「已到大修期，必须停机检修」 |
| 日历到期 | 「大检修周期 3 年，到期日 2026-11-01，余 41 天」 | 「必须在 11 月 1 日前停工」 |
| 仅本期增量 | 「该台无期初累计，数字仅为本期增量，请补上次大检修后累计」 | 直接把本期增量称为"累计" |
| 不配对 | 「该段未计入累计，请核实是仍在运行还是漏记停机」 | 按截止时间补后给累计值 |
| 重叠 | 「两段区间重叠，已原样保留，请核实台账」 | 自行去重后给"正确"的数 |

### 硬约束

- **超阈值不等于必须立即检修**。运行小时只是判据之一，实际检修时机要结合状态监测、工艺安排、备件到位情况综合判断，由设备工程师评估、公司设备管理部门按检修计划确定。
- 报告固定带两行声明：「阈值到期为计划提示，实际检修时机由设备工程师结合状态评估确定」「本材料由脚本汇总、模型成文，仅供设备员复核参考，不替代审批、定性、验收与签字；厂内制度与系统数据为准」。
- 不做剩余寿命评估与可靠性建模；不编排检修计划与停机窗口。

## 六、制度引用

- 检修分级按《中国石化设备管理规定》《炼化企业设备管理技术规定》：装置大检修（停工检修）/ 日常维修 / 抢修 / 专项。运行小时与年度周期只是申报大检修或部件更换的依据之一，周期数值以厂内检修规程、设备完整性管理体系文件为准，脚本不内置任何周期值。
- 特护设备（大机组、关键机组）运行状况按厂内特护管理要求逐台跟踪，本技能的累计结果可作特护日报/月报"运行状况"栏的数据来源。

## 七、下游衔接

- `items[].cumulativeHours` 可作 `lubrication-manager --run-hours` 输入，按运行小时判换油周期。
- 超阈值设备可接 `02-缺陷报修与检修管理/maintenance-demand-rollup` 提报检修需求；结合 `parameter-trend-alert` 的趋势一起看，比单看运行小时更可靠。
- 备机切换与盘车到期不在本技能，用 `standby-rotation-reminder`。

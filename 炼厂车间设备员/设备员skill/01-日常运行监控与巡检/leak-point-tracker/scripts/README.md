# scripts 使用说明

## track.js —— 主脚本

```bash
node "<技能目录>/scripts/track.js" \
  --input "<检测记录xlsx路径>" \
  --workshop "<车间名>" \
  --date <YYYY-MM-DD> \
  --out "<输出目录>" \
  [--ledger <历史漏点台账xlsx>] [--seal-points <密封点台账xlsx | "静:N,动:M">] \
  [--static-limit <‰>] [--dynamic-limit <‰>]
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 检测记录 / 漏点记录 xlsx 路径，或同结构 CSV 目录（工作表「检测记录」「漏点记录」「LDAR检测数据」等均可识别） |
| `--workshop` | 是 | 车间（运行部）名称 |
| `--date` | 是 | 统计截止日期 YYYY-MM-DD，修复时限与超期天数以此为基准 |
| `--out` | 否 | 输出目录。默认为系统临时目录 `<os.tmpdir()>/lpt-out`，**建议始终传 `--out`** |
| `--ledger` | 否 | 历史漏点台账 xlsx（含「漏点台账」工作表），用于续跟踪与新增判定；不传时本期漏点全部按新增登记并 warning |
| `--seal-points` | 否 | 泄漏率分母。两种形式：① 密封点台账 xlsx（工作表「密封点台账」，一行一密封点，按「密封类型」列或组件类型推定计数；或汇总表含「静密封点数 / 动密封点数」列）；② 字符串 `"静:12000,动:800"`。不传时静/动泄漏率为 `null` 并单列「未提供密封点总数」 |
| `--static-limit` | 否 | 静密封点泄漏率厂内考核线（‰）。不传时只列泄漏率不作达标判定 |
| `--dynamic-limit` | 否 | 动密封点泄漏率厂内考核线（‰）。同上 |
| `--threshold-voc` | 否 | VOCs 气体 / 轻液泄漏认定阈值（μmol/mol），默认参考口径 2000 |
| `--threshold-liquid` | 否 | 重液泄漏认定阈值（μmol/mol），默认参考口径 500 |
| `--repair-days` | 否 | 首次修复时限（天），默认参考口径 5 |
| `--final-days` | 否 | 最终修复时限（天），默认参考口径 15；小于 `--repair-days` 时报错 |

阈值与时限的默认值是**参考口径**而非法规数值的转述；制度出处为 GB 31570 与中国石化 LDAR 管理要求，数值以厂内制度文件为准（报告中由脚本写入出处行）。

### 产出

| 文件 | 内容 |
|---|---|
| `leaks.json` | `sealPoints`（顶层，`{static,dynamic}.{total,leaks}`，供 equipment-weekly-monthly-report 算泄漏率；未给 `--seal-points` 时为 null）、`meta`（含 `workshopScope` 车间范围核对结果数组：检测记录、历史台账、逐点密封点台账各一条 sheet/status/column/total/kept/dropped/droppedRows/blank）、`counts`、`metrics`（修复率、平均修复时长、`leakRate` 静/动密封点泄漏率、阈值与时限口径、按组件类型分布）、`newLeaks`、`open`、`overdue`、`delayed`、`repaired`、`undetermined`、`noLeak`、`unreachable`、`duplicates`、`ledger`、`items`、`warnings` |
| `leak-report.md` | 九节报告（一、总体概览；二、新增漏点；三、超期未修；四、未修复（期限内）；五、延迟修复（经批准）；六、未判定；七、修复闭环；八、编号重复与数据提示；九、情况说明），开头重点提示、制度出处行与合规提示行由脚本直接写入；说明段留 `<!-- ANALYSIS_START/END -->` 占位；醒目提示用「【注意】」「【未判定】」，不用 emoji |
| `ledger.xlsx` | 更新后的全量漏点台账（历史未复测条目 + 本期全部记录），含设备编号、装置、组件子类型、密封类型、检测方法、不可达点、复测日期、延迟修复批准日期/批准人、认定结果与依据、两级修复期限、超期天数、当前归类 |
| `summary.json` | 末行摘要落盘（Windows 控制台乱码兜底） |

### 关键判定口径（不可放宽）

- 检测值为空或无法解析 → 输出 `null` 并归入 `undetermined`，**绝不按 0 计为不泄漏**（环保合规红线）；带单位值（「3200ppm」「4.5 μmol/mol」）剥离单位取数并一次性 warning；带比较符（「>10000」）不猜测 → `null`
- 介质与介质状态无法归类导致阈值不确定 → `undetermined`，**不按气体或重液任一阈值默认处理**
- 无检测值的可见泄漏按定性口径单独判定：滴漏 / 成股流出即认定泄漏；渗漏列为观察项；**两类来源在报告中分开统计，不折算、不混算**
- 不可达点（「是否不可达」=是）且无检测值 → `undetermined`，不按不泄漏
- 状态「延迟修复」且有延迟修复批准日期 → `delayed` 单列，不计超期；**无批准日期 → `undetermined`**，既不按已批准也不按超期
- 密封点编号重复 → warning 注明两处行号，**两条均保留并各自判定，不自动合并**
- 已认定泄漏但修复状态缺失或无法识别 → `undetermined`，不按未修复或已修复默认处理
- 状态填「已修复」但无最终修复日期 → 留在 `open`，**不计入修复闭环**
- 修复率分母为 0 → `null`，报告显示「—」，**不写 0%**
- 静/动密封点泄漏率 = 本期认定泄漏点数 ÷ 密封点总数 × 1000（‰）；无总数 → `null`；静/动无法识别的泄漏点单独计数、不进任一分子；**未给厂内考核线不判合格/达标**
- 本底值只登记（`items[].bg`），不参与认定、**不从检测值中扣除**；输入有非空本底值时给一条 warning（列行数，`counts.backgroundFilled`），md 口径处加一行「本底值：本底值仅登记，未从检测值中扣除；如厂内按扣除本底后的净值判定泄漏，请按厂内口径复核」；本底值列全空或无该列时不提示
- 合规提示行与制度出处行由脚本直接写入 md，**不得删除或改写**
- 车间范围核对（D007）：检测记录、`--ledger` 历史台账、逐点形式的密封点台账各自按「车间」列核对 `--workshop`（`C.workshopScope`）。有本车间行时剔除其他车间的行并 warning（逐车间写行数），车间列为空的行按本车间保留；车间列取值全不一致时不筛，warning 与报告标题后均以【注意】提示；无车间列或命中的是「车间负责人」等人员列时不筛（「维护工厂」等不读入车间字段），口径行写「输入未含车间列，车间范围以取数条件为准」。口径行写在报告头「认定口径」之前

### 别名合并说明

`ALIASES = C.mergeAliases({...局部...})`：局部别名优先，再并入中石化系统共享别名（SAP PM / EM / 智能巡检）。已核对的合并影响：
- 「设备编号 / 设备 / 设备号 / 设备编码 / 技术对象编号 / EM编码」归**设备编号**列单独展示，不再作位号别名（SAP 设备编号是流水号，不是位号）；「功能位置 / 技术对象 / TAG」归位号。
- 密封点编号别名已去掉「序号 / ID」：LDAR 系统导出常带「序号」列，保留会误配。
- 共享别名「设备」在前缀轮可能命中「设备描述」等列（仅当表中无设备编号类列时），该列只做展示不参与判定。

### 退出码
- `0`：成功，末行输出 `{"ok":true,...}`
- `1`：失败，末行输出 `{"ok":false,"error":"...","warnings":[...]}`

## make-sample.js —— 样例生成

```bash
node scripts/make-sample.js [--seed <n>] [--date <YYYY-MM-DD>]
```

生成 6 份样例：主检测记录（覆盖全部边界，含一条经批准的延迟修复）、LDAR 系统 / SAP 列名导出（标签号、功能位置、设备、工厂区段、组件子类型、密封类型、检测方法、是否不可达、复测日期、延迟修复批准、带单位检测值）、脏数据变体（编号重复 + 合计行 + 标题行 + 别名列头 + 状态无法识别）、全闭环变体（无告警提示）、历史漏点台账（`--ledger` 续跟踪）、密封点台账（`--seal-points` 分母，1600 行：静 1200 / 动 400）。
seed 改变检测时间在区间内的取值与检测值在阈值同一侧的取值，但不改变结论：主样例恒为 15 条记录、9 处认定泄漏（仪器 7 + 可见 2）、3 处超期未修、2 处期限内未修、1 处延迟修复、3 处修复闭环、3 处未判定、3 处未认定泄漏。

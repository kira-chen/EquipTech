# 泄漏认定阈值、修复时限、泄漏率与表述规范（中石化体系炼化厂车间设备员口径）

## 〇、制度出处与归口

- 制度出处：**GB 31570《石油炼制工业污染物排放标准》与中国石化 LDAR 管理要求**（名称引用，本文件不转述任何法规数值）。脚本内置的阈值与时限是**默认参考口径**，数值以厂内制度文件为准；用户给出厂内口径时用参数覆盖，报告中标注「用户指定口径」。
- 岗位边界：车间设备员做漏点登记、台账、修复进度跟踪与催办、泄漏率统计、提 SAP PM **维修通知单**；法定 LDAR 检测与报告、泄漏率考核线、达标判定由公司环保（HSE）部门与生态环境主管部门归口；延迟修复审批走厂内 LDAR 管理流程；工单创建与定工时由计划员 / 维修单位归口。
- 交付对象：车间设备主任 / 公司设备管理部门。

## 一、泄漏认定阈值（默认参考口径）

> **本表为脚本内置的默认参考口径，不是任何一家厂的正式规定，也不是法定限值的转述。** 用户给出厂内口径时，用 `--threshold-voc <阈值>` / `--threshold-liquid <阈值>` 覆盖；覆盖后报告中标注「用户指定口径（已覆盖：--threshold-voc……）」，未覆盖时标注「默认参考口径（references/ldar-rules.md，以现行法规与厂内规定为准）」。

| 介质类别 | 默认泄漏认定阈值 | 说明 |
|---|---|---|
| VOCs 气体 / 轻液 | **2000 μmol/mol** | 气相、轻液（汽油、石脑油、液化气、干气等）密封点的净检测值达到或超过该值即认定泄漏 |
| 重液 | **500 μmol/mol** | 重油、渣油、蜡油等重质液体密封点采用更严的阈值 |
| 介质状态缺失 / 无法识别 | **不适用** | 标 `undetermined`，**绝不按气体或重液任一阈值默认处理** |

判定式：`检测值 ≥ 该介质类别阈值` → 认定泄漏；`检测值 < 阈值` → 未认定泄漏。带单位的检测值（「3200ppm」）剥离单位取数；带比较符（「>10000」）不猜测，进未判定。

## 二、可见泄漏定性口径（无检测值通道）

现场巡检发现的跑冒滴漏**没有仪器检测值**，按目视形态定性判定，**不折算为浓度，也不与仪器检测值混算**：

| 目视形态 | 判定 | 说明 |
|---|---|---|
| 滴漏、成股流出、喷溅 | **认定泄漏** | 进入修复时限跟踪，与仪器检测认定的漏点同样计入 `newLeaks` / `overdue` / `repaired` 与泄漏率分子 |
| 渗漏、油迹、微渗 | **不认定泄漏，列为观察项** | 留痕在台账中，不计入认定泄漏数，不计算修复时限 |
| 目视未见泄漏 | 不认定泄漏 | |
| 形态无法识别，且无检测值 | **`undetermined`** | 不按不泄漏处理 |

报告「一、总体概览」中必须分来源列出：仪器检测（记录数 / 认定泄漏数）、现场可见泄漏（记录数 / 认定泄漏数）、未判定。**禁止把可见泄漏按某个浓度值计入仪器检测统计，也禁止把两类来源的认定数合并后当作仪器检测结果对外表述。**

## 三、不可达点

LDAR 系统标记「是否不可达 = 是」的密封点，本期无检测值、无可见泄漏记录时 → `undetermined`（原因写明不可达点未检测），同时计入 `counts.unreachable`。**不按不泄漏处理**；不可达点的检测安排按厂内 LDAR 管理要求执行，脚本不替用户判断是否免检。

## 四、修复时限默认口径

> 同样为默认参考口径，以现行法规与厂内规定为准；`--repair-days` / `--final-days` 可覆盖。

| 时限 | 默认天数 | 起算日 | 超期判定 |
|---|---|---|---|
| 首次修复 | **5 天** | 检测 / 发现日期 | 截止日期 > 起算日 + 5 天 且「首次修复日期」为空 → 首次修复超期 |
| 最终修复 | **15 天** | 检测 / 发现日期 | 截止日期 > 起算日 + 15 天 且未完成最终修复 → 最终修复超期 |

- 两类超期同时成立时，报告按**最终修复超期**列示（更严重），超期天数取最终修复超期天数
- `--final-days` 小于 `--repair-days` 时脚本报错终止，不做静默修正
- 已认定泄漏但**检测时间缺失或无法解析** → 时限无法计算，该点留在「四、未修复」中跟踪并 warning，**绝不按超期或未超期任一侧默认处理**

## 五、延迟修复（单列状态）

需要停工、停车或特殊条件才能修复的漏点，按厂内 LDAR 管理要求可**经批准延迟修复**。脚本口径：

| 情形 | 归类 | 说明 |
|---|---|---|
| 状态为「延迟修复」且台账有**延迟修复批准日期** | `delayed` 单列「五、延迟修复（经批准）」 | **不计超期**；保留原最终修复期限供参考；须在批准的停工/检修窗口内修复并复测 |
| 状态为「延迟修复」但**无批准日期** | `undetermined` | 原因写明「未填延迟修复批准日期」；**既不按已批准延迟处理，也不按超期处理**，由设备员补录审批记录后重算 |

延迟修复的审批本身由厂内流程归口，脚本只核对台账里有没有批准日期与批准人，不判断批准是否合规。「计划检修」「停车修复」「已提通知单」等写法仍归**未修复**，照常计超期——未经批准的等待不等于延迟修复。

## 六、修复闭环判定

| 归类 | 判定条件 | 说明 |
|---|---|---|
| `repaired` 已修复闭环 | 状态 = 已修复 **且** 最终修复日期非空 | 唯一计入修复率分子的情况；最终修复日期晚于最终修复期限时，仍计闭环但标注「超出最终修复时限 N 天」；复测日期与复测值展示 |
| `overdue` 超期未修 | 已认定泄漏 **且** 未闭环 **且** 未经批准延迟 **且** 超出首次或最终修复时限 | 输出超期类型与超期天数 |
| `open` 未修复 | 已认定泄漏 **且** 未闭环 **且** 在时限内（或时限无法计算） | 含「状态填已修复但无最终修复日期」的项 |
| `delayed` 延迟修复（经批准） | 已认定泄漏 **且** 状态延迟修复 **且** 有批准日期 | 不计超期 |
| `undetermined` 未判定 | 检测值缺失/无法解析且形态不明 / 介质状态无法确定阈值 / 不可达点未检测 / 已认定泄漏但修复状态缺失或无法识别 / 延迟修复无批准日期 | 单列一节并注明缺哪个字段 |
| `noLeak` 未认定泄漏 | 检测值低于阈值，或目视为渗漏、未见泄漏 | 留痕，不进修复跟踪 |

**禁止**：
- 检测值为空或无法解析时按 0 计为不泄漏（**本技能最关键的合规红线**）
- 介质状态不明时按气体 2000 或重液 500 任选其一套用
- 把「状态填已修复但无最终修复日期」的项计入修复闭环
- 把可见泄漏的滴漏项折算浓度后与仪器检测值一并统计
- 把无批准日期的「延迟修复」当作已批准，或反过来当作超期
- 密封点编号重复时自动合并为一条

## 七、修复率与泄漏率算法

```
修复率 = 最终修复闭环数 / 本期认定泄漏数 × 100%
静密封点泄漏率（‰）= 本期认定泄漏的静密封点数 / 静密封点总数 × 1000
动密封点泄漏率（‰）= 本期认定泄漏的动密封点数 / 动密封点总数 × 1000
```

- 修复率分母为本期**认定泄漏**的漏点数（仪器认定 + 可见泄漏认定），**不含 `undetermined` 与 `noLeak`**；**分母为 0 时输出 `null`，报告显示「—」，不得写 0%**
- 泄漏率分子按「密封类型」列或组件类型推定分静/动（见 input-spec）；无法识别的泄漏点单独计数、不进任一分子并「【注意】」提示
- 泄漏率分母来自 `--seal-points`（密封点台账逐点计数 / 汇总表 / "静:N,动:M"）；**未提供 → `null`，报告单列「【未判定】未提供密封点总数」，不得写 0‰**
- **考核线以厂内指标为准**（常见 ≤0.5‰ / ≤2‰ 仅为经验参考，不写入脚本）：只有 `--static-limit` / `--dynamic-limit` 给了厂内考核线才判「不高于 / 高于考核线」，否则判定列写「未判定（未提供厂内考核线）」，**不得自行判合格或达标**
- 平均修复时长 = 已闭环项的（最终修复日期 − 检测/发现日期）均值，仅纳入两端日期均可解析且非负的项；无可计算项时输出 `null`，显示「—」

## 八、未判定项处理要求

未判定项在本技能中享有三项固定待遇，**任何情况下不得删减或弱化**：

1. **开头提示**：存在未判定项时，报告开头「【注意】重点提示」写明「N 处记录因检测值缺失或字段不全无法判定……未按不泄漏处理」，由脚本直接写入（不是占位符）。
2. **单独成节**：「六、未判定清单」逐项列出密封点编号、位号、原始检测值、原始介质/状态、原始泄漏形态、原始状态、未判定原因与出处行号。
3. **不进任何统计口径**：既不计入认定泄漏数，也不计入未认定泄漏数；修复率与泄漏率分子不含未判定项。

无超期未修项且无未判定项时，开头改写为「本期无超期未修漏点，亦无因数据缺失而未判定的记录」，**不得凭空生成告警**。

## 九、编号重复处理

同一密封点编号在本期检测记录中出现两次及以上时：

1. **两条均保留并各自判定**，脚本不自动合并、不去重、不取较严或较宽的一条
2. 产生 warning，具体到 sheet 名与两处行号
3. 进「八、编号重复与数据提示」一节，由设备员核实是否为同一密封点（常见于编号录入错误、同一设备多个密封点共用编号）

## 十、说明段表述规范

撰写 200~400 字，结构固定为五段：

1. **总体情况**：统计范围、记录数、认定泄漏数（分仪器 / 可见两类，分静 / 动密封）、采用的阈值与时限口径。
2. **新增漏点**：本期新增项数、涉及组件类型与装置区域、检测值区间；需维修的已提或拟提维修通知单。
3. **超期未修与延迟修复**：逐条或分类说明超期类型（首次 / 最终）、超期天数、责任人；经批准延迟修复的项数与安排窗口；无批准日期的延迟修复须补录。
4. **修复闭环与泄漏率**：闭环项数、修复率、平均修复时长；静/动密封点泄漏率及分母来源；有厂内考核线才写达标与否，否则写「考核线以厂内指标为准，本期未判定」。
5. **下一步安排**：未判定项的补测补录安排、超期项的修复计划、需纳入检修窗口的项、不可达点检测安排。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 未判定项 | 「因检测值缺失，该密封点是否泄漏无法判定，须补测后重新登记」 | 「检测值为 0，未泄漏」「未测到，按合格计」 |
| 可见泄漏 | 「现场目视为阀杆连续滴漏，按定性口径认定泄漏，无仪器检测值」 | 「目测约 3000 μmol/mol」「折合浓度超标」 |
| 渗漏观察项 | 「法兰面渗油，按定性口径列为观察项，未认定泄漏」 | 「轻微泄漏，已认定」「基本不漏，可忽略」 |
| 超期 | 「检测日期起算已超出最终修复时限 12 天，台账记录状态为未修复」 | 「责任人拖延」「车间不重视」 |
| 延迟修复 | 「经批准延迟修复 1 处（批准日期 X），列入停工窗口；另 1 处状态为延迟修复但无批准日期，已列未判定，须补录审批记录」 | 「延迟修复的都不算超期」「口头同意即可」 |
| 泄漏率 | 「静密封点泄漏率 X‰（分母来自密封点台账 N 点），考核线以厂内指标为准，本期未判定」 | 「泄漏率 X‰，低于国家标准 0.5‰，达标」「未提供总数按 0‰」 |
| 阈值 | 「按默认参考口径（气体/轻液 2000、重液 500 μmol/mol），制度出处 GB 31570 与中国石化 LDAR 管理要求，数值以厂内制度为准」 | 「按国标 2000 判定」「法定限值为 2000」 |
| 维修安排 | 「已提维修通知单，待计划员排工单」 | 「已开工单」「车间已定工时」 |
| 修复率 | 引用 leaks.json 的 `metrics.repairRate` | 自行计算或换算口径 |
| 分母为 0 | 「本期无认定泄漏的漏点，不计算修复率」 | 「修复率 0%」「修复率 100%」 |
| 编号重复 | 「两条记录编号相同，脚本未合并，须核实是否为同一密封点」 | 「已去重」「按一处漏点计」 |

### 硬约束

- **不核算 VOCs 排放量**，不做物料衡算、不估算年排放量。
- **不编制法定 LDAR 检测报告**、备案表与排污许可证执行报告，不替代第三方检测机构出具的检测数据。
- **不替代环保部门的达标判定**，不内置泄漏率考核线。本报告只做车间内部的漏点登记与修复进度跟踪。
- **不做泄漏根本原因分析与密封选型建议**，不代为下达停车、隔离或应急处置指令，不替代延迟修复审批。
- **数量、天数、比率一律引用 leaks.json**，不得自行统计。
- **合规提示行与制度出处行不得删除或改写**：
  > 本报告为车间内部泄漏点跟踪材料，不替代法定 LDAR 检测报告与排污许可执行报告；泄漏认定阈值、修复时限与泄漏率考核线以现行法规与厂内规定为准，达标判定以生态环境主管部门意见为准。
  > 制度出处：GB 31570 与中国石化 LDAR 管理要求（名称引用，不转述数值）；脚本内置阈值与时限为默认参考口径，数值以厂内制度文件为准。

## 十一、与相邻技能的边界

| 技能 | 管什么 | 与本技能的分界 |
|---|---|---|
| **`emission-daily-check`**（环保排放数据日检） | **排放浓度日检**：废气排放口、废水排口的在线/手工监测浓度，逐项对照排放限值做达标核查 | 对象是**排放口的排放浓度**，关注**是否达标排放**；本技能对象是**装置密封点的泄漏**，关注**漏点是否按时限修复闭环与泄漏率**。**排放浓度超标不等于有漏点，漏点超期未修也不直接构成排放超标**，两份产出不得互相引用对方的结论数字 |
| `inspection-data-digest` | 巡检 / 点检数据汇总与异常识别 | 巡检中发现的跑冒滴漏，登记跟踪转本技能 |
| `equipment-weekly-monthly-report` | 设备周报月报 | 月报的静/动密封点泄漏率直接读本技能 `leaks.json` 的 `metrics.leakRate` |
| `defect-intake-grading` | 设备缺陷登记与分级（A/B/C） | 漏点需走缺陷维修流程时转该技能 |
| `hazard-closure-tracker` | 隐患整改闭环跟踪（五定） | 泄漏被认定为隐患后的整改跟踪转该技能 |

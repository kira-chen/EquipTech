# 交付自检清单

运行脚本后、交付前逐项核对。

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；若为 `false`，已把 `error` 原文告知用户并终止，未手工判定泄漏或计算时限
- [ ] `warnings` 已逐条告知用户，未隐去任何一条（缺表 / 缺列 / 检测值无法解析 / 密封点编号重复 / 状态取值非法 / 未提供历史台账）
- [ ] `leaks.json`、`leak-report.md`、`ledger.xlsx` 均已生成

## 未判定项（最高优先级，环保合规红线）
- [ ] 检测值为空或无法解析的记录，在 `undetermined` 中且 `value` 为 `null`，**未按 0 计为不泄漏**
- [ ] 未判定项**未**出现在 `noLeak`（未认定泄漏）数组中，也未出现在认定泄漏清单中
- [ ] 介质与介质状态无法确定阈值的记录在 `undetermined` 中，**未按气体 2000 或重液 500 任一阈值套用**
- [ ] 已认定泄漏但修复状态缺失 / 无法识别的记录在 `undetermined` 中
- [ ] 「五、未判定清单」逐条注明缺哪个字段与出处行号
- [ ] 存在未判定项时，报告开头的提示在，未删除或弱化
- [ ] 说明段未把未判定项写成「未测到即合格」「浓度为 0」

## 两类来源不混算
- [ ] 「一、总体概览」中仪器检测与现场可见泄漏的记录数、认定泄漏数分行列出
- [ ] 可见泄漏项的 `value` 为 `null`、`threshold` 为 `null`，**未被折算为浓度**
- [ ] 渗漏项归 `noLeak` 并注明为观察项，未被当作认定泄漏
- [ ] 说明段中可见泄漏的表述未带浓度数字，未与仪器检测值合并陈述

## 编号重复
- [ ] 重复编号的记录**两条均在** `items` 中，未被合并或去重
- [ ] warning 注明两处行号
- [ ] 「七、编号重复与数据提示」一节保留全部重复项，已提示用户核实是否为同一密封点

## 修复时限与超期
- [ ] 超期天数、首次/最终修复期限来自 `leaks.json`，未手工推算
- [ ] 「三、超期未修清单」每条都有超期类型（首次 / 最终）与超期天数
- [ ] 检测时间缺失的泄漏点未被判为超期，也未被判为未超期，已 warning
- [ ] 采用的阈值与时限口径已写明（默认参考口径 / 用户指定口径 + 覆盖项）

## 修复闭环
- [ ] 状态填「已修复」但无最终修复日期的项**未**计入 `repaired`，仍在「四、未修复」中
- [ ] 修复率数值与 `metrics.repairRate` 一致；分母为 0 时显示「—」而非 0%
- [ ] 平均修复时长无可计算项时显示「—」而非 0
- [ ] 超出时限后才修复的项已标注「超出最终修复时限 N 天」

## 台账

- [ ] 台账中「认定结果」「认定依据」列与报告口径一致

## 数字一致性
- [ ] 报告中每个数字都能在 `leaks.json` 的 `counts` / `metrics` 中找到对应，未自行统计

# 通用口径：设备类型未覆盖时的保守表述规范

> 当 `--equip-type` 未填、或填写的类型不在泵类/机组类/静设备类/电仪类/安全阀五张口径表内时，脚本**只给通用排查框架**，并在 warnings 与报告第二节打出提示。

## 一、为什么不套用其他类型的原因表

炼化厂设备种类多，工况差异大。把离心泵的「不对中、汽蚀」硬套到一台不认识的设备上，表面上给了具体答案，实际是**凭通用知识编造**：

- 设备员可能照着去核实一圈，浪费工时且什么也查不出；
- 报告一旦进了台账，错误的原因方向会被后续检修沿用；
- 真实原因反而不在候选里，越排查越偏。

**因此：类型不覆盖时宁可只给框架，也不编具体原因。** 交付时必须明确告诉用户「该设备类型不在知识库内，以下只是通用排查思路」。

## 二、通用排查框架（规则 G1~G4）

| 规则号 | 框架项 | 机理 | 支持依据 |
|---|---|---|---|
| G1 | 通用框架：运行工况变化 | 负荷、介质、上下游操作调整引起的表观异常 | 负荷或工况近期有调整 |
| G2 | 通用框架：检修或变更引入的问题 | 近期检修、复位或改造后未恢复到位 | 近期做过检修或复位；现象为突发 |
| G3 | 通用框架：部件自然劣化 | 磨损、老化、腐蚀等随运行时长累积的劣化 | 现象为渐变 |
| G4 | 通用框架：检测或显示侧的问题 | 测点、仪表或记录本身失真，设备实际未必异常 | 现场便携仪器复测结果与在线示值不一致 |

建议核实项：

- **通用框架：运行工况变化**（G1）：核对异常出现前后的负荷与工艺参数变化；与工艺员确认是否有操作调整；对比同工况的历史数据
- **通用框架：检修或变更引入的问题**（G2）：查近期检修、变更与复位记录；核对复位后的验收数据；确认现场是否有遗留工具、盲板或临时设施
- **通用框架：部件自然劣化**（G3）：查该设备累计运行时长与上次检修时间；查历史同类故障记录；核对定期检测数据的趋势
- **通用框架：检测或显示侧的问题**（G4）：用便携仪器在现场复测一次；与同一部位的其他测点比对；确认测点安装位置与上次是否一致

## 三、什么时候会落到通用框架

| 情形 | 脚本行为 |
|---|---|
| `--equip-type` 未提供 | warning + 通用框架，`covered=false` |
| 类型填了但不在五张表内（如「皮带机」「起重机」） | warning 指明该类型不覆盖 + 通用框架，`covered=false` |
| 类型覆盖，但所述现象在该类型表里无对应条目（如泵类的「仪表指示异常」） | warning 指明现象无对应条目 + 通用框架，`covered=true` 但 `usedGenericFrame=true` |
| 现象描述无法归入任何已知现象类型 | warning 请用户补充更具体描述，落到通用框架 |

## 四、保守表述模板

> 该设备类型（XXX）不在本技能的故障口径库内，因此**不给出针对该类型的具体原因判断**，以下只是通用排查框架：先看工况有没有变、再看近期检修有没有留问题、再看是不是自然劣化、同时确认测量本身是否可靠。
>
> 要拿到更有针对性的初判，建议补充：该设备的类型与结构简介、近期运行参数、历史故障记录；或直接联系对应专业的设备工程师。

## 五、绝不能做的事

- 不得因为「都是转动设备」就把泵的原因表套到未覆盖的机型上。
- 不得把通用框架项写成具体原因（如把「部件自然劣化」写成「轴承已到寿命」）。
- 不得省略「该类型不覆盖」的提示，让用户误以为这是针对性判断。
- 通用框架同样适用「需核实」「不给停机意见」「保留声明行」三条硬约束。
- 提示一律用「【注意】」，不用 emoji。

# 初判信息清单与追问话术

## 必需信息

| 字段 | 参数 | 为什么必需 | 缺失时的追问 |
|---|---|---|---|
| 设备位号 | `--tag` | 异常必须挂到具体设备（SAP 功能位置，不是 8 位设备流水号） | 「是哪台设备？位号（功能位置）报一下」 |
| 现象描述 | `--symptom` | 用于识别现象类型并选口径表 | 「具体什么表现？振动、异响、温度高、漏还是打不上量？」 |
| 设备类型 | `--equip-type` | 决定读哪张故障口径表；**不填只给通用框架**；末尾词优先（「压缩机电机」按电机） | 「这台是离心泵、往复压缩机、换热器、电机还是安全阀？」 |
| 发现时间 | `--time` | 与参数、检修记录做时间对齐 | 「什么时候发现的？上一班有没有记录？」 |

## 影响初判质量的条件信息

| 字段 | 参数 | 什么情况下要问 | 追问 |
|---|---|---|---|
| **是否突发** | `--sudden` | **任何情况，缺失则关注度等级未判定** | 「是突然出现的，还是这几天慢慢变差的？」 |
| **是否影响运行** | `--affects-run` | **任何情况，缺失则关注度等级未判定** | 「现在影响装置运行吗？有没有降量？」 |
| 是否特护设备 | `--special` | 大机组、关键机组必问；是则关注度按最高档 | 「这台是不是特护设备（特护台账里的）？」 |
| 偏差阈值 | `--limits` / `--dev-pct` | 参数表有基准值时必问，否则参数不判升高/偏低 | 「有没有这几个参数的报警限值或允许偏差？DCS 报警组态、运行规程里的都行」 |
| 近期是否检修 | `--recent-repair` | 振动、异响、泄漏类必问 | 「最近有没有检修过、复过位、动过管线？」 |
| 负荷/工况变化 | `--load` | 性能下降、温度、电流类必问 | 「负荷这两天有没有调整？提量还是降量？」 |
| 运行参数 | `--params` | 有点检或 DCS 记录时 | 「有没有这台的参数记录？DCS 趋势导出、点检仪导出都行，轴承温度、电流、流量、压差」 |
| 历史故障记录 | `--history` | 想看是不是老毛病复发时 | 「这台以前出过类似问题吗？SAP 里按功能位置导一下维修通知单」 |

## 追问原则

1. **一次性列出所有缺项**，不要挤牙膏式逐个追问。
2. **不得用假设值填补后直接给结论**。特别是「是否突发」与「是否影响运行」，不能因为描述里写了「有点」就当成不影响。
3. **缺数据不等于排除**。用户说「没有频谱数据」时，依赖频谱区分的原因（不对中、动平衡不良）判未判定并保留在候选里，**不得因此把它们从可能原因中删掉**。
4. 用户明确说「不知道」时，按未判定处理并说明补齐后可评估，**不要替用户猜**。

## 口语化表述与结构化对应

| 用户可能这样说 | 结构化 |
|---|---|
| 「这泵抖得厉害」 | 现象=振动偏大 |
| 「像在磨砂子 / 像打石头」 | 现象=异响，且疑似汽蚀特征噪声 |
| 「轴承烫手」 | 现象=温度异常，且轴承温度上升 |
| 「打不上量了 / 憋压」 | 现象=性能下降 |
| 「刚检修完就这样」 | 近期是否检修=是 |
| 「这几天慢慢变差的」 | 是否突发=否 |
| 「一下子就振起来了」 | 是否突发=是 |
| 「已经降量了」 | 是否影响运行=是 |

## 不能代替用户判断的事

- **不问「要不要停机」，也不答**。用户问「该不该停」时，回答「本初判不给停机意见，该决策由设备工程师会同调度按厂内规定作出」，然后给核实项与上报建议。用户问「要不要报工程师/报设备主任」时，按关注度（红/橙/黄）给上报建议。
- 不替用户定偏差阈值。用户没给限值又问「温度 78 算不算高」时，回答「没有厂内限值或允许偏差，脚本不判升高/偏低」，请其提供 DCS 报警限值或运行规程指标。
- 不代为创建工单。确认缺陷后只提示「按厂内流程在 SAP 创建维修通知单」，工单、工时、备件由计划员/维修单位负责。
- 用户递来频谱图、油液报告、探伤报告时，**不判读其专业结论**，只把「请诊断人员出具结论」列为核实项；用户自己已给出的结论性描述（如「频谱以 2 倍频为主」）可以作为依据采信，但须注明来源是用户提供。

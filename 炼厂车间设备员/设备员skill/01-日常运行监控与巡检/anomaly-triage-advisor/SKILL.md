# 设备异常初判与处置建议（anomaly-triage-advisor）

面向中石化体系炼化厂车间（运行部）设备员，在发现设备异常时快速形成初步判断与下一步动作建议，减少对专业工程师的无效打扰。**本技能只做初判辅助，不替代专业诊断、维修决策与停机审批；结论须由设备工程师或车间设备主任复核。**

## 适用条件
- 用户描述具体设备异常现象（异响、振动大、温升、泄漏、电流波动、压力异常等），并希望得到初步判断与下一步动作。
- 可附：该设备近期运行参数（DCS 趋势导出、点检仪导出、手工点检表）、厂内限值表（上限/下限或偏差阈值）、历史故障记录（SAP PM 维修通知单导出或车间台账）。附件越全，初判可信度越高。
- 车间设备员可做的部分：现象归纳、参数与历史比对、核实项安排、按厂内流程上报、确认缺陷后在 SAP 创建**维修通知单**。
- 由他人归口的部分（技能只提示不代做）：停机/降负荷决定（设备工程师会同生产调度）、精密诊断结论（状态监测/诊断人员）、安全阀校验与整定（校验机构，周期以厂内规定为准）、事故定性与责任认定（安全环保部门）、工单创建与工时定额（计划员/维修单位）。
- 不适用：要求给出确定性故障结论；要求决定是否停机；安全事故的原因定性与责任认定；精密诊断（频谱、油液、无损检测）的结论判读。

## 前提条件
- 输入：用户的现象描述（必需）。可选附件：`.xlsx`/`.csv`（参数记录、限值表、历史记录）、`.docx`/`.md`（设备档案）。PDF 不读：先用平台 pdf 技能转为 txt/docx 再传入，扫描件需 OCR。
- 必填信息：设备位号（功能位置）或名称、设备类型（离心泵/往复压缩机/换热器/电机/安全阀等）、现象描述、发现时间。
- 环境：可执行 Node.js ≥ 18（有附件时用于解析与比对）。**若环境无法执行 node，明确告知用户并终止，不得手工估算或凭印象初判。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| DCS位号数据 | `get_tag_history` | `tag`：位号；`for_skill=anomaly-triage-advisor` | `--params`（目录 A） |
| DCS位号数据 | `get_tag_limits` | `tag`：位号 | `--limits`（目录 B） |
| 设备资产管理 | `get_failure_history` | `tag`：位号；`for_skill=anomaly-triage-advisor` | `--history`（目录 C） |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；表中目录字母相同的放同一个目录，不同字母分开放，把目录作为“交给脚本”一列的参数值。
2. `get_tag_history`：输出快照形态的「运行参数」表：每个参数一行，含最新值、基准值和上下限。
3. `get_failure_history`：输出「故障记录」表（故障现象、故障日期、故障原因）。
4. 位号没有 DCS 测点或 `get_tag_history` 取不到数时，改用点检巡检App 的 `get_inspection_records`（`tag`：位号；`for_skill=anomaly-triage-advisor`，返回当天巡检记录）放进目录 A 作 `--params`，代替 DCS 快照；巡检记录没有基准值，能判趋势的参数会变少。两者不要放在同一目录。

## 操作步骤
1. **补齐关键信息** —— 按 `references/intake-questions.md` 逐项核对：设备类型、现象、发生时间、是否突发、是否影响运行、是否特护设备、伴随现象、近期检修史。缺项时一次性向用户列出需要补充的问题，**不得用假设值填补后直接给结论**。
2. **解析附件（如有）** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/triage.js" --symptom "<现象描述>" --equip-type "<设备类型>" --tag "<位号>" --out "<工作目录>/异常初判"
   ```
   可选：`--params "<参数xlsx>"`、`--limits "<限值表xlsx>"`、`--dev-pct "温度=10,压力=8,振动=20,电流=10"`、`--history "<历史故障记录>"`、`--sudden 是|否`、`--affects-run 是|否`、`--special 是|否`（特护设备）、`--time <ISO 8601 带时区>`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户。脚本用法详见 `scripts/README.md`。
   - **偏差阈值不写死**：参数"升高/偏低"只按限值表上下限、参数表行内高报/低报、或 `--dev-pct` 按参数类型给的百分比判定；三者都没有时该参数不判趋势，依赖它的原因进未判定（不按固定 15% 默认）。
   - 判定条件依赖的字段为空（如无参数数据、无历史记录）：对应原因项标记为 `undetermined`（未判定）并单列一节，**不得因缺数据而静默排除某个可能原因**。
3. **读取 triage.json 并匹配知识口径** —— 从 `<输出目录>/triage.json` 获取 `candidates`（候选原因及匹配依据）、`checkItems`（建议核实项）、`undetermined`（未判定项）、`riskLevel`（关注度 红/橙/黄/未判定）、`escalation`（上报建议）。再按设备类型读 `references/` 下对应口径文件（`fault-patterns-pump.md`、`fault-patterns-compressor.md`、`fault-patterns-static.md`、`fault-patterns-electrical.md`、`fault-patterns-safety-valve.md`，无对应类型读 `fault-patterns-generic.md`）。
4. **撰写初判报告** —— 按"现象复述 → 可能原因（按可能性排序，每项注明支持依据与反证）→ 建议立即核实项 → 建议动作 → 未判定项与所需补充数据 → 上报建议"结构撰写。**每条原因必须注明依据来源（参数/历史/现象/口径文件），无依据的推测须标注"推测，待核实"。** 关注度用 红/橙/黄 三档，不写 A/B/C（与设备重要度分级撞名）。
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `triage.md` 与 `triage.json`。**必须保留报告中的声明行："本结论为初判辅助，由脚本汇总、模型成文，不替代专业诊断与停机决策，须由设备工程师或车间设备主任复核；厂内制度与系统数据为准"，不得删除或改写。**

## 预期结果
- `triage.md`：异常初判报告，含现象复述、可能原因排序、建议核实项、建议动作、未判定项、上报建议六节（warnings 非空时另附"数据提示"），开头与末尾各含固定声明行。
- `triage.json`：候选原因与核实项的结构化结果（含 `params` 每项的阈值来源 `thresholdSource`、`limits`、`history` 的通知单号与损坏代码）；`summary.json`：脚本末行摘要。
- 交付时向用户说明：初判依据了哪些数据、哪些参数因缺阈值未判趋势、哪些原因因缺数据未能判定、建议补充什么数据后重新初判；确认为缺陷的，提示按厂内流程在 SAP 创建维修通知单。

## 不适用范围
- 不给出确定性故障结论，不决定是否停机、降负荷或抢修。
- 不判读频谱图、油液分析报告、无损检测报告的专业结论；不判安全阀整定与校验结论。
- 不做安全事故定性、责任认定与经济损失估算。
- 不替代厂内异常上报流程，不代为下达任何指令；不创建工单。

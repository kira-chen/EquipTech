# 特种设备定检到期管理（special-equipment-inspection-due）

面向中石化体系炼化厂车间设备员，按台账计算本车间特种设备的定期检验到期日与使用单位年度检查到期日，生成到期提醒与报检准备清单。**到期计算由脚本完成，模型不得延长周期或判定"可以缓检"；超期使用属违法，须醒目提示。** 压力容器 / 压力管道的检验周期由**安全状况等级**决定，不由 GC 级别决定；安全阀校验周期以厂内规定与校验报告为准，脚本不代入。

## 适用条件
- 用户说"特种设备定检到期了吗 / 压力容器该报检了 / 锅炉外检到期没 / 年度检查做了没 / 报检要准备什么 / 定检计划"，并提供特种设备台账。
- 覆盖设备类别（按设备品种中文写法识别）：压力容器、压力管道、锅炉、起重机械、场（厂）内专用机动车辆；台账里的安全阀只按台账载明的下次检验日期提示。
- 车间设备员可做：台账到期提醒与定检计划汇总、使用单位年度检查的组织与记录、报检资料准备、遗留整改项跟踪、检验报告归档核对。
- 由其他岗位归口（技能只提示、不判定、不办理）：报检手续、检验机构选择与受理（特种设备管理员）；检验结论、安全状况等级、监控使用期限（检验机构）；安全阀校验与送校（valve-instrument-calibration-ledger）。
- 不适用：一般设备的周期性维护；检验结论的判定与解释；延期检验的申请与论证。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含「特种设备台账」，列名支持特种设备平台 / SAP PM / EM 导出写法（功能位置、设备、设备描述、设备品种、设备代码、使用登记证编号、检验机构、检验类型、安全状况等级、年度检查日期、工厂区段等），字段见 `references/input-spec.md`。锅炉的检验类型（外部检验 / 内部检验 / 水压试验）请用独立「检验类型」列。
- 必填信息：车间名称、基准日期（YYYY-MM-DD）。可选：提前提醒天数（默认 90 天）、设备类别过滤、检验报告目录、整改项清单。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工推算法定到期日。**

## 操作步骤
1. **确认车间与基准日期** —— 从用户消息或文件名中提取；检查台账是否含设备类别、上次检验日期与安全状况等级，**缺失时必须提示补齐，不得按同类设备默认周期推算**；台账无「上次年度检查日期」列时说明年度检查一节不出数。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/inspection.js" --input "<xlsx路径>" --workshop "<车间名>" --date <YYYY-MM-DD> --out "<工作目录>/定检管理"
   ```
   可选：`--lead-days <提前提醒天数>`、`--category <压力容器|压力管道|锅炉|安全阀|起重机械|场内机动车辆>`、`--reports "<检验报告目录>"`、`--issues "<整改项清单xlsx>"`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺列/设备类别无法识别/「储罐」待核实/安全状况等级缺失/锅炉未填检验类型/台账下次检验日期与规则计算不一致/年度检查超期/含安全阀的互指提示等）。脚本用法详见 `scripts/README.md`。
   - 台账中"下次检验日期"与按规则计算结果不一致：两者并列显示并 warning 提示核实，**以台账中检验报告载明的日期为准，脚本计算值仅作校验参考**。
   - 安全状况等级缺失、锅炉检验类型缺失、「储罐」未写明是否压力容器：归入 `undetermined` 单列一节，**绝不按最长周期处理，也不替用户认定储罐是压力容器**。
3. **读取 inspection.json** —— 从 `<输出目录>/inspection.json` 获取：`overdue`（已超期，含超期天数）、`dueSoon`（临期）、`normal`、`undetermined`、`dateConflict`（台账与计算不一致）、`annualCheck`（年度检查：overdue / dueSoon / normal / undetermined，台账无该列时为 null）、`monitored` / `stopped`、`prepMaterials`（按类别的报检应备资料清单）、`openIssues`（上次检验遗留整改项）、`reports`（报告归档核对）、`counts`。
4. **撰写"定检管理说明"** —— 读 `references/inspection-rules.md` 的表述口径，撰写 200~400 字，按"到期概览 → 超期设备与法律风险 → 临期设备与报检安排 → 年度检查与遗留整改项 → 数据待核实项"结构，替换 `inspection.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**数量与天数一律引用 inspection.json。存在超期设备时，脚本已在报告开头写入"【注意】存在超期未检特种设备，超期使用违反《特种设备安全法》，应立即停用并报检"，该提示不得删除或弱化。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `inspection.md`、`inspection.json` 与 `报检准备清单.md`。

## 预期结果
- `inspection.md`：十节报告——到期概览、超期清单（醒目）、临期清单、检验日期不一致项、待核实项、遗留整改项、年度检查到期、监控使用与应停用设备、检验报告归档核对、定检管理说明；末尾为口径声明行。
- `报检准备清单.md`：按设备类别列出的报检应备资料（含作业许可与特种作业证复审提示）；`inspection.json`；`summary.json`。
- 交付时向用户说明：超期数量、临期数量、待核实数量（含储罐待核实）、年度检查超期数量、遗留整改项数量、脚本 warnings（如有）。

## 不适用范围
- 不判定检验结论与安全状况等级（以检验机构报告为准）。
- 不办理报检手续，不替代特种设备管理员的法定职责。
- 不做延期检验的申请与论证，不认可任何形式的超期使用。
- 不出具设备可继续使用的判定意见；不替用户认定「储罐」是否为压力容器。
- 不管理安全阀校验台账与送校批次（用 valve-instrument-calibration-ledger）。

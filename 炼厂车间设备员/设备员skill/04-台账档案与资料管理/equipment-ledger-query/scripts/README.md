# scripts 使用说明

## query.js —— 主脚本

```bash
node "<技能目录>/scripts/query.js" --input "<台账xlsx>" --query '<查询表达式>' --out "<输出目录>"
node "<技能目录>/scripts/query.js" --input "<台账xlsx>" --describe --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 设备台账 xlsx 或 CSV 目录（SAP PM 技术对象清单 / EM 导出 / 车间台账） |
| `--query` | 是（`--describe` 时不需要） | 查询表达式（JSON）或直接写位号 / 设备编号 |
| `--describe` | 否 | 只输出列名、已填/空行数与样例值，不做查询；优先于 `--query` |
| `--out` | 否 | 输出目录，默认 `<os.tmpdir()>/elq-out`，**建议始终传** |
| `--history` | 否 | 检修历史 xlsx（SAP 工单导出亦可），按位号关联 |
| `--fields` | 否 | 指定返回列，逗号分隔 |
| `--limit` | 否 | 最大返回条数，默认 200 |
| `--format` | 否 | `table`（默认多条）或 `detail`（逐台展开） |
| `--spare` | 已停用 | 传入即报错并指向 spare-parts-inventory-query |

### 查询表达式

```jsonc
// 单台详情（简写：--query "P-101A" 或 --query "10012345"；位号与设备编号两列都查）
{"type":"detail","tag":"P-101A"}

// 条件筛选
{"type":"filter",
 "where":[["专业","eq","动设备"],["投用日期","lt","2015-01-01"]],
 "orderBy":{"field":"投用日期","dir":"asc"}}

// 分组统计（按 ABC 标识）
{"type":"stats","groupBy":"重要度","where":[["装置","eq","CDU"]]}
```

操作符：`eq` `ne` `contains` `startsWith` `in` `gt` `gte` `lt` `lte` `empty` `notEmpty`

字段名用技能内列名（位号、设备编号、设备名称、规格型号、制造厂、建造年份、投用日期、专业、区域、介质、重要度、状态、装置、车间、成本中心、工作中心、出厂编号、设备代码）或台账原有的其它列名（如业务系统导出的「设备类型」「特护标记」「功率(kW)」「设计压力(MPa)」，以表头原文去空白为列名，原样返回；「设备类型」不归入专业，没有专业列时也按「设备类型」原名查询）；原列名末尾带单位括号时，不带单位的写法（如「设计压力」）在唯一对应时解析到该列，生效条件里写实际列名；不做包含或近义匹配。不确定时先 `--describe`。

### 产出

| 文件 | 内容 |
|---|---|
| `result.json` | 命中记录（含 `_matchedBy` 命中依据、`_投用年限`、`_投用年限说明`；带 `--history` 时 `_检修历史`，每条含 `date` 完工日期、`order`、`orderType`、`content`、`vendor`、`occurred` 发生时间、`symptom` 故障现象）、统计、生效条件、台账实际列、`meta.hasTagCol/hasEquipNoCol`、缺失字段；`--describe` 时为 `describe` 列表 |
| `result.md` | 查询结果报告（「一、…」单节 + 可选「二、台账中不存在的字段」+ 互指提示 + 声明行 + 附：数据提示） |
| `result.xlsx` | 多条结果时导出 |
| `summary.json` | 末行摘要落盘 |

### 口径
- 「位号」= SAP 功能位置 / EM 设备位号；「设备编号」= SAP 8 位流水号 / EM 编码，分列。只有设备编号列的旧台账按设备编号定位并 warning。
- 检修历史按完工日期倒序；无完工日期（未完工）的记录按发生时间参与排序，`date` 保持 null 不用发生时间冒充，报告里写「无完工日期，某日发生」并带出故障现象。
- 投用年限按「投用日期/开始日期」推算（365.25 天/年，注明基准日期）；只有「建造年份」的不推算。
- 声明行固定为："数据来自所提供台账文件，权威数据以 EM 设备管理信息系统 / ERP（SAP PM）技术对象主数据与设备档案为准。"

### 退出码
- `0`：成功
- `1`：失败（含查询字段不在台账中、非法表达式、输入不存在、既无位号也无设备编号列、传入 `--spare`）

**注意**：查询条件涉及台账中没有的字段时脚本会报错终止，而不是跳过条件返回全部数据，避免用户误以为结果是按条件筛出来的。

## make-sample.js

```bash
node scripts/make-sample.js --out examples [--seed <n>]
```

生成 4 份样例：主台账（12 台，带 SAP 8 位设备编号；动 5 静 4 电 2 仪 1，3 台早于 2015 年，1 台规格型号为空）、SAP PM 技术对象清单导出（6 台，1 台只有建造年份）、检修历史（SAP 工单导出列名）、EM 别名列头变体（标题行 + 合计行）。

## selftest.js

```bash
node scripts/selftest.js
```

151 条断言，覆盖三种查询类型、10 个操作符、空值显示、字段不存在报错、空结果、检修历史关联（含 SAP 工单列名）、`--spare` 停用、SAP PM / EM 别名列头（功能位置/设备/设备描述/ABC标识/制造商/型号编号/建造年份/开始日期/工厂区段/维护工厂）、位号与设备编号分别命中、只有建造年份不推算年限、台账原有其它列（设备类型/功率/带单位的设计压力）可查可筛可统计、无设备编号列时「设备类型 / 设备类别 / 设备等级」不被前缀匹配进设备编号、无专业列时「设备类型」不改名为专业（SAP 表头「设备」仍归设备编号）、「特护标记」不并入重要度、`--fields` 缺失字段写入 result.json、未完工检修记录排序与故障现象、`--describe`、合计行、参数校验、默认输出目录在 tmpdir、产出完整性。

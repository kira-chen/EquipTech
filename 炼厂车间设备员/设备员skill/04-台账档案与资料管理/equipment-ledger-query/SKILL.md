# 设备台账查询（equipment-ledger-query）

面向中石化体系炼化厂车间设备员，用自然语言查询设备台账（SAP PM 技术对象清单、EM 设备管理信息系统导出表或车间自维护台账），替代在 Excel 里反复筛选。**所有返回数据必须来自台账文件，模型不得凭常识补充设备参数、厂家或型号。**

## 适用条件
- 用户说"查一下这台设备 / P-101 什么型号 / 这个功能位置是哪台 / 设备编号 10012345 是哪台 / 哪些设备是某厂家的 / 台账里有多少台 / 投用多久了 / 台账有哪些列"，并提供设备台账文件。
- 支持四类操作：单台设备详情（按位号或设备编号）、条件筛选（按专业/装置/区域/厂家/投用年限/重要度 ABC）、统计汇总（计数、分组、排序）、列结构查看（`--describe`，只列列名与样例值，便于先确认台账有什么再提问）。
- 车间设备员可做：查、筛、统计、整理成表给车间设备主任或公司设备管理部门。
- 不适用：台账数据的新增与修改（由 EM / SAP 主数据维护流程归口）；备件库存与代用（用 spare-parts-inventory-query）；图纸、说明书等技术文件检索（用 technical-document-finder）；作为设备参数的权威来源（以 EM 设备管理信息系统 / ERP（SAP PM）技术对象主数据与设备档案为准）。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含设备台账工作表（sheet 名含"设备台账 / 台账 / 设备清单 / 技术对象 / 功能位置"均可）。列名支持 SAP PM / EM 导出常见写法（功能位置、设备、设备描述、对象类型、ABC标识、制造商、型号编号、建造年份、开始日期、工厂区段、维护工厂、成本中心等），见 `references/input-spec.md`。可选：检修历史表（SAP 工单导出亦可，用于关联查询）。
- **位号与设备编号分列**：「位号」= SAP 功能位置 / EM 设备位号；「设备编号」= SAP 8 位设备流水号 / EM 编码。查询时两者都可命中，结果里分别展示并写明按哪一列命中。
- 必填信息：查询意图（用户的自然语言问题）。可选：限定车间、装置、专业范围。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得凭印象回答设备参数。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 设备资产管理 | `get_equipment_ledger` | 用户限定车间时带 `workshop`：车间名；跨车间查询或只查一台时不带 | `--input`（目录 A） |
| 设备资产管理 | `get_failure_history` | `tag`：位号；`for_skill=equipment-ledger-query` | `--history`（目录 B） |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；表中目录字母相同的放同一个目录，不同字母分开放，把目录作为“交给脚本”一列的参数值。
2. `get_failure_history`：输出表名为「检修历史」。
3. 脚本没有车间参数，只按台账内容查询。不带 `workshop` 取到的是全厂台账（常减压车间、加氢车间等），用户问某车间的台数、清单、统计时，要么取数带 `workshop`，要么在查询条件 `where` 中加 `["车间","eq","<车间>"]`，不得把全厂结果当作本车间结果。

## 操作步骤
1. **解析查询意图** —— 从用户问题中提取：查询类型（详情/筛选/统计/看列）、目标字段、筛选条件、排序与分组要求。**意图歧义时（如"老设备"指投用年限还是型号老旧；"关键设备"指 ABC 标识 A 类还是特护设备）向用户确认一次，不得自行设定口径。** 不确定台账里有哪些列时，先跑 `--describe`。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/query.js" --input "<台账xlsx>" --query "<查询条件JSON或位号/设备编号>" --out "<工作目录>/台账查询"
   node "<技能目录绝对路径>/scripts/query.js" --input "<台账xlsx>" --describe --out "<工作目录>/台账查询"
   ```
   可选：`--history "<检修历史xlsx>"`、`--fields "<返回字段列表>"`、`--limit <返回条数>`、`--format <table|detail>`。`--spare` 已停用（传入即报错并指向 spare-parts-inventory-query）。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺列/位号不存在/筛选条件字段不在台账/只有建造年份未推算年限/结果为空等）。脚本用法详见 `scripts/README.md`。
   - 台账原有的其它列（如设备类型、特护标记、功率(kW)、设计压力(MPa)）以表头原文为列名，可直接查、筛、统计；带单位的列也可写不带单位的名字（唯一对应时）。「设备类型」不归入「专业」，台账没有专业列时按「设备类型」原名查。
   - 查询字段不在台账中：脚本报错并列出台账实际字段，**不得用相近字段代替，也不得凭常识补充数值**。
   - 结果为空：明确回答"台账中未查到符合条件的设备"，**不得放宽条件后返回近似结果而不说明**。
3. **读取 result.json** —— 从 `<输出目录>/result.json` 获取：`records`（命中记录，含 `_matchedBy` 命中依据、`_投用年限`）、`stats`（统计结果）、`fieldsNotFound`（查询了但台账没有的字段）、`counts`、`appliedFilters`（实际生效的筛选条件）、`meta.hasTagCol / hasEquipNoCol`（台账是否有位号列、设备编号列）；`--describe` 时为 `describe`（列名、已填/空行数、样例值）。
4. **组织回答** —— 单台详情用字段列表呈现，位号与设备编号分别写明；多条结果用表格；统计结果给出数字与分组明细。**涉及推算（投用年限）时注明计算方式与基准日期；SAP 只有"建造年份"无"开始日期"的设备不推算年限，照实说明。若某字段台账为空，显示"—（台账未填）"，不得留白让用户误以为是零或无。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后回答用户。结果较多时同时输出 `result.xlsx` 便于用户继续处理。**必须保留声明行："数据来自所提供台账文件，权威数据以 EM 设备管理信息系统 / ERP（SAP PM）技术对象主数据与设备档案为准。"**

## 预期结果
- `result.md`：一节「一、设备详情 / 查询结果 / 统计结果 / 列名与样例值」（四选一）；查询了台账没有的字段时追加「二、台账中不存在的字段」；末尾为备件/资料互指提示、声明行与「附：数据提示」（warnings 非空时）。
- 直接回答用户问题（对话形式），必要时附 `result.xlsx` 与 `result.json`。
- 回答中说明：命中条数、按位号还是设备编号命中、生效的筛选条件、台账中缺失的字段、脚本 warnings（如有）。

## 不适用范围
- 不修改、新增、删除台账数据（EM / SAP 主数据维护由公司设备管理部门与主数据流程归口）。
- 不补充台账中没有的设备参数，不做参数推算与型号推荐。
- 不做备件库存、在途与代用查询（用 spare-parts-inventory-query）。
- 不检索图纸、说明书、规程等技术文件（用 technical-document-finder）。
- 不作为设备参数的权威依据用于设计、选型或安全计算。

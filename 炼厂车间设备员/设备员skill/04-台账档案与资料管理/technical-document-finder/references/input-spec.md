# 输入规格：技术资料检索

## 一、资料路径（必需，`--docs`）

可以是一个目录（递归扫描，最多 6 层）或单个文件。以隐藏文件（`.` 开头）与 Word 临时文件（`~$` 开头）开头的文件一律跳过。文件数超过 `--max-files`（默认 300）直接报错，不静默截断。

### 支持的格式

| 格式 | 内容可检索 | 说明 |
|---|---|---|
| `.docx` | 是 | 用 `lib/docx-lite` 抽文字层，段落与表格都进检索范围；表格行以 `|` 分隔 |
| `.md` | 是 | 按行切段 |
| `.txt` | 是 | 按行切段 |
| `原名.pdf.txt` / `.pdf.docx` / `.pdf.md` | 是（标注转换文本） | PDF 经平台 pdf 技能转换的产物，识别为该 PDF 的转换文本：沿用目录清单中 PDF 的版本与存放位置，引用处标注"PDF 转换文本，须核对原件"，顶部【注意】提示份数 |
| `.xlsx` / `.csv` | 作为资料目录清单读取 | **不作为资料原文**，只提供文件定位、版本、存放位置线索 |
| `.pdf` | **否** | **脚本不读 PDF**：请先用平台 pdf 技能转为 txt/docx 再传入，扫描件需先 OCR；本次只做文件定位 |
| `.doc` `.xls` `.ppt` | **否** | 旧版 Office 二进制格式，请在 Office 中另存为 `.docx` / `.xlsx` 后传入；只做文件定位 |
| `.png` `.jpg` `.jpeg` `.gif` `.bmp` `.tif` `.tiff` | **否** | 图片格式图纸 / 扫描件，无文字层；需 OCR 后以 txt 传入 |
| `.dwg` `.dxf` | **否** | CAD 原图，无文字层可供本脚本检索 |
| 其他 | 跳过并 warning | 不静默跳过 |

**PDF 前置转换是统一口径**（SKILL.md、scripts/README.md 与本文件一致）：即使是电子版可复制文字的 PDF，本脚本也不读；转换后的文本由平台 pdf 技能（模型读取）产生，**未经脚本验证，引用时须人工核对原件**。未转换的 PDF 进 `unreadable` 并出 warning，只返回文件定位；图纸上的尺寸、材质、编号等一律不得据此作答。

### 段落编号

文字层按行切分，空行跳过，序号从 1 开始连续编号。引用出处写成「文件名 + 第 N 段」。`.docx` 的页眉页脚在正文之后，表格以 `### 表格 N` 起头，段号照常连续。

## 二、资料目录清单（可选，混在 `--docs` 路径里的 xlsx/csv）

xlsx 的 sheet 名匹配「资料目录」「资料清单」「目录」「清单」「档案」；csv 只有一张表，整张表即目录，文件名不限（如「资料目录补充.csv」「设备资料登记.csv」均可），编码 UTF-8（可带 BOM）或 GBK。

| 列名 | 必需 | 说明 |
|---|---|---|
| 文件名 | 是 | 与实体文件按文件名匹配（含关系即可）；PDF 的转换文本「原名.pdf.txt」也能匹配到 PDF 的登记行 |
| 资料类型 | 否 | 图纸 / 说明书 / 规程 / 技术协议 / 检验报告；留空时按文件名推断，推不出写 null |
| 关联位号 | 否 | 与 `--tag` 归一后相等即判定关联（`--tag` 为设备编号且台账命中时，与台账位号相等亦可）；SAP 导出写「功能位置」亦可 |
| 版本 | 否 | 如 A/0、B/1；写进引用出处 |
| 存放位置 | 否 | 档案柜、图纸柜、受控文件夹、EM 文档模块编号等 |
| 归档日期 | 否 | |

### 列名别名

别名表 = 局部别名（优先）+ 共享 `SYSTEM_ALIASES`（SAP PM / EM 列名）：

| 标准列名 | 可识别写法 |
|---|---|
| 文件名 | 文件名、资料名称、文件名称、名称、资料、图纸名称、文档名称、文件 |
| 资料类型 | 资料类型、类型、文件类型、文档类型、资料类别、类别 |
| 关联位号 | 关联位号、位号、设备位号、功能位置、TAG（「设备编号」是 SAP 流水号，不作位号） |
| 版本 | 版本、版次、版本号、修订版、Rev |
| 存放位置 | 存放位置、存放路径、位置、归档位置、档案柜、路径 |
| 归档日期 | 归档日期、归档时间、日期、发布日期、生效日期 |

表头行取前 10 行中命中必需列最多的一行，因此带标题行的导出表也能读。

**目录登记了、但路径下没有实体文件的条目** → 进 `catalogOnly` 单列，注明"仅为台账登记信息，未读到文件内容，需按存放位置调阅原件"，并出 warning。已提供转换文本的 PDF 视为已提供实体文件。

## 三、设备台账（可选，`--ledger`）

sheet 名匹配「设备台账」「台账」「设备清单」「技术对象」「功能位置」「设备」。只取四列，用于补充关联线索。

| 列名 | 必需 | 用途 | 可识别写法 |
|---|---|---|---|
| 位号 | 是 | 与 `--tag` 归一后比对 | 位号、设备位号、TAG、**功能位置**、功能位置编号、技术标识、技术对象 |
| 设备编号 | 否 | `--tag` 给的是 SAP 设备编号时也可命中，`ledgerInfo.matchedBy` 标「设备编号」；命中后改用该行位号做关联，设备编号保留为线索 | 设备编号、**设备**（SAP 8 位流水号）、设备号、设备编码、EM编码 |
| 设备名称 | 否 | 作为关联线索（文件名或内容中出现设备名称也算关联）；**台账中不唯一时不用**（见下） | 设备名称、名称、**设备描述**、技术对象描述 |
| 规格型号 | 否 | 同上，不唯一时同样不用 | 规格型号、型号、规格、**型号编号** |

台账中查不到 `--tag` 时出 warning 并继续，**不用近似位号代替**，此时仅按位号本身做关联判定。

**设备名称 / 规格型号不唯一**：台账里另有位号不同的设备，其名称（型号）与本设备相同或包含本设备的名称（型号）时，该项不作关联线索，出 warning「设备台账中设备名称「X」不唯一（…），不作关联线索」，并记入 `meta.ledgerInfo.droppedClues`（`kind` / `value` / `sharedWith`）。A/B 泵同名同型号最常见：查 P-2101B 时，文件名或内容只写「原油进料泵」而不写 P-2101B 的资料不会被关联。

## 四、会被跳过 / 单列的内容

- 全空行、首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行（warning 提示）
- 没有文字内容的文本文件 → `unreadable`，原因写"文件内无文字内容"
- 解析失败的 `.docx`（损坏、不是真 zip）→ `unreadable`，原因写"解析失败：<原因>"，**不中断整体检索**
- 未转换的 PDF、图片、CAD、.doc/.xls/.ppt → `unreadable`，原因写明该怎么转换
- 与设备无法关联的文件 → `unrelated` 单列，说明"文件名与内容中均未出现位号及台账线索，未强行关联"

## 五、产出

| 文件 | 内容 |
|---|---|
| `matches.json` | `documents`（相关文件，含 `convertedFrom`）/ `passages`（命中段落，含 `convertedFrom`）/ `conflicts`（取值不一致）/ `unreadable` / `unrelated` / `catalogOnly` / `counts` / `meta` |
| `matches.md` | 六至七节报告，含转换文本【注意】提示、版本声明行与分析段占位 |
| `summary.json` | 末行摘要落盘 |

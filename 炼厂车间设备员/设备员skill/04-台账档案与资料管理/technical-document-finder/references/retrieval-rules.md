# 检索口径与回答规范

## 一、关联判定口径

一份文件与设备"关联"，必须有可追溯的依据，脚本在 `relatedBy` 里写明是哪一条：

| 依据 | 判定方式 | `relatedBy` 写法 |
|---|---|---|
| 文件名含位号 | 文件名中出现位号（字符间的 `- _ · . /` 与空白忽略；位号前不能紧挨字母或数字、后面不能紧跟数字，见下） | `文件名含位号：P-1101A` |
| 文件名含设备名称/型号 | 需提供 `--ledger`，台账里的设备描述或型号编号出现在文件名中；**该名称/型号在台账中不唯一时不用**（A/B 泵同名同型号） | `文件名含设备名称（台账）：常压塔顶回流泵A` |
| 内容中出现位号 | 文字层某一段中出现位号，记下段号 | `内容中出现位号：P-1101A（第3段）` |
| 资料目录清单标注 | 清单里该文件的「关联位号 / 功能位置」等于查询位号（xlsx 或 csv 清单均可） | `资料目录清单标注关联位号：资料目录清单.xlsx 第2行` |
| 文件名/内容含设备编号 | `--tag` 给 SAP 设备编号且台账命中时，编号本身保留为线索 | `内容中出现设备编号：10002101（第2段）` |

位号比对做归一化：大小写不敏感，`P-1101A` / `p1101a` / `P_1101A` 视为同一位号。**位号要整段出现**：前面紧挨字母或数字、后面紧跟数字的不算命中——查 V-1101 不带出 PSV-1101（安全阀）、LV-1101（液位计）或 V-11011 的资料，查 T-1101 不带出 LT-1101。以字母结尾的位号同时认 A/B 简写：资料写「P-2101A/B」「P-2101A、B」时，查 P-2101A 或 P-2101B 都能关联，查 P-2101C 不关联。`--tag` 给 SAP 设备编号且提供台账时，按设备编号命中台账并带出功能位置，`ledgerInfo.matchedBy` 标「设备编号」；**此后按台账位号做关联**（文件名、内容、目录清单关联位号），设备编号同时保留为线索，报告抬头写「编号（台账位号 X）」。

台账名称、型号是辅助线索，只有在台账中唯一时才用：另有位号不同的设备与之同名（同型号），或名称包含它时，弃用该线索并出 warning，记入 `ledgerInfo.droppedClues`。否则查 P-2101B 会把只写「原油进料泵」的 P-2101A 技术协议、检修规程也带进来。

**判不出关联的文件一律进 `unrelated` 单列**，写明"文件名与内容中均未出现位号及台账线索，未强行关联"。**不按目录同级、不按文件名相似度、不按设备类型硬凑关联**——一台泵的说明书不能算作另一台泵的资料。

用 `--doc-type` 过滤时，被过滤掉的相关文件同样进 `unrelated`，并注明是被类型过滤掉的（`filteredOut`），让用户知道它存在，只是不符合本次类型要求。

### 资料类型判定

优先取资料目录清单里的「资料类型」列；没有清单时按文件名关键词推断（装配图/总图→图纸，说明书/手册→说明书，规程/操作法/作业指导书→规程，技术协议/技术条件→技术协议，检验报告/试验报告/探伤→检验报告）。**推不出来写 `null`，md 里显示「—（未判定）」，不默认归到某一类。**

## 二、PDF 前置转换与未解析文件（最重要的一条）

**脚本不读 PDF。** 统一口径（与 SKILL.md、scripts/README.md、input-spec.md 一致）：PDF 先用平台 pdf 技能转为 txt/docx 再传入，扫描件需先 OCR；转换产物按「原名.pdf.txt」命名放同一目录。

| 情形 | 脚本处理 | 回答口径 |
|---|---|---|
| 已提供转换文本 `原名.pdf.txt` | 识别为该 PDF 的转换文本，可检索；`convertedFrom` 记录来源；沿用目录清单里的版本与存放位置；顶部【注意】提示份数 | 引用时写「出处：X.pdf.txt 第 N 段（PDF 转换文本，须核对原件 X.pdf）」；**转换文本由平台 pdf 技能（模型读取）产生，未经脚本验证** |
| 未转换的 `.pdf` | 进 `unreadable`，原因写明前置转换步骤；若与设备关联同时进 `documents` 但 `contentSearchable: false`、`paragraphs: null`；**绝不产生 `passages`** | 「该 PDF 未转换，脚本未读内容，只能定位到文件；请先用平台 pdf 技能转为 txt 后重跑」 |
| `.doc` / `.xls` / `.ppt` | 进 `unreadable`，原因写"请另存为 .docx / .xlsx" | 同上，提示另存 |
| 图片 / CAD | 进 `unreadable`，无文字层 | 「图上的尺寸、材质需打开原件查看」 |

**回答时的硬约束**：可以说"该设备的装配图是 P-1101A装配图.pdf，存放在图纸柜2-4"，**绝不能说**"图纸上标注叶轮直径为 XXX""按图纸材质为 XXX"。用户问未转换 PDF 的内容时，正确回答是：

> 装配图为 PDF，**本次未读取其中内容**，只提供文件定位：文件名 P-1101A装配图.pdf，版本 A/1，存放于图纸柜2-4。如需检索内容，请先用平台 pdf 技能转为 txt（扫描件需 OCR）再传入；图上的尺寸与材质也可打开原件查看。

## 三、命中为空

两种"空"，都要如实说，且都不放宽：

| 情况 | 回答 |
|---|---|
| 设备本身没有关联资料 | 「所提供资料中未找到与 XXX 关联的文件」+「未放宽关联条件，也未用其他设备的资料代替」 |
| 有关联资料但查询内容没命中 | 「所提供资料中未找到与『XXX』相关的内容」+「未用通用知识补充」 |

**禁止**：
- 用通用知识、行业惯例、标准条文补答（"一般机械密封力矩取 40~50N·m"——资料里没写就是没写；用户要问通用做法，指引 equipment-knowledge-qa）
- 用同型号、同类型、邻位号设备的资料代答
- 把没命中说成"资料里大概是……"
- 降低检索词精度后返回近似结果而不说明

正确做法是告诉用户缺哪类资料：「说明书里没有查到汽蚀余量，该参数通常记在泵的性能曲线或数据表中，可补充提供后重查」——描述该去哪找，不替资料给数。

## 四、原文引用规范

### 出处必须带

每条引用写成：**文件名 + 第 N 段**（有版本时加版本；转换文本加"PDF 转换文本，须核对原件"）。例如：

> **出处：P-1101A常压塔顶回流泵使用说明书.docx　第11段　版本 A/0**
>
> 机械密封压盖螺栓应对角均匀紧固，安装力矩 45N·m，不得超拧。

`passages` 里 `text` 是完整段落原文，`excerpt` 是按 `--context` 截出的上下文，**引用给用户时用 `text`**，excerpt 只用于长段落的预览。

### 原文与解释必须分开

先照录原文（引用块），再另起一段解释。解释里**不得出现原文没有的数值、判定、条件**。

| 应写 | 不应写 |
|---|---|
| 原文：「安装力矩 45N·m」<br>解释：说明书对压盖螺栓给出的是 45N·m。 | 「力矩按 45N·m，一般分三次对角上紧」（"分三次对角"是别处的话，混进来就成了这份资料的内容） |
| 原文：「轴承温度不超过 75℃」<br>解释：规程给的温度上限是 75℃。 | 「轴承温度不超过 75℃，超过 80℃ 应停机」（80℃ 是补出来的） |

## 五、多处原文不一致

脚本按「同一关键词、同一单位、不同文件」识别取值冲突，写进 `conflicts`。例如说明书写 45N·m、检修规程写 50N·m。**判冲突要求两份资料各有对方没有的取值**；一份资料的取值被另一份完全包含时不算（如检修规程只写径向偏差 0.05mm，说明书写径向 0.05mm、轴向 0.08mm，两处并不矛盾）。判为冲突时，该单位下的全部取值连同出处一并列出。

**处理口径：全部列出，标明各自出处与版本，提示用户核实版本，不自行取其一。**

禁止：
- 取版本较新的那份当答案（版本新不等于受控现行，本技能不判定有效性）
- 取数值较保守的那份（"按小的来更安全"是自行判断，不是资料内容）
- 只报一个值不提另一个

正确回答：

> 两处资料对同一项给出的数值不一致：
> - 使用说明书（版本 A/0）第 11 段：安装力矩 45N·m
> - 检修规程（版本 B/1）第 7 段：紧固力矩 50N·m
>
> 两份资料版本不同，**本技能不判定哪份现行有效**，请核对受控文件系统（设备档案室 / EM 文档模块）后确定采用值。

同一文件内的多个取值、不同单位的数值（力矩 N·m 与端面比压 MPa）不算冲突，不误报。

## 六、必须附带的说明

每次回答都要说明：

1. 检索了多少份资料、命中多少段、其中几份是 PDF 转换文本
2. 未解析的文件有哪些（未转换 PDF / .doc / 图片 / 损坏文件）及该怎么转换
3. 脚本 warnings（逐条）
4. **「引用内容来自所提供资料，资料版本有效性请以受控文件系统为准；未能解析的文件已列出。经平台 pdf 技能转换的文本属模型读取产生，未经脚本验证，须人工核对原件。」**（报告中已自动带）

## 七、不做的事

- 不读 PDF、图片与 CAD 内容，不做 OCR（PDF 走平台 pdf 技能前置转换）
- 不补充资料中没有的技术数值与结论（通用知识问答用 `equipment-knowledge-qa`）
- 不判定资料版本的有效性与受控状态
- 不做选型、强度、安全计算
- 不编制检修方案与新规程（用 `repair-plan-assistant`）
- 不查台账参数（用 `equipment-ledger-query`）

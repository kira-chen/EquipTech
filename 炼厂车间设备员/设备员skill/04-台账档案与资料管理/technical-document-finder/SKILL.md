# 技术资料检索与原文引用（technical-document-finder）

面向中石化体系炼化厂车间设备员，按设备位号快速定位技术资料并基于资料原文回答技术问题。**所有技术数值与结论必须引用资料原文并标注出处；资料中没有的内容一律回答"资料中未找到"，不得用通用知识补充。** 问"这台设备的资料怎么写"用本技能；问"这类设备一般怎么做、原理是什么"用 equipment-knowledge-qa。

## 适用条件
- 用户说"找一下这台设备的图纸 / 说明书怎么说 / 检修规程里写的是什么 / 技术协议里有没有提到 / 这个参数在哪查"，并提供技术资料文件或资料目录清单。
- 支持两类任务：资料定位（找到哪些文件与设备相关）、资料问答（基于原文回答具体技术问题）。
- 车间设备员可做：按位号整理设备一机一档资料清单、核对资料目录与实体文件、从随机资料中查技术参数并注明出处。
- 不适用：台账参数查询（equipment-ledger-query）；设备原理与通用做法问答（equipment-knowledge-qa）；检修方案的编制（repair-plan-assistant）；替代受控文件系统（设备档案室 / EM 文档模块）的版本与有效性认定。

## 前提条件
- 输入：技术资料文件（`.docx` / `.md` / `.txt`）或资料目录清单（`.xlsx` / `.csv`）。可选：设备台账（SAP PM 技术对象清单或 EM 导出，用于按位号关联资料，位号与设备编号都可命中）。
- **PDF 前置步骤（统一口径）**：PDF 先用平台 pdf 技能转为 txt/docx 再传入，脚本不读 PDF；扫描件需先 OCR。转换产物按「原名.pdf.txt」命名放在同一目录，脚本会把它识别为该 PDF 的转换文本并在引用处标注"须人工核对原件"。旧版 `.doc` / `.xls` 请在 Office 中另存为 `.docx` / `.xlsx` 后传入。图片与 CAD 图纸只能做文件定位。
- 必填信息：设备位号（功能位置）或设备编号、查询内容（找什么资料或问什么技术问题）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得凭通用知识回答技术问题。**

## 操作步骤
1. **确认设备与查询内容** —— 位号或设备名称、要找的资料类型或要问的技术问题。**问题涉及具体数值（力矩、间隙、试压压力、材质牌号）时，明确告知用户答案必须来自资料原文，资料缺失则无法回答。** 资料里有 PDF 的，先按前置步骤转换。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/find.js" --docs "<资料目录或文件路径>" --tag "<位号>" --query "<查询内容>" --out "<工作目录>/资料检索"
   ```
   可选：`--ledger "<设备台账xlsx>"`、`--doc-type <图纸|说明书|规程|技术协议|检验报告>`、`--context <返回上下文字数>`、`--all-matches`、`--max-files <N>`（默认 300，超过直接报错不静默截断）。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（PDF 未转换只做定位 / 转换文本须核对原件 / .doc 需另存 / 位号在资料中未出现 / 台账设备名称或型号不唯一、未作关联线索 / 命中为空 / 目录登记但无实体文件等）。脚本用法详见 `scripts/README.md`。
   - 未转换的 PDF、图片、CAD、.doc/.xls：脚本 warning 并进 `unreadable`，**只能返回文件定位，不得声称读到了内容**。
   - 命中为空：明确回答"所提供资料中未找到相关内容"，**不得用通用知识或其他设备的资料代替**。
3. **读取 matches.json** —— 从 `<输出目录>/matches.json` 获取：`documents`（相关文件：文件名、类型、与设备的关联依据、`convertedFrom` 转换来源）、`passages`（命中段落：原文、所在文件、位置、上下文、是否来自转换文本）、`conflicts`（多处原文取值不一致）、`unreadable`（未解析的文件及原因）、`catalogOnly`（目录登记但无实体文件）、`counts`。
4. **组织回答** —— 资料定位类：列出相关文件及关联依据。资料问答类：**先给出原文引用（标明文件名与位置，转换文本注明须核对原件），再用一两句话解释；原文与解释必须分开，解释不得引入原文没有的数值或结论。** 多处原文不一致时全部列出并提示用户核实版本。
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后回答用户。**必须保留声明行："引用内容来自所提供资料，资料版本有效性请以受控文件系统为准；未能解析的文件已列出。经平台 pdf 技能转换的文本属模型读取产生，未经脚本验证，须人工核对原件。"**

## 预期结果
- `matches.md`：六至七节报告——相关资料文件、原文引用、多处原文不一致、无法检索内容的文件、（资料目录已登记但未提供实体文件，有数据时）、无法关联的文件、资料解读（分析段占位）；含转换文本时顶部有【注意】提示；末尾为声明行。
- 直接回答用户问题（对话形式），附相关文件清单与原文引用；必要时输出 `matches.json`。
- 回答中说明：检索了多少份资料、命中数量、未解析的文件（PDF 未转换 / .doc / 图片）、转换文本份数、版本提示、脚本 warnings（如有）。

## 不适用范围
- 不读 PDF、图片与 CAD 内容，不做 OCR（PDF 走平台 pdf 技能前置转换）。
- 不用通用知识补充资料中没有的技术数值与结论（设备通用知识问答用 equipment-knowledge-qa）。
- 不判定资料版本的有效性与受控状态。
- 不编制检修方案、操作规程等新文件。

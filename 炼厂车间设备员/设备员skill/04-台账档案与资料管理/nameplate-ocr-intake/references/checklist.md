# 交付自检清单

运行脚本后、交付前逐项核对。

## 前置确认
- [ ] **位号由用户提供**，未从照片背景、设备喷漆字或文件名推断
- [ ] 设备类型已确认，字段模板用的是该类型的模板
- [ ] 平台确实用 Read 读取了图片；**图片附件缺失或读图失败时已明确告知用户并终止**，未根据文件名、台账现值或用户口述编造铭牌参数
- [ ] node 可执行；不可用时已终止，未手工成文录入表

## 识别与置信度
- [ ] **每个字段都标了三档置信度之一**：清晰可读 / 部分模糊需核对 / 无法辨认
- [ ] 模糊位用 `▢` 占位，**未猜测任何模糊字符**（尤其 `0/O`、`1/I`、`5/S`、`6/8`）
- [ ] 小数点位置存疑的字段判为 blurry，未按"常见值"推定量级
- [ ] `unreadable` 字段的值为空，未用相近值或常识填充
- [ ] 铭牌上没有的项以 `unreadable` + reason「铭牌上无此项」提交，未凭空造值
- [ ] **clear / blurry 字段都抄录了铭牌原文 `raw`**（含单位与原始写法）；脚本标「疑似小数点错位」改判 blurry 的字段未被改回 clear

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；若为 `false`，已把 `error` 原文告知用户并终止
- [ ] `warnings` 已逐条告知用户，未隐去任何一条
- [ ] `intake.json`、`intake.md`、`intake.csv` 均已生成

## 台账比对
- [ ] 报告中每个数字都来自 `intake.json` 的 `counts`，未自行统计
- [ ] **位号已存在且参数不一致时，差异项已逐项列出**，并同时给出「识别错误」与「设备已更换」两种可能；相差 10 的整数倍的已按"疑似小数点错位"优先核对识别
- [ ] 用 SAP 设备编号查台账时，已说明按设备编号命中、台账功能位置是什么，未把设备编号写成位号
- [ ] **未自动覆盖台账任何数据**，冲突字段的建议录入值全部留空
- [ ] 未提供台账时，报告写「未提供台账文件，未做查重与比对」，**未说成「台账中没有这台设备」**
- [ ] 台账中无对应列的字段已单列，**未硬塞进相近的列**
- [ ] 台账某字段为空时显示「台账未填」，未留白也未按零处理

## 单位
- [ ] 单位与台账口径不一致的字段已提示核对，**未自动换算改写识别值**
- [ ] 未标注单位的字段已提示核对，**未假设铭牌单位就是台账口径**

## 不补充
- [ ] 未补充铭牌上没有的参数（实际运行参数、检修历史、备件清单）

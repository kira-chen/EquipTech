# 输入规格：铭牌识别结果与台账对齐

**分工**：读图识别由**模型**完成（平台的图像能力；**识别值由模型读图产生，未经脚本验证**），`scripts/intake.js` 只做识别结果的**后处理**——字段对齐台账（SAP PM / EM 列名）、raw 量级校验、单位校验、与台账现值比对查重、置信度校验、生成待确认录入行。脚本**不读图片**。

## 一、`--fields` 识别结果 JSON

模型按 `references/nameplate-fields.md` 的字段模板逐项提取后，把结果组成 JSON 传给脚本。既可直接作为参数值传入，也可写成 `.json` 文件后把**文件路径**传给 `--fields`（推荐，避免命令行转义问题）。

### 格式

```jsonc
{
  "photo": "P-1101A铭牌-20260921.jpg",   // 可选，照片文件名，仅写入报告头部
  "fields": [
    {
      "name": "制造厂",                   // 必需，字段名（用模板里的标准名）
      "value": "大连耐酸泵厂",            // 必需，识别值；unreadable 时必须为 null
      "confidence": "clear",              // 必需，三档之一：clear / blurry / unreadable
      "unit": null,                       // 可选，铭牌上印的单位原文
      "raw": "大连耐酸泵厂",              // clear/blurry 时必需：铭牌原文（含单位与原始写法，模糊位用 ▢）
      "note": null,                       // 可选，识别备注
      "reason": null                      // blurry/unreadable 时必需，说明为什么
    }
  ]
}
```

`{"制造厂": "大连耐酸泵厂", ...}` 这类**没有置信度的简写形式不被接受**，脚本报错终止——硬约束要求每个字段逐项标注置信度，简写没有置信度就只能靠默认，而默认成 clear 正是本技能要防的事。

### 三档置信度

| 档位 | 含义 | `value` 要求 | 报告去处 |
|---|---|---|---|
| `clear` | 清晰可读，字符无歧义 | 非空 | 识别结果表 + 建议录入行 |
| `blurry` | 部分模糊，需核对 | 非空，模糊位用 `▢` 占位 | 识别结果表 + **需核对项**；建议录入行中该字段留空待确认 |
| `unreadable` | 无法辨认 / 铭牌上无此项 | **必须为 `null`** | **无法辨认项**单列；不进建议录入行 |

**校验规则（脚本强制）**：

1. `confidence` 不是这三个值之一 → **报错终止**（不得默认为 clear）。
2. `confidence` 缺失 → **报错终止**（不得默认为 clear）。
3. `unreadable` 但 `value` 非空 → **报错终止**（矛盾输入，宁可报错也不猜哪个对）。
4. `blurry` / `unreadable` 缺 `reason` → warning，报告里 reason 写「未说明」。
5. `clear` 但 `value` 为空 → 改判 `unreadable` 并 warning（空值不可能是清晰可读的）。
6. `clear` 但 `value` 里含 `▢` → 改判 `blurry` 并 warning（有占位符就不是清晰可读）。

### `raw` 铭牌原文（clear / blurry 必填）与量级校验

识别值由模型读图产生，脚本无法验证识别是否正确；它能做的是用模型**同时抄录的铭牌原文 raw** 做一次量级核对：

| 情况 | 脚本处理 |
|---|---|
| clear / blurry 字段缺 `raw` | warning「未提供铭牌原文 raw，无法做量级校验」，`rawMissing: true`，建议录入行注明"未做量级校验，录入前须核对原件"（不中断） |
| 识别值中的数字都能在 raw 中找到 | `rawCheck.status: ok` |
| 识别值数字与 raw 中某数相差 10 的整数倍（4.0 vs 40、1.35 vs 1350） | **疑似小数点错位或漏位**：`rawCheck.status: magnitude`，clear **改判 blurry**，建议录入值留空 |
| 识别值数字未出现在 raw 中且无倍数关系 | `rawCheck.status: mismatch`，warning 提示核对识别（不改判） |
| 识别值有数字但 raw 无数字 | `rawCheck.status: noNumberInRaw`，warning 提示核对原文是否录全 |
| raw 含 `▢` | 不做数字比对（模糊位无法比） |
| `unreadable` 字段 | 不要求 raw |

汇总进 `rawIssues` 与 `counts.rawMissing / rawIssues`，报告「3.3 铭牌原文（raw）量级校验」单列。

## 二、`--tag` 位号（必需）

- 位号**必须由用户提供**。`--tag` 缺失 → 脚本报错终止，错误信息提示「位号须由用户提供，铭牌上通常没有位号，不得从照片或文件名推断」。
- `--tag` 只接受非空字符串。
- 脚本**不会**从 `--fields` 里的「出厂编号」「产品编号」回填位号，也不解析 `photo` 文件名。
- `--tag` 给的是 SAP 设备编号（8 位流水号）时：先按位号列查，未命中再按「设备编号」列查；命中则 `meta.ledgerMatchedBy = '设备编号'`、`meta.ledgerTag` 带出功能位置，并 warning 说明。**设备编号不是位号**，用户给的标识原样保留。

## 三、`--equip-type` 设备类型（必需）

决定字段模板与必备字段。可识别的写法：

| 标准类型 | 可识别写法 |
|---|---|
| `泵` | 泵、pump、离心泵、往复泵、屏蔽泵 |
| `电机` | 电机、马达、motor、电动机 |
| `压缩机` | 压缩机、compressor、风机、鼓风机 |
| `换热器` | 换热器、热交换器、冷却器、再沸器、冷凝器、空冷器、exchanger |
| `容器` | 容器、压力容器、塔、塔器、罐、储罐、反应器、分离器、vessel |
| `阀门` | 阀门、阀、valve、安全阀、调节阀 |
| `仪表` | 仪表、变送器、表、instrument、流量计、压力表 |

无法归入以上任一类 → 报错终止并列出支持的类型，**不按「通用」兜底**（字段模板对不上会产生错误的对齐结果）。

## 四、台账文件（可选，`--ledger`）

sheet 名匹配「设备台账」「台账」「设备清单」「技术对象」「功能位置」「设备」。字段口径与 `equipment-ledger-query` 一致：

| 列名 | 必需 | 说明 |
|---|---|---|
| 位号 | 是 | 查重键（SAP 功能位置） |
| 设备编号 | 否 | SAP 8 位流水号 / EM 编码，单列展示；`--tag` 给设备编号时按此列命中 |
| 设备名称 | 否 | |
| 规格型号 | 否 | 对齐铭牌的「型号」「规格」 |
| 制造厂 | 否 | 对齐铭牌的「制造厂」 |
| 出厂编号 | 否 | 对齐铭牌的「出厂编号」（SAP「制造商序列号」） |
| 设备代码 | 否 | 对齐铭牌的「设备代码」（特种设备代码 / 注册代码） |
| 投用日期 | 否 | **不对齐铭牌的「制造日期」**，见第八节；SAP「建造年份」同样不对齐 |
| 专业 / 区域 / 介质 / 重要度 / 状态 | 否 | 铭牌上没有，不参与对齐 |

|---|---|---|
| 位号 | 位号、设备位号、TAG | 位号编码、**功能位置**、功能位置编号、技术标识、技术对象、技术对象标识 |

| 设备名称 | 设备名称、名称、设备描述 | 技术对象描述、功能位置描述、描述 |
| 规格型号 | 规格型号、型号、规格、型号编号 | 技术参数 |
| 制造厂 | 制造厂、厂家、制造商、生产厂家、供应商 | 制造单位 |
| 投用日期 | 投用日期、投用时间、投产日期、启用日期、安装日期 | 开始日期、投运日期、建造年份 |
| 出厂编号 | 出厂编号、产品编号、机号、序列号、出厂序号、制造商序列号 | 出厂编码 |
| 设备代码 | 设备代码、特种设备代码、注册代码、注册编号 | — |
| 制造日期 | 制造日期、出厂日期、生产日期 | — |

表头行取前 10 行中命中位号列的一行；首列以 合计 / 小计 / 总计 / 共计 / 总数 开头的行跳过并 warning。**「设备编号」不是位号别名**：SAP 导出表里「功能位置」是位号、「设备」是流水号，两者分列。

未提供 `--ledger` → 不做查重与比对，`conflicts` 为 `null`，报告写「未提供台账文件，未做查重与比对」，**不得声称「台账中无此位号」**（没看过台账就不知道）。

## 五、台账字段对齐规则

铭牌字段名 → 台账列名的映射（按设备类型）：

| 铭牌字段 | 台账列 | 适用类型 |
|---|---|---|
| 制造厂 | 制造厂 | 全部 |
| 型号 | 规格型号 | 全部 |
| 规格 | 规格型号 | 型号缺失时才对齐到规格型号 |
| 出厂编号 | 出厂编号 | 全部（台账无此列则不比对） |
| 设备代码 | 设备代码 | 容器、换热器（承压设备；台账无此列则不比对） |
| 制造日期 | 制造日期 | 全部（台账无此列则不比对） |
| 额定功率 / 配用功率 | 功率(kW) | 泵、电机、压缩机 |
| 流量 | 流量(m³/h) | 泵、压缩机 |
| 扬程 | 扬程(m) | 泵 |
| 转速 / 额定转速 | 转速(r/min) | 泵、电机、压缩机 |
| 额定电压 | 电压(V) | 电机 |
| 额定电流 | 电流(A) | 电机 |
| 设计压力 | 设计压力(MPa) | 换热器、容器、阀门 |
| 设计温度 | 设计温度(℃) | 换热器、容器 |
| 换热面积 | 换热面积(m²) | 换热器 |
| 容积 | 容积(m³) | 容器 |
| 公称通径 | 公称通径(mm) | 阀门 |
| 公称压力 | 公称压力(MPa) | 阀门 |
| 主体材质 / 泵壳材质 / 阀体材质 | 材质 | 对应类型 |
| 执行标准 | 执行标准 | 全部 |
| 重量 | 重量(kg) | 全部 |

台账列的定位同样走别名：先按标准列名全等，再按别名表，因此台账写「生产厂家」「型号」「功率」（不带单位后缀）或 SAP 的「制造商」「型号编号」都能对齐到对应的标准列。

台账里**确实没有**对应列 → 该字段照常进建议录入行，并在 `unmapped` 中列出，报告提示「台账无此列，需先加列或人工判断放哪」，**不得硬塞进相近的列**。

## 六、单位换算校验

脚本按下表**校验**铭牌单位与台账口径是否一致。**不一致时只出 warning 提示核对，绝不自动换算改写 `value`**——因为铭牌单位可能本身就印错了，自动换算会把错误固化。

| 台账口径 | 等价单位（不告警） | 需核对的单位（warning + 换算参考值） |
|---|---|---|
| kW | kW、千瓦、KW | HP、hp、马力（×0.7457）、PS（×0.7355）、W（×0.001） |
| MPa | MPa、兆帕 | bar（×0.1）、kgf/cm²、kg/cm²、公斤（×0.098）、psi（×0.006895）、kPa（×0.001） |
| ℃ | ℃、°C、度、C | ℉、°F（(F−32)×5/9） |
| m³/h | m³/h、m3/h、立方米/小时 | L/s（×3.6）、L/min（×0.06）、m³/min（×60）、GPM（×0.2271） |
| r/min | r/min、rpm、RPM、转/分 | — |
| kg | kg、千克、公斤 | t、吨（×1000）、g（×0.001） |
| mm | mm、毫米 | m（×1000）、cm（×10）、inch、"（×25.4） |
| m² | m²、m2、平方米 | ft²（×0.0929） |
| m³ | m³、m3、立方米 | L、升（×0.001） |
| V | V、伏 | kV（×1000） |
| A | A、安 | mA（×0.001） |
| m | m、米 | mm（×0.001）、ft（×0.3048） |

换算参考值只写进 warning 与报告的「需核对项」说明栏，`value` 保持铭牌原值不动。

铭牌上**没印单位**时 → warning「字段 X 未标注单位，请核对台账口径（台账口径为 Y）」，**不假设它就是台账口径**。

## 七、查重与冲突判定（核心）

提供 `--ledger` 时，按 `--tag` 在台账中查找（先位号列，再设备编号列）：

### 情况 A：位号在台账中不存在
→ 判为**新增建档**。`conflicts` 为空数组，建议录入行全部为新增值；台账里没有对应列的字段（如台账无「电压(V)」列时的额定电压、防爆标志）同样进 `unmapped`，建档前先加列或人工判断放哪。

### 情况 B：位号已存在，且各对齐字段与台账现值一致
→ 判为**已有记录，参数一致**。warning 提示「位号 X 已在台账中且参数一致，无须重复录入」。

### 情况 C：位号已存在，但有字段不一致
→ **逐项列出差异，交用户判断，绝不自动覆盖。** 每个差异项给出两种可能的解释：

| 可能 | 表现 | 建议动作 |
|---|---|---|
| **识别错误** | 差异集中在易混字符（`0/O`、`1/I`、`5/S`、`6/8`），该字段置信度为 `blurry`，或识别值与台账值相差 10 的整数倍（小数点错位） | 重拍铭牌或核对出厂资料后再定 |
| **设备已更换** | 差异跨多个字段（制造厂 + 型号 + 出厂编号同时变），或出厂编号 / 设备代码完全不同 | 走变更流程（`moc-change-assistant`，《中国石化变更管理规定》口径），台账需做变更记录而非直接改写 |

脚本按以下口径给出 `hint`（仅提示，**不下结论**）：

- 该字段 `confidence` 为 `blurry` → `hint: "该字段识别置信度为部分模糊，优先核对识别是否有误"`
- 识别值与台账值相差 10 的整数倍 → `hint: "识别值与台账值相差 10 的整数倍，疑似小数点错位或漏位，优先核对识别是否有误"`
- 出厂编号不一致 → `hint: "出厂编号不一致，可能是设备已更换，建议核对是否走过变更流程"`
- 差异字段数 ≥ 3 → `hint: "多个字段同时不一致，建议整体核对是否为同一台设备"`
- 其余 → `hint: "需人工核对铭牌原件或出厂资料"`

**三条硬规则**：

1. 脚本**不修改台账文件**，`--ledger` 只读。
2. 冲突项**不进** `intake.csv` 的建议录入值列，该字段在 csv 里留空并在「冲突说明」列注明，等用户判断。
3. 一致性比较前先做归一化（去空白、全半角、大小写、`×`/`x`、`φ`/`Φ`/`Ф`），归一化后仍不同才算差异——避免把 `ZA-100-250` 与 `ZA-100-250 ` 报成冲突。
   - **制造日期**先去掉台账导出带的时分秒（`2015-02-01 00:00:00`），再按两者中较粗的精度比：铭牌多只印年月（`2015.02` / `2015年2月`），台账导出为完整日期（`2015-02-01`），年月相同即一致；年月不同，或两边都精确到日而日不同，仍判不一致。
   - **带单位的参数列**（功率、流量、扬程、转速、设计压力、设计温度、容积等）两边都是纯数值时按数值比：`2.50` 与 `2.5`、`2.0` 与 `2` 一致。出厂编号、设备代码等编号列不按数值比（`0176750` 与 `176750` 不是同一个号）。
   - **材质**：台账按部位合写（`泵体 ZG230-450 / 叶轮 ZG1Cr13`、`壳体 Q345R / 管束 10#`）时，泵壳材质只与「泵体 / 泵壳 / 壳体」一段比，阀体材质只与「阀体 / 壳体」一段比，主体材质只与「壳体 / 筒体 / 主体 / 本体」一段比，不跨部位配对。部位名按上述词表做前缀匹配，台账写成 `泵体铸铁`（部位名与材质之间没有空格）或 `泵壳：HT250` 时同样能分出部位与材质。

## 八、不做的事

- **不补充铭牌上没有的参数**：实际运行参数、检修历史、投用日期、所属专业、区域，一律不进产出。
- **制造日期 ≠ 投用日期**：铭牌上是制造日期，脚本只写进 `制造日期`，**绝不填进台账的「投用日期」列**；SAP「建造年份」也不与制造日期比对。
- **不猜模糊字符**：`▢` 原样保留进报告，不做任何补全。
- **不自动换算单位**：只给换算参考值供人核对。
- **不改写用户台账文件**：只输出 `intake.csv` 待确认，正式录入走 EM / SAP 主数据维护流程。
- **不验证识别正确性**：脚本不读图；raw 量级校验只能发现识别值与模型自抄原文的不一致。

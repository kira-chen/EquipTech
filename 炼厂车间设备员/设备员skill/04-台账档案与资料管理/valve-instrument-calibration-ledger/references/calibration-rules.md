# 校验到期口径、归口分工与表述规范

## 一、归口分工（中石化体系炼化厂口径）

| 对象类别 | 归口 | 本技能做什么 | 本技能不做什么 |
|---|---|---|---|
| 安全阀、爆破片（安全附件） | **车间设备员**提报送校、跟踪整改；校验由有资质检定机构实施 | 到期提醒、送检批次、不合格整改跟踪、证书归档核对 | 不判定校验结论，不延长周期 |
| 压力表、温度计等计量器具 | 计量（仪表）专业，按检定规程强制检定 | `--category 全部` 时按台账周期提醒 | 不安排检定、不判定精度 |
| 可燃/有毒气体报警器 | 计量（仪表）专业 | 同上，仅台账提醒 | 不安排标定 |
| 联锁与安全仪表回路（SIS） | 仪表专业（SIS 功能测试，工艺参与） | 同上，仅台账提醒；超期时提示安全联锁有效性无保障 | 不做功能测试、不判定 SIL |
| 称重与流量计量装置 | 计量专业 | 同上，仅台账提醒 | — |
| 压力容器/管道/锅炉本体定期检验、年度检查 | 特种设备管理员 | 不在本技能范围，用 `special-equipment-inspection-due` | — |

默认 `--category 安全阀`。报告对计量/仪表类对象写「计量（仪表）专业归口，仅台账提醒」，不替其安排检定。

## 二、周期应查哪份规定（脚本不代入数值）

> **脚本不内置任何默认周期。** 台账周期缺失时该项进待确认，报告只提示应向谁核实、查哪份规定；**不得在报告中代算到期日**。

| 对象类别 | 周期依据（只写出处，数值以用户提供的制度文件与校验报告为准） | 缺失时向谁核实 |
|---|---|---|
| 安全阀 | 《中国石化设备管理规定》与厂内安全附件管理制度；TSG 21、TSG D7005 对安全附件校验的要求；延长校验周期须有厂内审批文件 | 车间设备主任 / 公司设备管理部门（机动部/设备部） |
| 爆破片 | 厂内安全附件管理制度与制造厂更换周期要求；超压泄放后必须更换 | 同上 |
| 压力表、温度计 | 计量检定规程与厂内计量器具管理制度（强制检定目录） | 计量管理员 / 仪表专责 |
| 气体报警器 | 厂内可燃/有毒气体检测报警器管理制度与检定规程 | 仪表专责 |
| 联锁与 SIS | 厂内 SIS 管理制度、SIL 评估确定的功能测试间隔 | 仪表专责 / SIS 管理员 |
| 计量装置 | 贸易结算按强制检定，内部核算按厂内规定 | 计量管理员 |

## 三、到期判定口径

```
计算下次校验日期 = 上次校验日期 + 校验周期
  月 / 季 / 年 / 半年 → 按自然月推（C.addMonths，1 年 = 12 个月；03-31 + 6 月 = 09-30；闰日 + 1 年 = 02-28）
  天 / 周            → 按天推
剩余天数 = 计算下次校验日期 - 基准日期
```

| 状态 | 判定 |
|---|---|
| `overdue` 超期 | 剩余天数 < 0，超期天数 = -剩余天数 |
| `dueSoon` 临期 | 0 ≤ 剩余天数 ≤ 提前提醒天数（默认 30 天，`--lead-days` 可调） |
| `normal` 正常 | 剩余天数 > 提前提醒天数 |
| `undetermined` 待确认 | 周期、上次校验日期、对象类别任一缺失或无法解析 |
| `unresolvedFail` 不合格未整改 | 上次校验结论为不合格且无整改闭环记录 |

**判定优先级**：`unresolvedFail` > `undetermined` > 到期计算三态。即一项若既是不合格未整改又缺周期，归入不合格未整改。

### 台账下次校验日期与计算值不一致

台账登记了「下次校验日期」且与按周期计算值不同时，**两者并列展示于附一并 warning**，脚本的状态判定以计算值为准（有周期与上次日期时口径唯一），但报告不得声称台账登记值有误——可能是经批准的周期调整，须由设备员核实。

## 四、不合格未整改的处理（关键口径）

上次校验结论为不合格时，该对象的计量与保护性能已被检定机构否定：

1. **不得按合格处理参与到期计算** —— 不输出剩余天数、不输出超期天数，不进入 overdue/dueSoon/normal 任一档。
2. **单列 `unresolvedFail` 一节醒目提示**，列出位号、类别、上次校验日期、结论原文、证书编号与台账出处行号。
3. **进入送检清单**，批次备注为「上次不合格且无整改记录，须先整改后复校」——先整改再复校，不是直接送检。
4. **未提供整改清单时一律按未整改处理**，不得反向推定「无整改记录即已整改」。
5. **「故障」「待修」「检修中」「停用」是设备状态，不是校验结论**：归 `result: null` 并 warning 提示补填检定机构结论，既不按不合格也不按合格。

只有整改清单中状态明确为闭环（已整改/已完成/已处理/已更换/已复校/已复检，且不含未、待、不、正在、进行中）的项，才恢复按上次校验日期参与到期计算，且 JSON 中保留 `remediation` 记录供追溯。整改完成日期早于台账本次（不合格）校验日期的，是上一次不合格的旧记录，不能证明本次已整改，仍按不合格未整改处理并 warning；整改完成日期未填的按整改状态判定。同一位号在整改清单里有多行时，在该位号全部闭环记录里配对：有一条完成日期不早于本次校验日期（或未填完成日期）即算已整改，JSON 的 `remediation` 取完成日期最晚的那条；全部都早于本次校验日期才按未整改处理。旧整改记录的 warning 只对统计范围内的记录发出。

## 五、送检批次归并

送检清单 = 超期 + 临期 + 不合格未整改三类。按「对象类别 ｜ 校验周期原文」归为一批：同类别同周期的对象通常委托同一检定机构、走同一份委托单，便于集中送检与停车窗口安排。周期待确认的对象单列一批「周期待确认」，提示先定周期再委托。计量/仪表类批次只作提醒，委托检定由计量（仪表）专业办理。

## 六、证书归档核对（`--certs`）

按文件名是否含台账「证书编号」或「位号」判断证书是否归档；只核对文件存在性，不读证书内容。缺证书不等于未校验，报告写「未匹配到证书文件，请核实归档」。

## 七、说明段表述规范

撰写 200~350 字，结构固定为五段：

1. **到期概览**：统计范围（默认安全阀 / 全部）、台账总数、超期/临期/正常/不合格未整改/待确认分布。
2. **超期项与风险**：逐条或分类说明超期对象、超期天数。**安全阀、爆破片、报警器、联锁回路超期时，必须明确写出「该项在校验有效期外，不得作为有效的安全保护措施，相应安全联锁的有效性无保障」**。
3. **不合格未整改项**：列明对象与结论原文，说明须先整改后复校，不得按合格状态继续投用。
4. **送检安排建议**：按批次说明建议的委托与停车窗口安排，注明需要停车拆装的对象（安全阀、爆破片）；计量/仪表类只提醒，由计量（仪表）专业安排。
5. **待确认项**：列明缺哪个字段、需向谁核实（车间设备主任、仪表专责、计量管理员、SIS 管理员）。

### 用词要求

| 场景 | 应写 | 不得写 |
|---|---|---|
| 超期安全阀 | 「PSV-1101 已超期 35 天，处于校验有效期外，不得作为有效安全保护措施」 | 「已超期但压力正常，可继续使用」 |
| 联锁回路超期 | 「SIS-1501 超期，安全联锁有效性无保障，请仪表专业安排功能测试」 | 「联锁应该还有效」 |
| 不合格项 | 「上次校验不合格且无整改记录，须先整改后复校」 | 「重新送检即可」 |
| 「故障」结论 | 「结论栏填的是设备状态，请补填检定机构结论后重算」 | 「故障按不合格处理」 |
| 待确认项 | 「校验周期未登记，须向车间设备主任核实厂内规定后补入台账」 | 「按同类 1 年周期估算已超期」 |
| 数字 | 引用 calibration.json 的 counts 与 overdueDays | 自行统计或估算 |

### 硬约束

- **不做校验结论判定**。脚本与模型都不判定某台安全阀或仪表是否合格，结论以检定机构证书为准。
- **不给出「可继续使用」的意见**。超期项的处置由车间设备主任与公司设备管理部门决定。
- **不延长周期**。台账周期与厂内规定不一致时如实提示，不擅自按更宽松的周期计算。
- **不对待确认项代算到期日**。缺字段就是缺字段。
- **不替计量（仪表）专业安排检定**，只做台账提醒。

## 八、必保留说明行

报告顶部必须原样保留：

> 校验结论以有资质检定机构出具的证书为准；超期未校的安全附件与安全仪表不得作为有效安全保护措施。

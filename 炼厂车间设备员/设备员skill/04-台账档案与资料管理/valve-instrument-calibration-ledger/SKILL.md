# 安全阀校验台账到期管理（valve-instrument-calibration-ledger）

面向中石化体系炼化厂车间设备员，管理本车间安全阀（含爆破片）校验台账的到期提醒与送检准备。**到期判定由脚本完成，模型不得延长周期；校验结论以有资质检定机构出具的证书为准。** 压力表、温度计等计量器具的检定与 SIS/联锁功能测试由计量（仪表）专业归口，本技能对这些对象只做台账到期提醒。

## 适用条件
- 用户说"安全阀什么时候校验 / 哪些安全阀该送校了 / 出个送检清单 / 上次不合格的那几个整改了没 / 校验证书齐不齐"，并提供校验台账。
- 车间设备员可做：安全阀与爆破片校验台账的到期提醒、送检批次整理、不合格项整改跟踪、证书归档核对；计量器具/报警器/联锁回路只作台账提醒（`--category 全部` 或指定类别）。
- 由其他专业归口（技能只提示、不判定、不安排）：压力表温度计检定、报警器标定、SIS 功能测试（计量/仪表专业）；安全阀校验作业与结论（有资质检定机构）；特种设备本体定期检验与年度检查（特种设备管理员，用 special-equipment-inspection-due）。
- 不适用：校验结论的判定；实际检定作业与出具证书；对超期项给出"可继续使用"的意见。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含「校验台账」（工作表名含 校验台账 / 检定台账 / 仪表台账 / 计量台账 / 安全阀台账 / 安全附件 均可），列名支持 EM / SAP PM / 特种设备平台导出写法（功能位置、设备、设备描述、设备品种、型号编号、整定压力、检验周期、检验日期、检验结论、校验报告编号、检验机构、所属设备等），字段见 `references/input-spec.md`。
- 必填信息：车间名称、基准日期（YYYY-MM-DD）。可选：提前提醒天数（默认 30 天）、统计类别（默认 安全阀）、不合格项整改清单、校验证书目录。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工推算到期日。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 设备资产管理 | `get_safety_valves` | `workshop`：车间名（与 `--workshop` 一致；只查单台时改用 `tag`：位号） | `--input` |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；把目录作为“交给脚本”一列的参数值。
2. **必须带 `workshop` 参数取数**：导出的校验台账没有车间列。脚本只在输入带车间列时按 --workshop 核对（剔除其他车间的行；车间列全不一致时不筛并在报告开头提示）；MCP 导出多数不带车间列，取数时仍必须带 workshop，不带参数会把其他车间的安全阀统计进本车间报告。

## 操作步骤
1. **确认车间、基准日期与统计范围** —— 默认只统计安全阀（车间设备员归口）；用户要看压力表、报警器、联锁时用 `--category 全部` 或指定类别，并说明这些类别仅作台账提醒。检查台账是否含校验周期与上次校验日期；**周期缺失时不得代入任何默认周期**（安全阀校验周期以厂内规定与校验报告为准，`references/calibration-rules.md` 只说明应查哪份规定）。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/calibration.js" --input "<xlsx路径>" --workshop "<车间名>" --date <YYYY-MM-DD> --out "<工作目录>/校验管理"
   ```
   可选：`--lead-days <提前提醒天数>`、`--category <安全阀|爆破片|计量器具|报警器|联锁回路|计量装置|全部>`（默认 安全阀）、`--issues "<不合格整改清单xlsx>"`、`--certs "<校验证书目录>"`（按证书编号或位号匹配文件名核对归档，不读证书内容）。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺列/周期无法解析/上次校验日期缺失/结论为「故障」等设备状态/证书编号重复/默认范围排除了多少条计量仪表记录/按车间剔除的行数与车间名/车间列为空的行数等）。warning 以【注意】开头说车间列取值与 --workshop 不一致时，多半是传错了文件，先请用户核对输入再交付。脚本用法详见 `scripts/README.md`。
   - 周期或上次校验日期缺失：归入 `undetermined` 单列一节，**绝不按同类对象默认周期处理**。
   - 上次校验结论为不合格但无整改记录：标记 `unresolvedFail` 醒目提示，**不得按合格处理参与到期计算**；整改清单的整改完成日期早于本次不合格校验日期的，是旧记录，不算整改（同一位号多行时，只要有一条闭环记录不早于本次校验日期就算已整改，不看行序）；「故障」「待修」是设备状态不是校验结论，归 null 并提示补填。
   - 月/季/年周期按自然月推算到期日（1 年 = 12 个月），台账登记的下次校验日期与计算值不一致时两者并列，不擅自采信其一。
3. **读取 calibration.json** —— 从 `<输出目录>/calibration.json` 获取：`overdue`（超期未校，含超期天数）、`dueSoon`（临期）、`normal`、`undetermined`、`unresolvedFail`（不合格未整改）、`byCategory`（分类汇总，含归口）、`sendList`（建议送检清单，按类别+周期归批）、`certs`（证书归档核对）、`counts`、`meta.categoryDefaulted`（是否按默认范围统计）。
4. **撰写"校验管理说明"** —— 读 `references/calibration-rules.md` 的表述口径，撰写 200~350 字，按"到期概览 → 超期项与风险 → 不合格未整改项 → 送检安排建议 → 待确认项"结构，替换 `calibration.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**数量与天数一律引用 calibration.json；安全阀与安全仪表回路超期须明确提示影响安全联锁有效性；计量/仪表类只提醒，不替计量（仪表）专业安排检定。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `calibration.md`、`calibration.json` 与 `送检清单.xlsx`。**必须保留说明行："校验结论以有资质检定机构出具的证书为准；超期未校的安全附件与安全仪表不得作为有效安全保护措施"。**

## 预期结果
- `calibration.md`：八节报告（到期概览、超期清单、不合格未整改清单、临期清单、待确认项、分类汇总、送检批次建议、校验管理说明）+ 三个附节（下次校验日期不一致项、证书编号重复、校验证书归档核对；前两个仅在有数据时出现），顶部为固定说明行，含计量/仪表类时另有【注意】归口提示。
- `送检清单.xlsx`：「送检清单」明细 +「批次汇总」两张表；`calibration.json`；`summary.json`。
- 交付时向用户说明：统计范围（默认安全阀 / 全部）、超期数量、临期数量、不合格未整改数量、待确认数量、缺证书台件数、脚本 warnings（如有）。

## 不适用范围
- 不做校验与检定作业，不出具校验结论与证书。
- 不判定仪表精度是否满足工艺要求；不安排计量器具检定与 SIS 功能测试（计量/仪表专业归口）。
- 不替代特种设备本体的法定定期检验与年度检查（用 special-equipment-inspection-due）。
- 不对超期项给出"可继续使用"的意见，不延长周期。

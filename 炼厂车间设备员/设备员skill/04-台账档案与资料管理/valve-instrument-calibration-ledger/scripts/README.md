# scripts 使用说明

## calibration.js —— 主脚本

```bash
node "<技能目录>/scripts/calibration.js" \
  --input "<校验台账xlsx>" \
  --workshop "<车间名>" \
  --date <YYYY-MM-DD> \
  --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 校验台账 xlsx 路径，或同结构 CSV 目录；工作表名含 校验台账 / 检定台账 / 仪表台账 / 计量台账 / 安全阀台账 / 安全附件 均可 |
| `--workshop` | 是 | 车间名称 |
| `--date` | 是 | 基准日期 YYYY-MM-DD，用于计算超期与临期 |
| `--out` | 否 | 输出目录，默认系统临时目录 `<os.tmpdir()>/vicl-out`，**建议始终传 `--out`** |
| `--lead-days` | 否 | 提前提醒天数，默认 30；非负整数 |
| `--category` | 否 | 统计范围：安全阀（**默认**，车间设备员归口）/ 爆破片 / 计量器具 / 报警器 / 联锁回路 / 计量装置 / 全部（`all` 亦可）。默认范围排除的记录数写入 warning；计量/仪表类仅作台账提醒 |
| `--issues` | 否 | 不合格整改清单 xlsx；不提供则所有不合格项按未整改处理并 warning |
| `--certs` | 否 | 校验证书目录：按文件名是否含证书编号或位号核对归档，列出缺证书台件；**不读取证书内容** |

### 产出

| 文件 | 内容 |
|---|---|
| `calibration.json` | `overdue / dueSoon / normal / undetermined / unresolvedFail / byCategory（含归口）/ sendList / dupCerts / certs / counts / meta` |
| `calibration.md` | 八节报告 + 附一（下次日期不一致，有数据时）/ 附二（证书重复，有数据时）/ 附三（证书归档核对，固定）；顶部保留必保留说明行，含计量/仪表类时另有【注意】归口提示；说明段留 `<!-- ANALYSIS_START/END -->` 占位 |
| `送检清单.xlsx` | 「送检清单」明细 +「批次汇总」两张表，按「对象类别 ｜ 校验周期原文」归批 |
| `summary.json` | 末行摘要落盘（Windows 控制台乱码兜底） |

`counts` 字段：`total`（本次统计范围）、`totalInLedger`（文件总计）、`overdue`、`dueSoon`、`normal`、`undetermined`、`unresolvedFail`、`safetyCriticalOverdue`、`instrumentItems`（计量/仪表类条数）、`sendBatches`、`sendItems`、`dupCerts`、`nextMismatch`、`certsMissing`（未提供 `--certs` 时为 null）。

### 判定口径要点
- **默认只统计安全阀**（车间设备员归口）。压力表/温度计检定、报警器标定、SIS 联锁功能测试由计量（仪表）专业归口，`--category 全部` 时只作台账到期提醒，报告与分类汇总标注归口。
- **到期日按自然月推算**：月/季/年/半年周期用 `C.addMonths`（1 年 = 12 个月，03-31 + 6 个月 = 09-30），天/周周期按天推。
- **周期或上次校验日期缺失 → `undetermined` 单列**，绝不代入同类对象默认周期；安全阀校验周期以厂内规定与校验报告为准。
- **上次结论不合格且无整改记录 → `unresolvedFail`**，不参与到期计算；整改清单的整改完成日期早于本次不合格校验日期的是旧记录，不算整改并 warning（只对统计范围内的记录发出）；同一位号在整改清单里有多行时，在全部闭环记录里找能配对本次不合格的一条（完成日期 ≥ 本次校验日期，或未填完成日期），有日期的取最晚一条，不因行序被旧记录覆盖；**「故障」「待修」等设备状态不是校验结论**，归 null 并 warning 提示补填检定结论。
- 台账「下次校验日期」与按周期计算值不一致 → 两者并列于附一 + warning，不擅自采信其一；只对 `--category` 统计范围内的记录出 warning（与附一、`counts.nextMismatch` 一致）。
- 证书编号重复 → 附二列出 + warning 提示核实是否串号。
- 对象类别无法识别 → 归入 `undetermined` 并在分类汇总中单列「未识别」。
- 别名表 = 局部别名 + 共享 `SYSTEM_ALIASES`（`C.mergeAliases`）：功能位置 → 位号；SAP「设备」8 位流水号 → 设备编号（单列，不作位号）；设备描述 → 名称；型号编号 → 型号；整定压力 → 量程；检验机构、所属设备（安装位置）等。详细口径见 `references/calibration-rules.md`。

### 退出码
- `0`：成功，末行输出 `{"ok":true,...}`
- `1`：失败，末行输出 `{"ok":false,"error":"...","warnings":[...]}`（缺参、非法日期、非法 `--category`、输入/整改清单/证书目录不存在、无校验台账工作表）

## make-sample.js —— 样例生成

```bash
node scripts/make-sample.js --out examples [--seed <n>] [--date <YYYY-MM-DD>]
```

生成 3 份样例：主校验台账（六类对象、五种状态，车间自维护列名）、不合格整改清单、EM / SAP PM 导出风格变体（功能位置 / 设备 / 设备描述 / 设备品种 / 型号编号 / 整定压力 / 检验周期 / 检验日期 / 检验结论 / 校验报告编号 / 检验机构 / 所属设备，含标题行、合计行、空位号行与「故障」结论）。
seed 改变量程数值、SAP 设备编号与上次校验日期的小幅偏移，但结论不变：主样例 `--category 全部` 恒为 3 超期、2 临期、3 待确认、1 组重复证书、1 处下次日期不一致，不配整改清单时不合格未整改 2 项、配清单时 1 项；默认（安全阀）恒为 4 条：1 超期、2 正常、1 不合格未整改；SAP 变体默认恒为安全阀 3 条：1 超期、2 正常（「故障」归 null，不计不合格），压力表 1 条不纳入。

# 设备变更管理辅助（moc-change-assistant）

面向中石化体系炼化厂车间设备员，按《中国石化变更管理规定》的分类框架（**工艺技术变更 / 设备设施变更 / 管理变更 × 重大 / 一般**，"临时"是属性）判断一项改动是否需要走变更流程，梳理需评估项、应更新的资料与承压设备的法定手续。**是否属于变更、变更类型与级别由脚本按规则判定，模型不得自行放宽；最终认定以厂内变更管理部门（公司设备管理部门 / 变更管理归口部门）按厂内实施细则为准。**

## 适用条件
- 用户说"这个改动要走 MOC 吗 / 换型号要不要报变更 / 材质降一档行不行 / 加个取样口算变更吗 / 临时加条跨线 / 变更申请怎么写 / 改完台账要改哪些"，并说明改动内容。
- 覆盖设备设施变更：材质变更、型号规格变更、结构改动、备件代用、临时措施；工艺参数与联锁定值变更（工艺技术变更）可判定但由工艺 / 仪表专业提报；管理变更（组织、制度、维保单位）级别由厂内制度定。
- 车间设备员可做：设备设施变更的判定与提报、变更评估要点整理、台账与资料更新清单、承压设备改造的法定手续提示、临时变更的期限与恢复计划跟踪。
- 由其他专业或部门归口（技能只提示）：工艺参数变更（工艺专业提报）、联锁定值与控制方案变更（仪表专业提报）、变更审批（变更管理部门）、HAZOP / SIL / 强度校核（专业出具）、改造告知与监督检验办理（特种设备管理员）。
- 不适用：变更的审批决定；技术方案的设计与计算；HSE 风险评估的专业结论。

## 前提条件
- 输入：用户对改动的描述（必需）。可选：设备台账（SAP PM 技术对象清单 / EM 导出，用于核对原状态与识别承压设备）、原设计资料、拟变更方案、厂内变更管理实施细则（`--spec` xlsx，预填模板在 `assets/templates/plant-spec-template.xlsx`）。
- 必填信息：设备位号（或 SAP 设备编号）、原状态、拟变更后状态、变更原因、是否临时变更及期限。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得自行判定是否属于变更。**

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 设备资产管理 | `get_equipment_ledger` | `tag`：位号 | `--ledger` |

## 操作步骤
1. **确认变更要素** —— 按 `references/intake-questions.md` 核对：位号、原状态、变更后状态、变更原因、是否影响介质与操作条件、是否影响安全设施、是否临时、期限、是否压力容器/压力管道。**"原状态"与"变更后状态"必须具体到参数或型号，笼统描述（"换个泵""换成 P-2101B"）须追问；只写位号不算具体。**
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/moc.js" --tag "<位号>" --before "<原状态>" --after "<变更后状态>" --reason "<变更原因>" --out "<工作目录>/变更评估"
   ```
   可选：`--category <材质|型号|结构|工艺|控制|备件代用|管理>`、`--same-model-material <是|否>`（同型号同材质同厂家才判同类替换）、`--affects-perf <是|否>`、`--exceeds-design <是|否>`、`--special <是|否>`（是否压力容器 / 压力管道）、`--temporary --until <YYYY-MM-DD>`（早于今天时脚本照常输出该期限，并 warning 提示核实是否已恢复或转正式变更）、`--spec "<厂内变更制度xlsx>"`、`--ledger "<设备台账xlsx 或 CSV 目录>"`、`--workshop`、`--applicant`、`--name`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（变更类别无法识别 / 原状态描述不足 / 未确认是否承压设备 / 厂内制度无法解析 / 与厂内制度冲突等）。脚本用法详见 `scripts/README.md`。
   - 判定所需信息不足：输出 `undetermined` 并列出还需补充哪个要素，**绝不因信息不足而判定"不需要走变更"**。
   - 同规格不同厂家代用：脚本判"待厂内评审（材料代用单 / 同类替换评审）"，是否报变更以厂内制度为准，不自动判一般变更。
   - 厂内制度与默认口径冲突：以厂内制度为准，冲突点在 `conflicts` 中列出。
   - 不带 `--category` 时按描述识别类别：管理变更只看原状态与变更后状态（变更原因里写到承包商不算）；「10#罐」「20号机组」这类设备编号不当作碳钢牌号；前后材质按完整牌号比对（HT250 → HT200 算材质改变；15CrMoR、12Cr2Mo1R 等带 R/G 后缀的牌号按完整牌号识别，前后都是 15CrMoR 不算材质改变）。识别结果不对时用 `--category` 指定。
3. **读取 moc.json** —— 从 `<输出目录>/moc.json` 获取：`isChange`（true / false / null）、`changeTypeCn`（工艺技术 / 设备设施 / 管理变更）、`level` / `levelCn`（重大 / 一般 / 待厂内评审 / 不属于变更 / 未判定）、`temporary`、`basis`、`ruleId`、`ownership`（提报专业与设备员可否直接提报）、`statutory`（压力容器 / 压力管道三项法定手续）、`assessItems`（按安全、工艺、设备、电气仪表、环保、操作规程六专业分组）、`docUpdates`（应更新的 EM / SAP PM 台账、图纸、规程清单）、`undetermined`、`conflicts`、`temporaryPlan`、`counts`。
4. **生成变更评估要点** —— 按 `assets/templates/moc-template.md` 成文，含：变更概况、是否属于变更及依据、归口与提报专业、需评估项、应更新资料、待确认信息、与厂内制度的冲突点、特种设备法定手续提示、临时变更期限与恢复计划、变更申请要点提示。**判定依据须引用规则条款编号（RN1、R1~R8、U1~U6）或厂内制度条款，不得只写结论。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `moc.md` 与 `moc.json`。**必须保留声明行："本判定为辅助参考，变更是否成立、变更类型、级别与审批要求以厂内变更管理部门按《中国石化变更管理规定》及厂内实施细则认定为准；未经批准不得实施变更"，不得删除或改写。**

## 预期结果
- `moc.md`：十节评估要点——一、变更概况；二、是否属于变更及依据（变更类型、级别、临时属性）；三、归口与提报专业；四、需评估项（按专业）；五、应更新资料清单；六、待确认信息；七、与厂内制度的冲突点；八、特种设备法定手续提示；九、临时变更期限与恢复计划；十、变更申请要点提示（分析段占位）；末尾为固定声明行。
- `moc.json`：判定结果与清单；`summary.json`：脚本末行摘要。
- 交付时向用户说明：判定结论（是否变更、类型、级别、是否临时）、依据条款、提报专业、需评估项数、应更新资料数、待确认信息、承压设备法定手续是否适用、脚本 warnings（如有）。

## 不适用范围
- 不审批变更，不替代变更管理部门或 HSE 部门的认定。
- 不做技术方案设计、强度校核与选型计算。
- 不出具 HAZOP、SIL、风险评估等专业结论。
- 不替工艺 / 仪表专业提报工艺参数与联锁定值变更，只做设备侧提示。
- 不替用户实施台账与图纸的修改，不办理改造告知、监督检验、使用登记变更。

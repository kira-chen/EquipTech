## 关键验证点

1. **信息不足绝不判「不需要走变更」**（最关键）：用例 8 中 `isChange` 输出 `null`、`level` 为 `undetermined`，并在「六、待确认信息」中逐项列出还需补充哪个要素，报告明示「未判定不等于不需要走变更」；只写位号（P-2101B / 1000-CDU-P1101B）不算具体。
2. **「不属于变更」只能正面命中**：用例 1 填了 `--same-model-material 是` 才判 RN1；不填该参数时同样的描述会按 R6 待厂内评审，而非默认为不属于变更。
3. **三大类 × 重大/一般 + 临时属性**：每个判定都带 `changeTypeCn`（工艺技术 / 设备设施 / 管理变更）；「临时」不是级别，`--category 临时` 转为属性并 warning。
4. **同规格不同厂家代用待厂内评审**：用例 7 默认口径 `level: review`、`isChange: null`，提示走材料代用单；厂内制度可定为一般或重大并记冲突。
5. **承压设备三项法定手续**：用例 2、3 按台账对象类型识别为压力容器，第八节固定列出改造告知、监督检验、使用登记变更（只提示名称，不写数值）；台账为离心泵且描述无承压词时按「待确认」列出并进未判定清单，不默认免办。
6. **归口专业**：用例 4、5 的 `ownership.equipmentEngineerCanSubmit` 为 false，报告提示转交工艺 / 仪表专业。
7. **厂内制度优先**：用例 7 中 `ruleId` 改为厂内条款号，`defaultVerdict` 保留默认口径结论备查，冲突点单列一节；制度表的「变更类型」列可改变三大类归属并 warning。
8. **判定依据带条款号**：每个用例的 `basis` 与 `ruleId` 都能对照 `references/moc-rules.md` 复核（RN1、R1~R8、U1~U6，或厂内条款号）。
9. **声明行固定保留**：所有用例的 `moc.md` 末尾都含「本判定为辅助参考，变更是否成立、变更类型、级别与审批要求以厂内变更管理部门按《中国石化变更管理规定》及厂内实施细则认定为准；未经批准不得实施变更」原文；产出无 emoji。
10. **临时变更必出期限与恢复计划**：用例 6 输出恢复期限与四项恢复计划提示；去掉 `--until` 后判未判定（U5），而不是按临时变更放行。

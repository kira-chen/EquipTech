# 交付自检清单

运行脚本后、交付前逐项核对。

## 脚本执行
- [ ] 末行 JSON 的 `ok` 为 `true`；为 `false` 时已把 `error` 原文告知用户并终止，**未手工判定是否属于变更**
- [ ] `warnings` 已逐条告知用户，未隐去任何一条
- [ ] `moc.json` 与 `moc.md` 均已生成

## 变更要素
- [ ] **原状态与变更后状态均已具体到参数或型号**（只写位号、"换成备用那台"不算），笼统描述已向用户追问后再判定
- [ ] 变更原因已确认；未提供时已告知申请时须补充
- [ ] 是否临时已确认；临时变更已取得期限
- [ ] 结构或材质改动已确认对象是否为压力容器 / 压力管道（`--special` 或台账），未确认的按「待确认」列出三项法定手续
- [ ] 抽取结果已回读给用户确认，不确定的要素标「待确认」，未猜测填充

## 判定
- [ ] 是否属于变更、变更类型（工艺技术 / 设备设施 / 管理）、变更级别、是否临时、判定依据均来自 `moc.json`，未自行放宽或收紧
- [ ] **判定依据引用了规则条款编号（RN1、R1~R8、U1~U6）或厂内制度条款号，不是只写结论**
- [ ] **未出现因信息不足而判定「不需要走变更」的情况**
- [ ] `isChange` 为 `null` 且 `level` 为 `undetermined` 时，报告中明示「未判定不等于不需要走变更」
- [ ] 「不属于变更」的结论只在 RN1 正面命中时给出，即已确认型号、材质与厂家均未改变
- [ ] 同规格不同厂家代用写的是「待厂内评审（材料代用单 / 同类替换评审）」，未自行判一般变更
- [ ] 工艺参数、联锁定值变更已写明由工艺 / 仪表专业提报，设备员只做设备侧提示，未替其提报

## 未判定
- [ ] 未判定项单列一节，逐项写明还需补充哪个要素
- [ ] 未按最宽松（不属于变更）或最严格（一律重大变更）默认处理
- [ ] 已告知用户补齐要素后重新运行即可判定

## 厂内制度
- [ ] 用户提供厂内制度时已用 `--spec` 读入（无现成表时已给 `assets/templates/plant-spec-template.xlsx`）
- [ ] **冲突点已逐条列出，并明确以厂内制度为准**
- [ ] 未提供厂内制度时，已说明采用的是默认口径（《中国石化变更管理规定》分类框架），厂内有实施细则时以厂内为准

## 特种设备法定手续
- [ ] 承压设备的结构或材质改动已列出**改造告知、监督检验、使用登记变更**三项，并说明由特种设备管理员办理
- [ ] 未确认是否承压设备时按「待确认」列出，未默认免办；`--special 否` 时第八节写不适用

## 临时变更
- [ ] **期限已明确写出**
- [ ] **恢复计划提示已给出**：恢复责任人、恢复内容、恢复验收方式、到期未恢复的升级处置
- [ ] 已提示到期未恢复须重新申请延期；级别未因「临时」而降低

## 需评估项与资料更新
- [ ] 需评估项按安全、工艺、设备、电气仪表、环保、操作规程六个专业分组呈现
- [ ] 重大变更已包含多专业会审的提示
- [ ] 应更新资料清单已列出（EM / SAP PM 台账、P&ID、设备档案、规程等），并说明由资料管理岗与设备员按厂内流程执行
- [ ] 已说明需评估项是提示清单，专业结论（HAZOP、SIL、强度校核）须由对应专业出具

## 分析段
- [ ] 已替换 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字
- [ ] 字数 200~400
- [ ] 五段结构齐全：变更必要性、判定结论（类型、级别、是否临时）与依据条款、归口提报专业、需重点评估的专业与理由、资料更新 / 法定手续 / 审批提示
- [ ] 未替用户做技术方案设计、强度校核或风险评估结论
- [ ] 产出未使用 emoji，醒目提示用「【注意】」「【未判定】」

## 声明行
- [ ] **`moc.md` 末尾保留了固定声明行原文，未删除、未改写：**
      「本判定为辅助参考，变更是否成立、变更类型、级别与审批要求以厂内变更管理部门按《中国石化变更管理规定》及厂内实施细则认定为准；未经批准不得实施变更」

## 交付说明
- [ ] 已说明判定结论（是否变更、类型、级别、是否临时）、依据条款、提报专业、需评估项数、应更新资料数、待确认信息、冲突点数、法定手续是否适用
- [ ] 已说明口径来源（默认口径 / 厂内制度 / 两者一致）
- [ ] 已提示未经批准不得实施变更；提交对象为车间设备主任 / 公司设备管理部门（变更管理归口部门）

# 备件需求提报（spare-parts-demand）

面向中石化体系炼化厂车间（运行部）设备员，根据检修计划与历史消耗生成备件需求清单，供上报物资部门与公司设备管理部门（机动部/设备部）。**需求量推算由脚本按规则完成，模型只负责成文；不得凭经验调整数量或增补清单外的物料。**

车间设备员可做的部分：按检修计划与消耗规律整理需求申报稿。**采购数量、定额与安全库存标准由物资部门审定，检修计划由计划员/设备管理部门确定**，本技能只出申报稿。

## 适用条件
- 用户说"报备件计划 / 下个月要什么备件 / 检修用的备件清单 / 备件申请表"，并给出（或即将给出）检修计划、历史消耗记录或设备台账。
- 覆盖两类需求来源：检修计划驱动（PM 工单/预留对应的备件）、周期消耗驱动（按历史消耗与安全库存推算）。
- 不适用：库存现状查询（spare-parts-inventory-query）；消耗规律的深度分析（spare-parts-consumption-analysis）；采购决策、供应商选择与定额审定。

## 前提条件
- 输入：一个或多个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），可含「检修计划」（SAP PM 工单组件/预留导出：订单号、订单描述、基本开始日期、物料、预留数量）、「历史消耗」（SAP MB51 物料凭证导出：物料、过账日期、数量、移动类型；262/202 冲销按负数抵减，101 收货等不计入）、「设备台账」「备件目录」，字段见 `references/input-spec.md`。多个文件含同名工作表时合并读取并提示。**脚本不读 PDF 与图片。**
- 必填信息：车间名称、需求周期（如 2026-Q4 或 2026-10）。可选：库存现状表（SAP MB52 导出，用于扣减在库量）、安全库存标准（再订货点）、在途采购信息、厂内采购提前期（`--lead-days`）与历史期数下限（`--min-periods`）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工推算需求量。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 备件库存MRO | `get_reservations` | `workshop`：车间（必带） | `--input`（目录 A） |
| 备件库存MRO | `get_material_movements` | `workshop`：车间（必带） | `--input`（目录 B） |
| 备件库存MRO | `get_inventory` | — | `--stock`、`--intransit`（目录 C） |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；表中目录字母相同的放同一个目录，不同字母分开放，把目录作为“交给脚本”一列的参数值。
2. `get_inventory`：一次返回「库存表」「在途采购」两个 csv，放同一目录，该目录同时作 `--stock` 和 `--intransit`。
3. 目录 A、B 用逗号拼接后作 `--input`。
4. `get_material_movements` 必须带 `workshop`：脚本的 `--workshop` 只写入报告标题、不筛选记录，不带会把其他车间的领用算进本车间需求。不要再加 `tag`、`query`、日期参数：脚本按全表过账日期确定 MB51 窗口（默认近 12 个月），窗口内无领用的月份按 0 计入期数（数量无法解析的月份剔除，不补 0），按位号或物料过滤后窗口变窄、无领用月会少计。
5. `get_reservations` 必须带 `workshop`（与 `--workshop` 同值）：工具按预留位号所在车间筛，不带会返回全厂未关闭工单的预留、混入别的车间，脚本不按车间过滤。只报某几台设备时可另加 `tag`（位号，逗号分隔）。交付前仍按「位号」核对计划需求各行是否属于本车间。
6. 计划需求按 `--period` 核对「基本开始日期」：晚于周期末的属后续周期，脚本单列 `planOutOfPeriod`、不计入本期；早于周期初而预留仍在的（工单未关闭、料未领）仍计入本期并 warning 提示核实；建议到货日早于今天的标「已过，请催办」（`arrivalPassed`）。

## 操作步骤
1. **确认需求周期与推算口径** —— 车间、周期、推算方式（仅按检修计划 / 仅按历史消耗 / 两者合并）；**口径不明确时必须确认，不同口径结果差异很大**。厂内采购提前期与期数下限有规定时一并问清，没有则用默认值并在产出中标注。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/demand.js" --input "<xlsx路径>[,<路径2>...]" --workshop "<车间名>" --period "<需求周期>" --out "<输入同目录>/备件需求"
   ```
   可选：`--stock "<库存现状xlsx>"`（扣减在库）、`--safety "<安全库存标准xlsx>"`、`--intransit "<在途采购xlsx>"`、`--method <plan|history|both>`、`--lookback <历史回溯月数，默认 12>`、`--months <需求周期月数>`（周期无法自动识别时显式给出）、`--lead-days <建议到货提前天数，默认 15>`、`--min-periods <历史期数下限，默认 6>`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺表/缺列/多文件合并/备件编码不一致/历史数据期数不足/冲销行/单位不统一等）。脚本用法详见 `scripts/README.md`。
   - 历史消耗数据期数不足（少于 `--min-periods`，默认 6 期）：该备件的推算量标 `lowConfidence` 并单列，**不得按不足的数据外推后当作正常需求**。
   - 备件编码或名称不一致导致无法归并：列入 `codeAmbiguity` 供用户确认，**不得自动合并不同编码的物料**。
   - 未提供库存表：需求量为毛需求，明确标注"未扣减在库量"，**不得默认库存为零而直接作为采购量**。
3. **读取 demand.json** —— 从 `<输出目录>/demand.json` 获取：`items`（逐项：备件编码、名称、规格、单位、需求量、来源依据、对应设备或项目、建议到货时间）、`netDemand`（计划毛需求 / 历史毛需求 / 合计，扣减库存与在途后的净需求）、`lowConfidence`、`codeAmbiguity`、`noHistory`（无历史无计划依据的项）、`unitConflicts`、`planOutOfPeriod`（基本开始日期晚于需求周期、未计入本期的计划需求）、`counts`、`meta`（含 `leadDays`、`minPeriods`、`mergedSources`、`periodRange`）。
4. **生成需求清单与申报表** —— 按 `assets/templates/demand-template.md` 成文，含：需求概况与口径说明、需求明细表、净需求表（毛需求分列）、低置信度项、编码待确认项、无依据项、申报说明。**每项需求必须注明依据（对应 PM 工单/项目编号或历史消耗期数），无依据的项不得出现在正式清单中，只能列入建议核实区。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `demand.md`、`demand.json` 与 `备件需求表.xlsx`。**必须保留说明行："本清单为车间申报稿，采购数量与定额以物资部门审定为准"。**

## 预期结果
- `demand.md`：备件需求申报稿，七节：一、需求概况与口径说明（含提前天数、期数下限、合并来源）；二、需求明细；三、净需求（未给库存表时为"毛需求汇总（未扣减在库量）"）；四、低置信度项；五、编码待确认项（含单位不一致）；六、无依据项；七、申报说明（分析段占位）。开头与末尾各一处说明行，有 warnings 时另有"附：数据提示"。
- `备件需求表.xlsx`：可直接提交的申报表（物料编码/物料描述/计划毛需求/历史毛需求/合计/在库/在途/净需求）；`demand.json`；`summary.json`。
- 交付时向用户说明：需求项数、净需求项数、低置信度项数、待确认编码数、采用的推算口径与参数（提前天数、期数下限）、脚本 warnings（如有）。

## 不适用范围
- 不做采购决策、供应商选择与价格谈判。
- 不审定备件定额与安全库存标准。
- 不替代物资部门的计划审核与库存策略。
- 不推荐替代型号（代用候选用 spare-parts-inventory-query）。
- 不读 PDF / 图片。

# scripts 使用说明

## demand.js —— 主脚本

```bash
node "<技能目录>/scripts/demand.js" \
  --input "<检修计划/历史消耗 xlsx>[,<路径2>...]" \
  --workshop "<车间名>" \
  --period "<需求周期>" \
  --out "<输出目录>"
```

### 参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--input` | 是 | 一个或多个 xlsx / CSV 目录，逗号分隔。在全部文件中查找「检修计划」（含「预留」「工单备件」）与「历史消耗」（含「物料凭证」「MB51」）表；**多个文件含同名表时合并读取并 warning**（不再只取第一个） |
| `--workshop` | 是 | 车间名称；检修计划、历史消耗表带车间列时按它核对车间范围 |
| `--period` | 是 | 需求周期，如 `2026-Q4`、`2026-10`、`2026-10~2026-12`、`2026`、`2026-H1`；同时解析出起止日期（`meta.periodRange`），检修计划需求按「基本开始日期」核对：晚于周期末的单列 `planOutOfPeriod` 不计入，早于周期初的仍计入并标 `startBeforePeriod`、warning；识别不了起止日期时不过滤并 warning |
| `--out` | 否 | 输出目录，默认第一个输入文件同目录下 `spd-out/`；**建议始终传 `--out`** |
| `--method` | 否 | `plan` / `history` / `both`，默认 `both` |
| `--lookback` | 否 | 历史回溯月数，默认 12 |
| `--months` | 否 | 显式指定需求周期月数，覆盖 `--period` 自动解析 |
| `--stock` | 否 | 库存现状表，扣减在库量。**不给则输出毛需求** |
| `--safety` | 否 | 安全库存标准表 |
| `--intransit` | 否 | 在途采购表，扣减在途量 |
| `--lead-days` | 否 | 建议到货提前天数（非负整数），默认 **15**；未显式给出时 md 口径说明标「默认值，厂内采购周期不同时用 --lead-days 调整」 |
| `--min-periods` | 否 | 历史消耗期数下限（正整数），默认 **6**；低于此值判 `lowConfidence`；未显式给出时 md 标「默认值」 |

### 产出

| 文件 | 内容 |
|---|---|
| `demand.json` | items / netDemand（含 `grossPlan`/`grossHistory`/`gross` 分列）/ lowConfidence / codeAmbiguity / noHistory / unitConflicts / counts / meta（含 `leadDays`、`minPeriods`、`mergedSources`、`workshopScope` 车间范围核对结果） |
| `demand.md` | 七节申报稿：概况与口径、需求明细、净需求、低置信度、编码待确认、无依据项、申报说明；口径说明写车间范围，车间列取值与 `--workshop` 全不一致时标题下写【注意】提示 |
| `备件需求表.xlsx` | 备件需求表（物料编码/物料描述/计划毛需求/历史毛需求/毛需求合计/在库/在途/净需求）、需求明细、低置信度项、编码待确认、无依据待核实 五个工作表 |
| `summary.json` | 末行摘要落盘 |

### 退出码
- `0`：成功（含「某类需求为空」，这是正常结果不是错误）
- `1`：失败（输入不存在、指定口径所需的表缺失、非法参数）

### 关键行为

1. **未给 `--stock` 就是毛需求**。净需求全部为 `null`，`counts.needPurchase` 为 `null` 不是 0，报告第三节标题改为「毛需求汇总（未扣减在库量）」并加粗警示「不得直接作为采购量」。
2. **期数不足单列**。历史消耗有效期数 < `--min-periods`（默认 6）期的备件进 `lowConfidence`，不进正式清单也不进净需求。
3. **编码不合并**。毛需求汇总 key 是 编码+单位，不是名称。同名多编码、同编码多名称一律进 `codeAmbiguity` 待确认。
4. **单位不换算**。同编码多单位分别统计；需求单位与库存单位不符时不扣减。
5. **依据必填**。缺项目编号或缺需求数量的项进 `noHistory`，正式清单每项都有 `basis`。
6. **缺数据不补零**。数量无法解析 → null（显示「—」），历史消耗中无法解析的期直接剔除，不按 0 摊薄月均。
7. **净需求为负置 0**，注明「库存充足，本期无需采购」。
8. **SAP 列名**：检修计划接 PM 工单/预留导出（订单号→项目编号、订单描述→项目名称、基本开始日期→计划开工、物料→备件编码、预留数量→需求数量、功能位置→位号）；历史消耗接 MB51（过账日期按月归并、「数量」作消耗数量、移动类型 261/201 发料计正、262/202 冲销计负、101/311 等不计入）；库存接 MB52（非限制使用库存、再订货点、库存地点）。**「数量」不作库存量别名，「设备编号」不作位号别名。**
9. **毛需求分列**：净需求表与申报表分「计划毛需求 / 历史毛需求 / 毛需求合计」三列。
10. **多文件合并**：同名工作表跨文件合并读取，同编码同月数量累加，warning 提示确认不是重复导出。
11. **MB51 无领用月按 0 计**：物料凭证只记发生的业务，导出窗口（全表过账日期的首月~末月，含 101 收货等不计消耗的行）内没有领用凭证的月份即当月未领用，按 0 计入期数，月均按窗口月数摊；窗口末月是运行当月（未满月）时该月不计入期数与月均，窗口只有当月时同样不计入、按历史不足处理（不算月均，warning 提示补充历史月份）；依据写「其中无领用月按 0 计 N 期」，`meta.mb51Window` 记录窗口。窗口内某月只有数量无法解析的行（如「两件」）时，该月不补 0、不计入期数，依据写「数量无法解析剔除 N 期」。汇总式「历史消耗」表（一行一个月）没列的月份仍不补 0。
12. **车间范围核对**：检修计划、历史消耗表（每个文件每张表各一次）带车间列（车间/所属车间/属地车间/运行部，或其后加「名称」；「车间负责人」等人员列不算）时按 `--workshop` 核对：剔除其他车间的行并 warning，车间为空的行保留；没有一行是本车间时不筛，warning 与报告开头写【注意】；无车间列不筛，口径写「以取数条件为准」；「维护工厂」不当车间列。`meta.workshopScope` 为数组，每张表一项：`sheet`、`status`（`noWorkshop`/`noColumn`/`checked`/`mismatch`）、`column`、`total`、`kept`、`droppedRows`、`dropped`（按车间的剔除行数）、`blank`。库存、安全库存、在途表按编码查找，不核对。

### 推算式

```
检修计划驱动：毛需求 = 计划需求数量（PM 预留数量）
              建议到货 = 计划开工日 − lead-days（默认 15 天）；早于今天时 arrivalPassed: true，md 标「已过，请催办」并 warning
              基本开始日期晚于需求周期末 → planOutOfPeriod 单列，不计入本期
历史消耗驱动：月均 = 最近 N 期消耗合计 ÷ 有效期数（MB51 窗口内无领用月按 0 期计入）
              毛需求 = 月均 × 需求周期月数 + 安全库存
净需求       = (计划毛需求 + 历史毛需求) − 在库 − 在途（负数置 0）
历史期数下限 = min-periods（默认 6 期）
```

口径细节见 `references/demand-rules.md`。

## make-sample.js

```bash
node scripts/make-sample.js [--seed <n>]
```

生成 `sample-demand.xlsx`（检修计划 8 行 + 历史消耗）、`sample-stock.xlsx`、`sample-intransit.xlsx`、`sample-safety.xlsx`、`sample-plan-only.xlsx`，以及 SAP 变体 `sample-sap-reservation.xlsx`（PM 工单预留导出）+ `sample-sap-mb51.xlsx`（MB51 物料凭证，含 262 冲销与 101 收货行），两者用逗号一起传给 `--input`。

seed 变数量变，但结论不变：2 项无依据、1 项低置信度、1 组编码待确认、1 项单位不一致、1 项库存充足。

## selftest.js

```bash
node scripts/selftest.js
```

240 条断言，覆盖：正常路径与推算式、期数不足单列（含 5/6 期边界）、MB51 只有当月数据按历史不足处理、编码不一致不合并、无库存表输出毛需求、依据必填、单位不换算、净需求公式与负值置 0、`--method` 三态、缺表缺列不中断、数值无法解析不按 0、参数校验、周期解析、别名列头与合计行、多输入文件、产出完整性，以及中石化口径：SAP PM 预留列名与 MB51 列名命中、过账日期按月归并、262 冲销按负数、101 收货不计、MB51 窗口内无领用月按 0 期计与当月未满月不计（汇总式消耗表不补 0）、数量无法解析的月份不补 0 并在依据中写明剔除期数、两文件同名表合并与 warning、毛需求分列（json/md/xlsx）、`--lead-days` 默认与覆盖、`--min-periods` 默认与覆盖、SAP 库存「数量」不作库存量、无 emoji、计划需求按需求周期过滤（周期外单列、早于周期仍计入并提示、无开始日期提示、周期识别不了不过滤）、建议到货日已过提示；P002 车间范围核对：检修计划两车间混合只留本车间、车间为空保留、历史消耗剔除其他车间、全不一致不筛并【注意】、无车间列口径说明、「维护工厂」不当车间列。

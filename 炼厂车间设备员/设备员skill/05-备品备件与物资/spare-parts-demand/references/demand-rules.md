# 需求推算口径与申报表述规范

所有数量由 `scripts/demand.js` 按本文口径算出并写入 `demand.json`。**模型只负责成文，不得凭经验调整数量、不得增补清单外的物料、不得把低置信度项或无依据项挪进正式清单。**

## 一、两类需求来源

### 1. 检修计划驱动

检修计划表中每个项目对应的备件清单**直接成为需求**，不做二次推算。

```
毛需求 = 检修计划中该项目的需求数量
依据   = 检修项目 <项目编号>（<项目名称>）
建议到货 = 计划开工日 − lead-days 天（默认 15，厂内采购提前期不同时用 --lead-days 调整；未显式给出时产出标「默认值」）
```

- **按需求周期核对基本开始日期（计划开工）**：`--period` 解析出起止日期后，晚于周期末的计划需求属后续周期，单列 `planOutOfPeriod`、不计入本期毛需求与净需求；早于周期初、但工单/预留尚未关闭（料未领出）的，仍是本期要备的料，计入本期并标 `startBeforePeriod`、warning 提示核实工单是否仍要执行；无开始日期的计入并 warning；周期识别不了起止日期时不过滤并 warning。
- **外车间预留不计入**：`get_reservations` 取数必须带 `workshop`（按预留位号所在车间筛）；导出文件仍混有外车间位号时，按位号剔除后重跑，不得计入本车间需求。
- 建议到货日早于今天的，`arrivalPassed: true`，明细标「已过，请催办」并 warning，成文时提醒尽快催办或与计划员确认开工日期。
- 同一备件被多个项目用到时，按编码+单位累加，依据里列出全部项目编号。
- **项目编号为空**或**需求数量为空/无法解析** → 该项无有效依据，进 `noHistory`，不入正式清单。

### 2. 历史消耗驱动

```
月均消耗 = 最近 N 期（N ≤ --lookback）消耗合计 ÷ 有效期数
毛需求   = 月均消耗 × 需求周期月数 + 安全库存
依据     = 历史消耗 <期数> 期（<起始月>~<结束月>）
```

- 有效期数只数「月份有值且消耗数量可解析」的期。**无法解析的期直接剔除，不按 0 计入分母摊薄月均。**
- MB51 物料凭证导出：过账日期按月归并；移动类型 261/201 等发料计正，262/202 等冲销按负数抵减当月，101 收货、311 转储等不计入消耗（各 warning 一次）。
- **MB51 无领用月按 0 计**：凭证表只记发生的业务，导出窗口（全表过账日期的首月~末月，含 101 收货等行）内某物料没有领用凭证的月份就是当月未领用，按 0 计入期数，月均按窗口月数摊（只数有领用的月会把一年领 3 次算成每月都领、月均放大数倍，也会把稀疏领用误判为期数不足）。窗口末月是运行当月、未满月时，该月不计入期数与月均；窗口只有当月时同样不计入，此时没有可用的历史月，按历史期数不足处理（不算月均、不给推算量，单列低置信度并提示补充此前月份的物料凭证）。依据写「其中无领用月按 0 计 N 期」。窗口内某月的领用行数量无法解析（如「两件」）时，该月不是「没领用」而是「领了但数不清」，不补 0、不计入期数，依据写「数量无法解析剔除 N 期」。汇总式「历史消耗」表（一行一个备件一个月）没列的月份可能是没统计，仍只数有值的期。
- 未提供 `--safety`、库存表也无安全库存列时，安全库存不加，推算式里写明「未提供安全库存标准，未加安全库存」。
- 需求周期月数由 `--period` 解析，无法识别时按 1 并 warning。

`--method both`（默认）时两类来源都算，同一编码+单位的毛需求相加，依据合并列出；净需求表与申报表把**计划毛需求、历史毛需求、合计**分列。

多个输入文件含同名工作表时合并读取（同编码同月数量累加）并 warning，不再只取第一个文件。

## 二、置信度判定（硬约束）

| 条件 | 归属 | 处理 |
|---|---|---|
| 历史消耗有效期数 ≥ min-periods（默认 6） | `items` 正式清单 | 正常推算 |
| 历史消耗有效期数 < min-periods | `lowConfidence` | **单列，不进正式清单，不进净需求**。给出参考推算量但注明「期数不足，仅供参考，未按不足的数据外推作为正常需求」 |
| 无项目编号 / 需求数量缺失 | `noHistory` | **单列建议核实区**，说明缺什么依据，请补齐后重新提报 |

期数下限默认 6（脚本 `DEFAULT_MIN_PERIODS`），`--min-periods` 可按厂内口径调整；未显式给出时产出标「默认值」。刚好等于下限进正式清单，少一期判低置信度。

**每项进入正式清单的需求都必须有 `basis` 字段**：检修项目编号，或历史消耗期数与月份区间。没有依据的项一律不进正式清单——这一条 selftest 有断言锁死。

## 三、编码归并（硬约束：绝不自动合并）

两类不一致均列入 `codeAmbiguity`，**脚本不做任何自动归并**：

| 类型 | 判定 | 处理 |
|---|---|---|
| 同名同规格多编码 | 名称+规格相同但编码不同 | 各编码的需求分别成行，提示「请确认是否为同一物料」 |
| 同编码多名称 | 同一编码在检修计划与历史消耗中名称不同 | 提示「请核对台账」 |

毛需求汇总的 key 是 **编码 + 单位**，不是名称。两个编码即便名称规格完全一样也各占一行，合并会让申报量翻倍。

## 四、单位处理（硬约束：绝不换算）

- 同一编码出现多种单位（个/套/台/片/组）→ 按单位**分别统计**，列入 `unitConflicts` 并 warning，**不做任何换算**（不假定 1 套 = N 个）。
- 需求单位与库存表单位不一致 → **不扣减在库量**，该项净需求为 null，注明「单位不一致，未做换算，未扣减在库量」。

## 五、库存扣减与净需求（硬约束）

```
净需求 = 毛需求 − 在库量 − 在途量
```

| 情形 | 净需求 | 表述 |
|---|---|---|
| 未提供 `--stock` | `null` | **「未提供库存表，本项为毛需求，未扣减在库量，不得直接作为采购量」**。报告第三节标题改为「毛需求汇总（未扣减在库量）」，`counts.needPurchase` 为 null 而非 0 |
| 库存表有该编码、库存量为空/无法解析 | `null` | 「库存量为空或无法解析，无法计算净需求，**未按库存为 0 处理**」 |
| 库存表无该编码 | 按在库 0 算 | 「库存表中无此编码，按未入库处理（在库 0），请核实是否漏登」，并 warning |
| 毛需求无法计算 | `null` | 「毛需求无法计算（数量缺失），未按 0 处理」 |
| 净需求计算结果 ≤ 0 | `0` | **「库存充足，本期无需采购」**，`sufficient: true` |
| 未提供 `--intransit` | 在途按 0 | 口径说明写明「未提供在途采购表，净需求未扣减在途量」 |

**最关键的一条**：没有库存表就绝不能把毛需求当采购量报上去。脚本全程标注，报告第三节顶部有加粗警示，xlsx 申报表第 3 行也写同样的话。

## 六、申报表述规范

| 场景 | 应写 | 不应写 |
|---|---|---|
| 无库存表 | 「毛需求 24 片，未扣减在库量，需物资部门按实际库存核减」 | 「需采购 24 片」 |
| 期数不足 | 「历史仅 3 期，推算量 7 组仅供参考，建议人工核定」 | 「月均 2.33，本季需 7 组」 |
| 多编码 | 「BJ-DP-0101 与 BJ-DP-0101B 名称规格相同，编码不同，未合并，请确认」 | 把两个编码的量加起来报一行 |
| 单位不一 | 「个：6.24；套：7.14，未换算」 | 「合计 13.38」 |
| 库存充足 | 「在库 6 个大于本期需求，库存充足，本期无需采购」 | 直接不列这一项 |
| 无依据 | 「BJ-FM-0201 缺项目编号，列入建议核实，未进正式清单」 | 按经验补个项目编号后报上去 |
| 净需求为 null | 「库存量未填，无法算净需求」 | 「净需求 = 毛需求」 |

## 七、必须保留的说明行

**「本清单为车间申报稿，采购数量与定额以物资部门审定为准」**

出现在三处，缺一不可：`demand.md` 抬头与结尾、`demand.json` 的 `meta.statement`、`备件需求表.xlsx` 第 2 行。

## 八、第七节「申报说明」怎么写

`demand.md` 第七节的 `<!-- ANALYSIS_START -->` / `<!-- ANALYSIS_END -->` 之间由模型补写，内容围绕：

1. 本期需求的主要构成（检修驱动占几项、周期消耗占几项、金额大项）。
2. 重点保障项（对应大修项目、长周期采购件、到货时间紧的）。
3. 需要物资部门重点关注的：低置信度项如何核定、待确认编码如何定版、无依据项谁来补。
4. 口径参数：采用的建议到货提前天数与期数下限是默认值还是厂内规定。
5. 口径限制的再声明（尤其未扣减在库量时）。

**数字一律引用上表，不得另行估算；不得在这一段里给出新的需求量。**

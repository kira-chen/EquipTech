# 消耗统计口径与表述规范

## 一、统计维度

| 维度 | 说明 |
|---|---|
| 按设备 | 按领用设备位号聚合。**位号为空的记录不参与**，单列「未归属消耗」 |
| 按备件 | 按备件编码聚合。未归属的量仍计入，保证总量不丢失 |
| 按月份 | 按出库日期的年月聚合 |
| 按设备类型 | 需提供 `--ledger`；未提供时该节为 null |

## 二、单位处理（硬规则）

**不同单位分别统计，绝不换算。**

炼化厂备件出库常见「套 / 个 / 台 / 片 / L / kg / 桶」混用。把 3 套和 20L 加成 23 是没有意义的数字，还会让后续的金额折算与趋势对比全部失真。

因此：
- 每个统计分组内按单位分行输出（`byUnit: [{unit, qty}]`）
- 报告中显示为 `12 套 / 38 L`
- 单位种类大于 1 时 warning 提示「已按单位分别统计，未做换算」

单位列为空时归入「（未填单位）」，同样单独成组。

## 三、数量缺失

数量为空或无法解析 → 该条记录的 `qty` 为 `null`，计入所在分组的 `unknownQty`，**不计入合计**。

**禁止**：按 0 计、按同类均值补、按 1 计。

报告中显示为 `12 套（2 条数量未填）`。

## 三之二、移动类型（SAP MB51）

出库记录带「移动类型」列时：261/201/221/281/291/601 发料计正；262/202/222/282/292/602 冲销按负数抵减当期数量与金额（错领退回不算消耗）；101 收货、311 转储等不计入消耗。各情形 warning 一次，`counts.reversals` 记录冲销条数。无此列时全部按消耗计。

## 四、金额折算

金额来源优先级：**本位币金额列 > 单价表 > 不折算**。

- 出库记录有「本位币金额」列：直接取用（冲销计负），不再乘单价；该列为空的记录再按单价表折算（有单价表时）
- 仅有单价表：按单价 × 数量折算；单价表中查不到的备件金额为 `null`，计入 `unpriced`
- 两者都无：全部金额为 `null`，报告写「未提供单价表且无本位币金额列，未折算」
- `meta.amountSource` 与 md 概览写明来源

**禁止**：使用估计单价、用同类备件单价代替、按历史均价推算。

## 五、未归属消耗（硬规则）

位号为空的出库记录单列一节，**既不平摊到其他设备，也不排除后当作完整统计**。

平摊会凭空制造出某台设备的消耗；排除会让报告里的总量小于实际领用量。两者都是失真。正确做法是如实列出，让设备员去补位号。

报告中列出前 20 条（编码、名称、数量、单位、日期、领用单位、行号），超出部分提示查 JSON。

## 六、异常增长识别

基期三种取法：`--prev` 上期 `consumption.json`；`--prev` 上期出库表 + `--prev-from/--prev-to`；或仅 `--prev-from/--prev-to` 在同一导出里切基期（首次使用拿不到上期 JSON 时用这个）。基期不得与本期重叠；md 异常节写明基期来源。

### 区间长度归一

两期统计区间天数不同时，**按日均归一后再比倍数**。

不归一会出现荒谬结果：本期统计 3 个月、上期统计 1 个月，即使消耗速率完全相同，倍数也会算成 3 倍而误报异常。

- 两期天数相同：直接比数量
- 两期天数不同：比日均（`数量 / 天数`），报告中额外显示日均列并注明
- 上期数据缺区间信息：按原始数量比对并 warning 说明未归一

### 判定阈值

默认 2 倍（`--anomaly-ratio` 可调，须大于 1）。只在**同一备件编码 + 同一单位**可比时判断。

基期没有该备件消耗、本期有消耗的（本期新出现），没有倍数可算，**不计入异常增长，但单列 `newInPeriod`** 并在异常节列出「基期无消耗、本期新出现的备件」，同样只提示核实方向、不断言原因；否则从 0 到有的增长会被静默漏掉。基期该编码有消耗、只是单位不同的（如基期按「片」、本期按「包」），**不算本期新出现**，单列 `unitMismatch` 并写「两期单位不同、不可比」，不换算、不计算倍数；只有基期完全没有该编码、或该编码在基期全部单位的数量都为 0，才算新出现。基期整段无记录时没有可比基期，都不列。

### 表述规范（硬规则）

异常增长**只是统计结果**，不是原因结论。

| 应写 | 不得写 |
|---|---|
| 「本期消耗达到上期 3.2 倍」 | 「消耗异常偏高」 |
| 「建议核实是否与某次检修、重复故障或统计口径变化相关」 | 「说明该设备可靠性下降」 |
| 「本技能不断言原因」 | 「原因是机封选型不当」 |

消耗增长的常见合理原因：计划检修集中在本期、统计口径变化、一次性备货领用、设备台数增加。这些都不是问题。**断言原因需要设备员结合实际情况判断，脚本给不出。**

## 七、分析段表述规范

撰写 250~400 字，五段结构：

1. **总体情况**：记录条数、备件种类、涉及设备、金额（折算时）
2. **消耗集中的设备与备件**：排行前几位，只陈述数字
3. **异常增长项与建议核实的方向**：列出倍数，提示可能需要核实的方向，**不断言原因**
4. **未归属消耗**：条数与占比，建议补位号
5. **建议跟进事项**：如消耗集中的设备建议接 `repeat-failure-detector` 做重复故障核查

### 硬约束

- 数量、倍数、金额一律引用 `consumption.json`
- 不断言消耗异常的原因
- 不判定是否存在浪费或管理问题
- 不做财务成本核算与预算建议
- 不评价设备可靠性水平

## 八、下游衔接

消耗异常的设备建议接 `repeat-failure-detector` 核查是否存在重复故障；备件缺口建议接 `spare-parts-demand` 提报需求。

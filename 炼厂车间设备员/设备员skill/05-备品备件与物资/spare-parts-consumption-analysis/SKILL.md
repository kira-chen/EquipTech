# 备件消耗分析（spare-parts-consumption-analysis）

面向中石化体系炼化厂车间（运行部）设备员，从出库/领用记录统计备件消耗分布，识别消耗异常增长的设备与备件，为可靠性改进提供线索。**统计与异常判定由脚本完成，模型只负责解读；不得手工统计或断言消耗异常的原因。**

车间设备员可做的部分：消耗统计、异常线索提出、补位号与核实。**费用核算、预算与定额调整由物资与财务部门归口，可靠性结论由设备工程师基于多方数据得出。**

## 适用条件
- 用户说"备件消耗统计 / 哪台设备最费备件 / 消耗是不是异常 / 同比环比看一下 / 备件用量分析 / 花了多少钱"，并给出（或即将给出）出库或领用记录。
- 支持三个统计维度：按设备、按备件品类、按时间（月度/季度趋势）；支持 SAP MB51 物料凭证（移动类型 261/201 发料计正、262/202 冲销按负数抵减、101 收货等不计入）。
- 不适用：备件需求提报（spare-parts-demand）；库存现状查询（spare-parts-inventory-query）；财务成本核算与预算编制。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含「出库记录」或「物料凭证」（MB51），字段见 `references/input-spec.md`（过账日期/出库日期、物料/备件编码、物料描述、数量、基本计量单位、功能位置/位号、成本中心/领用单位、用途、订单/工单号、移动类型、本位币金额）。可选：单价表（无本位币金额列时折算）、基期数据（上期 `consumption.json`、上期出库表，或同一导出里指定基期起止）、设备台账（按设备类型归类）。**脚本不读 PDF 与图片。**
- 必填信息：车间名称、统计区间（起止日期）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得手工统计消耗。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 备件库存MRO | `get_material_movements` | `workshop`：车间（必带）；`start_date`：统计起始日，与 `--from` 相同（如近 90 天）；要和基期比时取基期起始日，与 `--prev-from` 相同 | `--input` |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；把目录作为“交给脚本”一列的参数值。
2. `workshop` 必须带：脚本的 `--workshop` 只写入报告标题、不筛选记录，不带会把其他车间的领用混进本车间统计。工具最多返回近 12 个月。
3. 和上一期比：一次取到基期起始日，用 `--prev-from`/`--prev-to` 在同一导出里切基期（基期不得与本期重叠）。

## 操作步骤
1. **确认统计区间与维度** —— 车间、起止日期、统计维度、是否折算金额、基期怎么取；**既无本位币金额列也无单价表时不折算金额，不得使用估计单价**。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/consumption.js" --input "<xlsx路径>" --workshop "<车间名>" --from <YYYY-MM-DD> --to <YYYY-MM-DD> --out "<输入同目录>/消耗分析"
   ```
   可选：`--price "<单价表xlsx>"`、`--prev "<上期 consumption.json 或上期出库xlsx>"`、`--prev-from <基期起> --prev-to <基期止>`（`--prev` 为出库表时必填；只给这两个参数则在同一导出里切基期）、`--ledger "<设备台账xlsx>"`、`--by <equipment|part|month>`、`--top <排行条数>`、`--anomaly-ratio <异常增长倍数阈值，默认 2>`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺列/位号缺失/单位不一致/冲销与收货行处理/金额来源/日期超出区间等）。脚本用法详见 `scripts/README.md`。
   - 领用设备位号为空：归入 `unattributed`（未归属）单列一节，**绝不平摊到其他设备，也不得排除后当作完整统计**。
   - 单位不一致（个/套/台混用）：warning 并按单位分别统计，**不得强行换算**。
   - 有「本位币金额」列直接取用（冲销按负数），不再乘单价；单价表只补金额列为空的记录。
3. **读取 consumption.json** —— 从 `<输出目录>/consumption.json` 获取：`byEquipment`（按设备：消耗项数、数量、金额、占比）、`byPart`（按备件品类）、`byMonth`（时间分布）、`byType`（有台账时）、`topConsumers`（消耗排行）、`anomalies`（异常增长项：本期与基期对比、增长倍数）、`newInPeriod`（基期无消耗、本期新出现的备件，无倍数，不计入异常）、`unitMismatch`（基期有消耗但两期单位不同、不可比，不算新出现）、`unattributed`、`compare`（基期来源与区间）、`counts`（含 `reversals` 冲销条数）、`meta.amountSource`。
4. **撰写"消耗分析"** —— 读 `references/analysis-rules.md` 的表述口径，撰写 250~400 字，按"总体情况 → 消耗集中的设备与备件 → 异常增长项与可能关联（仅提示需核实的方向）→ 未归属消耗 → 建议跟进事项"结构，替换 `consumption.md` 中 `<!-- ANALYSIS_START -->` 与 `<!-- ANALYSIS_END -->` 之间的占位文字。**数量、金额、倍数一律引用 consumption.json；异常增长只提示"建议核实是否与某次检修或重复故障相关"，不得断言原因。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后交付 `consumption.md`、`consumption.json` 与 `消耗统计表.xlsx`。消耗异常设备建议接 `repeat-failure-detector` 做重复故障核查。

## 预期结果
- `consumption.md`：消耗分析报告，八节（有台账时九节）：一、统计概览（含金额来源、冲销条数）；二、按设备分布；三、按备件分布；四、时间分布；（五、按设备类型，仅有台账时）；五/六、消耗排行；六/七、异常增长项（写明基期来源）；七/八、未归属消耗；八/九、消耗分析（分析段占位）。有 warnings 时另有"附：数据提示"。
- `消耗统计表.xlsx`：按设备 / 按备件 / 按月份 / 未归属四张表；`consumption.json`；`summary.json`。
- 交付时向用户说明：统计区间、消耗总项数与金额（折算时，说明来源）、冲销条数、异常项数与基期、未归属项数、脚本 warnings（如有）。

## 不适用范围
- 不断言消耗异常的原因，不判定是否存在浪费或管理问题。
- 不做财务成本核算、预算编制与费用分摊。
- 不评价设备可靠性水平（可靠性结论由工程师基于多方数据得出）。
- 不做备件定额的调整建议。
- 不读 PDF / 图片。

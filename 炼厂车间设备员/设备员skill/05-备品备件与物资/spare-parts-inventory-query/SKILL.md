# 备件库存查询与代用提示（spare-parts-inventory-query）

面向中石化体系炼化厂车间（运行部）设备员，快速查询备件库存与在途情况，并在无库存时列出同规格候选项。**库存数据一律来自所提供文件（SAP MM / EM 导出）；代用可行性由设备工程师或技术人员判定，模型只列候选与需确认的技术要点，不得给出"可以代用"的结论。**

车间设备员可做的部分：查库存、查在途、按位号找对应备件、把候选和差异摆给技术人员看。**代用审批、出库与采购决策由设备工程师、物资部门按厂内制度归口。**

## 适用条件
- 用户说"这个备件有库存吗 / 库里还剩几个 / 能不能用别的型号代 / 在途什么时候到 / 放在哪个库 / 这台泵有哪些备件"，并提供库存表。
- 支持三类查询：按物料号/备件编码、名称或规格查库存；**按设备位号（功能位置）查对应备件**（"按位号查备件"归口本技能，equipment-ledger-query 的 `--spare` 已停用并指向本技能）；无库存时查同规格候选。
- 不适用：设备台账参数查询（equipment-ledger-query）；备件需求的提报（spare-parts-demand）；消耗规律分析（spare-parts-consumption-analysis）；代用可行性的技术判定与审批。

## 前提条件
- 输入：一个 `.xlsx`（或同结构 CSV 目录，UTF-8 或 GBK），含「库存表」（SAP MB52/MMBE 导出的「库存」表亦可），字段见 `references/input-spec.md`（物料/备件编码、物料描述/名称、规格型号、基本计量单位、非限制使用库存/库存量、再订货点/安全库存、库存地点/库位、状态、位号）。可选：在途采购表、备件设备对应表（SAP 导出通常无位号列，按位号查时需要）、备件目录（含技术参数）。**脚本不读 PDF 与图片。**
- 必填信息：查询内容（编码、名称、规格或设备位号）。
- 环境：可执行 Node.js ≥ 18，脚本仅用内置模块，无需 npm 安装。**若环境无法执行 node（无 Bash 工具或 `node --version` 失败），明确告知用户并终止，不得凭印象回答库存数量。**

## 数据获取（MCP）

平台接入了业务系统 MCP 服务时，按下表调用工具取数，不再请用户上传导出文件；未接入时按操作步骤请用户提供系统导出文件。工具全部只读，不在业务系统里创建或修改任何单据。

| 服务 | 工具 | 参数 | 交给脚本 |
|---|---|---|---|
| 备件库存MRO | `get_inventory` | — | `--input`、`--intransit`（目录 A） |
| 备件库存MRO | `get_material_substitutes` | — | `--catalog`（目录 B） |

取数后：

1. 工具返回下载链接（60 分钟内有效，过期重新调用）。csv 按原文件名放进新建的空目录，不改文件名，不与其他技能的文件混放；表中目录字母相同的放同一个目录，不同字母分开放，把目录作为“交给脚本”一列的参数值。
2. `get_inventory`：一次返回「库存表」「在途采购」两个 csv，放同一目录，该目录同时作 `--input` 和 `--intransit`。
3. `get_material_substitutes`：备件目录，配合 `--alternatives` 给出代用候选。

## 操作步骤
1. **确认查询对象** —— 物料号/备件编码、名称、规格或设备位号；**名称模糊时（如"机封"）先列出候选再确认，不得自行选定一个返回**。用户问的是设备本身的型号、参数、检修历史时转 equipment-ledger-query。
2. **运行脚本** —— 技能目录以平台实际加载路径为准（Windows 路径加双引号）：
   ```bash
   node "<技能目录绝对路径>/scripts/inventory.js" --input "<库存xlsx>" --query "<编码或名称或规格>" --out "<工作目录>/库存查询"
   ```
   可选：`--tag "<设备位号>"`（按设备查备件，与 `--query` 二选一）、`--mapping "<备件设备对应表xlsx>"`（SAP 导出无位号列时配合 `--tag`）、`--intransit "<在途采购xlsx>"`、`--catalog "<备件目录xlsx>"`（扩大同规格候选范围）、`--alternatives`（启用代用候选检索）、`--fuzzy`（模糊匹配名称）、`--limit <n>`。
   读取末行 JSON 摘要（同时写入 `<out>/summary.json`）：`ok` 必须为 `true`，`ok:false` 时把 `error` 告知用户并终止；`warnings` 非空时逐条告知用户（缺列/编码不存在/同名多编码/库存为负/对应表中的物料无库存记录等）。脚本用法详见 `scripts/README.md`。
   - 查询无结果：明确回答"库存表中未查到"，**不得放宽条件返回近似型号而不说明，也不得声称"应该有"**。
   - 同名不同编码：全部列出并提示用户按编码确认，**不得合并库存量**。
   - SAP 导出的「数量」列不是库存量（脚本不读作库存）；库存量以「非限制使用库存」为准。
3. **读取 inventory.json** —— 从 `<输出目录>/inventory.json` 获取：`matches`（命中备件：编码、名称、规格、库存量、安全库存、库位、状态）、`belowSafety`（低于安全库存/再订货点）、`safetyUndetermined`（无法判定）、`inTransit`（在途信息：数量、预计到货、采购订单号 `po`，在途表无采购订单列时为 null）、`alternatives`（同规格候选项及参数差异；所查件无库存时有库存候选置顶）、`ambiguous`（同名多编码）、`meta.tagSource`（按位号查的匹配依据）、`counts`。
4. **组织回答** —— 按 `assets/templates/inventory-answer-template.md` 组织。库存查询：给出数量、库位、是否低于安全库存、在途情况。按位号查：说明匹配依据（库存表位号列 / 备件设备对应表）。代用查询：列出候选项并逐项列出**参数差异**与**需技术确认的要点**（材质、压力等级、温度范围、接口尺寸、精度）。**必须写明"代用是否可行须由设备工程师或技术人员确认"，不得给出可否代用的结论。**
5. **交付前自检** —— 对照 `references/checklist.md` 逐项检查；通过后回答用户，必要时输出 `inventory.xlsx`。**必须说明："库存数据来自所提供文件，实物数量以仓库实盘为准"。**

## 预期结果
- 直接回答用户问题（对话形式），附库存明细与代用候选表；`inventory.md` 五节：一、查询结果；二、低于安全库存（含无法判定）；三、在途情况；四、同规格候选（代用参考）；五、同名多编码待确认；末尾声明行与互指说明，有 warnings 时另有"附：数据提示"。必要时输出 `inventory.json` / `inventory.xlsx`。
- 回答中说明：命中项数、低于安全库存项、在途情况、代用候选数与需确认要点、脚本 warnings（如有）。

## 不适用范围
- 不判定代用是否可行，不推荐具体替代型号作为结论。
- 不做出库、锁定、预留等库存操作。
- 不保证数据与仓库实物一致（以实盘为准）。
- 不做采购与调拨决策。
- 不查设备台账参数（用 equipment-ledger-query）。

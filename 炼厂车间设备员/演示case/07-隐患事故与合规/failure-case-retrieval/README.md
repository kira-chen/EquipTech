# 故障案例检索（failure-case-retrieval）· 演示与回归样例

> 本目录为技能 `failure-case-retrieval` 的演示与回归样例，不进发布包；开发包（`build.sh --with-examples`）中位于技能目录 `examples/`。
> 全部样例由 `node scripts/make-sample.js` 再生，数值随 seed 变化但结论不变。
> **案例内容全部虚构**，不对应任何真实事件。

## 关键验证点

1. **无案例库即不可用（最关键）**：例 7、例 8 两条路径均 `ok:false` + `exit 1`，`error` 中带「本技能不可用」与「不得用通用知识」。收到后唯一正确的回答是告知用户并终止，**不得降级为通用知识问答，也不得"通用知识 + 免责声明"折中**。
2. **命中为空不补位**：例 5 中 `counts.matches` 为 0、`matches` 为空数组，5 条未达标案例全部落在 `lowSimilarity`，一条都没被提上来。`cases.md` 原样写出「案例库中未检索到类似案例」并说明「不降低标准返回不相关案例，也不以通用知识补充」。
3. **低相似度只能当背景**：例 1 的 12 条低分案例单独成节（最多呈现 `--top` 条），每条带 `note: "相似度较低，仅供参考"`，md 中写明「不得作为主要参考」。
4. **匹配依据 + 不同点齐全**：每条案例（含低相似度）都有 `matchBasis` 与 `differences`。例 3 未给 `--part`，每条 `differences` 中出现「未提供当前故障部位，部位维度未参与比对」；`meta.weights` 显示 text 0.647 / type 0.353 / part 0。
5. **相似度靠类型撑起来的要点破**：分数在 0.3~0.45 区间、文本项低于 0.3 的案例，`differences` 中带「现象描述用词重合度低，文本相似主要不成立」。
6. **两行声明**：任何一次成功运行（含命中为空）的 `cases.md` 都在抬头原样写出「案例中的原因是当时该案例的结论，不代表当前故障的原因；是否适用须结合当前设备实际情况判断。」与通用声明行。
7. **机型不混淆**：「离心压缩机」「往复压缩机」「螺杆压缩机」「汽轮机」「挤压造粒机」归一后互不相同，例 5 因此不会误把离心压缩机轴承案例算作同类，例 12 不会拿离心泵轴承案例充数。
8. **SAP 列名与代码**：例 9 中「功能位置」归位号、「设备」归设备编号、「描述」归现象、「损坏代码」归故障代码；代码相同只影响排序、不改相似度，代码相同但设备类型不同且低于下限的案例仍留在低相似度节。
9. **PDF 不读**：例 14 直接报错并指路平台 pdf 技能，脚本不会声称读到 PDF 内容。

## 再生样例

```bash
node scripts/make-sample.js            # 默认 seed=1
node scripts/make-sample.js --seed 7   # 数值变化，结论不变
```

seed 1 / 7 / 42 实测：例 1 恒为 4 命中 / 12 低分 / 16 条可检索，例 5 恒为 0 命中，例 9 恒为 2 命中 / 2 代码相同。

## MCP 取数对照

平台接入业务系统 MCP 时不用附件：按 SKILL.md「数据获取（MCP）」调用工具，csv 放进新建的空目录 A，作 `--cases A`。`equip_type` 按设备台账的设备类型原样填写（离心泵、往复压缩机、换热器、调节阀……），工具按原值精确筛选。演示数据每天按剧本刷新，预期结果只列每天稳定的结论。

| # | 示例问题 | MCP 调用 | 运行参数 | 预期结果 |
|---|---|---|---|---|
| M1 | P-2101A 驱动端振动大、轴承箱异响，本厂离心泵有没有类似案例 | 设备资产管理 `get_failure_history`（equip_type=离心泵，for_skill=failure-case-retrieval）→ A | `--cases A --symptom "驱动端振动大，轴承箱有异响" --equip-type 离心泵 --part 轴承` | 工作表「历史故障」读入，无 warning；返回 5 条命中，首条为 P-2101A 自身的历史通知单 10045502（驱动端振动大，轴承箱有杂音，相似度 0.90，当时更换驱动端轴承）；其余为其他离心泵驱动端轴承箱案例，`differences` 带「现象描述用词重合度低」；位号与设备编号分列 |

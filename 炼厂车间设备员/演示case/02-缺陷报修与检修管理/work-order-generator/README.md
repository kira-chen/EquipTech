## 关键验证点

1. **不自编工单号/通知单号**：产出中没有 `GD-YYYYMMDD-NNN` 之类编号，CSV「通知单号(SAP生成)」列留空，只有草稿序号 1..N。`--prefix`/`--order-ledger` 已废止，传入报错。
2. **位号查不到台账不猜型号**：`sample-defects` 中 P-2103A 不在 `sample-equip-ledger` 里，即使设备名写着「急冷油泵A」，设备编号、规格型号、安装位置、投用日期一律 `null`，md 显示「待补充」，并列入信息缺口清单。
3. **SAP 列名直读**：台账的 功能位置→位号、设备→设备编号（不当位号）、设备描述→设备名称、型号编号→规格型号、工厂区段→安装位置、专业类别→专业、开始日期→投用日期；历史记录的 订单→原订单号、基本开始日期→维修日期、订单描述→维修内容、主工作中心→承修单位。
4. **无历史记录不编履历**：I-2501 在 `sample-repair-history` 中无记录，章节写「历史维修记录中无位号「I-2501」的记录」；完全不给 `--history` 时写「未提供历史维修记录」。
5. **近 N 次截断**：P-2101A 有 4 条历史记录，默认只展示最近 3 次并注明「共 4 条，展示近 3 次」；`--history-n 2` 可改为 2 次。
6. **优先级不默认**：`sample-no-level` 无等级列且不给 `--priority`，优先级判未判定（PU1），通知单类型随之未判定（NU1），单列在「信息缺口清单 → 未判定项」，不按「3 中」/M1 蒙混过去。
7. **工时与备件不给数值**：JSON 的 `dispatch.laborHours`/`dispatch.spare` 恒为 `null`，md 只写「工时由承修单位在工单（订单）中填写」「备件由承修单位按台账与备件库确定」。
8. **说明行与声明行**：`notifications.md` 开头有通用声明行，首尾各一处「本通知单草稿由车间设备员核对后在 SAP 中创建，通知单号由系统生成……」；不含 emoji，提示用「【注意】」「【未判定】」。

## 再生样例

```bash
node scripts/make-sample.js            # seed=1
node scripts/make-sample.js --seed 9   # 滴数、工作中心变化；草稿数、专业分布、边界命中不变
```

## MCP 取数对照

> 平台接入设备资产管理 MCP 时不上传附件：`get_notifications` → 目录 A（`--input`），`get_equipment_ledger` → 目录 B（`--ledger`），`get_failure_history`（输出表名「维修记录」）→ 目录 C（`--history`）。单条缺陷用 `--defect` 文字描述配 `--tag`，台账与维修记录按 `tag` 取；批量时三个工具都带 `workshop`。

| # | 示例问题 | MCP 调用 | 运行参数 | 预期结果 |
|---|---|---|---|---|
| M1 | P-2101A 驱动端振动大、轴承箱异响，出通知单草稿并带台账和维修记录 | 设备资产管理 `get_equipment_ledger`（tag=P-2101A）→ 目录 B；`get_failure_history`（for_skill=work-order-generator，tag=P-2101A）→ 目录 C | `--defect "P-2101A 进料泵驱动端振动明显变大，轴承箱有异响" --tag P-2101A --applicant 常减压车间 --due <月底> --ledger <目录B> --history <目录C>` | 1 张草稿；带出设备编号 10002100、规格型号 OH2 150-400、安装位置 1#常减压装置机泵区、投用日期 2016-02-24；历史维修 2 条（更换机械密封、更换驱动端轴承复查对中），带原工单号；现象识别为振动、专业动设备；未给等级与优先级 → 优先级与通知单类型未判定，不按「3 中」默认 |

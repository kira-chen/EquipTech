## 关键验证点

1. **累计 = 期初累计 + 本期增量**：阈值表「期初累计小时」列给上次大检修后累计；缺列时累计仅为本期增量并在概览【注意】与 warning 明示。
2. **三类阈值分开判**：运行小时（`24000h`）、启停次数、日历周期（`3年` 按自然月算到期日）；同一机组两个维度各列一条。
3. **阈值类型为空不默认**：案例 3 进未判定，不按运行小时猜。
4. **不配对不补停机**：案例 2 与案例 7 的末条运行都不按截止时间补。
5. **重叠不去重**：P-1102B 两段重叠原样累加并提示核实。
6. **停机间隔不误报**：M-1501 两段之间 3 天正常停机不报缺口。
7. **SAP 列名**：功能位置是位号，「设备」是流水号不是位号。
8. **车间范围核对（D007）**：本目录样例都不含车间列，各对照行结果与加核对前一致（2026-11-05 逐行复跑核对）；报告口径处多一行「车间范围：输入未含车间列，车间范围以取数条件为准。」，输出 JSON 的 `meta.workshopScope` 各表 `status` 为 `noColumn`。

## 再生样例

```bash
node scripts/make-sample.js            # seed=1
node scripts/make-sample.js --seed 4   # 时刻与期初累计变化，超阈值/临期/未判定计数不变
```

## MCP 取数对照

平台接入业务系统 MCP 时不用附件：按 SKILL.md「数据获取（MCP）」调用 `get_run_events` 和 `get_maintenance_plans`（两者都传 `workshop`），csv 放进同一个空目录作 `--input`，`--date` 用当天；DCS 启停记录里停机时间为空表示仍在运行，加 `--running-until "<DCS 数据截止时刻>"`（不是取数时刻；演示数据截至当天 09:00）。演示数据每天按剧本刷新，预期结果只列每天稳定的结论。

| # | 示例问题 | MCP 调用 | 运行参数 | 预期结果 |
|---|---|---|---|---|
| M1 | 常减压车间累计运行小时，哪些超 8000h、哪些快到，在运的算到现在 | DCS位号数据 `get_run_events`（workshop=常减压车间）+ 设备资产管理 `get_maintenance_plans`（workshop=常减压车间，for_skill=runtime-hours-tracker）→ 同一目录 | `--input <目录> --workshop 常减压车间 --date <今天> --running-until "<今天> 09:00"` | 阈值表内设备全部列出且全部带期初累计（本期无启停记录的备机如 P-2101B 也列出，注明「本期无运行记录」，本期 0h、累计 = 期初值）；P-2101A 自上次大检修累计超 8000h 阈值（在运段计到 DCS 数据截止时刻）；如 P-3102A 进超阈值或接近阈值清单，按清单所列表述，不写死；在运设备由 warning 一次点名；无未判定、无不配对。不加 `--running-until` 时在运设备的当前运行段单列不配对、运行小时阈值判未判定，P-2101A 的超阈值会漏掉 |
| M2 | 加氢车间运行小时，哪些接近大修周期 | DCS位号数据 `get_run_events`（workshop=加氢车间）+ 设备资产管理 `get_maintenance_plans`（workshop=加氢车间，for_skill=runtime-hours-tracker）→ 同一目录 | `--input <目录> --workshop 加氢车间 --date <今天> --running-until "<今天> 09:00"` | 阈值表内设备全部列出且全部带期初累计；无未判定、无不配对；如有超阈值或接近阈值设备（如 C-5302B、P-5201A、P-5101A），按 runtime.json 的 exceeded / dueSoon 清单列出，集合随剧本日变化，不写死 |

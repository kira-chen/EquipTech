## 三、已定的技术方案

| 项 | 决定 | 理由 |
|---|---|---|
| 语言 | Node.js（LTS），用 `@modelcontextprotocol/sdk` 和 `zod` | 本机已有的技术栈。npm 依赖只用在 MCPServer 里，技能仍然零依赖 |
| 进程 | 一个进程挂 6 个端点：`/mcp/eam`、`/mcp/dcs`、`/mcp/inspection-app`、`/mcp/work-permit`、`/mcp/mro`、`/mcp/hse` | 对客户端来说是 6 个独立的 MCP Server，部署和运维只需要一个容器 |
| 传输 | 主用 Streamable HTTP，同时保留旧版 SSE 端点 | 兼容只支持 SSE 的平台 |
| 鉴权 | `Authorization: Bearer <token>`，兼容 `?key=` 查询参数 | 服务挂在公网，必须鉴权。有的平台只能在 URL 里带 key。token 从环境变量读取，不入库 |
| 数据 | 用固定随机种子在启动时生成，日期相对当天计算 | 演示时数据始终是“当前”状态，比如超期、临期这些判断不会因为日期过去而失效。同一个种子每次生成相同的数据 |
| 返回 | 每个数据工具返回三样东西：摘要文本（行数、列名、前 20 行）、CSV 全文（不超过 500 行时内联）、带时效 token 的 CSV 下载链接 `/files/<id>.csv` | 技能脚本只能读文件，平台 Agent 拿到链接或 CSV 后写成文件，再传给 `--input` |
| 只读 | 不提供任何写工具 | 见清单统一约定第 8 条 |
| 健康检查 | `GET /healthz` | 供部署和监控使用 |

建议的目录结构（实现时可以调整，但要在 MCPServer/README.md 里写清楚）：

```text
MCPServer/
├── README.md            # 启动、配置、端点、接入方法
├── package.json
├── src/
│   ├── server.js        # HTTP、鉴权、端点路由
│   ├── systems/         # 6 个系统，每个系统一个文件，注册各自的工具
│   ├── data/            # 种子数据生成：位号主数据先行，各系统共用
│   └── export.js        # CSV 生成和下载链接
├── test/                # 工具单测和技能端到端验收脚本
├── Dockerfile
└── docker-compose.yml
```

## 四、Mock 数据要求

1. **一套共用位号。** 先生成一个虚构车间的设备主数据，包括装置、单元、功能位置和位号，6 个系统都引用它。规模建议是 2 到 3 套装置、60 到 100 台设备，覆盖机泵、换热器、塔器、容器、压缩机、电机、安全阀和仪表。
2. **示例问题要用到的设备必须存在：** P-2101A 进料泵（离心泵，介质柴油，常减压车间）、E-1201 换热器（介质柴油）。P-2101A 要有近期振动上升的 DCS 历史数据和巡检记录。
3. **历史深度：** 工单和通知单覆盖近 12 个月。DCS 历史值至少 30 天，每小时一个点，要包含一段超限过程。
4. **口径：** 按清单第十节执行，包括 CLSD 和 TECO、A/B/C 分级、SAP 优先级 1~4、中文列名、保留少量脏数据。
5. **全部虚构。** 不使用真实企业名、人名、手机号或证件号。

## 六、阿里云部署

**已定方案：**

| 项 | 做法 |
|---|---|
| 部署形态 | ECS（或轻量应用服务器）+ Docker Compose |
| 镜像 | 在本机构建：本机是 Apple Silicon，要用 `--platform linux/amd64`。用 `docker save` 打包，`scp` 到服务器后 `docker load`，避免服务器访问 Docker Hub 不稳定的问题 |
| 反向代理 | 用 Caddy 容器做 HTTPS（自动申请证书），反代到 Node 服务 |
| 密钥 | token 放在服务器的 `.env` 里，不入库，也不写进任务书或聊天 |

**开工时要先向用户确认这几件事（未确认前只做本地开发）：**

1. 是否已有 ECS，以及它的地域、公网 IP，本机的 SSH 登录方式。
2. 地域和域名：
   - 中国内地服务器用域名提供 HTTPS 服务，需要已经 ICP 备案的域名；
   - 没有备案域名的话，建议用中国香港地域。
3. 接入方是哪个平台，以及它支持 Streamable HTTP 还是只支持 SSE、怎么填写鉴权信息。
4. 公网开放范围：对所有人开放并靠 token 鉴权，还是另外限制来源 IP。

下面这些操作执行前要逐一说明确认点并征得同意：服务器上的 SSH 操作、开放安全组端口、申请证书、写入 `.env`。

## 七、验收标准

1. **工具齐全：** 6 个端点合计 45 个工具，名称和返回字段与清单一致。
2. **鉴权：** 不带 token 返回 401，token 错误返回 401。
3. **技能端到端（最重要）：** 对用到 MCP 的 37 个技能逐个验收：
   - 先用工具导出 CSV；
   - 再用技能的主脚本 `--input` 跑一遍；
   - 不能出现列名识别失败；
   - 关键数字要与 mock 数据的真实值一致，比如待处理缺陷数、超期工单数、到期检验数；
   - 用脚本完成，验收结果写进 `MCPServer/README.md`。

   这一条是为了防止 Onto-Demo 实测时出现的问题重演：字段码没有被识别，日报把 5 条未处理缺陷算成了 91 条，TECO 被误算成超期。
4. **公网：** 部署后用 MCP Inspector（`npx @modelcontextprotocol/inspector`）连上公网地址，列出全部工具并逐个调用成功；下载链接过期后不能再访问。
5. **示例问题：** 岗位配置里的 3 个示例问题，在平台上接入 MCP 后能取到对应数据。

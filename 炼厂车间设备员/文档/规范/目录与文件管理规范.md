# 设备员skill 目录与文件管理规范

适用于 `炼厂车间设备员/设备员skill/` 下的所有内容，所有成员和 AI 助手都要遵守。

核心规则：**`设备员skill/` 只放技能本身。与运行、验证、上架某个技能无关的文件，一律不进这个目录。**

## 一、目录结构

只允许以下结构，不在表内的文件和目录都不能新增。

| 层级 | 允许的内容 |
|---|---|
| `设备员skill/` | 8 个 `0N-分类名/` 目录，`README.md` |
| `0N-分类名/` | 技能目录，`README.md` |
| `<技能目录>/` | `SKILL.md`、`上架信息.md`、`样例问题.md`、`scripts/`、`references/`、`assets/` |

技能目录内部的规定：

| 位置 | 放什么 | 要求 |
|---|---|---|
| `SKILL.md` | 技能定义 | frontmatter 的 `name` 必须与目录名一致 |
| `上架信息.md` | 技能名称、简介、描述、5 个示例问题 | 技能清单从这里生成，格式不能改 |
| `样例问题.md` | 样例问题说明 | 与 `上架信息.md` 同步修改 |
| `scripts/` | 主脚本、`make-sample.js`、`selftest.js`、`README.md`，以及被主脚本或 `SKILL.md` 调用的辅助脚本 | 不放一次性脚本 |
| `scripts/lib/` | 共享库和本技能的规则模块 | 共享库规则见第五节 |
| `references/` | `input-spec.md`、`checklist.md`、`sample-output.md` 和业务口径文件 | 须被 `SKILL.md` 或脚本引用 |
| `assets/templates/` | 产出模板 | 须被 `SKILL.md` 或脚本使用 |

**演示case：** 各技能的演示与回归样例统一放在 `炼厂车间设备员/演示case/`，不放在技能目录内。

| 位置 | 放什么 | 要求 |
|---|---|---|
| `演示case/README.md` | 全部技能的演示目录索引 | 新增或删除技能时同步 |
| `演示case/<0N-分类名>/<技能目录>/` | `README.md`（示例问题↔附件对照表、关键验证点）、`make-sample.js` 的产物和回归样例 | 分类名、技能目录名与 `设备员skill/` 完全一致；全部使用虚构数据；不进发布包 |

- `make-sample.js` 不传 `--out` 时默认写到这里；`上架信息.md`、`样例问题.md` 的附件只写文件名，文件都在这个目录。
- 开发包（`package.sh --with-examples`）打包时把这个目录放进包内的 `<技能>/examples/`，脚本在仓库外运行时按 `examples/` 查找。

## 二、命名

- 技能目录名使用小写英文和连字符，如 `leak-point-tracker`，创建后不随意改名。
- 会进入发布包的文件名只用英文。打包校验会拒绝含中文文件名的包，例外是不进发布包的 `上架信息.md` 和 `样例问题.md`。
- 不用表示版本或状态的后缀，如 `-v2`、`-new`、`-final`、`-副本`。版本由 Git 管理。

## 三、禁止放入的内容

| 类型 | 示例 | 应该放在哪里 |
|---|---|---|
| 临时文件和运行产物 | `*-out/`、`*.tmp`、`*.bak`、`~$*.xlsx`、日志 | 系统临时目录，或脚本的 `--out` 指向目录外 |
| 演示与回归样例 | `examples/`、`演示附件/`、`sample-*.xlsx`、对照表 | `炼厂车间设备员/演示case/<分类>/<技能>/` |
| 打包产物 | `*.zip`、技能清单 | `炼厂车间设备员/dist/`，不入库 |
| 规范和说明文档 | 规范、口径对照 | `炼厂车间设备员/文档/规范/` |
| 过程材料 | 核验报告、任务书、评审记录、会议纪要、阶段总结 | 仓库根目录 `ProjectManage/`，按其 README 的规则存放；2026-11-03 及以前的留在 `炼厂车间设备员/文档/过程记录/` |
| 图标和图片素材 | 图标、宣传图 | `炼厂车间设备员/素材/` |
| 工具脚本 | 批处理、打包、统计脚本 | `炼厂车间设备员/tools/` |
| 个人笔记和草稿 | `todo.md`、`笔记.md` | 个人本地，不入库 |
| 第三方依赖 | `node_modules/`、`package.json` | 不允许。技能只用 Node.js 内置模块 |
| 真实业务数据 | 真实台账、人员信息、手机号、身份证号 | 不允许入库。样例一律虚构 |
| 密钥和账号 | 令牌、密码、`.env` | 不允许入库 |

## 四、临时文件

- 运行脚本时用 `--out` 指定系统临时目录或仓库外目录，不要输出到技能目录。
- 脚本的默认输出目录必须是系统临时目录，不能写到技能目录内。
- 调试用的文件在提交前清理干净。不确定一个文件是否有用时，不要提交。
- 不要用 `git add .` 一次性加入所有改动。先看 `git status`，确认每个文件都该提交。

## 五、共享库

`common.js`、`xlsx-lite.js`、`docx-lite.js` 在多个技能里各有一份，所有副本必须完全相同。

| 文件 | 副本数 |
|---|---|
| `common.js` | 50 |
| `xlsx-lite.js` | 48 |
| `docx-lite.js` | 11 |

修改时：

1. 先在协同群里告知，避免多人同时修改。
2. 改好其中一份，再同步到所有副本。
3. 跑全部 50 个技能的自测。
4. 单独提交，不和其它改动混在一起。

```bash
cd 炼厂车间设备员/设备员skill
SRC=<改好的文件路径>
find . -path "*/scripts/lib/$(basename "$SRC")" ! -path "$SRC" -exec cp "$SRC" {} \;
```

## 六、新增、修改和删除技能

**新增技能**

1. 先确认分类和技能边界，避免与现有技能的触发词重叠。不新增分类，确实需要时由负责人决定。
2. 按第一节建好技能目录和 `演示case/<分类>/<技能>/`，按[技能实现规范](技能实现规范.md)实现。
3. 通过 `make-sample`、`selftest` 和一次真实运行。
4. 运行 `bash 炼厂车间设备员/tools/package.sh --skill <英文名>`，确认能打包。
5. 更新所在分类的 `README.md`、`设备员skill/README.md` 的技能数、断言数，以及 `演示case/README.md` 的索引。

**修改技能**

- 改了脚本行为，要同步 `selftest.js`、`scripts/README.md`，必要时同步 `SKILL.md` 和 `references/`。
- 改了输出 JSON 的字段，要检查下游技能。流转关系见 `设备员skill/README.md` 的“共享数据约定”。
- 不能为了让自测通过而删除或放宽断言，除非业务规则确实改了，并在提交信息里说明。

**删除技能或改目录**

- 属于结构调整，要先和负责人确认，并单独提交。
- 技能的演示目录按 `设备员skill/` 的层级定位。改技能所在分类、改技能目录名，或删除技能时，用 `git mv` 同步调整 `演示case/` 下对应目录。

## 七、提交前检查

在 `炼厂车间设备员/设备员skill/` 下运行，前 4 段和第 6 段命令应该没有任何输出，第 5 段的“版本”都应为 1。

```bash
# 1. 根目录有没有多余内容
find . -mindepth 1 -maxdepth 1 ! -name '0*' ! -name README.md ! -name .DS_Store
# 2. 分类目录有没有多余文件
find . -mindepth 2 -maxdepth 2 -type f ! -name README.md ! -name .DS_Store
# 3. 技能根目录有没有多余内容
find . -mindepth 3 -maxdepth 3 ! -name SKILL.md ! -name 上架信息.md ! -name 样例问题.md ! -name scripts ! -name references ! -name assets ! -name .DS_Store
# 4. 有没有临时文件和打包产物
find . \( -name '*-out' -o -name '*.tmp' -o -name '*.bak' -o -name '~$*' -o -name node_modules -o -name '*.zip' -o -name '*.log' \)
# 5. 共享库是否一致
for n in common.js xlsx-lite.js docx-lite.js; do echo "$n 版本 $(find . -path "*/scripts/lib/$n" -exec git hash-object {} + | sort -u | wc -l | tr -d ' ')"; done
# 6. 技能与演示目录是否一一对应
diff <(find . -mindepth 2 -maxdepth 2 -type d | sort) <(cd ../演示case && find . -mindepth 2 -maxdepth 2 -type d | sort)
```

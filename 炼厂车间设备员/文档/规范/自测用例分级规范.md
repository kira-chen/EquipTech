# 设备员技能包 · 自测用例分级规范

本规范的适用范围是 `设备员skill/` 下各技能的 `scripts/selftest.js`。每条断言都要分到 BVT、A、B、C 四级中的一级，改动后可以只跑与改动相称的那几级，不必每次都跑全量。

## 一、级别定义

分级按断言出错后会造成什么后果来定，不看用例是何时写的、因什么写的。

| 级别 | 业内常见叫法 | 回答的问题 | 本项目包含的用例 |
|---|---|---|---|
| BVT | 冒烟测试、构建验证测试、Level 0、P0 | 这一版能不能用 | 主命令用标准输入跑通：`ok:true`、退出码 0、主要产出文件生成、报告章节齐全；对这次运行的结果顺带做的计数断言 |
| A | 基本功能、Level 1、P1 | 主结论对不对 | 核心计算与判定；中石化口径的关键规则；底线规则；车间范围核对的主路径 |
| B | 重要功能、Level 2、P2 | 常用的其他用法对不对 | 可选参数与次要功能；参数校验与错误路径；输入兼容；次要路径下的口径规则 |
| C | 一般与边界、Level 3~4、P3 | 少见情形和细节对不对 | 低频边界；文案措辞与格式细节；内部函数单元测试；只复现单个历史缺陷的窄场景 |

运行时按优先级累加：跑 A 级时 BVT 也一起跑，跑 C 级就是全量。

## 二、定级方法

对每一节断言，从 BVT 到 C 逐级判断，命中哪一级就定哪一级。

1. **BVT：** 每个技能只有一节到两节，只用主流程的 1~3 次运行，包括生成夹具的运行。这一节要回答的是“这一版能不能用”，不负责证明结果算得对。通常就是原来的「正常路径」「基础统计」一节，再加上「产出完整性」一节。
2. **A：** 断言出错后，设备员会拿到错误的主结论，或被误导做出判断。具体包括以下几类。
   - **核心计算与判定：** 计数、分级、超期、完好率、异常识别等出现在报告结论里的数。
   - **中石化口径的关键规则：** [中石化口径对照](中石化口径对照.md)里的指标算法，以及 SAP、EAM 标准导出的主格式。
   - **底线规则：** 不编造；不外推；缺失不当 0（null 不是 0）；不确定的不判定（undetermined 不被默认处理）；不替用户下结论。
   - **车间范围核对的主路径：** [D007](../../../ProjectManage/决策记录/D007-脚本侧车间范围核对口径.md) 规定的剔除其他车间行，以及车间不一致时的【注意】提示。
3. **B：** 出错后影响的是某个常用的附加用法，主结论不受影响。具体包括以下几类。
   - **可选参数与次要功能：** 环比、同比、阈值调整、topn、按某个维度分组、xlsx 导出的细节。
   - **参数校验与错误路径：** 缺参数、非法取值、文件不存在时返回 `ok:false` 并以退出码 1 退出。
   - **输入兼容：** 别名列头、表头前有标题行、合计行、多文件或目录混合输入、其他系统的列名。
   - **次要路径下的口径规则：** 例如读上期产出时核对车间、无车间列时的说明。
4. **C：** 以上都不是。具体包括以下几类。
   - **低频边界：** 空表、0 字节文件、损坏文件、极端日期、单元格取值非法。
   - **文案与格式细节：** 提示语的字面、emoji、排序、换行。
   - **内部函数单元测试。**
   - **只复现单个历史缺陷的窄场景。** 如果该缺陷影响主结论，按它的影响定级，不放 C。

同一节里的断言后果不同时，把这一节拆成几节分别定级。

**各级占比：** 定级只按上面的方法，不为凑占比调高或调低级别。

- **现有占比：** 50 个技能共 11789 条断言，其中 BVT 826 条（7%）、A 4805 条（41%）、B 4491 条（38%）、C 1667 条（14%）。
- **A 级为什么偏高：** 业内常见的 A 级占比在 25%~35% 之间，本技能包高于这个范围，原因是底线规则断言多，例如不编造、null 不当 0、不确定的不判定。
- **何时复查：** 某个技能的占比明显偏离上面的整体比例时，例如 BVT 超过 15%，或 A 级超过 60%，回头检查定级是否有误；定级没有问题就保持不变。

## 三、写法

每个 selftest.js 在 `ok`/`eq` 之前放下面这段分级代码，50 个技能写法一致：

```js
// 用例分级（见 文档/规范/自测用例分级规范.md）：SELFTEST_LEVEL=BVT|A|B|C 只跑该级及更高优先级的节，不设时跑全量
const LEVELS = ['BVT', 'A', 'B', 'C'];
const RUN_LEVEL = LEVELS.indexOf(String(process.env.SELFTEST_LEVEL || 'C').toUpperCase());
if (RUN_LEVEL < 0) { console.error(`SELFTEST_LEVEL 只能取 ${LEVELS.join('、')}`); process.exit(2); }
const byLevel = { BVT: 0, A: 0, B: 0, C: 0 };
let curLevel = null;
function section(level, fn) {
  if (!LEVELS.includes(level)) throw new Error(`未知用例级别 ${level}`);
  if (LEVELS.indexOf(level) > RUN_LEVEL) return;
  curLevel = level; fn(); curLevel = null;
}
```

- **断言计数：** `ok` 先确认当前处于某一节内，再按级别计数，失败项前面标上级别：

  ```js
  const ok = (c, n) => {
    if (!curLevel) throw new Error(`断言须写在 section() 内：${n}`);
    byLevel[curLevel]++;
    if (c) pass++; else { fail++; failures.push(`[${curLevel}] ${n}`); }
  };
  ```

- **结尾输出：** 在原有的“自测：N 通过，M 失败”一行之后，再打印一行各级断言数：

  ```js
  console.log(`用例级别 ${LEVELS[RUN_LEVEL]}：BVT ${byLevel.BVT}，A ${byLevel.A}，B ${byLevel.B}，C ${byLevel.C}`);
  ```

- **节的写法：** 每节写成 `section('A', () => { ... });`。原有的节标题注释保留在它上一行。断言编号里的字母是原来的节号，和级别无关，不改。
- **断言位置：** 断言必须写在节内，写在节外会直接报错。
- **夹具：** 生成夹具（`mk(...)`、写 JSON）以及定义 `run`、`raw` 等辅助函数，开销都很小，应放在节外。多节共用的放到文件前部；只给相邻几节用的，可以用一个 `{ ... }` 块包住这几节，在块内定义。
- **运行结果变量：** `r` 这类运行结果变量在文件前部用 `let r;` 声明，各节内只赋值，不重新声明。
- **节之间的依赖方向：** 一节可以使用前面同级或更高优先级节的运行结果，例如 C 级节读 A 级节的 `r`；反过来不行。BVT 节只能依赖 BVT 节。

## 四、运行

```bash
SELFTEST_LEVEL=A node scripts/selftest.js              # 单个技能，只跑 BVT 和 A
node tools/selftest.js --level BVT                     # 全部技能并行跑 BVT
node tools/selftest.js --level B --skill <英文名>       # 指定技能，可重复传
```

`tools/selftest.js` 默认按 CPU 核数并行运行，结尾汇总各级断言数、失败项和耗时。`tools/package.sh` 打包前也通过它跑自测，默认全量，可以用 `--test-level` 指定级别。

各时点跑哪一级（D009）：

| 时点 | 运行级别 | 命令 |
|---|---|---|
| 改动过程中的快速检查 | 全部技能 BVT，加上所改技能的全量 | `node tools/selftest.js --level BVT`，再 `node tools/selftest.js --skill <英文名>` |
| 合并到 main 前 | 全量 | `node tools/selftest.js`，见 [GitHub 协同规范](GitHub协同规范.md)第四节 |
| 打包上架前 | 全量 | `bash tools/package.sh`，默认即全量，不加 `--test-level` |

在 8 核以上的机器上，全部技能跑 BVT 约 3 秒，全量约 1 分钟。改了共享库、打包工具或多个技能时，改动过程中也直接跑全量。

## 五、新增与修改用例

- **新增断言：** 加断言时按第二章定级，放进对应的节；没有合适的节就新开一节。
- **改了级别或节结构：** 要确认以下三点。
  - 四个级别分别运行都全绿。
  - C 级的断言总数与修改前相同。
  - 各级运行的断言数等于全量运行时该级及以上各级断言数之和。
- **改动与定级不符：** 发现某条断言的失败影响比它的级别更大时，把它调高，不要为了让低级别运行更快把它压低。
